# 灵知新版课程接入与部署

## 代码与运行边界

启智和灵知共用一个 GitHub 仓库、一次提交。启智位于 `qizhi/`，灵知位于仓库根目录；Compose 的灵知 build context 为 `../..`，不再经过 Git 子模块。

```text
启智首页“我的课程”
├── 新版 → /lingzhi/courses → 同域反向代理 → lingzhi:7860
└── 旧版 → /my-courses      → 启智课程页面与 server:8000
```

启智 OAuth/JWT 与 RBAC 提供正式身份。灵知通过启智内部 `GET /user/current` 验证 token，并把正式教师映射为 `qizhi:<user-id>` actor；浏览器提供的 `X-User-Id` 由服务端覆盖。HTTP、SSE 和 WebSocket 使用同一登录态。登录缺失、角色不足和身份服务不可用分别返回 401、403、503。

启智的 `Course → Resource` 继续保存在 PostgreSQL；灵知的 `CourseDocument + CourseBlock[]` 继续保存在独立数据目录。代码合仓不改变课程所属系统，不自动转换课程或迁移 owner；历史共享 actor 课程仍需显式、可审计的归属迁移。

## 拉取与配置

```bash
git clone https://github.com/elgoog577215-beep/hackthon.git
cd hackthon
cp -n qizhi/server/.env.example qizhi/server/.env
cp -n qizhi/deploy/.env.example qizhi/deploy/.env
```

已有这个统一仓库的工作区使用 `git pull --ff-only`。旧启智仓库保留作历史追溯和恢复；其运行目录切换应作为独立发布执行，不在现有数据目录中覆盖 Git 根目录。

配置分为两份：

| 文件 | 内容 |
| --- | --- |
| `qizhi/server/.env` | 启智的数据库、OAuth、JWT、模型和可选外部服务凭据 |
| `qizhi/deploy/.env` | Compose 构建及灵知运行配置、论文服务反向代理目标 |

原来写死在代码中的部署值已移出公开源码。迁移服务器时，需要把原私有配置和旧源码中的实际部署值写入对应环境变量，不能直接用示例默认值替换生产配置。

启智数据库统一读取 `DATABASE_HOST/PORT/USER/PASSWORD/NAME`；也可用 `SYNC_DATABASE_URL` 和 `ASYNC_DATABASE_URL` 分别覆盖完整连接串。连接 Compose 自带数据库时，主机为 `db`，库名、账号和密码需与现有数据库一致。仅设置 `ENV=PROD` 不再隐式选择写死的云数据库地址。

启智文本模型读取 `VLLM_TEXT_ENDPOINT`、`VLLM_API_KEY` 与 `VLLM_MODEL`，模型默认 `qwen3.8-27b`。灵知读取 `LINGZHI_AI_API_BASE`、`LINGZHI_AI_API_KEY`，文本角色固定使用指定的 `qwen3.8-27b`，地址与凭据来自私有配置。论文检查如需直接代理，在部署环境设置容器可访问的 `ESSAY_CHECK_PROXY_URL`，包含目标 `/api/` 后缀。

Compose 已配置 `QIZHI_AUTH_VERIFY_URL=http://server:8000/user/current` 和 `QIZHI_AUTH_ALLOWED_ROLES=teacher,admin`。灵知前端构建启用 `/lingzhi/` 前缀和正式启智认证，不复制启智 JWT 密钥。

## 构建和启动

从仓库根目录执行：

```bash
./scripts/qizhi.sh check
./scripts/qizhi.sh build
./scripts/qizhi.sh up -d
./scripts/qizhi.sh ps
```

`check` 只检查源码、依赖清单和 Compose 配置，不启动服务。`build/up/ps/logs` 共用同一 Compose 文件和项目名 `edu-ai-home`。既有容器名和卷名保留，不能另起一个新项目名后误以为旧数据丢失。

灵知不额外暴露宿主端口。启智 Nginx 将 `/lingzhi/` 转发到内部 `lingzhi:7860`，覆盖页面、静态资源、API、SSE 和 WebSocket。

## 服务器迁移与回退

1. 记录当前版本，备份启智数据库、上传文件、灵知数据卷和私有环境配置，并确认恢复方法。
2. 在独立发布目录拉取整个仓库的确定提交，配置私有环境变量；核对 Compose 项目名、数据库和数据卷仍指向原现场。
3. 确认没有需要保护的运行中生成任务，再构建并切换。原运行目录和服务在切换前继续保留。
4. 验证后再把新目录作为服务器的正式代码入口。失败时使用原发布目录和环境重新构建启动，不删除数据卷。

后续回滚选择整个仓库的已验收提交，再重新构建受影响服务。只修改启智代码不会触发灵知独立生产环境的 GitHub Actions 发布；独立灵知镜像及发布包不包含 `qizhi/`。

## 上线验收

```bash
curl -fsS http://127.0.0.1/lingzhi/api/health
curl -fsSI http://127.0.0.1/lingzhi/courses
```

还需验证：启智首页新旧课程入口、教师登录、未登录与学生账号拒绝访问、新课程 owner、API/SSE/WebSocket 同域请求，以及指定真实模型的生成结果。合仓的源码检查和前端构建不能代替这些生产证据。
