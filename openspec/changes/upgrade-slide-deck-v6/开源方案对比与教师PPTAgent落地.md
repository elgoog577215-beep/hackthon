# 教师 PPT Agent：开源方案对比与落地边界

## 一、当前结论

教师工作台不需要另起一条 PPT 生产链。正式链路继续使用现有 V6：

```text
已确认教案与讲稿
→ 课程教学单元图
→ PPT Agent 故事规划
→ PPT Agent 视觉规划
→ 结构化页面合同
→ Web/PPTX 同源渲染
→ 质量门禁
→ 原子发布与失败恢复
```

本轮发现的主要问题不是渲染器能力不足，而是教师入口曾绕过共享 AI 规划器，使用确定性适配器把教学块直接映射成页面。它造成一页对应一个来源块、重复标题、单一版式和大量纯文字页。该旁路必须退出，教师入口复用唯一 V6 主链。

## 二、候选项目对比

| 方案 | 可吸收能力 | 不直接采用的原因 | 灵知落点 |
|---|---|---|---|
| PPTAgent / DeepPresenter | 先规划再设计、参考课件分析、工具调用、渲染后反思与局部修复 | 运行栈重，沙箱与模型依赖多；自由生成不能代替课程真源、教师确认和版本关系 | 吸收“规划—执行—检查—局部修复”的 Agent 工作方式 |
| Presenton | 自托管 API、自定义模板、页面编辑、可编辑 PPTX、多模型适配 | 它解决通用演示文稿生产，不理解教案、讲稿、教学块和学校正式文件关系 | 作为编辑体验、模板管理和服务接口对标，不作为课程真源 |
| PptxGenJS | 稳定生成可编辑 OOXML；支持文本、表格、图表、形状、母版 | 只负责确定性渲染，不负责教学故事、事实约束和视觉判断 | 后续作为 PPTX 导出层候选；当前先保留已验证的 V6 Web/PPTX 同源渲染器 |
| PPTist | 成熟 Web 端编辑器 | AGPL 对商业集成约束较强；编辑器不能替代生成链 | 只参考交互，不复制核心代码 |
| AIPPT | 大纲确认、逐页重生成、模板化生成 | 部分可编辑交付依赖 OCR/VLM 重建，语义真源较弱 | 参考“先看结构、再逐页处理”的交互 |

## 三、技术取舍

1. Agent 只拥有规划权，不拥有课程事实真源。它只能选择已确认的教学单元、来源块、模板布局和来源支持的视觉形式。
2. 页面生成采用“受约束 Agent + 确定性编译器”，不让模型自由输出不可维护的 PPTX 二进制或任意 HTML。
3. 故事规划失败时整次候选失败，保留上一可用版本；视觉规划只允许在不损失学科硬内容时降级，并标记人工检查。
4. 上传的旧 PPT 将来作为视觉参考与模板归纳来源，不直接覆盖系统正式课件，也不成为第二份课程正文。
5. 首先解决故事质量，再比较导出引擎。当前 41 页问题发生在规划层，先换渲染器不会解决重复标题和一块一页。

## 四、本轮落地

- 教师 PPT 正式入口改为共享 AI 故事规划器与共享 AI 视觉规划器。
- 删除教师专用确定性故事/视觉适配器。
- 增加规划来源门禁：已退役的确定性适配器不能再次被标记为“AI 已完成”并发布。
- 正式课件保存轻量故事板摘要，教师可在“生成详情”中检查页序、标题、教学单元、版式数量与每页来源块数量。
- 继续沿用来源冻结、讲稿/教案修订绑定、检查点恢复、上一版本保留、Web/PPTX 同源和导出检查。
- 生成详情与候选诊断增加模型调用次数、输入/输出 Token、重试和 AI 忙时；课程级指标可累计比较不同版本的成本与速度。
- 故事规划只向模型发送必要的来源块、安全分页和版式 ID，不再为每个教学单元重复发送完整版式槽位合同。验收课首批失败路径从 108,051 降至 25,418 个估算输入 Token。
- “余额不足”现在按提供方级故障处理：停止继续轮询同一付费池的其他模型，保留上一版并明确提示配置问题。

## 五、验收口径

同一门验收课重新生成后，至少核对：

- `planning_status.story_ai.providers` 不再出现 `teacher-plan-adapter`；
- 故事板不存在确定性的一块一页映射；
- 非续页标题保持唯一，页面顺序与教学块顺序一致；
- 视觉决策不再几乎全部为 `text_native`；
- 来源块可见覆盖、讲稿全文备注绑定、Web/PPTX 合同和导出检查继续为通过；
- 模型不可用或质量门失败时不覆盖上一可用版本。
