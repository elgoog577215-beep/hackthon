## Context

前端 `http.ts` 已统一拦截 Axios 请求，但目前只通过 `ElMessage.error` 显示一段字符串。`task-observability.ts` 和 `CourseProductionNotice.vue` 已证明“可理解原因 + 折叠技术详情”的方向可用，但它们只认识课程生产任务。大量页面仍自行读取 `response.data.detail`，因此不能稳定保留错误码和请求现场。

课程状态同时承担课程准备度、后台任务状态、资产状态和当前编辑模式，导致同一对象在不同页面出现互相冲突的词。

## Goals / Non-Goals

**Goals:**

- 一个异常在全站拥有稳定的中文名称、归纳原因和安全技术详情。
- 普通 Axios 异常无需各页面重复造提示；局部错误仍可复用同一展示组件。
- 请求编号可从浏览器反馈追到服务端日志。
- 课程级只回答“是否完成备课”，局部任务和异常留在所属工作区。
- 保留用户输入、已生成内容和恢复动作，不用错误提示覆盖正文。

**Non-Goals:**

- 不在浏览器暴露 Python/JavaScript 完整堆栈、请求头、令牌、请求体或服务器绝对路径。
- 不把后台健康检查和轮询异常全部弹到用户面前。
- 不在本轮重写每一个业务接口的领域错误码；未知错误先由 HTTP 状态、接口域和原始反馈安全归一。
- 不把教案、讲稿等资产的内部真实修订状态删除；只移除当前编辑器中无操作价值的持续徽标。

## Decisions

1. **错误数据使用单一 `AppErrorPresentation`。**
   字段固定为 `title`、`summary`、`technicalDetail`、`code`、`requestId`、`status` 和 `retryable`。业务页面不得再次直接拼接 `response.data.detail` 作为完整 UI。

2. **错误名称按“显式业务名 -> 错误码 -> 请求接口域 -> HTTP 状态”确定。**
   显式业务名用于教案保存等清楚动作；已分类错误码优先于文本正则；未知接口再由 URL 和方法映射到“课程读取失败、教案保存失败”等预设中文名。

3. **归纳原因和技术详情分离。**
   面向用户的原因只说明发生了什么、当前影响和下一步。错误码、请求编号、状态码、方法、URL 与后端原始反馈放入默认折叠的技术详情框。

4. **默认请求全局呈现，静默请求由所属区域就地呈现。**
   `silentError` 继续阻止后台轮询打断用户；普通 Axios 错误由根级错误反馈层统一显示并去重。局部编辑器和整页加载错误直接使用同一组件，避免只有一行红字。

5. **服务端只暴露安全诊断标识。**
   每个请求生成或复用 `X-Request-Id`。未捕获异常在响应中返回 `internal_server_error` 和请求编号；异常类型、消息和堆栈写服务端日志。前端详情框不得采集 Authorization、Cookie、请求体或完整堆栈。

6. **正式课程只投影两态。**
   有未完成或需处理的备课任务、空白课程和未完成正式准备时显示“正在备课”；正式课程准备链完成时显示“备课完成”。异常在错误区域展示，不新增“异常课程”状态。

7. **编辑模式不是生命周期。**
   教案和讲稿编辑器删除“草稿、编辑中、AI 方案、待确认、已确认”等顶栏徽标。保存中由按钮忙碌态表达；候选由画布差异表达；保存失败、冲突和未同步才显示结构化错误。

## Risks / Trade-offs

- URL 归一只能给未知接口提供稳定名称，不能替代后端领域错误码；后续接口应逐步补齐 `code/message`。
- 全局错误层可能遇到重复失败；使用签名去重和最多三条可见记录控制噪声。
- 课程“备课完成”目前沿用正式课程与生成任务的现有真源，不把五项资产数量另建成第二套状态仓库。
