## Context

当前教师课程生产能力来自两组实现：

- 旧整课链：`course_generation_workflow.py`、`course_service.py`、`task_manager.py` 以及旧生成对话框和 generation store。它擅长从课程要求一路规划大纲、教案、正文和练习，已经积累了提示词、并发、检查点、降级与质量门，但任务边界过大，不适合教师逐讲备课。
- 新工作台链：`teacher_lesson_authoring.py`、`teacher_script.py`、`SlideDeckV6` 及教师工作台组件。它允许资产独立创建、按讲选择资料、编辑、确认和恢复，符合教师从任意已有材料继续工作的方式，但部分生成能力尚未复用完整，尤其是讲稿和 PPT。

因此目标不是维护两条链，也不是为新界面重写一套后端，而是把旧链拆成可复用能力，由新工作台成为唯一教师编排入口。

## Goals / Non-Goals

**Goals:**

- 冻结课程层级、产品术语、正式资产和上下游边界。
- 形成唯一教师主链：`大纲 → 本讲课型与教学块 → 教案 → 讲稿 → PPT`。
- 支持从零生成、从上传原文件吸收、从任一已有正式资产继续三种入口。
- 大纲与教案优先复用当前成熟实现；讲稿与 PPT 重点吸收旧正文和旧课件链能力。
- 每一步都具有可见进度、工作稿、确认、失败保留、恢复和修订来源。
- 逐步关闭旧教师整课写入口，同时保持学生学习运行时兼容。

**Non-Goals:**

- 不把题库、日历和配套文档强行串进教案到 PPT 的阻塞链。
- 不把内部 40 类 archetype、提示词选择或技术模块名直接展示给教师。
- 不因合同冻结一次性删除旧代码、迁移全部历史课程或重写成熟大纲与教案。
- 不在本变更内改造学生学习、练习、笔记和 AI 老师运行时。

## Decisions

### 1. 课程结构和生产边界固定

正式层级为：

```text
课程
└── 章：知识结构和大纲组织边界
    └── 讲（LessonUnit）：备课、授课、资料、任务、版本和恢复边界
        └── 讲内小节：一讲内部的内容组织边界
```

“章”不承担生成任务恢复；“讲内小节”不复制一份独立正式教案。每讲拥有一份可修订教案、一份正式讲稿和一组 PPT 版本。

### 2. 教师可见分类与内部策略分开

教师可见合同为：

```text
课程类别
→ 教学类型：系统学习 / 项目实战 / 问题探究 / 考试冲刺
→ 学科类型
→ 学科细分
→ 本讲课型：理论讲授 / 实践操作 / 理论与实践 / 案例研讨 / 实验探究 / 项目工作坊 / 复习测评
→ 教学块
```

教学类型决定整门课的默认组织偏好；学科类型与学科细分帮助 AI 选择专业表达；本讲课型可以覆盖默认偏好；教学块是最终可见、可调的课堂路径。现有 `course_pedagogy.py` 的 40 类 archetype、内部模块注册表和选择分数继续作为实现策略，由上述字段编译得到，不成为另一套产品语言。

### 3. 教学块先确认，教案再生成

系统根据教学类型、学科、该讲目标、时长和来源材料推荐本讲课型与教学块，并为每块显示：

```text
名称、作用、内容摘要、建议时间、教学活动、预期产出
```

教师可改课型、增删、改名和排序教学块。确认后才流式生成教案正文。推荐值是可编辑草稿，不是额外审批页；确认与生成在同一中间内容面连续完成。

### 4. 原文件先吸收，再进入正式修订

来源优先级为：

```text
教师明确选择的主来源
> 已确认的上游正式资产
> 教师选择的参考资料和联网来源
> 课程基本信息与系统模板
```

教师上传原教案并指定为主来源时，系统先解析其分块、顺序、字段和原文，形成结构化工作修订；默认保留原结构和表达，只补齐缺失字段。若来源与系统建议冲突，界面展示冲突和候选，不静默覆盖。原文件保留在资料空间，正式教案保存在系统真源，两者以来源关系连接。

### 5. 教案负责怎么教，讲稿是中性课程内容本体

教案规定“为什么教、教什么、怎样组织、如何评价”，以教学块为骨架，并保存教师动作、学生活动、时间和检查方式。讲稿只规定该讲的课程内容：定义、边界、推理、例题、辨析、实践任务与总结。它使用中性书面语言，既不以教师口播视角写作，也不以学生指令或个性化学习视角写作。每个讲稿块稳定绑定一个教学块与知识范围，但教案中的提问、板书、巡视和等待等课堂调度不进入讲稿正文。

旧一键课程的“正文”最接近讲稿，但不是直接改名。旧正文中的背景引入、概念讲解、过程推导、案例、练习、总结、学科产物完整性和前后连贯继续吸收；学生个性化、课堂调度、整课自动推进和旧发布语义不迁移。

### 6. PPT 以已确认讲稿为语义真源，按资料现场三分流

正式来源链为：

```text
已确认教案修订
→ 已确认讲稿修订
→ PPT 文书（逐页教学任务、主要结论、可见文案、页型、页数、版式与构图）
→ 文书质量门与修订冻结
→ SlideDeckV6 从文书确定性编译
→ 教师确认同一文书修订
→ Web 预览与正式 PPTX 导出
```

PPT 文书是讲稿到最终 PPT 之间的唯一逐页内容合同，记录 `source_lesson_plan_revision_id`、`source_script_revision_id`、每页讲稿块来源和文书修订。它先于 deck 完整产生，可以精简讲稿、拆分页面和选择表达形式，但不得增加或改变知识。文书质量门阻断原始公式标题、页间重复、缺少页面任务/结论和故事规划降级；最终 PPT 渲染器只负责把已冻结文书放入模板，不再写内容。教案或讲稿变化只把受影响 PPT 标记为过期，保留最后可用版本。

PPT 阶段独立拥有 `ppt-v6:{lesson_unit_id}` 来源关系，不自动沿用教案阶段的选择。具体分流为：

| 输入现场 | 内容方案 | 交付物 |
|---|---|---|
| 无额外资料、无 PPTX | 确认讲稿是唯一内容源 | `讲稿 → PPT 文书 → PPT` |
| 有主参考/参考/联网来源、无 PPTX | 讲稿继续负责知识语义；额外资料按相关讲稿块绑定，只指导案例、依据与页面表达 | `讲稿 + 冻结资料 → PPT 文书 → PPT` |
| 已有 PPTX | 不重生成整套 PPT；保留原 PPTX，对照确认讲稿、已选资料及其他当前教学资产 | `原 PPTX + 讲稿 + 资料 → 审阅报告` |

参考资料不是第二份讲稿。规划器可看到与当前讲稿块相关的证据摘要，但可见文案、标题、公式、数字与识别符仍必须受已绑定讲稿块支持。`ppt_manuscript_v1` 同时冻结资料关系与每页证据 ID，使变更、重试和导出都可追溯。

### 7. 所有教师生成共用任务和修订底座

资产生成可以使用不同任务类型，但只能有一个任务所有者和一个修订真源：

```text
TaskManager：任务 ID、阶段、心跳、检查点、取消、恢复和幂等
TeacherLessonAuthoringRepository：大纲、教案、讲稿和 PPT 的工作/确认修订指针
领域生成器：只负责从冻结输入产生候选或工作片段
```

SSE 只是任务投影，断线后从持久化工作片段恢复。任何失败不得清空已生成片段或覆盖最后确认版本。确定性降级若通过结构质量门，可作为“待 AI 优化”的工作稿，但未确认教案不能生成正式讲稿，未确认讲稿不能生成正式 PPT。

### 8. 旧链能力按矩阵迁移，不按文件搬家

| 能力 | 旧链资产 | 新主线归宿 | 迁移原则 |
| --- | --- | --- | --- |
| 课程要求与教学类型 | 课程生成请求、类型合同 | 课程基本信息与默认组织偏好 | 复用字段和校验，不保留旧整课入口 |
| 大纲规划 | 目录规划、章节命名、时长约束 | 教师大纲任务 | 复用成熟规划器，确认后停止 |
| 教学策略 | `course_pedagogy.py`、40 类 archetype | 本讲课型与教学块推荐 | 作为内部策略，不新增教师术语 |
| 教案 | `CourseTeachingPlanV3`、质量门、知识锚点 | 按讲教案修订 | 有机融合，禁止覆盖成熟结构 |
| 正文 | 学科模板、逻辑块、并发与降级 | 中性课程讲稿块生成 | 选择性吸收学科表达和完整性，不迁移学生视角和整课流程 |
| PPT | 旧课件来源适配与版本 | `PPT文书 → SlideDeckV6 → PPTX` | 文书只投影确认讲稿，模板渲染不写知识，旧版本保留只读 |
| 资料 | 检索、正文读取、来源分级 | 当前讲主来源/参考/联网来源 | 作用域跟随当前讲，原件不变真源 |
| 任务与质量 | 检查点、幂等、批次、质量门 | 统一 TaskManager 与资产质量门 | 只保留一个状态所有者 |

### 9. 题库、日历和配套文档是旁支

题库可使用课程与讲次上下文生成，但可跳过；教学日历是正式文件类型并使用学校模板生成；评分细则、自查清单等配套文档通过二级模板库快捷生成。它们均进入文件空间并可引用其他正式资产，但不阻断教案、讲稿、PPT。

### 10. 旧教师整课链按门退场

迁移门如下：

1. **G0 合同冻结**：标准语言、资产图、来源优先级和确认门写入正式文档与规格。
2. **G1 能力盘点**：旧链每项成熟能力、提示词、测试和数据均有保留、迁移或废弃结论。
3. **G2 新链接管**：新工作台只调用共享领域服务，不再向旧教师整课真源新增正式写入。
4. **G3 只读兼容**：历史教师资产完成抽样迁移和对账，旧入口只读，仍可回退读取最后可用版本。
5. **G4 删除退场**：生产调用为零、迁移与回滚演练通过后，删除旧教师 UI、API、路由和专属写入。学生使用的共享能力不能随旧教师入口一起删除。

## Risks / Trade-offs

- **同一底层服务被误认为两条链**：任务类型可以不同，但教师编排入口、资产真源和确认规则只能有一套；用调用图和写入测试防止分叉。
- **原教案吸收时丢失教师习惯**：默认忠实保留结构和表达，系统建议只形成候选；解析不确定部分明确标记。
- **讲稿、PPT 文书和最终 PPT 再次双源**：PPT 文书强制引用确认讲稿修订，禁止同时把整段讲稿和教案模块拼成两个语义来源；最终 PPT 只渲染文书。
- **旧链删除过早**：每个退场动作绑定数据审计、生产调用和回滚证据；未过门只允许兼容，不删除。
- **分类让教师负担过重**：学科类型和细分可由 AI 识别，教学类型在课程级可改，本讲只要求教师看到并可调课型与教学块。

## Migration Plan

1. 完成 G0：冻结正式语言、资产图、来源优先级和确认门。
2. 完成 G1：审计旧整课链与新工作台代码、提示词、测试、数据和调用，建立可追踪能力矩阵。
3. 复用成熟大纲与教案服务，让新工作台只负责分步编排和交互投影。
4. 选择性吸收旧正文的学科模板与逻辑块，建立教学块到中性讲稿块的稳定映射和质量门。
5. 让 V6 在确认讲稿之后先形成可审阅的 PPT 文书，再确定性渲染，并补齐精确过期、定向重建、失败保留和版本回退。
6. 统一任务、质量和恢复，完成真实模型与浏览器主路径验收。
7. 依次通过 G2、G3、G4，关闭并删除旧教师整课入口。

回滚时恢复上一稳定工作台调用适配器并继续读取最后确认修订；禁止用回滚覆盖教师已上传原件、已确认正式资产或学生学习数据。

逐项能力所有者、提示词处理方式、已确认缺口和退场证据维护在[教师课程生产能力迁移清单](./能力迁移清单.md)。该清单只记录当前代码核验结论；实施勾选仍以 `tasks.md` 为准。
