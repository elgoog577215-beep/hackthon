## Context

当前教师课程生产能力来自两组实现：

- 旧整课链：`course_generation_workflow.py`、`course_service.py`、`task_manager.py` 以及旧生成对话框和 generation store。它擅长从课程要求一路规划大纲、教案、正文和练习，已经积累了提示词、并发、检查点、降级与质量门，但任务边界过大，不适合教师逐讲备课。
- 新工作台链：`teacher_lesson_authoring.py`、`teacher_script.py`、`SlideDeckV6` 及教师工作台组件。它允许资产独立创建、按讲选择资料、编辑和恢复，符合教师从任意已有材料继续工作的方式，但部分生成能力尚未复用完整，尤其是讲义和 PPT。

因此目标不是维护两条链，也不是为新界面重写一套后端，而是把旧链拆成可复用能力，由新工作台成为唯一教师编排入口。

## Goals / Non-Goals

**Goals:**

- 冻结课程层级、产品术语、正式资产和上下游边界。
- 形成唯一教师主链：`课程表单 → 轻量讲次方案 → 完整大纲 → 全课教案预览 → 分讲教案 → 分讲讲义 → PPT 页面内容稿 → PPT`。
- 支持从零生成、从上传原文件吸收、从任一已有正式资产继续三种入口。
- 大纲与教案优先复用当前成熟实现；讲稿与 PPT 重点吸收旧正文和旧课件链能力。
- 每一步都具有可见进度、当前工作修订、可选编辑、失败保留、恢复和精确修订来源。
- 逐步关闭旧教师整课写入口，同时保持学生学习运行时兼容。

**Non-Goals:**

- 不把题库、日历和配套文档强行串进教案到 PPT 的阻塞链。
- 不把旧学科细分、内部 40 类 archetype、编排节奏、提示词选择或技术模块名直接展示给教师。
- 不因合同冻结一次性删除旧代码、迁移全部历史课程或重写成熟大纲与教案。
- 不在本变更内改造学生学习、练习、笔记和 AI 老师运行时。

## Decisions

### 1. 课程结构和生产边界固定

新课程的教师可见正式层级为：

```text
课程
└── 讲（LessonUnit）：备课、授课、资料、任务、版本和恢复边界
    └── 讲内小节与教学块：一讲内部的内容组织和定位锚点
```

大纲可以按主题组织知识关系，历史课程继续兼容章/节读取，但章和讲内小节都不承担新的生成任务、正式资产或恢复边界。每讲只拥有一份连续可修订教案、一份教师可直接讲授的讲义和一组 PPT 版本。

### 1.1 教师大纲使用“表单 → 轻量讲次方案 → 完整大纲”三个真实步骤

第一步由教师填写课程表单。第二步用一次有界请求生成轻量讲次方案，只负责讲次顺序、标题和内容简介；每个完整返回的讲次立即流式显示，未返回的讲次只显示真实生成状态。结构校验通过后，页面只保留讲次标题和内容简介的连续编辑文档，不预先显示课程目标、学时、模块、考核和教学日历等第三步字段的空壳。方案立即可编辑并停止后台生成。这个停点是两次生成之间的主动继续点，不是对已生成资产的确认门：教师可以调整标题、简介、顺序并增删讲次，只有明确点击“继续生成完整大纲”后，系统才冻结最新方案快照并启动第三步。

第三步先根据教师最新保存的讲次方案生成一次课程级正式合同，补齐课程定位、目标、成果关联、模块、考核与参考资料；合同通过结构校验后，再为方案中的每个讲次创建一个稳定详情单元。每讲根据同一课程级合同及冻结的标题、内容简介生成学习目标、内容边界、分项学时、重难点、教学活动、学习任务、案例资源和达成检验。全部详情单元一次入队，统一交给全局容量控制器调度并发，不再按“四讲一批、最多两批”等页面批次塑造后端链路。模型增量必须先保存为工作片段再真实流式投影；各讲可以乱序完成，但最终只由本地确定性规则按方案讲次顺序排序、校验课程级字段、讲数、逐讲学时与总学时，并汇编为同一份大纲工作稿。

各轮 Prompt 只说明本轮要生成的对象、生成依据和 JSON Schema，不用枚举下一轮字段作为负面禁令。轮次边界由 OpenSpec、Schema、后端归一化白名单与自动测试共同保证：模型返回 Schema 之外的字段时，后端丢弃这些字段；轻量讲次方案的修订身份也不能由后续模型响应改写。

每个详情单元绑定同一轻量方案修订 ID，只能补全本讲详情，不得改写讲数、顺序、讲次标题或教师编辑后的内容简介。检查点分别保存轻量方案、逐讲详情与失败原因；某讲失败时保留方案及其他讲次，只重试该讲。所有必需讲次结构可用后，完整大纲成为当前工作修订并停留在大纲页，不自动切换教案或启动任何下游任务。

### 1.2 生成完成直接形成当前工作修订

大纲、教案和讲义不设置人工确认门。模型返回非空且结构可用的结果后，任务即完成并写入当前工作修订，下游只检查这个修订是否存在、是否仍绑定当前上游来源；教师可以直接进入下一步，也可以随时编辑。编辑保存会形成新的当前修订，并使精确绑定旧来源的下游产物标记过期。

大纲、教案和讲义在任务内执行版本化结构校验；模型未返回内容、结构无法解析、来源过期或任务失败时只保留检查点并提供重试。结构可用的结果直接写入当前工作修订并解锁下一步，随后生成的质量审阅报告只提供改进建议，不改变完成状态，也不形成新的确认门。大纲工作台只保留低强调“查看大纲审阅”按钮，教师按需在弹窗查看摘要、位置和修复动作；报告不常驻正文或右栏。

### 2. 教师可见分类与内部策略分开

教师可见合同为：

```text
课程类别：只用于教务档案，不参与编排

课程级：
学习目的：系统学习 / 项目实战 / 期末冲刺
× 一级学科类型：八种完整学科合同之一
× 课程教学类型：理论课 / 实验课 / 实践课 / 研讨课 / 项目课 / 综合课
→ 大纲、讲次课型分布与必备教学环节

讲次级：
本讲目标 × 本讲课型 × 学科规则 × 课程级约束
→ 教学块
```

学习目的决定为什么学与最终结果，一级学科类型决定专业动作、成果证据和安全护栏，课程教学类型决定整课主导教学方式，本讲课型决定当前课堂主弧，教学块是这些约束结合当前内容、时长、难度与资料后的唯一编排结果。

旧概念按以下方式吸收：系统/项目/考试迁入学习目的；旧问题探究保留核心问题并迁入内部探究策略，默认推荐研讨课或适合学科的探究课型；学科细分变成一级学科合同中的条件规则；40 类 archetype 和 105 个模块变成内部专业动作；编排节奏变成课程教学类型执行规则。它们不再拥有教师可见的平行字段。

### 3. 整课语义与本讲课型分两级编译

系统先根据学习目的、一级学科合同与课程教学类型形成整课结构，再根据本讲目标、本讲课型、学科规则、课程约束、时长、难度和来源材料，通过唯一语义编译器形成教学块，并为每块保存：

```text
名称、作用、内容摘要、建议时间
教师动作、学习者行动、认知投入、预期产出、达成检查
达到 / 部分达到 / 未达到的反馈分支、调整选项
进入支持、分组方式与前后衔接
```

课程基础只显示学习目的、一级学科与课程教学类型；当前讲显示本讲准备、系统推荐课型、推荐理由与教学块摘要。系统自动把推荐课型与教学块保存为当前编排修订并允许立即生成教案；教师调整课型时形成新的当前编排修订，已有下游只标记过期。生成前不增加逐块增删排序编辑器；最终教学块在一讲一份的连续教案中可见，教师通过直接编辑教案或 AI 候选调整。任何调整都形成差异和影响，不得让 Prompt 在下游重新选择类型或块顺序。

完整大纲形成后，教案阶段先从同一当前大纲投影全课生成预览：课程目标、模块、讲次、顺序、每讲学时和总学时都只读同一课程真源，不要求教师重复填写课程表单。预览不是强制步骤条或新的确认门；全课设置没有必填项，资料和逐讲补充要求均为可选。默认主操作是“生成全部教案”，教师也可以在当前讲执行“只生成本讲”。

全课任务为所有符合条件的讲次一次创建稳定子任务并全部入队，由统一容量控制器并发调度；每讲真实流式投影自己的持久工作片段，完成即形成该讲当前教案，不等待其他讲次。单讲任务不要求前序讲次完成；任一讲失败只影响该讲并可独立重试。首次进入新课程默认第一讲，恢复已有课程时默认最近未完成、失败或受上游影响的讲次。

知识责任暂时归入教案，不前移为课程大纲字段。每讲教案生成阶段同时产出原子知识规范陈述、首次负责、复用、前置关系和完整教学块实施；不得先等待一个独立知识骨架模型任务完成后再启动详细教案。模型只做一次有业务意义的教案生成，本地根据返回对象分配稳定知识 ID、验证归属与引用、按讲内顺序汇编。知识 ID、内部关系键和模块 ID 不作为教师需要确认的中间产品；教师只在教案中查看自然语言的知识依据和最终课堂安排。

这套合同把教学从“内容与活动清单”推进为“学习调控系统”：教师不是照着 AI 流程执行，而是围绕目标组织学习者行动，读取可观察表现，并决定继续、补支架、重教、变式或提高挑战。课堂实施条件是编排输入，同一目标在不同时长、班额、设备、网络、安全和无障碍条件下可以采用不同进入与参与方式，但核心成果标准保持一致。

灵知当前只支持备课。教学块中的学习证据、检查方式和三档反馈是教师预先设计的课堂实施内容，随教案与讲稿一起审阅，不代表系统采集了真实课堂事实。当前变更不得新增授课视图、课中记录、学生表现采集或课后复盘资产；教师备课修改仍只通过大纲、教案、讲稿、题库和 PPT 的现有候选与修订关系处理。

### 4. 原文件与全课要求统一进入结构化更新链

来源优先级为：

```text
教师明确选择的主来源
> 当前成功且来源未过期的上游修订
> 教师选择的参考资料和联网来源
> 课程基本信息与系统模板
```

教师可在首次准备中同时上传大纲、教案、讲稿、PPT 及其他参考文件。上传弹窗只承担原件进入、解析进度与失败恢复；完成后进入独立的“审计与更新中心”。教师后续替换材料或直接提出全课调整，也进入这一中心。前端统一投影为“变化来源 → 生成关系/影响 → 教师判断 → 执行与回执”；后端仍由材料吸收与课程变更各自的领域命令产生工作稿或候选，不合并正式数据真源。

教师在生成页选择资料时，每个文件必须独立保存作用范围：全部讲次、一个连续讲次范围或若干指定讲次。启动大纲详情、全课教案或单讲任务时，系统冻结实际选中的文件修订、作用范围与补充要求为本轮输入快照；任务运行中新增、删除或改范围只影响下一轮，不静默改变在途结果。没有资料或补充要求时也可以生成。

独立中心以左侧变化来源、中间生成关系或影响范围、右侧变更详情为主结构，同时显示主/参考来源、课程位置、版本角色、解析质量、冲突、未变内容和历史回执。只有会改变结果的冲突才要求教师决定。教师可处理整次变化，也可只处理某个对象；其他对象的未决问题不得阻断当前已就绪对象。工作台各步骤不重复嵌入审计卡片，只保留一个课程级入口；从大纲、教案、讲稿、PPT 或课程文件进入时，返回必须恢复原备课位置。

执行只在 `TeacherLessonAuthoringRepository` 中创建带稳定修订 ID、来源块、页码/幻灯片位置、主参考角色与审计方案 ID 的结构化工作稿。工作稿符合对应正式对象的边界并成为当前可编辑修订；不改动原件，不覆盖历史修订，不写入学生可见课程。教师可以继续编辑，也可以直接以该当前修订进入下一生成步骤。同一审计方案重试必须幂等；局部执行保留已成功目标，只重做变化或失败目标。

DOCX 必须保留标题层级、列表、表格单元格、页眉页脚、图片/媒体存在性、公式、批注和修订痕迹边界；PDF 必须保留页码、文本块与可用区域，文本层失败时才进入逐页本地 OCR；PPTX 必须保留页、对象位置、图表系列、讲者备注、图片与动画存在性。无法理解的图片、动画顺序、批注采用状态和复杂版式只记录复核要求，不猜测语义。

### 5. 教案规定怎么教，讲义写出教师实际怎么讲

教案规定“为什么教、教什么、怎样组织、如何评价”，以教学块为骨架，并保存教师动作、学生活动、时间、资料工具、预期产出和检查方式。教师界面统一称下游详细文本为“讲义”，底层继续使用 `script` 兼容标识。讲义依据当前成功且来源未过期的教案修订，写出教师站在讲台上实际怎样讲：既包含定义、边界、推理、例题、辨析、实践任务与总结，也包含自然过渡、现场提问、可能回应、活动指令和反馈提示。每个讲义块稳定绑定一个教学块与知识范围；纯后台调度和内部生成语言不进入讲义，但对真实授课有用的教师语言必须保留。

讲义阶段默认提供“生成全部讲义”，一次为所有具备当前教案的讲次创建稳定子任务并交给共享容量控制器，保留“只生成本讲”。单讲输出在安全预算内时使用一个真实流式请求生成全部教学块；超出预算时，系统只把相邻且完整的教学块按预计输出量组成分片，所有分片在同一轮并行请求。每个分片都读取同一份冻结上下文合同：本讲目标与课型、完整教学块目录、当前分片教学块细节、知识与资料范围、术语表、前后语义衔接锚点和禁止重复责任。该合同由当前教案确定性编译，不额外调用模型。分片返回后按稳定教学块顺序本地汇编；缺块、截断、格式和明确重复只重试失败分片或相邻边界，不整讲二次重写。

真实吐字事件至少携带 `lesson_unit_id`、`block_id`、分片身份、递增序号和提供方文本增量。服务端先把可恢复片段写入任务检查点，再投影给前端；多个讲次或分片可以乱序吐字，前端必须写回对应教学块，不能用定时器切割完整结果模拟逐字输出。

旧一键课程的“正文”只提供知识内容原料，不能直接改名为讲稿。旧正文中的背景引入、概念讲解、过程推导、案例、练习、总结、学科产物完整性和前后连贯继续吸收；学生个性化、整课自动推进和旧发布语义不迁移。讲稿质量门必须同时检查专业完整、自然可讲、块间过渡、课堂提问与活动反馈，不能只检查教材内容是否齐全。

### 6. PPT 以当前讲义为语义真源，按资料现场三分流

正式来源链为：

```text
当前教案修订
→ 当前讲义修订
→ PPT 文书（逐页教学任务、主要结论、可见文案、页型、页数、版式与构图）
→ 文书质量门与修订冻结
→ 教师确认同一文书修订
→ SlideDeckV6 从已确认文书确定性编译
→ Web 预览与正式 PPTX 导出
```

PPT 文书是讲义到最终 PPT 之间的唯一逐页内容合同，记录 `source_lesson_plan_revision_id`、`source_script_revision_id`、每页讲义块来源和文书修订。无原版 PPT 时，只要当前教案与讲义修订存在且来源未过期，PPT 工作台即可启动。PPT 内部仍把页面内容稿作为独立任务：先生成、完整展示并由教师确认；第二步生成 PPT 在页面内容稿确认前保持锁定。第二步复用第一步的冻结检查点和同一文书修订，不能重新调用内容规划器悄悄改写。文书可以精简讲义、拆分页面和选择表达形式，但不得增加或改变知识。文书质量门阻断原始公式标题、页间重复、缺少页面任务/结论和故事规划降级；最终 PPT 渲染器只负责把已确认文书放入模板，不再写内容。教案或讲义变化只把受影响文书与 PPT 标记为过期，保留最后可用版本。

PPT 阶段独立拥有 `ppt-v6:{lesson_unit_id}` 来源关系，不自动沿用教案阶段的选择。具体分流为：

| 输入现场 | 内容方案 | 交付物 |
|---|---|---|
| 无额外资料、无 PPTX | 当前讲义是唯一内容源 | `讲义 → PPT 文书 → PPT` |
| 有主参考/参考/联网来源、无 PPTX | 讲义继续负责知识语义；额外资料按相关讲义块绑定，只指导案例、依据与页面表达 | `讲义 + 冻结资料 → PPT 文书 → PPT` |
| 已有 PPTX | 不重生成整套 PPT；保留原 PPTX，对照当前讲义、已选资料及其他当前教学资产 | `原 PPTX + 讲义 + 资料 → 审阅报告` |

参考资料不是第二份讲稿。规划器可看到与当前讲稿块相关的证据摘要，但可见文案、标题、公式、数字与识别符仍必须受已绑定讲稿块支持。`ppt_manuscript_v1` 同时冻结资料关系与每页证据 ID，使变更、重试和导出都可追溯。

### 7. 所有教师生成共用任务和修订底座

资产生成可以使用不同任务类型，但只能有一个任务所有者和一个修订真源：

```text
TaskManager：任务 ID、阶段、心跳、检查点、取消、恢复和幂等
TeacherLessonAuthoringRepository：大纲、教案、讲义和 PPT 的当前工作修订与历史版本
领域生成器：只负责从冻结输入产生候选或工作片段
```

SSE 只是任务投影，断线后从持久化工作片段恢复。任何失败不得清空已通过的任务检查点或覆盖最后可用版本。模型未返回内容、结构无法解析或任务失败时不能写入新修订、不能解锁下游；失败讲次只保留检查点并可单独重试。结构可用结果形成当前修订后，质量建议可以标记为 `completed_with_warnings`，但不得阻断下游或要求教师先查看。旧报告在合同版本变化后重新计算，不能充当新修订的结构校验结果。

返回协议也复用现有生成和候选接口：耐久任务投影已保存的工作片段；自由文本只转发提供方真实增量；短时结构化候选使用同一通用包装返回开始、心跳和终态结果，不展示半截 JSON。本地提供方如果只能整段返回，保留真实的等待状态和整段结果，不在返回后人工切块伪造流式。

状态同步只负责读取并恢复已经存在的任务、当前修订和页面位置。监听器、路由守卫、轮询器和恢复逻辑不得因为进入编辑、保存草稿、收到审阅报告或发现上游变化，就自动关闭编辑、继续下一段生成、切换阶段或重新生成下游。上游变化只能标记精确下游“需更新”，最后可用版本继续保留，是否更新由教师的下一次可见操作决定。

### 7.1 工作台导航与右栏只投影当前真实任务

左侧一级导航固定表示大纲、教案、讲义、PPT 阶段。大纲是整课对象，不展开讲次二级目录；教案、讲义和 PPT 固定显示同一讲次二级目录，不因空态、生成态或编辑态消失。每讲用两行分别显示讲次身份和当前阶段的真实状态，状态只来自持久任务与当前修订，例如未生成、排队中、生成中、已完成、需更新或失败；审阅建议不得伪装成生成状态。

右栏不常驻 AI 助手，也不复制左侧讲次列表。生成前只显示本阶段资料准备、各文件讲次范围与可选补充要求；生成中切换为当前讲任务详情、实际输入快照、真实进度和可用控制；生成后显示当前版本、上游修订与实际使用依据。教师主动调用 AI 修改时仍复用现有候选与课程调整能力，但不得由右栏监听器自动打开、自动应用或改变生产阶段。

### 8. 旧链能力按矩阵迁移，不按文件搬家

| 能力 | 旧链资产 | 新主线归宿 | 迁移原则 |
| --- | --- | --- | --- |
| 课程要求与四种旧 `course_type` | 课程生成请求、类型合同 | 三种学习目的、六种课程教学类型与兼容适配器 | 系统/项目/考试直接迁入学习目的；问题探究保留核心问题，迁入内部策略并推荐研讨课或适合学科的探究课型 |
| 大纲规划 | 目录规划、章节命名、时长约束 | 教师大纲任务 | 复用成熟规划器，生成完整大纲后停止 |
| 教学策略 | `course_pedagogy.py`、subject variant、40 类 archetype、105 个模块 | 八种一级学科合同、六种课程教学类型合同、七种本讲课型模板、内部专业动作库与统一编排器 | 复用成熟规则，不保留平行产品状态 |
| 教案 | `CourseTeachingPlanV3`、质量门、知识锚点 | 按讲教案修订 | 有机融合，禁止覆盖成熟结构 |
| 正文 | 学科模板、逻辑块、并发与降级 | 可直接讲授的教师讲稿块生成 | 选择性吸收知识内容和完整性，重新生成自然教师讲述，不迁移学生视角和整课流程 |
| PPT | 旧课件来源适配与版本 | `PPT文书 → SlideDeckV6 → PPTX` | 文书只投影当前讲义，模板渲染不写知识，旧版本保留只读 |
| 资料 | 检索、正文读取、来源分级 | 当前讲主来源/参考/联网来源 | 作用域跟随当前讲，原件不变真源 |
| 任务与质量 | 检查点、幂等、批次、质量门 | 统一 TaskManager 与资产质量门 | 只保留一个状态所有者 |

### 9. 题库、日历和其他课程文件是旁支

题库可使用课程与讲次上下文生成，但可跳过；教学日历是正式文件类型并使用学校模板生成；评分细则和考试课程材料自查清单作为“其他课程文件”下的直接左栏入口，点击即进入对应结构化表单，不再经过“配套文档”汇总页。底层继续共用同一套模板和正式文件数据，不建立第二份真源。这些文件均进入文件空间并可引用其他正式资产，但不阻断教案、讲义、PPT。

### 10. 旧教师整课链按门退场

迁移门如下：

1. **G0 合同冻结**：标准语言、资产图、来源优先级和生成准入条件写入正式文档与规格。
2. **G1 能力盘点**：旧链每项成熟能力、提示词、测试和数据均有保留、迁移或废弃结论。
3. **G2 新链接管**：新工作台只调用共享领域服务，不再向旧教师整课真源新增正式写入。
4. **G3 只读兼容**：历史教师资产完成抽样迁移和对账，旧入口只读，仍可回退读取最后可用版本。
5. **G4 删除退场**：生产调用为零、迁移与回滚演练通过后，删除旧教师 UI、API、路由和专属写入。学生使用的共享能力不能随旧教师入口一起删除。

### 11. 备课助手只做按需能力调度，不占用生产右栏

备课助手不作为课程工作台右栏的常驻切换页。教师通过明确的 AI 修改入口主动提出要求后，系统使用三类稳定能力：要求不清楚时先澄清；只影响当前大纲、教案、讲义、题库或 PPT 对象时调用该对象原有候选接口；涉及多个资产、整课批量替换，或改变章讲小节身份与顺序时，调用现有 `CourseEvolutionPlan`。这一判断在模型调用前完成，避免用一次额外模型请求只做接口分流。

整课方案继续复用原影响审阅、结构确认、下游候选、逐项排除、采用、回执和撤销机制，页面进入同一课程“审计与更新中心”。按需入口只投影方案 ID、处理状态和影响摘要；它不保存课程内容，不复制 `CourseEvolutionPlan`，也不直接执行正式写入。学习者 AI 老师仍负责解释、学习记录和个人调整，不与教师备课权限混用。

工作区的审阅是方案本身的结构化编辑，不是第二轮对话。教师可在原 `review` 接口直接改变单元处理方式、批量纳入或排除，也可编辑完整候选课程树。后端用调整后的数据重新编译同一方案的操作组，旧候选失效后由原 `generate` 接口定向补齐。自然语言“修正理解”仍会产生新方案，但新方案通过 `supersedes_plan_id` 记录来源，旧方案明确转为已取代，不再并列留作待处理任务。

恢复也复用原接口：候选生成再次调用 `generate` 时保留已成功操作，只补失败或缺失迁移；正式应用的部分失败则在原 `accept` 接口传入 `retry_failed`，只把失败的下游操作 ID 交回原资产执行器；课程文档操作组和已成功资产不重放。

### 12. 课程目标与预期成果关联是大纲内部关系

`learning_objectives`、`education_objectives` 和 `measurable_outcomes` 继续保存大纲正文。`outcome_alignment` 只保存成果序号到目标、讲次、评价证据和覆盖范围的关系，不复制成果正文。正式大纲页面和导出文档由同一结构投影关联表；旧课程缺失关联时显示待补充并进入整篇审读建议，不影响原大纲阅读。

## Risks / Trade-offs

- **同一底层服务被误认为两条链**：任务类型可以不同，但教师编排入口、资产真源和生成准入规则只能有一套；用调用图和写入测试防止分叉。
- **原教案吸收时丢失教师习惯**：默认忠实保留结构和表达，系统建议只形成候选；解析不确定部分明确标记。
- **讲稿、PPT 文书和最终 PPT 再次双源**：PPT 文书强制引用确认讲稿修订，禁止同时把整段讲稿和教案模块拼成两个语义来源；最终 PPT 只渲染文书。
- **旧链删除过早**：每个退场动作绑定数据审计、生产调用和回滚证据；未过门只允许兼容，不删除。
- **分类让教师负担过重**：课程级只选择学习目的、一级学科和课程教学类型，讲次级可以按需修改本讲课型；学科细分、专业动作和编排细节由系统解释，不再要求教师逐步确认旧多层分类。

## Migration Plan

1. 完成 G0：冻结正式语言、资产图、来源优先级和生成准入条件。
2. 建立新旧字段适配器，按“明确新字段 > 明确旧字段 > 系统推断 > 安全默认”解析并记录来源。
3. 把学科细分、archetype、编排节奏和模块注册表迁入一级学科合同、课程教学类型合同、本讲课型模板和专业动作库，建立唯一语义编译入口。
4. 完成 G1：审计旧整课链与新工作台代码、提示词、测试、数据和调用，建立可追踪能力矩阵。
5. 复用成熟大纲与教案服务，让新工作台只负责分步编排和交互投影。
6. 选择性吸收旧正文的知识模板与逻辑块，建立教学块到可直接讲授的教师讲稿块的稳定映射和质量门。
7. 让 V6 从当前讲义先形成可审阅的 PPT 文书，再确定性渲染，并补齐精确过期、定向重建、失败保留和版本回退。
8. 统一任务、质量和恢复，完成三种学习目的、八种学科、六种课程教学类型和七种本讲课型的代表性组合及真实模型与浏览器主路径验收。
9. 依次通过 G2、G3、G4，关闭并删除旧教师整课入口。

回滚时恢复上一稳定工作台调用适配器并继续读取最后可用修订；禁止用回滚覆盖教师已上传原件、历史资产或学生学习数据。

逐项能力所有者、提示词处理方式、已确认缺口和退场证据维护在[教师课程生产能力迁移清单](./能力迁移清单.md)。该清单只记录当前代码核验结论；实施勾选仍以 `tasks.md` 为准。
