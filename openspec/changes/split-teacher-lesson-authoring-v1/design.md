## Context

当前教师课程生产能力来自两组实现：

- 旧整课链：`course_generation_workflow.py`、`course_service.py`、`task_manager.py` 以及旧生成对话框和 generation store。它擅长从课程要求一路规划大纲、教案、正文和练习，已经积累了提示词、并发、检查点、降级与质量门，但任务边界过大，不适合教师逐讲备课。
- 新工作台链：`teacher_lesson_authoring.py`、`teacher_script.py`、`SlideDeckV6` 及教师工作台组件。它允许资产独立创建、按讲选择资料、编辑、确认和恢复，符合教师从任意已有材料继续工作的方式，但部分生成能力尚未复用完整，尤其是讲稿和 PPT。

因此目标不是维护两条链，也不是为新界面重写一套后端，而是把旧链拆成可复用能力，由新工作台成为唯一教师编排入口。

## Goals / Non-Goals

**Goals:**

- 冻结课程层级、产品术语、正式资产和上下游边界。
- 形成唯一教师主链：`课程基础 → 大纲与讲次课型分布 → 本讲课型 → 教学块 → 教案 → 讲稿 → PPT 文书 → PPT`。
- 支持从零生成、从上传原文件吸收、从任一已有正式资产继续三种入口。
- 大纲与教案优先复用当前成熟实现；讲稿与 PPT 重点吸收旧正文和旧课件链能力。
- 每一步都具有可见进度、工作稿、确认、失败保留、恢复和修订来源。
- 逐步关闭旧教师整课写入口，同时保持学生学习运行时兼容。

**Non-Goals:**

- 不把题库、日历和配套文档强行串进教案到 PPT 的阻塞链。
- 不把旧学科细分、内部 40 类 archetype、编排节奏、提示词选择或技术模块名直接展示给教师。
- 不因合同冻结一次性删除旧代码、迁移全部历史课程或重写成熟大纲与教案。
- 不在本变更内改造学生学习、练习、笔记和 AI 老师运行时。

## Decisions

### 1. 课程结构和生产边界固定

正式层级为：

```text
课程
└── 章：知识结构和大纲组织边界
    └── 讲（LessonUnit）：备课、授课、资料、任务、版本和恢复边界
        └── 讲内小节：一讲内部的内容组织边界
```

“章”不承担生成任务恢复；“讲内小节”不复制一份独立正式教案。每讲拥有一份可修订教案、一份正式讲稿和一组 PPT 版本。

### 2. 教师可见分类与内部策略分开

教师可见合同为：

```text
课程类别：只用于教务档案，不参与编排

课程级：
学习目的：系统学习 / 项目实战 / 期末冲刺
× 一级学科类型：八种完整学科合同之一
× 课程教学类型：理论课 / 实验课 / 实践课 / 研讨课 / 项目课 / 综合课
→ 大纲、讲次课型分布与必备教学环节

讲次级：
本讲目标 × 本讲课型 × 学科规则 × 课程级约束
→ 教学块
```

学习目的决定为什么学与最终结果，一级学科类型决定专业动作、成果证据和安全护栏，课程教学类型决定整课主导教学方式，本讲课型决定当前课堂主弧，教学块是这些约束结合当前内容、时长、难度与资料后的唯一编排结果。

旧概念按以下方式吸收：系统/项目/考试迁入学习目的；旧问题探究保留核心问题并迁入内部探究策略，默认推荐研讨课或适合学科的探究课型；学科细分变成一级学科合同中的条件规则；40 类 archetype 和 105 个模块变成内部专业动作；编排节奏变成课程教学类型执行规则。它们不再拥有教师可见的平行字段。

### 3. 整课语义与本讲课型分两级编译

系统先根据学习目的、一级学科合同与课程教学类型形成整课结构，再根据本讲目标、本讲课型、学科规则、课程约束、时长、难度和来源材料，通过唯一语义编译器形成教学块，并为每块保存：

```text
名称、作用、内容摘要、建议时间、教师活动、学生活动、预期产出、达成检查
```

课程基础只显示学习目的、一级学科与课程教学类型；当前讲显示本讲课型。教师启动生成时，系统锁定当前课型和编排结果并流式生成教案正文，不增加生成前的逐块编辑页。最终教学块在教案中可见，教师通过直接编辑教案或 AI 候选调整；任何调整都形成差异和影响，不得让 Prompt 在下游重新选择类型或块顺序。

### 4. 原文件先吸收，再进入正式修订

来源优先级为：

```text
教师明确选择的主来源
> 已确认的上游正式资产
> 教师选择的参考资料和联网来源
> 课程基本信息与系统模板
```

教师上传原教案并指定为主来源时，系统先解析其分块、顺序、字段和原文，形成结构化工作修订；默认保留原结构和表达，只补齐缺失字段。若来源与系统建议冲突，界面展示冲突和候选，不静默覆盖。原文件保留在资料空间，正式教案保存在系统真源，两者以来源关系连接。

### 5. 教案规定怎么教，讲稿写出教师实际怎么讲

教案规定“为什么教、教什么、怎样组织、如何评价”，以教学块为骨架，并保存教师动作、学生活动、时间和检查方式。讲稿依据已确认教案写出教师站在讲台上实际怎样讲：既包含定义、边界、推理、例题、辨析、实践任务与总结，也包含自然过渡、现场提问、活动指令、可能回应和反馈提示。每个讲稿块稳定绑定一个教学块与知识范围；纯后台调度和内部生成语言不进入讲稿，但对真实授课有用的教师语言必须保留。

旧一键课程的“正文”只提供知识内容原料，不能直接改名为讲稿。旧正文中的背景引入、概念讲解、过程推导、案例、练习、总结、学科产物完整性和前后连贯继续吸收；学生个性化、整课自动推进和旧发布语义不迁移。讲稿质量门必须同时检查专业完整、自然可讲、块间过渡、课堂提问与活动反馈，不能只检查教材内容是否齐全。

### 6. PPT 以已确认讲稿为语义真源，按资料现场三分流

正式来源链为：

```text
已确认教案修订
→ 已确认讲稿修订
→ PPT 文书（逐页教学任务、主要结论、可见文案、页型、页数、版式与构图）
→ 文书质量门与修订冻结
→ 教师确认同一文书修订
→ SlideDeckV6 从已确认文书确定性编译
→ Web 预览与正式 PPTX 导出
```

PPT 文书是讲稿到最终 PPT 之间的唯一逐页内容合同，记录 `source_lesson_plan_revision_id`、`source_script_revision_id`、每页讲稿块来源和文书修订。无原版 PPT 时，PPT 工作台必须把它做成第一步独立任务：先生成、完整展示并由教师确认；第二步生成 PPT 在确认前保持锁定。第二步复用第一步的冻结检查点和同一文书修订，不能重新调用内容规划器悄悄改写。文书可以精简讲稿、拆分页面和选择表达形式，但不得增加或改变知识。文书质量门阻断原始公式标题、页间重复、缺少页面任务/结论和故事规划降级；最终 PPT 渲染器只负责把已确认文书放入模板，不再写内容。教案或讲稿变化只把受影响文书与 PPT 标记为过期，保留最后可用版本。

PPT 阶段独立拥有 `ppt-v6:{lesson_unit_id}` 来源关系，不自动沿用教案阶段的选择。具体分流为：

| 输入现场 | 内容方案 | 交付物 |
|---|---|---|
| 无额外资料、无 PPTX | 确认讲稿是唯一内容源 | `讲稿 → PPT 文书 → PPT` |
| 有主参考/参考/联网来源、无 PPTX | 讲稿继续负责知识语义；额外资料按相关讲稿块绑定，只指导案例、依据与页面表达 | `讲稿 + 冻结资料 → PPT 文书 → PPT` |
| 已有 PPTX | 不重生成整套 PPT；保留原 PPTX，对照确认讲稿、已选资料及其他当前教学资产 | `原 PPTX + 讲稿 + 资料 → 审阅报告` |

参考资料不是第二份讲稿。规划器可看到与当前讲稿块相关的证据摘要，但可见文案、标题、公式、数字与识别符仍必须受已绑定讲稿块支持。`ppt_manuscript_v1` 同时冻结资料关系与每页证据 ID，使变更、重试和导出都可追溯。

### 7. 所有教师生成共用任务和修订底座

资产生成可以使用不同任务类型，但只能有一个任务所有者和一个修订真源：

```text
TaskManager：任务 ID、阶段、心跳、检查点、取消、恢复和幂等
TeacherLessonAuthoringRepository：大纲、教案、讲稿和 PPT 的工作/确认修订指针
领域生成器：只负责从冻结输入产生候选或工作片段
```

SSE 只是任务投影，断线后从持久化工作片段恢复。任何失败不得清空已生成片段或覆盖最后确认版本。提供方失败后可以保存明确标记的恢复草稿以便继续编辑，但恢复内容不等于模型成功，也不具备确认或 PPT 准入资格；只有真实模型正文或教师完整修订同时通过当前结构、教学实质、来源和整讲质量门后才能确认。旧质量报告在合同版本变化后必须重新计算，不能沿用历史 `passed`。

### 8. 旧链能力按矩阵迁移，不按文件搬家

| 能力 | 旧链资产 | 新主线归宿 | 迁移原则 |
| --- | --- | --- | --- |
| 课程要求与四种旧 `course_type` | 课程生成请求、类型合同 | 三种学习目的、六种课程教学类型与兼容适配器 | 系统/项目/考试直接迁入学习目的；问题探究保留核心问题，迁入内部策略并推荐研讨课或适合学科的探究课型 |
| 大纲规划 | 目录规划、章节命名、时长约束 | 教师大纲任务 | 复用成熟规划器，确认后停止 |
| 教学策略 | `course_pedagogy.py`、subject variant、40 类 archetype、105 个模块 | 八种一级学科合同、六种课程教学类型合同、七种本讲课型模板、内部专业动作库与统一编排器 | 复用成熟规则，不保留平行产品状态 |
| 教案 | `CourseTeachingPlanV3`、质量门、知识锚点 | 按讲教案修订 | 有机融合，禁止覆盖成熟结构 |
| 正文 | 学科模板、逻辑块、并发与降级 | 可直接讲授的教师讲稿块生成 | 选择性吸收知识内容和完整性，重新生成自然教师讲述，不迁移学生视角和整课流程 |
| PPT | 旧课件来源适配与版本 | `PPT文书 → SlideDeckV6 → PPTX` | 文书只投影确认讲稿，模板渲染不写知识，旧版本保留只读 |
| 资料 | 检索、正文读取、来源分级 | 当前讲主来源/参考/联网来源 | 作用域跟随当前讲，原件不变真源 |
| 任务与质量 | 检查点、幂等、批次、质量门 | 统一 TaskManager 与资产质量门 | 只保留一个状态所有者 |

### 9. 题库、日历和配套文档是旁支

题库可使用课程与讲次上下文生成，但可跳过；教学日历是正式文件类型并使用学校模板生成；评分细则、自查清单等配套文档通过二级模板库快捷生成。它们均进入文件空间并可引用其他正式资产，但不阻断教案、讲稿、PPT。

### 10. 旧教师整课链按门退场

迁移门如下：

1. **G0 合同冻结**：标准语言、资产图、来源优先级和确认门写入正式文档与规格。
2. **G1 能力盘点**：旧链每项成熟能力、提示词、测试和数据均有保留、迁移或废弃结论。
3. **G2 新链接管**：新工作台只调用共享领域服务，不再向旧教师整课真源新增正式写入。
4. **G3 只读兼容**：历史教师资产完成抽样迁移和对账，旧入口只读，仍可回退读取最后可用版本。
5. **G4 删除退场**：生产调用为零、迁移与回滚演练通过后，删除旧教师 UI、API、路由和专属写入。学生使用的共享能力不能随旧教师入口一起删除。

## Risks / Trade-offs

- **同一底层服务被误认为两条链**：任务类型可以不同，但教师编排入口、资产真源和确认规则只能有一套；用调用图和写入测试防止分叉。
- **原教案吸收时丢失教师习惯**：默认忠实保留结构和表达，系统建议只形成候选；解析不确定部分明确标记。
- **讲稿、PPT 文书和最终 PPT 再次双源**：PPT 文书强制引用确认讲稿修订，禁止同时把整段讲稿和教案模块拼成两个语义来源；最终 PPT 只渲染文书。
- **旧链删除过早**：每个退场动作绑定数据审计、生产调用和回滚证据；未过门只允许兼容，不删除。
- **分类让教师负担过重**：课程级只确认学习目的、一级学科和课程教学类型，讲次级只确认本讲课型；学科细分、专业动作和编排细节由系统解释，不再要求教师理解旧多层分类。

## Migration Plan

1. 完成 G0：冻结正式语言、资产图、来源优先级和确认门。
2. 建立新旧字段适配器，按“明确新字段 > 明确旧字段 > 系统推断 > 安全默认”解析并记录来源。
3. 把学科细分、archetype、编排节奏和模块注册表迁入一级学科合同、课程教学类型合同、本讲课型模板和专业动作库，建立唯一语义编译入口。
4. 完成 G1：审计旧整课链与新工作台代码、提示词、测试、数据和调用，建立可追踪能力矩阵。
5. 复用成熟大纲与教案服务，让新工作台只负责分步编排和交互投影。
6. 选择性吸收旧正文的知识模板与逻辑块，建立教学块到可直接讲授的教师讲稿块的稳定映射和质量门。
7. 让 V6 在确认讲稿之后先形成可审阅的 PPT 文书，再确定性渲染，并补齐精确过期、定向重建、失败保留和版本回退。
8. 统一任务、质量和恢复，完成三种学习目的、八种学科、六种课程教学类型和七种本讲课型的代表性组合及真实模型与浏览器主路径验收。
9. 依次通过 G2、G3、G4，关闭并删除旧教师整课入口。

回滚时恢复上一稳定工作台调用适配器并继续读取最后确认修订；禁止用回滚覆盖教师已上传原件、已确认正式资产或学生学习数据。

逐项能力所有者、提示词处理方式、已确认缺口和退场证据维护在[教师课程生产能力迁移清单](./能力迁移清单.md)。该清单只记录当前代码核验结论；实施勾选仍以 `tasks.md` 为准。
