# 教师课程生产能力迁移清单

> 状态：G1 能力盘点第一版<br>
> 核验日期：2026-08-27<br>
> 核验对象：当前 `main` 的前端路由、工作台、后端路由、领域服务、任务与聚焦测试<br>
> 用途：决定旧整课链的能力如何被新工作台吸收；不是删除清单，也不替代 `tasks.md`

## 1. 当前两套实现的真实边界

### 1.1 当前正式教师入口

正式入口是 `/courses` 和 `/course/:courseId/workspace/:mode`：

```text
TeacherTeachingCalendarView
→ TeacherCourseLibraryView / TeacherCourseCreateView
→ CourseWorkspaceView
→ TeacherCourseWorkbench
```

旧 `/teacher/course/:courseId/...` 地址已经在 `frontend/src/router/index.ts` 重定向到同一课程空间、学生视角预览或 V6 PPT 工作台。`TeacherCourseProductionView.vue`、`TeacherCourseOverviewView.vue`、`TeacherCourseFilesView.vue` 和非嵌入式 `TeacherCourseSidebar.vue` 仍保留源码，但不再由正式路由挂载；它们属于 G3 调用审计对象，不是新功能应继续依赖的页面。

### 1.2 新工作台仍在复用旧链的部分

新工作台生成大纲时，经 `CourseWorkspaceView.startOutlineGeneration` 调用 `courseStore.generateCourse`，再进入 `/api/course-generation/generate`。请求携带 `target_course_id` 和 `teacher_authoring_mode=lesson_assets_v1`，后端把它投影为教师大纲任务。也就是说，新工作台是新的教师编排壳，但大纲规划、任务和部分数据仍合理复用旧整课链能力。

因此不能按文件名把 `course_generation` 整体删除。必须把“教师入口”“共享生成能力”“学生整课运行时”分开判断。

## 3. 提示词与模板的迁移判断

### 3.1 直接保留

- 大纲：`build_outline_skeleton_v2_prompt`、`build_outline_batch_v2_prompt` 及校正提示词。
- 教案：`build_teaching_plan_skeleton_v3_prompt`、`build_teaching_plan_batch_v3_prompt`、知识细节和关系字段修复提示词。
- 教案 AI 优化：当前紧凑字段合同、最小充分修改和小节身份保护。
- V6：故事规划、来源保真、布局容量和视觉修复合同。
- 灵知正式真源：课程基线、结构化大纲、`CourseTeachingPlanV3`、教学块、来源与修订边界全部保留，外部模板不得覆盖。

### 3.2 拆开吸收

外部正式大纲/教案模板按三层吸收：

1. 字段层：课程基本信息、定位与简介、教学目标、考核、学时安排、参考资料。
2. 生成层：知识与能力、过程与方法、可选迁移与创新，以及“任务进入 → 核心教学 → 学习者行动 → 检查证据”的职责闭环。
3. 投影层：从现有真源确定性渲染高校正式大纲和教案；缺少来源时明确为未确认，不编造书目、案例或数据。

这三层由 `course_authoring_templates.py` 统一版本化；提示词只读取契约，导出只读取正式数据，不保存平行大纲或教案正文。

旧 `build_content_prompt` 不整体搬入讲稿。需要逐项抽取并建立测试：

1. 八种一级学科合同及其内容条件对应的讲解行为；
2. 背景引入、概念讲解、过程推导、案例、示范、练习、互动、检查、总结等逻辑块约束；
3. 前后小节连贯性、知识范围和资料依据；
4. 输入预算、超时、一次结构修复和可信降级；
5. 代码、公式、表格等学科产物的完整性。

这些能力进入“教学块 → 教师讲稿块”的策略选择器；学生自学口吻、学习者个性化、发布 CourseDocument、整节自由重写和练习发布不迁入讲稿。教师现场讲述不是旧正文能力的直接搬运，而是依据已确认教案重新生成的自然过渡、提问、活动指令和反馈提示。

### 3.3 逐步退场

- 旧教师整课页面和未挂载侧栏：先确认无动态导入和生产访问，再删除。
- 旧轻量教师 PPT 生成/候选：V6 全部覆盖历史需求后改为只读导出，再删除写入口。
- 旧教师整课任务的正文、练习和发布阶段：新工作台不再创建后进入只读兼容；学生仍使用的共享代码不删除。

## 4. 旧教学链资产的唯一归宿

旧链不再作为产品结构保留，而是按“保留、吸收、内化、退场”榨干。每项资产只有一个新拥有者：

| 旧资产 | 里面具体有什么 | 新拥有者 | 处理方式与当前状态 |
| --- | --- | --- | --- |
| 四种旧 `course_type` | 系统学习、项目实战、问题探究、考试冲刺及对应必填信息 | 学习目的、具体课程目标、内部策略 | 系统/项目/考试已单向转换；问题探究保留核心问题，学习目的按结果判断并默认推荐研讨课；历史批量对账待完成 |
| 八种学科与旧学科细分 | 学科识别、专业行为、证据、产物、安全护栏和内容条件 | 八种一级学科标准库 | 一级名称保留；二级名称不再展示，识别依据和行为规则吸收到一级合同；完整版本化待完成 |
| 40 类 archetype | 针对内容阶段选择的目的、教学动作、成果和护栏 | 学科条件规则与内部专业动作库 | 不再作为产品分类；逐项去重吸收，当前仍由旧策略兼容读取 |
| 学术基础、应用导向、成果驱动 | 整课内容重心和结果倾向 | 课程教学类型与具体课程目标 | 分别吸收到理论/综合、实践/研讨、项目及交付物要求，不再单列“课程定位” |
| 讲练一体、问题驱动、案例研讨 | 整课组织倾向或单讲主弧 | 课程教学类型执行规则或本讲课型 | 按作用范围迁移，不再单列“教学组织偏好” |
| 解释与推理、分析与迁移、设计与实作 | 学习者要表现出的能力和评价重心 | 具体课程目标、教学块产出与成果证据 | 作为可观察行为和评价标准保存，不再单列“能力重点” |

| 七种旧 `lesson_type` | 理论、讲练、实践、案例、实验探究、项目、复习的课堂主弧 | 七种本讲课型模板 | 名称和价值保留；已参与每讲推荐与教学块排序 |

## 5. 下一实施切片

按风险和依赖，下一阶段不是先删旧代码，而是连续完成以下纵向切片：

1. **教学语义第二版已接入**：新旧字段适配、教学定义、课程合同、讲次课堂弧、推荐依据和可执行教学块合同已有同一入口；下一步把旧学科细分、archetype、节奏和模块彻底迁入版本化标准库与专业动作库。
2. **课程基础新交互已完成**：学习目的、一级学科和课程教学类型已取代旧生成偏好；下一步在当前讲清楚显示本讲课型、推荐依据、最终教学块和修改影响。
3. **教案与讲稿耐久切片已完成**：教案按 V3 规划批次保存检查点，讲稿逐块持久化；教师停止或失败后都可沿用相同输入继续剩余单元。
4. **教师讲稿升级已完成代码接入**：八类学科产物、知识边界、连贯、代码/公式/表格完整性、自然口语、块间过渡、提问、活动指令和反馈已进入同一生成器与 V7 发布门；下一步做真实模型跨学科对照。
5. **V6 来源、PPT 文书与轻量 PPT 已初步收束**：V6 只消费确认讲稿块，`ppt_manuscript_v1` 已成为逐页内容与渲染之间的显式合同，旧轻量 PPT 写链已删除，历史数据只保留只读导出。

教学语义和教师讲稿完成真实模型对照后，再收紧 V6 来源并启动旧轻量 PPT 与旧教师页面的 G3 只读审计。

## 6. 尚未核验的退场条件

以下内容没有证据前不得标记完成：

- 真实课程数据中旧教案、旧正文和旧 PPT 的数量、来源与最后访问时间；
- 生产日志中 `/api/course-generation/generate` 的教师/学生调用分布；
- 旧教师页面是否仍被外部书签、演示脚本或自动化访问；
- DOCX/PDF 原教案已能真实解析浙大理论课、实践课样例，但端到端生成后的字段级结构保真率仍未核验；
- 旧正文模板迁入讲稿后跨学科真实模型质量；
- 统一任务后教案、讲稿、V6 的断线、重启、重复点击和幂等矩阵。
