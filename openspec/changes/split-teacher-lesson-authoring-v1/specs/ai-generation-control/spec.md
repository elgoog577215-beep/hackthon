## ADDED Requirements

### Requirement: 四阶段生成必须暴露一致的控制动作

教学大纲、分讲教案、讲义和 PPT MUST 根据同一任务状态提供一致动作：运行中可暂停或取消，暂停后可继续或取消，失败后可重试，完成后可重新生成。清除操作 MUST 只清除本次未完成片段，不得删除当前可用修订、历史版本或最后可用产物。所有控制 MUST 使用真实任务 ID，页面不得用本地布尔值伪造完成或取消结果。

#### Scenario: 清除失败讲次的工作稿

- **WHEN** 第三讲教案任务失败且已有上一版可用教案
- **THEN** 教师可以清除本次失败任务的工作片段并重新生成
- **AND** 上一版可用教案、历史版本和其他讲次保持可用

### Requirement: 全课教案生成必须是父任务与按讲子任务

系统 MUST 支持一次选择可选课程资料和补充要求后启动全课教案生成父任务，并为每个计划讲次建立拥有稳定任务 ID 的子任务。所有符合条件的子任务 MUST 一次入队，由共享容量控制器统一并发调度，不得按讲次顺序串行等待。父任务 MUST 汇总排队、完成、运行、暂停和失败数量；每个子任务 MUST 可独立暂停、继续、取消、重试和查看失败原因。

#### Scenario: 只重试失败讲次

- **WHEN** 十二讲中十讲完成、一讲暂停、一讲失败
- **THEN** 父任务显示真实汇总状态且保留十讲结果
- **AND** 教师可以只继续暂停讲或只重试失败讲

#### Scenario: 全部讲次一次入队

- **WHEN** 教师对十二讲课程点击“生成全部教案”
- **THEN** 系统一次创建并入队十二个稳定子任务，再由统一并发额度决定同时运行数量
- **AND** 页面不得把“上一讲完成”作为下一讲开始的业务条件

### Requirement: 全课讲义生成必须复用父任务与按讲子任务合同

系统 MUST 让全课讲义与全课教案复用同一父任务聚合和按讲子任务控制语义。所有符合条件的讲义子任务 MUST 一次入队并由共享容量控制器并发调度；父任务只汇总真实子任务状态，不得把讲次顺序或教学块顺序变成模型请求的串行锁。

#### Scenario: 只重试失败讲义

- **WHEN** 十二讲讲义中十一讲完成而第七讲失败
- **THEN** 父任务保留十一讲结果并显示第七讲失败原因
- **AND** 重试只创建或恢复第七讲的未完成分片

### Requirement: 教师资产任务必须共用统一控制合同
系统 MUST 为教师大纲、教案、讲稿和 PPT 任务使用同一任务所有者，统一任务 ID、幂等键、阶段、心跳、检查点、取消、失败保留和恢复语义。任务类型可以不同，但不得各自维护平行状态机或正式资产真源。

#### Scenario: 重复点击生成教案
- **WHEN** 教师在同一讲、相同冻结输入下重复点击生成
- **THEN** 系统返回或恢复同一活动任务
- **AND** 不创建两份竞争的教案工作修订

### Requirement: 等待教师继续不得伪装为后台运行或人工确认

轻量讲次方案完成后，任务 MUST 进入持久的主动等待状态并停止发起详情模型请求。该状态 MUST 表示“方案可编辑，等待教师明确继续”，不得复用 `waiting_for_review`、`confirmed` 或后台运行状态。进程重启、页面刷新和任务恢复 MUST 保留该等待现场，但 MUST NOT 自动继续生成完整大纲。

#### Scenario: 在轻量方案停点重启服务

- **WHEN** 课程方案已生成且教师尚未点击继续时服务重启
- **THEN** 任务恢复为同一主动等待状态，当前方案修订保持可编辑
- **AND** 系统不创建任何讲次详情模型请求

#### Scenario: 教师查看轻量讲次方案

- **WHEN** 轻量方案生成完成并等待教师继续
- **THEN** 页面只显示可编辑的讲次顺序、标题和内容简介
- **AND** 不显示课程目标、学时分配、知识模块、考核方式和教学日历等未生成的完整大纲字段

### Requirement: 大纲各轮 Prompt 必须描述本轮生成对象

第一轮 Prompt MUST 正向说明生成轻量讲次方案及其 JSON Schema；第二轮 MUST 先说明生成课程级正式字段，再说明逐讲生成目标、学时、活动与达成检验。Prompt MUST NOT 通过枚举下一轮字段的负面禁令承担轮次隔离。轮次边界 MUST 由 OpenSpec、Schema、后端归一化白名单和自动测试保证；模型返回当前 Schema 之外的字段时，系统 MUST 丢弃这些字段。

#### Scenario: 第一轮模型越界返回正式字段

- **WHEN** 第一轮响应除标题和内容简介外还包含课程目标、模块、学时或逐讲详情
- **THEN** 后端归一化结果只保留轻量讲次方案 Schema 中的字段
- **AND** 第二轮继续基于教师最新保存的轻量方案生成正式字段

### Requirement: 状态监听器不得创造用户未执行的动作

前后端状态监听、路由同步、轮询和恢复逻辑 MUST 只对账已有任务、修订和页面位置。它们 MUST NOT 自动关闭编辑、点击继续、切换阶段、重开审阅状态、重生成下游或覆盖最后可用版本。生成、继续、重试、重新生成和应用 AI 修改只能由对应的用户可见操作触发。

#### Scenario: 教师在大纲完成后进入编辑

- **WHEN** 教师打开已完成大纲并开始编辑
- **THEN** 系统保持编辑现场并只保存教师明确提交的修订
- **AND** 监听器不得取消编辑、启动教案或把大纲退回待审阅

### Requirement: 生成审阅报告必须与准入状态分离

大纲、教案和讲义 MUST 在写入当前修订前通过版本化结构校验；结构可用后生成的质量审阅报告 MUST 只作为改进参考，不得改变完成状态或下游准入。页面 MUST 以低强调“查看审阅”按钮打开弹窗，关闭后回到原对象和位置；报告 MUST NOT 常驻正文、生产右栏或讲次状态行。PPT 页面内容稿的独立质量与确认合同不受此条取消。

#### Scenario: 教案完成但存在建议

- **WHEN** 第三讲教案结构可用并已成为当前修订，同时审阅报告有两项改进建议
- **THEN** 第三讲仍显示已完成并可生成讲义
- **AND** 教师可按需在弹窗查看建议，未查看不阻断下一步

### Requirement: 教师任务不得进入学生整课生命周期
系统 MUST 为教师资产任务使用教师观察入口。学生 generation preview 和学习页不得消费教师任务，教师任务也不得写入学生 CourseDocument 正文或发布状态。

#### Scenario: 教师生成第二讲讲稿
- **WHEN** 教师启动第二讲讲稿任务
- **THEN** 学生课程页面不显示该任务进度或工作稿
- **AND** 学生原整课生成和学习行为保持不变

### Requirement: 讲次检查点必须稳定复用
系统 MUST 冻结讲次任务的教学块、小节和批次身份，恢复时只继续未完成单元。批次 ID 不得因重算并发或容量而重新指向不同内容。

#### Scenario: 模型服务中断后恢复
- **WHEN** 第二讲五个教学块中三个已完成且模型调用中断
- **THEN** 恢复任务只处理第二讲剩余教学块
- **AND** 已完成结果不重做，其他讲次不启动

### Requirement: 流式事件必须来自持久工作状态
系统 MUST 先持久化可见工作片段，再通过 SSE 投影任务进度。刷新、断线或前端重连不得使已生成内容退回初始表单，也不得把仅存在于内存的 token 冒充正式工作稿。

#### Scenario: 生成中途刷新页面
- **WHEN** 教师在教案生成一半时刷新页面
- **THEN** 页面从持久任务和工作修订恢复已完成片段与当前阶段
- **AND** 教师可以继续等待、重试或退出，不会看到内容被清空

### Requirement: 所有模型生成必须立即返回真实进度
系统 MUST 在不新增平行业务接口的前提下，为所有模型生成返回可见进度。耐久任务 MUST 投影已保存的工作片段；自由文本 MUST 只转发提供方的真实文本增量；短时结构化候选 MUST 在原接口上返回开始、心跳和一个完整终态结果，不得向用户暴露未闭合的 JSON。

#### Scenario: 本地模型不支持 token 流
- **WHEN** 本地提供方只在生成完成后返回整段文本
- **THEN** 页面立即显示已接收和真实等待状态
- **AND** 服务端将返回方式标记为 `buffered_fallback`
- **AND** 系统不得在结果到达后人工切块伪造逐字输出

#### Scenario: 结构化 AI 候选正在生成
- **WHEN** 教师优化大纲、教案、讲稿、课程正文或 PPT 页面
- **THEN** 原候选接口返回开始和心跳事件
- **AND** 只在完整候选通过现有校验后返回终态结果
- **AND** 原候选、当前修订和历史版本保持不变

### Requirement: 旧教师整课写入必须按迁移门退场
系统 MUST 在旧整课教师入口删除前完成能力盘点、真实数据对账、生产调用审计、只读兼容和回滚演练。G2 通过后旧入口不得新增教师正式资产写入；G4 通过前不得无证据删除学生仍使用的共享能力。

#### Scenario: 旧入口仍有生产调用
- **WHEN** 调用审计发现仍有教师请求进入旧 `course_generation` 写路径
- **THEN** 系统保持兼容入口并阻止 G4 删除
- **AND** 迁移任务记录调用来源和目标新服务

#### Scenario: 旧教师调用归零
- **WHEN** 新链接管、历史数据对账、只读期和回滚演练均通过且生产调用为零
- **THEN** 系统可以删除旧教师 UI、API、路由和专属写入
- **AND** 学生整课与学习运行时回归必须继续通过
