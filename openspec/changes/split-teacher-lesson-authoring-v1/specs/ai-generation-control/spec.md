## ADDED Requirements

### Requirement: 四阶段生成必须暴露一致的控制动作

教学大纲、分讲教案、讲义和 PPT MUST 根据同一任务状态提供一致动作：运行中可暂停或取消，暂停后可继续或取消，失败后可重试，完成后可重新生成。清除操作 MUST 只清除本次未完成片段，不得删除当前可用修订、历史版本或最后可用产物。所有控制 MUST 使用真实任务 ID，页面不得用本地布尔值伪造完成或取消结果。

#### Scenario: 清除失败讲次的工作稿

- **WHEN** 第三讲教案任务失败且已有上一版可用教案
- **THEN** 教师可以清除本次失败任务的工作片段并重新生成
- **AND** 上一版可用教案、历史版本和其他讲次保持可用

### Requirement: 全课教案生成必须是父任务与按讲子任务

系统 MUST 支持一次选择课程资料和补充要求后启动全课教案生成父任务，并为每个计划讲次建立拥有稳定任务 ID 的子任务。父任务 MUST 汇总完成、运行、暂停和失败数量；每个子任务 MUST 可独立暂停、继续、取消、重试和查看失败原因。

#### Scenario: 只重试失败讲次

- **WHEN** 十二讲中十讲完成、一讲暂停、一讲失败
- **THEN** 父任务显示真实汇总状态且保留十讲结果
- **AND** 教师可以只继续暂停讲或只重试失败讲

### Requirement: 教师资产任务必须共用统一控制合同
系统 MUST 为教师大纲、教案、讲稿和 PPT 任务使用同一任务所有者，统一任务 ID、幂等键、阶段、心跳、检查点、取消、失败保留和恢复语义。任务类型可以不同，但不得各自维护平行状态机或正式资产真源。

#### Scenario: 重复点击生成教案
- **WHEN** 教师在同一讲、相同冻结输入下重复点击生成
- **THEN** 系统返回或恢复同一活动任务
- **AND** 不创建两份竞争的教案工作修订

### Requirement: 教师任务不得进入学生整课生命周期
系统 MUST 为教师资产任务使用教师观察入口。学生 generation preview 和学习页不得消费教师任务，教师任务也不得写入学生 CourseDocument 正文或发布状态。

#### Scenario: 教师生成第二讲讲稿
- **WHEN** 教师启动第二讲讲稿任务
- **THEN** 学生课程页面不显示该任务进度或工作稿
- **AND** 学生原整课生成和学习行为保持不变

### Requirement: 讲次检查点必须稳定复用
系统 MUST 冻结讲次任务的教学块、小节和批次身份，恢复时只继续未完成单元。批次 ID 不得因重算并发或容量而重新指向不同内容。

#### Scenario: 模型服务中断后恢复
- **WHEN** 第二讲五个教学块中三个已完成且模型调用中断
- **THEN** 恢复任务只处理第二讲剩余教学块
- **AND** 已完成结果不重做，其他讲次不启动

### Requirement: 流式事件必须来自持久工作状态
系统 MUST 先持久化可见工作片段，再通过 SSE 投影任务进度。刷新、断线或前端重连不得使已生成内容退回初始表单，也不得把仅存在于内存的 token 冒充正式工作稿。

#### Scenario: 生成中途刷新页面
- **WHEN** 教师在教案生成一半时刷新页面
- **THEN** 页面从持久任务和工作修订恢复已完成片段与当前阶段
- **AND** 教师可以继续等待、重试或退出，不会看到内容被清空

### Requirement: 所有模型生成必须立即返回真实进度
系统 MUST 在不新增平行业务接口的前提下，为所有模型生成返回可见进度。耐久任务 MUST 投影已保存的工作片段；自由文本 MUST 只转发提供方的真实文本增量；短时结构化候选 MUST 在原接口上返回开始、心跳和一个完整终态结果，不得向用户暴露未闭合的 JSON。

#### Scenario: 本地模型不支持 token 流
- **WHEN** 本地提供方只在生成完成后返回整段文本
- **THEN** 页面立即显示已接收和真实等待状态
- **AND** 服务端将返回方式标记为 `buffered_fallback`
- **AND** 系统不得在结果到达后人工切块伪造逐字输出

#### Scenario: 结构化 AI 候选正在生成
- **WHEN** 教师优化大纲、教案、讲稿、课程正文或 PPT 页面
- **THEN** 原候选接口返回开始和心跳事件
- **AND** 只在完整候选通过现有校验后返回终态结果
- **AND** 原候选、当前修订和历史版本保持不变

### Requirement: 旧教师整课写入必须按迁移门退场
系统 MUST 在旧整课教师入口删除前完成能力盘点、真实数据对账、生产调用审计、只读兼容和回滚演练。G2 通过后旧入口不得新增教师正式资产写入；G4 通过前不得无证据删除学生仍使用的共享能力。

#### Scenario: 旧入口仍有生产调用
- **WHEN** 调用审计发现仍有教师请求进入旧 `course_generation` 写路径
- **THEN** 系统保持兼容入口并阻止 G4 删除
- **AND** 迁移任务记录调用来源和目标新服务

#### Scenario: 旧教师调用归零
- **WHEN** 新链接管、历史数据对账、只读期和回滚演练均通过且生产调用为零
- **THEN** 系统可以删除旧教师 UI、API、路由和专属写入
- **AND** 学生整课与学习运行时回归必须继续通过
