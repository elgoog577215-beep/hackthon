# 变更：升级结构化教案工作台

## Why

灵知当前已经生成唯一的 `CourseTeachingPlanV3`，并将它作为正文、课程知识库、练习、PPT 和其他教学表达的上游合同。前端已经提供“总体教案 / 分小节教案”两种阅读视图，但 `GenerationLessonPlan.vue` 只允许切换小节和打开知识点，不能修改、保存、比较或应用教案变化。后端也只有教案投影和修订读取能力，没有对应的草稿、变更命令和影响分析。

启智提供了可编辑 Markdown、自动保存、未保存离开保护、`analyze -> generate -> fact-check -> refine` 流程和大纲/教案/PPT 资源关系等可借鉴模式；但启智的 Markdown 文档是文档级真源，不能直接替代灵知当前的结构化教案合同。本变更吸收低负担编辑体验，同时保持灵知“一门课程一份语义真源、确定性投影、修订链和下游依赖”的边界。

## What Changes

1. 将教案从只读投影升级为教师可控制的结构化工作台。
2. 支持总体层、分小节层和字段级的手工编辑、AI 改写与定向重新生成。
3. 使用可变草稿与不可变正式修订分离的模型，支持自动保存但不让每次输入直接污染正式课程。
4. 在正式应用前返回确定性的差异、影响范围、阻断项和需要重建的派生对象。
5. 让教案变更进入现有课程修订、课程知识库、正文、练习、PPT 和教学表达的同源链。
6. 提供修订历史、比较、恢复和幂等回执，支持并发冲突与过期候选处理。
7. 保持新课程首次生成的现有阶段、模型调用次数、目录确认门和发布门不变；编辑能力是生成后和发布前的工作台能力，不新增一个强制的独立确认阶段。

## 非目标

- 不把整份教案改成独立 Markdown 真源。
- 不允许教师直接修改稳定知识 ID、课程修订 ID、来源绑定、系统质量报告和其他编译字段。
- 不在教案工作台直接增删章节或替代目录编辑器。
- 不建立启智式独立资源树，不把多个教案副本并列为产品真源。
- 不在本变更中实现多人协作、权限审批、跨课程知识共享或数据库迁移。
- 不把 AI 文本直接写入正式教案；所有 AI 结果必须先成为结构化候选并经过确认。

## 预期结果

教师可以在同一门课程中完成：

```text
阅读总体/分小节教案
→ 编辑字段或选择内容交给 AI
→ 草稿自动保存并跨刷新恢复
→ 查看修改前后差异和影响对象
→ 确认应用形成新教案修订
→ 选择立即重建或稍后处理受影响的正文/知识/练习/PPT
→ 在历史中查看、比较、恢复和撤销
```

## Capabilities

### New Capabilities

- `teaching-plan-workbench`：定义唯一结构化教案的草稿、正式修订、字段权限、结构化命令、AI 候选、确定性影响分析、下游重建、历史比较与工作台交互合同。

### Modified Capabilities

- 无。既有课程版本、AI 提案和教学表达能力作为本变更的依赖继续复用，不在本计划中修改它们的正式规格。

## Impact

- 后端：教案草稿与修订、结构化 patch、教案变更集、影响分析、课程命令、下游失效与派生任务、历史与回执。
- 前端：`GenerationLessonPlan.vue`、教案工作台状态、编辑器、差异审阅、影响图、AI 候选、修订历史、刷新/离开保护和中英文 locale。
- 课程域：`course_teaching_plan` 修订进入统一课程修订向量；课程知识库、正文、练习、PPT 和 `TeachingRepresentation` 注册表消费新的来源修订。
- 验证：后端 schema/命令/影响/并发测试，前端组件和状态测试，生产构建，中英文与 390/789/1024/1440 视口 Playwright smoke。

## 发布门

只有以下条件全部满足才允许合并实现：

- 正式教案仍只有一份，草稿不会被下游任务消费。
- 直接编辑、AI 候选、确认应用、冲突、撤销和重复请求都有结构化回执。
- 影响范围由确定性规则计算，并能解释受影响与保持不变的对象。
- 关键变更经过现有教案/课程/知识/表达质量门；失败时旧正式版本继续可读。
- 中英文模式没有中文残留、原始 key、文字遮挡或窄屏横向溢出。
- 全量相关测试、前端构建、OpenSpec 校验和真实 API/UI smoke 通过。
