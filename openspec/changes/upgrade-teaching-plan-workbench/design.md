# 设计：结构化教案草稿、修订与影响驱动工作台

## 1. 现有边界与复用点

### 1.1 现有真源

- `CourseDocument` 负责课程章节、目标、课程块和正文语义。
- `course_teaching_plan` 保存唯一正式 `CourseTeachingPlanV3`；`course_teaching_plan_projection.py` 只负责安全投影。
- `CourseKnowledgeBase`、`CourseKnowledgeMap` 和 `KnowledgeBinding` 从正式教案与课程合同确定性编译。
- `course_revisions.py` 已能把 `course_teaching_plan.revision_id` 纳入课程修订向量。
- `course_commands.py` 已提供正文块替换、文本 patch、块操作组和小节目标更新，可复用其版本校验、幂等回执和操作日志模式。
- `CourseEvolutionPlan` / `CourseEvolutionOperation` 已提供 AI 候选、影响预览、确认、撤销和冲突模式；教案候选应沿用白名单提案与领域命令，不创建平行 AI 写入链。

### 1.2 不改变的约束

```text
课程结构/正文真源：CourseDocument
教学设计真源：当前课程唯一 CourseTeachingPlanV3
知识真源：当前课程 CourseKnowledgeBase
教案/PPT/讲义/题目：带来源修订的确定性投影或派生表达
草稿：可变、可恢复、不可被正式生成消费
修订：不可变、可比较、确认后才成为当前
```

首次生成继续使用现有“目录确认 → 教案骨架/批次 → 本地汇编 → 知识编译 → 正文/资产”的链路。工作台不插入新的自动确认门；用户只在明确应用教案变化时产生新的正式修订。

## 2. 数据模型

### 2.1 `TeachingPlanDraft`

草稿保存用户正在编辑的结构化计划，不改变当前正式计划。

```json
{
  "schema_version": "teaching_plan_draft_v1",
  "draft_id": "tpd_...",
  "course_id": "...",
  "base_plan_revision_id": "tp_...",
  "base_course_revision_vector": {},
  "payload": {},
  "changed_paths": [
    "overall.learning_objectives[0]",
    "sections.sec_01.teaching_modules.mod_02.teaching_guidance"
  ],
  "validation": {
    "status": "valid|warning|blocked",
    "issues": []
  },
  "updated_at": "...",
  "expires_at": null
}
```

规则：

- 草稿必须绑定创建时的教案修订和课程修订向量。
- 草稿 patch 使用结构化路径和预期值，拒绝模糊全文替换。
- 自动保存只写草稿，不更新 `course_teaching_plan`、`CourseDocument` 或任何正式教学表达。
- 草稿跨刷新可恢复；同课程只有一个当前用户工作草稿，旧草稿可进入历史审计但不作为当前真源。
- 基础正式修订发生变化时，草稿进入 `stale`，允许重新基于当前修订合并，不得静默覆盖。

### 2.2 `TeachingPlanRevision`

确认应用后产生不可变正式修订。可以先以当前文件仓库的课程数据字段保存，待后续数据库化时沿用同一 schema。

```json
{
  "schema_version": "teaching_plan_revision_v1",
  "revision_id": "tpr_...",
  "course_id": "...",
  "revision_number": 3,
  "parent_revision_id": "tpr_...",
  "source_revision_vector": {},
  "plan_payload": {},
  "change_set_id": "tpc_...",
  "quality_report": {},
  "created_by": "teacher|ai_assisted",
  "created_at": "..."
}
```

正式字段仍写入课程当前的 `course_teaching_plan`，历史修订进入 `course_teaching_plan_revisions` 或等价仓库；历史保存完整计划快照，不保存只可恢复的差分。

### 2.3 `TeachingPlanChangeSet`

变更集承载差异、影响和应用状态。

```json
{
  "schema_version": "teaching_plan_change_set_v1",
  "change_set_id": "tpc_...",
  "course_id": "...",
  "base_plan_revision_id": "tpr_...",
  "operations": [],
  "diff": {},
  "impact_report": {},
  "status": "draft|ready|applied|stale|rejected|undone|failed",
  "idempotency_key": "...",
  "created_at": "..."
}
```

每个 operation 必须有稳定操作 ID、目标路径/对象 ID、操作类型、旧值摘要、新值摘要、来源（手工/AI）、理由和预期修订。

## 3. 编辑权限与字段分类

### 3.1 直接可编辑字段

这些字段可在草稿中直接输入，并执行同步 schema/长度/空值校验：

- 总体：课程定位、目标对象、学习起点、总体目标、前置要求、教学策略说明、评价方式说明。
- 小节：学习目标、教学职责说明、教学指导、章节衔接说明。
- 知识包中的描述性字段：知识陈述、条件、边界、能力描述、易错表现、掌握标准文本。

### 3.2 必须生成影响预览的字段

- 教学模块新增、删除、替换和顺序调整。
- 知识点归属、首次负责小节、复用关系和前置关系。
- 评价证据、能力点、易错纠偏和掌握标准的结构变化。
- 全课目标或学习起点导致多小节策略变化。

### 3.3 只读字段

- `knowledge_id`、`node_id`、`module_id`、`revision_id`、来源修订、绑定 ID。
- 系统计算的质量状态、派生状态、编译时间、模型调用信息和稳定 hash。
- 章节树本身；章节增删和排序回到目录编辑器。

只读字段必须在 UI 以“由课程/知识库自动维护”等明确理由呈现，不能只是不显示编辑入口。

## 4. 变更生命周期

```text
GET 正式教案 + 当前修订向量
→ 创建/恢复 TeachingPlanDraft
→ 手工 patch 或 AI 生成候选
→ 本地 schema + 教案结构门
→ 计算 diff + impact report
→ 生成 TeachingPlanChangeSet
→ 教师查看差异、影响与质量问题
→ 确认应用
→ 再校验基础修订/锁定/幂等键
→ 创建 TeachingPlanRevision
→ 更新课程正式教案与课程修订向量
→ 确定性重编译知识/绑定/教学表达
→ 创建受影响内容的重建候选或任务
→ 返回逐对象 receipt
```

### 4.1 草稿保存

- 用户停止输入 800–1200ms 后防抖保存草稿；AI 流式完成后立即保存候选草稿。
- 保存失败保留本地草稿并显示“未同步”，不显示成功 toast。
- 页面刷新、切换小节、离开页面前都读取服务端草稿状态。
- 离开时若草稿比服务端最新状态更新，提示继续编辑、放弃草稿或重试同步。

### 4.2 应用确认

- 应用按钮必须展示“将产生第 N 个教案修订”和影响对象数量。
- 教师可以逐项勾选影响对象的重建策略：立即生成、标记待处理、放弃该项；教案本身的正式修订不能只应用一半。
- 高影响变更（知识身份、前置关系、章节职责变化）没有完整影响报告或质量阻断时不可应用。
- 应用使用幂等键；重复请求返回原回执，不重复创建修订或重建任务。

## 5. 确定性影响矩阵

| 变更类别 | 必须失效/重建 | 保持不变 | 默认策略 |
| --- | --- | --- | --- |
| 定位、对象、策略说明文字 | 总体教案投影、教师摘要 | 稳定知识 ID、无关课程块 | 应用后同步投影 |
| 单节学习目标 | 当前小节正文、目标绑定、相关练习与 PPT 页 | 无关小节知识与资产 | 生成局部候选 |
| 教学指导/模块职责 | 当前模块对应正文、讲义/PPT、理解检查 | 无关模块 | 局部重建 |
| 知识陈述、能力、易错、掌握标准 | 当前知识绑定、相关正文、题目、练习、PPT | 未引用知识点 | 先编译知识影响，再按需重建 |
| 知识首次负责/复用/前置关系 | 受影响小节及后续依赖 | 不在关系闭包内的对象 | 阻止静默应用，必须审阅 |
| 增删/排序章节 | 目录、教案、正文、知识、练习、PPT 全链 | 历史版本 | 回到目录修订流程 |

影响报告必须分别列出 `changed`、`needs_regeneration`、`stale`、`unchanged` 和 `blocked`，并给出每一项的来源路径和判断理由。

## 6. AI 辅助修改

### 6.1 入口

- 字段旁“让 AI 改写”：当前字段 + 小节上下文 + 必要知识闭包。
- 小节“重新生成”：当前小节教案、相邻衔接、课程类型、学科课型、资料边界。
- 总体“调整全课”：先返回全课影响预览，不直接生成全课正文。
- 选中一段文字后“改得更具体/更适合初学者/增加例子”等快捷动作；选区必须绑定结构化字段和稳定路径。

### 6.2 AI 合同

- AI 只输出 `TeachingPlanOperationProposal`，不得直接调用正式写接口。
- 提案必须包含目标、输入修订、结构化 patch、理由、置信度/质量问题、影响范围和过期时间。
- 生成仍可复用启智的“分析 → 生成 → 核查 → 优化”阶段语义，但核查以灵知现有确定性教案校验和质量合同为准，不把 LLM 自评当作通过。
- AI 提案过期、目标已变或基础修订不一致时标记 `stale`，提示重新生成。

## 7. 后端模块与接口

建议新增以下模块，具体文件名可在实施时按现有路由结构落位：

- `teaching_plan_revisions.py`：草稿、正式修订、变更集和仓库。
- `teaching_plan_commands.py`：结构化 patch、模块操作、知识语义变更、应用与撤销。
- `teaching_plan_impact.py`：字段语义、显式依赖和派生对象影响分析。
- `routers/teaching_plan_workbench.py`：读取、草稿保存、校验、AI 候选、差异、应用、历史、恢复。

接口契约：

```text
GET  /api/courses/{course_id}/teaching-plan/workbench
POST /api/courses/{course_id}/teaching-plan/baseline
POST /api/courses/{course_id}/teaching-plan/drafts
PATCH /api/courses/{course_id}/teaching-plan/drafts/{draft_id}
POST /api/courses/{course_id}/teaching-plan/validate
POST /api/courses/{course_id}/teaching-plan/ai-proposals
POST /api/courses/{course_id}/teaching-plan/change-sets
POST /api/courses/{course_id}/teaching-plan/change-sets/{id}/apply
POST /api/courses/{course_id}/teaching-plan/change-sets/{id}/reject
POST /api/courses/{course_id}/teaching-plan/revisions/{id}/restore
GET  /api/courses/{course_id}/teaching-plan/revisions
GET  /api/courses/{course_id}/teaching-plan/revisions/{id}/diff
```

所有写接口必须携带 `idempotency_key`、`base_plan_revision_id`、`base_course_document_revision`（若适用）和当前用户身份；409 返回结构化冲突信息和最新工作台投影。

## 8. 前端工作台

### 8.1 页面结构

- 顶部：课程名、教案修订、草稿状态、影响摘要、应用/放弃按钮。
- 总体视图：定位、对象、起点、总体目标、策略、评价、章节路径、知识坐标。
- 分小节视图：学习目标、课堂路径、课程模块、知识结构、能力、易错、掌握标准、前后衔接。
- 右侧或临时面板：AI 修改、差异、影响、历史；不永久挤压主体内容。
- 知识标签继续跳转知识库，但稳定 ID 和系统状态不可直接编辑。

#### 教案 AI 协作编辑模式

- 教师从标准教案进入 AI 修改时，工作台临时切换为“左侧教案画布 + 右侧多轮对话”，阶段导航和资料托盘让出空间；退出后恢复原工作台，不新增页面和产品层级。
- 左侧始终显示当前结构化教案。AI 候选只作为预览层覆盖候选值，并对真实变化字段高亮；候选未确认前不写入当前工作修订。
- 右侧固定显示课程、讲次、小节和资料范围。连续补充要求时，前序教师消息一并进入下一次候选生成，最新要求优先；旧候选先经现有放弃接口关闭，避免并存多个待处理候选。
- 对话中的“定位、放弃、采用”与画布顶部的候选操作指向同一个服务端候选；采用继续复用现有 `ai-candidates/{id}/resolve` 修订链，并回显采用、放弃或替换回执。
- 桌面端右栏默认占 38%，允许在 32%–46% 内通过指针或键盘调整；加载、错误、候选待确认和回执均使用真实状态，不模拟模型思考阶段。
- 前端以 `ready → clarifying | generating → review → accepting | rejecting → success` 为显式状态机，任一处理步骤失败进入 `error` 并保留可重试动作；刷新后恢复与当前工作修订匹配的未处理候选，不把恢复误报成重新生成。
- 模糊要求先询问教师优先修改目标、活动检查或课堂节奏；明确要求才生成候选。发送模型的上下文只保留有界的最近教师要求，最新要求优先，并明确最小充分修改、目标可观察、活动检查对齐和默认保持总时长。
- AI 模式只保留一套候选确认操作：右侧助手打开时，左侧只负责展示真实候选与字段高亮；退出助手后，画布顶部恢复候选入口与采用/放弃操作。总进度入口位于教案工具栏，滚动条与分栏拖拽器不再形成永久可见的并列竖轨。

### 8.2 交互状态

```text
viewing → editing → draft_saving → draft_saved
                       ↓
                 validation_blocked
draft_saved → reviewing_diff → ready_to_apply
ready_to_apply → applying → applied | conflict | failed
```

每个状态都必须有中英文文案、禁用条件、失败处理和可恢复动作。

### 8.3 不新增产品层级

- 不增加第二套课程工作室。
- 生成现场仍复用学习工作区 URL 和教案视图。
- 教案工作台是教师控制能力，不成为学生端一级入口。
- 不把教案字段做成密集表单；长文本使用分段编辑，结构操作使用可解释的操作菜单和审阅弹窗。

## 9. 兼容与迁移

- 已有课程读取没有 `course_teaching_plan` 时，继续显示“暂无结构化教案/已有学习目标”状态，不伪造可编辑字段，也不因打开页面自动写入。
- canonical 历史课程若已发布目录包含稳定小节，可由教师显式触发确定性 V3 基线编译；该动作不调用模型、不改正文，并记录迁移来源、质量报告、幂等回执和首个正式修订。
- 缺少稳定结构化目录或编译质量未通过时继续只读，不提供绕过目录真源的编辑入口。
- 历史 V2 教案先通过现有兼容读取归一化为 V3 投影；第一次正式编辑前创建基线 `TeachingPlanRevision`，不静默改写旧课程。
- 旧课程若缺少稳定知识绑定，只允许编辑描述性字段；知识结构编辑需要先完成知识绑定补全。
- 取消、失败或删除草稿不影响正式课程、历史修订和已发布教学表达。
- 旧的正文块级课程生长命令继续可用；它们与教案变更的来源修订必须在应用后重新校验，不能互相覆盖。

## 10. 实施编排、估算与灰度

### 10.1 依赖顺序

```text
M0 基线与字段合同
→ M1 草稿/修订/手工结构化编辑纵切
→ M2 确定性影响分析与下游来源状态
→ M3 AI 候选、完整工作台与历史恢复
→ M4 历史兼容、真实联调与灰度发布
```

- `M1` 可以先在 feature flag 后完成端到端开发，但在 `M2` 可用前不得向真实用户开放正式应用按钮。
- 前端编辑器可在 `M1` schema 冻结后与 `M2` 并行；差异、影响和应用面板必须消费真实接口，不用长期 mock 契约替代后端。
- AI 候选依赖字段权限、结构化命令、影响分析和过期校验，不得为了演示提前绕过 `M1/M2`。
- 历史 V2/V3 兼容依赖正式修订仓库稳定；不得在 schema 未冻结前批量改写旧课程。

### 10.2 里程碑与退出门

| 里程碑 | 对应任务 | 核心交付物 | 内部退出门 | 粗略工作量 |
| --- | --- | --- | --- | --- |
| M0 合同冻结 | 0.x | 基线夹具、字段白名单、状态枚举、术语与接口草案 | 现有 V2/V3/缺失教案样本可重复读取；首次生成链无变化 | 2–3 人日 |
| M1 手工编辑纵切 | 1.x、2.x、4.1–4.3、5.1–5.3 | 草稿、正式修订、结构化 patch、基础差异、保存与冲突 UI | 编辑 → 自动保存 → 刷新恢复 → 校验 → 生成新修订闭环通过；草稿不污染正式产物 | 8–12 人日 |
| M2 影响与同源传播 | 3.x、6.x | 确定性影响矩阵、来源失效、定向重建候选、逐对象回执 | 六类代表变更都能解释受影响/不受影响对象；重建失败保留最后可用产物 | 8–10 人日 |
| M3 AI 与完整工作台 | 4.4–4.6、5.4–5.9 | AI 字段/小节/全课候选、差异影响审阅、历史比较恢复、中英文响应式 UI | AI 不直写；过期候选被拒绝；桌面/平板/移动和 zh/en 闭环通过 | 7–10 人日 |
| M4 兼容与发布 | 7.x、8.x | 历史课程兼容、真实 API/UI smoke、监控与发布材料 | 全量规格校验、相关测试、构建、真实联调和回滚演练通过 | 4–6 人日 |

总量按当前文件仓库、单体前后端和既有命令/修订能力估算为 **29–41 人日**。两名熟悉代码库的前后端开发并行时，日历周期约 **4–6 周**；单人全栈顺序推进约 **6–9 周**。这是范围估算，不是交付承诺；`M0` 发现课程文件锁、历史数据或下游来源链比当前判断更复杂时，应先更新估算再进入 `M1`。

### 10.3 灰度与回滚

1. 新工作台由课程级 feature flag 控制，关闭时继续展示现有只读投影。
2. 第一批只开放测试课程与新建 V3 课程，验证草稿、应用、下游失效和恢复；不自动迁移历史课程。
3. 第二批开放具备完整知识绑定的 V3 历史课程；缺失绑定的课程只开放描述性字段。
4. V2 课程只有在首次编辑基线修订创建、读取归一化和回滚演练通过后才开放。
5. 回滚只关闭新工作台入口和新写入，不删除草稿、变更集、修订或历史表达；当前正式教案和最后可用下游产物保持可读。

### 10.4 观测指标

- 草稿保存成功率、P95 保存延迟、冲突率和刷新恢复成功率。
- 影响报告计算成功率、平均受影响对象数、`blocked` 原因分布和误失效回归数。
- 正式应用成功率、幂等重复命中率、修订创建失败率和下游重建成功率。
- AI 候选接受/拒绝/过期率、从候选到确认的耗时，但不得用接受率代替教学质量。
- 历史恢复成功率、旧课程只读降级数量、中英文/响应式回归数。

## 11. 验证策略

### 后端

- schema 归一化、字段权限、路径 patch、空值/长度/枚举和结构门。
- 草稿保存、刷新恢复、过期、并发、幂等、拒绝和失败不污染正式版本。
- 总体/小节/知识/模块各类变更的影响矩阵快照。
- AI 提案白名单、输入修订、过期和确认回执。
- 正式修订应用后知识库、正文、练习、PPT、表达注册表的来源修订与 stale 状态。
- 历史差异、恢复创建新版本、撤销和旧课程兼容。

### 前端

- 组件测试覆盖总体/小节双视图、字段编辑、草稿状态、冲突、差异和影响分组。
- Playwright 覆盖：生成完成 → 编辑总体目标 → 自动保存 → 刷新恢复 → AI 候选 → 查看差异 → 应用 → 看到新修订和下游状态。
- 390、789、1024、1440 视口检查正文宽度、弹窗、固定操作栏、无横向溢出和无文字重叠。
- zh/en 模式检查无中文残留、无原始翻译 key、按钮文字不截断。

### 发布

- `openspec validate --all`、`git diff --check`、后端相关 pytest、前端测试和生产构建。
- 真实 API smoke 覆盖草稿、校验、应用、冲突和历史读取；不使用只验证 HTTP 200 的假回执。
- 记录完整改动链：草稿 ID、变更集 ID、教案修订 ID、课程修订向量、下游重建任务和最终回执。
