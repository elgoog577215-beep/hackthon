## ADDED Requirements

### Requirement: 一门课程必须只有一个多模式工作区
系统 MUST 将课程设置、备课制作和正式课程作为同一 `course_id` 下的三个一级模式。三个模式 MUST 共享课程身份与正式领域状态，且每次使用完整内容宽度，不得重新建立教师端产品壳。

#### Scenario: 从课程库进入课程
- **WHEN** 用户点击课程卡的“进入课程”
- **THEN** 系统进入该课程的统一工作区
- **AND** 默认显示课程设置而不是独立教师总览或学生正文

#### Scenario: 切换到正式课程
- **WHEN** 用户从课程设置或备课制作切换到正式课程
- **THEN** 系统进入原课程学习现场
- **AND** 目录、正文、AI 老师、练习、笔记、错题和进度继续读取原正式状态

### Requirement: 课程设置与备课制作必须按职责分组
课程设置 MUST 包含基本信息、资料、课程设计和教学日历。备课制作 MUST 包含大纲、讲次备课、练习和 PPT。课程生产总览 MUST NOT 作为一级或二级模块出现。

#### Scenario: 教师准备一门课程
- **WHEN** 用户依次打开资料、课程设计、大纲和讲次备课
- **THEN** 每个模块在对应一级模式内可直接定位
- **AND** 页面不要求返回独立教师首页或课程生产总览

### Requirement: 课程设计与讲次备课必须共享教学方案真源
系统 MUST 将 `CourseTeachingPlan.overall` 投影为课程设计，将 `CourseTeachingPlan.sections` 投影为讲次备课。两者 MUST 复用同一草稿、正式修订、差异、影响和历史链，统一流程 MUST NOT 写入平行教师讲次真源。

#### Scenario: 修改某讲备课内容
- **WHEN** 用户在讲次备课修改一个小节并确认应用
- **THEN** 系统产生同一 `CourseTeachingPlan` 的新正式修订
- **AND** 课程设计能读取该修订的总体投影
- **AND** 不创建第二份教师讲次正式教案

### Requirement: 子模块必须按需加载并保留当前课程状态
统一工作区 MUST 只阻塞当前内容区所需的关键请求。资料、日历、大纲和教学方案 MUST 在首次打开时加载，并在同课程切换后保留已加载状态和未提交草稿；可选聚合请求不得阻塞整个页面。

#### Scenario: 在资料与教学日历之间反复切换
- **WHEN** 用户已分别打开过资料和教学日历后再次切换
- **THEN** 页面恢复原目录或日历草稿
- **AND** 不重新执行整套课程、任务、教案、PPT 和发布请求

### Requirement: 旧教师路由必须安全收束
系统 MUST 将旧教师课程路由重定向到统一工作区的等价模式。重定向 MUST 保留 `course_id` 和可表达的子模块定位，不得删除或静默迁移旧数据。

#### Scenario: 打开旧教师文件链接
- **WHEN** 用户访问 `/teacher/course/:courseId/files`
- **THEN** 系统进入该课程的“课程设置 / 资料”
- **AND** 文件读取继续受当前身份和课程绑定约束
