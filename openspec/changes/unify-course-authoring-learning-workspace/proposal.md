## Why

当前产品把同一门课程拆成学生课程库、学习现场和独立教师课程工作台。教师页重复加载课程、任务、教案、日历和表达状态，页面切换会重复挂载并串行请求；同时讲次教案与讲次 PPT 又建立了平行持久化，造成界面、术语、性能和真源边界同时分裂。

课程设置、备课制作和课堂使用本质上是同一课程在不同工作阶段的投影，应共享课程身份、课程文档、教学方案、课件和生成任务，而不是维护两套产品。

## What Changes

- 在原课程视觉体系内新增统一课程工作区，一级模式固定为“课程设置 / 备课制作 / 正式课程”。
- 课程设置承载基本信息、课程资料、课程设计和教学日历；备课制作承载大纲、讲次备课、练习和 PPT。
- 课程级课程设计与分讲备课共同读取 `CourseTeachingPlan`，不再让教师讲次仓库成为新流程真源。
- 文件空间新增稳定 `course_id` 绑定，嵌入课程设置并保留原文件和目录结构。
- PPT 继续进入原 `PptWorkspaceView` 并读取同一 `TeachingRepresentation / SlideDeckSpec`。
- 旧 `/teacher/...` 路由重定向至统一工作区；课程生产总览和独立教师壳退出主流程。
- 子模块首次打开时按需加载，已打开模块在同一课程工作区内保留状态，避免每次切换全量重载。

## Capabilities

### New Capabilities

- `unified-course-workspace`: 同一课程内设置、备课与正式使用的统一界面和导航合同。
- `course-owned-file-space`: 课程文件空间与稳定课程身份的归属、兼容迁移和使用合同。

### Modified Capabilities

- `learning-experience-shell`: 课程库继续承担发现与创建，但课程卡进入统一课程工作区；正式课程模式保持原学习现场骨架。

## Supersedes

- `integrate-teacher-course-production-calendars-v1` 中“学生端与教师端必须保持独立产品入口”和独立教师壳决策。
- `split-teacher-lesson-authoring-v1` 中将教师讲次教案与 PPT 建成平行正式真源的决策；保留其按讲编辑、候选、恢复和版本交互价值。
- `add-teacher-course-space` 中工作包暂不绑定课程 ID、从课程库进入独立文件空间的决策。

## Impact

- 前端：课程库入口、课程路由、统一模式导航、课程设置/备课页面、学习页、文件空间、教学日历和旧教师路由。
- 后端：课程文件空间清单和创建接口增加 `course_id`；旧教师讲次 API 暂时只作为兼容读取边界保留。
- 文档：产品蓝图、产品状态和系统架构从“双端隔离”更新为“单课程多模式”。
- 验证：后端课程文件测试、前端路由/组件测试、构建、OpenSpec、中文/英文及桌面/移动真实页面验收。
