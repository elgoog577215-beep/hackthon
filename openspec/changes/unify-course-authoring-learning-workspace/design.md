## Context

现有原课程界面已经承载 `CourseDocument`、`CourseTeachingPlan`、正式练习、PPT、AI 老师与学习记录。独立教师页再次组合相同状态，并额外引入 `TeacherLessonAuthoringRepository` 和按课程名称匹配的 `TeacherCourseSpaceRepository`。这既增加首屏请求，也让同一课程出现多个入口和多个潜在真源。

## Decisions

### 1. 一个课程工作区，四个连续阶段

课程卡进入 `/course/:courseId/workspace/setup`。用户可见主轴为：

```text
课程：概览 / 资料 / 教学设计 / 日历
大纲：章节结构 / 顺序 / 确认
正文：原学习现场中的目录 / 正文 / 配套练习与学习工具
PPT：原同源课件工作台
```

四阶段是产物链导航，不是只能向前的向导。每次只显示一个完整内容面，用户可以往返查看真实状态；桌面、移动和 PPT 工作台都保持同一主导航。

### 2. 原课程真源优先

- 大纲继续来自生成工作区蓝图或 `CourseDocument` 投影。
- “课程 / 教学设计”的全课视图读取 `CourseTeachingPlan.overall`。
- 同一教学设计工作台的分小节视图读取 `CourseTeachingPlan.sections`，复用同一草稿、候选、差异、应用和历史接口。
- PPT 继续读取 `TeachingRepresentation / SlideDeckSpec`。
- 练习继续读取正式题目与尝试状态。

统一工作区不得调用 `TeacherLessonAuthoringRepository` 创建新的讲次正式版本。旧接口保留到真实环境数据审计和迁移完成，随后单独删除。

### 3. 文件是课程资产，不是课程语义副本

课程文件包增加 `course_id`。同一 owner 和 course 默认只有一个活动包；旧包无 `course_id` 时，嵌入页可以按课程标题找到唯一候选并通过显式绑定接口迁移，不能长期依赖标题关联。文件可作为生成材料引用，但目录和文件名不直接改写课程文档。

### 4. 按需加载并在工作区内保留

进入统一工作区只加载课程与当前阶段或子模块。资料、日历、大纲和教学设计在首次访问时加载；同一课程内切换子模块后组件保持挂载，避免重复请求和丢失草稿。阻断性加载只覆盖当前内容区，不覆盖整个应用。

### 5. 旧路由是兼容入口，不再是产品结构

所有 `/teacher/course/:courseId/...` 路由映射到统一工作区对应模式和子模块。`/teacher/courses` 映射到课程库。旧页面源码在兼容期可以保留，但不再由主路由访问；真实数据迁移完成后删除。

## Risks and recovery

- 旧课程文件包可能同名：只自动选择稳定 `course_id` 匹配；标题匹配仅作为单一候选提示，不静默绑定多个包。
- 未发布课程可能没有正式练习或 PPT：对应阶段显示真实上游条件和进入正文或继续生成的动作，不伪造完成状态。
- 教学日历存在未保存草稿：组件保持原离开保护；统一工作区切换子模块前由组件保存状态，不全量重建。
- 回滚时可恢复旧路由映射；新增 `course_id` 字段向后兼容，不删除旧清单和文件。
