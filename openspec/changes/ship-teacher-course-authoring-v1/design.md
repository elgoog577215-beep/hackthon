## Context

灵知当前已经拥有统一课程生产链和结构化课程内核：`POST /api/course-generation/generate` 创建唯一 `GenerationJob`，任务在隔离工作区中依次形成需求、目录、`CourseTeachingPlanV3`、课程知识、正文、正式练习、质量结果和发布回执，最终发布为 `CourseDocument + CourseBlock`。目录、教案、正文和任务状态也已经在同一课程 URL 中投影。

当前问题不是缺少生成算法，而是教师作者链没有闭合：

- 课程创建缺少学期、课时、课堂环境等教师约束，很多要求只能写入自由文本。
- 大纲已有修改能力，但教师侧仍混用章、小节等旧结构语言，尚未统一为按讲编辑。
- `CourseTeachingPlanV3` 擅长知识、能力、易错、掌握标准和课程块职责，但缺少课堂执行所需的时间、师生活动、准备和作业。
- 正文已有块级 AI 候选与课程命令，但入口偏学习现场，缺少手工草稿和完整作者操作。
- 教案修改能形成影响报告，却还不能稳定完成受影响正文、练习与外部表达的定向重建。
- `CourseDocument` 已声明图像、音频、视频和图示块，课程生长也已有 `AnimationSpec`，但通用动画渲染仍是原型。
- 已有预算、并发、检查点和恢复测试不能替代真实提供方下的速度、成功率和质量验收。

本设计面向课程创建者和教师，不把灵知扩张为 LMS、班级管理、多人协作或学校文件管理平台。教师端 V1 与现有学习现场共用课程真源，但学生侧个性化生长不是本次发布前置。

## 2026-08-31 教师课程生产修正合同

本节依据两次教师会议和用户逐项确认形成，是本变更当前最高优先级的开发合同。下文仍出现“章/小节作为教师层级”“统一固定课堂顺序”“90 分钟默认一讲”“旧课程迁移”时，均以本节为准；旧字段只允许留在兼容适配层，不能重新进入新建课程、教师界面或模型决策。

| 序号与改动 | 领域定义 | 产品机制 | 交互设计 | 技术架构与完成证据 |
| --- | --- | --- | --- | --- |
| 1. 正式课程层级改为“课程 → 第 N 讲” | “讲”是教师生产、确认、恢复的最小正式单元；知识点和教学块只是讲内组成 | 大纲、教案、讲义、PPT 全部以同一 `lecture_id` 对齐 | 页面、标签、状态只显示“讲”，不显示章、小节二级 Tab | 新课程写入 `authoring_structure_version=lecture_v1`；内部兼容容器保持一讲一容器，测试不得出现教师可见章/小节 |
| 2. 讲数由教师决定 | AI 不拥有课程规模决定权 | 系统根据周次与已选时段给出建议讲数，教师可修改后确认 | 建课和课程信息显示“计划讲数”及建议，不替老师自动锁死 | `planned_lecture_count/lecture_count` 为正式输入；生成 Prompt 只能消费，不能改写 |
| 3. 浙大一课时固定 45 分钟 | “一课时”是 45 分钟；一讲可以占 1、2、3 个或更多连续课时 | 每讲时长按教师选择的连续格计算，不设“两课时一讲”默认 | 课表一格代表 45 分钟，界面明确标注 | 服务端常量和校验固定为 45；单讲时长为连续格数 × 45 |
| 4. 建课时设置真实周课表 | 排课属于课程基础信息，不属于大纲正文 | 学年、学期、起止周、星期/节次格和地点共同形成课程级计划 | 教师可点击 7×13 课表任意格；一周可选多次课，连续格自动组成一次授课 | 保存结构化 `schedule_slots`、`active_week_start/end`；旧 weekday/periods 仅作投影 |
| 5. 当前不做停课、调课和补课 | 单次例外日程不属于本轮课程定义 | 等接入浙大系统后再由外部校历形成例外 | 当前界面不出现不可用入口或假状态 | 不新增例外日程表、接口和迁移；规格明确排除 |
| 6. 放弃旧章/节课程迁移 | 历史课程不是新讲次模型的强制输入 | 旧课程保持原样可读，新课程只走 `lecture_v1` | 不出现迁移向导、批量转换或确认弹窗 | 不运行数据迁移；兼容读取与新建写入边界测试分开 |
| 7. 课程基础信息与大纲分责 | 名称、编号、类别、学分、周学时、对象、先修课、学期、时间、地点、学习目的、学科类型、课程教学类型属于课程基础；简介、目标、考核属于大纲 | 课程信息是后续生成共同输入，不复制大纲内容 | 课程信息始终从右栏顶部进入，创建与编辑使用同一字段 | `course_profile + teacher_course_brief` 原子同步；大纲字段不回写建课表单 |
| 8. 课程库只保留两种课程级状态 | 课程级只有“备课中/备课完成” | 任务暂停、失败、待确认属于讲次或产物局部状态 | 课程卡不显示含糊的“待处理”课程状态 | 状态由正式产物推导，不用任务状态直接赋值 |
| 9. “备课完成”按全课正式结果推导 | 大纲和每讲教案、讲义、PPT 都是完成条件 | 计划讲数确定分母；全部确认才完成 | 未完成项在对应讲次提供下一动作 | 投影检查大纲确认和 N 讲三类产物确认；覆盖缺失、失败和追加讲次测试 |
| 10. 大纲是整门课的按周按讲计划 | 大纲讲清课程设计和每讲轮廓，不承担逐分钟教案 | 一次生成全课大纲，确认后形成全部讲次 | 中间栏显示正式大纲文档与按讲进度 | 同一结构化模板投影中英文简介、目标、教学与考核、周讲进度、日历/思政、参考资料和课程网站 |
| 11. 每讲大纲控制在可读轮廓 | 每讲需同时说明内容、结果和前后关系 | 默认目标为 100–180 个中文字，超长不作为教案塞入大纲 | 教师看到完整但不过长的讲次条目 | Prompt 和质量检查对信息完整度与长度共同校验 |
| 12. 生成顺序按“全课大纲 → 全部讲次教案” | 大纲先决定课程整体结构，教案再落实课堂执行 | 教师确认大纲后可批量生成全部教案；每讲独立失败、重试和确认 | 批量任务显示总进度和单讲状态，不要求逐讲重复启动 | 父任务管理 N 个讲次子任务；成功结果不因单讲失败被清空 |
| 13. 一讲只对应一份正式教案 | 教案的正式边界与讲次一致 | 教案内部不再拆成可独立确认的小节 | 左侧按讲选取，中间显示本讲完整教案，无教案小节 Tab | `lesson_unit_id` 对应一份工作修订和确认修订；内部 section 仅作兼容载体 |
| 14. 教学目标固定为三类 | 目标名称只用“知识目标、能力目标、育人目标” | 三类共同指导教学块；育人目标无依据时可留空，不由 AI 编造 | 三组字段直接编辑，不再增加过程方法、创新力、达成证据等平行分类 | 结构化字段与生成、编辑、导出共用；兼容 `learning_objective` 只作投影 |
| 15. 教案采用正式外壳 | 外壳包含基本信息、三类目标、重点难点、本讲教学设计、教学资料与活动记录 | 课前准备按需；总结、作业、拓展放在教学过程之后；照片由教师课后补充 | 画布连续阅读与编辑，不把栏目做成二级产品层级 | 单一模板函数供 Prompt、编辑器和导出使用；AI 返回的活动照片强制清空 |
| 16. 课堂过程由动态教学块组成 | 教学块是讲内专业执行单元，不是固定教学步骤 | 每块必须包含时长、目标/内容、教师活动、学生活动、产出、检查、反馈/调整、衔接、讲义/PPT 映射 | 中间栏按实际顺序呈现块，可连续编辑，不预置无意义空卡 | 编排器补全合同，保存和确认共用质量门；缺字段时阻止确认并定位到块 |
| 17. 教学块结构随学科变化 | 数学、语言、实验、项目等课程拥有不同专业动作 | 学科标准包决定候选结构；案例、讨论、实践按需选用，不能每讲固定全出现 | 教师看到的是本讲实际结构，不看到通用九步模板 | `subject_standard_pack` 与统一编排器共同生成；Prompt 禁止硬编码固定顺序 |
| 18. 讲义和 PPT 严格承接已确认上游 | 讲义是教师可直接讲授的完整内容；PPT 是讲义的课堂表达 | 已确认教案生成完整讲义，已确认讲义再生成 PPT 文书和 PPT | 未确认上游时下游主操作禁用并说明原因 | 保存来源修订向量；生成接口校验确认状态，失败保留最后可用版本 |
| 19. 左栏只负责生产顺序与定位 | 左栏不是资料栏或课程信息栏 | 主序为大纲、教案、讲义、PPT；题库等进入其他课程文件 | 保留既有三栏布局和左栏位置，不重做页面骨架 | 只调整阶段数据和名称，不改工作台网格合同 |
| 20. 中栏承载正式内容和主要命令 | 中栏是当前产物的正式查看、编辑和审阅区 | 与当前对象直接相关的生成、保存、确认、AI 审阅位于内容顶部或就近位置 | 不把课程信息按钮移到左上角，不用说明卡挤占正文 | 复用既有内容画布与命令组件；桌面同视口做前后截图验收 |
| 21. 右栏始终先显示课程信息 | 课程信息是所有生产阶段的稳定上下文 | 无论是否已有资料，入口始终存在；资料操作位于其下 | 顶部固定“课程信息”，下方分别显示“上传资料文件/上传参考文件” | `CourseReferenceTray` 固定入口并通过统一事件打开信息面板 |
| 22. 右栏随任务状态改变 | 右栏同时承担操作和状态，但同一时刻只展示当前有用内容 | 准备、生成、暂停、失败、待审阅、已确认六态决定可用命令 | 生成时隐藏加号和移除；暂停显示继续/取消；失败显示原因、保留来源、重试；审阅/确认显示真实来源和重生成提示 | 状态由真实 job/revision 派生；上传锁定、暂停/恢复/取消/重试调用原任务；动效尊重 `prefers-reduced-motion` |
| 23. 资料文件与参考文件分开 | 资料文件是主要内容来源，参考文件是补充来源 | 两类来源拥有不同角色但进入同一生成快照和来源审计 | 两个上传入口始终清楚区分，完成后可查看、调整和移除 | 关系表保存 `primary/reference`；生成绑定和产物来源回执可追溯 |
| 24. 全课 AI 审阅必须保留 | AI 审阅是正式作者能力，不是可隐藏的实验入口 | 统一走“提出要求 → 查看影响 → 审阅候选 → 应用或撤销” | 入口留在工作台主要命令区；复杂不成为隐藏理由 | 继续复用候选、影响、正式命令、回执和撤销，不建立第二修改链 |
| 25. UI 改造以既有三栏为基线 | 本轮改变内容与状态，不改变工作台基本空间关系 | 新机制嵌入左导航、中内容、右操作/状态的既有职责 | 不整体换布局；只修正错误入口、阶段名称、动态状态和教案画布 | 改前后同页面、同数据、同桌面视口比较；构建、交互和控制台同时通过 |

生产顺序因此固定为：

```text
课程信息与周课表
→ 教师确认讲数
→ 生成并确认全课大纲
→ 批量生成、逐讲审阅并确认教案
→ 按讲生成并确认完整讲义
→ 按讲生成并确认 PPT 文书与 PPT
```

| 6. 审阅增强 | 通用视频、数字人和自动配音 | 范围外 | 不进入 V1，不作为课程可用性的依赖 |
| 7. 交付运维 | 课程修订与确认回执 | 已有 | 补来源对齐、草稿处理、质量报告和重复确认幂等 |
| 7. 交付运维 | 历史比较和恢复 | 部分 | 恢复必须创建新修订，不能覆盖或倒退历史 |
| 7. 交付运维 | 中英文与响应式页面 | 部分 | 对全部新增流程执行 locale、窄屏、键盘和读屏验收 |
| 7. 交付运维 | 教师任务级遥测和交付看板 | 缺失 | 串联请求、模型单元、修订、错误、恢复和完成指标 |
| 7. 交付运维 | 功能开关、白名单和只读降级 | 部分 | 增加分能力控制、紧急停止写入和数据不删除验证 |
| 7. 交付运维 | 真实模型交付基准与教师试点 | 缺失 | 至少 20 次 12 小节真实运行并完成端到端教师验收 |

## Goals / Non-Goals

**Goals:**

1. 教师从空白课程开始，在一个连续工作区完成创建、生成、编辑、质量审阅、确认、学生视角预览和再次修订。
2. 课程要求、目录、教案和正文均可手工编辑；高影响修改必须先形成草稿、差异和影响报告。
3. 教案成为可实际执行的课堂教案，同时继续作为知识、正文、练习和外部教学表达的教学语义来源。
4. AI 只生成结构化候选，教师确认前不改变正式课程；冲突、失败和重启不丢失最后可用产物。
5. 课程生成达到量化的真实模型性能、成功率和质量发布门。
6. 提供四类受控动画，任何多模态失败都能安全降级。
7. 通过中英文、桌面、平板、窄屏、键盘和读屏相关验收后灰度上线。

**Non-Goals:**

1. 不实现文件夹、文件权限、学校模板导出和通用文件管理，只消费资源引用、解析文本和来源信息。
2. 不实现第二套通用 PPT 视觉编辑器、动画回导或任意 PPT 深度优化。允许对课程空间中不可变的外部 PPTX 建立页级文字索引、一致性审阅和可恢复文字修订；只有教师确认后的修订才能登记为当前 PPT。
3. 不实现班级、学生名单、单次停课/调课/补课、多人协作、审批流和 LMS 管理；建课所需的固定周课表属于本变更范围。
4. 不实现数字人、通用视频课、自动配音、任意 HTML/JavaScript 或模型生成代码执行。
5. 不把学生个性化课程生长、长期学习效果或个人学习地图纳入 2026 年 9 月 1 日发布门。
6. 不以追求出版级视觉和完全自动生成取代教师审阅；V1 的目标是可用、可控、可恢复的教师初稿生产线。

## Decisions

### 1. 交付范围是生产级 V1，而不是无限功能集合

V1 的完整性按边界判断：进入本规格的功能必须具有输入、处理、输出、异常、权限、状态和验收；未进入范围的功能必须关闭或清楚标记为不提供，不能以空按钮、演示数据或“即将支持”参与发布验收。

**替代方案：**把长期蓝图全部纳入本次发布。该方案会让学生侧生长、PPT、文件系统和视频生成挤占教师作者主链，无法在四周内完成真实故障与质量验收，因此拒绝。

### 2. 不建立教师课程副本，工作台只是领域真源的作者投影

教师工作台读取一个聚合 `TeacherCourseAuthoringProjectionV1`，但该投影不独立持久化课程正文。它由以下当前对象确定性组成：

```text
CourseGenerationRequest
+ CourseBlueprintRevision
+ TeachingPlanRevision
+ CourseDocumentRevision
+ QuestionBankRevision
+ TeachingRepresentation source revisions
+ active GenerationJob / rebuild tasks
-> TeacherCourseAuthoringProjectionV1
```

聚合投影返回每个阶段的正式修订、草稿、质量、过期状态、可用动作和下一步。页面 Store 只能缓存投影，不能成为新的课程状态仓库。

**替代方案：**新建完整 `TeacherCourse` JSON，把目录、教案和正文复制进去。该方案会制造第二真源和跨副本同步问题，因此拒绝。

### 3. 扩展现有生成请求，而不是把教师条件塞进 prompt 文本

新增版本化 `TeacherCourseBriefV1`，作为现有生成请求中的结构化字段组。它在生成工作区中拥有正式修订，发布后随课程 envelope 保存，不独立复制课程内容。

```text
TeacherCourseBriefV1
- academic_term: string, optional, max 100
- active_week_start / active_week_end: integer, required
- schedule_slots: { weekday: 1..7, period: 1..13 }[]
- target_audience: string, required, max 500
- total_class_hours: integer, required, 1..1000
- course_period_minutes: literal 45
- lecture_count: integer, required, >= 1
- teaching_context: classroom | online | blended | self_study
- class_size: integer, optional, 1..1000
- course_type / difficulty / pedagogy modes / grounding strategy
- additional_requirements: string, optional, max 10000
- material_refs: ResourceRef[]
```

教师确认的讲数、总学时、固定 45 分钟课时和周课表是硬约束。系统可以根据有效周数与每周授课段给出讲数建议，但不得由模型静默决定或改写。连续格形成一次授课，一次授课可以占一格或多格。文件系统仅提供 `resource_id`、解析状态、可用文本、来源摘要和访问结果；本系统不根据本地路径读取任意文件。

**替代方案：**继续使用一个“额外要求”输入。该方案不可验证、不可稳定迁移，也不能确定性检查课时，因此拒绝。

#### 3.1 课程基础信息面板聚合现有两类元数据

面板只是同一门课程基础信息的聚合投影，不建立第二份课程信息。`course_profile` 继续保存编号、类别、学分、专业、课程简介等教务档案；课程基线保存三种学习目的之一、八种一级学科之一、六种课程教学类型之一、难度与课时，讲次修订保存七种本讲课型之一。内容编排先由 `学习目的 × 一级学科类型 × 课程教学类型` 形成整课结构，再由 `本讲目标 × 本讲课型 × 学科规则 × 课程约束` 形成教学块。旧 `generation_request` 中的 `course_type`、学科细分、`teaching_context`、`grounding_strategy` 与 `composition_style` 等字段只保留读取和历史请求兼容，不再作为教师独立输入或平行编排状态。

修改时由一个课程信息命令同时更新两者，并强制同步以下重复字段：

- `course_profile.total_hours` 与 `teacher_course_brief.total_class_hours`；
- `course_profile.target_grade`、`generation_request.target_audience` 与 `teacher_course_brief.target_audience`；
- `academic_year + term` 与 `teacher_course_brief.academic_term`；
- 学习目的与当前 `course_intent` 的兼容目标字段。

课程名称在本面板中只读。修改课程名称同时涉及 `CourseDocument.title` 与文件空间名称，应由独立课程重命名命令承担，不得在元数据面板中只改一处。

每次修订保存完整的上一版基础信息快照。查看历史和恢复只操作这些基础信息，不嵌入大纲、课次、教案、讲稿、PPT 或资料引用。修订成功后只更新后续生产所读取的基线，不自动重生成现有产物。

**替代方案：**把“课程上下文”做成下游产物总览。这会混淆课程基础约束与生成结果，并重复文件视图的职责，因此拒绝。

### 4. 按讲大纲变化使用领域操作，不直接覆盖整份蓝图

目录草稿增加以下白名单操作：

- `INSERT_LECTURE`
- `UPDATE_LECTURE`
- `MOVE_LECTURE`
- `SPLIT_LECTURE`
- `MERGE_LECTURES`
- `RETIRE_LECTURE`

每个操作必须携带 `base_blueprint_revision_id`、稳定讲次 ID、预期旧值摘要、幂等键和教师理由。新讲次由系统分配 ID；移动必须保持依赖无环；合并或退休已发布讲次时保留墓碑和历史引用。章、小节操作只允许旧课程兼容读取，新课程不得写入。

目录草稿保存不改变正式目录。教师应用后创建新目录修订，并根据节点身份和来源向量计算下游状态：`unchanged / stale / rebuild_required / blocked`。未受影响节点继续复用，禁止把目录变化一律升级为整课重做。

**替代方案：**前端编辑整份 JSON 后 `PUT` 覆盖。该方案无法处理并发、幂等、历史锚点和局部影响，因此拒绝。

### 5. 每讲教案扩展 `CourseTeachingPlanV3`，不建立另一份学校教案

`CourseTeachingPlanV3` 保持唯一教学设计真源。总体层新增：

- `academic_term`
- `total_class_hours`
- `lesson_duration_minutes`
- `teaching_context`
- `class_profile`
- `teaching_preparation`
- `course_assessment_plan`

分讲层新增：

- `planned_minutes`
- `key_difficulties`
- `knowledge_objectives / ability_objectives / education_objectives`
- `teacher_activities / student_activities`
- `resource_refs`
- `in_class_checks`
- `expected_output`
- `feedback_strategy / adaptation_options`
- `transition`
- `handout_ppt_mapping`
- `homework`
- `teaching_notes`

教学块增加时长、目标与内容、教师动作、学生动作、预期产出、检查、反馈与调整、衔接、讲义/PPT 映射，并支持插入、删除和排序。所有教学块分钟数之和必须与本讲课时合同一致；稳定知识 ID、模块 ID、来源绑定和系统质量字段继续只读。块的类型和顺序随学科与本讲目标变化，案例、讨论和实践均为按需能力，不是固定必需步骤。

教师确认的本讲编排是块身份、顺序和时钟的唯一权威。模型只补充教学内容，不得改变 `arrangement_block_id`、`module_id`、讲次归属或分钟数；生成、AI 候选采用、手工保存和确认必须经过同一个对齐函数和课时质量门。模型漏掉教学块字段时，系统从同一已确认编排恢复缺失合同并保留已有有效内容；总分钟数与确认编排不一致时不得确认。活动照片只由教师课后补充，模型输出不得写入。

教案草稿、AI 候选、差异、正式修订、历史和恢复继续由 `upgrade-teaching-plan-workbench` 拥有。本变更不创建第二教案仓库。

**替代方案：**另建“学校教案”文档并从课程教案导出。该方案会让教师修改无法稳定反向影响课程，形成双真源，因此拒绝。

### 6. 正文编辑采用独立草稿，正式应用复用课程命令

新增按 `course_id + actor` 隔离的 `CourseContentDraft`。草稿只保存操作列表和预览，不复制整门课程：

- `PATCH_COURSE_SPAN`
- `REPLACE_COURSE_BLOCK`
- `INSERT_COURSE_BLOCK`
- `RETIRE_COURSE_BLOCK`
- `REORDER_COURSE_BLOCK`

手工输入以 650 毫秒防抖保存到服务端草稿，保存失败时前端保留未同步值。AI 改写复用现有块候选服务，但必须进入同一草稿和差异审阅，不允许学习侧临时回答直接变成正式正文。

应用时，`CourseCommandService` 校验文档修订、块修订、知识引用、操作顺序和幂等键，并以一次逻辑操作组形成新 `CourseDocument` 修订。重复提交返回原回执；任一操作失败时不报告部分成功。

**替代方案：**每次失焦直接写正式块。该方案没有审阅、冲突和批量撤销边界，因此拒绝。

### 7. AI 负责判断影响，索引、Rank 与关系图负责让它少读、快读和不漏读

全量 AI 扫描全部正式文件是影响判断的语义基线，但不能成为每次修改的默认执行方式。课程越大，全量扫描的等待、token 和重复读取成本越高。因此系统在大纲、教案、题库、讲稿、PPT 及后续正式资产生成或发布时，同时建立可重建的 `CourseChangeIndexV1` 投影：

```text
课程 / 正式文件 / 章节 / 小节 / 教学模块 / 题目 / 讲稿块 / PPT 页面
+ 原文定位、摘要、实体、知识与目标绑定
+ 关键词倒排、embedding、结构路径、显式来源关系
+ 内容哈希、正式修订和正反向邻接索引
```

索引不是课程真源，也不能替代原文。AI 最终判断一个候选是否受影响时仍读取该候选的正式内容。正式变化使用以下循环：

```text
保留老师原话并形成可修订的意图解释
-> 关键词 / 实体 / 语义 / 结构 / 显式关系多路召回
-> Rank 高召回候选
-> AI 精读并判断直接、间接、可能与不受影响
-> 根据新线索继续扩展召回
-> 覆盖度检查或低置信度回退扩大扫描
-> 生成逐单元候选与影响回执
```

显式依赖关系负责加速候选扩展、解释“为什么受影响”和应用后的一致性校验；向量相似度负责发现没有显式绑定的语义候选；AI 负责结合老师目标和正式原文判断真实影响。任何单一信号都不得直接发布修改。

工作台不得为了复用小节修改接口而给全课要求伪造 `section_id`。课程级读取使用一次性 `TeacherCourseChangeContext` 投影：优先读取正式 `CourseDocument`，正式文档尚为空时继续读取教师大纲生成工作区，并按原领域仓库聚合 `TeacherLessonAuthoringRepository`、`TeachingRepresentationRepository` 和 `QuestionBankRepository` 的当前修订。投影只保存稳定单元 ID、来源修订、短文本与关系键，不拥有或回写任何课程正文。

```text
CourseDocument / TeacherOutlineWorkspace
+ TeacherLessonAuthoring (lesson plan + script)
+ TeachingRepresentation (V6 PPT pages)
+ QuestionBank
-> disposable CourseChangeIndex projection
-> cross-asset high-recall candidates
-> AI impact judgement
-> CourseEvolutionPlan.teacher_change_planning
```

课程级入口为 `/evolution/course-context` 与 `/evolution/course-plans`；现有 `/evolution/plans` 继续服务真实小节或内容块修改。两条链不得通过猜测预览节点来互相冒充。课程结构、正文或资产尚未生成时，工作台显示 `available / partial / stale / missing` 的真实就绪状态；只有所有可分析来源均为空时才返回 `course_change_source_unavailable`，该错误不得被前端归类为修订冲突。

教师端使用 `/course/:courseId/changes/:planId?` 独立路由承载全课长任务，不再把可恢复、多阶段工作压进课程页弹层。顶部四阶段始终表示老师的决策进度；请求态保持单栏，分析态渐进披露影响，结构态先确认候选课程树与迁移范围。界面必须分别标记“预计影响”“修改候选”“实际回执”：当前仅完成预计影响时，流程仍停留在“分析影响”，不得通过按钮或文案暗示候选已经生成。

#### 7.1 老师的语言是证据，不是必须准确填写的命令枚举

系统保存 `CourseChangeIntentV1.raw_request`、当前 `interpreted_goal`、硬约束、偏好、保护要求、假设、信号与待澄清问题。内容、结构与混合只属于内部执行策略：

- 没有足够证据时先用成本较低的语义发现路线，但将策略标为 `provisional`；
- 扫描中发现章节、课时、先修或教学目标边界变化时，可在保留原话的前提下升级为结构或混合策略；
- 老师补充目标、纠正 AI 理解或课程现场出现新证据时，新计划通过 `supersedes_plan_id` 取代旧计划，旧解释和候选继续可追溯；
- 只有安全所必需且无法从课程现场推断的问题才阻断执行，不要求老师先学会系统术语。

`CourseChangeScenarioMatrixV1` 只用于覆盖设计、提示 AI 检查遗漏和建立测试集，不是要求老师选择的产品分类，也不得成为硬路由表。

| 场景族 | 初始策略 | 允许的动态变化 |
| --- | --- | --- |
| 精确术语、版本或实体更新 | 语义影响 | 发现课程目标或结构变化后升级混合 |
| 知识事实、政策或来源更新 | 语义影响 | 来源不足或范围不收敛时扩大扫描或阻断 |
| 教学目标、难度、受众或教学策略变化 | 语义影响 | 需要重排章节、课时或先修时升级结构 |
| 考核、题库或评分标准变化 | 语义影响 | 改变课程目标或章节组织时升级混合 |
| 重命名、移动或重新排序 | 结构重整 | 破坏教学叙事时追加语义重写 |
| 新增或退休章节 | 结构重整 | 对新内容生成、旧引用迁移和缺口补齐 |
| 拆分或合并章节 | 结构重整 + 语义判断 | 根据旧资产实际适配性决定迁移或重生成 |
| 整课重构 | 约束式重新生成 | 旧资产作为来源、保护项和可复用候选池 |
| 模糊、变化中或混合表达 | 临时语义发现 | 随课程证据和老师补充动态重规划 |

#### 7.2 内容变化按影响检索处理

内容变化至少覆盖术语版本、知识事实、教学目标、受众难度、教学策略、案例资料、考核标准、局部增删和纯视觉表达。系统先定位可能受影响的正式单元，再由 AI 阅读原文并决定：保持、重新绑定、局部改写、重新生成、退休或等待老师确认。

内容路线不得在发现结构改变后继续按文本替换执行。涉及章节数量、归属、顺序、课时、先修或教学职责边界时，必须进入结构路线，再基于新结构生成内容候选。

#### 7.3 结构变化是以旧课程为基础的约束式重新生成

结构变化不是普通内容修改的扩大版，也不是一律整课重做。系统先形成结构操作和候选课程图，再决定旧资产在新结构中的去向：

```text
CurrentCourseGraph
+ CourseStructureOperation[]
-> ProposedCourseGraph
-> IdentityMapping
-> CourseUnitMigration[]
-> 下游候选重整与重新生成
```

结构操作使用以下可执行原语；AI 可以从任意自然语言组合出它们，但不能发明绕过领域校验的写入方式：

- `INSERT_OUTLINE_NODE`
- `UPDATE_OUTLINE_NODE`
- `MOVE_OUTLINE_NODE`
- `REORDER_OUTLINE_NODES`
- `SPLIT_OUTLINE_NODE`
- `MERGE_OUTLINE_NODES`
- `RETIRE_OUTLINE_NODE`
- `REBUILD_OUTLINE`

重命名、移动与排序通常保留稳定 ID；新增生成新 ID；退休保留墓碑和历史引用；拆分形成一对多映射；合并形成多对一映射；整课重构允许建立新的候选结构，但旧课程继续作为来源、保护约束与可复用资产池。

每个大纲、教案、题目、讲稿块、PPT 页面或其他正式单元都必须获得一个可解释的迁移判定：

| 判定 | 含义 |
| --- | --- |
| `reuse_exact` | 身份、内容和归属不变 |
| `reuse_rebind` | 内容仍适合，只改变章节、来源或目标绑定 |
| `rewrite_partial` | 保留核心内容，重写标题、转场、例子或表达 |
| `regenerate` | 旧内容已经不适合新的目标或结构，重新生成 |
| `retire` | 新课程不再使用，但保留历史和引用解析 |
| `blocked` | AI 无法可靠归属、保护要求冲突或硬约束未通过 |

迁移率不是目标。系统不得为了显示“复用很多”而把不合适的旧内容硬塞进新章节，也不得为了实现简单而把仍然适用的教师确认内容全部重做。

#### 7.4 五类教师资产按自己的语义迁移

| 资产 | 可优先迁移 | 通常需要改写或重生成 |
| --- | --- | --- |
| 大纲 | 未变化的稳定节点、原有资料和目标引用 | 新章节边界、目标分配、先修和课时 |
| 教案 | 仍符合目标的模块、活动、案例和检查 | 新讲次教学设计、拆分课时、合并后的课堂流程 |
| 题库 | 知识与能力绑定仍有效的题目 | 新知识缺口、重复题、答案依据或评价标准变化 |
| 讲稿 | 独立完整且仍适配的讲解块 | 开场、转场、总结、拆分或合并后的叙事链 |
| PPT | 语义未变的页面与纯视觉组件 | 页序导航、新章节页、来源讲稿已变化的页面组 |

结构候选先通过层级、无环、课时、先修、目标与知识覆盖检查。教师确认结构理解后，系统才按新结构拓扑并行生成下游候选，避免在错误结构上浪费模型调用。最后一次发布仍需展示完整影响、保护项、阻断项和实际回执。

#### 7.5 计划是编排候选，不是第二课程真源

`CourseChangePlanV1` 作为当前 `CourseEvolutionPlan` 内的教师全课变更规划元数据，保存意图、执行策略、结构操作、单元迁移和基础修订向量。正式大纲、教案、题库、讲稿和 PPT 仍由各自领域仓库拥有；计划只能调用这些领域命令或生成器形成影子候选。

影响范围审阅只在计划内保存选中与排除的 `migration_id`、审阅时间和 `formal_content_changed=false`。在领域执行器尚未返回候选和应用回执前，前端只能称为“影响计划”或“已保存范围”，不得显示成已生成候选、已应用或版本冲突。

候选发布前必须满足：基础修订仍然一致、结构检查点已确认、保护内容没有被静默改写、需要 AI 生成的单元候选已经就绪、所有 `blocked` 项均已处理。发布失败保留 last-good；刷新、重试或重新解释老师要求不得覆盖旧计划历史。

**替代方案一：**每次让模型读取所有正式文件。该方案可作为低置信度回退，但默认使用会造成不可控等待和 token 浪费。

**替代方案二：**只依赖显式关系或向量相似度决定影响。前者会漏掉隐含语义，后者无法证明正式范围，两者都不能代替 AI 阅读原文。

**替代方案三：**结构变化一律迁移或一律整课重做。前者会保留不再适配的内容，后者会覆盖教师确认资产；系统必须逐单元选择迁移、改写、重生成或退休。

### 8. 首次生成继续使用一条完整主链，并把教师可见结果逐阶段发布到工作区

保留当前完整链：

```text
TeacherCourseBrief
-> 目录骨架与批次
-> 目录确认
-> 全课教案骨架、批次与本地汇编
-> 知识和块职责确定性编译
-> 正文有界并行
-> 正式练习定向补齐
-> 发布质量门
-> 教师确认
-> CourseDocument
```

每个模型单元使用连续无输出超时、最终载荷预算、提供方共享容量调度和最多一次局部纠正。小节失败不能取消其他小节；服务重启只恢复缺失单元；本地降级必须显式标记 `review_required`，不得冒充完整 AI 质量。

教师确认的计划讲数和按讲大纲写入同一任务的修订约束；恢复任务、批次重算和最终大纲汇编都必须精确复用确认后的讲数，不能再次从原始提示推断规模。终态任务索引省略请求快照时，恢复入口从任务隔离工作区还原 `generation_request`；已确认大纲不再因派生指纹变化被丢弃。分讲讲义按已确认教学块逐块生成；未闭合但可唯一判断的 Markdown 公式定界符先做局部格式修复，无法确定的格式错误只阻断当前块并保留此前检查点。提供方认证、额度和后备通道失败只建立有界冷却，冷却到期后必须允许同一任务继续，不得依赖重启进程解锁。

无原版 PPTX 时，教师生成界面执行“PPT 文书 → PPT”两步。模型请求只消费完整验证合同的有界投影：保留每个讲稿块身份、显式标题、必要来源摘录和最多两个代表性安全分页方案，删除重复证据和版式组合，并在调用前执行字符预算预检；完整未压缩合同继续作为返回结果校验真源。相邻短讲稿块通过稳定页面组进入故事规划，代表性分页优先选块数均衡的完整方案，避免一块一页或先过度塞满再生成大量续页；页面标题优先使用已确认讲稿块标题，但必须投影为学生可见的学习主题，“给出、提供、选取、重点突出”等生产指令不得进入标题或台上正文。AI 故事规划通过后，其页面摘要拥有学生画布的精简投影，编译器不得再把同一讲稿的完整 prose 回填为续页；完整讲述只进入 speaker notes。整讲至少建立课程开场、学习路径和课堂收束，模板负责视觉层级与容量，不得用卡片容器替代页面叙事。超预算、标题不可分配、缺失开场/路径/收束和提供方失败必须返回可解释失败码与单一恢复动作，不能解锁第二步或发布不完整文书。故事或视觉提供方暂时不可用时，只允许生成绑定已确认来源、显式标记降级且必须经教师确认的文书；未确认降级文书不得直接编译或发布 PPT。教师选定的主题冻结在文书修订中并贯穿 Web、PPTX 与导出接口，任何后续阶段不得静默回退到默认主题。导出还必须通过必需来源区域、文本框溢出、Web/PPTX 合同一致和客观级质量门。

不增加为动画、教学画像、关系图或普通质量评分服务的整课模型调用。新增模型调用必须证明其产生不可由已有结构化事实或模板编译的教学语义。

### 9. 质量分为发布硬门和教师建议，不用一个总分决定发布

发布硬门只覆盖：

- schema 和修订一致性
- 用户显式规模与课时合同
- 必需目录、教案、知识和正文存在
- 稳定 ID、来源和知识绑定有效
- 正式练习公开/私有合同完整
- 空块、坏公式、坏代码围栏、坏图示和不可解析动画
- 过期下游被错误标记为最新

教师建议覆盖：表达密度、例子丰富度、活动可实施性、重复、节奏和可选多模态机会。建议不得自动触发整课模型重写，也不得因为风格偏好阻止发布。

教学大纲的教师建议先对结构化真源做一次确定性的整篇审读，识别课程定位缺失、目标套话、标题负载过重、跨批次重复和达成检验模板化。报告只保存规则版本、定位、证据与修复指令，不生成第二份大纲，也不返回主观总分。默认界面以正式文档投影呈现课程定位、全课成果、先修要求和教学进度；结构树只在教师编辑或主动切换时出现。

教师在首次大纲确认阶段选择带节点定位的建议后，系统把该建议转换为现有大纲原子操作候选，只允许定点修改名称、目标、范围、达成检验与前置关系。整篇字段缺失或已离开首次确认阶段时只给出建议，不伪装成当前原子协议可执行的按钮。候选仍需经过确定性结构校验与教师确认；系统不得因为建议存在而自动写入、自动整课重写或阻止确认。

固定评测集至少覆盖八类学科模板、系统学习与项目实战、3/12/21 节规模和资料充分/不足两类输入。每次模型、Prompt、调度或 schema 变化都要输出同输入对比。

### 10. 动画使用白名单模板和静态降级

保留 `animation_spec_v1` 的知识引用、对象绑定、关键帧、降级帧和无障碍文字，新增长度与模板限制。V1 模板注册表固定为：

- `process_flow_v1`
- `timeline_v1`
- `state_transition_v1`
- `math_algorithm_steps_v1`

模型只选择模板并填充受约束参数，不能返回脚本、任意坐标绘制程序、HTML 或 JavaScript。前端提供播放、暂停、上一步、下一步、重置、进度和文字说明；`prefers-reduced-motion` 下默认显示关键帧。解析、模板、资源或渲染失败时依次降级为静态关键帧、图示、完整文字。

首版不生成 MP4。以后需要视频导出时，从同一 `AnimationSpec` 派生，不改变课程真源。

### 11. 确认、预览和回滚共用修订，不增加整课发布层

教师可以比较课程要求、目录、教案和正文的当前修订与历史修订。恢复历史版本时创建新的当前修订，不能删除中间版本或把修订号倒退。

大纲、教案、讲稿和 PPT 各自保存工作稿、质量结果和已确认修订；教师确认就是该产物进入正式课程关系的唯一门。学生视角预览使用教师身份直接读取当前课程投影，并复用学习界面的渲染器所见即所得。系统不维护“学生网站”“待发布修改”或整课发布回执，也不要求所有课次同时完成才能预览。

上游变化仍按照来源修订传播 `stale`，但只要求真正受影响的下游对象重新确认；该状态属于对应产物，不升级为整门课程发布阻断。题库、讲稿与 PPT 继续遵守各自的审核和质量边界。

回滚通过关闭功能开关、停止新写入和恢复最后发布修订完成，不删除草稿、历史或失败候选。

### 12. 性能目标以真实提供方 P95 和成功率作为发布门

在固定硬件、固定提供方、固定模型和固定输入集上记录：

| 指标 | V1 发布目标 |
| --- | --- |
| 12 节标准课程端到端成功率 | 不低于 95%，连续真实运行不少于 20 次 |
| 首个目录节点可见时间 | P95 不超过 60 秒 |
| 12 节课程进入最终发布确认 | P95 不超过 10 分钟 |
| 单字段草稿保存 | P95 不超过 1 秒，不含离线等待 |
| 单内容块 AI 候选完成 | P95 不超过 90 秒 |
| 重启恢复开始时间 | 服务健康后 30 秒内进入对账或明确可恢复状态 |
| 已完成单元重复生成率 | 0% |
| 多模态失败导致课程不可读 | 0% |

目标在真实基线测量后可以收紧，但不得无证据放宽。指标不达标时禁止用动画、百分比或本地保底掩盖真实等待和失败。

### 13. 可观察性围绕教师任务，而不是底层调用堆日志

关键事件采用 `teacher_course_<object>_<action>` 命名并至少携带 `course_id`、`job_id`、actor、课程规模、阶段、修订、提供方、模型、耗时、结果、失败码、恢复单元和降级原因。必须覆盖：

- 创建提交、目录首次可见、目录确认
- 教案完成、草稿保存、AI 候选、应用
- 正文首块与全部完成、局部重生成
- 质量阻断、定向恢复、产物确认
- 动画生成、渲染和降级

日志不得保存完整 prompt、模型隐藏推理、教师敏感资料或学生数据。生产看板至少显示成功率、P50/P95、各阶段失败、恢复成功率、降级率和确认完成率。

### 14. 前端保持同一课程空间并提供等价的非拖拽操作

不新增与课程库、课程工作区平行的顶层页面。教师在现有课程工作区中切换目录、教案、课程和各产物确认状态；学生视角预览保留在顶栏并直接读取当前教师投影。PPT 入口先区分“上传并审阅”与“根据已确认讲稿生成”：上传不受前置生成门禁限制，生成仍复用现有 V6 工作台。

外部 PPTX 上传后先保存不可变原件，再建立页、文字块、内容哈希和原形状位置索引。审阅报告显式列出本次实际读取的大纲、已确认教案、当前题库和已确认讲稿修订，只输出定位、依据、置信边界和修改入口，不伪造总分。手工编辑和 AI 修改都写入可恢复工作修订；AI 只能先形成候选，不得直接覆盖工作稿或原件。

完整课程修改与材料更新共用课程空间顶栏的“审计与更新”入口，进入同一独立宽工作区。页面左侧将上传/替换材料和教师全课要求统一显示为变化来源；中间根据来源切换为生成关系或影响范围；右侧承载来源证据、结构化预览、处理判断、保护边界和实际回执。全课修改内部仍按“说出要求—分析影响—审阅修改—应用完成”运行：普通内容变化展示影响导航、原因、当前摘录和范围勾选；结构变化展示新旧课程树与迁移统计；真正应用后才显示实际回执、失败项、未变化项和整次撤销。个人学习地图和学习证据轨迹仍属于学生现场，不进入教师备课产品。

老师原话、AI 当前理解和保护要求是贯穿状态的任务上下文：提出要求后以紧凑上下文条贯通分析、审阅和回执，不永久占用独立右栏；正式应用前可以就地展开修正，应用后只读保留。空态直接进入要求输入，不再用解释卡重复说明系统规则。只有实际发现的资产才进入影响导航，未发现或尚未扫描的五类资产不提前铺满。聊天只负责理解与精调，完整影响和结果由结构化画布承担。

普通内容变化默认展示确定影响、可能影响、保持不变、阻断及“为什么受影响”的因果路径。结构变化切换为新旧课程树、身份映射和逐资产迁移结论，顶部直接汇总复用、重绑、局部改写、重生成、退休和待决定数量。结构确认前不启动昂贵下游生成；应用前称“预计影响”，应用后称“实际结果”，两者不得混用。

2026-08-28 的实现增量继续沿用这一条链路。普通内容修改由 AI 返回基于当前正式字段的精确 `before -> after` 补丁，本地校验命中后编译成既有 `REPLACE_COURSE_BLOCK`；“A 统一替换为 B”这类显式字面替换先由本地正式字段扫描确定性编译，模型不可用或返回非法 JSON 时仍可得到可审阅补丁，零正式命中则返回范围澄清，不能展示“应用 0 项”的假候选。整课结构修改必须返回完整目标树、旧新身份来源和显式退休节点，本地校验完整性后编译成一个 `REBUILD_COURSE_OUTLINE`。两类候选都进入同一个 `CourseEvolutionPlan`，教师可以逐项排除，应用时仍调用既有原子操作组、修订检查、幂等回执和撤销，不建立第二套课程正文、结构写入口或任务状态机。未生成安全候选的下游教案、题库、讲稿和 PPT 必须在实际回执中标为未变化或失败，不能把预计影响冒充已完成联动。

资料增强同样扩展现有 `MaterialAsset -> ParsedDocument -> EvidenceBlock` 管线。现代 Office 继续直接解析；旧 `.doc/.ppt/.xls` 只在隔离临时目录中经 LibreOffice 转成对应 OOXML 后复用原解析器，原件保持不可变；文本型 PDF 解析为空时才进入本地逐页 OCR，并保存页码、区域和置信度；PPTX 在文字之外确定性提取对象位置、图表系列、讲者备注、图片数量/替代文本边界及“存在动画但不解释动画语义”的证据。转换器、OCR 或视觉证据不足必须显式降级并保留警告，不得虚构图像、公式、动画或版式含义。

真实微积分题库复跑暴露出另一类结构问题：同一讲的完整技能与全部可观察证据被同时广播给每一道题，导致单题任务过长、难度漂移，并在语义与解答质量门被整体拒绝。修复继续复用现有 `assessment_blueprint -> assessment_semantics -> assessment_orchestrator -> question_bank_rebuild` 链路：蓝图的概念、目标、掌握槽位各自编译一个主要目标、允许的学习者动作数、推理步数和题干长度预算，模型只消费当前槽位的有界投影，三个槽位共同覆盖讲次。课程兼容准备与逐题模型活动都续写同一个重建任务的正式心跳；质量门拒绝后保持当前有效题库，不用降门或平行生成器换取表面成功。

失败讲次重试仍是同一课程检查点的有界恢复：范围任务只有在课程、评估合同和题库重建合同与原整课检查点一致时，才能把成功节点合并回原 `published_node_ids` 并移除对应失败；原计划节点全部完成后才把整课任务改为完成。范围任务的 bundle 仍进入同一正式题库修订，不拥有第二套课程状态。

桌面端可以使用拖拽排序，但键盘、触屏和窄屏必须提供“上移、下移、移入章节、移出章节”等菜单命令。所有图标按钮提供 tooltip 和读屏名称。新增文案同步维护 `zh` 与 `en` locale；390、789、1024、1440 像素均不得出现遮挡、不可达操作、原始翻译 key 或中文残留。

## Risks / Trade-offs

- **四周内同时补齐作者能力、质量和动画，范围仍然偏大** → 将课程与教案编辑、确认和恢复设为阻断主线；动画通过独立开关和静态降级交付，不能反向阻塞核心确认。
- **现有产品蓝图以学习者为核心，教师端优先可能造成产品叙事冲突** → V1 只提升课程创建者和教师审阅能力，不引入班级与 LMS；规格确认后对产品蓝图做最小语义修订。
- **新课堂字段可能扩大 Prompt 并拖慢教案生成** → 只在相关批次传递当前小节的课时切片；课程级字段由本地编译进入总体教案，不重复广播完整对象。
- **目录结构编辑可能破坏笔记、作答和知识绑定** → 已确认节点使用退休与新修订，不硬删除；应用前必须生成影响报告，存在活动 Attempt 或无法迁移的引用时阻断。
- **教案与正文同时编辑可能产生交叉冲突** → 两类草稿记录各自基础修订；任一正式应用后，另一草稿重新计算影响并标记冲突，不静默合并。
- **真实模型性能受供应商额度和限流影响** → 复用共享容量调度、负健康缓存和明确提供方错误；发布报告同时记录模型内耗时与端到端耗时，不用本地回退算成功。
- **教师内容质量评价主观** → 硬门只判断明显错误，教师量表使用结构完整、目标一致、可实施、事实风险和修改负担五个维度，保留原始评分和理由。
- **动画模板覆盖不了所有学科** → V1 只在可确定表达的四类概念上启用；不适配时选择图示或文字，不强制每节生成动画。
- **现有活动 OpenSpec 范围重叠** → 本变更只做教师端总控和整链发布门；详细教案草稿行为继续由 `upgrade-teaching-plan-workbench` 拥有，学生适应任务不计入本次完成度。

## Migration Plan

1. 固化当前 `CourseDocument`、目录、`CourseTeachingPlanV3`、题库修订、教学表达、任务恢复和中英文前端基线；建立 3/12/21 节及八类学科验收夹具。
2. 增加 `TeacherCourseBriefV1` 与课堂教案字段的向后兼容读取。新课程只写新字段；旧课程缺失字段时显示“待补充”，不得伪造课时或师生活动。
3. 在功能开关后上线目录结构命令、教案课堂字段和正文草稿。先对新建 V3 课程开放，再对完整绑定的旧课程开放显式迁移。
4. 接入多粒度课程索引、混合召回、Rank、AI 精读判断、直接结构影响和逐单元迁移。开始阶段只生成报告并标记状态，确认对账稳定后再开启候选任务；结构变化先确认候选结构，再生成下游。
5. 接入动画模板注册表，先开放静态预览，再开放播放；任何异常自动关闭对应模板并回退。
6. 使用真实模型完成不少于 20 次 12 节课程运行，以及 3/21 节、资料充分/不足、服务重启、断网和提供方失败矩阵。
7. 由至少 5 名目标教师完成“新建课程—改目录—改教案—改正文—处理质量—发布—恢复历史”任务；收集完成率、耗时、求助和阻断问题。
8. 按内部测试课程、新建课程 10%、50%、100% 逐档灰度。每档观察不少于一个完整生成周期，关键指标恶化时关闭写入或动画开关。
9. 发布后保留旧读取链一个版本周期；确认没有新写入后再退役被新命令接管的旧入口。

### 回滚策略

- 关闭 `TEACHER_COURSE_AUTHORING_V1` 时保留课程读取、已发布版本和现有课程生成，不删除任何草稿。
- 可以分别关闭目录结构编辑、课堂教案字段写入、正文作者命令、定向自动重建和动画渲染。
- 已正式应用的新修订不通过文件覆盖回滚；使用领域恢复命令创建新的当前修订。
- 若新 schema 读取失败，旧课程继续走兼容投影，新课程停止新写入并显示明确维护状态。
