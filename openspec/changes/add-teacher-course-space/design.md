## Context

当前 `materials` 仅以全局哈希资产保存，并可绑定到课程生成请求。前端的 `MaterialInputPanel` 只从 `<input type=file multiple>` 取得扁平文件列表；没有工作包、目录路径、教师归属、文件树或下载接口。项目已使用 `X-User-Id` 作为学习记录等私有资源的用户边界，因此教师空间沿用该请求身份边界，而不引入新的登录系统。

## Goals / Non-Goals

**Goals:**

- 提供教师 -> 课程 -> 学年/学期工作包的持久化、隔离与可查询模型。
- 以浏览器提交的文件清单和 `relative_path` 导入一个本地目录；服务端绝不接受或解析客户端绝对路径。
- 保留原文件、内容哈希、相对路径、分类建议、最终分类、导入批次和时间，支持单文件下载和整个工作包 ZIP 下载。
- 将已有材料管线作为底层文件验证和解析复用点；课程空间资料不会被删除或覆盖已有课程生成材料。

**Non-Goals:**

- 不做多人协作、学校 SSO、共享盘同步、病毒扫描服务或 Office 在线编辑。
- 不做 B 的教学大纲/教案/日历生成、学校模板回填或 AI 内容生成。
- 不导入浏览器无法读取的本地路径，不从压缩包内自动解压，不持久化教师电脑路径。

## Decisions

1. **独立 `TeacherCourseSpaceRepository`，而非把工作包塞进现有课程 JSON。**
   工作包与学习课程的生命周期不同，且 A 首发需要先管理资料而不是先生成学习课程。仓库使用独立原子 JSON 元数据和文件目录，保留未来将工作包显式关联至现有课程的余地。

2. **文件上传走工作包专用接口，复用材料的扩展名和大小校验。**
   `webkitRelativePath` 在浏览器端被规范化为相对路径，服务端再拒绝空路径、`..`、绝对路径和路径分隔符绕过。这样既能保留目录结构，也不把不可信路径用于磁盘寻址。

3. **整批资料采用“确定性底线 + 一次 AI 语义理解 + 教师确认”。**
   系统先解析可读取的正文，并用路径、文件名、扩展名和高置信正文结构形成安全底线；随后把整批资料和当前课程结构交给同一次模型判断，补充文档用途、课程/章节位置、版本角色和文件关系。每个结果都保存依据、置信度和分析来源。AI 不得推翻明确的文件格式、强正文结构或教师已确认结论；提供方失败时保留规则结果并明确标记降级，不能伪装成 AI 成功。老师可以在确认页直接改正文档用途，人工决定始终优先。

4. **导出保持原件。**
   单文件用受控下载流；整包使用临时流式 ZIP 响应。ZIP 在写入文件前显式写入所有目录条目，因此空文件夹也能被下载和解压保留；文件继续使用真实相对路径，不把 Word/Excel 转为图片或 Markdown。

5. **课程创建完成后进入工作台，并用一次短弹窗选择备课起点。**
   “从零开始”直接关闭弹窗并保留空工作台；“基于已有资料”在弹窗内完成整文件夹、多文件或拖拽导入，随后原位展示识别出的资料结构。老师确认或修正后进入同一个工作台。文件系统继续作为课程基础设施存在，不再承担新课程的首个主任务页面。

6. **工作包可以空白创建，也可按学校材料模板创建真实目录。**
   模板只创建截图中本身为文件夹的六项，并连续编号为 0–5；不生成 `.docx`、`.xlsx`、`.pdf` 占位项，也不伪造无法打开的零字节文件。旧模板中的 12、13、14 目录在读取时安全迁移为 3、4、5，并同步更新真实目录和资产相对路径。教师可在对应目录中上传真实材料，或继续新增任意层级目录。

7. **采用“飞书知识库式目录交互 + 启智现有视觉语言”。**
   左栏承担课程选择和可展开目录树；右侧只显示当前打开目录的文件夹、文件和待补充文件位，并用面包屑返回上级。新建和导入总是写入当前目录；后端同时把文件物化到 `content/<relative_path>`，使这一层级不是前端投影或数据库假树。

8. **新增界面优先复用项目原有组件和视觉规范。**
   教师文件空间继续使用项目既有的 Vue、Pinia、Element Plus、图标、按钮、表单、弹窗和设计 token；只有现有组件无法表达目录树、文件行或媒介预览行为时才增加局部组件或样式。新实现不得另造一套按钮尺寸、边框、圆角、字体层级或交互反馈。

9. **文件预览按媒介特征自适应，而非使用统一固定框。**
   图片以原始像素尺寸为首选，超出视口后才等比例缩小且不拉伸；PDF 使用接近视口的阅读区域并保留浏览器原生缩放、分页和下载能力；窄屏统一受视口上限约束。下载动作的图标与文字必须作为同一行内控件对齐。

10. **整文件夹导入同时保存文件和目录结构。**
    目录选择使用每个文件的 `webkitRelativePath`；桌面拖拽使用 `DataTransferItem.webkitGetAsEntry()` 递归读取所有批次，不能把目录拖拽退化为扁平的 `dataTransfer.files`。前端除文件相对路径外还提交目录路径，后端规范化后物化目录并写入 entries，使嵌套层级在文件删除后仍可保留；纯空目录通过拖拽目录和后端目录契约支持。

11. **文件与文件夹删除必须二次确认并真实删除存储。**
    文件删除同步移除 manifest 资产、不可变源副本和 `content` 中的可见副本；文件夹删除按规范化相对路径级联移除其子目录、资产记录和源副本，不能只删除前端树节点。前端使用项目现有 Element Plus 确认框，文件夹确认信息必须显示将连带删除的文件数，取消时不发送删除请求。

12. **资料准备状态属于工作包，而不是一次性的前端提示。**
    新工作包从 `pending` 开始，首次导入后进入 `review`，老师确认后为 `completed`，主动跳过则为 `skipped`。旧工作包缺少该字段时按 `completed` 处理，避免升级后打断正在使用的课程。

13. **正式文件只关联老师上传的原始文件。**
    关系记录以工作包中的 `source_asset_id` 为唯一来源，因此大纲、教案、讲稿、PPT 等正式文件不能互相作为文件来源。右侧栏只呈现正式文件的“母文件”和“参考原始文件”，以及原始文件被哪些正式文件使用；课程生成链路中的上游依赖不伪装成文件关系。

14. **默认来源由导入识别结果派生，人工决定优先。**
    工作台第一次打开某个正式目标时，按文档类型、讲次编号和标题匹配一个主来源及少量相关参考原件，并写入与手动选择相同的关系真源。系统同时记录该目标已经完成来源配置；老师之后即使清空全部来源，也不会在刷新后被自动匹配重新覆盖。讲稿优先匹配同讲原讲稿，其次匹配同讲原教案；PPT 优先匹配同讲原 PPT，其次匹配原讲稿或原教案。

## Risks / Trade-offs

- [浏览器目录 API 存在差异] → 保留“选择文件”降级入口并提示相对路径是否保留。
- [大型课程资料占用空间] → 工作包首次沿用 50 MB 单文件限制；服务端返回逐文件失败，成功文件仍保留；后续配额是独立政策。
- [同名文件/重复导入] → 同工作包内以相对路径 + SHA-256 去重；同路径内容变化创建新资产记录并保留导入历史。
- [身份头可伪造] → 本次保持项目既有开发身份模型；所有读取/写入以请求身份过滤，生产 SSO 是上线前阻断项。

## Migration Plan

新仓库不迁移或改写现有 `materials` 数据。部署时创建空的课程空间目录；回滚时移除路由入口即可，已有工作包文件保持在独立目录，避免影响已有课程和材料资产。

## Open Questions

- 真实学校部署的教师账号、容量和留存策略由 SSO/存储治理任务确定；本变更不假定永久无限空间。
