## ADDED Requirements

### Requirement: 课程生产页面必须使用现有真实状态
系统 MUST 在 `/course/:courseId/production` 使用现有课程、生成任务、目录、教案、课程正文、发布门和 PPT 工作台状态，不得建立平行 Store、模拟计时器或静态成功状态。

#### Scenario: 打开生成中的课程
- **WHEN** 教师从课程库打开一个正在生成的课程
- **THEN** 页面加载该课程的 generation preview 和活动任务
- **AND** 顶部状态、当前阶段、进度、失败和下一动作与后端任务一致

#### Scenario: 刷新真实生产页
- **WHEN** 教师在任一生成阶段刷新浏览器
- **THEN** 页面重新加载课程和任务状态并恢复到可操作阶段
- **AND** 不依赖刷新前的本地模拟数据才能显示内容

### Requirement: 课程生成阶段必须可独立停靠和恢复
系统 MUST 将课程要求、教学大纲、分讲教案、课程内容、PPT 和发布呈现为独立阶段。完成一个阶段 MUST NOT 自动启动下一阶段或自动发布。

#### Scenario: 只确认教学大纲
- **WHEN** 教师确认教学大纲后离开页面
- **THEN** 系统保留确认后的大纲和后续可用动作
- **AND** 不自动生成全部教案或 PPT

#### Scenario: 只完成部分教案
- **WHEN** 教师完成若干教学单元的教案后暂停任务
- **THEN** 已完成教案保持可编辑和可确认
- **AND** 教师可以稍后只继续未完成或失败部分

### Requirement: 上下游阶段必须显示真实阻断和来源变化
系统 MUST 根据现有确认门、课程 projection 和来源修订决定阶段是否可用。阻断、过期或失败 MUST 显示具体原因和恢复入口，不得只显示通用失败 toast。

#### Scenario: 大纲未确认时打开教案
- **WHEN** 教师在教学大纲尚未确认时选择分讲教案
- **THEN** 页面显示上游未确认的阻断原因
- **AND** 提供返回并确认大纲的动作

#### Scenario: 生成任务局部失败
- **WHEN** 任务报告一个或多个教学单元失败
- **THEN** 页面显示失败单元、错误消息和是否可重试
- **AND** 已完成单元保持可用且不会被清空

### Requirement: PPT 必须继续复用既有工作台和接口
系统 MUST 使用现有 `ppt-workspace` 路由、canonical source 门和 PPT 构建/导出接口，不得在教师课程生产页复制 PPT 状态机。

#### Scenario: 从确认教案进入 PPT
- **WHEN** 当前课程满足现有 PPT 工作台输入条件且教师选择继续制作 PPT
- **THEN** 系统进入该课程的现有 PPT 工作台
- **AND** 返回时恢复原课程、教学单元和 PPT 上下文

#### Scenario: 课程仍为生成预览
- **WHEN** 当前课程尚未满足 canonical source 要求
- **THEN** PPT 入口明确说明阻断原因并保持不可执行
- **AND** 不以空壳页面或假生成替代现有门

### Requirement: 真实生产页必须符合既有 UI 与可访问性基线
系统 MUST 复用原项目组件、设计 token、按钮、字体、间距和反馈；页面 MUST 使用左侧分类、顶部单行状态和正文优先的布局，并在中英文及支持视口内保持关键操作可达。

#### Scenario: 桌面首屏
- **WHEN** 教师以 1440×900 视口进入课程生产页
- **THEN** 首屏在顶部状态后立即出现当前阶段正文
- **AND** 不先铺设解释卡、抽象指标或重复说明

#### Scenario: 窄屏使用
- **WHEN** 视口缩小到 680 像素
- **THEN** 阶段和讲次导航以可操作的折叠或重排形式保留
- **AND** 主要按钮、错误和保存状态不被隐藏或遮挡
