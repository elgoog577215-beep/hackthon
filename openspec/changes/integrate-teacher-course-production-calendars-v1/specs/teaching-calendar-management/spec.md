## ADDED Requirements

### Requirement: 单课程教学日历必须真实持久化且与课程隔离
系统 MUST 为每个教师身份与课程保存独立 `TeachingCalendarV1`，包含稳定修订号和 `ClassSessionV1` 列表。刷新或重启服务后，已保存日历 MUST 可重新读取。

#### Scenario: 创建并刷新教学日历
- **WHEN** 教师为课程创建教学日历、添加场次并保存
- **THEN** 系统原子持久化新修订并返回完整日历
- **AND** 刷新页面后日期、地点、教师和班组保持不变

#### Scenario: 其他身份读取日历
- **WHEN** 另一个 `X-User-Id` 请求该课程的教学日历
- **THEN** 系统不会返回原教师保存的日历
- **AND** 可为该身份创建独立日历而不互相覆盖

### Requirement: 教学单元与授课场次必须分层
系统 MUST 允许一个 `LessonUnit` 关联零个、一个或多个 `ClassSession`。场次 MUST 保存实际日期、时间、地点、教师、类型、班组和学时，而不复制课程正文。

#### Scenario: 同一实验拆分班组
- **WHEN** 教师为同一教学单元创建 A、B、C 三个实验班场次
- **THEN** 三个场次拥有不同稳定 ID 和班组字段
- **AND** 都引用同一个 `lesson_unit_id`

#### Scenario: 未关联大纲的临时课次
- **WHEN** 教师手工增加一次答疑或补课且暂不关联大纲
- **THEN** 系统允许 `lesson_unit_id` 为空并保存该场次
- **AND** 后续可以再建立关联而不更换 `session_id`

### Requirement: 教师必须能够编辑、增加和减少课次
系统 MUST 支持新增、修改、取消和删除草稿场次，并校验日期、时间顺序、必填内容和学时。危险删除 MUST 二次确认。

#### Scenario: 增加和减少课次
- **WHEN** 教师新增一条课次并删除另一条未确认场次
- **THEN** 保存后的日历反映新的场次数量和顺序
- **AND** 删除操作在前端经过二次确认

#### Scenario: 时间字段无效
- **WHEN** 结束时间早于或等于开始时间，或日期格式无效
- **THEN** 系统拒绝保存并返回可定位字段的失败原因
- **AND** 当前草稿不丢失

### Requirement: 大纲派生必须生成候选而不是覆盖日历
系统 MUST 能从当前课程大纲派生按教学单元排序的日历候选。已有日历存在时，派生 MUST 返回差异和新增候选，不得覆盖手工日期、地点、教师或班组。

#### Scenario: 空日历从大纲派生
- **WHEN** 课程存在可用大纲且当前日历没有场次
- **THEN** 系统为每个可授课教学单元生成一个未排期候选场次
- **AND** 保留 `lesson_unit_id`、顺序和来源修订

#### Scenario: 大纲更新后重新派生
- **WHEN** 教师已经排课后大纲新增教学单元
- **THEN** 系统只提示新教学单元的候选和来源变化
- **AND** 不修改既有场次的日期、地点和教师

### Requirement: 日历更新必须检测修订冲突
系统 MUST 要求更新携带 `base_revision`。当服务端已有更新时，系统 MUST 返回 409 和当前修订，不得最后写入静默覆盖。

#### Scenario: 两个页面同时保存
- **WHEN** 较旧页面基于过期修订提交保存
- **THEN** 系统拒绝该更新并返回当前 revision
- **AND** 前端保留本地草稿并提供重新加载或比较入口

### Requirement: 教师教学总日历必须只读聚合当前身份的场次
系统 MUST 按日期范围聚合当前身份拥有的全部课程日历，并提供月、周和列表展示所需的课程、场次、地点、状态和稳定颜色键。总日历 MUST NOT 持久化第二份场次。

#### Scenario: 聚合多门课程
- **WHEN** 教师拥有三门课程且各课程日历存在本月场次
- **THEN** 总日历在一个查询中返回三门课程的相关场次
- **AND** 每条记录携带课程 ID 和场次 ID 以便跳转

#### Scenario: 点击总日历事件
- **WHEN** 教师点击某一课程场次
- **THEN** 系统进入对应课程教学日历并定位该场次
- **AND** 修改仍在单课程日历完成

### Requirement: 日历接口必须返回明确失败原因
系统 MUST 对缺少稳定身份、课程不存在、字段校验失败、修订冲突和持久化失败返回可区分的状态码、错误 code 和用户可理解 message。

#### Scenario: 缺少身份
- **WHEN** 写入请求没有稳定 `X-User-Id`
- **THEN** 系统拒绝写入并返回身份缺失错误

#### Scenario: 课程不存在
- **WHEN** 请求引用不存在的课程 ID
- **THEN** 系统返回 404 和课程不存在原因
- **AND** 不创建孤立日历文件
