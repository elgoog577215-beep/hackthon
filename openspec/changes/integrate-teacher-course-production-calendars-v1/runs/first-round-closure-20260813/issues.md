# 第一轮闭环对抗性对齐与问题清单

日期：2026-08-13
范围：课程生产、单课教学日历、教师教学总日历
判断口径：必须使用真实接口、可刷新恢复、成功和失败均有可观察证据；页面存在不等于流程跑通。

## 1. 第一轮已经闭合的链路

### 1.1 课程生产

- 课程生产总览使用真实课程节点，不再用本地模拟讲次数组。
- 快速预览使用项目统一 `MarkdownRenderer`，Markdown 与 KaTeX 公式不再以原始源码显示。
- 预览顶部和底部均保留“下一步：PPT”，长内容在预览内部滚动，不会把主操作推到视口之外。
- 教案阶段保留当前讲次，真实进入 `GenerationLessonPlan`；AI 助手在窄屏作为浮层打开，不再压缩正文。
- AI 优化实测真实创建教案草稿并调用 AI candidate 接口，返回逐字段 diff；教师可以接受或拒绝，候选不会直接发布。
- 教案 → PPT 保持 `courseId + nodeId`；进入现有 PPT 工作台后真实流式构建 11 页课件，质量检查通过；返回恢复原课程、PPT 阶段和讲次。
- 返回后重新读取同源课件 registry；已生成、来源更新、生成中、失败、可制作不再全部显示为“可制作”。

### 1.2 单课教学日历

- 手工新增、编辑、删除、保存使用真实持久化 API 和 revision 冲突保护。
- 从大纲生成只补充缺失候选，不覆盖教师已经填写的日期、地点、教师等排课字段；无新增时明确提示。
- 表格/月历可切换；真实修改地点后保存、刷新仍存在，并能被教学总日历读取；验证后已恢复测试数据。
- 第一轮提供真实 CSV 交换：UTF-8 BOM、Excel 可打开、覆盖 13 个日历字段；导入先解析、校验、去重和确认，再进入未保存草稿。
- CSV 行级错误会指出行号与字段原因；同一时间的 `13:30` 与 `13:30:00` 会按同一场次去重。

### 1.3 教师教学总日历

- 真实聚合当前教师三门课程、五条场次；月/周/列表三种视图均读取同一 ClassSession 数据。
- 总日历保持只读；点击场次返回单课教学日历，并带 session 参数聚焦原场次。
- 单课修改后总日历立即反映，不创建第二份日历数据。

## 2. 对照完整产品方案后仍未完成的部分

以下不是第一轮“伪装已完成”的内容，继续留作第二轮或单独 change。

### P0 — 课程生产资产模型仍不够细

1. 当前正式教案工作台仍偏“全课 teaching plan + section 编辑”，尚未形成每一讲独立的 `工作稿 / 教师确认版 / 学生发布版` 三指针。
2. PPT 工作台目前是课程级 representation；生产页可以携带讲次上下文，但后端尚未把“每讲多份 PPT + 每份多版本”建成完整资产集合。
3. 大纲变更后的下游影响范围还没有按讲次精确显示为“来源已更新”；当前只能识别课件 registry 的 ready/stale 等总体状态。
4. 总览尚缺批量选择讲次、逐讲独立任务、逐讲失败/重试和 last-good 并列展示。
5. 长任务已经有真实 PPT 进度页，但还没有统一成讨论方案中的右下角教师任务浮窗与全局任务中心。

### P0 — 正式教学日历导入导出尚未完成

1. CSV 是第一轮真实数据交换，不等于学校正式交付。
2. 尚未实现导入 Word/PDF/Excel 后保留原文件、识别证据、字段置信度、差异候选与 unresolved rows。
3. 尚未实现浙江大学模板的可编辑 DOCX 与固定阅读 PDF；必须复刻课程元数据、10 列、A/B/C 小组、跨页和末页备注区，同时去掉浏览器打印噪声。
4. 尚未实现学校校历导入、节假日/调休识别，以及“原日期—建议日期—原因—影响范围”的可选择冲突方案。
5. 日历长文本仍以表格内编辑为主，完整方案要求教学内容、教学要求、备注和大纲关联进入侧边编辑器。
6. 大纲删除/改名后的“来源已移除/来源已更新”候选及选择性同步尚未实现。

### P1 — 教学总日历与入口

1. 总日历已能聚合与回跳，但还要补密集同日课程的堆叠/查看更多、异常/加载/空态完整回归。
2. 教师身份、课程所有权目前沿用既有 `X-User-Id` 机制，尚未建立正式 teacher identity / 授权模型。
3. 总日历暂不直接编辑，这符合 V1 决策；后续若要跨课程改课，必须回到单课日历，不能在总日历复制数据。

### P1 — 文件系统与发布

1. 大纲、日历、教案、PPT 尚未全部统一为带稳定 CourseAsset ID 的同一资产真源。
2. 文件空间自动归档、文件夹导入识别、移动重命名不丢教学关联、空文件夹和回收站属于后续 CourseAsset bridge。
3. 学生发布快照与教师当前确认版的逐讲对照，还没有在课程生产总览完整呈现。

## 3. 本轮发现但已经解决的问题

- 所谓“乱码”不是字符编码损坏，而是原始 Markdown/LaTeX 被字符串截断后直接输出；已改为统一渲染器和结构化预览。
- 教案页面确实有 AI 能力，但原布局在窄屏下隐藏/挤压；已改为显式入口与响应式浮层。
- 课程生产总览虽然按讲次预览不同正文，但进入教案后组件默认停留在“全课教学设计”，导致切换讲次时右侧看起来始终相同；现已让教师生产入口按 `nodeId` 默认打开“本讲教案”，左栏切换同步更新 URL，并将“全课设计”保留为明确的独立视图。
- PPT 工作台能真实生成，但返回生产页后局部状态仍显示“可制作”；已改为读取同源课件 registry。
- 日历过去只看见空壳；现已用真实多课程数据验证保存、刷新、聚合、回跳、CSV 导入导出与重复识别。

## 4. 需要下一轮共同收敛的产品问题

1. “分讲教案”第一版是否必须立刻拆成后端独立资产，还是先以现有全课 teaching plan 的 section 作为兼容层，再迁移到独立 CourseAsset？建议先做兼容层与稳定 ID 映射，避免重写现有接口。
2. 每讲多 PPT 的第一版最小模型：`一份主课件 + 历史版本`，还是一开始支持 `主课件/习题课件/实验课件` 多资产？建议先支持一主一辅，数据模型允许扩展。
3. 学校正式日历导入的首批格式优先级：建议 `Excel + PDF`，Word 后置；导出仍以 `可编辑 DOCX + 阅读 PDF` 为正式交付。
4. 校历冲突方案是否进入日历侧栏逐条确认，还是使用批量审阅页？建议小于 10 条侧栏确认，更多时进入批量审阅。

## 5. 第二轮建议硬门

1. 新建课程 → 大纲候选 → 教师确认 → 至少两讲独立教案状态 → 只为其中一讲生成 PPT → 刷新恢复。
2. 大纲修改一讲 → 只标记对应教案/PPT stale → last-good 仍可预览 → 教师选择是否重建。
3. 导入一份真实教学日历 Excel/PDF → 展示识别证据和差异 → 选择接受 → 保存 → 导出浙江大学 DOCX/PDF 并逐字段对账。
4. 导入学校校历 → 识别节假日/调休 → 生成不自动应用的冲突方案 → 教师选择后总日历同步。
5. 三门课程、同日多场次、A/B/C 小组在总日历正确堆叠，点击任何场次都回到唯一 ClassSession。

## 6. 2026-08-13 真实 AI 十讲补充验证

本节使用网页中的真实 AI 创建流程验证，不使用 Markdown 导入、直接写数据库或伪造本地状态。测试课程为 `人工智能基础十讲（完整流程联调2）`，课程 ID 为 `11706e0e-2384-4e29-8abc-0eccb498eb10`。

### 6.1 已真实跑通

1. DeepSeek Flash 真实生成 10 个一级章节、20 个二级教学单元；教师在网页确认大纲。
2. 教案规划真实按 20/20 单元生成并确认；课程正文也完成 20/20，生产页可逐讲快速预览。
3. 教学日历从仍处于 generation workspace 的大纲生成 10 个候选课次：每个一级章节对应一次课，二级单元合并为该次课的教学要求。
4. 建课时的 `2026-2027 秋冬` 自动回填到教学日历；不再显示“未设学年 / 未设学期”。
5. 通过网页为 10 个课次填写 10 个不同日期（2026-08-17 至 2026-08-28，跳过周末）、13:30–15:00、地点、教师和 2 学时；保存返回修订 1。
6. 教学总日历在 2026 年 8 月精确显示该课程的 10 个事件；浏览器计数为 10。后端访问日志同时记录 derive POST 200、calendar PUT 200 和 total-calendar GET 200。
7. 后端针对预算与日历的定向测试共 21 项通过；前端生成弹窗契约测试 13 项通过。
8. 新建课程页的“预计课次”现已传入原生成弹窗的 `teacher_course_brief.section_count`。浏览器实测填写 10 后，弹窗内部生成约束为 10；没有新建第二套生成接口。

### 6.2 为什么老版本更容易生成、现在一开始反而失败

1. 老版本在提交 `96cff53` 中为一次性蓝图调用显式给出 16000 输出 token；结构较扁平，因此虽然慢，但不容易在最重的结构化 JSON 阶段被截断。
2. 新版本引入了“先生成层级骨架，再按章节分批”的更可靠架构，但骨架默认预算回退到 4096。
3. DeepSeek Flash 会消耗隐藏推理预算。两次真实失败都发生在 32% 大纲阶段：一次报告 `max_tokens=4096, chars=4333`，一次报告 `max_tokens=4096, chars=0`；分批正文尚未开始。
4. 本轮仅把大纲阶段默认上限恢复到 8192，并保留现有分层/分批架构，没有回退老版一次性生成，也没有改变 PPT 接口。

### 6.3 当前仍未通过的硬问题

1. **教师 PPT 被学生发布门错误阻断。** 教案已确认且 20 个正文单元已有内容，但生产页仍要求 `isPublished && currentDocumentRevision` 才开放 PPT。学生题库覆盖检查缺失 16/20 节，使整门课保持 `completed_with_warnings`，进而让教师无法继续 PPT。这违反“教案确认后可按需继续 PPT，学生发布另行确认”的产品决策。下一步应新增/复用教师草稿源适配层，保持现有 PPT 生成接口不变，不能简单移除按钮禁用后拿占位文档生成。
2. **课次、章节、小节仍缺少独立领域字段。** 本轮已把新建页的“预计 10 课次”兼容映射到既有 `section_count=10`，浏览器与组件测试均通过；但尚未重新完整跑一门新课程证明模型最终严格返回 10 个教学单元。已生成的联调课程仍是 10 章、20 小节，日历通过章节聚合为 10 次课。后续仍应持久化 `expected_session_count`，明确“章节 / 教学单元 / 实际课次”三者关系，不能长期把课次等同于小节。
3. **学生题库修复不稳定。** 首轮缺 15 个节点，点击修复后调用 54 个题目槽位仍缺 16 个节点；部分模型调用返回空响应。失败 UI 一度误归因为 provider unavailable，实际上是题目被校验丢弃/覆盖不足，需要展示准确分项原因。
4. **任务轮询触发 429。** 多页面同时观察课程时，`GET /api/tasks?limit=100` 周期性 429；课程与日历仍可保存，但控制台留下错误，生产进度可能短暂陈旧。应合并全局观察器或对 429 做退避和单例轮询。
5. **生成内容中的 Mermaid 仍有语法错误。** 普通 Markdown 已正确渲染，但部分 AI 图示在预览中显示 Mermaid syntax error，需要生成后语法校验或降级为代码块。

结论：真实 AI 的“大纲 → 教案/正文 → 10 次教学日历 → 教学总日历”已经闭合；“教案 → 教师 PPT”仍被旧学生发布门阻断，因此完整课程生产 V1 还不能标记为全部通过。

## 7. 2026-08-14 第一轮最终修复结论

上一节记录的是修复前的直接证据，保留用于说明根因。其硬阻断已在本轮关闭：

1. 统一以一级章节作为 `LessonUnit`，二级内容属于讲内知识节点；验收课程在课程概览、课程生产、讲次导航和教学日历均为 10 讲。
2. 教师确认大纲后通过兼容适配建立教师教案源；PPT 只依赖教师确认源，不再依赖学生发布，也没有伪造发布快照。
3. 教师预览进入只读 `teacher-preview`；真实浏览器网络断言未出现学习记录、进度、练习或 AI 对话写入。
4. 教案 AI 助手通过真实 Flash 模型产生逐字段候选；局部修复不再被与本次修改无关的历史校验问题错误阻断。
5. 单课日历的新增、删除二次确认、候选差异、完整排期口径、保存同步、月/周/表格、长字段侧栏和导出已闭合；总日历可以稳定配色、筛选待完善场次、标冲突并精确返回排期或备课。
6. 浙江大学第一套正式导出已从同一保存修订生成：可编辑 DOCX、固定 PDF、XLSX 和 CSV。最终修订 14 含 10 个课次；PDF 为可搜索文本且渲染无裁切。
7. 880px 下教案正文被隐藏 AI 侧栏空列挤压的问题已修复；AI 关闭时正文占满剩余宽度，打开时使用覆盖式侧栏。

最终回归：后端 29 项通过，前端 51 项通过，生产构建通过，9 条真实浏览器流程通过。第一轮课程生产、单课教学日历与教学总日历可判定为闭合；学校校历/Word-PDF-Excel 识别、多 PPT 资产版本链和 CourseAsset 文件空间桥接仍属于后续独立 change，不再与本轮完成状态混淆。
