# 变更：升级有依据、可恢复的课程生产 V2

## Why

灵知已经具备需求、目录、全课教案、课程知识、正文、练习、质量检查和发布主链，也已经有材料解析、联网检索和检查点恢复能力。但真实完整课程运行暴露出五个仍会直接损害教师信任的问题：

1. 提供方、额度或兜底凭据只有在长任务执行中才暴露，已完成 7/8 个小节时仍可能以整阶段失败收场。
2. 上传资料虽然能解析为文本证据，但多文件仍偏串行，扫描 PDF、表格、公式、版面与阅读顺序的质量缺少可见合同；联网入口存在但不能保证部署可用，也没有按知识缺口二次检索。
3. `CourseKnowledgeBase` 主要在全课教案完成后编译，知识身份、前置关系、易错和掌握标准容易受分节生成影响，关系方向和覆盖完整度缺少全局门禁。
4. 教案默认展示结构化生成字段，课程生成现场同时暴露阶段、百分比、树、批次和技术状态。教师看不到一份接近正式交付物的教案，也难以迅速判断“已经完成什么、现在需要什么、失败后会保留什么”。
5. 学科教学画像、学科变体和小节课型已经存在，但还没有被编译成一个跨知识库、教案、正文和练习传递的版本化学科生成模板，下游仍可能各自猜测学科讲法。

本变更把“快”定义为更早获得可用产物，把“稳”定义为失败只影响最小单元，把“好”定义为来源、知识、教学设计和正文都能通过可解释质量门，而不是单纯缩短一次模型调用。

## What Changes

- 在创建生成任务前增加提供方、模型、凭据、额度/限流和联网能力预检；不可用时不创建一个注定失败的长任务。
- 将课程填写页收束为主题/目标、教学对象、课时、资料来源四组必要信息；难度、学科讲法、题目策略、章节数量和额外要求统一进入可选高级设置。
- 将上传资料和联网研究合并为同一个“课程依据”区域，提供解析状态、质量、缺失能力和隐私边界反馈。
- 把现有学科教学画像、学科变体、课型原型和模块注册表编译为唯一的 `SubjectGenerationTemplateV3`；模板不仅列出模块，还必须分别定义课程推进、原子知识、关系、教案、正文和评估的可执行标准，并让计算机核心基础、物理工程设计和历史等细分类型保存自己的推进、知识、证据、护栏与最终成果。模板 ID 与版本进入任务、检查点及所有下游产物，老师无需选择技术模板。
- 在每次任务开始时，把课程类型、类型化意图、学习者起点、`SubjectGenerationTemplateV3`、难度和资料边界编译为唯一的 `CourseDesignContractV2`；目录、小节目录、知识、教案、正文和评估只消费各自阶段投影并保存同一修订 ID。每个阶段显式声明只读输入、唯一允许输出、禁止修改和完成证据；这份质量内核在 compact/minimal Prompt 中不可压缩。
- 多文件解析使用有界并行；扫描页按页 OCR 降级，保留表格、公式、图片、讲者备注、工作表和来源定位，并输出版本化解析质量报告。
- 联网研究使用两段式检索：资料处理期做主题级广泛检索；知识候选形成后按低置信知识点和覆盖缺口做定向补证。所有来源进入同一不可变证据包。
- 把课程局部知识图谱前移为教案与正文的正式上游：分节候选并行生成，全课串行去重、稳定 ID、所有权和前置 DAG 对齐，详情与六类关系再并行补全；冻结之后还必须通过“教学就绪”门，不能把只有 prerequisite 的目录顺序图、缺少掌握标准或易错覆盖的知识库继续传给教案。知识提示词只负责知识，教案提示词只消费冻结知识并负责教学设计，禁止一个输出同时创建 `knowledge_details` 与 `teaching_modules`。
- 从结构化教案确定性编译一份教师默认看到的正式教案文档，包含教学对象、目标、重难点、策略、资源、评价、逐课时教学过程、作业、量规和来源；结构化编辑视图保留为次级能力。
- 教师提交需求后只展示“目录确认 → 自动生成课程 → 确认发布”三步产品电路；只有目录和发布是人工确认门。知识、教案、正文、练习和质量检查归入中间自动生产，主区域只回答当前产物、已保存数量、预计下一步和是否需要确认；生产分组、批次、模型、重试和原始阶段进入“生成详情”。
- 每个分节、批次和解析单元完成后立即保存并投影；7/8 已完成必须显示 7/8，失败恢复只重做失败单元，不得退回 0/8。
- 建立内容质量门：来源覆盖、知识完整、关系方向、目标可观察、课堂可执行、跨节一致、模板泄漏、事实风险和教师修改负担分别报告，不用一个总分掩盖必要子门。
- 使用固定的 4 章 8 节和 12 节跨学科基准记录端到端 P50/P95、首个可用产物、成功率、重复生成率和教师量表。

## Capabilities

### New Capabilities

- `grounded-course-production`：定义课程生成预检、证据准备、课程局部知识图谱、正式教案文档、可恢复编排、教师可见三阶段投影和质量/性能门。

### Modified Capabilities

- `material-evidence-pipeline`：补充高保真解析质量、并行处理和两段式联网补证合同。
- `subject-knowledge-infrastructure`：补充单门课程局部知识图谱的稳定身份、丰富节点/关系和全局质量门。
- `teaching-representation-model`：补充从结构化教案确定性编译正式教师教案文档的合同。

## Impact

- 后端：`course_service.py`、`course_generation_workflow.py`、`task_manager.py`、`generation_workspace.py`、`material_pipeline.py`、`web_retrieval.py`、`course_knowledge_base.py`、`course_knowledge_map.py`、教案投影和质量模块。
- 前端：`CourseGenerationDialog.vue`、`MaterialInputPanel.vue`、`CourseProductionStage.vue`、`GenerationLessonPlan.vue`、知识库图谱与生成 Store；新增文案同步维护中文和英文。
- 数据：扩展生成工作区中的证据、知识图谱候选、单元状态和正式教案投影；不建立第二课程正文、第二教案或第二任务真源。
- 验证：OpenSpec 全量校验、后端领域/恢复/材料/知识测试、前端组件/Store/构建、中英文与多视口真实页面、真实提供方完整课程基准。

## 发布门

- 任务创建前能识别不可用提供方、无效兜底和未配置联网能力。
- 任一局部失败都保留已完成解析、知识、教案和正文单元，并准确投影完成数。
- 正式教案默认视图可直接阅读、打印或导出，且所有内容都来自当前结构化教案与来源绑定。
- 课程知识图谱无孤立必讲节点、无无效端点、无前置环、无明显反向关系；易错、掌握标准和来源覆盖达到版本化阈值。
- 12 节标准课程真实运行成功率不低于 98%；首个目录 P50 不超过 30 秒，首份正式教案 P50 不超过 60 秒，首节正文 P50 不超过 90 秒，完整课程 P50 不超过 3 分钟、P95 不超过 6 分钟。
- 中文、英文、390/789/1024/1440 视口没有原始 key、中文残留、文字遮挡、不可达主操作或仅靠颜色表达的状态。
