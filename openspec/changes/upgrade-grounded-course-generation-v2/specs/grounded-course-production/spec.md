## ADDED Requirements

### Requirement: 学科生成模板必须作为全链路的唯一学科合同

系统 MUST 在目录规划前从版本化学科注册表解析 `SubjectGenerationTemplateV2`。该模板 MUST 分别提供课程架构、知识节点/关系、教案模块/课型、正文表达和评估形式的可执行合同；课程类型、学段、难度和资料 MUST 作为同一模板的修饰合同，不得产生平行学科真源。

#### Scenario: 微积分课程进入不同生成阶段
- **WHEN** 系统已将课程解析为数学形式学科的微积分变体
- **THEN** 知识库、教案、正文和练习 MUST 保存并消费同一 `template_id` 与 `template_version`
- **AND** 知识库 MUST 覆盖定义条件、推导/前置关系、反例和错因
- **AND** 教案与正文 MUST 落实直觉、形式化、例题、变式与错误分析等数学模块
- **AND** 目录、知识、教案、正文和练习 MUST 分别能指出它消费的模板合同字段

### Requirement: 单次任务必须先冻结统一课程设计合同再按阶段投影

系统 MUST 在目录模型调用前把课程类型、类型化意图、学习者起点、`SubjectGenerationTemplateV2`、难度和资料边界编译为版本化 `CourseDesignContractV1`。目录、小节目录、知识身份、知识补全、教案、正文和评估 MUST 只消费各自阶段投影并保存同一合同修订；compact/minimal Prompt MUST NOT 通过删除课程类型、学科语法、最终成果或证据边界来换取速度。

#### Scenario: 项目制微积分课程分章并行展开目录
- **WHEN** 章节骨架已经冻结并分批展开小节
- **THEN** 每个小节目录批次 MUST 继续消费项目交付物、里程碑规则和数学形式学科推进合同
- **AND** 不同批次 MUST 保存同一 `course_design_contract_revision_id`
- **AND** 小节目录 MUST NOT 退化为与系统学习相同的通用教材章节

### Requirement: 课程生产必须在长任务创建前完成能力预检

系统 MUST 在创建 `GenerationJob` 前校验主/备提供方、模型、凭据、共享容量、联网能力和资料可读性。预检阻断时 MUST NOT 创建注定失败的长任务；可选能力降级时 MUST 向教师说明范围并要求明确接受。

#### Scenario: 主模型额度不足且兜底凭据无效
- **WHEN** 教师提交一门完整课程生成请求
- **THEN** 系统 MUST 在长任务创建前返回结构化阻断原因
- **AND** MUST NOT 先生成部分目录后才暴露无可用提供方

### Requirement: 课程局部知识图谱必须先于教案和正文冻结

系统 MUST 先从已确认目录和准入证据形成分节知识候选，再执行全课去重、稳定课程内 ID、所有权和前置 DAG 对齐。正式教案、正文和练习 MUST 只引用通过质量门的冻结图谱；模型 MUST NOT 自造正式课程知识 ID。知识详情、易错、掌握标准、来源和关系必须在知识阶段完成并通过独立质量门；教案生成 MUST 只引用已冻结知识，不得在同一模型输出中同时创建知识详情和教学模块。

#### Scenario: 两个小节生成同义知识点
- **WHEN** 分节候选分别返回名称不同但语义相同的知识点
- **THEN** 全课对齐 MUST 合并为一个稳定课程内 ID
- **AND** MUST 保存首次负责与复用小节
- **AND** 下游 MUST NOT 各自保留漂移身份

#### Scenario: 知识详情尚未通过质量门
- **WHEN** 任一必讲知识缺少可观察能力、可信易错、掌握标准或关系端点无效
- **THEN** 系统 MUST 将知识阶段保持为待修复或失败
- **AND** MUST NOT 启动教案模型批次
- **AND** 已通过的知识批次 MUST 保留并可从检查点复用

### Requirement: 正式教案必须提供教师可直接阅读的确定性文档投影

系统 MUST 从当前 `CourseTeachingPlanV3`、课程知识图谱和来源绑定确定性编译正式教案文档。文档 MUST 包含课程信息、教学对象、目标、重难点、策略、资源、评价、逐课时过程、作业和来源；该文档 MUST NOT 成为第二教案真源。

#### Scenario: 教师打开已完成教案
- **WHEN** 结构化全课教案已经通过质量门
- **THEN** 默认视图 MUST 展示一份完整连续的正式教案
- **AND** 教师 MAY 切换到结构化总体或分课时编辑
- **AND** 文档中的每项内容 MUST 能回到正式结构化字段或来源

### Requirement: 生成工作必须按最小单元持久化并可局部恢复

系统 MUST 为资料解析、知识候选、知识补全、教案批次和正文小节分配稳定 work-unit ID，并在单元校验通过后原子保存。任务失败或服务重启后 MUST 只调度缺失和可重试失败单元。

#### Scenario: 八个教案小节中七个已经完成
- **WHEN** 第八个小节因提供方限流失败
- **THEN** 任务投影 MUST 显示 `7/8` 已完成
- **AND** 教师 MUST 能查看七个已保存候选
- **AND** 恢复 MUST 只重新生成第八个小节和必要的全课一致性门

### Requirement: 教师可见生成过程必须收束为三步产品电路

教师提交需求后，系统 MUST 只展示“目录确认、自动生成课程、确认发布”三步产品电路。只有目录和发布是人工确认门；知识、教案、正文、练习与质量检查属于中间自动生产，不得伪装成必须逐级确认的用户步骤。主界面 MUST 优先说明当前产物、完成数量、下一步、是否等待教师和恢复动作；课程结构、教案与知识、课程内容等生产分组以及模型、批次、重试、token 与原始 phase MUST 进入按需详情。

#### Scenario: 教案阶段正在并行生成
- **WHEN** 教师查看课程生产现场
- **THEN** 主界面 MUST 高亮“自动生成课程”并显示真实完成小节数
- **AND** MUST NOT 同时用多个互相竞争的百分比和技术阶段作为主信息
- **AND** MUST NOT 要求教师先确认教案才能继续生成正文

### Requirement: 课程内容质量必须使用独立必要子门

系统 MUST 分别检查来源覆盖、知识完整、关系方向、目标可观察、课堂可执行、跨节一致、模板泄漏和事实风险。任一必要硬门失败 MUST NOT 被总分或模型自评覆盖；教师建议 MUST 定位到具体字段、知识、关系或课程块。

#### Scenario: 前置关系方向与理由相反
- **WHEN** 关系理由说明 A 是 B 的前置，但边方向保存为 B 指向 A
- **THEN** 关系方向门 MUST 阻止图谱冻结
- **AND** MUST 返回关系 ID、两个端点、理由和建议修复方向

### Requirement: 完整课程必须达到真实提供方性能与稳定性门

系统 MUST 在固定模型池、参数、资料和质量合同上运行独立完整课程基准，并分别记录排队、模型、资料、检索、编译和教师等待耗时。Mock、缓存样板和确定性保底 MUST NOT 计入真实成功率。

#### Scenario: 发布课程生成优化
- **WHEN** 至少二十次 12 节真实运行完成
- **THEN** 端到端成功率 MUST 不低于 98%
- **AND** 首个目录、首份正式教案、首节正文和完整课程 MUST 分别满足版本化 P50/P95 门
- **AND** 已完成单元重复执行率 MUST 为 0%
