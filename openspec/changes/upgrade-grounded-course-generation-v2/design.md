# 设计：证据—知识—教案—正文的可信课程生产链

## 1. 设计原则

1. 教师看到的是产物与决策，不是模型调用拓扑。
2. 课程规模增加工作单元数量，不扩大单次模型调用到不可恢复。
3. 来源先进入不可变证据包；知识图谱冻结后，教案和正文才引用稳定知识身份。
4. 串行只保留必须统一全局语义的门，耗时语义工作尽量有界并行。
5. 临时候选可以逐单元可见，正式发布仍保持原子和来源一致。
6. 任何降级都标记质量和原因，不把确定性保底冒充完整 AI 结果。
7. 学科生成模板是目录、知识、教案、正文和练习的共同上位合同；课程类型、学段、难度和资料只作为修饰层，不建立平行模板真源。
8. 一个模型输出只承担一种专业责任：知识批次不得设计课堂，教案批次不得创造知识，正文批次不得改写冻结知识身份。

## 2. 目标运行链

```text
教师简报 + 资料绑定 + 联网选择
-> GenerationPreflightV1
-> SubjectGenerationTemplateV2 解析与冻结
-> 并行资料解析 + 主题级联网检索
-> EvidencePackageV2 去重、冲突与覆盖门
-> 目录骨架 + 有界章节扩展
-> 教师确认目录
-> 分节知识候选并行
-> 全课知识去重、稳定 ID、所有权与前置 DAG 对齐（串行）
-> 知识详情/六类关系/易错/掌握/来源并行补全
-> CourseKnowledgeGraphDraftV1 + CourseKnowledgeBase 独立质量门与冻结
-> 教案分批并行（只读冻结知识）+ 全课一致性汇编
-> FormalLessonPlanDocumentV1 确定性编译
-> 分节正文/练习有界并行
-> 跨节事实、来源、知识与教学闭环终检
-> 教师确认并幂等发布 CourseDocument
```

## 3. 串行门与并行工作

### 3.1 必须串行

- 任务预检：提供方、模型池、兜底凭据、容量、联网与资料可读性。
- 证据准入：去重、用途/权威、冲突和覆盖缺口。
- 目录确认：教师唯一的中途强确认门。
- 全课知识对齐：同义合并、稳定 ID、首次负责小节、复用归属、关系方向和前置 DAG。
- 最终一致性门：跨节术语、来源、课时、知识覆盖、练习合同和发布回执。

### 3.2 有界并行

- 多文件解析，默认并发 3；单文件内部页 OCR 使用更小并发并受共享 CPU/内存预算控制。
- 主题级联网查询与资料解析同时进行；查询默认并发 2。
- 每个小节的知识候选、知识详情补全、教案详情和正文生成分别使用自适应并发。
- 教案批次默认 2–3 节一组；额度/限流升高时降低并发，健康恢复后缓慢提升。
- 练习和非阻断表达可以在对应正文与知识冻结后异步生成，不阻塞首个可用正文。

## 4. 新增与扩展对象

### 4.0 `SubjectGenerationTemplateV2`

该对象是现有学科教学画像、学科变体、课型原型和教学模块注册表的确定性投影，不是第二套模板真源。V2 不只回答“有什么模块”，还要回答“这一学科如何形成一门课”。至少保存：

- 稳定 `template_id`、`template_version`、主/辅学科模式与细分学科变体；
- `course_architecture_contract`：课程推进主线、章节职责、综合成果和禁止的目录组织方式；
- `knowledge_contract`：原子知识标准、必需字段、正式六类关系、来源规则、学科特有知识重点和反模式；
- `lesson_plan_contract`：课程级/小节级教学模块、课型选择规则、课堂过程标准、师生活动和检查证据；
- `content_contract`：学科讲解语法、例子/反例/变式/证据组织方式、正文质量底线和模板泄漏禁令；
- `assessment_contract`：可观察学习证据、最终成果、题目或任务形态和质量标准。

生成任务必须固定该投影的 ID 和版本。目录、知识库、教案、正文和题库只能消费同一投影；恢复时不得重新路由到另一模板。模板只提供学科规则，课程类型、学段、难度、资料和教师要求必须作为显式修饰合同叠加，不能复制出另一套 Prompt 真源。

### 4.0a `CourseDesignContractV1`

该对象在单次生成任务开始时，由课程类型与类型化意图、学习者起点、`SubjectGenerationTemplateV2`、难度合同和资料边界确定性编译。它不是新的课程或教案真源，而是保证并行模型批次仍在设计同一门课的任务级产品合同。

合同保存唯一修订、来源修订、用户确认门、自动质量门，以及目录、目录细化、知识身份、知识补全、教案、正文和评估七个阶段投影。每个 Prompt 只能接收自己的投影和同一修订 ID，不得重复广播整份模板，也不得读取另一阶段的输出职责。目录细化必须继续消费课程类型与学科推进合同；正文投影必须保留最终成果、学科表达、证据边界和质量底线，即使运行时因预算进入 compact/minimal 上下文也不能退化为通用讲义。

### 4.1 `GenerationPreflightV1`

```json
{
  "schema_version": "generation_preflight_v1",
  "status": "ready|blocked|degraded",
  "provider_pool": [],
  "retrieval": {"requested": true, "available": false, "reason_code": "..."},
  "materials": {"count": 3, "readable": 3, "estimated_work_units": 18},
  "capacity": {"recommended_concurrency": 2, "estimated_calls": 14},
  "issues": []
}
```

`blocked` 时不创建长任务；`degraded` 只允许教师明确接受的非关键能力降级。预检不得记录密钥或完整资料正文。

### 4.2 `ParsedDocumentQualityV2`

除文本长度和区块数量外，至少报告：

- 页/幻灯片/工作表覆盖；
- OCR 覆盖与置信区间；
- 阅读顺序、标题层级、表格结构、公式、图片/图注和讲者备注保留率；
- 乱码、空页、重复页、截断和降级原因；
- 可用于事实依据、只适合作为讲法参考或必须人工复核的结论。

### 4.3 `CourseKnowledgeGraphDraftV1`

节点至少包含：

- 稳定课程内 ID、规范名、别名、陈述、类型、条件和边界；
- 正例、反例、难度、可观察能力；
- 易错表现、辨别证据、纠偏策略；
- 掌握标准、来源引用、首次负责小节、复用小节、置信度和版本。

关系只能使用正式六类：

- `prerequisite`、`derives`、`equivalent_to`、`contrasts_with`、`applies_to`、`generalizes`；
- source、target、理由、成立条件、来源、置信度和方向校验结果。

课程树只是按教学顺序投影；关系图、易错图和能力图都读取同一图谱，不拥有第二份节点。

### 4.4 `FormalLessonPlanDocumentV1`

该对象是 `CourseTeachingPlanV3` 的确定性只读投影，不是 Markdown 真源。默认结构：

1. 课程基本信息与学情；
2. 可观察教学目标；
3. 教学重点与难点；
4. 教学策略、准备、资源与评价；
5. 每课时教学过程表：时间、教师活动、学生活动、知识/能力、检查证据；
6. 作业、输出与量规；
7. AI/隐私/伦理边界（适用时）；
8. 已核验来源与待复核项。

结构化编辑仍作用于正式教案字段；文档视图只负责可读、打印和导出。

### 4.5 `GenerationExperienceProjectionV1`

教师主界面只显示三步：

```text
课程结构 -> 教案与知识 -> 课程内容
```

投影独立返回：当前步骤、已完成/总单元、最近保存产物、当前主动作、是否等待教师、是否可继续、失败单元和预计范围。底层 phase、batch、provider route、token、retry 和 heartbeat 进入可展开详情，不成为主流程标签。

## 5. 联网检索策略

### 5.1 第一段：主题级广泛检索

在资料解析期间根据课程主题、对象、目标和资料缺口生成 3–6 条查询，优先官方、标准、原始论文和权威机构。结果进入来源候选，不直接改目录。

### 5.2 第二段：知识缺口定向补证

知识候选对齐后，为以下对象生成查询：

- 缺少来源的必讲知识；
- 低置信、时间敏感或存在资料冲突的陈述；
- 缺少反例、边界、易错辨别或掌握证据的知识；
- 教师要求的最新政策、标准、案例或数据。

两段结果统一去重、归一 URL、执行注入过滤和来源分层。用户权威资料优先于一般网页；网页事实必须保存引用与抓取时间。

## 6. 恢复与部分结果

- 每个解析页组、知识候选批次、知识详情批次、教案批次和正文小节都拥有稳定 work-unit ID。
- 单元写入先进入隔离工作区，校验通过后原子标记 `completed`。
- 任务投影从单元仓库确定性统计完成数，不从最终汇编产物反推。
- 中断后重新读取已完成单元，只调度 `pending|retryable_failed`；已完成单元重复执行率必须为 0%。
- 7/8 教案完成时，正式计划仍未冻结，但教师可以查看 7 个只读候选和缺失单元；恢复只重做第 8 个单元并重新运行全课一致性门。

## 7. 质量门

### 7.1 硬门

- schema、修订、稳定 ID、来源引用和显式规模/课时合同；
- 必讲知识覆盖、关系端点、前置无环和语义方向；
- 必需教案字段、逐课时分钟、教师/学生活动和检查证据；
- 正文事实可追溯、知识/目标绑定、正式练习公开/私有合同；
- 模板泄漏、空泛占位、坏公式、坏代码围栏和跨章节引用错误。
- 知识冻结必须独立于教案验收：全部知识详情、能力、可信易错、掌握标准和关系先通过门禁并形成冻结修订，教案批次才允许启动。

### 7.2 教师建议

- 目标是否可观察；例子/反例是否足够；活动是否可实施；
- 解释密度、重复、节奏、跨节衔接和修改负担；
- 易错是否有辨别证据和修复方法，掌握标准是否能由任务观察。

建议不单独阻止发布，但必须定位到字段、知识、关系或课程块，并提供修复入口。

## 8. 性能与稳定性

- 共享容量控制使用 provider 级 token bucket、负健康缓存和带抖动退避。
- 批次大小根据上下文预算、平均输出长度、限流历史和失败率在 1–3 节间自适应。
- 真实基准分别记录模型耗时、排队、资料处理、检索、确定性编译和教师等待，不用一个端到端数字掩盖瓶颈。
- 发布门使用至少 20 次独立 12 节运行；固定输入、资料版本、模型池、参数和质量合同版本。

## 9. 迁移与回滚

- 新投影和正式教案文档先作为只读增强，不改变现有课程与教案真源。
- 知识图谱新字段向后兼容；旧课程缺少字段时显示治理缺口，不在读取时伪造。
- 两段式检索与高保真解析通过独立开关灰度；关闭后继续使用现有已保存证据包。
- 回滚关闭新编排入口和新 UI 投影，不删除任何已完成单元、教案修订、知识库或课程文档。
