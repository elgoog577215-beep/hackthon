# D-05 生成与导入任务可观察性

## CAPABILITY

教师在课程生成或课程导入期间，可以在同一个任务中心确认任务正在做什么、已经完成什么、为什么失败，以及继续操作会复用或重做哪些成果。任务即使跨页面或服务重启，也保留可查询的状态和恢复入口。

## CONSTRAINTS

- 用户可见的标准阶段固定为：资料接收、解析与分类、检索证据、内容生成、质量检查、导出与发布。
- 后端可以保留更细的内部阶段，但每个内部阶段必须稳定投影到一个标准阶段。
- 产物生成过程中的局部校验（例如目录、教案批次、知识图谱校验）仍属于“内容生成”；只有跨产物的最终质量闸门进入“质量检查”。
- 课程现场标题下方显示实时任务摘要，至少包含当前动作；有批次/条目计数和更新时间时一并显示，暂停、中断、待确认和完成时切换为对应结果与恢复提示。
- 课程现场实时摘要与顶部六阶段条必须由同一任务状态投影，不能出现“教案仍在生成、质量检查却已完成”的冲突。
- 通用启动文案（如“正在处理”或“正在生成”）不得覆盖已经可确定的精确阶段；当前阶段缺失或落后于引导工作流时，界面必须从 `guided_workflow` 与 `recovery` 合同恢复精确投影。
- 正文内容达到 `18/18` 只代表内容产物已齐备，不代表课程已经发布；发布前检查进行中时显示“质量检查”进行中、“导出与发布”待开始。
- 发布质量检查阻断时显示“质量检查”受阻、“导出与发布”待开始；旧阶段历史不得把当前阶段之后的步骤重新标为完成。
- 失败任务不得显示为 100% 成功；100% 仅表示可用成果已经产出并进入完成状态。
- 运行任务必须公开最后心跳时间；超过两分钟没有更新时，界面提示“可能停滞”，但不擅自宣告失败。
- 错误信息同时包含用户可读原因、技术错误码和建议动作。技术详情可以折叠，不能代替用户文案。
- 恢复动作由后端恢复合同决定；前端不能根据失败状态猜测可恢复性。
- Markdown 导入源文件只作为任务私有恢复材料保存，不进入任务列表响应；任务完成后清理。

## IMPLEMENTATION CONTRACT

### Actors and surfaces

- 教师：从课程库发起导入，在任务中心查看进度、错误和恢复动作。
- 课程任务中心：混合展示生成与导入任务，并使用同一套六阶段状态。
- 课程生成页：继续保留教学审阅步骤，但其进度语义与任务中心共享。
- 课程生成页标题下方不再展示阶段说明性静态文案，改为 `aria-live="polite"` 的当前任务摘要；完整错误与恢复边界仍在任务中心和恢复卡片展示。
- 任务中心的精确当前动作使用单一、原子的礼貌播报区；阶段列表不整体重复播报，避免一次状态变化触发多段重复读屏。

### States and transitions

- `pending -> running -> completed`
- `running -> failed -> pending`：仅当恢复合同 `can_resume=true`。
- `running -> paused -> pending`：从最近保存点继续。
- 每次阶段变化写入有界 `phase_history`；当前阶段写入 `heartbeat_at`。

### Interfaces and data

- `POST /api/import_markdown/jobs` 创建持久化导入任务并立即返回任务 ID、预分配课程 ID。
- `/tasks` 和 `/tasks/{id}` 返回 `type`、`phase_history`、`heartbeat_at`、`error_code`、`error_user_message`、`recovery`。
- `POST /tasks/{id}/resume` 对导入任务复用源文件和已解析检查点，不创建重复课程。

## NON-GOALS

- 本轮不实现文件夹选择、目录结构纠正或多文件自动分类策略。
- 本轮不新增联网检索算法，只如实显示现有检索/题库补充阶段；无需检索的导入任务将该阶段标为已跳过。
- 本轮不改变课程生成的教学审阅和发布策略。

## OPEN QUESTIONS

- 多文件/文件夹导入进入后，需要确定批次失败是“部分成功”还是“整批回滚”。
- 导入源文件的生产保留时长需要后续形成平台级数据保留策略。

## HANDOFF

合同已具备直接实现条件；使用 TDD 覆盖阶段投影、错误状态、停滞检测、导入持久化和恢复。
