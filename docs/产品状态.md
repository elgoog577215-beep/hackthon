## 1. 当前判断

灵知已经跨过功能原型拼装，课程数据和主要生成入口已经统一；当前重点是整理旧写入、补齐异常恢复，并用多学科真实课程检查生成质量。

课程生成、结构化课程、正式练习、学习事实、AI 老师、课程调整和 PPT 同源表达都已有真实代码与入口；当前主要问题不再是功能是否存在，而是异常恢复、修改影响计算和跨模块验收还未全部达到可发布标准。真实“微积分”课程已经贯通大纲、分讲教案、确认讲义、正式题库和教师学生视角预览，但一次数学课程成功不等于跨学科质量已经完成。

当前不能对外宣称“完整课程 Agent 已完成”，原因集中在四处：

1. 课程知识仍缺完整的独立修订仓库、知识命令，以及课程与知识双向变化时的影响计算和处理。
2. 课程生长已有样板纵向链，但完整操作代数、部分接受后的依赖重算、跨域恢复和广域真实验收仍在建。
3. 教师端产品路径已收束为“我的课程（默认）/ 我的日历 → 课程空间 → 学生视角预览”。新课程的正式层级只有“课程 → 第 N 讲”，知识点与教学块只存在于讲内；历史章/节课程保持兼容读取，不执行迁移。课程创建、查看和编辑共用中英文名称、代码、层次、类别、学分、周/总学时、先修课、学年学期、有效周次、地点和 7×13 周课表合同，每格固定 45 分钟并允许一周多次、连续任意格；系统据此建议讲数，最终由教师确认。停课、调课和补课等待浙大系统接入。课程工作台保持既有三栏布局，主链为“大纲 → 教案 → 讲义 → PPT”，题库、教学日历、评分细则和自查清单归入其他课程文件。课程信息入口始终位于右侧资料栏顶部；资料栏在生成前分别提供资料文件和参考文件上传，并在同一栏提供唯一的整课生成入口；生成中隐藏添加与移除并切换为实际来源、整课进度和暂停/继续/取消，失败后保留来源并支持调整或重试，生成完成但未确认时恢复来源核对；内容确认后右栏改为已使用资料摘要，默认收起上传入口，只有教师主动选择“调整资料”才重新展开，并明确资料变化不会直接改动已确认内容。联网未配置时不显示联网入口。教案同时支持“生成全部教案”和“只生成本讲”：批量任务严格按课程顺序串行，单讲任务只处理当前讲且不要求前序讲次完成；中栏在首次生成前显示本讲准备、推荐课型、推荐理由和教学块摘要，教师确认或调整课型后再生成。每讲保留独立任务、工作修订和恢复点。在线教案与导出共用基本信息、知识目标、能力目标、育人目标、重难点、按需课前准备、动态教学块、总结、作业/拓展、拓展阅读和教师课后活动照片合同。每个教学块包含时长、目标内容、资料工具、师生活动、产出、检查、反馈调整、三档处理、进入支持、分组、衔接及讲义/PPT 映射，并按学科选择结构，不再固定案例、讨论和实践顺序。AI 审阅入口保留为“提出要求 → 查看影响 → 审阅候选 → 应用或撤销”。课程级状态只显示“备课中 / 备课完成”，并由确认大纲及所有计划讲次的确认教案、讲义和 PPT 确定性推导。旧教师 API、数据和内部 `script`、章/节 ID 仍处于兼容期，不构成第二套用户路径。
   准备弹窗和课程文件系统已共用正文解析与整批 AI 理解：同一工作包统一返回文档用途、课程/章节位置、版本角色和原件关系，并持久化依据、置信度、缺失材料、低置信结果与明确降级状态。现有解析管线已补齐旧 `.doc/.ppt/.xls` 隔离临时转码、扫描 PDF 本地逐页 OCR，以及 PPTX 对象位置、图表系列、讲者备注、图片数量/替代文本和动画存在性证据；原件保持不可变，无法确定的图片、复杂公式、动画和完整视觉语义只记录边界与降级警告。文件管理已补齐多选、批量移动、重命名、自定义文件夹管理和回收站；低频操作放在选中后的批量栏与右键菜单，被正式文件引用的原件仍禁止移入回收站。教师修正优先于后续 AI 批次；当前已用真实模型验证名称模糊的中文教案及同讲关系，跨学科、复杂扫描表格/公式和超大型文件包质量仍需继续验收。
   PPT 工作区按资料情况支持三种处理：无额外资料时执行“确认讲义 → 页面内容稿 → PPT”；有主参考、参考资料或联网来源但无 PPTX 时，用独立 `ppt-v6:{lesson_unit_id}` 关系保存本次确认的资料，讲义仍是内容语义真源，资料只指导案例、依据与页面表达；已有 PPTX 时保留原件，对照当前大纲、已确认教案、题库、讲义和 PPT 工作区资料生成审阅报告，不默认重生成整套 PPT。无原版 PPT 的生成界面已拆成两个真实步骤：第一步独立生成、完整展示并确认 `ppt_manuscript_v1`；第二步仅在确认后解锁，并读取已确认的页面内容稿修订确定性生成 deck，不能再次调用内容规划器改写。页面内容稿质量门会阻断原始 LaTeX 标题、相邻页重复、缺失页面任务/结论和故事规划降级；上游变化同时使页面内容稿和 PPT 过期。右侧资料区在 PPT 工作区保持可用；`ppt_manuscript_v1` 保存已确认的资料关系与每页相关证据 ID。上传 PPTX 不要求前四步已完成，也不进入上述两步生成；原件保持不可变，手工编辑与 AI 候选都形成新修订，教师显式确认后才登记为当前 PPT；当前实现只承诺文字与结构审阅，不冒充完整版式、图表和动画编辑。
   生产 AI 修改已进入统一协作模式：左侧正式内容画布承载候选与高亮，右侧助手承载多轮要求、必要澄清、生成/审阅/采用/放弃/失败重试状态与操作回执。助手在模型调用前分流三类要求：含糊要求先澄清；当前对象的小改继续调用大纲、教案、讲义、题库或 PPT 的原候选接口；多资产、整课批量替换和章讲小节删并移换直接调用原 `/evolution/course-plans` 接口，并在同一侧栏显示尚未应用的方案与真实影响摘要。教师点击“查看并确认”进入同一“审计与更新中心”；课程工作台只保留一个入口，原材料审计与课程调整地址只作兼容跳转。前端组合 Store 只统一变化来源与页面选中状态，未增加平行正式数据 Store、公开 API 或课程真源。教师全课要求现在能把精确内容补丁编译为正式块替换，也能把完整目标树、身份映射和显式退休节点编译为一次结构重建；两者都进入现有 `CourseEvolutionPlan` 和操作组，支持逐项排除、应用数量、前后差异、实际 applied / failed / unchanged 回执和整次撤销。确认范围或结构后，原生成入口会把已审阅迁移继续编译为教案候选、讲义分节候选、V6 PPT 页批次候选和题库修订候选；原 accept/undo 入口调用各领域既有采用与回退能力。精确术语替换会确定性扫描六类可编辑文字，保护 ID、修订、来源和答案真值；自由语义修改仍经过各资产质量门。跨仓储写入不是单一数据库事务，部分失败必须按资产回执呈现并保留 last-good，不能把预计影响冒充已应用结果。

4. 教学语义已经深化为“课程合同 → 讲次合同 → 教学块实施合同”：`学习目的 × 一级学科类型 × 课程教学类型` 形成整课结构，`本讲目标 × 本讲课型 × 学科规则 × 课程约束` 形成课堂主弧，每个教学块必须写清教师动作、学习者行动、学习证据、检查、反馈调整、进入支持与前后衔接。第三版统一语义编译器已接入 `subject_standard_pack_v1`：八种一级学科及常用学科画像共用版本化的专业动作、典型产物、证据、误区、来源与安全边界、产物语言、质量规则和教学块配方。大纲读取整份标准包，教案从原“总体教案引领”读取学科教案语言，讲义读取学科讲授语言，题库在原出题上下文中读取学科题目语言，PPT 继续只从已确认讲义和课程块提取学习者需要看到的内容，不另建文案链。本地固定样本已覆盖八类学科、三种学习目的和六种课程教学类型并通过编译检查；105 个旧模块去重、更多学院样本、全历史数据对账、真实课堂记录和真实模型跨学科验收仍未完成，不能把本地测试等同于所有学科的真实生成质量。
5. 产品还缺真实长期学习样本证明“课程调整后确实改善，失败时能够回退”。

## 2. 成熟度口径

| 状态 | 含义 |
| --- | --- |
| 稳定基座 | 真源、写入链、异常合同和主要回归已经稳定，可被其他能力依赖 |
| 主链可用 | 正常路径已进入生产主链，仍有边界、兼容或完整验收缺口 |
| 样板可用 | 已有真实使用样板，但尚未覆盖任意范围、异常组合或大规模场景 |
| 在建 | 正在由活动 OpenSpec 实施，不能作为完成能力承诺 |
| 待验证 | 实现或设计存在，但缺真实用户、真实模型、长期效果或视觉证据 |

成熟度描述的是当前证据，不是百分比，也不替代 OpenSpec 任务状态。

## 5. 当前攻坚顺序

### 5.1 立即收尾

完成 Mermaid 已知导入样本的真实 UI 验收。该工作没有新的产品设计依赖，完成后应归档规格，减少活动变更噪音。

### 5.2 当前主攻

教师端三段主路径已经收束产品入口；当前主攻转为文件空间内的领域作者能力和兼容退场：

1. 已完成第一版新旧教学字段适配，继续补齐历史课程批量对账、回滚和全部兼容调用的来源记录。

3. 大纲入口已显示学习目的、一级学科和课程教学类型；下一步在当前讲教案中投影本讲课型、推荐依据、师生行动、证据、反馈分支与修改影响，并把同一正式数据继续投影为课中实施和课后复盘状态。
