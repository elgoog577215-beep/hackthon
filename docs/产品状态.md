## 1. 当前阶段判断

灵知已经跨过“功能原型拼装”阶段，进入**统一真源后的主链收束期**。

课程生成、结构化课程、正式练习、学习事实、AI 老师、课程调整和 PPT 同源表达都已有真实代码与入口；当前主要问题不再是功能是否存在，而是这些能力的正式合同、异常恢复、影响分析和跨模块验收还没有全部闭合。

现阶段不能对外宣称“完整课程 Agent 已完成”，原因集中在四处：

1. 课程知识仍缺完整的独立修订仓库、知识命令和双向影响闭环。
2. 课程生长已有样板纵向链，但完整操作代数、部分接受后的依赖重算、跨域恢复和广域真实验收仍在建。
3. 教师端课程与教案生产工作台 V1 已进入实施；教案已形成可编辑纵向样板，但课程要求、目录、正文作者命令和完整下游重建仍未闭合。
4. 产品还缺真实长期学习样本证明“课程调整后确实改善，失败时能够回退”。

## 2. 成熟度口径

| 状态 | 含义 |
| --- | --- |
| 稳定基座 | 真源、写入链、异常合同和主要回归已经稳定，可被其他能力依赖 |
| 主链可用 | 正常路径已进入生产主链，仍有边界、兼容或完整验收缺口 |
| 局部闭环 | 已有真实纵向样板，但尚未覆盖任意范围、异常矩阵或规模化场景 |
| 在建 | 正在由活动 OpenSpec 实施，不能作为完成能力承诺 |
| 待验证 | 实现或设计存在，但缺真实用户、真实模型、长期效果或视觉证据 |

成熟度描述的是当前证据，不是百分比，也不替代 OpenSpec 任务状态。

当前 4×8 微积分完整链路的本机 Codex 研发验收进一步收紧了上述判断：目录耗时约 139 秒、全课教案阶段约 1672 秒，8 节模型正文的单节生成耗时中位数约 251 秒，均未达到活动 OpenSpec 的发布时延门。本次产物覆盖 8/8 节模型正文、8 份 45 分钟小节教案以及 31 个知识节点、65 条前置关系，但知识质量报告仍为 `strict_passed=false`，关系图也只有前置关系、没有来源落地；因此它证明了内容深度和检查点恢复能力，不能证明速度、生产稳定性或知识图谱完整性。

当前优化批次已先收紧“不能误报完成”的边界，并减轻教师等待时的认知负担：题目生成不再暴露“快速/思考”两套策略，复杂题与关键修复自动使用必要推理，其余单元通过批量并行、有界恢复和本地确定性求解提速，不减少质量门或重试预算；课程生成已把原来同一模型输出中的知识工程与教学设计拆成先后两波并行批次，知识未冻结且未达到教学就绪不启动教案，检查点只重试失败批次并校验课程设计合同修订；`SubjectGenerationTemplateV3` 与 `CourseDesignContractV4` 让学科分型、阶段责任、指令优先级、资料隔离、结果密度和实际产物质量成为不可压缩质量内核，运行预算只压缩重复上下文；`course_prompt_v37` 又把创始人通读发现的内容问题写回正式结构：每门课冻结 `course_spine` 与跨节闭环义务，正文限制为一个主任务和最多一个真迁移任务，禁止重复完整解答、重复矩阵、学习者可见生成腔与未交付证据，关键数值必须用平衡/反代/比例等独立关系交叉核验，外部定理依赖必须显式命名。固定微积分与机械设计各三节样本中，候选相对旧版匿名胜出，并修复了机械三节数据漂移、启动静强度漏验、刚度证据冒领、30 mm 轴应力不一致，以及微积分循环/隐含先修和净变化迁移不足；但这仍是单次本地 Codex 研发样本，不代表 4×8/4×12 端到端真实模型性能门已经通过。

## 5. 当前攻坚顺序

### 5.1 立即收尾

完成 Mermaid 已知导入样本的真实 UI 验收。该工作没有新的产品设计依赖，完成后应归档规格，减少活动变更噪音。

### 5.2 当前主攻

以教师端课程与教案生产工作台 V1 为当前总控，先收束其教案前置能力，再展开其他作者链：

1. 在已合并的课程生成与教案成果上，先交付简化填写/过程体验和正式教案默认视图。
2. 补齐教案模块增删排序、知识结构操作、字段级恢复，以及下游复用、过期、定向重建和失败保留状态。
3. 继续补齐扫描资料公式/图表/讲者备注/工作表保真，并扩展课程局部知识图谱的条件、边界、正反例、能力、易错和掌握关系。
4. 扩展课程要求与目录结构命令，再接入正文作者命令和统一版本恢复。
5. 用固定 4×8 与跨学科 4×12 基准完成至少 20 次真实模型运行，未达到成功率和 P50/P95 时继续定位串并行、配额与恢复瓶颈。

### 5.3 下一主链

教案工作台收束后，回到结构化自适应课程 OpenSpec 的前置缺口：

```text
课程知识独立修订与命令
-> 证据治理与来源回跳
-> 课程操作组和依赖索引
-> 任意范围课程生长
-> 独立效果复验
```

不能先扩张自主 Agent、自由多模态或新顶层入口，因为这些能力仍依赖上面的真源、命令和效果合同。

## 7. 状态更新门

只在以下情况更新本文：

- 能力首次进入正式主链。
- 主链从局部闭环升级为稳定基座。
- 关键缺口、风险或当前主攻发生变化。
- OpenSpec 新建、归档、替换或范围发生实质变化。
- 真实验证推翻原有完成判断。

普通提交、测试数量、Prompt 版本、单个 bug 和每日进度不进入本文。它们留在 Git、架构文档、OpenSpec 或验收记录中。
