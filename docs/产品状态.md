## 1. 当前判断

灵知已经跨过功能原型拼装，课程数据和主要生成入口已经统一；当前重点是整理旧写入、补齐异常恢复，并用多学科真实课程检查生成质量。

课程生成、结构化课程、正式练习、学习事实、AI 老师、课程调整和 PPT 同源表达都已有真实代码与入口；当前主要问题不再是功能是否存在，而是异常恢复、修改影响计算和跨模块验收还未全部达到可发布标准。真实“微积分”课程已经贯通大纲、分讲教案、确认讲稿、正式题库和教师学生视角预览，但一次数学课程成功不等于跨学科质量已经完成。

当前不能对外宣称“完整课程 Agent 已完成”，原因集中在四处：

1. 课程知识仍缺完整的独立修订仓库、知识命令，以及课程与知识双向变化时的影响计算和处理。
2. 课程生长已有样板纵向链，但完整操作代数、部分接受后的依赖重算、跨域恢复和广域真实验收仍在建。
3. 教师端产品路径已收束为“我的日历 / 我的课程 -> 课程空间 -> 学生视角预览”：学生视角预览直接读取教师当前课程投影，不再设置整门课程的“学生网站”“待发布修改”或二次发布动作；当前投影以大纲工作区为结构真源，只叠加仍匹配当前确认教案且通过现行质量门的确认讲稿，避免任务完成后退回旧发布快照。大纲、教案、讲稿和 PPT 继续由各自确认状态守门。新建课程在教师首页以弹窗打开，名称是唯一必填项，其他基本信息默认展开，文件统一在课程空间上传；提交后直接进入课程工作台，并在工作台上选择“从零开始”或“基于已有资料”。后一模式在短弹窗中批量导入原始文件、确认系统识别出的大纲/教案/讲稿/PPT/题库/教务材料结构，再回到同一工作台。每个工作区第一次打开时按资料类型和讲次自动匹配主来源与参考资料，老师后续替换、增补或清空后不再被自动结果覆盖。课程工作台现提供“大纲、教案、题库、讲稿、PPT”五个非阻塞入口，左侧为备课步骤、中间为表单/流式生成/正式内容、右侧为主来源、参考资料与联网来源。教师大纲任务先流式生成带名称的大章节骨架，在同一中间栏逐章确认小节数后恢复原任务并持续生成小章节；总学时不再自动换算小节，完整大纲也在中间栏审阅编辑。一章只有一节是合法教学结构，数据仍保留章/节两级，界面只在该状态下收起重复的小节标题或子标签；多节时继续完整显示并支持独立编辑。分讲教案已收束为同一份标准教案：现有教学策略仍投影为内部课型和有序教学块，但前端不再提供逐块编辑器；老师点击“生成本讲教案”时系统自动锁定当前建议并启动原 `CourseTeachingPlanV3` 引擎，生成后通过 AI 助手说明影响、形成调整或重新生成候选。未锁定内部编排的直接请求仍由后端拒绝。教案生成的可见正文增量按批次持久化并通过 SSE 推送，原页面立即显示可读工作稿，断线可恢复且失败不清空已生成片段；完成后再用通过质量门的完整修订替换工作稿。查看、编辑、AI 候选和确认均在同一中间内容面完成，并继续复用知识范围修订锚点与 `standard_lesson_plan_v1` 质量门。教案质量门现额外阻断把资料边界、模型策略、质量门和抽象流程套话写进教师可见文本。每讲只保存一份正式讲稿资产；讲稿已用有稳定身份、角色、知识和时间绑定的教师讲稿块取代自由 Markdown 真源，并改为按确认教学块逐块生成：每完成一块就写入同一持久任务并通过 SSE 投影，刷新或局部失败保留已完成内容，重试只继续缺失块，全部通过结构质量门后才原子写入正式讲稿修订。工作台原位展示完成块、当前进度和失败后的“继续生成剩余内容”。讲稿生成已吸收旧正文链的学科讲解、知识边界、前后连贯和内容完整性能力，并从现有教学模块确定性编译八类学科产物与课堂动作合同；`direct_teaching_script_v8` 与 `teacher_script_quality_v8` 同时阻断缺失的必要代码/公式、公式或代码格式不完整、不可执行的练习/反馈、教材式正文、机械调度标签、内部系统语言、罐头衔接语、缺失块间过渡、模板占位、跨块复读和不足以支撑整讲时长的浅层内容。模型生成、教师编辑、AI 候选采用、本地恢复和旧版兼容共用同一确认门；质量版本变化后旧报告不能继续放行。提供方失败时只保存明确标记的可编辑恢复草稿，不得确认或进入 PPT，失败任务与当前正文来源在页面中分开呈现。真实模型跨学科自然度、准确性与时长对照仍需继续验证。内容编排由前述分类确定性编译，不再作为独立教师偏好；每次生成直接以所选主来源、参考资料和联网来源形成资料边界，不再要求选择资料使用方式。教师选择 DOCX、PDF、Markdown 或 TXT 原教案为主来源时，系统复用资料解析器保留原顺序、块类型和页码/路径并按当前讲映射；PPTX 才走旧课件证据提取。PPT 通过教师 `SlideDeckV6` 工作台只消费带明确修订且覆盖全部小节的已确认讲稿块；旧轻量 PPT 写链已删除，历史文件只读导出，视觉模板只负责版式容量，不反向改变课型与教学结构。教案和讲稿任务现共用 `teacher_asset_job_v1` 的幂等键、心跳、检查点、停止与恢复合同；教师停止后保留已完成块。教案、题库、讲稿和 PPT 交接共享讲次导航。联网来源从当前工作区打开调研对话框，显示真实检索词、网域覆盖、正文深读状态、可信分级和许可；后端在原搜索接口内按查询/网域重排并有界读取 HTML/PDF 正文，单页失败回退摘要，只有教师勾选后才转成课程资料资产并进入证据链。题库可以跳过，组卷作为题库内部操作，保存后的题库与试卷由文件视图管理。五步之外已增加不编号的“配套文档”模板库，首批提供浙大评分细则和考试课程材料自查清单，生成物作为可修订、可导出的课程正式文件进入文件空间。旧教师 API/源码仍处于数据审计兼容期，完整下游精确重建尚未完成。
   准备弹窗和课程文件系统已共用正文解析与整批 AI 理解：同一工作包统一返回文档用途、课程/章节位置、版本角色和原件关系，并持久化依据、置信度、缺失材料、低置信结果与明确降级状态。现有解析管线已补齐旧 `.doc/.ppt/.xls` 隔离临时转码、扫描 PDF 本地逐页 OCR，以及 PPTX 对象位置、图表系列、讲者备注、图片数量/替代文本和动画存在性证据；原件保持不可变，无法确定的图片、复杂公式、动画和完整视觉语义只记录边界与降级警告。文件管理已补齐多选、批量移动、重命名、自定义文件夹管理和回收站；低频操作放在选中后的批量栏与右键菜单，被正式文件引用的原件仍禁止移入回收站。教师修正优先于后续 AI 批次；当前已用真实模型验证名称模糊的中文教案及同讲关系，跨学科、复杂扫描表格/公式和超大型文件包质量仍需继续验收。
   PPT 工作区按资料情况支持三种处理：无额外资料时执行“确认讲稿 → PPT 文书 → PPT”；有主参考、参考资料或联网来源但无 PPTX 时，用独立 `ppt-v6:{lesson_unit_id}` 关系保存本次确认的资料，讲稿仍是内容语义真源，资料只指导案例、依据与页面表达；已有 PPTX 时保留原件，对照当前大纲、已确认教案、题库、讲稿和 PPT 工作区资料生成审阅报告，不默认重生成整套 PPT。无原版 PPT 的生成界面已拆成两个真实步骤：第一步独立生成、完整展示并确认 `ppt_manuscript_v1`；第二步仅在确认后解锁，并读取已确认的文书修订确定性生成 deck，不能再次调用内容规划器改写。文书质量门会阻断原始 LaTeX 标题、相邻页重复、缺失页面任务/结论和故事规划降级；上游变化同时使文书和 PPT 过期。右侧资料区在 PPT 工作区保持可用；`ppt_manuscript_v1` 保存已确认的资料关系与每页相关证据 ID。上传 PPTX 不要求前四步已完成，也不进入上述两步生成；原件保持不可变，手工编辑与 AI 候选都形成新修订，教师显式确认后才登记为当前 PPT；当前实现只承诺文字与结构审阅，不冒充完整版式、图表和动画编辑。
   生产 AI 修改已进入统一协作模式：左侧正式内容画布承载候选与高亮，右侧助手承载多轮要求、必要澄清、生成/审阅/采用/放弃/失败重试状态与操作回执。教师全课要求现在能把精确内容补丁编译为正式块替换，也能把完整目标树、身份映射和显式退休节点编译为一次结构重建；两者都进入现有 `CourseEvolutionPlan` 和操作组，支持逐项排除、应用数量、前后差异、实际 applied / failed / unchanged 回执和整次撤销。确认范围或结构后，原生成入口会把已审阅迁移继续编译为教案候选、讲稿分节候选、V6 PPT 页批次候选和题库修订候选；原 accept/undo 入口调用各领域既有采用与回退能力，不增加平行页面、公开 API 或第二份课程真源。精确术语替换会确定性扫描六类可编辑文字，保护 ID、修订、来源和答案真值；自由语义修改仍经过各资产质量门。跨仓储写入不是单一数据库事务，部分失败必须按资产回执呈现并保留 last-good，不能把预计影响冒充已应用结果。

4. 教学语义已经深化为“课程合同 → 讲次合同 → 教学块实施合同”：`学习目的 × 一级学科类型 × 课程教学类型` 形成整课结构，`本讲目标 × 本讲课型 × 学科规则 × 课程约束` 形成课堂主弧，每个教学块必须写清教师动作、学习者行动、学习证据、检查、反馈调整、进入支持与前后衔接。第三版统一语义编译器已接入 `subject_standard_pack_v1`：八种一级学科及常用学科画像共用版本化的专业动作、典型产物、证据、误区、来源与安全边界、产物语言、质量规则和教学块配方。大纲读取整份标准包，教案从原“总体教案引领”读取学科教案语言，讲稿读取学科讲授语言，题库在原出题上下文中读取学科题目语言，PPT 继续只从已确认讲稿和课程块提取学习者需要看到的内容，不另建文案链。本地固定样本已覆盖八类学科、三种学习目的和六种课程教学类型并通过编译检查；105 个旧模块去重、更多学院样本、全历史数据对账、真实课堂记录和真实模型跨学科验收仍未完成，不能把本地测试等同于所有学科的真实生成质量。
5. 产品还缺真实长期学习样本证明“课程调整后确实改善，失败时能够回退”。

## 2. 成熟度口径

| 状态 | 含义 |
| --- | --- |
| 稳定基座 | 真源、写入链、异常合同和主要回归已经稳定，可被其他能力依赖 |
| 主链可用 | 正常路径已进入生产主链，仍有边界、兼容或完整验收缺口 |
| 样板可用 | 已有真实使用样板，但尚未覆盖任意范围、异常组合或大规模场景 |
| 在建 | 正在由活动 OpenSpec 实施，不能作为完成能力承诺 |
| 待验证 | 实现或设计存在，但缺真实用户、真实模型、长期效果或视觉证据 |

成熟度描述的是当前证据，不是百分比，也不替代 OpenSpec 任务状态。
