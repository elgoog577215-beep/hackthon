## 1. 当前阶段判断

灵知已经跨过“功能原型拼装”阶段，进入**统一真源后的主链收束期**。

课程生成、结构化课程、正式练习、学习事实、AI 老师、课程调整和 PPT 同源表达都已有真实代码与入口；当前主要问题不再是功能是否存在，而是这些能力的正式合同、异常恢复、影响分析和跨模块验收还没有全部闭合。

现阶段不能对外宣称“完整课程 Agent 已完成”，原因集中在四处：

1. 课程知识仍缺完整的独立修订仓库、知识命令和双向影响闭环。
2. 课程生长已有样板纵向链，但完整操作代数、部分接受后的依赖重算、跨域恢复和广域真实验收仍在建。
3. 教师端产品路径已收束为“我的日历 / 我的课程 -> 课程空间 -> 学生视角预览”：新建课程在教师首页以弹窗打开，名称是唯一必填项，其他基本信息默认展开，文件统一在课程空间上传；提交后先进入空课程工作台。课程工作台现提供“课程基础、教案、题库、讲稿、PPT”五个非阻塞入口，左侧为阶段、中间为表单/流式生成/正式内容、右侧为主来源、参考资料与联网来源。教师大纲任务先流式生成带名称的大章节骨架，在同一中间栏逐章确认小节数后恢复原任务并持续生成小章节；总学时不再自动换算小节，完整大纲也在中间栏审阅编辑。分讲教案已收束为同一份标准教案：现有教学策略仍投影为内部课型和有序教学块，但前端不再提供逐块编辑器；老师点击“生成本讲教案”时系统自动锁定当前建议并启动原 `CourseTeachingPlanV3` 引擎，生成后通过 AI 助手说明影响、形成调整或重新生成候选。未锁定内部编排的直接请求仍由后端拒绝。教案生成的可见正文增量按批次持久化并通过 SSE 推送，原页面立即显示可读工作稿，断线可恢复且失败不清空已生成片段；完成后再用通过质量门的完整修订替换工作稿。查看、编辑、AI 候选和确认均在同一中间内容面完成，并继续复用知识范围修订锚点与 `standard_lesson_plan_v1` 质量门。每讲只保存一份正式讲稿资产；讲稿已用有稳定身份、角色、知识和时间绑定的教师讲稿块取代自由 Markdown 真源，并改为按确认教学块逐块生成：每完成一块就写入同一持久任务并通过 SSE 投影，刷新或局部失败保留已完成内容，重试只继续缺失块，全部通过结构质量门后才原子写入正式讲稿修订。工作台原位展示完成块、当前进度和失败后的“继续生成剩余内容”。讲稿生成已吸收旧正文链的学科讲解、知识边界、前后连贯和内容完整性能力，并从现有教学模块确定性编译八类学科产物与课堂动作合同；`teacher_script_quality_v2` 阻断缺失的必要代码/公式和未闭合格式，表格与活动/反馈可执行性进入审核提示，失败后做一次针对性修复。真实模型跨学科对照仍需继续验证。内容编排由前述分类确定性编译，不再作为独立教师偏好；每次生成直接以所选主来源、参考资料和联网来源形成资料边界，不再要求选择资料使用方式。教师选择 DOCX、PDF、Markdown 或 TXT 原教案为主来源时，系统复用资料解析器保留原顺序、块类型和页码/路径并按当前讲映射；PPTX 才走旧课件证据提取。PPT 通过教师 `SlideDeckV6` 工作台只消费带明确修订且覆盖全部小节的已确认讲稿块；旧轻量 PPT 写链已删除，历史文件只读导出，视觉模板只负责版式容量，不反向改变课型与教学结构。教案和讲稿任务现共用 `teacher_asset_job_v1` 的幂等键、心跳、检查点、停止与恢复合同；教师停止后保留已完成块。教案、题库、讲稿和 PPT 交接共享讲次导航。联网来源从当前阶段打开调研对话框，显示真实检索词、网域覆盖、正文深读状态、可信分级和许可；后端在原搜索接口内按查询/网域重排并有界读取 HTML/PDF 正文，单页失败回退摘要，只有教师勾选后才转成课程资料资产并进入证据链。题库可以跳过，组卷作为题库内部操作，保存后的题库与试卷由文件视图管理。五步之外已增加不编号的“配套文档”模板库，首批提供浙大评分细则和考试课程材料自查清单，生成物作为可修订、可导出的课程正式文件进入文件空间。旧教师 API/源码仍处于数据审计兼容期，完整下游精确重建尚未闭合。
   PPT 第五步已按真实资料现场收拢为三分支：无额外资料时执行“确认讲稿 → PPT 文书 → PPT”；有主参考、参考资料或联网来源但无 PPTX 时，用独立 `ppt-v6:{lesson_unit_id}` 关系冻结资料，讲稿仍是内容语义真源，资料只指导案例、依据与页面表达；已有 PPTX 时保留原件，对照当前大纲、已确认教案、题库、讲稿和 PPT 阶段资料生成审阅报告，不默认重生成整套 PPT。右侧资料区在 PPT 阶段保持可用；`ppt_manuscript_v1` 保存冻结的资料关系与每页相关证据 ID。上传 PPTX 不要求前四步已完成；原件保持不可变，手工编辑与 AI 候选都形成新修订，教师显式确认后才登记为当前 PPT；当前实现只承诺文字与结构审阅，不冒充完整版式、图表和动画编辑。
   生产 AI 修改已进入统一协作模式：左侧正式内容画布承载候选与高亮，右侧助手承载多轮要求、必要澄清、生成/审阅/采用/放弃/失败重试状态与操作回执。大纲、教案、题库、讲稿和 V6 PPT 共用界面和状态机，但各自使用专用后端适配器和安全边界；题库候选只冻结重建任务，讲稿和 PPT 候选绑定基线修订并可跨刷新恢复。每次请求冻结精确资料 ID 与范围，候选采用前显示讲稿、题库和 PPT 的下游影响，但不自动改写任何下游正式内容。

4. 产品还缺真实长期学习样本证明“课程调整后确实改善，失败时能够回退”。

## 2. 成熟度口径

| 状态 | 含义 |
| --- | --- |
| 稳定基座 | 真源、写入链、异常合同和主要回归已经稳定，可被其他能力依赖 |
| 主链可用 | 正常路径已进入生产主链，仍有边界、兼容或完整验收缺口 |
| 局部闭环 | 已有真实纵向样板，但尚未覆盖任意范围、异常矩阵或规模化场景 |
| 在建 | 正在由活动 OpenSpec 实施，不能作为完成能力承诺 |
| 待验证 | 实现或设计存在，但缺真实用户、真实模型、长期效果或视觉证据 |

成熟度描述的是当前证据，不是百分比，也不替代 OpenSpec 任务状态。

## 5. 当前攻坚顺序

### 5.1 立即收尾

完成 Mermaid 已知导入样本的真实 UI 验收。该工作没有新的产品设计依赖，完成后应归档规格，减少活动变更噪音。

### 5.2 当前主攻

教师端三段主路径已经收束产品入口；当前主攻转为文件空间内的领域作者能力和兼容退场：

1. 先完成旧整课链与新工作台的能力复用矩阵：成熟大纲、教案、任务恢复、质量门和提示词模板必须有明确归宿，禁止重写同等能力。
2. 让新工作台统一经过“自动锁定本讲教学结构 -> 生成并确认教案 -> 生成并确认讲稿 -> 生成 PPT”的一条教师生产链；题库、日历和配套文档保持非阻塞旁支。
3. 重点重构讲稿与 V6 PPT：旧正文模板只作为可复用能力输入，正式讲稿以已确认教案为上游，PPT 只消费已确认讲稿块。
4. 补齐教案、讲稿和 V6 PPT 的精确影响索引、失败恢复、版本回退、来源过期和定向重建。
5. 真实数据和兼容调用完成审计、迁移与回滚验证后，才把旧教师整课入口改为只读并删除旧路由、API 与写入；学生学习运行时不在本轮退场范围。
6. 完成真实模型性能、遥测、灰度、告警与回滚发布门。

### 5.3 下一主链

教案工作台收束后，回到结构化自适应课程 OpenSpec 的前置缺口：

```text
课程知识独立修订与命令
-> 证据治理与来源回跳
-> 课程操作组和依赖索引
-> 任意范围课程生长
-> 独立效果复验
```

不能先扩张自主 Agent、自由多模态或新顶层入口，因为这些能力仍依赖上面的真源、命令和效果合同。
