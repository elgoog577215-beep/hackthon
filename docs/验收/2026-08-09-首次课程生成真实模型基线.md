## 为什么留这份

生成链改动风险高，但此前几轮验证都只跑了单元与组件测试——那些用假客户端，
证明不了真实模型下整条链能走通。这次环境里有可用配额，因此补上一次真实调用的
端到端基线，供后续改动前后对照。

## 运行方式

```bash
backend/.venv/bin/python scripts/generation_publication_smoke.py \
    --subject "一元一次方程的移项原理" --timeout 1800
```

提供方：`https://api.deepseek.com/v1`，模型 `deepseek-chat`（读 `.env`）。
脚本使用独立临时持久化目录，不写生产数据。

## 顺带修好的一处：smoke 脚本已过期

首次运行以 `烟测遇到非四步链路节点：teaching` 失败。排查确认**不是提供方问题**：
失败前 4 次真实调用全部 200 OK，是脚本自身把确认门硬编码成
`{"outline", "release"}`（四步链路时代的写法），而当前 `GUIDED_STEP_KEYS`
已是五步、并在 `teaching` 也暂停等待确认。

已改为集中常量 `REVIEW_GATE_STEPS = ("outline", "teaching", "release")` 并在
两处断言复用。`requirements` 由提交表单确认、`content` 由 worker 自动确认，
都不进入 `waiting_for_review`，故不在其中。
