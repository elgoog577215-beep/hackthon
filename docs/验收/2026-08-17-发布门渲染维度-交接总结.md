## 一句话

发布门的渲染维度是**两层**：后端文本判据负责低成本地消除「形状问题」，
`scripts/render_gate.mjs` 用真实渲染器负责兜住「形状修好之后仍然坏的内容」。
**两层缺一不可**——只跑文本层会放过 96.6% 的真实渲染缺陷。

## 现在拦什么、不拦什么

### 会阻断发布（critical）

| 错误码 | 含义 | 学习者会看到什么 |
|---|---|---|
| `render_gate:failed` | 真实渲染器判定该节渲染失败 | LaTeX 源码或错位排版 |
| `math_render_failed` / `block_render_failed` | 前端渲染时上报的失败 | 同上 |
| `unwrapped_display_environment` | 块级环境在 `$$` 外，**且归一化救不回** | 字面 `\begin{cases}` |
| `unclosed_math_fence` | `$$` 未闭合 | 后续正文被吞进公式 |
| `unclosed_code_fence` | ``` 未闭合 | 整段变成代码块 |
| `legacy_math_delimiter` | 单 `$` 独占行的旧式块级分隔符 | 公式不渲染 |

### 只告警、不阻断（warning / major / minor）

| 错误码 | 为什么不阻断 |
|---|---|
| `repairable_display_environment` | 源码不整洁，但渲染器会自动归一化，**学习者看到的是对的** |
| `table_missing_delimiter` / `table_delimiter_mismatch` | 表格结构问题，实测精确率低，降级为提示 |
| `markdown_block_join`、`feedback_math_as_code` | 影响观感，不影响正确性 |
| `empty_blockquote`、`list_numbering_restart` | 轻微排版瑕疵 |

### 明确不拦的

- **教学语义**（讲得对不对、深浅是否合适）——不在渲染维度的职责内；
- **缺空行的 `$$`**（正文与 `$$` 之间没有空行）——实测过，**决定不拦也不自动修**，
  理由见下方「已知不做的事」。

## 误报率与漏报率（8 门真实课程、792 节正文实测）

判定基准是**真实渲染器**（headless 跑 `frontend/src/utils/markdown.ts`，
与学习者浏览器同一条链路），不是人工判断。

| 门 | 阻断性误报 | 漏报 |
|---|---|---|
| 老口径（改造前） | 13/763 = **1.70%** | — |
| 只用文本判据（现状） | 4/763 = **0.52%** | 28/29 = **96.6%** ⚠️ |
| **文本判据 + `render_gate.mjs`** | 4/763 = **0.52%** | **0/29 = 0.0%** |

**读法**：判据越准，文本层单独能抓的越少——它抓的本来就是「形状」，
而形状修好之后仍然坏的内容只有真实渲染看得见。**这不是判据变差，
是职责边界变清楚了。所以发布前必须跑 `render_gate.mjs`。**

## 「我的内容被拦下来了，怎么办」

按拿到的错误码走：

**1. `render_gate:failed` / `math_render_failed`** —— 内容**真的**渲染坏了。

```bash
node scripts/render_gate.mjs --course <课程.json> --format text
```

输出会逐节点给出失败片段。常见三种成因（按出现频率）：

| 形态 | 例子 | 修法 |
|---|---|---|
| 块级围栏被拆开 | `$$\nV(x) =\n$$\n\begin{cases}…` | **已有自动修复**，见下 |
| 块级公式内混入 `$` | `\int_0^1 x \, $dx = …$` | 改内容 |
| 行内 `$…$` 未渲染 | `$\frac{a}{b}$` 显示为字面 | 改内容 |

第一种可以自动修：

```python
from canonical_content_repair import repair_display_math_shape
fixed = repair_display_math_shape(markdown)
```

它是**确定性形状修复**，不调模型、不改公式内容，已在写入 canonical 小节的
路径上自动生效（`persist_generated_node_content`）。**注意它只修形状**：
修完仍可能渲染失败，必须再跑一次 `render_gate.mjs` 确认。

**2. `unwrapped_display_environment`** —— 归一化救不回的块级环境。
最常见是环境名不匹配（`\begin{cases}` 配 `\end{aligned}`）。改内容。

**3. `repairable_display_environment`（warning）** —— **不用管**，
不阻断发布。想清理源码可以跑上面的修复函数。

**4. 判据本身可能错** —— 如果你确认渲染是正常的却被拦了，先用真实渲染器验证：

```bash
node scripts/render_gate.mjs --course <课程.json> --format text
```

渲染通过而判据阻断，就是误报，**改判据不要改内容**。改完必须重测误报率：

```bash
# 1) 重建真实语料（只读 git show，不动工作区）
python3 scripts/build_render_corpus.py --out /tmp/corpus

# 2) 用真实渲染器给每一节产出「渲染真值」
for f in /tmp/corpus/*.json; do
  node scripts/render_gate.mjs --course "$f" --quiet --out "/tmp/gate-$(basename "$f")"
done
python3 scripts/merge_render_truth.py --gate '/tmp/gate-*.json' --out /tmp/render_results.json

# 3) 对照判据与渲染真值，得出误报率 / 漏报率
python3 scripts/f1_render_gate_false_positive_probe.py \
  --corpus /tmp/corpus --render /tmp/render_results.json
```

跑通的样子：`误报 4/762 = 0.52%`、`漏报 29/30 = 96.7%`
——漏报由 `render_gate.mjs` 兜住，见上表。

> 分母与上表的 763 / 29 略有出入（762 / 30），是因为上表的渲染真值来自更早一次
> 基线，判定比现在的 `render_gate.mjs` 粗一档：它漏掉了《线性代数》1.6.3 那一节
> ——矩阵渲染正常但 `A \xrightarrow{...}` 连接符以字面反斜杠命令显示，人工核对过
> 确实是缺陷。**以本链路重跑的数字为准**，结论（0.52% / ~97%）不变。

**这是硬规矩**：动发布判据前先出误报率数字。Gap B1 挂了六天就是因为没有这个数。

## 打印态验收怎么跑

教案/课程要「教师能直接打印上课」时用：

```bash
# 课程正文，屏幕 + 打印两态，中英 × 桌面/移动四场景
PLAYWRIGHT_MODULE=/home/ubuntu/verify-mermaid/node_modules/playwright \
  node scripts/course_visual_acceptance.mjs \
  --course backend/data/courses/<id>.json --print \
  --out docs/验收/课程呈现

# 只抽含公式的节（打印验收关心公式，抽最长的节可能一条公式都没有）
  ... --print-only --math-first --nodes 6

# 对着已跑起来的页面判定，不需要改被测组件
  --url http://127.0.0.1:5173/<页面> --selector .lesson-dossier --print
```

打印态的两个失败码**修法完全不同，不要混**：

| 码 | 成因 | 改哪里 |
|---|---|---|
| `print:math_not_rendered` | 屏幕态就没渲染 | 内容 / 组件绑定。**改打印 CSS 无效** |
| `print:math_hidden_in_print` | 屏幕正常、打印态消失 | `@media print` 的可见性反选。**改内容无效** |

已验证的地基：`body * { visibility:hidden }` 加 `.根容器, .根容器 *`
的反选**能穿透 KaTeX 的嵌套 span**（384 次判定无一例外）。所以再出现
「打印态公式消失」，是那份打印样式漏了 ` *` 后代，不是这个写法做不到。

## ⚠️ 三条边界（不要外推）

1. **打印由 `window.print()` + CSS 实现，没有 PDF 导出管线。**
   关卡用 `page.emulateMedia({media:'print'})` 让 Chromium 按打印样式重算布局，
   等价于**打印预览的样式计算**，**不等价于任何 PDF 导出器的输出**。
2. **只在 Chromium 上验证过。** Firefox / Safari 的分页行为与 `visibility`
   反选语义**未测**，本文所有打印结论对它们**不成立**。
3. 关卡判定的是**可观察的呈现结果**（公式在不在、可不可见、有没有溢出），
   **不判定教学语义**。内容讲得对不对，需要教研人看。

## 已知不做的事（连同理由，避免有人重做一遍）

**缺空行的 `$$` 不自动补空行。** 全语料 1160 处、涉及 243 节，实测过：

- 三种嵌套场景（列表 / 引用块 / 表格）误报率**全部 0%**——我原先的顾虑不成立；
- 但**会把 2 个本来渲染完全干净的节点改坏**（被吞正文 0 → 597 字、0 → 105 字），
  新增误伤率 1.00%；
- 净账是干净节点 +5、代价 −2 节健康内容，**不值得**；
- 「只改嵌套、不碰纯段落」的折中方案也实测否掉了：误报 0%，但**改善也是 0**。

**替代方案**：上游提示词约束（块级公式前后留空行），零副作用；
下游由 `render_gate.mjs` 兜底。

## 建议给生成侧的提示词约束（归 lz-course-gen）

按实测的缺陷频率排序：

1. 块级环境（`cases`/`aligned`/`bmatrix`/`pmatrix`/`array`…）必须与其前缀写在
   **同一组** `$$…$$` 内，中途不得插入 `$$`；
2. 不得出现空的块级围栏（`$$\n$$` 或 `$$ $$`）；
3. 块级公式前后各留一个空行；
4. 块级公式内部不得出现 `$`。

第 1、2 条下游已有确定性兜底；第 3、4 条只能在生成侧解决。

## 写探针 / 改判据时的四条自查项

完整版见 `2026-08-17-打印态呈现验收关卡.md` 的方法论一节，这里只列标题
——**这四条每一条都对应一次我实际报错的假缺陷**：

1. 探针必须复刻真实应用的样式与脚本加载链（漏 `katex.min.css` → 测出 6400px 假溢出）；
2. 断言 `MarkdownRenderer` 的 DOM 必须等一帧（`scheduleUpdate` 对齐 rAF）；
3. 探针自己的传参、端口、状态隔离同样要验证（URL 传正文 → HTTP 431）；
4. 判据的正则要排除代码块（课程正文里到处是代码块）。

**一句总结**：测出「严重缺陷」时，先怀疑探针，再怀疑被测对象。
