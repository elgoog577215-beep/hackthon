# 打印态呈现验收关卡（`--print`）

> 2026-08-17，分支 `dev/lz-assess-ux`。
> 建在 `scripts/course_visual_acceptance.mjs` 里，**通过读取被测页面判定，
> 不需要改被测组件**。

## 为什么需要它

lz-lesson-plan 的结构化教案统一模板，验收标准是「教师能直接打印上课」。
打印态的公式渲染坏掉，那条验收就过不了——但在此之前，没有任何东西能自动判定
这件事。这道关卡就是那个判据。

呈现层归 lz-lesson-plan 维护，判据归这里。两边不冲突：关卡用 `--url` 对着一个
已经跑起来的页面测量，被测组件一个字都不用改。

## 边界（**不要外推**）

这三条写在脚本头、写进每一份 RESULT.md，这里再说一次：

1. **打印由 `window.print()` + CSS 实现，没有 PDF 导出管线。**
   本关卡用 `page.emulateMedia({media:'print'})` 让真实 Chromium 按打印样式重算
   布局，等价于**打印预览的样式计算**，不等价于任何 PDF 导出器的输出。
2. **只在 Chromium 上验证过。** Firefox / Safari 的分页行为与 `visibility` 反选
   语义未测，本文所有结论对它们**不成立**。
3. 关卡判定的是**可观察的呈现结果**（公式在不在、可不可见、有没有溢出），
   不判定教学语义。

## 地基结论：`body *` 反选能穿透 KaTeX 的嵌套 span

这是后面所有打印相关判断的前提，单独拎出来说明，因为它此前是未知数。

KaTeX 的产物不是一个元素，而是一棵深层嵌套的 `span` 树（`.katex` >
`.katex-html` > `.base` > `.mord` > `.mfrac` …），外加一份供读屏使用的
MathML 副本。教案的打印样式用的是这个经典写法：

```css
@media print {
  body * { visibility:hidden !important; }
  .lesson-dossier, .lesson-dossier * { visibility:visible !important; }
}
```

**问题是：`.lesson-dossier *` 这个后代选择器能不能覆盖到 KaTeX 深处的每一个
span？** 如果不能，公式会在打印时整体消失，而屏幕上一切正常——这是最难自查的
一类缺陷。

**实测结论：能。** 真实 Chromium 下，`emulateMedia({media:'print'})` 后
3 个公式（行内 `\det(A)\neq 0`、分数 `\frac{1}{\sqrt{2}}`、display 公式）
`katexVisible` 全部保持 3/3，同时应用外壳 `visibility` 正确变为 `hidden`。
截图确认排版正确、分数线宽 18px。

**推论**：以后再出现「打印态公式不见了」，**不是这个写法做不到，是那份具体的
打印样式写漏了**——最常见的是只反选了根容器、忘了 ` *` 后代。关卡的
`print:math_hidden_in_print` 就是报这个。

## 两个失败码必须分开：修法完全不同

同一个现象——「打印稿上没有公式」——有两个完全不同的成因。混成一个码会让人
去修错的地方，所以关卡把它们判成互斥的两类：

| 错误码 | 判定条件 | 成因 | 该改哪里 |
|---|---|---|---|
| `print:math_not_rendered` | **屏幕态**就没有 KaTeX 节点（或退化成 `math-fallback`），却读得到字面 `$...$` | 内容或渲染链的问题：公式语法错，或该字段根本没接 `MarkdownRenderer` | 内容 / 组件绑定。**改打印 CSS 没有任何用** |
| `print:math_hidden_in_print` | 屏幕态可见 N 个公式，切到 print 后少于 N | 打印样式的可见性反选没覆盖 KaTeX 嵌套 span | `@media print` 里的选择器。**改内容没有任何用** |

其余的码：`print:katex_error`（屏幕态就有 KaTeX 报错节点）、
`print:literal_latex`（打印稿上出现字面 LaTeX）、
`print:horizontal_overflow`（打印态横向溢出，纸上会被裁掉）、
`print:js_error`。

### 关卡确实能区分——用两个反例验证过

不能只验证「通过」，那证明不了判据有效。所以造了两个只在成因上不同、
症状相同的页面：

| 反例 | 构造 | 关卡输出 |
|---|---|---|
| 公式从未渲染 | 字段按纯文本绑定（**就是教案模板今天的状态**） | `print:math_not_rendered` ×4、`print:literal_latex` ×4 |
| 渲染了但被藏掉 | 真 KaTeX 渲染 + 打印样式**只反选根容器、漏掉 ` *`** | `print:math_hidden_in_print` ×4 |

两者互不串扰，且健康页面（`demo-matrix-growth-v2`）在同一关卡下四场景全过。

## 第一次真实使用：8 门真实课程的打印态实测

关卡的价值不能靠"能跑"证明，要靠"跑出了什么"证明。这是它的第一次真实使用。

**语料**：git 历史里的 8 门真实生成课程（`scripts/build_render_corpus.py` 可重建）。
**抽样口径**：`--math-first --nodes 6`——**只抽含公式的节，按篇幅取前 6 节**。
打印态验收关心的是公式，抽"最长的几节"可能一条公式都没有，那样的"通过"
什么也没证明。
**规模**：8 门课 × 6 节 × 4 场景 × 2 媒体 = 384 次判定，384 张截图。

| 其中「公式没渲染」`print:math_not_rendered` | **8 节全部** |
| 其中「渲染了但打印态被隐藏」`print:math_hidden_in_print` | **0** |

按课程：

| 课程 | 通过 | 打印态错误码 |
|---|---|---|
| 《辩论：逻辑构建与实战技巧》 | 6/6 | — |
| 《哲学：从古典到当代的系统性思维训练》 | 6/6 | — |
| 《机器学习：原理、算法与实践》 | 6/6 | — |
| 《经典力学：理论框架与工程应用》 | 6/6 | — |
| 《Python 高级编程》 | 6/6 | — |
| 《线性代数：理论与应用》 | 5/6 | `math_not_rendered` |
| 《高等代数：从结构到应用的数学基石》 | **3/6** | `math_not_rendered`、`literal_latex` |
| 《量子力学：从波函数到量子纠缠的系统化理解》 | **2/6** | `math_not_rendered`、`literal_latex` |

### 结论一：问题全在内容，不在打印样式

**8 个有问题的节全部是 `print:math_not_rendered`，`math_hidden_in_print`
一个都没有。** 这正是把两个码分开的价值——它一次就把责任判清楚了：

- 这些节**在屏幕上就已经坏了**，打印只是如实地把坏的东西印出来；
- **改打印 CSS 一行都不用动**。要修的是内容/生成链。

同时这也从反面再次确认了地基结论：真实课程里没有出现任何"屏幕好、打印丢"
的情况，`body *` 反选在 384 次判定中始终有效。

### 结论二：与 `render_gate.mjs` 交叉验证一致

打印关卡（真实 Chromium + 打印媒体）与 `render_gate.mjs`（jsdom + 真实 KaTeX）
是两条独立实现。在量子力学课上，两者标记的**节点与公式数完全吻合**：
1.3 线性算子（6 处）、1.9 算子代数（2 处）、2.2 薛定谔方程（3 处）、
2.4 无限深势阱（12 处）。两个独立工具得出同一结论，说明这不是某一方的
测量偏差。

### 结论三：根因是同一种构造，详见下一节的归因

8 个失败节点不是八个各自的毛病，而是**同一种「块级公式围栏被拆开」的构造**，
逐节点的最小复现片段、全量统计与归属判断见下一节。

**人工看过截图确认严重程度**：以《量子力学》1.3 为例，该节 38 个公式正常渲染、
6 个坏掉，坏掉的部分在打印稿上是整段 `\det(A) = \sum_{\sigma}...`、
`X|0\rangle = |1\rangle` 以及**整块 mermaid 源码**，夹在正常排版的正文中间。
教师直接打印带进教室的话，这几页是不能用的。

### 边界（同前，不要外推）

这 48 节的结论仅适用于：`window.print()` + CSS 的打印路径、Chromium、
本次抽样的含公式节点。**没有 PDF 导出管线**；其余节点、其余浏览器未测。
抽样是"含公式且最长的 6 节"，因此**这个 83.3% 不是全课程的通过率**——
它是「最可能出问题的那批节点」的通过率，全量通过率会更高。

## 8 个失败节点的归因：**同一种构造，不是八个各自的毛病**

40/48 已经说明关卡能用；这一节回答更要紧的问题——**坏掉的那 8 个为什么坏**。
归因决定修法归属：集中在少数构造 → 生成侧提示词该约束；分散随机 → 渲染或
清洗环节的问题。

### 结论：8/8 全部是同一种构造——「块级公式围栏被拆开」

不是靠肉眼看正文猜的。`render-diagnostics.ts` 在 KaTeX 抛错时会记下**失败的
那段源码**，用它反查每个节点，得到的形态高度一致：

```
$$
V(x) =            ← 前缀自己闭合成一个空的 $$ 块
$$
\begin{cases}     ← 环境被孤立在下一块，没有前缀
...
\end{cases}
$$

$$                ← 尾部还多出一个空块
```

模型想写的是一个公式 `V(x) = \begin{cases}...\end{cases}`，实际写成了
**「一个只有前缀的空块」+「一个孤立的环境块」+「一个多余的空块」**。

**8 个节点全部命中，共 27 处**，涉及的环境高度集中：

| 环境 | 处数 |
|---|---|
| `bmatrix` | 14 |
| `cases` | 5 |
| `array` | 4 |
| `pmatrix` | 3 |
| `vmatrix` | 1 |

**全部是矩阵类与分段函数类环境**，没有一个例外。没有出现「双上标」
「\left\right 不配对」「\text 里混中点」这些零散的语法错误——最初我按这些
维度做分类器，结果 36/42 落进 `other`，那正是分类器错了，不是构造分散。

### 每个节点的最小复现片段

| 课程 | 节点 | 拆分处数 | 典型前缀 → 环境 |
|---|---|---|---|
| 量子力学 | 1.3 线性算子与矩阵表示 | 4 | `A|\psi\rangle \leftrightarrow` → `bmatrix` |
| 量子力学 | 1.9 算子代数与对易关系 | 3 | `\sigma_x =` → `pmatrix` |
| 量子力学 | 2.2 薛定谔方程的建立与物理背景 | 1 | `V(x) =` → `cases` |
| 量子力学 | 2.4 一维无限深势阱问题的解析解 | 1 | `V(x) =` → `cases` |
| 高等代数 | 3.2 行列式的计算方法与性质 | 4 | `A =` → `bmatrix`；`\det(A) = 1 \cdot` → `vmatrix` |
| 高等代数 | 3.3 特征值与特征向量 | 4 | `\det(A - \lambda I) = \det\left(` → `bmatrix` |
| 高等代数 | 6.1 高斯消元与行阶梯形式 | 7 | `R_1 \rightarrow \frac{1}{2}R_1 \Rightarrow \left[` → `array` |
| 线性代数 | 1.7.6 齐次线性方程组解空间的秩与结构 | 3 | `\mathbf{x} = s` → `bmatrix` |

### 为什么它比看上去更严重：**它会吞掉后面的正文**

受控对照实验（同一段内容，只差一个空 `$$` 对）：

| | `$$` 计数 | 偶数？ | KaTeX | 退化 | `## 标题` 幸存 |
|---|---|---|---|---|---|
| 带空 `$$` 对 | 4 | 是 | 1 | **1** | **否** |
| 不带 | 2 | 是 | 2 | 0 | 是 |

多出来的空 `$$` 对**开启了一个没有闭合的数学块**，把后续正文连同
`## 深度原理` 标题一起吸进公式里。所以打印稿上看到的不只是几个公式变源码，
而是**整段正文加标题一起塌掉**——这就是截图里那些夹在正常排版中间的
`\det(A) = \sum_\sigma...` 和整块 mermaid 源码的来源。

### 全量统计：这个构造是失败的主因

在全部 792 节上交叉验证：

| | 渲染坏 | 渲染好 | 失败率 |
|---|---|---|---|
| **含围栏拆分** | 24 | 15 | **61.5%** |
| 不含 | 5 | 748 | **0.67%** |

- **覆盖率 82.8%**：29 个渲染失败节点里，24 个含这个构造。
- **提升 92 倍**：含此构造的节点失败率是不含的 92 倍。
- 剩下 5 个失败节点不含此构造，是零散的语法问题
  （`\omega^0^2` 双上标、`\left{...\right$}` 转义不配对等），**没有共同模式**。

### 归属判断：**生成侧，归 lz-course-gen**

理由是三条实测，不是推断：

1. **构造高度集中**——8/8 节点、27 处，全是矩阵/分段函数环境的同一种拆分。
   这是提示词层面能约束的事（「块级环境必须与其前缀写在同一组 `$$` 内」），
   不是渲染器该去猜的事。
2. **渲染侧已经尽力了**——`markdown.ts` 的 `normalizeLegacyDisplayShells` 等
   四个归一化函数就是在救这类形态，且**救回了 15 个**（含此构造但渲染正常的
   那 15 节）。剩下 24 个是归一化覆盖不到的变体。继续在渲染侧加正则是打地鼠：
   我自己写过一版「最小修复」正则，结果 8 个节点里只有 2 个改善、
   0 个完全修好，还有 3 个变得更糟（`2.4` 的退化数从 12 涨到 18）。
   **这条失败的尝试本身就是证据**：这个问题在下游修不干净。
3. **上游修一次，下游全好**——受控实验里，只要前缀与环境写在同一组 `$$` 内，
   渲染完全正常。

### 但有一件事落在我这边：**当前质量门把它判成了 warning**

拿这个构造回测今天的 `course_quality.py`，它命中的是
`repairable_display_environment`（**warning，不阻断发布**）。

那个降级是我上一轮做的，依据是「渲染器能修复它」。**现在的证据说明那个判断
过宽**：受控实验证明这个变体渲染器修不好，还会吞掉标题。61.5% 的失败率也
不该只给一个 warning。

**待办（我这边）**：把 `repairable_display_environment` 拆细——
「前缀与环境之间隔着 `$$`（即产生空 `$$` 对）」这个子形态应恢复为 `critical`；
真正能被归一化救回的形态才保留 warning。**这条我没有顺手改**，因为它会改变
发布门的阻断行为，需要按 F-1a 的标准重新测一遍误报率再动——不能凭一次受控
实验就调发布判据。

## 确定性形状修复的结果：40/48 → 41/48，但这不是正确的度量

归因结论是「同一种确定性的形状问题」，所以修法也做成确定性的：
`backend/canonical_content_repair.py` 的 `repair_display_math_shape()`
把被 `$$` 拆开的块级公式合并回一个完整块、丢弃多余空块。不调用模型，
不碰生成侧提示词。

用同一道关卡在同一批课程上重跑：

| | 修复前 | 修复后 |
|---|---|---|
| 通过 | 40/48 | **41/48** |
| `print:math_not_rendered` | 32 | 28 |
| `print:literal_latex` | 8 | 4 |

**这个数字比预期低，不该被包装成成功。** 但「节点通过率」不是这次修复的正确
度量——一个节点只要还剩一处公式退化就仍算失败，哪怕它已经从「吞掉整段正文」
变成「一个公式不好看」。

按**内容丢失量**度量，效果才显出来：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 被吞进公式的中文字数 | 2492 | **1008（−60%）** |
| 围栏拆分形态 | 27 处 | **0 处** |
| 空 `$$` 对 | 22 处 | **1 处** |

最直观的是标题恢复——标题被吞是内容丢失的硬证据：
《量子力学》2.4 从 12 个标题只剩 2 个，恢复到 8 个；2.2 从 8 个恢复到 13 个。

**没修好的是什么**：剩下 28 处退化经抽查**不是**围栏拆分，而是同一节点里
另外独立的缺陷（`\omega^0^2` 双上标、`\left{...\right$}` 转义不配对这类），
没有共同形状，确定性修复救不了。

**由此更正一处措辞**：82.8% 是「失败节点中含此构造的比例」，
**不是「修完就能过」的比例**——一个节点往往同时带着别的毛病。这两个数上一轮
没有分清。

## 方法论：写浏览器探针的四条强制自查项

在四条自查项之前，先记两条**关于「验收本身该怎么做」的判断**，它们比具体技巧
更上位：

### 零之一、关卡的价值不能靠「能跑」证明，要靠「跑出了什么」证明

一个只会通过的关卡和没有关卡是一回事。所以每道关卡至少要做到两件事：

1. **用反例证明它能报错**——本文那两个反例（纯文本绑定 / 打印样式漏掉 ` *`）
   就是为此存在的；只跑健康用例，等于没验证判据。
2. **拿去真实数据上跑，并如实报出跑到了什么**——8 门课 48 节跑出 8 个失败，
   再顺着失败做归因，才说明这道关卡值这份工。

推论：**报告里「全部通过」应当引起警惕，而不是让人放心**——先问「它在什么
情况下会报错？我验证过吗？」本轮就抓到过一次伪装成「全部通过」的探针 bug
（见自查项三）。

### 零之二、抽样要按「判据关心什么」抽，不是按「哪个最大」抽

打印态验收关心的是公式。最初的抽样口径是「最长的 N 节」，但最长的节可能一条
公式都没有——那样跑出来的「通过」什么也没证明。改成 `--math-first`
（**只抽含公式的节**，再按篇幅排序）之后，样本才落在判据真正管辖的范围内。

代价要一并说清：这样得到的 83.3% **不是全课程通过率**，而是「最可能出问题的
那批节点」的通过率。**抽样口径必须和结论一起写**，否则读者会把一个刻意选难的
样本当成整体水平。

### 一、探针必须复刻真实应用的样式与脚本加载链

**症状**：探针测出一个看起来很严重、但实际不存在的缺陷。

**我因此两次报出假缺陷：**

| # | 漏了什么 | 假缺陷 | 补上后 |
|---|---|---|---|
| 1 | `katex/dist/katex.min.css`（真实应用在 `frontend/src/main.ts:9` 加载） | `.mfrac` 失去布局规则，整页横向溢出 **6400px** | `docScrollWidth` 1024，分数线 18px |
| 2 | `@container lesson-plan` 容器（由 `GenerationLessonPlan.vue` 声明） | 窄屏规则永不命中，整页横向滚动 **514px** | 390px，只剩表格裁切 |

两次是同一个病：**探针没有复刻真实的渲染上下文**。挂载一个组件不等于复现它
在应用里的环境——它依赖的全局样式、父级容器、CSS 变量、插件注册，缺一样就
可能测出别的东西。

**操作方法**（写探针之前做，不是出问题之后做）：

1. `grep` 一遍 `frontend/src/main.ts` 的 import，逐条判断哪些是被测组件需要的；
2. 看被测组件的 CSS 里有没有 `@container` / `@media` / CSS 变量，
   往上找是谁声明的容器与变量，在探针里复现；
3. 断言前先渲染一次"已知正确"的内容，确认探针本身能得出正确结论。

**最重要的一条经验**：**测出"严重缺陷"时，先怀疑探针，再怀疑被测对象。**
6400px 的横向溢出、整页滚动这类夸张数字，通常是探针缺了什么，而不是产品真的
坏成那样。产品的真实缺陷往往是"少了一列""公式变成源码"这种更朴素的形态。

### 二、断言 `MarkdownRenderer` 的 DOM 必须等帧

`MarkdownRenderer.vue` 的 `scheduleUpdate` 把渲染对齐到
`requestAnimationFrame`（为流式输出合帧，实测 877 chunk / 6s）。因此**只等
`flushPromises` 会在渲染发生之前就断言**，看到空 DOM，报出「公式没渲染」的
假失败。

实测同一次挂载：只 `flushPromises` 得到 `0` 个 `.katex`，等一帧后得到 `1` 个，
且源码未泄漏——**KaTeX 全程都是好的**。

```ts
await new Promise(resolve => requestAnimationFrame(() => resolve(null)))
await flushPromises()
```

仓库里 `markdown-renderer.test.ts` 那条「块公式渲染为 KaTeX」用例就是因此长期
假失败的，已按上述写法修正。关卡与探针 HTML 均等两帧后才置 `data-ready="1"`。

### 三、探针自己的传参与隔离也会造出假缺陷

第一次真实批量运行时，8 门课里有课程在第 2 节就「渲染卡住」（`data-ready`
永不出现，20s 超时）。看上去像真实课程正文把渲染器打挂了。抓到浏览器控制台
才知道是**探针自己的 bug**：

| 症状 | 真实原因 | 修法 |
|---|---|---|
| 第 2 节起 `data-ready` 超时 | 正文经 URL query 传入，2796 字的正文 URL-encode 后**超出 HTTP 头长度上限，服务器回 431**，页面根本没执行 | 改用 `page.addInitScript` 注入全局，不走 query |
| 端口冲突导致整门课「验收失败」 | `strictPort:true` 固定 5197，前一次残留或并发实例直接撞死 | `port:0` 自动选端口，从 `server.config` 回读 |
| 后续节点可能读到第一节的正文 | `addInitScript` 是**累加**的，复用同一张页面时先注册的先执行、先赋值 | 每节 `context.newPage()`，用完即关 |

第三条尤其危险：它不会报错，只会让每一节测出**一模一样**的结果，看起来像
「全部通过」。验证方法是看逐节点数字**是否真的不同**——修好后同一门课三节
分别得到 katex=6/3/4，确认没有串味。

**归纳**：前两条自查项讲的是「探针要复刻真实环境」，这条讲的是「探针自己的
传参、端口、状态隔离同样要验证」。**任何一次"被测对象坏了"的结论，都要先排除
探针自身。**

### 四、判据的正则要排除代码块

Python 高级编程课一度被报 `print:literal_latex`，读到的"公式"是 `$"), "$`。
查证是**代码块里的字符串字面量**：`reverse_string("1234!@#$")` 到
`"$#@!4321"` 之间被 `$...$` 跨越匹配。修法是取字面 LaTeX 前先剔除
`pre / code / .mermaid` 的可见文本。修完该课从 5/6 变成 **6/6**——那是它唯一
的"缺陷"，纯属正则误伤。

**推广**：任何"在正文里找标记"的判据，都要先问"代码块里会不会有同样的字符"。
课程正文里恰恰**到处都是代码块**。

**本轮四次「先怀疑探针」全部奏效**：katex.min.css 缺失（6400px）、
容器查询缺失（514px）、URL 传参 431、代码块误匹配。**四次都是探针的问题，
没有一次是被测对象真的坏成那样。**

## 怎么跑

```bash
# 课程正文：屏幕 + 打印两态，中英 × 桌面/移动
PLAYWRIGHT_MODULE=/home/ubuntu/verify-mermaid/node_modules/playwright \
  node scripts/course_visual_acceptance.mjs \
  --course backend/data/courses/<id>.json --print \
  --out docs/验收/课程呈现

# 对着已跑起来的页面判定（不改被测组件）——统一模板进 main 后这样跑：
PLAYWRIGHT_MODULE=... node scripts/course_visual_acceptance.mjs \
  --url http://127.0.0.1:5173/<教案页面地址> \
  --selector .lesson-dossier --print \
  --out docs/验收/教案打印
```

`--selector` 给被测内容的根容器（教案是 `.lesson-dossier`）。
任何一条判据失败即退出非零，可直接作为发布前关卡。
