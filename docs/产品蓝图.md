## 1. 产品定义

### 1.1 产品定位

灵知是一套以结构化课程为核心，连接教师课程生产、统一学习现场、学习证据驱动的课程生长，并能从同一课程语义编译多种教学表达的 AI 课程系统。

它不是一次性课程生成器，也不是把聊天、题库、笔记和 PPT 拼在一起的工具箱。它要让一个真实学习目标形成可长期运行的闭环：

```text
目标、资料与学习起点
-> 结构化当前课程
-> 教案、讲稿、练习、PPT 与图解等同源教学产物
-> 阅读、提问、笔记、作答与项目表现
-> 有来源、有知识坐标的学习证据
-> 可反驳的教学判断与课程调整候选
-> 用户审阅并确认
-> 当前课程及受影响产物安全更新
-> 独立任务验证调整效果
-> 新证据进入下一轮课程生长
```

### 1.2 核心用户与任务

灵知服务两个围绕同一课程真源协作的角色：

- 课程创建者和教师：从目标、资料与教学约束创建课程，审阅并修改大纲、教案、讲稿、题库和 PPT，安全发布并继续修订。
- 学习者：围绕真实目标进行系统学习、项目实战、问题探究或考试准备，在同一现场阅读、练习、提问、记录并获得可解释的课程调整。

两类角色共享同一个课程身份和正式课程，但权限、入口与任务不同。灵知不扩张为班级管理、多人协作或学校文件管理平台。

产品必须闭合四类连续任务：

1. 从目标、资料和教学约束得到一门结构清楚、可审阅、可恢复的课程。
2. 让教师持续编辑各类教学产物，并看见上游修改对下游的真实影响。
3. 让学习者在同一现场完成阅读、练习、提问、记录和项目，不在工具之间搬运上下文。
4. 让课程依据真实学习证据安全调整，并用独立结果判断调整是否有效。

### 1.3 产品北极星

唯一北极星是**可验证学习闭环完成率**：

```text
有来源证据、形成正式课程修订并获得独立效果结果的已接受调整数
/
全部已接受课程调整数
```

生成数量、AI 对话数量、课程时长、PPT 页数和页面访问量只能解释过程，不能证明学习闭环成立。

### 1.4 产品范围

- 不做 LMS、班级管理、多人协作、课程商城、内容广场或社交网络。
- 不新增与课程库、课程工作区、AI 老师平行的顶层功能中心。
- 不让用户管理内部版本树，不建立长期覆盖正式课程的个人 Overlay。
- 不让 Agent 绕过证据、用户确认和正式命令直接改写课程。
- 不先做自由视频、数字人或 Skill 市场，再倒推课程语义。
- 不用单门样板课程、一次模型成功或局部测试代替跨学科与长期效果验证。

## 2. 教学体系设计

教学体系设计定义“灵知生产和服务的教育对象是什么、有哪些类型、怎样才算专业”。页面、Prompt 和代码只能实现这些定义，不能临时替代它们。

### 2.1 课程教学层级

教师课程生产统一使用以下层级：

```text
课程
├── 章：组织整门课知识与任务的结构单位
│   └── 讲（LessonUnit）：备课、授课、资料作用域、失败恢复和版本边界
│       └── 讲内小节：本讲内容的编辑和呈现单位
│           └── 教学块：课堂中实际发生的教学环节
```

一章可以安排多讲，一讲可以覆盖一个或多个知识小节。课程大纲决定“整门课讲什么以及怎样展开”；教学日历决定“何时、何地、由谁上”；本讲课型和教学块决定“一讲怎样组织”；教案、讲稿、练习和 PPT 分别承担不同教学职责。

现有代码或历史数据把章、讲和小节折叠时，只能通过兼容投影读取；新产品定义不得继续混用这些身份。

### 2.2 教学分类体系

| 分类 | 回答的问题 | 正式类型 | 控制方式 |
| --- | --- | --- | --- |
| 课程类别 | 这门课在教务上属于什么 | 通识必修、专业基础等行政属性 | 教师填写，不参与教学编排 |
| 教学类型 | 整门课默认怎样组织 | 系统学习、项目实战、问题探究、考试冲刺 | 一门课一个主要类型，教师可修改 |
| 学科类型 | 知识主要通过什么专业行为成立 | 通用、数学、编程工程、自然科学、生命医学、人文社科、语言、商业职业 | AI 可识别，教师可修改 |
| 学科细分 | 同类学科中的专业差异是什么 | 由学科类型下的稳定分型定义 | AI 推荐，教师可修改 |
| 本讲课型 | 当前一讲具体怎样上 | 理论讲授、实践操作、理论与实践、案例研讨、实验探究、项目工作坊、复习测评 | 每讲推荐一个，教师可更换 |
| 教学块 | 课堂按什么顺序发生哪些环节 | 通用块与学科专业块 | 可增删、排序、改时长和内容 |

这些分类不是同义词，也不能互相覆盖：

- 教学类型提供整门课的组织逻辑和课型分布倾向，不把所有讲锁成同一种课型。
- 学科类型与学科细分规定解释、证明、实践和评价应遵守的专业方法。
- 本讲课型把整课倾向与当前目标、资料和课时结合，形成一讲的组织方式。
- 教学块是最终进入教案和课堂的实际环节。

本讲课型应由“教学类型 + 学科类型/细分 + 本讲目标 + 学时 + 资料条件”共同决定，再据此组合默认教学块。内部细课型、模块注册表和生成模板只服务推荐与编译，不应成为教师必须理解的平行分类。

### 2.3 教学产物及其职责

| 教学产物 | 核心职责 | 主要依据 | 不应承担 |
| --- | --- | --- | --- |
| 课程大纲 | 定义课程定位、目标、边界、章节与讲次结构、先修关系和达成方式 | 教学类型、学科类型、课程目标、资料和规模 | 逐分钟课堂调度、完整讲述内容 |
| 教学日历 | 安排讲次的时间、地点、人员和进度 | 已确认大纲与实际排课条件 | 改写课程知识结构 |
| 全课教学设计 | 统一课程定位、对象、目标、策略、评价和章节责任 | 大纲、课程知识与教学约束 | 成为第二份课程正文 |
| 分讲教案 | 规定本讲怎样教：课型、目标、重难点、教学块、师生活动、时间、检查和作业 | 已确认大纲、全课设计、资料与本讲编排 | 代替完整授课内容 |
| 分讲讲稿 | 按已确认教案和教学块展开教师可直接使用、可逐块编辑的完整授课内容 | 已确认教案、课程知识和选定资料 | 重新选择课型、独立改变课程结构、退化为教材目录 |
| 正式题库 | 保存整门课可审阅、可版本化、可复用的正式题目与解答合同 | 目标、课程知识、资料和明确出题意图 | 成为课程生产的强制前置步骤 |
| 分讲练习与试卷 | 在明确范围内检查学习成果；试卷固定引用组卷时的题目修订 | 正式题库、当前教学范围与评价目标 | 复制题干答案形成第二题库 |
| PPT | 把已确认讲稿编译成学生可见画布和教师备注的同源教学表达 | 已确认讲稿、教案追溯和表现模板 | 在渲染阶段重新发明知识或教学结构 |
| 配套文档 | 处理评分细则、自查清单等学校提交、学生说明或归档材料 | 正式课程信息与真实学校模板 | 承担课堂教学主链 |

所有产物都必须区分输入、工作稿、已确认修订和导出投影。上传只表示原件已保存，模型生成只形成工作稿；只有教师导入、采纳或确认后才进入正式体系。

### 2.4 教学块体系

通用教学块包括：

- 课前准备、情境/问题/案例导入、目标说明。
- 概念/原理/要点讲解、过程推导、例题/案例分析、教师或专家示范。
- 独立思考、讨论研讨、练习实践、实验项目、课堂提问。
- 即时检查、巡视指导、成果展示、同伴互评、教师点评、纠错补充。
- 归纳总结、知识迁移、反思复盘和作业布置。

数学证明、代码调试、实验设计、材料辨析、情境对话、案例决策等专业块只在相关学科中出现。每个教学块至少说明：

- 名称、目的、顺序和计划时长。
- 所服务的目标、知识与难点。
- 教师活动、学生活动、资料工具与预期产出。
- 检查方式、反馈方式和必要备注。

同一种教学块在不同学科中的专业内容可以不同，但它在课堂中的责任必须稳定。前端显示的教学块使用教师能直接理解的课堂语言，内部模块名不直接暴露。

### 2.5 教学专业性标准

大纲、教案、讲稿、练习和 PPT 的专业性不能只靠“生成完整”判断，至少同时满足：

1. **目标一致**：产物服务已经确认的课程目标和本讲目标。
2. **学科成立**：解释、推理、证据、实践和评价符合当前学科的方法。
3. **结构衔接**：整课、章、讲、小节和教学块之间没有跳跃、重复或责任冲突。
4. **课堂可实施**：活动、时间、资料、教师动作和学生动作能够真实执行。
5. **成果可检查**：每个关键目标都有适当的学习产出与达成证据。
6. **来源可追溯**：指定资料、课程知识和生成内容之间可以回查。
7. **教师可控制**：系统建议可以采用、修改、拒绝和恢复，不自动成为正式结果。

模板和 Prompt 只能帮助实现这些标准，不能代替标准本身。不同学科和课型可以使用不同模板，但必须进入同一对象、关系和质量体系。

## 3. 产品逻辑设计

产品逻辑设计定义教学对象之间的组成、类型约束、派生组合、依赖状态和反馈演化。先生成什么只是其中一部分。

### 3.1 两条总控闭环

#### 结构化同源

结构化同源回答“同一门课程怎样产生一致的教学产物”：

```text
课程教学设计 + 课程知识
-> 正式课程
-> 教案 / 讲稿 / 练习 / PPT / 图解 / 讲义等同源产物
```

课程结构、知识身份和来源绑定共同约束所有产物。产物可以有自己的版式、编辑和确认状态，但不能脱离课程语义成为第二份课程正文。

#### 课程生长

课程生长回答“课程怎样依据真实教学与学习过程持续调整”：

```text
学习行为、记录与正式作答
-> 有来源的证据
-> 可反驳的教学判断
-> 范围受限的课程调整方案
-> 用户审阅与确认
-> 正式课程新修订
-> 受影响产物重新编译
-> 独立效果复验
```

AI 判断只是有依据的假设，不是学习事实。结构化同源保证修改后各类产物不漂移；课程生长保证修改来自真实证据，而不是随机生成。

### 3.2 对象关系与唯一真源

四个核心对象承担不同责任：

- `CourseDocument` 是当前正式课程的唯一语义容器，保存稳定课程身份、有序章节与内容块，以及目标、知识、来源和修订关系。
- `CourseBlock` 是正式课程正文中的最小稳定内容单元。`kind` 说明怎样呈现，`role` 说明承担什么教学作用；相同形式可以承担不同作用，相同作用也可以采用不同形式。
- `CourseTeachingPlan` 保存全课与分讲的教学设计责任，不成为第二份课程正文。
- `CourseKnowledgeBase` 保存当前课程实际教授的知识、能力、易错、掌握标准和精确教学绑定，不与跨课程学科知识库混为一谈。

课堂“教学块”与 `CourseBlock` 不是同一个对象：教学块描述一段课堂活动和师生行为，一个教学块可以编译出多个正式内容块；`CourseBlock` 描述最终课程内容怎样稳定保存和呈现，不能反过来代替课堂编排。

一件事实只能有一个拥有者，其他页面、文件、缓存和导出都是投影：

| 事实 | 唯一真源 | 允许的投影 | 禁止的平行真源 |
| --- | --- | --- | --- |
| 当前课程结构与正文 | `CourseDocument` | 目录、阅读正文、旧课程只读视图 | 完整 Markdown、页面本地课程副本 |
| 课程教学设计 | `CourseTeachingPlan` | 全课教案、分讲教案、生成约束 | 独立 Markdown 教案、课程蓝图副本 |
| 当前课程知识 | `CourseKnowledgeBase` | 知识图谱、标签、AI 上下文切片 | 跨课程知识身份、章节标题伪知识点 |
| 正式题目与试卷 | 版本化题库修订与题目修订引用 | 教师题库、练习、试卷 | 前端勾选状态、复制题干答案 |
| 正式作答 | `PracticeAttempt` | 错题本、练习反馈、掌握证据 | 本地完成状态、组件作答历史 |
| 学习行为事实 | `LearningEvent` | 进度、诊断输入、统计 | 节点本地已读状态 |
| 学习现场位置 | `LearningSnapshot` | 续学入口、滚动恢复 | 用快照代替学习事实 |
| 笔记与问答记录 | `LearningRecord` | 正文行内记录、记录总览 | 组件本地笔记库 |
| 当前学习者状态 | `LearnerModel` | 掌握、困难、偏好和策略投影 | 可独立写入的画像副本 |
| 课程调整建议 | `CourseEvolutionPlan` | 侧栏候选、审阅工作台、影响预览 | 每个入口一套候选状态 |
| 教学表达 | `TeachingRepresentation / RepresentationSet` | PPT、讲义、图解、音频等 | 独立漂移的第二课程正文 |

用户感知的是“当前正式结果 + 可撤销操作”，而不是底层版本树。历史修订用于追溯、冲突、撤销和效果比较，不成为顶层产品概念。

### 3.3 类型、派生与组合关系

```text
教学类型
× 学科类型与学科细分
× 课程和本讲目标
× 资料与实施条件
-> 本讲课型
-> 教学块组合
-> 分讲教案
-> 分讲讲稿
-> PPT 与练习等下游产物
```

关系规则必须满足：

- 上位类型提供约束和倾向，下位对象负责当前场景的具体决定。
- 教师明确选择优先于自动识别；自动识别必须可解释、可修改。
- 高层教学偏好只能在既有类型和学科约束内调节，不能反向污染学科判断或建立第二套分类。
- 稳定关系由产品规则表达，不能依赖模型临时从自然语言中猜测。
- 冲突时必须显示冲突对象、原因和可选处理，不静默覆盖任一已确认产物。

### 3.4 课程生产依赖

课程生产采用可跳转、但依赖清楚的五个入口：

```text
课程基础（大纲 / 教学日历）｜教案｜题库｜讲稿｜PPT
```

常见纵向路径是：

```text
课程目标与资料
-> 大纲章节骨架
-> 教师确认各章讲次规模
-> 完整大纲
-> 本讲课型与教学块
-> 分讲教案
-> 分讲讲稿
-> PPT
```

这条路径表达依赖，不是页面门禁：

- 教师可以跳过题库先制作讲稿或 PPT，也可以之后补题并把选中题目用于既有产物。
- 教学日历、题库、试卷和配套文档读取同一课程基线，但不是纵向链的强制步骤。
- 上游修改只让真正受影响的下游进入待复核、过期或重建，不整课重做。
- 课程规模只增加有界工作单元，不产生另一套生成协议。

### 3.5 状态与确认

所有生成和编辑统一遵循：

```text
输入或编排
-> 可见任务
-> 可恢复工作稿
-> 质量检查
-> 用户审阅
-> 正式确认
-> 下游影响与下一动作
```

生成完成、质量通过、教师确认和正式发布是不同状态。自动保存只保存工作现场，不等于正式应用。失败必须保留已完成单元和最后可用结果，只重试缺失或失败部分。

手工修改和 AI 修改都先形成候选。正式应用前必须说明：

- 修改了什么、依据是什么。
- 影响哪些对象，哪些保持不变。
- 是否存在冲突、过期、资料不足或质量阻断。
- 怎样拒绝、撤销、恢复或重新生成。

### 3.6 学习、练习与反馈

学习现场统一消费正式课程、课程知识和当前学习身份：

```text
正式课程 + 当前学习事实
-> 阅读、记录、练习与诊断
-> 新的正式学习事实
-> 可重算学习者状态
-> 当前进度、连续性与可解释行动
```

正式练习必须从教学目标和课程知识形成明确出题意图，公开题面与私有答案、量规、隐藏测试严格隔离。评分回答“是否达标”，诊断回答“答案表现出什么差距”；没有证据时不得反推学生未表达的思考过程。

原始事实、教学解释和正式状态严格分层：

```text
LearningEvent / LearningRecord / PracticeAttempt
-> EvidenceItem
-> AdaptationHypothesis
-> LearnerModel 或 CourseEvolutionPlan
```

单条明确强证据可以触发局部候选；范围越广，需要的独立一致证据越强。反证必须能够缩小或撤销判断。

### 3.7 内部职责分层

灵知内部继续使用“实体—功能—逻辑—AI”检查责任是否错位，但它只是产品内部职责视角，不是本文三个产品设计部分的平行框架：

| 内部职责 | 负责 | 不负责 |
| --- | --- | --- |
| 实体 | 保存课程、教案、知识、题目、学习事实、调整方案和教学表达等可追溯事实 | 为某个页面复制第二份事实 |
| 功能 | 围绕用户任务组合实体能力 | 独立拥有一套领域真源 |
| 逻辑 | 保存类型、派生、依赖、状态、证据和影响等稳定因果关系 | 把因果关系留给页面或 Prompt 临时判断 |
| AI | 完成结构、内容、解释和候选等语义工作 | 管理权限、版本、正式状态和用户确认 |

### 3.8 AI 与用户控制

AI 只承担确定性规则无法可靠完成的语义工作，例如结构与内容候选、资料理解、受约束的证据解释和局部重写。

- AI 回答、AI 建议、可审阅候选和正式动作必须区分。
- AI 可以主动提出改进，但不能替用户确认或扩大用户选择的范围。
- 正式动作必须进入统一影响分析、确认、正式命令和回执链。
- 模型不可用时，已有课程、练习、记录和最后可用产物继续可用。
- 涉及最新事实时读取可信时效资料，不能用模型记忆冒充证据。

## 4. 交互与界面设计

交互与界面设计把教学对象、产品关系、状态和动作翻译成用户能理解、能控制的界面。

### 4.1 界面表达原则

```text
对象 -> 合适的界面形态
关系 -> 布局、层级、导航和影响提示
状态 -> 反馈、差异和恢复入口
动作 -> 可预期、可撤销的控件
```

- 容器用于表达成组信息、独立状态、明确边界或可操作区域。
- 普通标题、说明和单行文字优先依靠位置、字号、颜色和留白建立层级，不为装饰增加边框和卡片。
- 正式内容优先以连续文档呈现；结构树、设置和建议只在任务需要时出现。
- 看起来可点击的元素必须可用；不可用时明确原因和恢复条件。
- 加载、空、成功、失败、冲突、过期、取消、恢复和只读降级都必须有真实状态。

### 4.2 产品空间

灵知只保留四类顶层任务空间：

1. **教师首页**：我的日历与我的课程。
2. **课程工作台**：课程生产、文件管理和正式课程预览。
3. **学习现场**：阅读、练习、记录、知识和学生 AI 老师。
4. **调整课程工作区**：分析影响、审阅候选、应用、撤销和复验。

PPT 等复杂表达使用从课程文件或工作台进入的专用工作区，不升级为平行顶层产品中心。

### 4.3 教师首页

教师首页在同一顶栏提供“我的日历 / 我的课程”：

- 我的日历由课程范围、教学日历和选中日期或课次状态组成。选择课程只改变日历投影，“进入课程”始终是独立动作。
- 我的课程是完整课程库，支持适合查找和管理的卡片或列表密度。
- 新建课程使用紧凑表单，课程名称是唯一必填项；创建后先得到空课程空间，再在课程基础中开始大纲生产。
- AI 新建与 Markdown 导入最终都进入同一个课程身份和课程对象。

### 4.4 课程工作台

课程工作台默认采用左、中、右三栏：

- 左栏：课程基础、教案、题库、讲稿、PPT 五个入口，以及课次和完成状态。
- 中栏：当前正式对象的表单、生成过程、工作稿、阅读、编辑、差异和确认。
- 右栏：当前对象的一个主来源、多份参考资料、联网来源和必要的 AI 协作。

左侧顺序表达常见备课路径，不伪装成全部强制门禁。中栏在同一位置完成“输入—生成—审阅—编辑—确认”，不为每个状态打开第二套页面。右栏始终服务当前阶段或当前讲次，不成为通用聊天中心。

每讲教案、讲稿和 PPT 共享上一讲、当前讲、下一讲导航。确认后主操作原位切换为常见下一动作，但教师仍可自由切换入口。

### 4.5 课程文件空间

课程文件按教师责任组织为：

```text
教务材料：学校提交、归档和制度性文档
课程逻辑文件：大纲、教案、讲稿-PPT、题库
辅助资料：老师题库、试卷、学生作业和其他原件
```

- 教务材料和课程逻辑文件可以投影同一正式修订，不复制底层内容。
- 上传原件只保存一次；正式对象保存主来源、参考资料和联网来源的关系。
- 单击文件夹进入，单击文件选中并更新详情，双击或明确主操作才打开、生成或编辑。
- 搜索覆盖整门课程并显示语义路径；无匹配项和空文件夹必须区分。
- 页面不提供泛化“新建”菜单。固定正式对象缺失时直接显示“未生成”，重复生成形成新修订而不是并列副本。

题库始终是一门课程唯一的正式题库。导入、AI 生成、审核、筛选和组卷都在同一题库工作台中完成；“组成试卷”是题库内部操作，不新增课程生产阶段。

### 4.6 学习现场

学习现场保持“左目录、中正文、右侧笔记或 AI、底部学习工具”的连续空间：

- 正式练习从正文对应位置或课程练习视图进入，关闭后回到原内容锚点。
- 桌面笔记在正文右侧展开；移动端使用全屏覆盖层，避免压缩正文。
- 错题本、复习、学习记录和知识图谱是正式领域事实的聚合视图，不建立各自的进度副本。
- 临时解释、反例、过渡和检查可以进入当前学习流，但不自动写入正式课程。

教师预览复用同一正式课程，但使用教师身份和明确的预览标识，不读取或写入学生数据。

### 4.7 调整课程

学生侧和教师侧都只保留一个“调整课程”概念。就近入口、AI 发起入口和独立工作区共享同一个服务端候选：

- 用户选择当前内容、当前讲次、相关后续或全课程范围。
- 单项局部变化可以原位审阅；跨对象或全课程变化进入完整工作区。
- 关闭、刷新或切换入口后恢复同一任务，不生成第二份候选。
- 用户选择的范围是硬边界，AI 不得扩大范围或替用户确认。

## 5. 产品边界、异常与演进

### 5.1 不可违反的边界

1. 一件事实只能有一个正式真源。
2. 教案、课程知识、正式题目、学习事实和教学表达各自拥有清楚边界。
3. 正式课程变化只能通过统一课程命令完成。
4. AI 输出、对话、笔记和自述不能直接成为掌握事实或正式课程内容。
5. 个性化只作用于当前课程，不跨课程共享运行时知识或学习结果。
6. 教学表达从课程派生，表达编辑与语义编辑必须分流。
7. 正式题面的公开内容与私有答案、量规和隐藏测试严格隔离。
8. 失败、降级、待审阅、质量通过、教师确认和正式发布必须区分。
9. 用户不需要理解内部版本树、Prompt 版本、模型调用策略和修订实现。
10. 旧链只能读取或迁移，不能继续生长新的写入规则。

### 5.2 异常与降级

| 场景 | 必须行为 | 禁止行为 |
| --- | --- | --- |
| 模型不可用 | 保留检查点、已完成单元和最后可用产物，提供恢复动作 | 清空整门课程、伪造 AI 成功 |
| 资料不足或冲突 | 标记缺口、降低置信度、请求补充或进入审阅 | 用模型常识冒充指定资料事实 |
| 课程修订冲突 | 重新定位候选或返回明确过期冲突 | 覆盖新修订、静默丢失修改 |
| 知识引用失效 | 阻止正式应用或进入知识维护候选 | 复制标题伪造知识 ID |
| 题目质量失败 | 隔离候选并保留当前有效题目 | 把坏题重新放回学生题池 |
| 验证器不可用 | 相关题型失败关闭，其他可验证内容继续 | 假装执行隐藏测试 |
| 表达生成失败 | 使用完整文字、静态替代或最后可用表达 | 阻断课程阅读、发布空白产物 |
| 学习锚点歧义 | 留在记录总览并提示重新定位 | 把记录强插到错误正文 |
| 服务重启 | 根据持久检查点只恢复未完成单元 | 重做全部已完成工作 |
| 旧课程缺少新合同 | 只读适配或显式迁移，降级可解释 | 双写旧对象和新对象 |

### 5.3 兼容与演进

- 新课程只写当前正式对象；旧对象只读适配，迁移必须幂等、可审计、可恢复。
- 兼容接口必须声明读取真源和写入目标，不能成为长期业务入口。
- 新增对象、页面、状态或能力时，必须说明现有对象为何不能承载、谁拥有状态、谁消费，以及旧链何时退出。
- 产品定义稳定但技术协议可以演进；实现细节由系统架构、OpenSpec 和状态板维护。
- 外部研究和 Demo 只有回写本文或正式规格后才改变产品方向。

## 6. 长期建设顺序与完成门

### 6.1 长期建设顺序

`P0-P6` 表示产品与工程的前置依赖，不表示当前完成度：

| 层级 | 必须先回答的问题 | 稳定产物 | 下一层解锁条件 |
| --- | --- | --- | --- |
| P0 可信执行与真源基座 | 系统能否稳定开发、验证、恢复并隔离数据 | 可复现运行时、质量门、数据边界和状态所有权 | 能区分产品缺陷、环境问题和测试污染 |
| P1 课程语义内核 | 课程、教案、知识、题目和表达由谁拥有 | 正式课程、课程命令、稳定知识与来源引用 | 课程可安全修改且不产生平行真源 |
| P2 学习证据与诊断内核 | 系统依据什么理解学习过程 | 正式学习事实、证据坐标和可重算学习者状态 | 调整能够指出来源、置信度和反证 |
| P3 可审阅课程生长 | 怎样把证据变成受控课程变化 | 调整方案、影响预览、用户确认、撤销和恢复 | 任意支持范围都能原子应用或拒绝 |
| P4 同源表达与完整学习现场 | 修改后各类产物和学习入口怎样一致 | 来源绑定的教案、讲稿、练习、PPT、图解和统一运行时 | 变化能精准重建，失败保留最后可用结果 |
| P5 效果验证与长期循环 | 怎样证明调整真的有效 | 独立复验、效果比较、失败回退和长期样本 | 不以“已接受”冒充“已改善” |
| P6 课程原生 Agent | AI 怎样组合成熟能力完成复杂目标 | 受证据、确认、正式命令和效果门约束的 Agent | Agent 只能组合成熟闭环，不能绕过它们 |

唯一内在顺序是：先让系统可信，再让课程可改；先让证据可信，再让调整发生；先让调整进入真实教学与学习现场，再验证效果；最后才把成熟能力交给 Agent 组合。

### 6.2 产品完成门

只有以下条件同时成立，灵知的目标产品才算完成：

1. 任意课程都能由稳定、有序、异构教学单元表达，修改不会静默破坏学习记录和历史作答。
2. 课程生成、教师修改和经确认的个性化调整共用同一课程内核。
3. 大纲、教案、课程知识、讲稿、正式题目和教学表达之间具有可验证的来源与修订关系。
4. 阅读、练习、笔记、错题、复习、知识图谱和 AI 老师共用同一学习运行时。
5. 所有正式题目都能说明为什么出、考什么、怎样判定，并隔离私有答案和隐藏验证。
6. 原始证据、AI 假设、学习者状态和课程调整严格分层，任何结论可回到来源。
7. 单条强证据可触发局部候选，广域修改需要更强范围依据；反证能够缩小或撤销判断。
8. 用户可以理解、选择、拒绝、部分接受、撤销和恢复课程变化，系统不会半应用。
9. 课程变化后，受影响教学产物能精确复用、过期、重建或安全降级，不产生漂移。
10. AI、媒体、图表、代码执行、评分或网络失败时，课程仍可继续学习并明确恢复。
11. 旧课程和旧入口通过只读适配或幂等迁移进入同一内核，不再产生第二条写链。
12. 多门跨学科真实课程证明完整生产与学习链，并有长期样本证明课程调整带来改善或触发安全回退。

这些完成门描述产品终局，不表示当前完成度。当前事实只看[产品状态](./产品状态.md)。
