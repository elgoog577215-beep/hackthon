# 灵知智能课程系统产品蓝图

灵知围绕一门持续生长的正式课程，把教师的课程设计、教学材料生产、真实教学、学生学习、学习证据、课程调整和效果验证连接成同一个产品。产品蓝图承载教学内容设计、产品运行逻辑和交互界面设计；代码、接口、数据结构、服务和任务编排由《系统架构》承接。

## 1. 灵知是什么

### 1.1 灵知处理的核心问题

灵知需要共同解决四个问题：

1. 教师怎样把教学设想转化为完整、专业、可以实施的课程。
2. 大纲、教案、讲义、题目、教学日历和演示课件怎样保持同源。
3. 教师教学和学生学习产生的真实证据怎样反过来改善课程。
4. 人工智能怎样参与课程设计、内容生产和课程修改，同时保留教师的决定权。

### 1.2 核心用户及其真实任务

- **教师**设计课程、准备教学、实施课堂、检查学习结果并调整课程。
- **学习者**理解课程内容、完成学习任务、记录问题、获得帮助并证明掌握。
- **课程设计者**维护课程结构、教学标准、内容模板与正式材料。

### 1.3 灵知管理的核心对象

- 一门持续生长的正式课程。
- 课程的教学设计、知识体系和资料来源。
- 大纲、教案、讲义、题目、教学日历、评价标准和演示课件。
- 教师教学过程、学生学习过程与学习证据。
- 根据证据形成的课程调整方案和新课程修订。

### 1.4 产品核心价值

```text
结构化同源
+ 教师可控的智能协作
+ 真实学习证据
+ 可验证的课程生长
```

结构化同源保证同一门课程的不同教学材料不会各自生长；教师可控保证人工智能只能提出候选、解释影响和执行经过授权的动作；真实学习证据让课程调整建立在实际教学与学习之上；效果验证判断一次调整究竟改善了学习，还是需要缩小、撤销或重新设计。

### 1.6 产品最终形成的结果

- 教师得到一套可以直接使用和持续维护的课程。
- 学习者得到与教师课程同源的学习体验。
- 每一次生成、修改和调整都有依据、影响范围和恢复方法。
- 课程是否改善最终由新的教学与学习证据判断。

## 2. 第一层：教学概念与内容设计

这一层定义一门课程由哪些内容组成、每类内容应该写什么，以及不同学科、教学方式和教学条件怎样改变实际内容。

### 2.1 教学内容设计全貌

```text
课程设计输入
-> 全课目标与内容结构
-> 课程大纲
-> 每讲内容设计
-> 教学块与内容单元
-> 教案
-> 讲义
-> 题目、任务、评价、图解和演示课件
-> 学习成果与学习证据
```

### 2.2 课程设计输入

设计一门课程前需要明确：

- 课程基本信息。
- 教学对象与学习起点。
- 学习目的。
- 课程最终目标与预期成果。
- 内容范围与不覆盖内容。
- 先修要求。
- 学时、班额和教学环境。
- 教师要求和教学风格。
- 已有课程资料、参考资料与正式模板。

### 2.3 改变教学内容的主要条件

- 三种学习目的。
- 八种一级学科类型。
- 六种课程教学类型。
- 七种本讲课型。
- 学生起点和目标难度。
- 课程规模、课时、班额和设备条件。
- 教师个人教学风格。
- 第二学科与跨学科关系。

这些条件不只是生成选项。它们必须实际改变课程目标、内容重点、教学块、例子、任务、证据和评价方式。

### 2.4 课程级内容模板

#### 2.4.1 课程设计说明模板

保存课程基本信息、学生起点、最终目标、内容范围、可用材料、实施条件和教师特别要求，是后续内容设计的共同依据。

#### 2.4.2 课程教学大纲模板

保存课程定位、教学对象、学习价值、内容范围、总学时、教学目标、课程要求、逐讲安排、考核方式和参考资料。

#### 2.4.3 目标—成果—评价对照模板

把每项课程目标与学生需要形成的成果、评价方式和达标标准对应起来，防止目标、教学活动和考试彼此脱节。

#### 2.4.4 全课内容结构模板

保存课程中心问题或最终成果、核心知识与能力结构、内容推进关系、跨讲成果和主要内容风险。

#### 2.4.5 教学日历内容模板

把课程讲次、学时、日期、教学任务、课前准备、课后任务和特殊安排映射到真实学期，但不凭空猜测节假日和调休。

### 2.5 讲次级内容模板

#### 2.5.1 本讲内容设计模板

保存学生起点、本讲目标、核心内容、内容难点、应用与证据以及课前课后安排。

#### 2.5.2 分讲教案模板

保存本讲基本信息、教学目标、重点与难点、教学设计思路、教学过程、课程总结、作业、拓展阅读和活动记录。

#### 2.5.3 分讲讲义模板

把教学块写成教师可以直接讲授的连续内容，包括自然进入、核心讲述、条件与边界、例子与推理、教师提问、学生可能回应、反馈与支架、活动指令、收束和过渡。

#### 2.5.4 演示课件页面内容稿模板

保存每一页的教学目的、页面类型、可见文案、版式、构图、讲者备注和讲义来源。页面内容稿是讲义到最终演示课件之间唯一的逐页内容合同。

### 2.6 教学块设计

教学块描述一段完整课堂活动，不等同于正文中的一个标题或段落。每个教学块至少包含：

- 教学块名称和教学作用。
- 与本讲目标的关系。
- 教师行动和学生行动。
- 学生需要投入的认知活动。
- 预计时间与组织方式。
- 使用的资料、设备和空间条件。
- 学生需要留下的学习证据。
- 达到、部分达到和未达到时的反馈分支。
- 必要支架、替代方案和下一块衔接。

### 2.7 内容单元模板库

课程内容根据实际学科和教学任务选择下列内容单元，不要求每讲机械覆盖全部类型：

1. 概念内容。
2. 原理与机制。
3. 推导、证明与论证。
4. 例题与示范。
5. 案例。
6. 实验与调查。
7. 操作与技能。
8. 代码与工程。
9. 材料阅读。
10. 讨论与论证。
11. 项目内容。
12. 复习与诊断。
13. 总结与迁移。

### 2.8 学生任务与评价内容

- 学生任务和作业模板。
- 单题、题组、练习和试卷模板。
- 评分标准与评分量规。
- 形成性检查和总结性评价。
- 学习成果与课程目标之间的对应关系。

任务必须说明学生要完成什么、交付什么、遵守什么约束、怎样判断达标，以及失败后怎样继续。评价既要判断是否达标，也要帮助识别仍缺少的知识、能力或过程证据。

### 2.9 资料与视觉表达内容

- 课程资料与参考资料。
- 拓展阅读。
- 公式、概念、条件、因果、步骤和对比图解。
- 用于情境联想和形象化解释的人工智能插图。
- 演示课件逐页内容。
- 各类材料的来源说明和使用边界。

图解与插图是对课程内容的表达，不是新的知识来源；只有教师采用后的表达才能进入共享教学材料。

### 2.10 不同条件怎样改变同一内容

#### 2.10.1 学习目的

系统学习强调完整结构、前后依赖和持续掌握；项目实战强调真实任务、过程产物和交付结果；期末冲刺强调考查范围、典型题型、诊断和短周期补缺。

#### 2.10.2 课程教学类型

理论课、实验课、实践课、研讨课、项目课和综合课分别改变全课课型分布、必备环节、成果形式与评价重心。

#### 2.10.3 本讲课型

理论讲授、讲练结合、实践操作、案例研讨、实验探究、项目工作坊和复习测评改变一讲中的时间结构、教学块顺序、师生活动和证据方式。

#### 2.10.4 学生起点与难度

学生起点和目标难度改变前置补充、例子跨度、推理深度、任务开放程度、支架强度和评价要求，但不能静默降低核心目标和学科标准。

#### 2.10.5 教师风格与课堂条件

教师风格改变讲授、提问、讨论和反馈的表达方式；课时、班额、设备和空间改变活动组织与替代方案。二者都不能破坏目标、证据和内容的专业性。

#### 2.10.6 跨学科关系

主学科决定课程主要问题、知识方法和评价标准；第二学科提供必要视角、工具或应用情境，不能与主学科争夺同一责任，也不能只添加表面术语。

### 2.11 八类学科内容设计包

灵知以八类一级学科内容设计包约束课程内容：

1. 通用课程。
2. 数学与形式科学。
3. 编程与工程技术。
4. 自然科学。
5. 生命科学与医学基础。
6. 人文社会科学。
7. 语言学习。
8. 商业与职业技能。

每个学科包统一包含：

```text
核心内容责任
-> 必须出现的专业内容
-> 适合的内容单元
-> 典型学习成果
-> 证据与评价方式
-> 常见错误
-> 不可突破的学科底线
```

八类学科包当前属于教师审阅候选。未经对应学科教师验证的内容必须保持候选状态，不能写成已经形成的教师共识。

### 2.12 内容质量标准

- 内容结构完整，关键栏目没有空缺或互相矛盾。
- 学科概念、方法、边界和证据要求成立。
- 目标、活动、成果、证据和评价保持一致。
- 教案能够指导真实教学，而不是课程内容摘要。
- 讲义能够直接用于讲授，而不是教材正文或课堂提纲。
- 学生任务能够产生可以判断的学习证据。
- 页面内容稿和演示课件与当前讲义同源。
- 内容适应真实课时、学生起点和实施条件。

### 2.13 完整贯穿样例

产品蓝图需要保留至少一套代表性课程样例，完整展示：

```text
课程输入
-> 大纲
-> 一讲内容设计
-> 教学块
-> 教案
-> 讲义
-> 页面内容稿
-> 学生任务
-> 评价标准
```

样例用于检查各类模板是否真的能够连接起来，不能反过来限制所有课程采用同一种教学写法。

### 2.14 教师审阅与内容定稿

- 区分通用内容标准、学科教师共识、教师个人偏好和待课堂验证意见。
- 每条教师意见说明影响的模板、内容单元、学科包或质量标准。
- 已确认意见进入正式内容设计；未确认意见继续保留候选身份。
- 课堂反馈如果推翻原设计，应修正相应内容合同，而不是只修改一次生成结果。

## 3. 第二层：产品机制与运行逻辑

这一层说明第一层定义的教学对象怎样创建、生成、修改、使用、失败、恢复和继续生长。

### 3.1 完整产品运行图

```text
第一执行区：创建课程
        |
        v
第二执行区：生成课程大纲
        |
        v
第三执行区：批量生成分讲教案
        |
        v
第四执行区：批量生成教师讲义
        |
        +--------------------+
        |                    |
        v                    v
第五执行区：其他教学产物   第六执行区：演示课件
        |                    |
        +----------+---------+
                   |
                   v
第七执行区：教师教学与学生学习
                   |
                   v
第八执行区：课程调整与联动更新
                   |
                   v
第九执行区：效果验证与下一轮生长
                   |
                   +-------------------> 新的课程修订与学习证据
```

每个执行区都必须说明使用什么已有事实和新增输入、系统怎样处理、用户作出什么决定、形成什么结果、结果被谁使用，以及失败后返回哪里。

### 3.2 产品角色与决定权

- 教师提供课程要求、选择教学条件、编辑内容、审阅候选并决定正式修改。
- 学习者阅读课程、完成任务、记录问题、提出需求并形成真实学习事实。
- 人工智能理解资料、生成内容候选、解释证据、分析影响并执行经过授权的动作。
- 系统保存正式结果、来源、任务、修订、学习事实、执行回执和恢复点。
- 人工智能不能替教师确认正式课程，也不能把单次弱信号直接解释为稳定学习问题。

### 3.3 正式产品对象及其责任

- **正式课程**保存课程身份、讲次顺序和当前正式内容。
- **课程设计依据**保存学生、目标、学科、教学方式、条件和教师要求。
- **课程教学设计**保存全课和分讲怎样教，不复制课程正文。
- **课程知识体系**保存本课程实际教授的知识、能力、边界、易错点和掌握标准。
- **课程资料与来源**保存内容依据、参考关系和正式模板关系。
- **教学产物**包括大纲、教案、讲义、题目、日历、评价标准、图解和演示课件。
- **学习事实**包括学习行为、笔记问答、正式作答和作品。
- **学习证据**把有来源的事实组织成能够支持或反驳教学判断的证据。
- **课程调整方案**保存调整依据、范围、候选变化、影响和复验安排。
- **生成任务与工作修订**保存过程状态、当前结果、最后可用结果和恢复点。

### 3.4 对象之间的关系

- **组成关系**说明什么属于课程、讲次、教学块或内容单元。
- **生成关系**说明什么输入共同形成什么结果。
- **来源关系**说明一项内容依据哪些课程事实、资料和上游产物形成。
- **依赖关系**说明上游变化会影响哪些下游。
- **使用关系**说明教师端和学生端怎样消费同一内容。
- **证据关系**说明什么事实能够支持什么判断。
- **修订关系**说明一次修改怎样形成新的当前结果。
- **影响关系**说明哪些对象需要更新、复核或保持不变。

### 3.5 第一执行区：创建课程

```text
课程基本信息
+ 教学对象
+ 学习目的
+ 学科类型
+ 课程教学类型
+ 教学条件
+ 教师要求
+ 可选资料和正式模板
-> 课程设计依据
-> 正式课程身份
-> 大纲生成准备
```

从零开始和基于已有资料创建课程，最终都进入同一个课程身份。信息缺失时显示缺失项；信息冲突时让教师选择；资料解析失败时保留原件并允许重新识别或人工指定；创建失败不能留下无法继续使用的半成品课程。

### 3.6 第二执行区：生成课程大纲

```text
当前课程设计依据
+ 教师输入
+ 已确认资料
+ 正式模板栏目
-> 轻量讲次方案
-> 教师调整讲次顺序、范围和重点
-> 完整课程目标与逐讲安排
-> 结构和学时检查
-> 当前大纲修订
```

大纲生成失败时回到本次冻结输入和已完成部分；教师修改后的讲次方案不得被重试覆盖；结构检查未通过时只重做缺失或冲突部分；当前大纲是教案、题目、日历和其他课程文件共同使用的课程级依据。

### 3.7 第三执行区：批量生成分讲教案

```text
当前完整大纲
+ 全课教学设计
+ 每讲目标和课型
+ 学科规则
+ 资料范围
+ 教师补充要求
-> 全部讲次任务一次进入队列
-> 每讲独立生成、检查和保存
-> 当前分讲教案
```

整课一次启动，逐讲独立执行。不同讲次可以并发，但不能互相覆盖；完成的教案立即可用；单讲失败只恢复失败或缺失讲次；大纲变化后只标记真正受到影响的教案，不重做整门课程。

### 3.8 第四执行区：批量生成教师讲义

```text
当前教案
+ 当前课程知识
+ 对应资料
+ 教师讲授要求
-> 教学块展开
-> 连续讲授内容
-> 结构和来源检查
-> 当前分讲讲义
```

讲义必须承接教案中的目标、教学块、师生活动和证据要求，并写成教师可以直接开口讲授的内容。单讲失败独立恢复；教案改变后按实际来源判断哪些讲义内容需要更新；最后可用讲义在新生成失败时继续可读。

### 3.9 第五执行区：生成其他教学产物

#### 3.9.1 题目与学生任务

由课程目标、当前知识、讲次内容、成果要求和评价意图共同形成。题面、答案、评分标准和隐藏检查必须各自承担明确责任。

#### 3.9.2 评分标准

由目标、任务成果、达标表现和常见问题共同形成。修改任务时必须检查评分标准是否仍然成立。

#### 3.9.3 教学日历

由课程讲次、教学安排、真实学期和教师日程共同形成。日期变化不应静默改写课程内容。

#### 3.9.4 图解和插图

由当前讲义中的教学块提出表达需求，生成候选后由教师采用。未采用的候选不能进入演示课件或学生端。

#### 3.9.5 配套文档

题库、试卷、评分细则、自查清单和其他配套材料读取同一课程基线，但不成为大纲、教案、讲义和演示课件主链中的强制步骤。

### 3.10 第六执行区：生成演示课件

#### 3.10.1 根据当前讲义生成

```text
当前且来源未过期的讲义
+ 教师采用的图解和插图
+ 正式课件模板
-> 页面内容稿
-> 教师审阅和确认
-> 演示课件
-> 预览与导出
```

#### 3.10.2 使用教师原有演示课件

```text
教师原有课件
-> 识别内容、版式和模板关系
-> 教师确认保留与替换范围
-> 与当前讲义建立来源关系
-> 形成可继续编辑和重建的课件
```

页面内容稿保留独立确认。最终演示课件只能编译已经确认的页面内容稿，不能在渲染阶段重新写课程内容。失败时保留最后可用课件，并允许按页面、教学块或讲次恢复。

### 3.11 第七执行区：教师教学与学生学习

```text
当前正式课程与教学产物
-> 教师课前设计和课堂实施
-> 学生阅读、练习、记录、提问和提交成果
-> 学习行为、笔记问答、正式作答与作品
-> 有来源的学习证据
```

活动已经完成不等于目标已经达到。浏览、停留和滚动只能说明发生过接触；正式作答、作品、操作过程和教师观察才能在适当条件下成为更强证据。教师端和学生端使用不同语言表达同一教学语义，但读取同一课程内容和当前修订。

### 3.12 第八执行区：课程调整与联动更新

```text
教师要求或学习证据
-> 明确调整对象和范围
-> 分析受到影响与保持不变的对象
-> 形成修改候选
-> 教师审阅、排除或调整
-> 应用或拒绝
-> 形成课程新修订
-> 精准更新受影响产物
-> 保留执行回执、撤销和恢复
```

用户选择的范围是人工智能不能突破的限制。局部变化可以在原对象旁审阅；跨讲次、跨产物和全课变化进入完整工作区。不同入口必须打开同一项调整任务，不能各自保存一份候选。

### 3.13 第九执行区：效果验证与下一轮生长

```text
调整前的课程与学习基线
+ 已应用的课程调整
+ 独立的后续学习任务
-> 新学习证据
-> 暂时改善、持续改善、无明显变化或出现反证
-> 保留、缩小、撤销或重新设计调整
-> 下一轮课程生长
```

一次成功只能表示初步支持，不能直接证明长期有效。范围越广的课程调整，需要越多独立、一致的后续证据。出现反证时必须能够缩小或撤销原判断。

### 3.14 覆盖九区的共同运行规则

1. 每次生成先固定本次使用的课程修订、资料、模板和教师要求。
2. 批量任务一次启动，按最小可恢复单元分别执行和保存。
3. 已完成结果立即保存，部分失败不能抹掉已完成内容。
4. 最后可用结果始终优先保留，新生成失败不能让教师失去旧结果。
5. 上游变化先分析影响，再决定复核、局部重建或保持不变。
6. 教师选择的范围不得被人工智能扩大。
7. 同一任务从不同入口进入时仍然是同一项任务。
8. 关闭、刷新和切换页面后能够继续查看和控制原任务。
9. 失败必须说明原因、影响范围、保留结果和恢复方法。

### 3.15 状态、候选、修订与确认

- 教师直接编辑当前内容后形成新的当前工作修订。
- 人工智能修改已有内容时先形成候选，由教师采用后形成当前修订。
- 大纲、教案和讲义生成完成，只要结果非空、结构可用且来源未过期，即可成为当前工作修订并被下游使用。
- 页面内容稿保留独立确认，未经确认不能生成正式演示课件。
- 没有返回内容、结构无法成立、来源硬冲突和违反不可突破要求时阻断使用。
- 普通表达和质量建议只形成可选审阅意见，不伪装成生成失败。
- 上游变化后，未重建的下游可以保持“最后可用但需要复核”，不能被自动覆盖。

### 3.16 失败、恢复和退出

产品必须分别处理：

- 模型没有返回内容。
- 返回内容无法形成合法结构。
- 内容违反硬性要求。
- 内容存在普通质量问题。
- 批量任务部分失败。
- 上下游修订冲突。
- 资料过期、缺失或范围不符。
- 模型暂时不可用。
- 用户取消、撤销或重新进入。

失败恢复始终从已保存的输入、检查点和最后可用结果继续，不重新制造一套任务或课程内容。

## 4. 第三层：交互与界面设计

这一层以现有界面为基线，把第二层的对象、关系、状态和动作转化为教师与学习者可以完成的任务。新的交互设计不脱离现有课程工作台、课程文件、审计与更新中心、演示课件工作区和学生学习现场重新发明一套界面。

### 4.1 现有界面全景

- **教师首页**承载我的课程与我的日历。
- **新建课程与备课起点**承载从零开始和基于已有资料两种入口。
- **课程工作台**承载大纲、教案、讲义和演示课件四个主阶段。
- **课程文件空间**承载正式课程文件、课程资料、参考资料和正式模板。
- **题库与其他课程文件**承载题目、试卷、评分细则和配套材料。
- **演示课件工作区**承载页面内容稿、模板、课件生成、预览和导出。
- **审计与更新中心**承载资料变化、模板映射、影响分析和执行回执。
- **课程调整工作区**承载跨对象候选、范围控制、采用、撤销和复验。
- **学生学习现场**承载阅读、练习、记录、知识和学生人工智能老师。
- **任务状态与恢复入口**承载生成、暂停、失败、重试和继续。

### 4.2 九区运行逻辑与现有界面的对应关系

| 产品执行区 | 现有主要载体 | 需要继续补齐的重点 |
| --- | --- | --- |
| 创建课程 | 教师首页、新建课程弹窗、备课起点选择 | 把完整课程设计输入与已有资料选择接入同一入口 |
| 生成大纲 | 课程工作台的大纲阶段 | 补齐输入依据、结构检查、失败返回和当前修订 |
| 批量生成教案 | 课程工作台的教案阶段 | 补齐全课预览、逐讲状态、部分失败和恢复 |
| 批量生成讲义 | 课程工作台的讲义阶段 | 补齐教案来源、逐讲生成和精准过期提示 |
| 其他教学产物 | 其他课程文件、题库、教学日历 | 统一来源、生成入口、状态和返回课程的位置 |
| 生成演示课件 | 演示课件工作区 | 保留页面内容稿确认和两种课件来源路径 |
| 教师教学与学生学习 | 学习现场、教师预览和后续课中视图 | 在现有学习界面基础上补齐课中实施和真实记录 |
| 课程调整与联动更新 | 审计与更新中心、原位候选、课程调整工作区 | 统一局部修改和跨对象修改，不建立平行候选 |
| 效果验证 | 调整工作区、学习现场和课后复盘 | 补齐调整前基线、复验任务和效果结论 |

第三层不为九个执行区分别创建九个页面，而是让现有任务空间共同承载完整运行链。

### 4.3 现有布局与视觉基线

- 保留当前已经成熟的蓝紫色视觉体系、信息密度和控件语言。
- 教师工作台继续使用左侧导航、中间正式内容和右侧任务信息。
- 学习现场继续使用左侧目录、中间正文、右侧笔记或人工智能老师和底部学习工具。
- 正式内容保持连续文档阅读，不把教学块拆成一排重卡片。
- 操作靠近所影响的对象；跨多个对象的影响审阅使用完整工作区。
- 短暂输入、状态和说明使用现有弹窗、侧栏或原位展开。
- 当前只设计和验收桌面端。

### 4.4 教师首页与创建课程

- 我的课程和我的日历在同一教师首页切换。
- 默认进入我的课程，支持搜索、筛选、卡片与列表查看。
- 新建课程收集课程基本信息、学生、目标、学科、教学方式、课时和教师要求。
- 教师选择从零开始或基于已有资料，两种路径最终进入同一个课程工作台。
- 已有资料在进入工作台前完成用途识别和集中确认，但文件导入不成为独立教学步骤。
- 创建失败时保留已经填写的内容并给出重试或退出方法。

### 4.5 课程工作台

- 左侧固定显示大纲、教案、讲义和演示课件四个主阶段。
- 大纲不展开讲次目录；教案、讲义和演示课件使用同一讲次顺序。
- 中间区域显示当前对象的输入、生成过程、当前修订、阅读、编辑和差异。
- 右侧区域随任务变化：生成前显示资料和要求，生成中显示真实进度和控制，生成后显示来源、修订和影响。
- 教师可以自由切换阶段，但系统根据真实依赖决定哪些动作可用。
- 生成完成后原位进入当前结果，不自动跳到下一讲或下一阶段。
- 学生视角预览复用学生真实学习界面，只增加教师身份和预览标识。

### 4.6 课程文件空间

一级目录固定承载教学大纲、分讲教案、讲义、演示课件、其他课程文件、课程资料和回收站。

- 正式课程文件读取同一课程和讲次关系，不复制底层内容。
- 上传原件只保存一次，再与正式对象建立主来源、参考资料或模板关系。
- 单击选择，明确打开动作进入查看或编辑；批量操作只在多选后出现。
- 删除默认进入回收站；仍被正式内容引用的资料不能直接删除。
- 固定正式对象缺失时显示未生成，重复生成形成新修订而不是并列副本。
- 文件变化进入审计与更新中心，工作台只接收教师确认后的来源关系和调整候选。

### 4.7 批量生成与任务反馈

- 教案和讲义默认只显示整课生成入口。
- 全部讲次一次进入任务队列，每讲显示真实状态和当前结果。
- 完成的讲次立即可以查看和使用。
- 某讲失败时原操作切换为重新生成，只恢复失败或缺失讲次。
- 暂停、取消、继续和恢复必须作用于真实任务。
- 页面关闭或刷新后重新进入，仍能查看和控制同一任务。
- 界面不使用虚假进度或整课遮罩掩盖部分完成和部分失败。

### 4.8 教师编辑与人工智能协作

- 教师直接编辑当前工作修订，保存后显示真实影响。
- 教师可以选择正文局部提出修改要求，候选在原对象旁显示。
- 跨讲次、跨产物或改变讲次身份和顺序的要求进入完整课程调整工作区。
- 候选必须显示改变内容、依据、影响对象和保持不变的内容。
- 教师可以逐项采用、排除、保留原文、撤销和恢复。
- 人工智能会话不能保存第二份课程正文，也不能占用生产任务右栏。

### 4.9 审计与更新中心

审计与更新中心统一承载：

- 新资料导入。
- 资料替换和过期。
- 正式模板栏目映射。
- 教师全课修改。
- 多对象影响分析。
- 冲突、缺失和解析质量。
- 修改候选、执行回执和恢复入口。

同一项变化从文件空间、工作台或人工智能入口进入时，必须回到同一审计或调整任务。

### 4.10 演示课件工作区

- 支持根据当前讲义生成和使用教师原有课件两条路径。
- 页面内容稿先于最终演示课件，并保留独立审阅和确认。
- 模板选择显示模板来源、适用页面和内容容量。
- 教师可以按页面、教学块和讲次重建受影响部分。
- 预览、导出、失败恢复和返回工作台都保留当前课程、讲次和任务位置。
- 最终课件不能脱离已确认页面内容稿增加新的课程知识。

### 4.11 学生学习现场

- 左侧显示讲次目录，中间显示连续课程正文。
- 学习者直接看见本讲要学会什么、完成什么和怎样证明学会。
- 正式练习从对应正文位置或课程练习视图进入，关闭后回到原内容锚点。
- 笔记和人工智能老师在正文右侧展开，不遮挡主要学习内容。
- 错题、复习、学习记录和知识关系读取正式学习事实，不建立各自的进度副本。
- 学习位置、笔记草稿和人工智能会话在合理范围内保持连续。
- 教师预览不读取或写入学生数据。

### 4.12 课中实施、课后复盘与效果验证

这三项能力在现有课程工作台和学习现场上延伸，不另起一套教师系统：

- 课中查看当前教学块、可直接讲授的讲义、时间、提问和备用方案。
- 教师快速记录真实学生表现，并区分观察事实和教学判断。
- 课后核对本讲目标、学生成果和课堂证据。
- 教师选择只调整当前讲、相关后续讲次或全课。
- 已应用调整保存调整前基线和后续复验安排。
- 效果结论能够回到原调整方案，并支持保留、缩小、撤销或继续调整。

### 4.13 全局状态与恢复体验

所有主要对象和任务统一表达：空状态、准备中、生成中、当前可用、部分完成、生成失败、来源过期、等待复核、存在冲突、已取消、可恢复和只读降级。

状态必须同时回答当前发生了什么、已有结果能否继续使用、用户现在能做什么，以及怎样恢复。

### 4.14 跨页面连续性

- 从课程库进入课程后保持课程身份。
- 从工作台进入文件、演示课件或调整工作区后能够返回原对象和位置。
- 从正文进入练习、笔记或人工智能老师后能够回到原内容。
- 同一任务从多个入口进入时不重复创建。
- 教师预览不产生学生学习数据。
- 生成和调整任务不因页面切换而消失。

## 5. 三层设计怎样闭合

本章不增加新的教学对象或产品模块，而是检查前三层能否逐项对应。

### 5.1 内容对象—产品机制—界面载体对照

第一层中的每个对象都必须回答：

```text
它是什么
-> 由什么形成
-> 谁能够修改
-> 怎样成为当前结果
-> 影响哪些对象
-> 用户在哪里看见和操作
-> 失败后怎样恢复
```

如果一个内容模板在第二层没有形成、修改和使用机制，它仍然只是文档模板；如果一个产品机制在第三层没有入口、过程、状态和决定方式，它仍然只是后台能力。

### 5.2 教师端与学生端同源

- 同一个课程目标在教师端表达为教会什么和怎样检查，在学生端表达为学会什么和怎样证明。
- 同一讲内容形成教案、讲义、演示课件和学生学习页面，但只有一份课程语义和正式来源。
- 学生端不得复制一份独立课程正文。
- 教师预览复用真实学习路径，不另建展示版本。

### 5.3 人工智能与正式结果的边界

```text
人工智能输出
-> 可审阅候选
-> 教师决定
-> 正式课程修订
-> 执行结果
-> 撤销与恢复
```

六者不能混成一个“生成成功”。人工智能可以提出改进、解释影响和执行受控动作，但不能替用户确认、扩大范围或隐藏失败。

### 5.4 变化传播的一致性

- 上游变化通过真实来源和依赖找到下游。
- 受影响内容进入复核或局部重建，不受影响内容明确保留。
- 普通质量建议只产生建议，硬性错误才阻断使用。
- 新结果生成失败时，最后可用结果继续存在。
- 更新完成后通过新的教学或学习证据重新验证。

### 5.5 跨层硬边界

- 一门课程只有一份正式正文。
- 学习事实与人工智能判断分开保存和表达。
- 教师决定不能被人工智能代替。
- 页面显示状态不能另建一套产品事实。
- 导出文件不能反过来成为课程真源。
- 学习位置不能冒充掌握证据。
- 技术字段、接口和存储方式不进入产品蓝图正文。

## 6. 产品完成标准

### 6.1 第一层完成标准

- 主要教学对象都有清楚定义和完整模板。
- 条件变化能够落实到具体内容、教学块、任务和评价。
- 八类学科设计包经过对应教师验证。
- 完整样例能够从课程输入贯穿到学习评价。

### 6.2 第二层完成标准

- 九个执行区都有输入、处理、决定、结果和返回路径。
- 批量、局部、失败、恢复和变化传播规则完整。
- 教师、学习者、人工智能和系统的权力边界清楚。
- 学习证据能够进入课程调整并接受独立效果复验。

### 6.3 第三层完成标准

- 每项产品机制都有现有或明确规划的界面载体。
- 教师与学习者能够完成完整任务，而不只是看见功能入口。
- 所有长任务都有真实状态和恢复路径。
- 用户能够看见修改内容、影响范围、执行结果和撤销方法。
- 新交互保持现有界面语言，不形成第二套产品。

### 6.4 整体产品完成标准

```text
教师能够完成课程设计
-> 系统能够形成同源教学产物
-> 教师能够真实教学
-> 学生能够真实学习
-> 系统能够获得可信证据
-> 教师能够据此调整课程
-> 后续学习能够验证调整效果
```

只有这条链真实成立，灵知才从课程内容生成工具成为完整的智能课程系统。
