## 1. 产品定义

灵知是一套以结构化课程为核心，连接教师课程生产、统一学习现场、学习证据驱动的课程生长，并能从同一课程语义编译多种教学表达的 AI 课程系统。

它不是一次性课程生成器，也不是把聊天、题库、笔记和 PPT 拼在一起的工具箱。目标是让一个真实学习目标形成可长期运转的闭环：

```text
目标、资料与学习起点
-> 结构化当前课程
-> 教案、正文、练习、PPT 与图解等同源表达
-> 阅读、提问、笔记、作答与项目表现
-> 有来源、有知识坐标的学习证据
-> 可反驳的教学判断与课程调整候选
-> 用户审阅并确认
-> 当前课程及受影响表达安全更新
-> 独立任务验证调整效果
-> 新证据进入下一轮课程生长
```

### 1.1 核心用户与任务

灵知服务两个围绕同一课程真源协作的角色：

- 课程创建者和教师：从目标、资料与教学约束创建课程，审阅并修改目录、课堂教案、正文、练习和教学表达，安全发布并继续修订。
- 学习者：围绕真实目标进行系统学习、项目实战、问题探究或考试准备，在同一现场阅读、练习、提问、记录并获得可解释的课程调整。

两类角色共享同一个 `course_id` 和 `CourseDocument`，但权限、入口和任务不同。灵知不扩张为班级管理、多人协作或学校文件管理平台。

产品需要闭合四类连续任务：

1. 从目标、资料和教学约束得到一门结构清楚、可审阅、可恢复的课程。
2. 让教师能持续编辑目录、教案和正文，并看见对练习与教学表达的真实影响。
3. 让学习者在同一学习现场完成阅读、练习、提问、记录和项目，不在工具之间搬运上下文。
4. 让课程依据真实学习证据安全调整，并用独立结果判断调整是否有效。

### 1.2 产品北极星

唯一北极星是**可验证学习闭环完成率**：

```text
有来源证据、形成正式课程修订并获得独立效果结果的已接受调整数
/
全部已接受课程调整数
```

生成数量、AI 对话数量、课程时长、PPT 页数和页面访问量只能解释过程，不能证明学习闭环成立。

### 1.3 明确不做

- 不做 LMS、班级管理、多人协作、课程商城、内容广场或社交网络。
- 不新增与课程库、课程工作区、AI 老师平行的顶层功能中心。
- 不让用户管理课程版本树，不建立长期覆盖正式课程的个人 Overlay。
- 不让 Agent 绕过证据、用户确认和领域命令直接改写正式课程。
- 不先做自由视频、数字人或 Skill 市场，再倒推课程语义。
- 不用单门样板课程、一次模型成功或局部测试代替真实跨学科与长期效果验证。

## 2. 产品总控模型

灵知由两条相互依赖但不能混为一谈的闭环组成。

### 2.1 结构化同源

结构化同源回答“同一门课程怎样产生一致的教学材料”。

```text
CourseTeachingPlan + CourseKnowledgeBase
-> CourseDocument
-> TeachingRepresentation
-> 教案 / 正文 / 练习 / PPT / 图解 / 讲义等投影
```

课程结构、知识身份和来源绑定共同约束所有表达。表达可以有自己的版式和编辑状态，但不能脱离课程语义成为第二份课程正文。

### 2.2 课程生长

课程生长回答“课程怎样依据学习过程持续调整”。

```text
LearningEvent / LearningRecord / PracticeAttempt
-> EvidenceItem
-> AdaptationHypothesis
-> CourseEvolutionPlan
-> 用户审阅与确认
-> CourseDocument 新修订
-> 受影响表达重编译
-> 独立效果复验
```

AI 判断只是有依据的假设，不是学习事实。正式课程变化必须可解释、可选择范围、可拒绝、可恢复、可撤销，并严格限制在当前 `course_id`。

### 2.3 两条闭环的关系

- 两条闭环共同维护当前课程，不建立“公共课程 + 个人覆盖层”的长期双真源。
- 结构化同源保证修改后各类教学表达不会漂移；课程生长保证修改来自真实学习证据而不是随机生成。
- 教师语义修改与学习者个性化调整可以来自不同入口，但最终都必须进入同一影响分析、确认、课程命令和修订链。
- 表达层编辑只改变表达；语义层编辑必须回到课程变化候选。

## 3. 产品空间与核心旅程

### 3.1 教师首页与课程入口

教师端首页在同一顶栏提供“我的日历 / 我的课程”两个一级入口，不把课程列表长期挤在日历左侧。我的日历由可交互教学日历与选中日期或课次状态组成；我的课程是完整课程库，支持卡片和列表两种密度。两者共享课程真源与路由语义，不建立平行教师产品壳。

从我的课程选择已有课程后进入课程工作台；点击日历课次可继续备课或预览当前正式课程。AI 新建与 Markdown 导入最终都必须得到同一 `course_id` 和同一课程领域对象。后台任务状态可以在首页和任务中心投影，但任务对象不成为课程真源。

新建课程从教师首页以一张紧凑弹窗打开。课程名称是唯一必填项；授课对象、课程类别、专业、学分、学时、考核方式、学年学期、课程介绍和教学目标默认完整展开并可稍后补充。建课阶段不上传文件，所有原文件统一进入课程工作台或文件视图。提交后先创建空课程空间并进入工作台，由教师在“课程基础”中开始大纲生成，避免创建动作绕过课程结构确认。

### 3.2 课程生产

课程工作台提供五个彼此可直接进入的生产入口：

```text
课程基础（大纲 / 教学日历）｜教案｜题库｜讲稿｜PPT
```

左侧顺序表达常见备课路径，不是依赖门禁。教师可以跳过题库先制作讲稿或 PPT，也可以之后用课程资料、已有题库、讲稿或 PPT 生成题目，并把选中题目补充回既有讲稿或 PPT。某类资产尚不存在时，中间栏显示该类型预设的结构化表单；提交后同一位置切换为真实流式生成，持续保留已生成内容、阶段、暂停、重试与恢复；生成完成后才进入正式编辑、迭代和影响分析。系统必须：

单次生成统一遵循“表单 → 可见任务 → 工作稿 → 教师确认”的最短闭环。任务运行时隐藏重复提交动作并持续显示真实进度；失败原位显示原因和一个重试入口；生成成功先展示可读工作稿，不直接冒充正式资产。确认后写入正式修订并聚焦常见下一入口，教师仍可从左侧自由跳转。分讲教案必须展示教学目标、重难点、课堂环节、师生活动、时间分配、课堂检查、作业与备注。大纲、教案和讲稿都在原展示面右上角解锁同页编辑；AI 优化只形成同页候选，采用后进入同一工作修订。每讲讲稿从已确认教案、教师补充要求和选定资料生成，全部小节成功后才原子保存为该讲唯一的讲稿资产。课次资产共享上一讲/当前讲/下一讲导航，右下角主操作在确认后原位切换为下一阶段。不再打开独立审阅页、学习页或第二套教案/讲稿界面；PPT 只消费已确认教案与已确认讲稿修订。

五个入口之外另设不编号的“配套文档”服务，专门处理面向学校提交、学生说明或课程归档，但不直接承担课堂教学的文档。进入后先显示二级模板卡片，再打开预填课程信息的结构化表单。只有得到真实学校样例支撑的模板才能上线；首批为浙江大学评分细则和考试课程材料自查清单。

- 尊重用户明确给出的课程规模和资料范围。
- 教师大纲先生成并展示带名称的大章节骨架，教师看到真实章节主题后逐章确认小节数，再由同一任务继续生成小章节。总学时只记录教学时间，不自动推导章节或小节数量。
- 用有界工作单元生成大课程，不把课程总量变成单次模型输入或产品级拒绝理由。
- 保存真实检查点；失败只重做缺失或失败单元，不重做已通过产物。
- 区分生成完成、质量通过与正式发布，不能把正文齐备显示为已发布。
- 本地降级必须明确标记，不得冒充完整 AI 质量通过。

### 3.3 课程文件空间与正式课程

课程准备发生在同一 `course_id` 的课程空间中，而不是通过“课程 / 大纲 / 正文 / PPT”的重复顶部 Tab 切换。课程空间提供两种互补视角，并默认进入工作台：

```text
工作台（默认）：以课程基础、教案、题库、讲稿、PPT 五个非阻塞入口组织课次资产和当前内容
文件视图（辅助）：按教师自建文件夹习惯组织整课、章节、资料和派生文件
```

- 工作台兼具生产与管理：左侧展示阶段依赖和完成度，中间在表单、流式生成、正式内容之间原位切换，右侧固定管理“一个主来源 + 多份参考资料 + 联网来源”。教案阶段的右栏以当前讲次为作用域：看到第几讲，上传、勾选或移除的资料就归到第几讲；切换讲次必须恢复各讲独立的引用集合。原文件仍是课程内只保存一次的稳定资产，讲次只保存引用关系，不复制文件。联网来源使用独立调研对话框：教师描述需求，系统在原接口内展示真实检索词，按查询和网域扩展覆盖，对有界高价值来源深读公开 HTML/PDF 正文并重整为可定位证据；单页失败回退摘要，教师勾选后才转成当前阶段可用的课程资料。AI 负责提取字段、标记缺失信息和生成候选，但通用聊天框不承担建课、上传或正式保存。
- 大纲的章节骨架确认、逐章小节数调整、完整审阅和结构编辑都在工作台中间栏完成；左侧阶段与右侧资料保持可见，不再为大纲编辑打开右侧抽屉或第二个界面。
- 课程类型、主题、学习目标、内容深度、知识组织、课程规模和生产模式继续使用课程现有 `generation_request` 作为唯一基线真源，但旧课程生成面板不再从大纲阶段重新打开。文件范围、联网与灵活补充要求属于每次阶段生成的运行参数；对话归纳或设置变更先形成可审阅候选，不静默覆盖已确认资产。
- 文件视图保持桌面资源管理器心智：左侧是可展开的整课、课次与真实子文件夹目录树，中间是当前目录的文件列表，右侧是当前文件夹或选中文件的属性、来源关系与操作。

- 整课层包含大纲、教学日历、整课参考资料与其他整课资产。教学日历是课程级固定文件和排课入口，并与大纲共同归入“课程基础”入口。
- 固定课程资产不等待用户“新建”后才出现：整课常驻大纲和教学日历，每个课次常驻教案、讲稿、题库和配套 PPT；缺失时直接标记“未生成”。资料文件夹只承载讲义、案例、阅读、课堂辅助和老师上传的原文件。
- 题库不是课程生产的必经步骤。题目主要在题库工作台中按当前选定资料和课次范围生成、审阅与修改；“组成试卷”是题库内部操作，不新增第六个生产阶段。保存后的题库和试卷作为正式资产进入文件视图，试卷固定引用组卷时的题目修订和题库修订，后续改题不会静默改写既有试卷。
- 配套文档在整课层使用独立文件夹，每种单例模板只显示一份当前正式文档；重新保存新增修订，不生成并列副本。右侧资料保存为双向引用关系，DOCX/Markdown 只是当前修订的导出投影。
- 文件空间同时区分三种对象：系统内可编制的正式文件、老师上传的带格式原文件、按修订生成的导出文件。正式文件以结构化数据或数据库对象保存；原文件只保存一份，导出文件只是快照，后二者都不得成为第二份课程真源。
- 每个正式文件保存主来源与参考资料；每个原文件反向列出引用它的正式文件。同一原文件可以出现在多个逻辑位置，但底层只使用稳定资产 ID 保存一份；移除引用不等于删除原文件。
- 文件空间沿用桌面资源管理器习惯：单击文件夹直接进入并自动展开祖先路径；单击文件只选中并更新右侧详情，双击或右侧主操作才打开、生成或编辑。列表显示名称、修改时间、类型、真实可得的大小和状态，文件夹不伪造大小。
- 搜索只作用于当前目录，始终提供清空动作；无匹配项时显示独立的“没有找到”状态，不与空文件夹混淆。
- 页面不再放置泛化的“新建”菜单。大纲、教案、题库、讲稿和 PPT 本身就是入口；只有参考资料、课次资料与自定义文件夹提供明确的“添加资料 / 新建文件夹”。重复生成形成原资产的新修订，不生成并列副本。
- 教案与讲稿在课程工作台同一内容面承载生成、查看、编辑、AI 候选、质量检查、确认和恢复；每讲只保存一条讲稿修订链。PPT 因画布编辑使用独立全屏工作区，但只允许从同一工作台和同一 V6 真源进入，不再维护第二套生成页。
- PPT 入口必须区分“AI 生成课件”和“老师上传的旧课件”。固定的配套 PPT 位永久保留，不因上传了旧课件而消失；前者随教案修订联动，后者保留原件，可选择只保存，或解析页面结构与文字生成一份待审阅教案草稿。已有确认教案不得被上传动作静默覆盖。
- 教师智能体以右侧协作栏与中间正式内容同时可见，默认使用教师视角分析教学原理与过程。它可按当前阶段和选定文件交流，并将对话归纳为可审阅候选；未经教师确认不写入正式区。
- “预览正式课程”进入明确标识的学生视角；正文块、正式题目与其他学习活动按当前修订组装，并复用练习、笔记、错题、学习概况、知识库和学生 AI 老师，不复制为一份新文档。
- 教师在学生视角中的个人学习记录只归属教师当前身份，不读取或写入任一学生数据，也不直接改写正式课程资产。

正式课程是结构化真源的运行时视图，文件是备课输入、可编辑投影或导出物。用户可以在两者之间往返，但正式语义修改只能通过影响分析、教师确认和课程修订链写入。

### 3.4 学习现场

学习现场保持“左目录、中正文、右侧笔记或 AI、底部学习工具”的连续空间：

- 正式练习从正文对应位置或课程练习视图进入，关闭后回到原内容锚点。
- 桌面笔记本从底部工具坞在正文右侧展开；移动端使用全屏覆盖层，避免压缩正文。
- 手写便签和 AI 问答摘要可以投影回正文附近，但 `LearningRecord` 仍是唯一事实源。
- 错题本、复习中心、学习记录和知识图谱是领域事实的聚合视图，不建立各自的进度或内容副本。
- 临时解释、反例、过渡和检查可以进入当前学习流，但不自动写入正式课程。

### 3.5 调整课程

学生侧只保留一个“调整课程”概念。正文中的就近入口和 AI 老师主入口共享同一个候选状态：

- 用户可以选择当前内容、当前小节、相关后续或全课程范围。
- 单项局部变化可在原位置或侧栏审阅；多项、跨小节或全课程变化进入完整审阅工作台。
- 课程空间顶栏提供直接入口；AI 老师只负责从对话发起或提示调整，不在聊天流中嵌入完整生成表单。进入独立工作台后继续读取同一个 `CourseEvolutionPlan`。
- 关闭、刷新或切换入口后恢复同一服务端任务，不生成第二份候选。
- 用户选择的范围是硬边界；AI 不得扩大范围、替用户确认或修改其他课程。

### 3.6 教学设计工作台

每门课程只有一份正式结构化 `CourseTeachingPlan`。文件空间中的“教案”是它按课次编辑、确认或导出的教学文档投影，不另外建立一份平行 Markdown 真源。全课设计描述课程定位、对象、起点、目标、策略、评价和章节责任；分小节设计描述教学路径、知识、能力、易错、掌握标准和课程块职责。

教案编辑必须遵守：

- 可变草稿与不可变正式修订分离，自动保存不等于正式应用。
- 手工修改和 AI 改写都先成为结构化候选。
- 应用前展示字段差异、影响对象、保持不变对象和阻断项。
- 稳定知识 ID、来源绑定、目录结构和系统质量字段不能被普通字段编辑绕过。
- 正式应用后，下游正文、练习、PPT 和其他表达按影响范围进入复用、过期或重建状态。

## 4. 领域真源

一件事实只能有一个拥有者。其他页面、Store、缓存和文件都是投影或兼容适配。

| 事实 | 唯一真源 | 允许的投影 | 禁止的平行真源 |
| --- | --- | --- | --- |
| 当前课程结构与正文 | `CourseDocument` | 目录、阅读正文、旧课程只读视图 | 完整 Markdown、页面本地课程副本 |
| 课程教学设计 | `CourseTeachingPlan` | 总体教案、分小节教案、生成约束 | 独立 Markdown 教案、课程蓝图副本 |
| 当前课程知识 | `CourseKnowledgeBase` | 知识图谱、标签、AI 上下文切片 | 跨课程运行时知识身份、章节标题伪知识点 |
| 正式题目与答案合同 | 版本化题库修订及私有解答合同 | 学生题面、教师题库、练习任务 | 前端答案、旧测验 Store、题目内隐藏评分条件 |
| 正式作答 | `PracticeAttempt` | 错题本、练习反馈、掌握证据 | 本地完成状态、组件内作答历史 |
| 学习行为事实 | `LearningEvent` | 学习进度、诊断输入、统计 | 节点 `is_read`、本地进度副本 |
| 学习现场位置 | `LearningSnapshot` | 续学入口、滚动恢复 | 用快照代替学习事件 |
| 笔记与问答记录 | `LearningRecord` | 正文行内记录、记录总览 | annotation 副本、组件本地笔记库 |
| 当前学习者状态 | `LearnerModel` | 掌握、困难、偏好和策略投影 | AI 对话摘要直接写入掌握事实 |
| 课程调整建议 | `CourseEvolutionPlan` | 侧栏候选、审阅工作台、影响预览 | 每个入口一套候选和确认状态 |
| 教学表达 | `TeachingRepresentation / RepresentationSet` | PPT、讲义、图解、音频等 | 独立漂移的第二课程正文 |

### 4.1 `CourseDocument`

`CourseDocument` 是当前正式课程的唯一语义容器，至少承载：

- 稳定课程身份和文档修订。
- 有序章节、分组和课程块。
- 课程块与目标、知识、来源及派生表达的绑定。
- 历史引用所需的稳定 ID 和修订信息。

用户感知的是“当前课程 + 可撤销操作”，不是版本包。历史修订用于冲突、追溯、撤销和效果比较，不成为顶层产品概念。

### 4.2 `CourseBlock`

`CourseBlock` 是课程内最小稳定教学单元。每个块必须区分：

- `kind`：内容怎样呈现，例如富文本、公式、代码、图片、图表、表格、题目引用、项目或复习检查点。
- `role`：内容承担什么教学作用，例如定向、前置、概念、推理、例子、反例、应用、反馈、易错、检查、补救、总结或迁移。
- `payload`：当前类型的结构化内容。
- `source_refs` 与语义绑定：内容依据什么、服务哪个目标和知识。
- 稳定块 ID、内容修订和指纹：支持影响分析、锚点迁移与幂等命令。

`kind` 与 `role` 不能合并。相同呈现形式可以承担不同教学作用，相同教学作用也可以由不同形式表达。

所有正式新增、替换、退休、恢复、移动、拆分和合并必须通过课程领域命令，路由和 UI 不得直接改写课程文件。

### 4.3 课程知识库

`CourseKnowledgeBase` 严格属于单门课程，保存该课程实际教授的概念组、原子知识、能力、易错、掌握标准、关系和精确教学绑定。

- 学科知识库可以提供术语、别名和生成校准，但不能替换当前课程知识 ID。
- 知识无法确认时必须暴露待审阅或阻断，不能复制标题伪造知识点。
- 普通表达调整不写知识语义；确需拆分、合并、重命名或改关系时进入知识维护候选和质量门。
- 学习结果、课程知识变化和运行时读取都不得跨课程传播。

### 4.4 学习事实与证据

原始事实、教学解释和正式状态必须分层：

```text
LearningEvent / LearningRecord / PracticeAttempt
-> EvidenceItem
-> AdaptationHypothesis
-> LearnerModel 或 CourseEvolutionPlan
```

- 原始证据保留来源、时间、课程、知识和发生时修订。
- AI 可以解释证据，但不能把推断伪装成事实。
- 单条明确强证据可以触发局部候选；范围越广，需要的独立一致证据越强。
- 掌握结论依赖可判定的正式表现；自述、聊天和一次成功只能提供不同强度的支持。

## 5. 四层产品模型

### 5.1 实体层

实体层保存可追溯事实：课程、教案、课程知识、学习目标、课程块、正式题目、作答、学习事件、学习快照、学习记录、学习者模型、调整方案和教学表达。

实体层必须回答：谁拥有这项事实、当前修订是什么、来源是什么、谁可以修改、失败后保留什么。

### 5.2 功能层

功能层只组合实体能力，不拥有第二份事实：

- 课程库：创建、导入、恢复、进入。
- 课程生产：需求、目录、生成、质量与发布。
- 教师端主空间：日历首页、课程文件空间和正式课程预览；教案、PPT 等工作台由其文件入口打开。
- 学习运行时：续学、正文、任务、记录、知识和 AI 协调。
- 课程调整：证据解释、范围候选、审阅、应用、撤销和复验。
- 表达工作台：从课程编译、编辑、检查和导出教学表达。

### 5.3 逻辑层

逻辑层负责稳定因果关系：

- 课程生产链和检查点恢复。
- 课程、教案、知识、题目和表达的修订向量。
- 正式题目质量、答案可判定性与私有解答隔离。
- 学习事件到进度、诊断、掌握和续学动作的投影。
- 证据强度、调整范围、影响分析和课程命令。
- 表达来源绑定、过期传播、最后可用版本和降级。

### 5.4 AI 能力层

AI 只承担不能由确定性代码可靠替代的语义工作：课程结构与内容表达、受约束的证据解释、教学候选和局部重写。

稳定 ID、版本冲突、权限、范围、来源绑定、质量门、命令应用、恢复和发布由系统控制。模型输出必须进入结构化协议、白名单与校验链，不能直接成为正式事实。

## 6. 五条正式运行链

### 6.1 课程生产链

```text
目标与资料
-> 需求合同
-> 目录骨架与有界批次
-> 唯一全课教案
-> 本地编译课程知识、稳定身份与块职责
-> 分单元生成正文
-> 编译并定向补齐正式练习
-> 确定性质量门
-> 用户确认发布
-> CourseDocument
```

课程规模只增加工作单元数量，不产生另一套生成协议。模型失败、进程重启或网络中断时保留已完成单元和最后可用产物。

### 6.2 学习运行链

```text
CourseDocument + 当前课程知识
+ LearningEvent + LearningSnapshot + LearningRecord + PracticeAttempt
-> LearningRuntime
-> 当前内容、活动任务、状态摘要和唯一下一动作
```

`LearningRuntime` 是无独立存储的协调投影，不能成为第七套状态仓库。

### 6.3 正式练习链

```text
教学目标与课程知识
-> 出题意图
-> 公开题面合同 + 私有解答合同
-> 独立求解与确定性领域验证
-> 质量门与发布策略
-> PracticeAttempt
-> 正式评分 + 受约束的作答诊断
-> 补救、再练和独立复验
```

学生题面不能泄露答案、量规、隐藏测试或验证器参数。评分回答“是否达标”，诊断回答“当前答案表现出什么差距”；没有证据时不得反推学生未表达的思考过程。

专项合同、阈值和回归指标由[通用题目生成评测](./评测/通用题目生成与质量闭环.md)维护。

### 6.4 课程生长链

```text
当前课程内的真实证据
-> 证据解释与反证
-> 范围受限的调整方案
-> 内容、知识和下游影响预览
-> 用户部分或整体确认
-> 原子课程命令与幂等回执
-> 新课程修订
-> 独立效果复验
```

确认前正式课程不变。部分接受必须重算依赖；冲突、过期和无法安全恢复必须明确返回，不能半应用或静默扩大范围。

### 6.5 教学表达编译链

```text
当前课程修订 + 教案 + 知识 + 来源绑定
-> RepresentationPlan
-> typed spec
-> renderer / provider
-> 质量门
-> RepresentationSet
```

浏览器预览与导出必须消费同一最终语义结构。高成本或不可靠表达可以降级为完整文字、静态图或最后可用版本，但不能让课程本身不可学习。

## 7. 交互与 AI 边界

### 7.1 交互先于入口

新增能力先回答用户正在完成什么任务、在什么上下文触发、怎样控制和退出，再决定载体。正文边缘、原位展开、覆盖层、右侧 AI、全宽工作台和独立页面只是候选，不应从功能名直接推导新页面。

所有用户可见能力必须：

- 贴近来源对象并保持返回位置。
- 默认暴露最小必要信号，理由、范围、历史和高级控制按需展开。
- 清楚说明为什么出现、将影响什么、哪些保持不变。
- 覆盖加载、空、成功、失败、冲突、过期、取消、恢复和只读降级。
- 同步维护中文、英文、桌面、移动端和无障碍状态。

### 7.2 AI 老师

AI 老师是同一课程内的协作界面，不是第二个产品或万能写入入口。

- 只读取当前任务所需的最小上下文。
- 区分回答、建议、候选和正式动作。
- 正式动作使用白名单、修订检查、幂等键和结构化回执。
- 模型不可用时，课程阅读、已有练习、记录和已保存候选继续可用。
- 涉及最新事实时必须读取可信时效资料，不能用模型记忆冒充当前证据。

### 7.3 用户控制权

- AI 可以主动提出课程改进，但不能替用户确认。
- 用户可以接受、拒绝、重生、补充要求、部分接受、撤销和恢复。
- 系统必须显示证据、理由、范围、影响和保持不变项。
- 撤销是领域补偿或新修订，不通过覆盖整门旧课程快照破坏后续事实。

## 8. 不可违反的产品边界

1. 一件事实只能有一个正式真源。
2. 当前课程正文以 `CourseDocument + CourseBlock` 表达，完整 Markdown 只用于导入、导出和旧课程兼容。
3. 教案、知识库、正式题目、学习事实和教学表达各自拥有清楚边界，不能互相复制成为真源。
4. 正式课程变化只能通过统一课程领域命令完成。
5. AI 输出、对话、笔记和自述不能直接成为掌握事实或正式课程内容。
6. 个性化只修改当前 `course_id`，不跨课程共享运行时知识或学习结果。
7. 教学表达从课程派生，表达编辑与语义编辑必须分流。
8. 正式题目的公开题面与私有答案、量规、隐藏测试严格隔离。
9. 失败、降级、待审阅、质量通过和正式发布必须是不同状态。
10. 用户不需要理解内部版本树、Prompt 版本、模型调用策略和修订实现。
11. 学生不获得课程块编排工作台；AI 可以生成候选，用户控制是否应用。
12. 旧链只能作为读取或迁移适配，不得继续生长新的写入规则。

## 9. 异常与降级

| 场景 | 必须行为 | 禁止行为 |
| --- | --- | --- |
| 模型不可用 | 保留已完成单元、检查点和最后可用产物，提供明确恢复动作 | 清空整门课程、伪造 AI 成功 |
| 资料不足或冲突 | 标记缺口、降低来源置信度、请求补充或进入审阅 | 用模型常识冒充指定资料事实 |
| 课程修订冲突 | 重新定位候选或返回过期冲突 | 覆盖新修订、静默丢失用户修改 |
| 知识引用失效 | 阻止正式应用或进入知识维护候选 | 自动复制标题生成新知识 ID |
| 题目质量失败 | 隔离候选并保留当前有效题目修订 | 把坏题重新放回学生题池 |
| Runner 或验证器不可用 | 实现题失败关闭，其他可验证题型继续 | 后端假装运行隐藏测试 |
| 表达生成失败 | 使用完整文字、静态替代或最后可用表达 | 阻断课程阅读、发布空白产物 |
| 学习锚点歧义 | 留在学习记录总览并提示重新定位 | 把记录强插到错误正文 |
| 服务重启 | 根据持久检查点对账并只恢复未完成单元 | 重做全部已完成工作 |
| 旧课程缺少新合同 | 只读适配或显式迁移，功能降级可解释 | 双写旧对象和新对象 |

## 10. 兼容与演进

- 新课程只写当前正式对象；旧对象只读适配，迁移必须幂等并可审计。
- 兼容接口必须声明读取真源和写入目标，不能把兼容层当作长期业务入口。
- 新增实体、API、Store、路由或状态机时，必须说明现有对象为何不能承载、谁拥有状态、谁消费、旧链何时退出。
- 产品语义稳定但实现协议可演进；版本号、迁移细节和当前代码链维护在架构文档、OpenSpec 和状态板。
- 外部研究和 Demo 只有回写本文或正式规格后才改变产品方向；录屏脚本不得创造生产系统不存在的业务事实。

## 11. 长期建设顺序

`P0-P6` 表示产品与工程的前置依赖，不是严重程度、商业优先级或允许一次性自动执行的任务列表。当前成熟度和主攻位置只看[产品状态](./产品状态.md)，具体施工只看活动 OpenSpec。

| 层级 | 必须先回答的问题 | 稳定产物 | 下一层解锁条件 |
| --- | --- | --- | --- |
| P0 可信执行与真源基座 | 系统能否稳定开发、验证、恢复并隔离数据 | 可复现运行时、质量门、数据边界、接口和状态所有权 | 领域改造能够区分产品缺陷、环境问题和测试污染 |
| P1 课程语义内核 | 课程、教案、知识、题目和表达由谁拥有 | `CourseDocument`、正式课程命令、稳定知识与来源引用 | 课程可被安全修改且不产生平行真源 |
| P2 学习证据与诊断内核 | 系统依据什么理解学习过程 | 正式学习事实、证据坐标、可重算学习者模型和诊断 | 课程调整能够指出来源、置信度和反证 |
| P3 可审阅课程生长 | 怎样把证据变成受控课程变化 | `CourseEvolutionPlan`、影响预览、用户确认、撤销和恢复 | 任意已支持范围都能原子应用或拒绝，不产生半修改 |
| P4 同源表达与完整学习现场 | 修改后所有教学表达和学习入口怎样一致 | 来源绑定的教案、正文、练习、PPT、图解及统一运行时 | 变化能精准重建，失败保留最后可用表达 |
| P5 效果验证与长期循环 | 怎样证明课程调整真的有效 | 独立复验、效果比较、失败回退和长期样本 | 调整不再以“已接受”冒充“已改善” |
| P6 课程原生 Agent | AI 怎样组合成熟能力完成复杂目标 | 受白名单、证据、确认、领域命令和效果门约束的 Agent | Agent 只能组合已成熟闭环，不能绕过它们 |

唯一内在顺序是：先让系统可信，再让课程可改；先让证据可信，再让调整发生；先让调整进入真实教学与学习现场，再验证效果；最后才把成熟能力交给 Agent 组合。

## 12. 产品完成门

只有以下条件同时成立，灵知的目标产品才算完成：

1. 任意课程都能由稳定、有序、异构 `CourseBlock` 表达，且课程修改不会静默破坏学习记录与历史作答。
2. 课程生成、教师语义修改和经确认的个性化调整共用同一个课程领域内核。
3. 教案、课程知识、正文、正式题目和教学表达之间具有可验证的来源与修订关系。
4. 阅读、练习、笔记、错题、复习、知识图谱和 AI 老师共用同一学习运行时，不建立平行状态。
5. 所有正式题目都能证明为什么出、考什么、怎样判定，并隔离私有答案与隐藏验证。
6. 原始证据、AI 假设、学习者状态和课程调整严格分层，任何结论可回到来源。
7. 单条强证据可触发局部候选，广域修改需要更强范围依据；反证能够缩小或撤销判断。
8. 用户可以理解、选择、拒绝、部分接受、撤销和恢复课程变化，系统不会半应用。
9. 课程变化后，受影响教学表达能精确复用、过期、重建或安全降级，不产生跨表达漂移。
10. AI、媒体、图表、代码执行、评分或网络失败时，课程仍可继续学习并明确恢复。
11. 旧课程和旧入口通过只读适配或幂等迁移进入同一内核，不再产生第二条写链。
12. 至少有多门跨学科真实课程证明完整生产与学习链，并有长期样本证明课程调整带来改善或触发安全回退。
