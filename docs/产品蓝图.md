## 1. 产品定义

### 1.1 产品定位

灵知是一套以结构化课程为核心，连接教师课程生产、统一学习现场、学习证据驱动的课程生长，并能从同一课程语义编译多种教学表达的 AI 课程系统。

它不是一次性课程生成器，也不是把聊天、题库、笔记和 PPT 拼在一起的工具箱。它要让一个真实学习目标形成可长期运行的闭环：

```text
目标、资料与学习起点
-> 结构化当前课程
-> 教案、讲稿、练习、PPT 与图解等同源教学产物
-> 阅读、提问、笔记、作答与项目表现
-> 有来源、有知识坐标的学习证据
-> 可反驳的教学判断与课程调整候选
-> 用户审阅并确认
-> 当前课程及受影响产物安全更新
-> 独立任务验证调整效果
-> 新证据进入下一轮课程生长
```

### 1.2 核心用户与任务

灵知服务两个围绕同一课程真源协作的角色：

- 课程创建者和教师：从目标、资料与教学约束创建课程，审阅并修改大纲、教案、讲稿、题库和 PPT，安全发布并继续修订。
- 学习者：围绕真实目标进行系统学习、项目实战、问题探究或考试准备，在同一现场阅读、练习、提问、记录并获得可解释的课程调整。

两类角色共享同一个课程身份和正式课程，但权限、入口与任务不同。灵知不扩张为班级管理、多人协作或学校文件管理平台。

产品必须闭合四类连续任务：

1. 从目标、资料和教学约束得到一门结构清楚、可审阅、可恢复的课程。
2. 让教师持续编辑各类教学产物，并看见上游修改对下游的真实影响。
3. 让学习者在同一现场完成阅读、练习、提问、记录和项目，不在工具之间搬运上下文。
4. 让课程依据真实学习证据安全调整，并用独立结果判断调整是否有效。

### 1.3 产品北极星

唯一北极星是**可验证学习闭环完成率**：

```text
有来源证据、形成正式课程修订并获得独立效果结果的已接受调整数
/
全部已接受课程调整数
```

生成数量、AI 对话数量、课程时长、PPT 页数和页面访问量只能解释过程，不能证明学习闭环成立。

### 1.4 产品范围

- 不做 LMS、班级管理、多人协作、课程商城、内容广场或社交网络。
- 不新增与课程库、课程工作区、AI 老师平行的顶层功能中心。
- 不让用户管理内部版本树，不建立长期覆盖正式课程的个人 Overlay。
- 不让 Agent 绕过证据、用户确认和正式命令直接改写课程。
- 不先做自由视频、数字人或 Skill 市场，再倒推课程语义。
- 不用单门样板课程、一次模型成功或局部测试代替跨学科与长期效果验证。

## 2. 教学体系设计

教学体系设计定义“灵知教什么、怎样教、怎样判断学会，以及不同教学对象如何组合”。本章所说的“完整教学语义”，指灵知当前产品支持并会约束大纲、教案、讲稿、练习、PPT 和课程生长的全部稳定语义，不试图穷尽世界上所有教育理论。

页面、Prompt、代码和模型只能实现这些定义，不能临时创造另一套教学分类、关系或质量标准。

### 2.1 共同教学原则

无论课程类型和学科怎样变化，灵知都遵守以下共同原则：

| 原则 | 产品语义 | 直接约束 |
| --- | --- | --- |
| 从成果反推 | 先明确学习者最终要解释、完成、判断或创造什么，再设计证据、活动和内容 | 大纲不能先罗列知识点再补目标；教案必须先有目标和达成检查 |
| 学科方法成立 | 不同学科用不同方式建立知识、证据和专业判断 | 数学不能用直觉替代定义，工程不能只讲概念，人文不能把解释写成唯一事实 |
| 主动加工 | 学习者必须计算、实现、分析、表达、操作、讨论或创造，不能只接收信息 | 每讲至少有与目标对应的学习者行动 |
| 讲解—行动—反馈闭环 | 解释和示范必须进入学习者行动，行动必须得到核对、反馈或修正 | 讲稿、练习和教案不能彼此断开 |
| 支架逐步撤除 | 新手先获得分步示范和提示，随后过渡到独立完成和迁移 | 难度变化不能只换“简单/困难”措辞 |
| 证据与判断分开 | 作答、作品和行为是事实；掌握判断、教学解释和课程建议是可修正结论 | 自述不能直接写成已掌握，AI 解释不能冒充学习事实 |
| 迁移而非复述 | 真正学会表现为能够在条件变化后选择、解释并使用所学 | 总结不能代替迁移任务，变式不能只替换数字或名词 |
| 教师最终控制 | AI 提供结构、内容和建议，教师决定教学目标、课型、教学块与正式结果 | 推荐必须可修改、拒绝、撤销和恢复 |

灵知不要求每节课使用同一教学法。共同原则负责守住底线，教学类型负责整课组织，学科类型负责专业方法，本讲课型和教学块负责把它们落到当前课堂。

### 2.2 教学语义词典与课程层级

#### 2.2.1 课程教学层级

```text
课程
├── 章：组织整门课知识、能力或任务的结构单位
│   └── 讲（LessonUnit）：备课、授课、资料作用域、失败恢复和版本边界
│       └── 讲内小节：本讲内容的编辑和呈现单位
│           └── 教学块：课堂中实际发生的教学环节
```

一章可以安排多讲，一讲可以覆盖一个或多个知识小节。课程大纲决定“整门课讲什么以及怎样展开”；教学日历决定“何时、何地、由谁上”；本讲课型和教学块决定“一讲怎样组织”；教案、讲稿、练习和 PPT 分别承担不同教学职责。

现有代码或历史数据把章、讲和小节折叠时，只能通过兼容投影读取；新产品定义不得继续混用这些身份。

#### 2.2.2 正式术语

| 术语 | 回答的问题 | 作用范围 | 是否直接给教师选择 |
| --- | --- | --- | --- |
| 课程类别 | 这门课在教务上属于什么 | 教务档案 | 是，但不参与教学编排 |
| 课程规模 | 这门课承诺覆盖多少 | 全课程 | 由课时与范围共同确定，教师可修正 |
| 目标难度 | 学习者最终需要在多大挑战和独立程度下完成 | 全课程并投影到各讲 | 是，入门、进阶、高阶 |
| 教学类型 | 整门课围绕什么主线组织 | 全课程 | 是，一门课一个主要类型 |
| 学科类型 | 知识主要通过什么专业行为成立 | 全课程 | AI 推荐，教师可锁定或修改 |
| 学科细分 | 同类学科中的专业差异是什么 | 全课程或稳定课程片段 | AI 推荐，教师可修改 |
| 第二学科 | 是否需要另一种学科行为共同完成目标 | 全课程或局部 | 需要时显式确认 |
| 高层教学设计偏好 | 课程希望呈现什么气质和能力重心 | 全课程 | 是，少量教师语言选项 |
| 课程编排节奏 | 讲解、案例、项目、探究等教学块怎样分布 | 全课程与各讲 | 由类型、学科和偏好共同编译，不形成平行菜单 |
| 课程阶段 | 当前内容处于引入、奠基、发展、整合还是成果阶段 | 章与讲 | 系统判断，教师通过结构调整改变 |
| 学科教学原型 | 当前内容最适合用哪种学科教学动作完成 | 小节与讲 | 内部推荐语义，不形成平行菜单 |
| 本讲课型 | 当前一讲在教师看来具体怎样上 | 讲 | 是，七种教师可见课型 |
| 教学块 | 课堂按什么顺序发生哪些环节 | 讲 | 是，可增删、排序和修改 |
| 教学产物 | 教学设计和内容以什么正式形式保存、审阅和使用 | 全课或讲 | 通过工作台操作 |
| 学习成果证据 | 用什么可观察结果判断目标是否达成 | 目标、讲与课程 | 教师确认，学习过程产生 |

这些术语不能互相替代。尤其要区分：教学类型不是学科类型，学科教学原型不是教师课型，教学块也不是正式课程正文中的 `CourseBlock`。

### 2.3 教学对象、课程规模与实施条件

#### 2.3.1 教学对象与学习起点

教学对象描述课程面向哪一类人，例如教育阶段、专业背景、语言水平、年龄或职业场景；学习起点描述这批学习者当前已经具备什么、缺少什么以及证据来自哪里。二者不能混为“用户画像”。

- 教师明确提供的教学对象和前置要求是课程设计约束。
- 学习者自述、访谈和历史表现必须标明证据来源；仅有自述时只能形成暂定起点。
- 已有优势可以减少重复讲解，但必须保留检查点；未知能力不能默认已掌握。
- 共性课程基线服务目标人群，个体差异通过支架、节奏、练习和经确认的课程调整处理，不建立个人平行课程正文。

#### 2.3.2 课程规模与覆盖承诺

课程规模决定可以诚实承诺的覆盖范围，不直接决定教学类型或难度：

| 课程规模 | 语义 | 可以承诺 | 必须说明 |
| --- | --- | --- | --- |
| 微型课 | 围绕一个可检查的核心切面完成短闭环 | 核心概览、入门或专题成果 | 本次不覆盖什么，不得自称完整学科课程 |
| 单元课 | 完整覆盖一个相对独立的知识或能力模块 | 一个单元的目标、结构与综合任务 | 单元边界以及与前后模块的关系 |
| 完整学期课 | 覆盖学科主干结构并形成跨章综合成果 | 主干知识、能力与阶段评价 | 仍未覆盖的进阶、选修或特殊范围 |

规模只改变覆盖宽度、讲次数量和内容密度，不降低专业标准。短课也必须有目标、必要前置、教学行动和检查；长课也不能为了“完整”堆积无关章节。精确课时阈值由正式技术合同维护，蓝图只规定覆盖语义。

#### 2.3.3 实施条件

总课时、单讲时长、班级规模、线上/线下环境、可用设备、资料许可、安全要求、考试日期和学校模板等实施条件会限制“怎样教”，但不能由模型静默改变。

- 总课时和单讲时长决定内容容量与教学块时长，容量不足时必须缩小范围或增加课时。
- 班级规模影响讨论、展示、反馈和协作方式，不改变目标和学科标准。
- 工具、实验、代码执行或联网条件不足时，必须提供可解释替代方案或阻断相关活动。
- 医学、实验、代码执行、隐私和外部资料使用遵守各自安全边界。
- 资料是知识和案例来源，不自动决定教学结构；资料冲突、缺失或时效不足必须显式标记。

### 2.4 四种教学类型

教学类型决定整门课的第一组织原则。它不改变学科如何建立知识，但会改变章节顺序、阶段成果、课型分布和评价节奏。

| 教学类型 | 核心组织问题 | 典型推进路径 | 主要输入 | 完成证据 | 不得退化为 |
| --- | --- | --- | --- | --- | --- |
| 系统学习 | 学习者要系统掌握哪个知识领域 | 知识地图 → 先修关系 → 基础到进阶 → 综合应用 | 学习目标、目标范围、已有基础、课程规模 | 能解释核心关系，并在综合任务中迁移使用 | 零散主题合集、百科目录 |
| 项目实战 | 学习者要完成什么项目，为此需要补齐什么 | 项目目标 → 交付物 → 里程碑 → 能力缺口 → 学习与验证 | 项目目标、交付物、约束、已有经验和不确定项 | 完成可检查成果，并说明关键决策与验证依据 | 普通知识目录外加一个期末项目 |
| 问题探究 | 学习者要回答什么核心问题 | 界定问题 → 子问题与假设 → 组织证据 → 检验解释与反例 → 有边界结论 | 核心问题、已有认识、证据范围和期望输出 | 形成可追溯证据、能说明限制的回答 | 把普通章节标题改成问句 |
| 考试冲刺 | 在有限时间内，哪些考纲能力最需要补齐 | 范围与准备度诊断 → 优先复习 → 专项练习 → 限时模拟 → 考前巩固 | 考试范围、时间、当前准备度和目标水平 | 分阶段检查与模拟任务达到目标准备度 | 平均复习全部内容、题海堆积 |

类型专属规则：

- 系统学习必须保持知识和能力的先修关系，课程结尾必须有跨章综合应用。
- 项目实战的每个阶段必须同时包含必要知识、实践动作和可检查产出；学习者自述经验只能暂定压缩，并在项目任务中验证。
- 问题探究必须允许证据改变原有认识，结论强度不得超过证据范围。
- 考试冲刺的优先级由考纲覆盖、剩余时间和薄弱程度共同决定，诊断和模拟必须能够校正最初判断。

教学类型与本讲课型是“分布倾向”，不是一一绑定：

| 教学类型 | 高频本讲课型 | 全课必须形成的结构 |
| --- | --- | --- |
| 系统学习 | 理论讲授、理论与实践、实践操作、复习测评 | 先修递进、阶段整合与最终迁移 |
| 项目实战 | 项目工作坊、实践操作、理论与实践、案例研讨 | 每个里程碑都连接必要知识、制作行动、检查和修订 |
| 问题探究 | 实验探究、案例研讨、理论讲授、理论与实践 | 问题、假设、证据、反例和有边界结论不断回环 |
| 考试冲刺 | 复习测评、理论与实践、实践操作 | 诊断、针对性补救、限时练习、模拟和策略复盘 |

### 2.5 八种学科类型

学科类型回答“在这个领域，什么算解释、什么算证据、什么算专业行动”。它约束内容、案例、练习、评价和讲稿语言。

| 学科类型 | 核心专业行为 | 基本教学链 | 代表性成果证据 | 硬边界 |
| --- | --- | --- | --- | --- |
| 通用课程 | 建立概念、执行方法、比较判断并应用 | 概念/方法 → 例子 → 行动 → 应用与迁移 | 能解释核心概念并完成真实应用任务 | 不能退化成百科介绍；必须能够实际使用 |
| 数学与形式科学 | 定义、表示、推导、求解、证明和建模 | 直觉 → 正式定义 → 完整推理/例题 → 变式 → 错误分析 | 独立求解、证明或形式化建模 | 直觉不能替代定义；推导和例题必须逻辑一致 |
| 编程与工程技术 | 需求分解、实现、运行、调试、测试和取舍 | 可运行示例 → 机制 → 修改 → 故障与质量 → 工程成果 | 可运行、可测试、可解释的工程交付物 | 不能只贴代码或只讲概念；版本和环境前提必须明确 |
| 自然科学 | 观察、提出问题、建立模型、组织证据和预测 | 现象 → 问题/假设 → 模型 → 实验/数据 → 解释、边界与应用 | 用模型和证据解释或预测现象 | 现象、模型、证据和结论必须分开；必须说明适用边界 |
| 生命科学与医学基础 | 在正确尺度连接结构、功能、机制、调节和证据 | 定位与结构 → 功能 → 机制 → 系统调节 → 案例与数据 | 解释生命过程或基础医学案例并说明不确定性 | 结构、功能和机制不能混写；不得给个人诊断或治疗建议 |
| 人文社科 | 提问、材料辨析、语境化、因果解释、观点论证 | 核心问题 → 语境与材料 → 解释/比较 → 论证 → 综合表达 | 有材料依据、能回应异议的分析或论证 | 事实、材料、观点和解释必须分开；争议不能写成唯一事实 |
| 语言学习 | 理解输入、注意形式、练习、互动、调解和修正 | 可理解输入 → 语块/形式 → 受控练习 → 真实输出 → 反馈修正 | 在目标情境中完成可理解、得体的真实表达 | 不能长期停留在单词和语法讲解；每章必须有真实输出 |
| 商业与职业技能 | 场景诊断、框架选择、案例决策、工具使用和成果交付 | 角色与约束 → 问题诊断 → 方法/工具 → 决策或行动 → 指标与复盘 | 可评价的业务方案、分析、沟通或决策成果 | 不能只讲框架和口号；活动完成不等于成果合格 |

### 2.6 学科细分与跨学科组合

#### 2.6.1 学科细分

学科细分不是课程名称标签，而是同一学科类型内部的稳定教学差异。每个细分会影响优先采用的学科教学原型：

| 学科类型 | 学科细分 | 适用语义 | 优先教学原型 |
| --- | --- | --- | --- |
| 通用课程 | 概念理解型 | 以概念、原理、关系和判断为主 | 概念建构、比较与判断 |
| 通用课程 | 方法应用型 | 以方法、流程、技能和实际操作为主 | 方法工作坊、案例应用 |
| 数学与形式科学 | 理论与证明 | 以定义、定理、逻辑、证明和形式关系为主 | 直觉与多重表征、证明与论证 |
| 数学与形式科学 | 计算与建模 | 以求解、统计、优化、建模和数据关系为主 | 解题策略、建模探究 |
| 编程与工程技术 | 编程基础 | 建立语法、程序结构、算法入门和运行反馈 | 最小运行闭环、引导式实现 |
| 编程与工程技术 | 软件工程与系统 | 处理系统、架构、服务、数据、网络和部署 | 引导式实现、测试与重构、项目与架构 |
| 编程与工程技术 | 数据与人工智能工程 | 处理数据、模型训练、推理、评估和工程质量 | 引导式实现、调试实验、测试与重构 |
| 自然科学 | 物理模型型 | 用变量、定律和模型解释或预测现象 | 现象探究、模型解释、证据论证 |
| 自然科学 | 实验探究型 | 通过实验、测量、对照和数据验证问题 | 现象探究、实验调查 |
| 自然科学 | 环境与工程应用 | 把自然科学模型用于环境、能源、地质或设计问题 | 实验调查、设计与应用 |
| 生命科学与医学基础 | 生命系统 | 连接细胞、个体、生态等尺度上的结构、机制和变异 | 结构与功能、机制与系统、比较与变异 |
| 生命科学与医学基础 | 医学基础 | 连接解剖、生理、病理、免疫、健康与机制证据 | 结构与功能、机制与系统、案例推理 |
| 人文社科 | 历史探究 | 围绕材料、时间、因果和变化形成历史解释 | 问题与语境、材料解释、因果与变化 |
| 人文社科 | 文本与文化解释 | 围绕文本、作品、文化语境和解释形成表达 | 材料解释、观点论证、综合表达 |
| 人文社科 | 哲学与规范论证 | 围绕概念、前提、价值、规范和异议进行论证 | 问题与语境、观点论证 |
| 人文社科 | 社会科学探究 | 围绕社会现象、研究材料、理论和公共问题形成解释 | 问题与语境、材料解释、观点论证 |
| 语言学习 | 日常交际 | 在日常角色、信息差和具体目的中完成交流 | 可理解输入、互动任务 |
| 语言学习 | 学术与职业沟通 | 处理专业文本、写作、演讲、转述和跨文化沟通 | 调解与转述、表现与修正 |
| 商业与职业技能 | 战略与运营 | 处理产品、运营、项目、组织和供应链决策 | 场景诊断、案例决策、成果交付与复盘 |
| 商业与职业技能 | 市场与沟通 | 处理营销、销售、谈判、品牌、客户和职业沟通 | 场景诊断、角色模拟 |
| 商业与职业技能 | 分析与财务决策 | 处理指标、数据、财务、投资和商业分析 | 工具工作坊、案例决策 |

#### 2.6.2 主学科与第二学科

一门课必须有一个主学科类型；只有完成目标确实需要另一种专业行为时，才增加第二学科：

| 组合强度 | 语义 | 结果要求 |
| --- | --- | --- |
| 轻量补充 | 第二学科只在少数内容中提供局部方法或表达 | 主学科成果不变，局部教学块增加第二学科护栏 |
| 协同支撑 | 两种学科行为在多个讲次中共同完成同一成果 | 关键讲次必须同时出现两种行为及其检查 |
| 双核心 | 两种学科能力都是课程最终成果不可缺少的部分 | 大纲、综合任务和评价必须分别证明两种能力，并检查它们的整合 |

教师明确锁定的主学科优先于自动识别。第二学科不能因为标题中出现某个词就自动升级；系统必须说明为什么需要、影响哪些讲次以及增加什么成果证据。

### 2.7 课程阶段与学科教学原型

#### 2.7.1 五个课程阶段

| 课程阶段 | 教学责任 | 典型成果 |
| --- | --- | --- |
| 引入 | 建立目标、问题、情境和学习必要性 | 能说清要解决什么、为什么值得学 |
| 奠基 | 建立必要概念、方法、表征、工具和前置能力 | 能完成带支架的基础解释或任务 |
| 发展 | 扩展关系、难度、案例、证据和独立行动 | 能独立完成相邻任务并解释过程 |
| 整合 | 连接多个知识或能力，比较方法并处理复杂约束 | 能在新情境中选择、组合和迁移 |
| 成果 | 形成综合作品、论证、项目、表现或考试准备度 | 能以明确标准提交、说明、修订和验证成果 |

阶段不是固定章节名称，也不是所有课程必须平均分配。微型课可以在一讲内完成缩短的五阶段闭环，完整学期课则会跨章反复形成局部闭环并走向全课成果。

#### 2.7.2 学科教学原型

学科教学原型是“当前内容最适合用什么专业教学动作完成”的细粒度语义。它服务系统推荐和教学块组合，不作为教师必须逐一理解的第二套课型菜单。

##### 通用课程原型

| 原型 | 教学目的 | 成果证据 | 关键护栏 |
| --- | --- | --- | --- |
| 概念建构 | 建立概念、关系和边界 | 能用自己的话解释，并用例子与反例划界 | 概念围绕问题组织；例子不能代替边界 |
| 方法工作坊 | 把方法拆成可执行步骤并逐步撤除支架 | 能脱离示范，按条件选择并执行方法 | 清单服务判断；步骤包含结果检查 |
| 比较与判断 | 比较多个对象或方案的条件、证据和取舍 | 能依据共同标准选择并说明理由 | 不无原则折中；结论回到使用条件 |
| 案例应用 | 把概念或方法用于有约束的案例 | 能完成案例判断并说明概念与事实的映射 | 案例不能只是故事；虚构情境必须标明 |
| 综合迁移 | 整合前序能力解决条件变化的新问题 | 能独立完成成果并说明选择、边界和自检 | 章节摘要不算迁移；必须改变情境或约束 |

##### 数学与形式科学原型

| 原型 | 教学目的 | 成果证据 | 关键护栏 |
| --- | --- | --- | --- |
| 直觉与多重表征 | 从问题或表征建立直觉，再连接定义、符号和条件 | 能在文字、图形、符号或数值表征间转换并说明不变量 | 直觉不能替代定义；各表征指向同一对象 |
| 解题策略 | 用完整例题呈现策略选择、推理和结果检查 | 能独立求解条件变化后的相邻问题并解释选法 | 不只展示步骤；变式不能只换数字 |
| 证明与论证 | 围绕命题条件建立推导链并比较证明思路 | 能补全或构造证明并指出每一步条件 | 不隐藏关键跳步；区分例证与证明 |
| 错误诊断 | 用典型错误定位误用的定义、条件或推理 | 能诊断、修复并构造暴露误区的反例 | 不只公布答案；错误必须可信且能定位原因 |
| 建模探究 | 把现实条件转化为变量、假设和关系，再解释结果边界 | 能建立、求解、检验模型并解释假设变化 | 明确变量和假设；结果回到现实语境 |

##### 编程与工程技术原型

| 原型 | 教学目的 | 成果证据 | 关键护栏 |
| --- | --- | --- | --- |
| 最小运行闭环 | 先获得可运行反馈，再解释机制和环境前提 | 能独立运行、核对输出并解释关键语句 | 代码可直接运行；环境与版本明确 |
| 引导式实现 | 从需求和分解进入实现，再用修改任务检验理解 | 能完成一个功能增量并用验收条件证明 | 不只复制答案；任务必须有需求和完成条件 |
| 调试实验 | 从故障形成复现、假设、定位、修复和回归闭环 | 能解释根因并验证修复没有引入回归 | 报错不等于根因；修复后必须复验 |
| 测试与重构 | 用测试保护行为，在保持契约下改善实现 | 能设计正常、边界和失败用例并证明行为不变 | 测试对应行为；前后必须有可比证据 |
| 项目与架构 | 围绕系统目标分解组件、接口和取舍 | 能交付可运行、可测试、可解释取舍的工程成果 | 架构服务真实规模；不用名词堆砌代替理由 |

##### 自然科学原型

| 原型 | 教学目的 | 成果证据 | 关键护栏 |
| --- | --- | --- | --- |
| 现象探究 | 从可观察现象提出可检验问题和假设 | 能区分观察与解释，并提出可被证据检验的问题 | 不先给结论再伪装探究；假设可支持也可反驳 |
| 模型解释 | 用变量、关系和假设构造模型并说明边界 | 能使用模型解释或预测，并指出成立条件 | 模型不是现实本身；证据与解释分开 |
| 实验调查 | 设计变量、对照、测量和数据分析检验问题 | 能设计可执行调查、分析数据并陈述不确定性 | 控制关键变量；数据不足不下强结论 |
| 证据论证 | 建立主张、证据和推理的可检查关系 | 能比较解释并根据证据质量修正主张 | 相关性不直接等于因果；说明替代解释 |
| 设计与应用 | 使用科学模型设计方案并按约束评价 | 能提出方案、说明依据并比较取舍 | 方案服从科学边界；评价标准先于设计 |

##### 生命科学与医学基础原型

| 原型 | 教学目的 | 成果证据 | 关键护栏 |
| --- | --- | --- | --- |
| 结构与功能 | 在正确尺度定位结构并解释其功能 | 能从尺度和结构特征推断功能并说明证据边界 | 位置描述不等于功能解释；必须标明尺度 |
| 机制与系统 | 沿因果链连接过程、调节、反馈和系统关系 | 能按因果顺序解释并预测关键环节变化 | 相关性不冒充机制；不跳过关键中介 |
| 生物证据与数据 | 用实验、数据、模型或统计评价生命科学主张 | 能说明数据支持什么、不支持什么 | 不根据单一研究下绝对结论；区分观察与推断 |
| 比较与变异 | 比较结构、物种、状态或条件并解释差异来源 | 能基于机制解释相同与差异 | 不价值化正常与异常；差异回到尺度和机制 |
| 案例推理 | 用结构、功能和机制解释教学案例 | 能提出机制解释、所需证据和不确定性 | 不给个人诊断或治疗建议；结论与证据强度相称 |

##### 人文社科原型

| 原型 | 教学目的 | 成果证据 | 关键护栏 |
| --- | --- | --- | --- |
| 问题与语境 | 建立值得追问的问题，只补充回答所需语境 | 能提出支持性问题并说明所需材料 | 背景不写成流水账；问题允许证据改变答案 |
| 材料解释 | 辨析来源、语境、表述和限制后形成解释 | 能引用具体材料并评价其立场和限制 | 材料内容不自动等于事实；解释必须指出依据 |
| 因果与变化 | 分析事件、制度或观念变化的多重原因和机制 | 能区分触发、条件和长期结构 | 先后发生不证明因果；时间线服务解释 |
| 观点论证 | 比较观点的概念、前提、证据和解释力 | 能提出可辩护主张、回应异议并承认边界 | 争议不写成唯一事实；比较使用共同标准 |
| 综合表达 | 整合多份材料和观点形成写作、讨论或公共表达 | 能提交有主张、证据、推理和异议回应的作品 | 不把摘要拼成论证；评价覆盖证据和推理 |

##### 语言学习原型

| 原型 | 教学目的 | 成果证据 | 关键护栏 |
| --- | --- | --- | --- |
| 可理解输入 | 通过可理解文本或话语获得意义并提取语块 | 能理解目标信息并在新输入中识别目标语块 | 输入难度可控；逐词翻译不等于理解 |
| 形式与准确性 | 从意义和使用中注意形式，再以受控练习建立准确性 | 能在语境中准确选择和变换目标形式 | 形式讲解回到意义和语用；不长期机械替换 |
| 互动任务 | 围绕角色、目的和信息差完成真实互动 | 能理解、回应并协商意义以完成任务 | 必须有信息差或真实选择；背稿不算自由互动 |
| 调解与转述 | 为特定对象重组、解释或转述信息 | 能按对象和目的重组信息并处理语用差异 | 不是逐字替换；保留关键信息和交际目的 |
| 表现与修正 | 完成综合语言行动并根据反馈再次表现 | 能产生真实输出并进行可观察修订 | 评价不只数语法错误；修订后复验交际效果 |

##### 商业与职业技能原型

| 原型 | 教学目的 | 成果证据 | 关键护栏 |
| --- | --- | --- | --- |
| 场景诊断 | 明确角色、目标、约束和相关方后界定问题 | 能提交结构化问题定义并区分症状、原因和约束 | 不先套框架再找问题；说明信息缺口 |
| 案例决策 | 从不完整信息形成选项、比较取舍并决策 | 能提交说明依据、风险和替代方案的决策备忘录 | 案例不设唯一标准答案；指标不替代判断 |
| 工具工作坊 | 理解工具适用条件并用它完成工作成果 | 能正确使用工具并解释关键判断 | 工具有适用边界；填表不等于完成分析 |
| 角色模拟 | 在目标冲突、信息差和时间约束下练习沟通 | 能完成角色表现并依据行为标准复盘 | 双方目标必须不同；复盘基于行为证据 |
| 成果交付与复盘 | 产出可使用成果并依据指标、风险和相关方影响迭代 | 能交付、接受评审并说明修订和影响 | 区分活动与质量；不得忽略伦理和相关方影响 |

### 2.8 七种教师可见本讲课型

本讲课型是教师操作层的稳定分类。系统可以从学科教学原型推荐课型，但教师看到和调整的是以下七种：

| 本讲课型 | 适用情境 | 最小教学弧 | 主要成果证据 | 不得退化为 |
| --- | --- | --- | --- | --- |
| 理论讲授 | 需要建立概念、原理、关系、模型或适用边界 | 问题/经验 → 核心解释 → 例子或推理 → 理解检查 → 归纳迁移 | 能解释为什么成立、在什么条件下成立 | 教师单向念稿、概念罗列 |
| 实践操作 | 需要形成程序、操作、表达或工具使用能力 | 任务与标准 → 示范 → 带支架练习 → 反馈修正 → 独立检查 | 能按标准独立完成操作或表现 | 只观看示范、机械照抄 |
| 理论与实践 | 原理理解和实际使用缺一不可 | 问题 → 原理 → 示范 → 学习者实践 → 解释选择 → 反馈迁移 | 既能完成任务，也能解释方法与边界 | 前半讲理论、后半做无关练习 |
| 案例研讨 | 需要在具体材料、情境或多种方案中形成判断 | 案例与问题 → 证据辨析 → 观点/方案比较 → 讨论决策 → 反思迁移 | 能依据材料或标准作出并捍卫判断 | 讲故事、猜标准答案 |
| 实验探究 | 需要通过观察、实验或证据检验问题 | 现象/问题 → 假设 → 设计 → 观察与数据 → 分析 → 结论与限制 | 能用证据支持、修正或反驳解释 | 先给结论再走实验流程 |
| 项目工作坊 | 需要围绕阶段成果协作制作并迭代 | 里程碑与标准 → 计划/分工 → 制作 → 检查点 → 展示评审 → 修订 | 形成可检查的阶段交付物和修订依据 | 自由活动、只汇报进度 |
| 复习测评 | 需要巩固、诊断、补救或迁移验证 | 提取练习 → 错误诊断 → 针对性再教/再练 → 迁移检查 → 学习策略 | 能说明薄弱原因并在新任务中改进 | 重讲一遍、只公布分数 |

课型决定课堂主弧，不要求每一讲只有一种教学动作。例如“理论讲授”也必须包含学习者行动和检查；“实践操作”也需要必要原理和标准。课型名称不能替代具体教学块。

学科教学原型与教师课型也不是固定一一映射。系统根据当前一讲包含的原型、目标和教学块选择主课型，常见归并关系如下：

| 教师可见课型 | 常见学科教学原型来源 |
| --- | --- |
| 理论讲授 | 概念建构、直觉与多重表征、证明与论证、模型解释、结构与功能、机制与系统、问题与语境、材料解释、可理解输入、形式与准确性 |
| 实践操作 | 方法工作坊、最小运行闭环、引导式实现、调试实验、互动任务、调解与转述、工具工作坊、角色模拟 |
| 理论与实践 | 同一讲同时需要概念/机制原型和实现/操作/表现原型时 |
| 案例研讨 | 比较与判断、案例应用、案例推理、观点论证、案例决策及材料比较类原型 |
| 实验探究 | 建模探究、现象探究、实验调查、证据论证及需要假设检验的内容 |
| 项目工作坊 | 项目与架构、成果交付与复盘，以及服务阶段交付物的综合原型 |
| 复习测评 | 错误诊断、表现与修正，以及以掌握检查和针对性补救为主的讲次 |

如果一讲包含多个原型，课型由主要学习成果决定，其他原型转化为其中的教学块；不得仅根据标题关键词机械定课型。

### 2.9 高层教学设计偏好与能力重点

高层偏好帮助教师快速表达课程气质，但它们不是新的教学类型、学科类型或课型。它们只能在已确定的教学和学科约束内调节章节入口、教学块比例和成果证据重心。

#### 2.9.1 课程定位

| 偏好 | 语义 | 主要影响 |
| --- | --- | --- |
| 学术基础 | 以概念体系、原理解释和必要推导建立扎实基础 | 增加定义、关系、推理、边界和先修结构的权重 |
| 应用导向 | 从真实问题和典型场景进入方法 | 增加场景、方法选择、应用和结果解释的权重 |
| 成果驱动 | 从可展示、可评价的最终成果反向组织课程 | 增加里程碑、交付物、评价标准和迭代的权重 |

#### 2.9.2 教学组织

| 偏好 | 语义 | 主要影响 |
| --- | --- | --- |
| 讲练一体 | 每个核心内容形成解释、示例、练习和反馈闭环 | 提高局部闭环密度，不把练习集中到最后 |
| 问题驱动 | 用逐步升级的关键问题串联知识 | 章节和讲次由问题关系推进，不按名词平铺 |
| 案例研讨 | 通过案例分析、比较和讨论形成判断 | 提高材料、证据、比较、决策和迁移比重 |

#### 2.9.3 能力重点

| 能力重点 | 目标语义 | 达成证据 |
| --- | --- | --- |
| 解释与推理 | 说清概念、证据、机制、步骤为什么以及怎样成立 | 完整解释、推导、论证、机制链或理由说明 |
| 分析与迁移 | 比较条件、识别结构、选择方法并用于新情境 | 新案例判断、变式、策略选择和迁移任务 |
| 设计与实作 | 形成可验证的作品、方案、实验、程序或表现 | 交付物、测试、演示、量规和迭代记录 |

课程定位和教学组织各选择一个主要偏好，能力重点可以多选。偏好不能覆盖教师明确选择的教学类型和学科类型；冲突时应说明冲突并要求教师取舍，而不是把偏好文本混入学科识别。

#### 2.9.4 课程编排节奏

系统根据教学类型、学科类型和教师偏好形成内部编排节奏。它只负责教学块的比例与先后，不改变学科专业模块：

| 编排节奏 | 典型顺序 | 适用倾向 |
| --- | --- | --- |
| 智能均衡 | 目标 → 讲解 → 示例/应用 → 学习者行动 → 检查反馈 | 没有明显单一偏向，或需要保持学科默认结构 |
| 理论推导 | 概念 → 深入推演 → 边界检验 → 例子 → 练习反馈 | 学术基础、解释与推理、数学证明等目标 |
| 案例实战 | 讲解 → 案例 → 真实场景 → 学习者行动 → 检查反馈 | 应用导向、案例研讨、典型问题解决 |
| 项目驱动 | 场景 → 必要知识 → 项目任务 → 执行反馈 → 成果迁移 | 项目实战、成果驱动、设计与实作 |
| 问题探究 | 关键问题 → 假设与概念 → 依据推演 → 边界检验 → 反思反馈 | 问题探究、证据解释和开放判断 |

同一个编排节奏在不同学科中必须使用不同专业动作。“项目驱动的数学课”仍要保留定义、推导和模型检查；“理论推导的工程课”仍要形成可运行验证。

### 2.10 难度、学习起点与课程难度曲线

难度表示学习者需要面对的挑战、可获得的支架、完成任务的独立程度以及迁移距离，不表示文字长度、术语数量、公式密度、代码量或题量。

#### 2.10.1 难度的五个组成部分

| 组成 | 回答的问题 |
| --- | --- |
| 入口要求 | 进入课程前至少需要哪些知识、能力和就绪度 |
| 挑战结构 | 前置负荷、抽象程度、推理深度、整合范围、任务复杂度和迁移距离多大 |
| 支架结构 | 示范、提示、节奏拆分和反馈多频繁、何时逐步撤除 |
| 掌握合同 | 准确性、独立性、解释、执行和迁移达到什么程度 |
| 学科适配 | 当前难度在本学科中应表现为什么专业任务和证据 |

#### 2.10.2 三种目标难度

| 目标难度 | 入口假设 | 挑战与支架 | 掌握证据 | 不得误解为 |
| --- | --- | --- | --- | --- |
| 入门 | 可以从零或极少前置开始 | 高支架、小步推进、即时反馈 | 能用自己的话说明核心概念，并在支架下完成标准任务 | 内容幼稚、只讲名词 |
| 进阶 | 已具备基础概念或基本操作 | 新方法处示范，其余逐步独立；保留质量标准和结果检查 | 能独立完成典型任务、解释关键选择并修正常见错误 | 单纯增加篇幅和步骤数 |
| 高阶 | 能独立处理典型问题并说明常用方法边界 | 低支架、高推理、高整合和远迁移；只在新约束与安全边界处支持 | 能独立处理开放约束，说明取舍、边界和不确定性，并迁移到陌生情境 | 删掉提示、跳过前置、堆术语制造困难 |

目标难度与学习起点必须分开：目标难度说明最终要到哪里，学习起点说明现在从哪里出发。起点未知时先安排简短诊断；存在缺口时优先增加桥接支架、前置单元或独立基础课，不得由系统静默降低最终目标。只有教师明确选择降低目标，才重新定义掌握合同。

#### 2.10.3 课程难度曲线

课程难度不是直线上升，而是“总体上升、遇到新能力重新加支架”的锯齿曲线：

```text
桥接前置 -> 奠定基础 -> 完整示范 -> 带支架练习 -> 独立任务
        -> 整合 -> 迁移 -> 掌握检查 -> 综合成果
```

难度曲线必须满足：

- 相邻讲次的挑战跨度有界，不连续制造无法承接的陡升。
- 新概念负荷与任务复杂度同时上升时，必须同步增加支架。
- 支架随能力形成逐步撤除，但检查标准和安全边界不能删除。
- 课程后段必须出现整合、迁移或综合成果，不能始终停留在示范。
- 学科适配决定高阶表现：数学体现证明、反例或建模，工程体现约束、测试和取舍，人文体现材料限制和强异议回应，不能用统一“难题”模板代替。

### 2.11 教学模块与教学块语义

#### 2.11.1 教学块正式合同

每个教师可见教学块至少说明：

- 名称、教学目的、顺序、计划时长和是否必需。
- 所服务的目标、知识、小节、课型和难点。
- 教师活动、学生活动、资料工具和预期产出。
- 检查标准、反馈方式、来源依据和必要备注。

教学块的名称可以因课堂语言调整，但责任不能漂移。一个教学块可以编译成多个正式内容块；多个连续内容块也可以共同服务一个教学块。

#### 2.11.2 全课程与每讲共同骨架

| 作用范围 | 必备模块 | 语义 |
| --- | --- | --- |
| 全课程 | 课程定位、学习路径、综合迁移 | 说明面向谁、形成什么成果、怎样递进以及如何综合使用 |
| 每讲 | 本讲任务、核心教学、学习者行动、检查与反馈 | 说明要完成什么、怎样建立知识、学习者做什么以及如何判断 |

本文在教师课程层级统一称“本讲任务”；现有“本节任务”文案是同一语义的兼容表达，不表示讲内小节另有一套任务真源。

任何学科的专业教学块都叠加在共同骨架上，不能删除目标、学习者行动或反馈，只留下专业内容。

#### 2.11.3 跨学科编排增强

| 编排增强 | 作用 |
| --- | --- |
| 深入推演 | 展开可检查的因果、推理或推导链 |
| 补充案例 | 增加与当前目标直接对应、可逐步拆解的案例 |
| 真实场景 | 把能力用于有角色、目标和约束的情境 |
| 项目实战 | 形成与前后课程连续的阶段性项目成果 |
| 问题探究 | 组织问题、假设、依据、推演和检验 |
| 边界与反例 | 用条件变化和反例检查概念、方法或结论 |

这些增强只调节当前学科合同内的内容节奏。例如数学中的“深入推演”仍必须遵守形式定义，商业课程中的“问题探究”仍必须产出可用决策，而不是把所有学科写成同一种通用课程。

#### 2.11.4 难度与支架

| 支架层级 | 教学动作 | 学习者责任 |
| --- | --- | --- |
| 分步示范 | 展示输入、判断、依据、步骤和结果检查 | 跟随并解释关键步骤 |
| 带支架练习 | 提供提示、半成品或中间检查点，并逐步减少 | 完成保留的关键步骤并使用反馈修正 |
| 迁移挑战 | 改变情境、条件、目标或约束 | 独立选择方法，说明边界、取舍和验收依据 |

难度必须改变支架、任务复杂度和独立程度，不能只要求模型“写得更难”。

#### 2.11.5 各学科模块集合

| 学科类型 | 全课程必备 | 每讲常规必备 | 按目标选用 |
| --- | --- | --- | --- |
| 通用课程 | 概念地图 | 解释性例子、应用场景 | 清单或模板、案例比较、概念模型、方法演练、综合迁移 |
| 数学与形式科学 | 前置诊断 | 直觉入口、正式定义、例题推演、变式练习、错误分析 | 证明与推导、数学建模、多重表征、策略选择、数学论证 |
| 编程与工程技术 | 工程成果路径 | 最小可运行示例、运行结果、机制拆解、修改任务、调试案例 | 测试与质量、架构设计、需求与设计、重构实践、代码评审 |
| 自然科学 | 现象到模型路径 | 现象与问题、模型与规律、实验与证据、适用边界、预测与应用 | 实验设计、数据分析、问题与假设、证据论证、科学设计 |
| 生命科学与医学基础 | 生命层级 | 定位与结构、功能、机制过程、调节与系统关系、机制案例 | 正常与异常、实验依据、尺度连接、生物数据推理 |
| 人文社科 | 问题与观点路径 | 背景与语境、材料与证据、观点与论证、观点比较、讨论或写作 | 材料辨析、时间线、核心问题、材料解释、因果与变化、综合回应 |
| 语言学习 | 交际场景路径、间隔复习 | 可理解输入、词汇与语块、形式、意义与使用、控制练习、真实输出 | 发音与文字系统、文化与语用、语言注意、互动协商、调解转述、反馈与修正 |
| 商业与职业技能 | 工作成果路径 | 业务场景、方法框架、案例拆解、工具与模板、实战任务、评价指标 | 角色模拟、数据分析、问题诊断、决策与取舍、成果复盘、伦理与相关方 |

“常规必备”表示该学科的完整课程必须系统覆盖这些行为，不表示每一讲机械塞入全部模块。当前讲应由目标、阶段、课型、时长和资料条件选出最小充分组合。

### 2.12 教学产物的完整语义

```mermaid
flowchart LR
    A["课程目标、类型、学科、规模与资料"] --> B["课程大纲"]
    B --> C["全课教学设计"]
    B --> D["教学日历"]
    C --> E["本讲课型与教学块"]
    E --> F["分讲教案"]
    F --> G["分讲讲稿"]
    B --> H["正式题库"]
    F --> H
    H --> I["分讲练习与试卷"]
    G --> J["PPT"]
    F --> J
```

图表示主要依赖，不是页面门禁。教师可以先写讲稿再补题，也可以只制作某些讲次；系统必须保留来源关系并在上游变化时精确提示影响。

| 教学产物 | 回答的核心问题 | 必须包含 | 主要上游 | 主要下游或证据 | 不应承担 |
| --- | --- | --- | --- | --- | --- |
| 课程大纲 | 这门课为什么存在、教什么、怎样递进并怎样达成 | 定位、对象、范围边界、总体成果、先修、章/讲结构、每讲责任、目标、达成检验和不覆盖项 | 目标、教学类型、学科类型、规模、资料和实施条件 | 全课设计、教案、日历、题库和影响基线 | 逐分钟调度、完整讲述内容 |
| 教学日历 | 课程何时、何地、由谁按什么进度实施 | 讲次、时间、地点、人员、进度状态和必要调整 | 已确认大纲与排课条件 | 教师首页、课前准备和进度检查 | 改写知识结构、另存大纲 |
| 全课教学设计 | 整门课采用什么教学与评价策略 | 定位、对象、学习起点、总体目标、教学主线、学科策略、评价设计、章节责任和知识坐标 | 已确认大纲、课程知识和教师约束 | 分讲课型、教案、评价和课程调整 | 成为第二份课程正文 |
| 分讲教案 | 这一讲怎样真实教完 | 本讲目标、课型、重难点、教学块、时长、师生活动、资料工具、检查、反馈、作业和前后衔接 | 大纲、全课设计、资料、本讲编排 | 讲稿、练习、PPT 和课堂执行 | 代替完整授课内容 |
| 分讲讲稿 | 教师站在讲台上具体怎样讲 | 按教学块组织的自然讲述、概念与边界、过渡、提问、示例/推理、活动指令、反馈提示和总结 | 已确认教案、课程知识和选定资料 | PPT、教师授课和讲稿修订 | 重新选课型、独立改结构、退化为教材正文或课堂提纲 |
| 正式题库 | 整门课有哪些可复用、可审阅的正式题目 | 出题意图、目标和知识范围、公开题面、私有答案/量规、难度、题型、验证与修订 | 大纲、教案、课程知识、资料和明确评价意图 | 练习、试卷、诊断和复验 | 成为生产链强制前置；混淆公开题面与私有答案 |
| 分讲练习与试卷 | 学习者是否在明确范围内达到目标 | 题目修订引用、作答规则、反馈或评分合同、范围和完成条件 | 正式题库、教学范围和评价目标 | 正式作答、诊断、掌握证据和课程调整 | 复制题干答案形成第二题库 |
| PPT | 学生当下看什么、教师怎样借助画布推进教学 | 每页教学任务、可见结论与必要过程、构图、讲稿来源、教师备注和证据关系 | 已确认讲稿、教案追溯和表现模板 | 课堂展示、讲义或其他表达 | 在渲染阶段重新发明知识和教学结构 |
| 配套文档 | 学校提交、学生说明、评分或归档需要什么正式材料 | 真实模板、结构化课程信息、适用对象、修订和导出 | 正式课程信息和学校模板 | 评分细则、自查清单、说明和归档 | 承担课堂教学主链、建立第二真源 |

所有产物必须区分输入、工作稿、质量结果、已确认修订和导出投影。上传只表示原件已保存，模型生成只形成工作稿；教师导入、采纳或确认后才进入正式体系。

### 2.13 教学语义的组合、对齐与质量标准

#### 2.13.1 完整组合关系

```text
课程目标 + 学习者起点 + 资料 + 规模 + 实施条件
× 教学类型
× 主学科类型 + 学科细分 + 可选第二学科
× 课程定位偏好 + 教学组织偏好 + 能力重点
× 目标难度 + 起点差距处理
-> 课程大纲与全课教学设计
-> 课程阶段 + 当前讲目标 + 编排节奏 + 难度角色 + 学时与资料条件
-> 学科教学原型
-> 教师可见本讲课型
-> 有序教学块
-> 教案
-> 讲稿 / 练习 / PPT
-> 学习成果证据与课程调整
```

组合优先级：

1. 教师明确目标、范围、类型和学科选择是硬约束。
2. 学科方法和安全边界高于高层偏好，偏好不能让专业方法失效。
3. 教学类型决定整课主线，课程阶段和本讲目标决定当前讲责任。
4. 学科教学原型负责推荐专业教学动作，教师可见课型负责课堂主弧。
5. 教学块负责真实实施，教学产物各自保存不同责任。
6. 冲突必须显示原因、影响和可选处理，不允许模型静默折中。

#### 2.13.2 目标—证据—活动—表达对齐

每个重要目标都必须沿同一条关系向下闭合：

```text
可观察目标
-> 达成证据
-> 学习者活动
-> 教师支持与反馈
-> 讲稿、练习和 PPT 表达
```

一个合格目标应说明“谁在什么条件下，完成什么可观察行为，达到什么标准”。“理解、掌握、熟悉”只有在后面接上解释、求解、分析、设计、表达或操作等可观察行为时才成立。

评价至少区分：

- 过程检查：及时发现误解、错误步骤和支架需求，用于调整当前教学。
- 阶段成果：检查一章或一个里程碑的综合能力。
- 最终成果：证明整门课承诺的解释、项目、结论、表现或考试准备度。
- 迁移复验：在新情境、延迟时间或独立任务中验证学习是否稳定。

#### 2.13.3 通用专业性标准

大纲、教案、讲稿、练习和 PPT 的专业性不能只靠“生成完整”判断，至少同时满足：

1. **目标一致**：产物服务已确认的课程目标和本讲目标。
2. **范围诚实**：课程规模、标题、定位和不覆盖项一致，不夸大完整性。
3. **学科成立**：解释、推理、证据、实践和评价符合当前学科方法。
4. **结构衔接**：整课、章、讲、小节和教学块没有跳跃、重复或责任冲突。
5. **课堂可实施**：活动、时间、资料、教师动作和学生动作能够真实执行。
6. **成果可检查**：每个关键目标都有适当产出、标准和达成证据。
7. **来源可追溯**：指定资料、课程知识和生成内容之间可以回查。
8. **表达适配**：大纲像大纲、教案像教案、讲稿能直接讲、PPT 适合课堂观看。
9. **教师可控制**：建议可以采用、修改、拒绝、撤销和恢复。
10. **失败可降级**：局部生成或表达失败不破坏已确认课程和最后可用结果。

#### 2.13.4 产物专项质量门

| 产物 | 最低专项质量门 |
| --- | --- |
| 大纲 | 定位和成果具体；范围与规模匹配；章节责任唯一；目标、先修和达成检验可追踪 |
| 教案 | 课型与目标匹配；教学块顺序成立；师生活动、时长和检查可执行 |
| 讲稿 | 内容完整且自然可讲；块间过渡顺畅；例子、提问、活动和反馈服务教案；不写成教材正文 |
| 题目与练习 | 出题意图明确；题面与答案隔离；评分和诊断合同成立；题目能暴露目标差距 |
| PPT | 每页只有明确教学任务；学生画布不过载；教师备注承接完整讲稿；预览和导出同源 |
| 课程调整 | 有真实证据、范围和反证；说明影响与保持不变项；正式应用后安排独立复验 |

模板和 Prompt 只能帮助实现这些语义和质量门，不能代替它们。不同学科和课型可以使用不同模板，但所有模板必须回到同一术语、关系、证据和教师确认体系。

## 3. 产品逻辑设计

产品逻辑设计定义教学对象之间的组成、类型约束、派生组合、依赖状态和反馈演化。先生成什么只是其中一部分。

### 3.1 两条总控闭环

#### 结构化同源

结构化同源回答“同一门课程怎样产生一致的教学产物”：

```text
课程教学设计 + 课程知识
-> 正式课程
-> 教案 / 讲稿 / 练习 / PPT / 图解 / 讲义等同源产物
```

课程结构、知识身份和来源绑定共同约束所有产物。产物可以有自己的版式、编辑和确认状态，但不能脱离课程语义成为第二份课程正文。

#### 课程生长

课程生长回答“课程怎样依据真实教学与学习过程持续调整”：

```text
学习行为、记录与正式作答
-> 有来源的证据
-> 可反驳的教学判断
-> 范围受限的课程调整方案
-> 用户审阅与确认
-> 正式课程新修订
-> 受影响产物重新编译
-> 独立效果复验
```

AI 判断只是有依据的假设，不是学习事实。结构化同源保证修改后各类产物不漂移；课程生长保证修改来自真实证据，而不是随机生成。

### 3.2 对象关系与唯一真源

四个核心对象承担不同责任：

- `CourseDocument` 是当前正式课程的唯一语义容器，保存稳定课程身份、有序章节与内容块，以及目标、知识、来源和修订关系。
- `CourseBlock` 是正式课程正文中的最小稳定内容单元。`kind` 说明怎样呈现，`role` 说明承担什么教学作用；相同形式可以承担不同作用，相同作用也可以采用不同形式。
- `CourseTeachingPlan` 保存全课与分讲的教学设计责任，不成为第二份课程正文。
- `CourseKnowledgeBase` 保存当前课程实际教授的知识、能力、易错、掌握标准和精确教学绑定，不与跨课程学科知识库混为一谈。

课堂“教学块”与 `CourseBlock` 不是同一个对象：教学块描述一段课堂活动和师生行为，一个教学块可以编译出多个正式内容块；`CourseBlock` 描述最终课程内容怎样稳定保存和呈现，不能反过来代替课堂编排。

一件事实只能有一个拥有者，其他页面、文件、缓存和导出都是投影：

| 事实 | 唯一真源 | 允许的投影 | 禁止的平行真源 |
| --- | --- | --- | --- |
| 当前课程结构与正文 | `CourseDocument` | 目录、阅读正文、旧课程只读视图 | 完整 Markdown、页面本地课程副本 |
| 课程教学设计 | `CourseTeachingPlan` | 全课教案、分讲教案、生成约束 | 独立 Markdown 教案、课程蓝图副本 |
| 当前课程知识 | `CourseKnowledgeBase` | 知识图谱、标签、AI 上下文切片 | 跨课程知识身份、章节标题伪知识点 |
| 正式题目与试卷 | 版本化题库修订与题目修订引用 | 教师题库、练习、试卷 | 前端勾选状态、复制题干答案 |
| 正式作答 | `PracticeAttempt` | 错题本、练习反馈、掌握证据 | 本地完成状态、组件作答历史 |
| 学习行为事实 | `LearningEvent` | 进度、诊断输入、统计 | 节点本地已读状态 |
| 学习现场位置 | `LearningSnapshot` | 续学入口、滚动恢复 | 用快照代替学习事实 |
| 笔记与问答记录 | `LearningRecord` | 正文行内记录、记录总览 | 组件本地笔记库 |
| 当前学习者状态 | `LearnerModel` | 掌握、困难、偏好和策略投影 | 可独立写入的画像副本 |
| 课程调整建议 | `CourseEvolutionPlan` | 侧栏候选、审阅工作台、影响预览 | 每个入口一套候选状态 |
| 教学表达 | `TeachingRepresentation / RepresentationSet` | PPT、讲义、图解、音频等 | 独立漂移的第二课程正文 |

用户感知的是“当前正式结果 + 可撤销操作”，而不是底层版本树。历史修订用于追溯、冲突、撤销和效果比较，不成为顶层产品概念。

### 3.3 类型、派生与组合关系

```text
课程目标、学习者起点、目标难度、资料、规模与实施条件
× 教学类型
× 主学科、学科细分与可选第二学科
× 高层教学设计偏好
-> 大纲与全课教学设计
-> 课程阶段、编排节奏、难度角色与学科教学原型
-> 本讲课型
-> 教学块组合
-> 分讲教案
-> 分讲讲稿
-> PPT 与练习等下游产物
```

本节只说明这些语义在产品对象之间怎样派生；各类型、原型、课型、教学块和产物的正式含义以第二章的完整教学语义为准。

关系规则必须满足：

- 上位类型提供约束和倾向，下位对象负责当前场景的具体决定。
- 教师明确选择优先于自动识别；自动识别必须可解释、可修改。
- 高层教学偏好只能在既有类型和学科约束内调节，不能反向污染学科判断或建立第二套分类。
- 稳定关系由产品规则表达，不能依赖模型临时从自然语言中猜测。
- 冲突时必须显示冲突对象、原因和可选处理，不静默覆盖任一已确认产物。

### 3.4 课程生产依赖

课程生产采用可跳转、但依赖清楚的五个入口：

```text
课程基础（大纲 / 教学日历）｜教案｜题库｜讲稿｜PPT
```

常见纵向路径是：

```text
课程目标与资料
-> 大纲章节骨架
-> 教师确认各章讲次规模
-> 完整大纲
-> 本讲课型与教学块
-> 分讲教案
-> 分讲讲稿
-> PPT
```

这条路径表达依赖，不是页面门禁：

- 教师可以跳过题库先制作讲稿或 PPT，也可以之后补题并把选中题目用于既有产物。
- 教学日历、题库、试卷和配套文档读取同一课程基线，但不是纵向链的强制步骤。
- 上游修改只让真正受影响的下游进入待复核、过期或重建，不整课重做。
- 课程规模只增加有界工作单元，不产生另一套生成协议。

### 3.5 状态与确认

所有生成和编辑统一遵循：

```text
输入或编排
-> 可见任务
-> 可恢复工作稿
-> 质量检查
-> 用户审阅
-> 正式确认
-> 下游影响与下一动作
```

生成完成、质量通过、教师确认和正式发布是不同状态。自动保存只保存工作现场，不等于正式应用。失败必须保留已完成单元和最后可用结果，只重试缺失或失败部分。

手工修改和 AI 修改都先形成候选。正式应用前必须说明：

- 修改了什么、依据是什么。
- 影响哪些对象，哪些保持不变。
- 是否存在冲突、过期、资料不足或质量阻断。
- 怎样拒绝、撤销、恢复或重新生成。

### 3.6 学习、练习与反馈

学习现场统一消费正式课程、课程知识和当前学习身份：

```text
正式课程 + 当前学习事实
-> 阅读、记录、练习与诊断
-> 新的正式学习事实
-> 可重算学习者状态
-> 当前进度、连续性与可解释行动
```

正式练习必须从教学目标和课程知识形成明确出题意图，公开题面与私有答案、量规、隐藏测试严格隔离。评分回答“是否达标”，诊断回答“答案表现出什么差距”；没有证据时不得反推学生未表达的思考过程。

原始事实、教学解释和正式状态严格分层：

```text
LearningEvent / LearningRecord / PracticeAttempt
-> EvidenceItem
-> AdaptationHypothesis
-> LearnerModel 或 CourseEvolutionPlan
```

单条明确强证据可以触发局部候选；范围越广，需要的独立一致证据越强。反证必须能够缩小或撤销判断。

### 3.7 内部职责分层

灵知内部继续使用“实体—功能—逻辑—AI”检查责任是否错位，但它只是产品内部职责视角，不是本文三个产品设计部分的平行框架：

| 内部职责 | 负责 | 不负责 |
| --- | --- | --- |
| 实体 | 保存课程、教案、知识、题目、学习事实、调整方案和教学表达等可追溯事实 | 为某个页面复制第二份事实 |
| 功能 | 围绕用户任务组合实体能力 | 独立拥有一套领域真源 |
| 逻辑 | 保存类型、派生、依赖、状态、证据和影响等稳定因果关系 | 把因果关系留给页面或 Prompt 临时判断 |
| AI | 完成结构、内容、解释和候选等语义工作 | 管理权限、版本、正式状态和用户确认 |

### 3.8 AI 与用户控制

AI 只承担确定性规则无法可靠完成的语义工作，例如结构与内容候选、资料理解、受约束的证据解释和局部重写。

- AI 回答、AI 建议、可审阅候选和正式动作必须区分。
- AI 可以主动提出改进，但不能替用户确认或扩大用户选择的范围。
- 正式动作必须进入统一影响分析、确认、正式命令和回执链。
- 模型不可用时，已有课程、练习、记录和最后可用产物继续可用。
- 涉及最新事实时读取可信时效资料，不能用模型记忆冒充证据。

## 4. 交互与界面设计

交互与界面设计把教学对象、产品关系、状态和动作翻译成用户能理解、能控制的界面。

### 4.1 界面表达原则

```text
对象 -> 合适的界面形态
关系 -> 布局、层级、导航和影响提示
状态 -> 反馈、差异和恢复入口
动作 -> 可预期、可撤销的控件
```

- 容器用于表达成组信息、独立状态、明确边界或可操作区域。
- 普通标题、说明和单行文字优先依靠位置、字号、颜色和留白建立层级，不为装饰增加边框和卡片。
- 正式内容优先以连续文档呈现；结构树、设置和建议只在任务需要时出现。
- 看起来可点击的元素必须可用；不可用时明确原因和恢复条件。
- 加载、空、成功、失败、冲突、过期、取消、恢复和只读降级都必须有真实状态。

### 4.2 产品空间

灵知只保留四类顶层任务空间：

1. **教师首页**：我的日历与我的课程。
2. **课程工作台**：课程生产、文件管理和正式课程预览。
3. **学习现场**：阅读、练习、记录、知识和学生 AI 老师。
4. **调整课程工作区**：分析影响、审阅候选、应用、撤销和复验。

PPT 等复杂表达使用从课程文件或工作台进入的专用工作区，不升级为平行顶层产品中心。

### 4.3 教师首页

教师首页在同一顶栏提供“我的日历 / 我的课程”：

- 我的日历由课程范围、教学日历和选中日期或课次状态组成。选择课程只改变日历投影，“进入课程”始终是独立动作。
- 我的课程是完整课程库，支持适合查找和管理的卡片或列表密度。
- 新建课程使用紧凑表单，课程名称是唯一必填项；创建后先得到空课程空间，再在课程基础中开始大纲生产。
- AI 新建与 Markdown 导入最终都进入同一个课程身份和课程对象。

### 4.4 课程工作台

课程工作台默认采用左、中、右三栏：

- 左栏：课程基础、教案、题库、讲稿、PPT 五个入口，以及课次和完成状态。
- 中栏：当前正式对象的表单、生成过程、工作稿、阅读、编辑、差异和确认。
- 右栏：当前对象的一个主来源、多份参考资料、联网来源和必要的 AI 协作。

左侧顺序表达常见备课路径，不伪装成全部强制门禁。中栏在同一位置完成“输入—生成—审阅—编辑—确认”，不为每个状态打开第二套页面。右栏始终服务当前阶段或当前讲次，不成为通用聊天中心。

每讲教案、讲稿和 PPT 共享上一讲、当前讲、下一讲导航。确认后主操作原位切换为常见下一动作，但教师仍可自由切换入口。

### 4.5 课程文件空间

课程文件按教师责任组织为：

```text
教务材料：学校提交、归档和制度性文档
课程逻辑文件：大纲、教案、讲稿-PPT、题库
辅助资料：老师题库、试卷、学生作业和其他原件
```

- 教务材料和课程逻辑文件可以投影同一正式修订，不复制底层内容。
- 上传原件只保存一次；正式对象保存主来源、参考资料和联网来源的关系。
- 单击文件夹进入，单击文件选中并更新详情，双击或明确主操作才打开、生成或编辑。
- 搜索覆盖整门课程并显示语义路径；无匹配项和空文件夹必须区分。
- 页面不提供泛化“新建”菜单。固定正式对象缺失时直接显示“未生成”，重复生成形成新修订而不是并列副本。

题库始终是一门课程唯一的正式题库。导入、AI 生成、审核、筛选和组卷都在同一题库工作台中完成；“组成试卷”是题库内部操作，不新增课程生产阶段。

### 4.6 学习现场

学习现场保持“左目录、中正文、右侧笔记或 AI、底部学习工具”的连续空间：

- 正式练习从正文对应位置或课程练习视图进入，关闭后回到原内容锚点。
- 桌面笔记在正文右侧展开；移动端使用全屏覆盖层，避免压缩正文。
- 错题本、复习、学习记录和知识图谱是正式领域事实的聚合视图，不建立各自的进度副本。
- 临时解释、反例、过渡和检查可以进入当前学习流，但不自动写入正式课程。

教师预览复用同一正式课程，但使用教师身份和明确的预览标识，不读取或写入学生数据。

### 4.7 调整课程

学生侧和教师侧都只保留一个“调整课程”概念。就近入口、AI 发起入口和独立工作区共享同一个服务端候选：

- 用户选择当前内容、当前讲次、相关后续或全课程范围。
- 单项局部变化可以原位审阅；跨对象或全课程变化进入完整工作区。
- 关闭、刷新或切换入口后恢复同一任务，不生成第二份候选。
- 用户选择的范围是硬边界，AI 不得扩大范围或替用户确认。

## 5. 产品边界、异常与演进

### 5.1 不可违反的边界

1. 一件事实只能有一个正式真源。
2. 教案、课程知识、正式题目、学习事实和教学表达各自拥有清楚边界。
3. 正式课程变化只能通过统一课程命令完成。
4. AI 输出、对话、笔记和自述不能直接成为掌握事实或正式课程内容。
5. 个性化只作用于当前课程，不跨课程共享运行时知识或学习结果。
6. 教学表达从课程派生，表达编辑与语义编辑必须分流。
7. 正式题面的公开内容与私有答案、量规和隐藏测试严格隔离。
8. 失败、降级、待审阅、质量通过、教师确认和正式发布必须区分。
9. 用户不需要理解内部版本树、Prompt 版本、模型调用策略和修订实现。
10. 旧链只能读取或迁移，不能继续生长新的写入规则。

### 5.2 异常与降级

| 场景 | 必须行为 | 禁止行为 |
| --- | --- | --- |
| 模型不可用 | 保留检查点、已完成单元和最后可用产物，提供恢复动作 | 清空整门课程、伪造 AI 成功 |
| 资料不足或冲突 | 标记缺口、降低置信度、请求补充或进入审阅 | 用模型常识冒充指定资料事实 |
| 课程修订冲突 | 重新定位候选或返回明确过期冲突 | 覆盖新修订、静默丢失修改 |
| 知识引用失效 | 阻止正式应用或进入知识维护候选 | 复制标题伪造知识 ID |
| 题目质量失败 | 隔离候选并保留当前有效题目 | 把坏题重新放回学生题池 |
| 验证器不可用 | 相关题型失败关闭，其他可验证内容继续 | 假装执行隐藏测试 |
| 表达生成失败 | 使用完整文字、静态替代或最后可用表达 | 阻断课程阅读、发布空白产物 |
| 学习锚点歧义 | 留在记录总览并提示重新定位 | 把记录强插到错误正文 |
| 服务重启 | 根据持久检查点只恢复未完成单元 | 重做全部已完成工作 |
| 旧课程缺少新合同 | 只读适配或显式迁移，降级可解释 | 双写旧对象和新对象 |

### 5.3 兼容与演进

- 新课程只写当前正式对象；旧对象只读适配，迁移必须幂等、可审计、可恢复。
- 兼容接口必须声明读取真源和写入目标，不能成为长期业务入口。
- 新增对象、页面、状态或能力时，必须说明现有对象为何不能承载、谁拥有状态、谁消费，以及旧链何时退出。
- 产品定义稳定但技术协议可以演进；实现细节由系统架构、OpenSpec 和状态板维护。
- 外部研究和 Demo 只有回写本文或正式规格后才改变产品方向。

## 6. 长期建设顺序与完成门

### 6.1 长期建设顺序

`P0-P6` 表示产品与工程的前置依赖，不表示当前完成度：

| 层级 | 必须先回答的问题 | 稳定产物 | 下一层解锁条件 |
| --- | --- | --- | --- |
| P0 可信执行与真源基座 | 系统能否稳定开发、验证、恢复并隔离数据 | 可复现运行时、质量门、数据边界和状态所有权 | 能区分产品缺陷、环境问题和测试污染 |
| P1 课程语义内核 | 课程、教案、知识、题目和表达由谁拥有 | 正式课程、课程命令、稳定知识与来源引用 | 课程可安全修改且不产生平行真源 |
| P2 学习证据与诊断内核 | 系统依据什么理解学习过程 | 正式学习事实、证据坐标和可重算学习者状态 | 调整能够指出来源、置信度和反证 |
| P3 可审阅课程生长 | 怎样把证据变成受控课程变化 | 调整方案、影响预览、用户确认、撤销和恢复 | 任意支持范围都能原子应用或拒绝 |
| P4 同源表达与完整学习现场 | 修改后各类产物和学习入口怎样一致 | 来源绑定的教案、讲稿、练习、PPT、图解和统一运行时 | 变化能精准重建，失败保留最后可用结果 |
| P5 效果验证与长期循环 | 怎样证明调整真的有效 | 独立复验、效果比较、失败回退和长期样本 | 不以“已接受”冒充“已改善” |
| P6 课程原生 Agent | AI 怎样组合成熟能力完成复杂目标 | 受证据、确认、正式命令和效果门约束的 Agent | Agent 只能组合成熟闭环，不能绕过它们 |

唯一内在顺序是：先让系统可信，再让课程可改；先让证据可信，再让调整发生；先让调整进入真实教学与学习现场，再验证效果；最后才把成熟能力交给 Agent 组合。

### 6.2 产品完成门

只有以下条件同时成立，灵知的目标产品才算完成：

1. 任意课程都能由稳定、有序、异构教学单元表达，修改不会静默破坏学习记录和历史作答。
2. 课程生成、教师修改和经确认的个性化调整共用同一课程内核。
3. 大纲、教案、课程知识、讲稿、正式题目和教学表达之间具有可验证的来源与修订关系。
4. 阅读、练习、笔记、错题、复习、知识图谱和 AI 老师共用同一学习运行时。
5. 所有正式题目都能说明为什么出、考什么、怎样判定，并隔离私有答案和隐藏验证。
6. 原始证据、AI 假设、学习者状态和课程调整严格分层，任何结论可回到来源。
7. 单条强证据可触发局部候选，广域修改需要更强范围依据；反证能够缩小或撤销判断。
8. 用户可以理解、选择、拒绝、部分接受、撤销和恢复课程变化，系统不会半应用。
9. 课程变化后，受影响教学产物能精确复用、过期、重建或安全降级，不产生漂移。
10. AI、媒体、图表、代码执行、评分或网络失败时，课程仍可继续学习并明确恢复。
11. 旧课程和旧入口通过只读适配或幂等迁移进入同一内核，不再产生第二条写链。
12. 多门跨学科真实课程证明完整生产与学习链，并有长期样本证明课程调整带来改善或触发安全回退。

这些完成门描述产品终局，不表示当前完成度。当前事实只看[产品状态](./产品状态.md)。
