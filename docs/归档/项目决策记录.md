## 2026-08-04 教案工作台升级计划与首期落地决策

- 背景：现有教案已经是正文、课程知识库、练习、PPT 和其他教学表达的上游合同，但用户侧仍只能在“总体教案 / 分小节教案”中阅读、选择小节和打开知识点，缺少修改、保存、差异审阅、影响预览与修订恢复。启智的可编辑 Markdown、自动保存、离开保护和多阶段 AI 优化可借鉴交互，但不能复制其文档级资源真源。
- 产品边界：一门课程继续只保留一份正式 `CourseTeachingPlanV3`。教案工作台不新增 Markdown 真源、独立大纲、并列教案副本或资源树；目录增删、排序和章节结构继续由目录编辑器负责，教案工作台只编辑教学语义及受控模块结构。
- 编辑协议：教师修改先进入可变草稿并防抖自动保存，只有经过结构校验、差异审阅和影响预览后，用户显式应用才生成不可变正式修订。稳定知识 ID、课程修订 ID、来源绑定和系统质量字段保持只读；并发写入必须携带基础修订和幂等键，冲突以结构化 `409` 返回。
- AI 权限：AI 字段改写、小节重新生成和全课调整只产生带字段路径、基础修订、理由、影响和过期时间的结构化候选，复用现有课程提案确认协议，不允许模型直接调用正式写命令。首次课程生成的阶段、模型调用次数、目录确认门和发布门保持不变。
- 同源影响：正式教案变化由确定性规则计算对课程知识库、正文、练习、PPT、讲义和其他 `TeachingRepresentation` 的影响，区分变化、待重建、陈旧、保持不变和阻断。旧正式产物在新产物重建失败时继续可读；恢复历史版本通过新修订完成，不覆盖历史事实。
- 实施顺序：先冻结基线与字段权限，再建设草稿/修订和结构化命令，然后接入影响分析、API/AI 提案、前端工作台、下游定向重建、历史兼容，最后完成中英文、响应式、API/UI smoke 和发布门验证。
- 首期落地：`hackthon/backend/teaching_plan_workbench.py` 将草稿、变更集、AI 候选和历史修订与课程 envelope 保存在同一原子命令边界；正式应用更新 `course_teaching_plan` 来源向量并复用 representation reconciliation 标记旧表示过期。`GenerationLessonPlan.vue` 已提供字段编辑、AI 候选接受/拒绝、差异审阅、应用回执与修订比较/恢复。
- 位置：`hackthon/openspec/changes/upgrade-teaching-plan-workbench/`、`hackthon/docs/product-blueprint.md`；未勾选 OpenSpec 任务仍是后续范围，尤其是受控模块结构操作、自动定向重建、AI 小节/全课候选、离开保护和多端端到端验证。

## 2026-07-23 学科教学模板 V2 与课型化决策

- 背景：原有八类学科模板已经能区分数学、编程、科学、人文、语言等基本教学取向，但实现上倾向于给同一学科的每个小节装入近乎相同的一整套模块，导致课程越长，课节结构越容易重复；编程、人文、商业等过宽分类内部也缺少必要的教学差异。
- 产品边界：用户侧继续只保留通用、数学、编程与工程、自然科学、生命与医学、人文社科、语言学习、商业与职业八类稳定模式，不新增一批需要理解和选择的产品概念。内部细分只用于确定性教学判断，不成为课程、教案或蓝图之外的新对象。
- 结构决策：学科教学编排升级为“一级模式 → 必要的内部细分 → 当前小节课型”。八类模式各有五种互补课型，共四十种；每种课型必须声明教学目的、模块组合、可观察学习证据、质量底线与适用课程阶段。编程等宽领域再使用二十一种内部变体区分真实教学差异，但不暴露为新的用户步骤。
- 生成决策：系统根据课程阶段、小节标题、学习目标和知识重点确定性选择当前课型；每节保留目标、核心讲解、学习者行动和反馈检查四个公共模块，只加入当前课型所需的学科模块，最多再补一个由明确信号触发的条件模块。禁止每节机械复用整套学科模板，也不为分类或选型新增模型调用。
- 同源与稳定：课型和学科质量合同进入总体教案引领、分小节教案、课程蓝图、教师投影、正文与定向修复 Prompt，但不得改变冻结目录、知识身份、课程块角色、资料边界、难度合同、批次、检查点、恢复和发布协议。旧课程不迁移；旧版教学画像继续读取，在运行时补齐新字段。
- 教学依据：计算机课程以真实任务中的知识、技能与职业倾向整合为核心；数学强调表征、推理、问题解决与有支架的挑战；科学强调现象、模型、探究和证据论证；生命医学强调尺度、系统机制、定量证据与情境推理；人文社科强调提问、材料、因果与论证；语言强调理解、互动、调解和反馈后再表达；商业职业强调问题界定、决策、工具、角色协作和可评审交付。详细依据与来源保存在 `hackthon/docs/research/学科教学模板V2设计依据-2026-07-23.md`。
- 位置：`hackthon/backend/course_pedagogy_archetypes.py`、`hackthon/backend/course_pedagogy.py`、`hackthon/backend/course_prompt_composer.py`、`hackthon/docs/architecture/course-generation.md`、`hackthon/docs/product-blueprint.md`、`hackthon/openspec/changes/build-structured-adaptive-course-ai/`。

## 2026-07-23 教案双视图、知识绑定与课程蓝图单向派生决策

- 背景：现有教案已经承担课程正文生成依据，但用户侧更接近分小节生产合同，缺少老师判断整门课的宏观视图；知识库虽然进入主链，教案页面仍没有用稳定知识身份把知识、能力、易错和掌握标准直观呈现。课程蓝图一度被误解为与教案并列的产品概念，存在概念膨胀和双真源风险。
- 产品边界：目录、教案、知识库、课程是用户需要理解的主要对象，练习是课程内资产的聚合入口。课程蓝图保留为后台机器执行合同，不成为独立产品入口，不允许脱离教案独立编辑教学语义。
- 教案决策：一门课程只保存一份正式全课教案，前端在同一份数据上提供总体教案与分小节教案。总体教案面向老师展示课程定位、教学对象、总体目标、学习起点、教学策略、评价设计、章节进程和全课知识坐标；分小节教案既是备课工作纸，也是课程块和正文生成的直接依据。
- 知识决策：教案中的知识以当前课程知识库的稳定知识身份绑定并以圆角标签呈现。标签不是装饰性的关键词，必须能回到知识库中的原子知识，并继续携带可观察能力、可信易错、掌握标准、条件、边界及关系。
- 生成决策：保持已经稳定的“目录骨架 → 教案骨架 → 有界详细批次 → 本地唯一汇编 → 知识库与关系确定性编译 → 正文小节生成”顺序、模型调用类型、检查点、重试和恢复协议。课程蓝图从当前正式教案与确定性生成约束单向编译，并保存教案版本来源。`course_prompt_v24` 进一步让教师视图与生成模板共用同一份确定性总体教学引领：课程定位、总体成果、教学对象、学习起点、教学主线、章节责任、评价证据和小节前后衔接进入现有详细教案与正文 Prompt，但不能改变冻结目录、知识身份、模块集合、资料和难度合同；仍不增加模型调用。
- 迁移与实验：旧课程不迁移。只有确定会改善效果且不破坏稳定性的链路变化才直接进入主线；不确定的变化先做同输入对照，不以新概念或并行真源试错。

## 2026-07-17 一门课程一套知识库与六类关系网络决策

- 背景：当前知识库虽然有章节结构，但内容容易退化为章节、小节名称的复制粘贴，缺少原子知识点、能力、易错、掌握标准以及能驱动教学的关系网络；旧设计又把跨课程 `SubjectKnowledgeLibrary` 置于当前课程知识库上游，容易让可选参考变成运行时真源和发布门禁。
- 核心边界：灵知实行“一门课程一套知识库”。`CourseKnowledgeBase` 是当前课程唯一的产品知识库和运行时知识坐标，随同一 `course_id` 的课程生成、修改、生长、撤销与恢复。知识 ID 只要求课程内稳定，不跨课程共享。`SubjectKnowledgeLibrary` 降为可选术语、别名和生成校准参考；缺失、冲突或版本落后不得阻断课程知识库、AI 使用与个人状态投影。
- 结构决策：纵向结构固定为 `CourseDocument 章节 → 小节 → ConceptGroup → KnowledgePoint`；章节与小节仍由课程文档拥有，知识库只保存路径引用。每个原子知识点必须包含知识命题、条件或边界、来源与颗粒度，并至少关联一个可观察 `SkillUnit` 和一个可验证 `MasteryCriterion`；`Misconception` 无可靠依据时允许为空，不生成模板内容。
- 关系决策：正式知识关系只允许 `prerequisite / derives / equivalent_to / contrasts_with / applies_to / generalizes` 六类。父子包含、课程先后和对象引用不进入关系网，禁止用无教学含义的 `related` 兜底。关系保存方向、理由、条件、来源与修订；多前提使用 `relation_group_id + all_of / any_of`，前置与一般化执行无环检查，对称关系规范化后只保存一条。
- 绑定决策：`CourseKnowledgeMap / KnowledgeBinding` 只承担知识与正文、课件、目标、题目、掌握标准和学习记录的精确教学绑定，并声明 `introduces / explains / demonstrates / reinforces / practices / assesses / remediates / extends` 等教学作用。题目和课件不得默认绑定整节全部知识。
- 生成与质量：新课程必须先生成知识蓝图，再依据知识点、能力、关系和教学作用生成正文、课件与练习，最后共同发布课程文档、知识库和绑定修订。章节标题复制、粗知识点、模板易错、无理由关系、悬空端点和整节泛绑定都是发布硬错误。历史课程无法确认真实知识时标记 `degraded / needs_enrichment`，不得用标题投影伪装成正式知识库。
- 实体收束：`ImprovementPoint` 退出新知识库核心写入；稳定目标迁入 `SkillUnit`，具体练习迁入 `PracticeTask` 或正式学习资产，个性化提升建议由 AI 根据学习证据动态生成。旧字段仅兼容读取和分类迁移。
- 全链影响：正文、课件、多模态表达、练习、诊断、AI 老师、学习证据、学习者模型与复习路径必须消费同一课程知识 ID；知识变化通过影响分析精确标记受影响对象，历史事实保留发生时的知识 ID 与修订。后续实现不得单独修知识库页面而绕开课程生成和学习主链。
- 实现状态：2026-07-17 已落地 `course_knowledge_base_v2` 第一条纵向主链，包括知识蓝图先行、标题复制与模板内容硬门、六类关系校验、正文 / 目标 / 题目 / 五类教学表达 / AI 的课程内 ID 绑定，以及历史课程独立 AI 知识化和失败不覆盖。真实扫描的 27 门可读取旧课程均保持 `degraded`，尚未自动迁移；另有 1 个既有课程 JSON 损坏而无法读取。损坏数据修复、独立知识仓库、拆分合并命令、旧新 ID 映射、课程—知识双向影响、可恢复批量迁移和多教学模式真实验收仍未完成，后续不得把这次纵向落地表述为全系统完成。
- 决策覆盖：本条替代 2026-07-15“结构化同源与个体化生长决策”中“跨课程正式库 → 课程知识库 → 映射”的三层知识边界；证据、候选、用户确认和课程生长等其余结论继续有效。

## 2026-07-15 课程生成完整生命周期与发布分级决策

- 背景：课程生成正常路径已经具备任务、工作区、质量检查和正式发布，但取消、删除、创建失败、provider 超时、质量建议和前端缓存各自处理，导致任务、外壳、工作区和正式文档可能失联。
- 生命周期：一次首次创建由唯一 `GenerationJob` 统一拥有请求号、生成工作区、未发布外壳和后台协程。创建采用补偿事务；取消先持久化停止状态并等待协程，再清理任务专属对象；删除课程先终止所有关联任务；清理已发布任务只能删除临时状态，不能删除正式课程。
- 请求边界：一次弹窗提交持有稳定 `request_id`，同请求号并发或重试只返回原 `job_id/course_id`；关闭后重新发起才使用新请求号。课程主题在任何持久化前规范化并拒绝空白输入。
- 模型边界：SDK 隐藏重试关闭并设置连接与读取上限；业务层只做有限节点重试。provider 超时、空流和连接错误必须作为结构化失败进入草稿保存与恢复链，禁止把错误字符串写进课程正文。
- 质量边界：`final_status` 表达严格质量，`publication_allowed` 表达最低可发布性。少量难度、迁移或表达建议允许带警告发布；空正文、生成失败、critical 内容问题、无效证据、必用资料遗漏和资产阻断继续禁止发布。
- 投影边界：前端只投影后端任务和正式文档。已发布警告显示“可以学习，有优化建议”，不计入活动任务；课程节点数只统计二级可学习课节；失联未发布外壳保留审计但不进入课程架。
- 验收：后端 278 项、根 API 104 项、前端 259 项与生产构建通过；真实 HTTP 验证并行生成、暂停恢复、取消、删除、重复提交去重；真实浏览器验证目标课程为 20 节、正式正文可读、目录和 AI 老师可用。

## 2026-07-15 课程生成过程可见决策

- 背景：用户要求课程生成像 AI 回答一样逐段出现。现有课程生成虽然已经有统一 `GenerationJob`、阶段进度、节点状态、隔离工作区和失败恢复，但任务中心主要显示百分比与阶段名，用户看不到真实课程内容正在形成。
- 产品定义：课程生成必须同时做到“生产状态可见”和“真实产出可见”。用户提交后进入与课程卡绑定的生成现场，看到需求整理、资料解析、教学结构、蓝图、章节正文、学习资产、质量检查和发布阶段；正文按章节逐段流式出现，支持跟随当前章节或固定查看任一已产出章节。多个章节并行生成时分别呈现，不混成日志。
- 真源边界：流式内容在节点质量处理前明确标记为 `AI 草稿`，节点 finalized 后替换为定稿投影，整课通过最终质量门后才发布正式 `CourseDocument / CourseBlock`。过程可见不等于暴露模型隐藏推理，只展示可验证阶段、资料处理结果、正文增量和质量状态。
- 恢复契约：WebSocket 只负责实时增量，事件需关联 `task_id + node_id + sequence + draft_revision`；首次进入、刷新、断网重连和事件缺口从服务端工作区读取累计草稿与最后序号，再继续订阅。本地缓存不得独立证明任务仍在运行，也不得成为草稿或完成判定真源。
- 当前实现判断：`backend/task_manager.py` 已在节点 `on_chunk` 时调用 `push_stream_chunk`，`frontend/src/stores/generation.ts` 已累计 `streamingContent`，但 `CourseTaskCenter.vue` 尚未渲染它；因此能力只停在后端流与前端缓冲，不能称为用户可见的流式生成。

## 2026-07-15 多模态同源教学表达编译决策

- 背景：用户要求把灵知进一步建设成多模态生成软件，并系统调研视频、动画、音频、PPT、图解、模拟以及市面上的原生多模态课程，同时要求把既有课程资产的每一份价值继续深挖。现有灵知已经有 `CourseDocument / CourseBlock`、课程知识、目标、资料证据、正式题目、学习事实、学习者模型和课程变化候选，如果再为每种媒体建立独立生成与保存链，会直接破坏“结构化同源 + 个体化生长”。
- 产品定义：多模态不是媒体工具箱，而是“同源教学表达编译”。`CourseBlock` 继续是课程语义和顺序真源；图解、幻灯、音频、动画、模拟、视频和数字人作为 `TeachingRepresentation / RepresentationSet` 挂回稳定课程块，不复制课程树、正文、知识、题目或学习状态。
- 编译链：目标链固定为 `课程块 + 知识 + 目标 + 资料证据 → RepresentationPlan → Diagram/Slide/Narration/Scene/Interaction typed spec → renderer/provider → 多模态质量门 → RepresentationSet → LearningRuntime 选择 → 学习证据评价`。多模态提供方只负责渲染，不拥有课程语义和学习事实。
- 复用与失效：定义、推导、例子、代码、数据、知识图、题目、误区、笔记和诊断先形成稳定语义单元，再派生多种表示；每个表示保存源修订和派生指纹。上游语义变化精准使相关表示 `stale`，主题、镜头、语速等表现变化只重渲染，不整课重做。
- 双向编辑：PPT、动画、模拟和讲稿的表现修改只产生表示修订；定义、例子含义、知识顺序、目标和评测变化必须解析成 `ChangeOperation` 候选，显示理由、范围与影响，用户确认后才修改课程真源。无法判定的修改保持待解释，禁止盲目反写。
- 路由与个体化：表达选择综合知识形态、教学 `role`、目标、当前课程证据、设备、无障碍、质量、成本和延迟；不建立固定视觉型/听觉型学习风格。观看、点击和一次反馈只作为弱证据，需与正式作答、诊断和独立复验共同评价效果。
- 实施顺序：先建立表示实体、派生关系与统一任务，再完成图解/图表，然后是可编辑 PPT 与 TTS、结构化动画与交互模拟、证据驱动选择，最后接入自由视频、数字人和启智教师公共课程协议。高成本表示按需生成并预先定义降级链，失败不能阻断基础课程。
- 开源策略：OpenMAIC 只移植场景/动作 DSL、播放器、白板、slide schema、provider registry 与 exporter 等发动机，不 fork 其课程和学习状态；ClassBuild 吸收资产计划与陈旧检测；Code2Video、Math-To-Manim 吸收 Planner/Coder/Critic 与 typed artifact/局部修复链；Mermaid、ECharts、Excalidraw、Manim、Motion Canvas、Three.js 作为可替换结构化渲染器逐级接入。所有许可证和第三方依赖在实现时重新审计。
- 当前状态：本轮只完成调研、蓝图与目标架构，不代表代码能力已经实现，也不直接修改启智。高影响实现必须先形成正式 OpenSpec，并继续使用灵知已有 `GenerationJob`、课程命令、学习事件和候选确认主链。
- 位置：`hackthon/docs/research/multimodal-course-generation-landscape-and-lingzhi-integration-2026-07-15.md` 与 `hackthon/docs/product-blueprint.md`。

## 2026-07-15 结构化同源与个体化生长决策

- 背景：用户决定先不修改启智，优先把灵知学生端的 AI 能力补完整。现有灵知已有 `CourseDocument / CourseBlock`、正式学习事实、学习者模型、统一 AI 老师、块级候选和课程知识设施，但仍主要是一次生成课程与当前位置被动答疑，尚不能把持续学习证据转化为当前和未来课程的完整结构变化。
- 最高原则：后续产品只以“结构化同源 + 个体化生长”为两条最高原则。结构化同源指课程、课程知识、目标、题目、记录和证据各有唯一真源，并通过稳定 ID、修订、引用和依赖图联动；个体化生长指课程的知识颗粒度、推导、例子、支架、任务、跨度和节奏随当前学生的真实证据持续变化。
- 知识边界（2026-07-17 修订）：`CourseKnowledgeBase` 是一门课程唯一的产品知识库和运行时坐标；`CourseKnowledgeMap / KnowledgeBinding` 连接课程知识点、正文块、课件、目标和题目。跨课程 `SubjectKnowledgeLibrary` 只保留为非阻塞术语与生成参考，不拥有当前课程知识身份。课程与课程知识可以双向生成影响候选，但个人变化不得自动写入参考目录。
- 证据边界：当前课程中用户向 AI 或问答框提交的每条文字都登记为原始思维证据；错题、作答、诊断、笔记和反馈作为事实证据。原始 `EvidenceItem`、可反证 `AdaptationHypothesis` 与确定性 `LearnerModel` 必须分层，一条输入不能直接变成稳定画像或掌握结论；当前阶段证据不跨课程使用。
- 动态门槛：证据强度综合直接性、范围、严重度、独立重复、一致性、效果、新鲜度和反证。单条非常明确的强证据可以立即形成局部候选；跨章节稳定模式可以推荐广域范围；“三次”只是例子，不能写成所有场景的硬阈值。问答结束、块完成、正式提交和离开小节是弹性汇总点，不阻止强证据即时行动。
- AI 权限与确认：AI 可以在候选层规划行级补写、块插入或修改、拆分、合并、重排、移除、检查点、补救路径、难度和知识变化，也可根据第二节证据提前调整第三至第五节；AI 不得替用户确认。未确认变化跨会话高亮保留，必须显示调整理由和范围，并支持接受、拒绝、重新生成、补充要求、目录框选、部分接受和安全撤销。
- 难度定义：难度不再只是一档标签，必须落实为知识颗粒度、抽象程度、推导完整度、例子数量与迁移距离、支架、任务复杂度、知识跨度、节奏、反馈频率和掌握独立性；只增加字数、术语或题量不算有效调整。
- 实施边界：当前不修改启智、不实现 PPT 双向编辑和视频生成。启智公共课程模板、灵知个人课程与可选参考目录未来属于三个权限域；个人课程变化只能成为教师审核候选，不能反向自动发布。
- 位置：完整交接文档为 `hackthon/docs/requirements/灵知AI课程智能体需求文档.md`，唯一蓝图已回写 `hackthon/docs/product-blueprint.md`，实施规格为 `hackthon/openspec/changes/build-structured-adaptive-course-ai/`。

- 背景：前期课程生成与课程使用为了解决覆盖失败、历史证据和学习迁移，引入了完整 `CourseVersion` 产品模型；同时新生成主链仍把完整 Markdown 当作课程正文真源，正式题目、复习、图谱和媒体则作为正文之外的资产或页面存在。用户明确指出，这种设计给产品增加了不必要的版本包袱，也没有表达课程可自由编排、可穿插代码、图片、视频、图表、题目和复习的真实形态。
- 产品结论：课程产品层只有一个当前 `CourseDocument`，结构固定为 `Course -> Section / Group -> ordered CourseBlock[]`。`CourseBlock` 的呈现与交互类型 `kind` 必须和教学作用 `role` 分离；文本、公式、代码、图片、音频、视频、图表、正式练习、代码任务、反思、项目、复习检查点和图谱嵌入均通过异构教学块进入同一课程流。
- 修订边界：用户不再感知或管理 `CourseVersion`、候选版本、版本比较和版本迁移页面。内部继续保留 `course_revision`、`block_revision`、稳定 ID、块墓碑、旧新 ID 映射和轻量操作日志，用于乐观并发、撤销、锚点迁移、作答证据冻结、审计和故障恢复；这些技术修订不得重新包装成用户可见版本产品。
- 领域边界：展示位置与领域归属分离。`PracticeBlock` 引用正式任务，作答仍归 `PracticeAttempt`；`ReviewCheckpointBlock` 保存范围和触发规则，个人到期状态仍归 `LearningRecord / LearningEvent`；`GraphBlock` 引用课程知识子图，个人掌握只作为派生覆盖；`MediaBlock` 引用正式媒体资产。笔记本、错题本、复习中心、掌握图和学习报告继续只是正式事实的功能视图。
- 主链结论：唯一产品主链固定为 `用户目标与资料 -> 课程生产与质量门 -> 当前 CourseDocument / CourseBlock -> LearningRuntime -> 学习行为 -> LearningEvent / LearningRecord / PracticeAttempt -> LearnerModel -> 统一 AI 助手 -> 临时回答或可确认 ActionProposal -> 领域命令与回执 -> 当前课程改进或新的学习行为`。个性化临时解释与补救不自动写回正式课程。
- 兼容策略：旧 Markdown、旧 node、旧 annotation、旧 quiz/review 和旧路由继续通过输入或输出适配器接入同一个课程与学习内核，兼容层不得拥有独立状态机、独立 AI prompt 或独立保存逻辑。旧 Markdown 确定性迁移为有序块，无法识别内容保留为 `raw_markdown`，疑似题目只生成候选资产。
- 被取代的产品语义：本决策取代“课程必须发布为用户可见版本”“完整 Markdown 是课程本体”“题目、复习与图谱只能作为正文外挂”“课程改写必须进入版本页面”的产品设计。此前关于稳定修订、历史作答不可改写、内容锚点、资产质量门、学习事实分层、LearningRuntime、AI 提案确认与幂等回执的工程原则继续有效。
- 横向护栏：正式事实不可伪造；个人数据不可串用或误删；AI 操作必须可拒绝；所有修改必须可恢复且不得静默覆盖；AI、媒体、图表或评分服务失败时，确定性学习主链仍可继续。
- 位置：`hackthon/docs/product-blueprint.md`。后续后端新旧链合并必须围绕 `CourseDocument + CourseBlock + LearningRuntime + 统一 AI 助手` 建立 OpenSpec，不能再增加平行课程真源或新的版本产品。

## 2026-07-13 学习现场单一路由与个人课程流收束决策

- 背景：课程生成、正式练习、诊断补救、学习记录、运行时适配和 AI 老师已分别具备能力，但旧 `CourseView / CourseWorkspace / SmartBar / 固定笔记列` 仍留下第二套页面语义，新增能力也没有全部进入正文课程流。
- 产品结论：学习者主空间固定为课程库与唯一学习现场。桌面保留左目录、中正文、右侧按需 AI 老师；移动底栏使用目录、练习、记录、图谱和 AI 五个并行工具入口，正文是当前页面而不再重复做导航项。统计继续是按需工具，不升级为顶部模式。
- 任务结论：正式练习只从正文任务引用或唯一连续性动作进入同一覆盖层，沿用 `PracticeAttempt / DiagnosticCase / RemediationSession`，关闭后刷新运行时并恢复来源滚动位置；不得复制题目或建立独立练习页。

- 边界：本轮没有宣称 `CourseDocument + CourseBlock` 已成为后端唯一持久真源；历史 `node + content_blocks` 仍是兼容承载，正式媒体块和块级课程命令属于后续内核迁移。

## 2026-07-12 取消学生课程工作室、改由 AI 运行时编排决策

- 背景：异构 `CourseBlock` 与难度节奏模型原本被进一步设计成课程工作室和手工块拖拽界面，但学生交换两个解释或题目顺序没有可靠教学依据，只会把内部课程结构暴露成无意义操作。用户明确要求由 AI 根据当前学习情况决定何时增加解释等教学块。

- 课程稳定性：基础 `CourseDocument / CourseBlock` 保持稳定。AI 不因一次交互随意重排基础课程，而是通过 `LearningRuntime` 在相关位置叠加个人临时 `AdaptiveBlock`，包括解释、反例、过渡、不计入掌握的理解检查、提示和最小补救。

- 被取代语义：本决策取代独立课程工作室、学生块拖拽、手工课程顺序编辑和“所有 AI 插入都必须逐次确认”；不取代内部 `CourseDocument / CourseBlock`、质量门、稳定 ID、修订、撤销和正式写入协议。
- 位置：`hackthon/docs/product-blueprint.md` 与 `hackthon/docs/frontend-product-convergence-blueprint.md`。后续 UI 样板应把原“课程工作室”草图替换为“AI 运行时适配”状态。

## 2026-07-12 手写便签与 AI 问答沉淀进入正文决策

- 背景：3 月版本把划线提问后的 AI 内容自动保存为笔记，是当时技术与界面限制下的妥协。真实目的不是把回答送进独立笔记本，而是让这次理解回到发生位置，成为个人课程正文中的可持续内容。用户进一步要求手写笔记也进入正文，并像 Word 插图一样由正文自动重排。
- 三层正文：最终个人学习流固定为 `稳定 CourseBlock + 临时 AdaptiveBlock + 持久 InlineLearningRecordBlock`。`InlineLearningRecordBlock` 只投影正式 `LearningRecord`，不写入基础 `CourseDocument`，不建立第二笔记真源。
- 手写便签：用户选中正文后点击“笔记”，原文附近立即出现行内编辑器并自动保存。短、纯文本便签在宽屏可作为页边便签参与正文环绕；长笔记、公式、代码和移动端统一完整占行。系统只保存语义锚点，不保存像素坐标或任意浮动位置。
- AI 问答沉淀：用户基于课程块主动提问只授权生成临时个人内容，不自动创建 `LearningRecord`。用户明确点击“保留为个人内容”后，才创建 `LearningRecord(note, source=ai_qa)`；连续追问继续使用同一个行内结果块，不复制完整聊天和中间输出。
- 保存边界：块级回答默认可移除，只有明确保留才通过既有提案与回执协议长期沉淀，并支持编辑、折叠、删除和撤销。普通聊天、AI 主动提醒和未完成输出不得自动保存；正式课程、正式题目、掌握事实和其他主动创建对象继续走确认协议。
- 排版与迁移：原文保留轻量标记和末尾图标作为锚点，便签或问答摘要紧邻原段落显示。短便签最多环绕一个，其余折叠聚合；移动端全部块级排列。课程内容变化后沿用 `block_id + block_revision_id + text_position + text_quote` 迁移并明确待确认或失效状态。
- 被取代语义：本决策取代“AI 回答只存在聊天侧栏”“自动保存后只能去笔记本查看”和“正文记录永远只是划线加小图标”；不取代 LearningRecords 真源、聚合记录工具、语义锚点和删除/迁移护栏。
- 位置：`hackthon/docs/product-blueprint.md` 与 `hackthon/docs/frontend-product-convergence-blueprint.md`。后续真实样板必须同时验证短便签环绕、长问答占行、连续追问更新和移动端回落。

## 2026-07-14 块级 AI 入口分层与效果反馈决策

- 背景：块级 AI 已形成四项学生理解动作，但规范课程把“改进正式正文”作为第五项放入同一菜单，学生答疑与课程资产编辑的权限、结果和风险边界混在一起；系统也只能记录回答完成，不能知道这次解释是否解决了当前问题。
- 入口分层：桌面端悬停课程块时，左侧留白轨道直接显示解释、举例、简化和提问，不设前置星光按钮；存在蓝紫层级轴的三级及以下节点，四项菜单统一放在线左侧，层级轴保持完整并作为菜单与正文的对齐基准。触屏端使用轻量点击入口。结果进入来源块下方的临时个人补充。具备课程编辑能力时，块右上角另提供低权重“改进正式正文”入口，继续进入既有候选、质量门和确认应用工作区。全局 AI 继续只承担历史、跨块问题和低频兜底。
- 回答结构：行内回答标题同时标明动作与来源块，连续追问在同一块内按轮次叠加，不覆盖前文，也不堆成多张卡。只有用户选择“重新生成”并说明需求时，才覆盖当前选中的回答。块级回答必须在当前问题处收束，不主动提出下一步、出题、保存或课程改写，也不使用“如果你愿意”等结尾邀请。
- 唯一增量：完整回答只增加“这次回答解决你的问题了吗？ / 已解决 / 还不清楚”。选择关联用户、课程、节点、会话、assistant 消息、块级动作和内容锚点，幂等写入 `assistant_answer_feedback_submitted` LearningEvent。

- 复用：以后增加 AI 评价指标时，先消费正式反馈事件并与后续独立学习证据对照，不在组件本地建立点赞状态，不把单次主观反馈直接等同掌握或教学效果。

## 2026-07-14 学习事实、学习者模型与统一 AI 老师主链收束决策

- 背景：学习域同时存在 `LearningEvent`、annotation、Learning OS、旧 profile、`LearnerState`、`TeachingDecision` 和浏览器统计，多条链都能写事实或生成画像。AI 老师虽然入口统一，但会读取互相冲突的状态，课程输出质量还会被误记为学习者事实。
- 正式事实：学习行为必须先进入 `LearningRecord`、`PracticeAttempt`、`LearningSnapshot`、诊断等正式领域对象，再以稳定操作 ID、幂等键和领域对象修订关联 `LearningEvent`。前端统一携带安装级匿名学习者 ID；正式学习接口缺失身份或使用 `default_user` 时拒绝个体读写。

- AI 边界：`LearningRuntime` 返回同批模型摘要和修订；`AIContextPackage` 只在意图需要时读取当前目标的最小模型证据。`teaching_guidance` 只调整本轮讲法，不拥有学习事实或竞争下一步；AI 回答、会话摘要、用户接受表述和 provider 失败都不能直接修改模型。
- 退役结果：生产代码删除旧 annotation、profile、Learning OS、`LearnerState`、`TeachingDecision`、长期学习种子路由及前端旧 profile/learning Store；学习概况取代独立画像页。课程输出质量继续做确定性检查，但不再写入学习者事件账本。
- 验收：两套后端测试、前端测试与生产构建通过；真实 HTTP 验证“事实写入 -> 模型修订变化 -> 运行时同修订 -> AI 上下文最小暴露”，并验证缺失身份被拒绝、重复写入幂等、provider 失败不改变模型。桌面、1024px 与 390px 的学习概况无横向溢出。

## 2026-07-14 统一知识库与课程知识映射分离决策

- 背景：上一版虽然把题目、误区和正文绑定到稳定 ID，但错误地将 `course → chapter → section → topic → knowledge_point` 定为正式知识树。这会让学生看到第二份课程目录，同一知识在不同课程中产生不同身份，课程顺序也会被误认为学科关系。该判断已由当前线性代数真实接口和 Code 平台知识库、标准库实现对照确认，必须直接改正，不能继续在旧定义上追加补丁。
- 正式两层：版本化统一知识库是跨课程学科语义真源，层级为 `subject → domain → topic → concept → knowledge_point`；能力点挂到一个主知识节点，易错点和提升点挂到能力点，四类对象共享同一个学科包、版本和修订。`CourseKnowledgeMap` 只保存课程节点、正文块与正式知识之间的覆盖、顺序和待归一候选。
- 身份边界：正式知识 ID 由版本化学科包决定，不包含课程 ID。课程生成模型不能自造正式 ID；只有规范名称或正式别名精确命中才能自动映射，相似但无法确认的表达保持待归一。课程映射拥有独立映射 ID，不得反向改写学科层级和正式关系。
- 统一库边界：能力点回答“应该会什么”，易错点回答“常错在哪里”，提升点回答“接下来怎样提高”。这些条目只为 AI 提供候选地图、统一命名和颗粒度；AI 必须先依据当前课程、任务与证据判断，再标记命中、部分命中或未命中，不能为了填 ID 强行套库。
- 资产与模型：正文、题目、掌握标准、课程误区、诊断和补救引用同一库中的正式知识、能力和易错 ID。学习者模型从正式事实确定性投影知识与能力状态，只有经诊断确认的易错才能形成个人信号；个人状态不写回正式库，一次阅读、错误或 AI 判断仍不能直接形成稳定结论。
- 迁移：现有 `knowledge_tree_v1` 降级为迁移输入和课程映射原料，旧课程只从 `key_points`、`knowledge_structure` 与旧图谱标签确定性匹配，不再生成“核心知识”正式主题。旧图谱运行时路由、课程树真源代码和前端旧命名随新链路接管后删除，不恢复旧力导向图或 AI 自动覆盖知识的链路。
- 学生体验：保留现有浅色高密度弹层、搜索、详情和正文跳转外壳，内容改为学科语义路径、当前课程覆盖、相关能力、易错点和提升方向；左侧课程目录继续承担课程导航，知识库不能再复制它。正式知识维护和候选审核属于教师或管理工作台。
- 首个闭环：线性代数只发布一个同时包含知识、能力、易错和提升的学科包，贯通新旧课程映射、学习资产、正式作答、诊断、AI 上下文、学习者模型和学生端；验证后再按同一通用模型扩展其他学科，不能为每门课程或每个学科另造一套运行时规则。
- 位置：`hackthon/openspec/changes/archive/2026-07-14-unify-knowledge-skill-mistake-library/`、`hackthon/backend/subject_knowledge.py`、`hackthon/backend/course_knowledge_map.py`、`hackthon/frontend/src/components/KnowledgeLibrary.vue` 与 `hackthon/docs/product-blueprint.md`。

## 2026-07-16 课程生成质量与课程知识库同链决策

- 背景：真实新课虽然能发布，但正式学科包仅覆盖线性代数时，其他课程的学生知识库会完全为空；同时课程正文可能保留模型自我纠错和题干答案矛盾，旧质量汇总仍将节点判为通过。只加强 prompt 无法解决生成、资产、知识和质量各走一套规则的问题。
- 唯一生成链（2026-07-17 修订）：课程蓝图确定后，在同一 `GenerationJob` 工作区先形成 `CourseKnowledgeBase` 知识蓝图，再依据它生成正文与资产并建立 `KnowledgeBinding`。课程局部结构固定为“章节 / 小节路径 → 概念组 → 原子知识点 → 能力点 / 易错点 / 掌握标准 + 六类关系”，内容生成、修订 prompt、学习资产、学生知识库读取和首次发布质量门必须消费同一批稳定课程内 ID。

- 质量边界：质量闸门以节点正文、难度子报告、资料证据和课程知识库结构共同决定通过状态。必须识别模型自我纠错、题干过程答案矛盾等一致性风险；核心知识覆盖采用语义片段匹配，迁移检查覆盖真实的应用场景、条件变化、算法取舍、规模与硬件约束，不能依赖几个固定词的字面命中。
- 当前范围（2026-07-17 复核）：2026-07-16 已实现的首次生成、历史课程确定性编译、资产引用、学生读取和发布质量门只属于旧结构底座；新的概念组、原子知识点、六类关系、掌握标准、精确绑定和标题复制禁令尚未进入代码主链。课程知识库独立修订仓库、候选式拆分合并、课程与知识双向影响、跨域命令组和学习后效果复验仍属于后续 OpenSpec 任务，不得提前宣称完成。

- 背景：章节 prompt 已有学科、难度、资料和知识上下文，但各节仍可能独立写好却在全课层面重复、错接或提前讲完后续内容；模型大纲异常时旧链还会退化为固定两章四节通用课程，表面完成实际违背用户要求。

## 2026-07-16 结构化同源与个体化生长按纵向闭环验收决策

- 背景：同源教学表达与个人课程生长原本按 `P0 / R1 / R2 / R3` 分层实施。该顺序有助于控制依赖，但容易把共享模型、单个接口或局部测试通过误报为产品完成，重复出现“新模块各自可用、整体体验却断裂”的问题。
- 验收单位：`P0 / P1 / R1 / R2` 只表示施工依赖，不表示产品优先级和完成度。结构化同源以“唯一课程真源 → 五类教学表达 → 来源绑定 → 影响预览 → 用户决定 → 同步/降级”为一条验收链；个体化生长以“个人证据 → 适应假设 → 范围候选 → 用户决定 → 个人运行时投影 → 撤销 → 后续效果比较”为另一条验收链。
- 当前落地：大纲、教案、讲义、练习册和 `SlideDeckSpec` 已从同一 `CourseDocument` 编译并支持 PPTX 导出；PPT 编辑先区分表现、等义、语义和模糊变化。AI 问答、记录、练习和反馈证据已进入用户与课程隔离的生长状态，足够证据可形成当前或当前加后续范围候选，接受后只改变个人运行时，支持拒绝、撤销和后续表现比较。
- 安全边界：自动证据链不得直接修改共享课程；旧 `source=evidence` 提案不再承担主动生长规则。表现层修改不得冒充课程语义修改；语义修改必须经过影响预览和用户确认。任何候选被接受、内容变长或用户点击完成都不能直接证明学习改善。
- 未完成边界：异步精准重建、最后可用版本降级、图解与动画规范、外部 PPT 回导、完整课程操作代数、知识双向影响、跨域恢复、行级候选和真实长期学习效果仍未完成，不得因首个联合闭环可运行而宣称完整 OpenSpec 已完成。
- 复用：以后跨模块大改先写两条或多条真实用户闭环和共同真源，再拆任务层级；每个阶段只记录“能力存在 / 进入主链 / 端到端闭环 / 效果验证”，最终完成声明必须由纵向演示和故障矩阵共同支持。
- 位置：`hackthon/backend/representation_compiler.py`、`representation_edits.py`、`course_evolution.py`、`learning_runtime.py`、`frontend/src/components/TeachingRepresentationsOverlay.vue`、`CourseEvolutionPanel.vue`、`docs/product-blueprint.md` 与两个在途 OpenSpec。
## 2026-07-17 结构化同源与个人课程生长演示闭环决策

- 背景：两段演示要求分别证明“一处语义变化，多种课程表达受控同步”和“学习证据形成隔离的个人课程生长”。现有代码已有注册表、候选和覆盖层，但自动确认与手动构建走不同重建路径，个人分步演示也没有正式动画规格，效果评价可能读取无关练习。

## 2026-07-18 六步生成的真实阶段边界与回改失效决策

- 背景：六步 UI 已经存在，但目录生成内部仍提前编译教学模块；课程内容确认后还会新增练习资产和执行可改变结果的修复。这样用户确认的只是中途快照，不是真正的阶段产物，上游回改也没有完整清除旧下游。
- 阶段边界：目录只负责课程结构与每节职责；目录确认后先冻结全课小节职责和后续保留边界，再逐节生成知识；知识确认后才编译教学方案；教学确认后生成正文；第 5 步等待确认前必须完成正文块、练习、掌握标准、易错、知识映射和质量检查；第 6 步只做同源与发布判断，不再静默改写用户审阅过的内容。
- 同源边界：每一步保存自身产物修订和实际消费的全部上游修订。确认时若输入修订已变化必须拒绝；发布时同时核对产物和输入链。用户从后续步骤返回目录时，知识、教学、内容和发布全部进入“需要重做”，重新确认目录后旧知识库、教学块、正文、资产和质量报告从工作区清除。
- 产品边界：当前目录支持直接返回修改；知识和教学支持产品级审阅与确认，但带用户修改意见的定向重做尚未开放，不得宣称六步都可编辑。知识审阅需要展示每节职责和关系，内容审阅需要展示质量、学习资产和人工关注项。
- 复用：以后新增阶段确认点必须满足“确认前产物已完整、确认后该阶段不再变异、上游变化可确定性作废下游”三个条件，不能只增加按钮或百分比。
- 位置：`hackthon/backend/guided_generation.py`、`course_generation_workflow.py`、`course_service.py`、`task_manager.py`、`routers/course_versions.py`、`frontend/src/components/CourseTaskCenter.vue`、`docs/product-blueprint.md` 与现有结构化课程 OpenSpec。

## 2026-07-17 结构化课件编译与同规格预览导出决策

- 背景：旧 PPT 虽然能导出，但本质是把课程正文按小节塞进页面，缺少教学意图、页面容量、版式差异和知识依据；浏览器预览与导出文件也可能各走一套渲染逻辑。继续只调整样式或 prompt 会让“同源”退化成同一段文字的多次复制。
- 唯一真源：课程语义仍只由 `CourseDocument`、正式题目和课程知识映射拥有。课件先编译为版本化 `SlideDeckSpec`，每页明确教学作用、版式、核心信息、结构化内容块、讲者备注、来源块、知识、能力、易错点和正式题目引用；课件不得成为第二份可独立漂移的课程正文。
- 同规格边界：学习页中的课件工作区和可编辑 PPTX 必须消费同一份 `SlideDeckSpec`。浏览器不能临时重组另一套页面，导出器也不能重新摘要正文。课程变化后只在影子结果完整通过时原子发布；逐页流式事件只用于展示生成现场，不能提前覆盖最后可用版本。
- 质量边界：课件质量门同时检查语义和视觉容量，包括来源绑定、必要教学页、Markdown 泄漏、正文整段复制、未知版式、全局与版式级文字容量。表现层修改保存在课件覆盖层，兼容重建时继续保留；语义变化仍回到正式课程命令和影响确认链路。
- 体验边界：2026-07-18 经用户确认，PPT 不再放在原学习页“教学资源”弹层，改为课程顶栏右上角一级入口和独立全屏工作台。界面独立只用于充分利用备课、编辑和投影空间，数据仍读取同一 `SlideDeckSpec`、来源绑定和派生注册表，不建立第二课件真源。工作台固定采用左侧完整页序、中间 16:9 画布、右侧质量/来源/编辑信息，顶部提供同步课程、交给 AI 老师、全屏演示和最右侧 PPTX 导出；教学资源弹层只保留大纲、教案、讲义和练习册。
- 内容与迁移：借鉴启智 PPT 模块的“整套大纲规划 → 分页填充 → 同结构预览与 PPTX → 讲者备注”思路，但不迁移其外部 iframe 或独立资源语义。灵知每个教学单元稳定形成学习目标、核心讲解和理解检查；正式题目优先引用原题，没有现成题目时只基于本节目标和原课程块生成解释任务与自检标准。
- Demo 证据边界：2026-07-18 第二轮打磨后，学习目标不再只绑定目标页，而是显式进入教案重点、讲义引导、核心讲解、例题和理解检查的来源依赖。目标变化先在全屏影响图中展示“修改前后教学证据、系统语义解释、真实受影响单元、明确保持不变单元”，教师确认前不修改课程真源；同步回执逐单元展示实际前后差异，并区分 `content_changed` 与 `source_verified`。演示模式补齐进度、讲稿快捷键和临时黑屏。
- 验收：原有真实“数据结构：原理与AI应用”97 页编译、10 类实际版式、97 份讲者备注和东亚字体验收继续有效；本轮另用真实课程生成 19 页完整课件，发现并修复内容增强后的易错页容量溢出，后端专项测试、前端入口/工作台/演示/导出测试和生产构建通过。导出文件页数、中文文本、东亚字体声明和讲者备注均可解析，并在原生 Microsoft PowerPoint 实际打开确认中文无乱码、对象可编辑。

## 2026-07-18 首次课程生成改为分阶段、可恢复生产线决策

- 背景：旧链在一次模型调用中同时要求课程目录、逐节知识结构和全课关系，复杂 JSON 只要局部不合法就整课纠正；审阅点又位于重计算之后。模型慢、格式错误或服务中断时，用户长期只看到固定百分比，已完成的局部结果也无法成为最小恢复单元。
- 正式生产顺序：同一 `GenerationJob` 固定为六步：1 需求，2 目录，3 知识蓝图，4 教学方案，5 课程内容，6 质量与发布。提交需求视为确认第 1 步；第 2 至第 6 步都必须展示阶段产物并等待用户确认，确认后才继续同一任务。产品不再提供直接生成或快速模式入口。
- 审阅边界：目录确认前不存在 `CourseKnowledgeBase`，知识蓝图确认前不形成教学方案，教学方案确认前不生成完整正文，课程内容确认前不进入最终发布检查，质量与发布确认前不产生正式课程。用户只判断产品内容，内部知识 ID、关系端点、质量矩阵和格式修复由系统负责。
- 同源边界：每一步确认同时冻结当前产物修订和它消费的上游修订。后续产物只能消费已确认修订；上游修订变化时，下游确定性进入“需要重做”。最终发布报告必须证明目录、课程知识库、教学方案、正文、目标、题目和教学表达仍来自同一条确认链，任一漂移都阻止发布。

- 运行可见性：前端固定展示 1—6 步及“未开始、生成中、待确认、已确认、需要重做、失败”状态；后台阶段继续携带当前小节、完成数、总数、心跳等待秒数和真实后端错误。每个目录或知识调用有独立阶段超时，超时后停止当前最小单元并保留最近检查点。
- 质量边界：知识包只能引用当前小节新知识和前序已存在的规范知识名称；系统随后分配稳定课程内 ID 并编译六类关系。全课知识门通过后才允许正文生成，最终一致性门仍负责跨节重复、顺序、承接和后续边界。
- 验收：原有专项回归继续覆盖目录停点、局部知识校验、单节失败与断点跳过；新增门禁必须覆盖六步顺序确认、越步拒绝、服务重启停留、上游失效传播、同源发布阻断、中英文步骤工作台和真实浏览器验收。未完成这些验证前不得把六步生产线表述为已完成。

## 2026-07-18 教学风格升级为课程块编排偏好决策

- 背景：课程创建原有“学术严谨、工业实战、苏格拉底、生动幽默”主要作为自然语言形容词进入 prompt，无法证明它实际改变了哪些课程块，也没有与难度共同决定每个块的挑战和支架。用户明确课程已经是块状教学设计，所谓风格应体现在理论推导、案例、真实场景、项目、代码和反馈等块的分布，而不是文字语气或视觉排版。
- 概念边界：教学结构回答“这个学科必须怎样教”，课程编排偏好回答“跨学科块角色怎样分布并形成节奏”，难度同时回答“目标等级需要哪些额外教学动作”和“每个块要求多大挑战、多少支架”，`CourseBlock.kind` 回答“最终用富文本、公式、代码实验或项目怎样呈现”。编排偏好与难度都不控制 AI 老师人格、页面排版和正文文风。
- 正式预设：新课程只展示 `balanced / theory_driven / example_driven / project_driven / inquiry_driven` 五种偏好。旧 `academic / industrial / socratic / humorous` 只按固定表映射到理论推导、案例实战、问题探究、智能均衡，用于历史任务恢复，不再成为新课程主输入。
- 编译顺序：先由学科教学模块注册表生成必需和条件模块，再由课程编排画像增加并排序跨学科模块，随后由目标难度增加或提升相应模块，最后把节级难度按块角色投影为支架、自主性、迁移和反馈契约。入门增加分步示范与带支架练习；进阶使用学科基线；高阶按课程位置增加深入推演、学科高阶模块和迁移挑战。后层不得删除学科必需模块，也不得绕过资料证据边界编造行业事实。
- 去重与追溯：学科、编排偏好和难度同时选择同一模块时只保留一个实例，使用 `selection_reasons` 记录全部选择原因；学科条件模块被难度选中时提升为必需。六步生产线的教学方案必须区分偏好新增和难度新增，确认后正文 prompt 逐项消费模块实例。最终 `CourseBlock.payload` 保留模块 ID、实例 ID、有效来源、全部选择原因、偏好和块级难度，教学方案与正式课程可以对账。
- 产品边界：本期不开放权重编辑器、拖拽块设计器或学生课程工作台。用户只选一种可理解偏好，系统负责确定性编译；更细的自然语言要求仍进入额外要求，但不能冒充正式块配方。
- 位置：`hackthon/backend/course_composition.py`、`course_pedagogy.py`、`course_service.py`、`course_prompt_composer.py`、`frontend/src/components/CourseGenerationDialog.vue`、`CourseTaskCenter.vue`、`docs/product-blueprint.md` 与 `openspec/changes/make-difficulty-drive-course-block-recipes/`。

## 2026-07-18 本节课程生长统一“块内升级 + 缺失块新增”决策

- 背景：用户明确要求同一小节既能强化已有理论推导，又能在缺少实战内容时新增实战块，并要求新内容立即进入课程知识、题目、PPT 和讲义的同源链。原链只能在目标块后追加支持块；块级重生成又是另一套候选状态，无法表达一个请求中的“已有则升级、没有则新增”，重复全对也只被当作缺口反证，不能推动课程提高挑战。
- 唯一方案链：用户主动本节调整与学习证据挑战建议统一进入 `CourseEvolutionPlan`。先解析要强化的教学 `role` 和难度方向，再读取本节真实 `CourseBlock.role`；已有作用执行 `REPLACE_COURSE_BLOCK` 并保留块 ID，缺失作用执行 `INSERT_COURSE_BLOCK`。不得用标题或 UI 顺序替代正式角色判断，也不得为两类触发建立第二 Store、第二确认状态或第二课程正文。
- 候选与正式提交边界：每个块候选生成后立即保存到方案工作区，生成失败保留检查点且不修改正式课程。所有候选必须同时通过本节知识引用、范围、目标角色、重复和内容质量门；全部通过后才允许用户整体确认。确认以稳定命令 ID 在一次 `CourseDocument` 提交中同时应用 replacements 与 insertions，避免半节课程处于新旧混合状态。
- 结构化同源边界：生成 prompt 消费本节 `CourseKnowledgeBase` 知识、能力、易错、掌握标准和关系上下文；候选块必须绑定本节课程内知识 ID，不能借用其他课程。提交后按课程操作日志对账并安全重建受影响教学表达；重建失败保留最后可用表达并在回执中明确失败，不能伪装同步成功。
- 学习证据边界：重复正式通过继续作为“当前存在知识缺口”的反证，同时成为“当前难度已掌握、可以提高挑战”的正证据。挑战建议先停在待生成状态，旧难度掌握事实和历史作答永久保留；应用后只把新状态标为等待更高挑战独立复验，不先清空掌握，也不把内容变难冒充学习改善。挑战效果由更高难度独立任务直接判断，不要求先点击或评价生长块；一道不同任务通过只形成初步支持，至少两道不同任务通过才确认。更高挑战连续失败只调整挑战跨度或支架，不反向制造旧难度知识缺口。
- 撤销边界：撤销恢复被升级块的旧载荷、知识引用和可见规则，只退役本次新增块；不覆盖其他并发合法课程变化、历史作答、笔记或掌握记录。
- 前端体验：AI 老师本节工作台固定展示“需求 → 结构 → 候选 → 同源 → 确认 → 复验”六步，候选明确标记升级或新增，并展示原内容、候选内容、保持不变范围、同源检查和效果复验方法。证据建议先提供“生成升级方案”，不能跳过候选与确认直接改课。
- 未完成边界：本轮完成块级升级与新增的纵向闭环，不等于行级修改、部分接受、多小节广域规划、跨域事务恢复、完整方案历史和长期真实效果样本已完成。

## 2026-07-18 Workflow 内加入轻量 AI 场景判断决策

- 背景：本节课程生长已有确定性六步链和块级增删改，但仅靠关键词解析难以理解“已经掌握了，想换成更贴近真实行业决策的讲法”等间接、组合表达。若把整条链改成自主 Agent，AI 又会同时承担场景判断、结构定位、写入和确认，边界过重且容易破坏同源与可恢复性。
- 正式方案：不建立独立 Agent 层。在现有 `CourseEvolutionPlan` Workflow 的“收到要求 / 读取证据”和“盘点真实课程块”之间加入一次受约束 AI 场景判断。它只输出场景摘要、判断理由、目标教学 `role`、生长方向、四维难度差异和资料要求；系统白名单过滤后，仍根据真实 `CourseBlock.role` 决定 `REPLACE / INSERT`。
- 失败边界：AI 不可用、超时、非 JSON、未知 role、非法方向或字段不完整时，立即使用同一结构契约的确定性规则保底。保底不是第二套产品链，后续候选、同源、确认、原子提交、撤销、表达重建和效果复验完全复用原 Workflow。
- 权限边界：AI 场景判断不能指定块 ID、课程范围、修订、确认结果或写入动作，模型返回的越权字段不会被消费。候选生成仍只能使用当前小节知识契约和绑定资料，不能借用其他课程。
- 资料边界：用户要求最新、前沿、近期或当前行业事实时，场景结果标记 `verified_current_sources`。没有显式时效核验的普通课程资料不能自动冒充当前证据；前端明确提示需要可信时效资料，候选只能生成不依赖时效断言的教学框架。
- 验收：后端覆盖复杂间接表达、非法输出、模型异常、确定性回退和系统自主决定升级/新增；前端展示“AI 场景理解 / 规则保底判断”、场景摘要、理由和资料提示。原有结构化同源、整体确认、撤销和复验链保持不变。
- 位置：`hackthon/backend/section_evolution.py`、`course_service.py`、`backend/tests/test_section_evolution.py`、`frontend/src/components/CourseEvolutionPanel.vue`、中英文 locale、`docs/product-blueprint.md` 与 `openspec/changes/build-structured-adaptive-course-ai/`。

## 2026-07-18 正式题目必须先解析题目、再评判答案决策

- 背景：旧题目链能把题目绑定到课程知识、能力和易错 ID，也能按量规评分，但“生成时挂了 ID”不能证明题目实际上考到了目标；总分和量规项也不能说明学生真实采用了什么思路。只加强出题 prompt 或评分 prompt 会继续把出题、题目质量、判分、错因和针对再练割裂成几段。
- 题目生产边界：主练习、综合检测、诊断题、补救题和独立复验题统一编译 `AssessmentIntent`，记录题目存在理由、当前课程知识 / 能力 / 易错 / 掌握标准、可观察动作、答案成立条件和难度契约。AI 必须先在看不到内部 ID 时独立解析题目实际考什么，再映射当前题目允许的课程 ID；范围外 ID、实际目标未命中、隐藏评分条件、歧义、不可判定答案或不可观察能力都阻止内容确认和发布。
- 失败闭环：第一次解析未通过时只重写该题题干，补齐条件、交付形式、可观察动作和判定边界，并签发新题目修订后再次解析；不得改变原 `AssessmentIntent`、题型、难度或答案量规，也不得从头重生整门课程。第二次仍未通过才进入用户可见阻断，避免重现“生成卡住但不知道改哪里”的结构问题。
- 作答边界：学生提交答案后，原量规评分与独立作答诊断并发执行。评分决定是否达标；诊断只根据真实答案说明学生思路、正确部分、关键差距和不确定性，再映射本题允许的课程知识、能力和易错。两者共同保存在同一 `PracticeAttempt`，不得用诊断替代正式判分，也不得为填标签补写学生没有表达的推理。
- 后续联动：真实诊断优先生成既有诊断假设，并让针对再练优先选择本次真正命中的能力或易错，而不是沿用题目上全部候选标签。学生页面展示题目目标、实际思路、具体差距和唯一下一步动作；查看完整解析后仍沿用原掌握证据降级规则。诊断模型失败时保留正式评分并明确标记不可用，不伪造个性化结论。
- 产品确认：课程第 5 步必须逐题展示“为什么出、实际考什么、同源命中、目标能力 / 易错、阻断原因”，通过题数不能替代逐题证据。当前实现进入主链，但只有完成真实新课程、真实开放答案、模型异常、中英文与多视口浏览器验收后，才能声明生产完成。
- 位置：`hackthon/backend/practice_analysis.py`、`learning_assets.py`、`task_manager.py`、`routers/practice.py`、`diagnostic_workflows.py`、`frontend/src/components/PracticeWorkspace.vue`、`CourseTaskCenter.vue`、`stores/courseWorkspace.ts`、`docs/product-blueprint.md` 与结构化课程 OpenSpec。

- 返工与确认：只有明显错误才把当前目录或当前小节退回 AI 重生一次，已完成小节保持检查点不变。一般质量由六步生产线中的用户审阅和确认负责；最终发布只继续守确认版本链、稳定课程内引用、基础绑定和正式产物可用性。

## 2026-07-19 强自述即时触发课程生长决策

- 背景：大会短视频需要用极少动作证明“课程会根据学生变化而生长”，但不能为录屏建立固定台词分支、隐藏开关或预制候选。产品真正需要的是一个可解释、可复现的强证据稳定点：学生一次说清自己的能力边界、持续困难、所需讲法和允许影响的范围，系统就能立即形成课程候选。
- 触发契约：AI 老师按四类语义识别强自述——已经会什么、持续卡在哪里、希望怎样讲、允许影响到哪里。跨位置范围必须由学生明确说出“本小节和相关后续”等硬边界；普通提问、模糊困惑或缺少后续范围的表达不得被扩大为广域候选。规则识别语义组合，不匹配某一句演示台词。
- 时序边界：`assistant_question_submitted` 登记成功即成为证据稳定点，系统立即刷新 `EvidenceItem → AdaptationHypothesis → CourseEvolutionPlan`，不等待 AI 流式回答结束。回答失败不能删除已登记证据和候选。
- 课程动作：满足完整契约后，系统依据当前课程知识关系和精确绑定选择当前位置与相关后续块，生成原因解释、结构化动画、独立正式题、下一处承接和后续检查。确认前课程真源不变；确认后以一次课程命令写入新的 `CourseDocument` 修订。强自述只允许生成候选，不能直接写掌握结论，效果仍由不同正式任务独立复验。

- 解耦边界：未批准的诊断、补救验证和综合测评只是增强候选稿，质量失败时必须隔离且运行时不得选用，但不阻断正文和核心练习均合格的首次课程发布；一旦教师批准，它们就重新进入正式硬门。
- 状态与交互：根质量报告必须把资产阻断提升为 `quality_failed`，并与 `publication_allowed` 分开。前端不得把 `completed_with_warnings + publication_allowed=false` 显示为五阶段全部完成；应停在发布阶段，提供“修复练习并重新检查”，通过后恢复最终确认发布。
- 位置：`hackthon/backend/task_manager.py`、`assessment_orchestrator.py`、`question_bank.py`、`learning_assets.py`、`course_quality.py`、`diagnostic_workflows.py`、课程生产前端、`docs/product-blueprint.md` 与结构化课程 OpenSpec。
