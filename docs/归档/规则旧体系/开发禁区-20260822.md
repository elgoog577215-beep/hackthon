# 灵知开发禁区（已归档）

> 文档状态：2026-08-22 迁移前的历史规则全文；当前规则以项目 `AGENTS.md` 为准
>
> 使用方式：只记录现在仍然不能采用的做法；历史经过查看[项目决策记录](./归档/项目决策记录.md)。

本文不是错误日志。每条禁区都应尽量由领域合同、Schema、自动化测试、lint 或运行时门禁执行；已经失效的条目直接修改或删除，不追加时间线。

## 1. 真源与状态

### 1.1 禁止建立平行课程真源

- 正式课程只写 `CourseDocument + ordered CourseBlock[]`。
- 生成工作区、旧 `nodes`、Markdown、前端缓存和教学表达只能作为中间态或投影。
- 新功能不得为了页面方便复制一份可独立漂移的课程正文。

### 1.2 禁止把课程文件等同于可学习课程

- 存储中存在 JSON 或课程外壳，不代表课程库应该展示它。
- 课程库只展示正式发布课程，或仍由真实生成任务承接的外壳。
- 失联历史资产先隐藏并保留审计，不在归属未确认时自动删除。

### 1.3 禁止把多个状态压成一个字段

- 任务阶段、节点完成、质量结果、发布许可、发布回执和课程可见性必须分开。
- 非阻断建议不能让已发布课程继续表现为活动失败任务。
- 前端不能只凭百分比或一个 `status` 推断生产事实。

### 1.4 禁止用父对象 ID 控制作业

- 暂停、恢复、删除、事件去重和状态对账使用 `task/job ID`。
- `course_id` 只用于归属和分组，不能替代任务身份。
- 同一课程的历史任务、当前任务和迟到事件必须能并存并正确隔离。

## 2. 版本、知识与学习事实

### 2.1 禁止隐式跨版本迁移

- 普通滚动、可见块和本地恢复只能更新同一课程版本内的位置。
- 版本变化必须经过带来源修订、影响计划和幂等键的正式确认命令。
- 不能通过普通位置同步把版本冲突表面抹掉。

### 2.2 禁止把导航节点伪造成学习目标

- 一级章节只负责导航和运行时刷新。
- 只有具有正文和正式目标的二级节点可以产生开始、进度和掌握事件。
- 不得为章节伪造目标来绕过入口判断。

### 2.3 禁止把正式学科包当成课程知识可用性的开关

- 每门课程先拥有可用的课程知识库和稳定课程内 ID。
- 学科库提供跨课程坐标、术语和治理状态，但模型不得自造正式学科 ID。
- 缺少正式学科包时仍可展示课程局部知识，并明确其治理状态。

### 2.4 禁止用 AI 会话改写学习事实

- 学习事实来自记录、作答、快照、诊断和关联事件。
- 学习者模型从正式事实确定性重算。
- 一次提问、失败、自述、点赞或 AI 判断不能直接形成稳定薄弱点、掌握结论或长期画像。

## 3. AI、生成与质量

### 3.1 禁止用兜底内容伪装生成成功

- 模型无结果、结构非法、违反用户硬约束和质量不足必须明确区分。
- 兜底只能做不改变业务语义的展示降级，不能替用户虚构课程目录、正文、答案或正式 ID。
- 最小单元降级必须记录原因和人工复核状态。

### 3.2 禁止让可视化反向成为第二生产链

- 生成预览只读取任务、检查点和安全草稿投影。
- 预览不得写学习进度、笔记、AI 修改或正式课程。
- 发布后切换正式 `CourseDocument`，不复制课程目录、正文和任务状态。

### 3.3 禁止用总分覆盖必要子闸门

- 发布通过必须同时满足必要的正文、难度、资料、知识、题目和一致性门。
- 模型自我纠错、题干答案矛盾和不可判定答案不能被高总分平均掉。
- 新质量规则必须同时准备应通过样本和必须阻断样本。

### 3.4 禁止修改规则却复用旧质量结论

- 任何会改变通过状态或问题代码的规则变化必须提升质量合同版本。
- 历史报告只有与当前合同身份完全一致时才能复用，否则从正式产物重新计算。
- 不能要求用户为了刷新确定性质量结论重新运行模型。

### 3.5 禁止只修一个执行入口

- 同一能力的自动、手动、恢复和兼容入口必须调用同一领域函数和质量门。
- 任何“已同步、有效、已掌握”都必须能指出同一对象、同一修订和同一证据范围。
- 纵向验收需要列出所有真实触发入口，不只覆盖主按钮。

### 3.6 禁止模型写入未授权正式结果

- AI 对正式课程、学习事实和长期模型的影响必须经过白名单动作、影响预览、用户确认、修订检查和幂等回执。
- 候选、回答、草稿和推理不等于正式业务对象。
- 不记录 Prompt 正文、密钥或 provider 推理内容。

## 4. 前端、解析与缓存

### 4.1 禁止后台同步反复驱动全局错误提示

- 轮询、健康检查和自动恢复使用局部或静默错误状态。
- 同一资源只保留一个同步所有者，同一异常只处理一次。
- 用户主动动作失败才显示一次明确的全局反馈。

### 4.2 禁止把浏览器缓存当成服务端真源

- 本地任务缓存只负责断网和刷新连续性。
- 联网后按任务 ID 与服务端对账；只有明确 404 才清除活动投影。
- 断网、超时和未知错误保留最后成功现场，不能伪造后台仍在运行。

### 4.3 禁止跨语法层清理 Markdown 和 LaTeX

- 公式修复必须尊重成对分隔符、Markdown、HTML 和渲染后 DOM 边界。
- 不全局删除公式分隔符旁空白，不让一个坏公式吞掉后续标题、列表或正文。
- `String.replace` 涉及字面 `$` 时使用回调，避免 replacement 特殊语义。
- 解析问题先建立真实失败样本；连续正则补丁产生回归时转向边界隔离或正式解析。

### 4.4 禁止只提高 z-index 处理浮层问题

- 悬停闪烁和裁切需要检查编译后选择器、`pointer-events`、祖先 `overflow`、堆叠上下文和视口边界。
- Vue `:global()` 必须覆盖完整跨组件选择器。
- 允许交互元素越界的容器不能用 `overflow:hidden` 裁掉操作区。

### 4.5 禁止让入口 HTML 与哈希资源共用缓存策略

- `index.html` 和 SPA 回退页必须重新验证或禁止缓存。
- 带内容哈希的静态资源可以长期 `immutable`。
- 发布验收同时检查首页、子路由和哈希资源响应头。

## 5. 测试、运行与 Git

### 5.1 禁止把局部检查写成完整验证

- 单测通过不等于真实模型、浏览器视觉、长期效果或生产环境通过。
- 课程生成需要同时看任务、工作区、质量、发布回执、课程库和学习页。
- Mock、演示预设和本地确定性保底不能替代真实 provider 发布门。

### 5.2 禁止混合收集当前两套后端测试

- 在测试目录包化和夹具导入收口前，分别运行 `pytest backend/tests` 与 `pytest tests`。
- 根目录直接 `pytest` 的 `conftest` 冲突不能误报为产品回归。
- 恢复单命令前先消除旧用例对顶层 `conftest` 的显式导入。

### 5.3 禁止污染任务提交

- 不提交密钥、运行数据、缓存、录屏、导出文档和其他任务改动。
- 显式暂存当前任务文件，不使用 `git add -A`。
- 推送前 fetch 并核对远端关系，不强推覆盖来源不明的历史。

## 6. 维护门

新增禁区必须满足至少一项：高代价错误曾重复发生；约束跨模块且无法只靠局部代码表达；未来开发者或 AI 很可能再次采用错误方案。

可以由单个测试、类型系统或局部注释完整表达的细节，不再追加到本文。禁区失效或已被更准确合同替代时，直接修改原条目；历史原因交给 Git 和归档决策记录。
