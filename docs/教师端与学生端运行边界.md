# 课程工作区统一与兼容边界

> 文档状态：当前运行边界说明
>
> 核验日期：2026-08-19

## 1. 当前结论

灵知不再把“教师端”和“学生端”当作两套产品。课程、大纲、正文和 PPT 是同一门课程沿产物链展开的四个阶段，共享 `course_id`、`CourseDocument`、`CourseTeachingPlan`、正式题目、教学表达和生成任务。

角色与权限仍然存在，但角色差异应表现为操作权限、默认入口和可见动作，不应再复制课程库、课程外壳、生成状态或正式资产。

## 2. 活动入口

| 入口 | 用途 |
| --- | --- |
| `/courses` | 创建、导入、恢复和进入课程 |
| `/course/:courseId/workspace/setup` | “课程”阶段：概览、资料、教学设计、日历 |
| `/course/:courseId/workspace/build` | “大纲”阶段；`build` 仅为兼容路由名，不是用户术语 |
| `/course/:courseId/learn/:nodeId?` | “正文”阶段：目录、正式内容、配套练习、笔记、AI 老师、错题与进度 |
| `/course/:courseId/ppt` | “PPT”阶段：同源 PPT 工作台 |

旧 `/teacher/courses` 和 `/teacher/course/:courseId/...` 仅作为兼容地址，重定向到上表的等价入口。课程生产总览不再是活动页面。

## 3. 共享真源与术语

- “课程 / 教学设计”的全课视图读取 `CourseTeachingPlan.overall`。
- 同一工作台的分小节视图读取 `CourseTeachingPlan.sections`。
- “教案”只用于已经确认或导出的正式教学文件语境。
- 大纲继续来自生成工作区蓝图或 `CourseDocument` 投影。
- 练习继续使用正式题目、尝试和诊断状态。
- PPT 继续使用来源绑定的 `TeachingRepresentation / SlideDeckSpec`。
- 资料包保存稳定 `course_id`，默认按 `owner_id + course_id` 查找；课程标题不是长期关联键。

统一流程不得写入旧 `TeacherLessonAuthoringRepository` 形成第二份讲次正式真源。

## 4. 性能边界

统一工作区首屏只阻塞课程主干和当前子模块。资料、日历、大纲与教学方案在首次打开时加载；同一课程内已打开的模块保持挂载，避免切换时重复读取整套课程、任务、教案、PPT 和发布状态。正式课程的学习资产、记录、进度与 AI 会话并行读取。

后台任务轮询属于全局生成状态投影，不得触发整页遮罩或重建当前模块。

## 5. 兼容期约束

1. 旧教师页面源码、讲次 API 和持久化文件暂时保留，但活动路由不得调用它们。
2. 删除旧 API 或文件前必须审计真实环境数据，确认没有未迁移的讲次、PPT、日历和资料引用。
3. 无 `course_id` 的旧资料包只能在当前 owner 下存在唯一同名候选时兼容绑定；多个候选必须人工选择。
4. 旧地址重定向必须保留课程 ID 与可表达的子模块位置。
5. 正式身份、RBAC、组织和班级发布关系仍是后续权限合同，不能用当前本地教师身份代替。

## 6. 删除完成门

只有在生产数据审计、迁移回执、旧地址访问日志、回归测试和回滚方案同时通过后，才能删除旧教师页面、`TeacherLessonAuthoringRepository` 及其 API。删除兼容代码不得改变正式课程、学习记录或 PPT 真源。
