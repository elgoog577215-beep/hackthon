# 教师端与学生端运行边界

> 文档状态：当前双端边界说明
>
> 核验日期：2026-08-16
>
> 核验基线：`7b474a998297c0253b5e8688d9c9b883e95af1a5`

## 1. 当前结论

**教师端和学生端已经拥有各自独立的产品入口、页面编排与使用流程，两端均可单独打开并正常使用。**

这里的“独立”指产品表面和运行编排隔离，不代表复制成两套后端、两套数据库或两套生成引擎。课程生成、PPT、AI 基础设施和正式课程数据继续复用同一套底层能力，避免教师端与学生端分别演化出不一致的实现。

## 2. 双端入口

| 使用者 | 入口 | 主要用途 |
| --- | --- | --- |
| 教师 | `/teacher/courses` | 进入教师课程库，管理课程生产、教学大纲、分讲教案、PPT、教学日历、课程文件和发布状态 |
| 学生 | `/courses` | 进入原课程库，继续使用课程学习、练习、笔记、AI 老师、学习进度和原 PPT 能力 |

进入具体课程后，两端仍使用不同的路由空间：

- 教师端：`/teacher/course/:courseId/...`
- 学生端：`/course/:courseId/learn/:nodeId?`、`/course/:courseId/ppt`

因此教师工作台的导航、页面调整和生产流程不会直接覆盖学生学习页；学生端原有路由与功能入口也没有被教师页面替换。

## 3. 已经隔离的内容

### 3.1 页面与导航

- 教师端拥有课程总览、课程生产、大纲、发布、课程文件、教学日历和教师 PPT 路由。
- 学生端保留原课程库、学习现场、练习、笔记、AI 老师、知识与 PPT 路由。
- 两端返回路径、页面状态和操作入口分别编排。

### 3.2 课程生成状态投影

教师页面通过 `frontend/src/features/teacher-course/useTeacherCourseRuntime.ts` 进入共享能力，并只把 `course_generation` 任务解释为教师课程生产生命周期。PPT 构建等其他任务不会被误判为“课程仍在生成”。

学生端继续使用原有 Store、路由和任务流程；适配层没有复制或替换学生端生成逻辑。

### 3.3 教师只读预览

教师查看学生版时使用 `teacherPreview=1` 的只读预览模式。该模式不会写入学生学习进度、学习记录或 AI 老师会话，避免教师预览污染学生行为数据。

## 4. 有意共享的底层能力

以下能力在两端之间共享，而不是复制：

- 课程生成引擎与任务基础设施；
- PPT 生成、模板、联网图片与导出能力；
- AI 提供方和通用调用基础设施；
- `CourseDocument`、课程修订和教学表达等正式课程资产；
- 稳定后端 API 与持久化仓库。

共享意味着朋友继续优化学生端所依赖的生成或 PPT 底层能力时，教师端可以通过适配层复用改进；教师端的页面重排也不需要改写或复制这些引擎。

## 5. 不能误解为“完全物理隔离”

当前尚未拆成以下形态：

- 两套独立部署的后端服务；
- 两套独立数据库或课程资产仓库；
- 完整的教师/学生身份认证、RBAC 和组织权限体系；
- 完整的“教师发布快照 → 指定学生班级消费”关系。

所以准确表述是：

> 两端已经实现**入口隔离、交互隔离和运行编排隔离**，均能独立使用；底层生成能力和正式课程资产按设计共享。身份权限与发布关系仍是后续需要打通的边界。

## 6. 后续开发约束

后续合并和开发必须遵守：

1. 学生端已有路由、生成、学习、练习、笔记、AI 老师和 PPT 能力不得被教师端改造削减。
2. 教师端新增能力优先经过教师适配层组合共享 Store 与 API，不复制生成引擎。
3. 教师预览学生版必须保持只读，不得创建学习记录、进度或 AI 会话。
4. 共享领域能力的升级应补充教师端与学生端双侧回归测试。
5. 发布关系完成前，不得把“共用课程资产”宣传为“已经完成班级授权和正式发布隔离”。
