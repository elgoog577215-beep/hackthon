>

本文回答“仓库怎样组织、正式数据由谁拥有、主要运行链怎样连接、新能力应该接在哪里”。它不维护产品愿景、实施进度、历史测试数字和具体 OpenSpec 任务。

## 1. 总体结构

```text
Vue 3 前端
  -> FastAPI HTTP / WebSocket
  -> 领域路由与应用服务
  -> 课程、知识、学习、题目、表达和任务仓库
  -> AI 提供方 / 文件系统 / 独立代码 Runner
```

| 目录 | 职责 |
| --- | --- |
| `frontend/` | Vue 3、Vite、Pinia、学习现场、教师工作台、PPT 工作台和中英文界面 |
| `backend/` | FastAPI、领域服务、生成编排、学习运行时、AI 能力、持久化和任务恢复 |
| `runner/` | 独立代码执行服务；主后端通过客户端调用，不在主进程直接执行用户代码 |
| `tests/`、`backend/tests/` | 兼容回归与当前后端领域测试；当前需要分别收集 |
| `scripts/` | 迁移、验收、部署、录屏和诊断工具，不拥有产品运行时真源 |
| `openspec/` | 高影响变更的提案、设计、正式规格、任务与归档 |
| `docs/` | 产品、状态、架构、事实记录、操作证据和历史归档 |

开发态由 `dev.sh` 或 `dev.bat` 启动前后端。生产态由 FastAPI 托管前端构建产物；`backend/static_serving.py` 区分入口 HTML 与带哈希资源的缓存策略。

## 2. 前端结构

### 2.1 页面入口

| 页面 | 主要职责 |
| --- | --- |
| `TeacherTeachingCalendarView.vue` | 教师端首页；承载课程列表、教学日历和课次状态 |
| `CourseWorkspaceView.vue` | 课程空间壳；在默认工作台中组装阶段导航/正式内容与嵌入式右侧 AI，并承载正式课程预览与文件视图切换 |
| `TeacherCourseSpaceView.vue` | 工作台视图的左阶段导航和中正式内容；文件视图的左文件夹、中当前目录和右文件详情 |
| `TeacherCourseWorkbench.vue` | 教师课程生产主界面；左阶段、中表单/流式内容/正式内容、右引用资料，不建立聊天式平行生产链 |
| `CourseReferenceTray.vue` | 管理当前正式文件的一个主来源、多份参考资料与联网来源；教案阶段以 `lesson-plan:<lesson_unit_id>` 为目标即时保存并恢复各讲独立引用，底层原文件仍只保存一份 |
| `WebResearchDialog.vue` | 阶段/课次范围的联网调研面板；展示实际检索词、网域与正文深读覆盖、来源摘要、可信度、许可与复核标记，只有教师确认后才进入资料链 |
| `CompanionDocumentStudio.vue` | 五步主链路之外的配套文档二级模板库；承载结构化表单、当前正式修订预览、继续编辑和导出 |
| `QuestionBankReviewPanel.vue` | 题库阶段的生成、审核、筛选与组卷入口；生成请求冻结当前选定的资料范围 |
| `ExamPaperComposer.vue` | 题库内的轻量组卷弹窗；提交有序题目修订引用，不复制题干或答案 |
| `SideAIPanel.vue` | 学习现场与局部编辑继续复用同一会话、变更候选与确认回执；不再作为课程工作台的核心生产栏 |
| `LearningView.vue` | 正式课程运行态；承载目录、正文块、正式练习、记录、诊断、AI 老师与教师只读预览 |
| `PptWorkspaceView.vue` | 同源 PPT 专用编辑工作台，消费与导出相同的 `SlideDeckSpec` |

路由由 `frontend/src/router/index.ts` 统一管理。教学日历首页使用 `/courses`；课程文件空间使用 `/course/:courseId/workspace/:mode`，`setup/build` 只是兼容实现名；正式课程与 PPT 专用工作台分别使用 `/course/:courseId/learn/:nodeId?` 与 `/course/:courseId/ppt`。旧 `/teacher/...` 地址只保留为兼容重定向，映射到同一课程的日历、文件空间或正式课程，不再挂载独立教师总览和生产页面。完整边界见[教师端与学生端运行边界](./教师端与学生端运行边界.md)。

新功能应先复用现有文件空间、专用编辑工作台、正文块和结构化任务语法，不按文件类型创建平行顶层产品壳。日历、文件、教案、讲稿、题库和 PPT 共享稳定课程身份与领域真源；兼容期旧教师适配层不得成为新流程依赖。

文件空间遵循资源管理器语义：根目录固定投影课程基础、教学内容、考核与考试、课程文档、资料库五类；文件夹单击进入，文件单击选中并更新始终可见的右侧详情，双击或右侧主操作才打开、生成或编辑。右侧只显示状态、少量属性、“来源资料 / 生成文件 / 用于”和直接操作。`teacher_course_space` 清单中的 `relationships` 以稳定课程资产 ID 连接原文件与正式文件；一个正式目标最多一个主来源，可有多份参考资料，删除引用不得删除底层 `mat-*`。课程工作台的教案资料栏把当前 `lesson_unit_id` 映射为 `lesson-plan:<lesson_unit_id>`，上传、勾选、移除时立即更新该目标关系，切换或刷新讲次时从资料 `usages` 恢复选择；同一 `mat-*` 可被多讲复用但不复制。文件视图中的“本讲资料”只汇总该讲已有关系，新上传的原文件仍只存入资料库。题库、试卷与课程文档在文件视图中作为正式资产投影，不建立文件视图专用真源。

身份域由 `frontend/src/router/index.ts` 的路由元数据或领域调用显式声明为 `teacher` / `learner`，`frontend/src/utils/http.ts` 只执行声明，不读取 URL 或路径正则猜测身份。教师首页、新建课程、课程工作台、文件空间、教学日历、任务控制、PPT 和 `teacherPreview=1` 的学习现场使用同一稳定教师身份；普通学习现场使用独立学习者身份。AI 会话本地缓存也按身份域与 `course_id` 分区。预览通过 `returnTo` 保留发起时的课程与课次位置。

### 2.2 状态所有者

Pinia Store 按领域投影组织：

- `course.ts`：当前课程与正式课程文档投影。
- `generation.ts`：生成任务、检查点、WebSocket 与恢复投影。
- `learningSession.ts`、`learningProgress.ts`：当前学习会话和进度。
- `learnerModel.ts`：后端正式学习者模型的只读投影。
- `aiTeacher.ts`：学生 AI 老师与教师智能体的会话、流式回答、提案与回执；请求中通过 `perspective` 分离两种上下文。
- `courseEvolution.ts`、`changeProposals.ts`：课程调整方案和审阅状态。
- `teachingPlanWorkbench.ts`、`teachingRepresentations.ts`：教案工作台和同源教学表达。

多个界面消费同一状态时复用一个 Store。组件局部状态只管理展示交互，不能成为可持久业务状态的第二真源。

### 2.3 渲染与国际化

- Markdown、KaTeX、Mermaid 和高亮通过共享渲染工具与组件处理，不在不同页面分别修补语法。
- 用户可见文案从 `frontend/public/locales/zh/translation.json` 和 `frontend/public/locales/en/translation.json` 读取。
- 课程正文与 AI 结果共用正式 Markdown 渲染链；解析修复只作用于所属语法层，不能跨代码、表格、链接、HTML 属性或第三方 DOM。

## 3. 后端分层

### 3.1 接入层

`backend/main.py` 组装 FastAPI，并挂载 `backend/routers/` 中的领域路由。路由负责鉴权、参数、HTTP 错误和响应转换，不直接复制领域状态机。

当前 `X-User-Id` 是本地稳定身份边界，不等价于正式登录鉴权。`courses.py` 在教师课程创建和目标草稿生成前要求稳定 actor，教师课程库按 `owner_id` 过滤；`course_access.py` 在所有课程子路由前统一阻断非所有者访问未发布教师课程，`tasks.py` 同样按任务所有者隔离查询与控制。发布后的课程可供学习者读取，但学习事实仍按学习者身份分区。正式多租户部署仍必须接入真实账号/会话 authority。

主要路由域包括：

- 课程与节点：`courses.py`、`nodes.py`、`course_versions.py`。
- 生成与任务：`tasks.py`、`materials.py`、`markdown_import.py`。
- 学习：`learning_runtime.py`、`learning_records.py`、`learning_progress.py`、`learning_snapshots.py`、`practice.py`、`diagnostics.py`。
- AI 与课程调整：`ai_teacher.py`、`change_proposals.py`、`course_evolution.py`、`block_regeneration.py`。
- 全课/分小节教学设计与表达：`teaching_plan_workbench.py`、`teaching_representations.py`。
- 课程资料与排课：`material_storage.py` 保存全局去重的原始 `mat-*`，`teacher_course_space.py` 用 `tca-*` 引用将其归入 `owner_id + course_id`，并保存正式文件的双向来源关系；`teaching_calendar.py` 保存课程排课。
- 配套文档：`course_companion_documents.py` 拥有模板合同、字段校验、每课程单例文档、不可变修订和 DOCX/Markdown 编译；`routers/companion_documents.py` 提供课程范围列表、生成、读取与导出接口，原文件关系仍由 `teacher_course_space.relationships` 拥有。
- 知识与题目：`knowledge_libraries.py`（含知识候选、确认、修订列表与覆盖检查）、`question_bank.py`、`exam_papers.py`、`learning_assets.py`。题库重建命令可显式冻结教师在工作台勾选的课程资料；`exam_papers.py` 保存试卷当前修订和有序题目修订引用。
- 产品使用记录：`usage_events.py`；只接收脱敏页面、会话、写操作终态和分类错误，不接收业务正文。

后端 API 按领域能力、命令或稳定投影设计，不按某张页面卡片设计专用状态接口。

| 领域 | 正式真源 | 不能作为真源的对象 |

| 课程知识演进 | 知识白名单命令回执与 `course_knowledge_revision_log` | 知识候选、影响报告、下游状态投影 |

| 正式题库与试卷 | 当前题库修订；`ExamPaper` 的有序题目修订引用与固定题库修订 | 前端勾选状态、复制到试卷中的题干或答案、文件列表投影 |

| 课程配套文档 | 版本化模板 + 结构化输入 + 当前不可变修订 | DOCX/Markdown 导出、文件列表投影、前端表单草稿 |

## 5. 主要运行链

### 5.1 教师课程生产链

```text
TeacherCourseBrief + 教学类型/学科画像 + 资料引用
-> 创建同一 course_id 下的空课程空间
-> teacher_outline_generation 生成章节骨架并等待逐章小节数确认
-> 恢复同一任务生成完整大纲并确认知识范围
-> 教师按讲启动生成，系统自动锁定本讲课型与教学块编排
-> teacher_lesson_plan_generation 生成、编辑并确认本讲教案
-> 已确认教学块编译为中性课程讲稿块，生成、编辑并确认本讲讲稿
-> 已确认讲稿块 + 可选 ppt-v6:{lesson_unit_id} 资料关系
-> 编译为可审阅并确认的 ppt_manuscript_v1
-> 已确认 PPT 文书由模板确定性编译为 TeachingRepresentation / SlideDeckV6 / PPTX
```

题库与试卷、教学日历和配套文档从同一课程基线和正式修订读取，但不是上述纵向链的阻断步骤。五个工作台入口可以独立进入；默认路径表达常见备课顺序，缺失依赖时只阻断当前动作。旧 `course_generation` 整课任务在兼容期只提供可迁移的规划、知识、提示词、质量、检查点和发布能力，不再拥有教师工作台的新写入；各能力被同一底层服务消费并通过迁移门后，旧教师 UI、路由和写入入口退场。

目录、教案和正文按有界工作单元执行并保存检查点。`teacher_outline_generation` 在 `outline_shape_ready` 使用教师专用断点，将老师确认的逐章数量保存在 `generation_stage_artifacts.outline.confirmed_shape_constraints`，不扩展学生端通用 guided workflow；完整目录继续使用原有 `outline` 审阅门。提供方失败只影响当前最小单元；恢复不得重做已经通过或已确认的章节骨架。确定性降级必须标记原因，不能冒充完整 AI 质量。

教师显式启用联网研究时，统一检索网关建立不可变 `RetrievalPackageV1`。首次生成可以先建本地蓝图再审阅检索支持的结构调整；课程工作台则由 `course_web_research.py` 在课程元数据中保存有界的阶段/课次调研会话。现有搜索接口先对较宽候选池按查询和网域做多样性重排，再由 `web_document_reader.py` 有界并发读取前 8 个公开 HTTPS 来源：HTML 提取正文层级，PDF 调用既有解析依赖，并为重点段落保留章节/段落定位；DNS、重定向、MIME、体积、超时或正文质量不通过时只对该来源回退搜索摘要。会话保存清洗后的查询、摘要、有界 `web_document_v1`、覆盖矩阵和审阅状态，不增加研究接口或第二套任务系统。教师勾选后，`material_pipeline.prepare_course_materials` 把正文或摘要转成 `mat-*` 资料，继续走 parse → evidence → grounding，再由 `teacher_course_space.relationships` 记录正式产物的双向来源。正文、教案和题库只消费当前勾选且已入库的来源；检索失败保留本地资产并显示分类原因，不用模型常识伪装联网核验。

教师作者能力继续在同一 `course_id` 和同一课程空间中扩展目录、教案、题库、讲稿与 PPT 命令，不建立第二课程工作室。五个入口可以独立进入，左侧顺序不构成生成门禁。题库文件导入由 `question_bank_imports.py` 在 `owner_id + course_id` 边界下持久化会话，复用 `material_storage -> material_parser` 的单份原文、块和页码定位；前端批量选择只按文件逐份调用既有单文件导入接口，每份文件拥有独立会话和失败边界，不建立批量事务或第二套导入真源。校对后调用 `merge_teacher_imported_questions` 编译为现有题目质量、生命周期、来源和不可变题库修订，再由 `teacher_course_space.relationships` 记录正式题库与原文件的双向关系。该路径不调用 AI 生成。题库 AI 重建只消费请求中冻结的资料引用和可选课次范围；组卷只接受当前修订中已审核且质量可用的题目，并把有序 `question_revision_id` 与 `source_bundle_revision_id` 写入不可变试卷修订。

生产 AI 工作区只统一交互不统一领域命令：`useTeacherProductionAiCollaboration` 和 `TeacherLessonAiWorkspace` 负责澄清、生成、候选审阅、采用/放弃、失败重试与可调宽分栏；大纲、教案、题库、讲稿和 V6 PPT 分别通过自己的领域适配器读写正式修订。所有候选冻结课程、对象、精确资料 ID/角色与基线修订；讲稿和 V6 PPT 候选由 `TeacherLessonAuthoringRepository` 持久化，题库采用后才创建正式重建任务。上游候选只预览下游影响，不自动改写讲稿、题库或 PPT。

分讲资产只有一条正式生产链：当前知识范围大纲修订 → 系统锁定本讲课型与教学块 → `CourseTeachingPlanV3 / standard_lesson_plan_v1` 生成、编辑并确认教案 → `neutral_course_script_v4 / teacher_script_quality_v4` 按块生成、编辑并确认中性讲稿 → 可选 `ppt-v6:{lesson_unit_id}` 来源关系只按相关讲稿块绑定证据 → `ppt_manuscript_v1` 编译逐页可见文案、页型、版式、构图、精确讲稿来源、资料关系与页面证据 ID → 教师确认 PPT 文书 → 模板确定性编译 `TeachingRepresentation / SlideDeckV6 / PPTX`。教案保存教师动作、学生活动、时间和课堂检查；讲稿只保存定义、边界、推理、例题、辨析、实践任务与总结，继续是 PPT 可见知识的唯一语义真源；额外资料只指导案例、依据和表达规划。渲染器只消费已冻结文书与模板，不再生成、摘要或改写知识。已有 PPTX 不进入该生成链，而是保留原件并与当前讲稿、教学资产和 PPT 阶段资料建立审阅报告。旧 `storyboard` 只作为历史页面规划展示，不冒充 PPT 文书。


`lesson_arrangement.py` 是内部本讲编排的适配层，不是新教案引擎。它复用 `course_pedagogy.py` 的学科画像、细课型和模块注册表，投影为本讲课型与有序教学块。前端不再提供逐块编辑器；教师点击生成时自动锁定当前建议，生成后的说明、调整和重新生成统一进入 AI 候选链。`TeacherLessonAuthoringRepository` 在讲次资产内保存 arrangement 工作/确认修订并记录大纲修订锚点；大纲变化后旧编排转为 `stale`。`PUT /api/teacher/courses/{course_id}/lessons/{lesson_unit_id}/arrangement/confirm` 只确认当前讲且校验所有讲内小节均有教学块；教案生成接口只取当前已确认修订，再把它编译回 V3 引擎的 `lesson_archetype + module_plan`。

教师大纲尚未生成整课 `module_plan` 时，服务层先用教学类型、学科画像、本讲目标和资料为本讲推荐本讲课型，并把内部模块注册表映射成教师可见教学块。老师指定原教案为主来源时，`teacher_lesson_source.py` 复用资料解析器保留 DOCX/PDF/文本的块类型、原顺序和页码/路径，并映射到当前讲内小节；PPTX 才走旧课件证据提取。模板只补齐缺失字段，AI 优化只形成候选。读取、生成、保存和确认都使用知识范围修订作为唯一大纲版本锚点，不得回退到较粗的 `blueprint_revision_id` 造成虚假过期。`TeacherLessonAuthoringRepository` 负责教案工作稿、确认修订、结构化讲稿修订与确认、V6 PPT 来源绑定和可查询任务投影；讲稿修订以有序 `blocks` 为真源，`content` Markdown 由块确定性生成，旧 `content` 只经单向兼容适配进入新结构。前端只提交一次任务并读取真实 `pending / running / failed / cancelled / completed` 状态。工作稿可保存并显示质量阻断，但只有完整覆盖当前讲次小节且本讲课型、教学块、教学目标、重难点、师生活动、时长、课堂检查、作业和知识冲突检查全部通过的当前修订才能确认。讲稿生成把教师输入原样写入教师专用提示词，同时继承内部模块注册表的 `output_contract`、`prompt_instruction` 和学科产物合同；教学块按已确认顺序逐块生成并设置单元超时，前一块课堂表达作为后一块的有限上下文，可见工作片段先持久化再通过 SSE 投影，局部失败只重试未完成单元。完成态不得自动确认。教师 V6 PPT 接口只接受带明确修订 ID 且完整覆盖本讲小节的当前已确认讲稿，并校验它绑定的已确认教案修订；内容语义只从讲稿块读取，再把 `module_id / role / concept_refs / planned_minutes` 投影为 CourseBlock。构建中任一来源变化都终止登记。旧轻量 PPT 的生成、优化、候选、草稿写入和任务代码已删除；只保留历史 deck 的只读导出兼容。旧 `TeachingPlanWorkbench` 与旧整课教师入口只作历史兼容，不得成为当前课程工作台的读写依赖。

历史 canonical 课程缺少 `course_teaching_plan` 时，教案工作台只读展示当前投影。教师可通过显式基线命令从已发布结构化目录确定性编译 `CourseTeachingPlanV3`；该命令校验当前 `course_document_revision`，不调用模型、不改正文，并原子记录迁移来源、质量报告、首个正式修订和幂等回执。缺少稳定目录或质量门未通过时继续只读。

### 5.2 学习运行链

```text
CourseDocument + 当前学习身份
-> LearningRuntime
-> 阅读、记录、正式练习和诊断
-> 正式领域对象 + LearningEvent
-> LearnerModel 确定性重算
-> 当前进度、连续性和可解释动作
```

一级章节只负责导航；只有具备正文和正式目标的可学习节点可以写入学习进度。普通位置同步不能跨课程版本迁移快照。

### 5.3 AI 老师与课程生长链

```text
当前课程锚点 + LearningRuntime + 最小必要证据
-> AIContextPackage
-> 解释、举例、简化、提问或白名单动作
-> 候选与影响预览
-> 用户接受、拒绝或调整
-> 领域命令 + 幂等回执
-> 新修订与后续独立效果证据
```

AI 会话不拥有学习事实。一次提问、失败、自述或模型判断不能直接形成稳定薄弱点，也不能直接修改共享课程。

AI 老师的联网状态属于会话设置，默认关闭且会话间隔离。仅普通回答可以检索；保存笔记、创建问题等直接动作不出站。查询只由公开课程上下文和当前问题组成，回答中的网页事实必须绑定消息来源和检索回执。

### 5.4 同源教学表达链

```text
CourseDocument 修订 + 来源绑定
-> 按代码行、公式顶层运算符和自然文本边界生成稳定的容量安全源片段
-> 表达编译器
-> 教案、讲义、练习册、PPT、图解或动画规格
-> 质量门
-> 原子发布新表达或保留最后可用版本
```

浏览器预览与导出必须消费同一规格。PPT 语义版式选择器只接收容量安全源片段；超容量原子不能直接穿透分页并终止整个新课程任务。V5 仍以完整来源块作为语义组边界：完整组无法安全呈现时记录整组排除决定，不把局部切片伪装成完整讲解。表现层修改不能冒充课程语义修改；语义变化必须回到课程命令和影响确认。

PPT 模板是表现层编译输入，不拥有教学语义。五套内置主题与个人模板统一解析为版本化主题快照；个人模板按 `owner_id / pack_id / immutable version` 隔离。V5 构建签名包含模板 ID、版本和 Manifest 摘要，任务快照、`SlideDeckSpec`、浏览器预览和 PPTX 导出消费同一份 `compiled_theme`。素材只能通过鉴权接口读取，客户端缓存为 Blob URL；持久表达不得暴露服务器物理路径。删除个人模板只隐藏列表，已经锁定版本的课件仍可重建和导出。

老师上传的 PPTX 不直接写入 `TeachingRepresentation`。课程文件空间先保存不可变原件；原有“生成教案草稿”依旧按页提取可见文字并以 `asset_id + slide` 作为证据。第五步的“上传并审阅”另外为每页和文字块保存稳定 ID、原形状位置、内容哈希和修订历史，并用实际可用的大纲、已确认教案、当前题库和已确认讲稿构建报告。手工编辑和 AI 只改可恢复工作修订；AI 先写候选，教师接受后才创建新修订，教师最终确认后才在 `TeacherLessonAuthoringRepository.ppt_assets` 登记 `engine=uploaded_pptx` 的当前主 PPT。导出只在原件副本上回放可编辑文字，不修改源 PPTX；旧 `.ppt`、表格单元格编辑、动画和完整视觉语义回导不进入本链。

V5 的最终修复与版式解析共享同一组标题、正文和可见条目预算，禁止用宽松的中间阈值把两张安全页重新合并成一张溢出页。练习页只允许在完整“问题—答案”对之间分页，并保留父语义原子来源。任意非 `quality_fallback` 的首轮 V5 候选未通过最终质量门时，都必须用严格 source-only 方案重新规划、重新分配并重新导出一次；该规则不依赖首轮规划器是否为 AI。两轮均失败时保留上一可用版本，同时把最终结构化阻断项和原始异常传给任务与前端。

V6 不设置教学业务页数上限，页面数量由完整来源和已发布模板容量共同决定；仅保留防止异常输入失控的实现安全上限。代码按完整源码行、步骤按完整动作、表格按完整数据行、正文按语义组或无损自然文字边界自动续页。单正文页以及代码/表格旁的来源解释不得被故事摘要替换；摘要只能作为导读，完整来源解释必须继续可见。最终发布门除几何溢出外，还必须验证可见代码/公式/表格保真、可见正文保真、有序步骤保真，以及编译器未生成来源中不存在的省略号。

教师 PPT Agent 在该 V6 链上增加“讲稿全量备注—学生画布投影”边界：完整教师讲稿逐字绑定 speaker notes，画布只保留当前教学动作所需的定义、条件、推导、例题数据、步骤、结论和任务，不显示问候、板书指令、停顿或解释话术。目标页使用冻结的小节正式标题；编译器续页必须依据当前来源片段生成不同的教学标题，公式标题把长等式链压缩为变量与结果，且 Web/PPTX 共享同一公式显示适配。质量报告固定包含画布平均/最大字数、画布与备注比例、教师口语清洁率和页面标题唯一率；任一正式块、公式、步骤或导出对象丢失时继续保留上一可用版本。

### 5.5 课程知识演进链

```text
知识白名单命令 + 当前知识库修订
-> 知识候选（质量门、稳定身份检查、双向影响）
-> 用户确认
-> 与课程修订原子提交 + 幂等回执
-> 下游正文、练习、教案与 PPT 的重建计划
```

知识库是课程底座，不是学习事实的第二存储。知识按实体寻址修订，改一个知识点只失效引用它的下游产物；经六类关系依赖的对象标为待复核而非直接重建，且关系遍历有界。稳定知识 ID 与来源绑定只能通过显式旧新映射迁移，不得原地改写；身份被破坏时整体阻断，不给重建清单。下游基于新知识重建失败时保留最后可用版本，旧的正文、练习和 PPT 继续可读。

待确认候选遇到基线前移时先尝试重定位：目标仍在且所改字段未被他人改动即按当前修订重算并要求再次确认；目标被拆分、合并、退役或同一字段已被改动则报冲突并说明原因，不静默覆盖他人改动。重定位只产出候选，不写入。

### 5.6 教师全课变更规划链

`course_change_planning.py` 拥有教师全课修改的规划合同，不拥有任何正式课程内容。`CourseChangeIntentV1` 永久保留老师原话、当前解释、约束、保护项、假设和 AI 产生的语义/结构信号；代码不按原话关键词硬分类。`CourseChangePlanV1` 作为现有 `CourseEvolutionPlan.teacher_change_planning` 的可选嵌套元数据，按当前证据选择 `semantic_impact`、`structural_regeneration` 或结构优先的混合执行，并可通过 `supersedes_plan_id` 重新规划。

结构计划使用新增、更新、移动、排序、拆分、合并、退休和重建八类大纲原语；每个大纲、教案、题目、讲稿块或 PPT 页面输出 `reuse_exact / reuse_rebind / rewrite_partial / regenerate / retire / blocked` 之一。规划校验只固定正式数据安全：基础修订锁定、结构确认点、保护项覆盖理由、候选就绪和阻断项处理；场景矩阵只用于覆盖测试，不是教师输入门槛或死路由。

当前实现已经提供合同、动态路由、重规划和发布前校验，并通过单元测试接入原 `CourseEvolutionPlan` 序列化。“调整课程”独立工作区根据现有计划状态投影六种界面：无活动计划显示请求与历史，意图草稿显示原话/解释与修正，临时策略或生成任务显示渐进扫描，语义计划显示受影响资产与原文/候选差异，结构计划显示新旧树与六类迁移统计，已应用或已撤销计划显示实际回执。六种内部状态对用户统一投影为“说出要求—分析影响—审阅修改—应用完成”四阶段流程；提出要求后，老师原话、AI 理解和保护要求通过紧凑上下文条贯通分析、审阅与回执。前端只渲染合同已经返回的资产、预览和回执；缺少真实预览时显示待载入状态，不补造内容。教师工作区复用现有候选审阅与正式命令入口，但不渲染学生个人地图或学习证据轨迹。

生成时多粒度索引、混合召回与 Rank、AI 精读扩展、真实候选结构图和五类资产执行器仍由 `ship-teacher-course-authoring-v1` 的活动任务继续实现；在这些链路闭合前不得声称全课修改已经交付。

### 5.7 任务、事件与恢复链

任务由 `task/job ID` 唯一控制，`course_id` 只用于课程归属，`owner_id` 用于任务查询和控制隔离。HTTP 提供完整投影，WebSocket 提供低延迟增量；前端缓存只保存最后成功现场，联网后必须与服务端按任务 ID 对账。

任务状态、质量结果、发布许可和课程可见性是正交概念，不得压成一个字段。部署重启通过持久任务和工作区恢复，不能为发布建立第二任务迁移系统。

### 5.8 产品使用记录链

```text
最终 Vue route / Axios 写操作终态 / 分类客户端错误
-> 前端有界队列与身份分组
-> /api/usage-events/batch
-> 事件和属性白名单
-> UsageEvent
-> 个人汇总、导出、硬删除 / 密钥保护的全局聚合
```

`UsageEvent` 只回答产品怎样被使用，不回答学习者是否掌握、课程是否发布或任务是否真正完成。路由只保存稳定 route name 或已经去掉查询参数并替换动态 ID 的 API 模板；请求体、响应体、答案、Prompt、错误消息、堆栈、IP、User-Agent、Cookie 和设备指纹不得进入账本。聚合使用服务端 `received_at`，客户端时间只用于排查顺序。

采集默认自托管，失败时保留有界本地队列并静默退出，不得改变正式请求的成功、失败或重试语义。服务端默认保留 180 天和最近 200,000 条；多实例部署前必须迁移到具备唯一约束与统一保留策略的数据库，不能让多个进程分别维护文件真源。

个人汇总、导出和删除复用项目当前 `X-User-Id` 稳定身份边界，不代表正式账号鉴权。多租户生产环境必须先接入真实账号/会话 authority，再把这些接口当作租户隔离保证。

## 6. 外部与存储边界

- AI 调用统一经过 `AIBase` 和共享容量控制；不同能力可以有专用 Prompt 和解析器，但不能绕过预算、超时、降级和敏感信息边界。
- 联网调用统一经过 `web_retrieval.py` 的 `SearchProvider` 边界。默认 `SearXNGSearchProvider` 只接受回环地址并访问同机 SearXNG；SearXNG 汇总分数仅作 Provider 元数据，来源仍由本地相关性、URL 安全、隐私脱敏、注入过滤和分层规则准入。
- SearXNG 由独立手动工作流按固定镜像部署到 `/opt/lingzhi/state/searxng`，只映射 `127.0.0.1:8080`。常规应用发布只预检，不更新该服务；Exa 适配器只用于显式兼容，不自动兜底。
- 联网检索只覆盖教师显式启用的课程蓝图/正文、课程工作台资料调研、题库和 AI 老师。评分、作答诊断、学习者模型、学习路径、既有课程结构演化以及 PPT/配图链路不出站。
- 文件上传经资料管线保存引用、解析结果和来源；浏览器或 Axios 生成 multipart boundary，后端是最终类型和大小边界。
- 用户代码只通过 `runner/` 隔离执行。主后端不直接 `exec` 用户代码。
- 本地 JSON、生成工作区和导出产物是当前实现介质，不代表所有对象共享同一生命周期。源码、用户数据、缓存、演示产物和发布包必须分开管理。
- 旧版本把教师空白草稿写入随机学习者身份时，只能通过 `scripts/reconcile_local_teacher_draft_owners.py` 的 dry-run、仓库外物理备份和空草稿/空文件包安全门迁移；非空对象与所有权冲突不得自动改绑。
- `usage_events.json` 是运行数据并被 Git 忽略；全局分析只返回聚合，原始使用记录只能由所属身份导出或删除。
- Prompt 正文、密钥和模型推理不进入日志、任务投影或文档。

## 7. 兼容、降级与扩展规则

- 旧课程可以只读兼容，新的正式写入必须进入当前领域命令和当前 schema。
- 模型失败可以返回可恢复失败、局部明确降级或最后可用结果，不能虚构正式业务内容来伪装成功。
- 同一能力的自动、手动、恢复和兼容入口必须共用领域函数、质量门和修订检查。
- 新增状态前先确认现有拥有者；新增接口前先确认能否扩展稳定领域投影。
- 新增 AI 能力必须说明输入依据、输出类型、是否持久化、用户控制、失败降级、恢复方式和旧入口退出计划。
- 具体字段、状态机、接口和验收场景以当前正式 OpenSpec 为准；架构变化完成后再更新本文，不提前记录设想。
