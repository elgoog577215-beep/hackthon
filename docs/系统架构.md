## 1. 技术架构设计

### 1.1 架构目标

技术架构承接产品蓝图中的教学体系、产品逻辑、交互与界面，目标不是堆积更多页面和生成接口，而是把稳定产品关系实现为可复用、可组合、可验证的能力。

```text
产品对象与规则
-> 结构化领域协议
-> 前端通用交互能力 + 后端原子领域能力
-> 工作流和 Agent 按任务组合
-> 确定性状态、权限、质量与恢复
```

核心原则：

1. 前端把稳定的对象、关系、状态和动作沉淀为共享组件与工作区能力，页面只负责组合。
2. 后端把类型判断、结构规划、教学块组合、内容生成、质量检查、局部修复和修订管理拆成边界清楚的能力。
3. 学习目的、一级学科类型、课程教学类型、本讲课型、教学块和教学产物之间的稳定关系进入注册表、规则或领域协议，不长期隐藏在 Prompt、页面分支或巨型服务中。
4. Agent 通过工具和结构化协议组合能力；权限、正式真源、状态迁移、质量门、恢复和发布继续由确定性系统控制。
5. 新增学习目的、一级学科合同、课程教学类型、本讲课型、教学表达或生成提供方时，优先扩展注册表和组合规则，不复制整条前后端链路。
6. 跨模块链路保留来源、任务、版本、输入摘要、输出状态、失败原因和恢复入口。

### 1.2 总体分层

```text
Vue 页面与工作区
-> 共享交互组件 / Pinia 领域投影
-> FastAPI HTTP / WebSocket 接入层
-> 应用服务与工作流编排
-> 领域对象、规则、命令与质量门
-> 仓库、任务工作区与修订日志
-> AI / 检索 / 文件 / 独立 Runner 等提供方
```

各层职责：

| 技术层 | 负责 | 不负责 |
| --- | --- | --- |
| 页面与工作区 | 组织当前任务、上下文和界面状态 | 保存正式业务事实、复制领域规则 |
| 共享组件与 Store | 复用交互语义、投影服务端状态 | 成为第二真源、独立发明状态机 |
| 接入层 | 身份、鉴权、参数、HTTP 错误和响应转换 | 复制领域状态机和生成逻辑 |
| 应用与编排层 | 组合已有领域能力、管理任务和检查点 | 绕过领域不变量直接写仓库 |
| 领域层 | 对象、规则、命令、质量合同和状态迁移 | 依赖具体页面布局 |
| 仓库与任务层 | 持久化、修订、幂等和恢复 | 解释产品语义 |
| 外部提供方 | 模型、检索、文件解析、渲染和隔离执行 | 决定正式状态和用户权限 |

### 1.3 仓库结构

| 目录 | 职责 |
| --- | --- |
| `frontend/` | Vue 3、Vite、Pinia、教师工作台、学习现场、PPT 工作台和中英文界面 |
| `backend/` | FastAPI、领域服务、生成编排、学习运行时、AI 能力、持久化和任务恢复 |
| `runner/` | 独立代码执行服务；主后端通过客户端调用，不直接执行用户代码 |
| `tests/`、`backend/tests/` | 兼容回归与当前后端领域测试 |
| `scripts/` | 迁移、验收、部署、录屏和诊断工具，不拥有运行时真源 |
| `openspec/` | 高影响变更的提案、设计、稳定规格、任务与归档 |
| `docs/` | 产品、状态、架构、事实、验收、研究和历史归档 |

开发态由 `dev.sh` 或 `dev.bat` 启动前后端；生产态由 FastAPI 托管前端构建产物，入口 HTML 与带哈希资源使用不同缓存策略。

## 2. 领域协议与正式真源

### 2.1 正式真源

| 领域 | 正式真源 | 不能作为真源 |
| --- | --- | --- |
| 正式课程 | `CourseDocument + ordered CourseBlock[]` | 生成草稿、旧 `nodes`、Markdown 导入稿、前端缓存 |
| 课程生成 | `GenerationJob + job_id 隔离工作区 + 发布回执` | 课程 ID、本地百分比、单条 WebSocket 消息 |
| 课程教学设计 | 版本化 `CourseTeachingPlan` 与分讲当前修订 | Markdown 投影、页面表单草稿 |
| 教师分讲资产 | `TeacherLessonAuthoringRepository` 中按 `LessonUnit` 保存的编排、教案、讲义、PPT 关系与修订 | 上传原件、旧整课快照 |
| 课程知识 | 当前课程 `CourseKnowledgeBase` 与稳定课程内 ID | 模型临时标签、目录标题、前端关系图 |
| 学科知识 | 版本化 `SubjectKnowledgeLibrary` | 单门课程自造的正式学科 ID |
| 正式题库与试卷 | 当前题库修订；试卷的有序题目修订引用和固定题库修订 | 前端勾选、复制题干答案 |
| 学习事实 | `LearningEvent`、`LearningRecord`、`PracticeAttempt`、快照与诊断 | AI 会话、页面统计、模型主观判断 |
| 学习者模型 | 从同批正式事实确定性重算的 `LearnerModel` | 可独立写入的画像副本 |
| 课程调整 | `CourseEvolutionPlan`、领域命令、修订和幂等回执 | 组件本地候选、旧 `CourseChangeSet` |
| 教学表达 | 来源绑定的 `TeachingRepresentation / SlideDeckSpec` | 浏览器临时重组、导出器二次摘要 |
| 配套文档 | 版本化模板、结构化输入和当前不可变修订 | DOCX/Markdown 导出、文件列表投影 |
| 产品使用记录 | 非权威、追加式 `UsageEvent` | 学习事实、服务日志、第三方画像 |

任何兼容读取都从正式真源生成投影。新写入不得扩大旧对象或建立平行协议。

### 2.2 修订、状态与命令

- 正式新增、替换、退休、恢复、移动、拆分和合并通过领域命令完成。
- 工作稿可变，正式修订不可变；自动保存只保存工作现场。
- 任务状态、结构可用性、质量审阅、当前修订、发布许可和课程可见性正交保存，不能压成一个字段。大纲、教案和讲义的旧确认字段只用于历史兼容，不再参与主链准入。
- 影响分析只标记真正依赖当前修订的下游对象；失败保留最后可用版本。
- 幂等键、基线修订和稳定对象 ID 共同阻止重复应用、静默覆盖和错位恢复。
- 前端 Store、WebSocket 和文件清单只是投影，必须能从 HTTP 正式状态重新对账。

### 2.3 身份与权限

身份域由路由元数据或领域调用显式声明为 `teacher` / `learner`，HTTP 客户端只执行声明，不根据 URL 猜测。

`X-User-Id` 是灵知内部稳定 actor 合同。本地独立运行时它仍是开发身份边界，不等价于登录鉴权；挂载到启智正式环境时，启智 OAuth/JWT 与 RBAC 是唯一身份 authority：

- 未发布教师课程、课程任务、资料和工作稿按 `owner_id` 隔离。
- 发布后的课程可以供学习者读取，但学习事实仍按学习者身份分区。
- 教师预览使用教师身份，不读取或写入学生数据。
- 正式构建从同域读取启智 bearer token，灵知通过内部 `GET /user/current` 验证当前用户和 teacher/admin 角色，再由服务端覆盖浏览器身份并注入 `qizhi:<user-id>`；HTTP、SSE 和 WebSocket 使用同一登录态。
- 身份验证结果只按 token 哈希短时缓存，不复制启智 JWT 密钥；登录失效、角色不足和身份服务不可用分别返回 401、403、503，健康检查不依赖登录态。
- 未配置 `QIZHI_AUTH_VERIFY_URL` 的本地环境继续沿用开发身份；历史共享 actor 课程不会自动归给正式账号，迁移必须显式映射 owner。

### 3.2 共享交互能力

前端复用单位不是“长得像的一张卡片”，而是稳定交互语义：

| 共享能力 | 统一处理 |
| --- | --- |
| 工作区骨架 | 阶段或目录导航、当前内容、上下文资料和响应式收拢 |
| 正式文档面 | 阅读、直接编辑、自动保存、AI 候选、差异、历史和恢复 |
| 结构导航 | 新课程的讲次、文件夹与稳定对象定位；历史章/节只读兼容 |
| 资料关系 | 主来源、参考资料、联网来源、反向使用关系与删除保护 |
| 生成任务 | 提交、流式片段、真实状态、暂停、重试、恢复与完成回执 |
| 审阅与影响 | 原文/候选差异、影响对象、保持不变项、阻断与部分接受 |
| 版本状态 | 当前、过期、降级、最后可用版本和来源修订；历史确认指针只兼容读取 |
| 错误反馈 | 统一分类、原位原因、一个主要恢复动作和可追踪错误码 |

共享组件只拥有展示和短时交互状态。课程、资料、任务、候选和正式修订继续由各自领域 Store 与后端真源拥有。

### 3.3 状态投影

Pinia Store 按领域投影组织：

- `course.ts`：当前课程和正式课程文档。
- `generation.ts`：生成任务、检查点、WebSocket 和恢复。
- `learningSession.ts`、`learningProgress.ts`：当前学习会话和进度。
- `learnerModel.ts`：后端正式学习者模型的只读投影。
- `aiTeacher.ts`：教师或学生视角的会话、候选、动作和回执。
- `courseEvolution.ts`、`changeProposals.ts`：课程调整计划和审阅状态。
- `teachingPlanWorkbench.ts`、`teachingRepresentations.ts`：教案与教学表达。
- `teacherLessonAuthoring.ts`：同一讲次编排、教案、讲义和 PPT 修订；教学块同时投影课型依据、师生行动、证据、反馈、调整和课堂条件。

多个界面消费同一状态时复用一个 Store。组件局部状态只管理展开、选中和临时输入，不能成为持久业务状态。

生成返回不再由各页自己判断，统一按结果类型处理：

- 课程、教案、讲义、题库和 PPT 等耐久生成继续由原任务所有者保存检查点，通过 WebSocket 或 SSE 投影真实工作片段，断线后从原任务恢复。
- AI 助手的自由文本在提供方支持时输出真实文本增量；请求一到达就返回已接收状态，提供方静默时只发等待心跳，不把心跳冒充回答。
- 大纲、教案、讲义、正文、练习引导和 PPT 的短时结构化 AI 候选复用原路由和原领域函数，前端通过 `Accept: text/event-stream` 获得“已开始—处理中—已完成/失败”；半截 JSON 不对外显示，只在完整结果通过现有校验后交付。
- 本地 Codex 提供方如果只能一次返回完整结果，明确标记为 `buffered_fallback`；页面显示真实等待状态，不在结果返回后人工切块伪装 token 流。

课前设计、课中实施和课后复盘是同一讲次真源的三种任务投影。前端以 `lesson_unit_id + arrangement_revision_id + asset_revision_id` 维持身份：课前显示完整编辑合同，课中显示当前块、讲义、计时、证据记录与已确认备选，课后显示目标—事实—判断—调整关系。课堂记录写入事件或教师观察，AI 判断和调整候选使用独立状态；只有教师确认的正式命令才创建新修订。

### 3.4 渲染、语言与设备

- Markdown、KaTeX、Mermaid、代码高亮和安全链接通过共享渲染链处理。
- 课程正文、AI 结果和导出预览不得在不同页面分别修补同一种语法。
- 用户可见固定文案进入中英文词典；课程内容保持原始语言。
- 桌面与移动端共用对象和状态协议，但布局、覆盖层、触控和密度分别验收。
- 身份、课程、讲次、内容锚点和返回位置通过稳定路由或状态参数传递，不从可见标题反推。

## 4. 后端能力架构

### 4.1 分层责任

`backend/main.py` 组装 FastAPI，`backend/routers/` 负责接入。路由只处理鉴权、参数、HTTP 错误和响应转换；应用服务协调领域能力；领域服务拥有不变量；仓库拥有持久化；编排器不复制领域规则。

后端 API 按领域能力、命令或稳定投影设计，不按页面卡片设计专用状态接口。

| 共享领域工具 | `knowledge_structure.py`、`learning_event_evolution.py`、`markdown_table.py`、`teacher_visible_language.py` |

`scripts/audit_backend_dependencies.py` 按 Python AST 递归检查后端生产模块的调用方向，并已加入仓库检查工作流。加上 `--report` 后会列出被调用最多的模块、直接依赖最多的模块、最大文件以及直接导入存储或任务对象的路由。当前源码检查覆盖 273 个生产模块，循环依赖为 0；并且禁止新代码重新从已退场的根模块名导入能力。`jobs/manager.py` 和 `course_generation/service.py` 虽已分出内容处理、PPT 构建、节点进度、关系检查与规划状态，但仍分别有约 9490 行和 7624 行，部分路由也仍直接取用多个仓库；因此当前结论是“主责已归位，继续拆分”，不是“架构已经全部拆完”。

旧链路处理以能力为单位，不以文件新旧或是否正在被调用为唯一依据：仍在使用且有独特价值的能力迁入现行主责模块；只为历史数据服务的逻辑收到明确的只读适配边界；无调用者、无独特能力、也不承担恢复职责的外壳直接删除。合并后只有一个能力主责者和一条正式写入路径，但不会为了形式上统一而删掉教师生产或学生学习中仍有用的能力。

### 4.3 教学策略引擎

产品已确认的教学规则分为两级：学习目的、一级学科类型和课程教学类型共同决定整课结构；本讲目标、本讲课型、学科规则和课程约束共同决定教学块。每个教学块必须写清教师动作、学习者行动、学习证据和反馈调整。技术架构必须用同一套语义编译入口承接：

```text
TeachingDefinition + UniversalTeachingPrinciples
+ 学习目的合同 + 一级学科合同 + 课程教学类型合同
+ 学习者起点、难度、资料、规模与实施条件
-> compile_course_semantics
-> GoalEvidenceMap + 大纲、全课教学设计、讲次课型分布与必备环节

当前讲目标 + 本讲课型模板 + 一级学科合同 + 课程级约束
+ 当前内容、阶段、时长、难度、资料与环境
-> compile_lesson_semantics
-> TeachingBlockCompiler（统一编排入口）
-> compile_teaching_block_contract
-> TeachingBlockPlan（教师动作、学习者行动、证据、反馈、调整、进入支持与衔接）
-> teaching plan / script / assessment / representation compiler
-> 各类正式产物

课堂真实表现 -> LearningEvent / 作品 / 作答 / 教师记录
-> 达成判断与局部调整候选
-> 教师确认 -> 受影响教学块或后续产物的新修订
```

七类技术资源各负其责：

| 资源 | 保存什么 | 负责什么 | 不负责什么 |
| --- | --- | --- | --- |
| 教学定义与共同原则 | 教师、学习者、AI 的责任，以及成果、行动、证据、反馈和迁移的共同底线 | 约束所有学科、课型、教学块和产物质量 | 变成教师需要选择的理论菜单 |
| 学习目的合同库 | 三种目的的必填信息、全课结果和质量门 | 约束大纲主线和全课评价 | 代替具体课程目标或决定每一讲怎样上 |
| 一级学科标准库 | 八种学科的识别规则、专业动作、证据、产物和安全护栏 | 约束内容、教学块、讲义和评价的专业性 | 再建立一套二级学科菜单 |
| 课程教学类型合同库 | 六种整课类型的课型分布、必备环节、评价重心和默认课堂弧 | 约束大纲、全课设计和每讲课型推荐 | 要求所有讲次使用同一种课型 |
| 本讲课型模板库 | 七种课型的最小教学弧、块角色、顺序倾向和完成证据 | 形成当前讲课堂主弧 | 替代学科专业动作或重写整课结构 |
| 专业动作库 | 可复用教学动作的输入、输出、适用条件和质量规则 | 被编排器选择并组合为教学块 | 直接暴露模块 ID 给教师 |
| 课堂条件与调整合同 | 时长、班额、分组、设备、网络、安全、无障碍要求和三档反馈分支 | 让同一目标在真实条件下可执行、可恢复 | 静默降低核心目标或把现场判断交给模型 |

代码、标准库、Prompt 与 Agent 的分工固定如下：

| 承载方式 | 必须负责 | 可以负责 | 不得负责 |
| --- | --- | --- | --- |
| 确定性代码 | 字段优先级、兼容转换、条件匹配、块选择、顺序、时长、预算、冲突和质量校验 | 根据结构化信号推荐类型 | 靠关键词临时发明产品分类 |
| 版本化标准库 | 教学定义、四类稳定语义、学科标准、课型模板、动作合同、课堂条件和质量规则 | 持续扩充专业知识 | 保存用户课程正文或任务状态 |
| Prompt | 在当前教学块内生成讲解、案例、活动、提问、可能回应、三档反馈、支持和过渡候选 | 对资料作语义理解，解释推荐理由 | 决定正式类型、块顺序、权限、准入或发布 |
| Agent / 工作流 | 调用编排、生成、检查、修订和影响分析工具 | 根据任务选择已有能力和恢复点 | 绕过统一编排器另造一条生成链 |

目标架构约束：

- 明确教师选择与自动推断分开保存；推断结果带证据和置信度。
- 目标难度与学习起点分开编译；难度落实为挑战、支架、独立性、迁移和学科任务，不通过篇幅、术语或题量伪造。
- 课程教学类型只调整整课课型分布、必备环节和评价重心，本讲课型只调整当前课堂主弧、块比例、角色和顺序；二者都不替代学科专业动作，冲突时先返回冲突，不静默折中。
- 课程教学类型、本讲课型和教学块注册表保存稳定 ID、角色、适用范围、输出合同和质量要求。
- 每个教学块必须保存教师动作、学习者行动、可观察证据、检查方式、达到/部分达到/未达到的处理、参与方式、进入支持和前后衔接；只有活动名称或内容摘要不构成可执行教学块。
- 生成服务消费编译后的合同，不在每个下游 Prompt 中重新解释一遍类型关系。
- 新学科、课程教学类型或本讲课型通过扩展注册表、映射和评测集进入，不复制教案、讲义和 PPT 整链。

当前 `main` 已将教学定义、学科标准、课程规划、教学指导和讲次编排归入 `teaching_design/`，由 `compiler.py` 作为第三版统一教学语义编译入口，并在原生成链上接入 `subject_standard_pack_v1`。标准包按“八种一级学科 → 学科画像”分层解析，明确记录专业认识方式、专业动作、典型产物、证据形态、常见误区、来源边界、安全边界、产物语言、质量规则和教学块配方；UI 设计按视觉与交互设计画像生成用户任务、线框图、交互原型、设计规范和可用性证据。课程生成、教师按讲编排、教学块合同与讲义 Prompt 消费同一份已解析标准包。`course_generation_v17 / course_prompt_v31` 让每讲直接返回并全链保留学生产出、判断标准和本讲范围；缺失内容保持空值并交由 `course_outline_editorial_v5` 定位，其中课程成果缺少目标、覆盖讲次或评价证据时进入非阻断审读建议，不再注入统一占位句。旧学科原型与 105 个模块仍处于兼容吸收期：

```text
teaching_design/compiler.py
  -> 教学定义与共同原则
  -> 新字段解析、旧字段单向转换与课程语义合同
  -> 解析并记录版本化学科标准包
  -> 讲次课型合同、课堂条件投影、质量规则与推荐依据
  -> 教学块的师生行动、证据、反馈、调整、支持和衔接合同
teaching_design/standards.py
  -> 八种一级学科默认标准与学科画像覆盖
  -> 专业动作、典型产物、证据、误区、来源、安全、质量规则与教学块配方
  -> 为大纲、教案、讲义、题库和 PPT 分别提供学科产物语言，不改变五类产物的正式真源
teaching_design/course_planning.py + course_generation/workflow.py
  -> 完整课程生成消费统一课程语义合同
course_pedagogy.py + subject variant
  -> 八种学科、旧学科细分与模块集合
course_pedagogy_archetypes.py
  -> 内容阶段到旧 archetype 的选择
course_composition.py
  -> 旧编排节奏与块顺序
teaching_design/lesson_arrangement.py
  -> 消费统一课程/讲次语义，兼容旧学科画像和模块集合，形成可执行教学块并执行结构质量检查
teaching_design/guidance.py + assessment_orchestrator.py

  -> 新课程正式写入只保存学习目的、一级学科类型和课程教学类型；旧分类字段仅留在历史读取与旧生成内核过渡边界
```

八种一级学科标准包已经建立第一版，并覆盖常用学科画像；但专业动作去重、更多学院固定样本、全链路历史数据迁移和真实跨学科模型验收尚未完成。因此标准包是现行编译入口，旧资产只作为兼容原料库，不能继续拥有产品分类权。迁移由 `split-teacher-lesson-authoring-v1` 承担，遵循以下转换：

| 旧字段或能力 | 新归宿 | 迁移要求 |
| --- | --- | --- |
| `course_type=systematic/project/exam` | 学习目的 | 分别转为系统学习、项目实战、期末冲刺 |
| `course_type=inquiry` | 学习目的 + 具体课程目标 + 内部探究策略 | 保留核心问题；学习目的按最终成果判断，默认推荐研讨课，并在适用讲次推荐实验探究或案例研讨 |
| `subject_variant` / 学科细分 | 一级学科合同的条件规则 | 保留识别依据与动作选择，不保留教师二级分类 |
| archetype / composition style | 内部动作与课程教学类型执行规则 | 保留成熟规则，删除平行产品状态 |
| 七种旧 `lesson_type` | 七种本讲课型 | `theory_practice` 映射讲练结合，`experiment_inquiry` 兼容映射实验探究，其余稳定迁移 |
| 105 个模块 | 版本化专业动作库 | 去重后继续复用作用、输入、输出和护栏，不暴露实现 ID |
| 旧 Prompt 约束与优质结果 | 模块化提示组件与回归集 | 只在当前语义和教学块内生成、检查，不拥有分类选择权 |

兼容解析优先级为“教师明确的新字段 > 教师明确的旧字段 > 系统推断 > 安全默认”，并记录 `resolved_from`、原值和转换结果；迁移完成前不得让新旧字段同时控制最终编排。

### 4.4 资料与证据

老师批量导入的原件由课程文件空间保留不可变副本，同时登记可供解析和生成使用的 `mat-*` 标识，不在文件树中复制第二份可见文件。正式目标保存一个主来源、多份参考资料和可选联网来源；系统只在目标从未配置时按资料类型与讲次自动建立默认关系，手动清空也作为正式配置保存。移除引用不删除原件，仍被引用的原件不能直接删除。

首次准备弹窗和课程文件系统都调用同一批量导入接口。接口先复用 `material_document_parser` 读取正文，再由 `course_material_understanding` 完成四维资料理解：确定性证据守住格式、强正文结构和教师确认，单次有界模型请求补充文档用途、课程/章节位置、版本角色及原件关系。结果随工作包持久化置信度、依据、分析来源、缺失材料和低置信文件；模型不可用时显式保存 `rule_fallback`，导入成功与 AI 成功不得混为一谈。每次增量导入都会重新分析完整工作包，使新文件可以与旧文件建立关系，但不得覆盖教师确认的文档类型。

`material_document_parser` 按格式选择适配器，但所有适配器只生成同一种 `ParsedDocument / EvidenceBlock`。`.docx/.pptx/.xlsx` 直接解析；`.doc/.ppt/.xls` 在隔离临时目录中经 LibreOffice 转成 OOXML 后回到同一解析器，原件不改写。DOCX 额外保留标题层级、列表、表格单元格、页眉页脚、图片/媒体数量、公式数量、批注与修订痕迹边界。文本型 PDF 按页保留可定位文本块，文本层为空时才逐页运行本地 OCR，并保留页码、区域与置信度；PPTX 额外保存对象位置、图表系列、讲者备注、图片数量与动画存在性。图片语义、复杂公式、批注采用状态和动画含义无法确定时只记录能力边界和降级警告，不生成推测内容。

`course_material_absorption` 把完整课程工作包编译为一份可执行审计方案，目标稳定寻址为 `managed:outline`、`lesson-plan:{lesson_unit_id}`、`script:{lesson_unit_id}` 和 `ppt-v6:{lesson_unit_id}`。方案保存文档类型、课程/讲次位置、版本角色、主/参考来源、解析质量、冲突和结构预览。`courseUpdateCenter` 把该材料方案与 `CourseEvolutionPlan` 投影为同一变化来源列表，`TeacherMaterialAuditReportView` 在唯一 `/course/:courseId/audit-updates/:planId?` 路由上展示“来源 → 关系/影响 → 判断 → 执行/回执”。材料执行仍按 `plan_id + target_id + content_hash` 幂等写入 `TeacherLessonAuthoringRepository`；全课调整仍由课程变更计划调用各领域命令。两者共用页面编排、历史与返回位置，不合并正式数据真源、质量检查或撤销命令。原件、当前修订和历史修订不被静默覆盖；中断后通过各领域回执安全对账。

教师显式启用联网研究时，统一检索网关生成不可变检索包或课程范围调研会话。公开 HTML/PDF 正文经过 URL 安全、正文质量、超时、体积和注入过滤；单个来源失败只回退该来源摘要。教师勾选后才转成课程资料，继续进入 parse -> evidence -> grounding，不直接成为正式内容。

## 5. Agent 与工作流架构

### 5.1 Agent 的位置

Agent 位于领域能力之上，负责理解任务、选择工具、编排步骤和汇总候选，不拥有正式数据，也不绕过既有工作流。

```text
用户目标 + 当前上下文
-> Agent 任务判断
-> 选择一个或多个结构化工具
-> 领域能力执行并返回候选/报告
-> Agent 解释结果与下一动作
-> 用户确认
-> 正式命令
```

教师备课助手把这套关系落实为三种调度结果，而不是另一条业务链：要求含糊时先澄清；只修改当前大纲、教案、讲义、题库或 PPT 对象时，继续调用该资产原有候选接口；涉及多种资产、整课批量替换，或改变章讲小节身份和顺序时，调用原 `/evolution/course-plans` 接口。后者只在 AI 侧栏投影方案 ID、状态和影响摘要，审阅、下游候选、采用、回执与撤销仍全部由现有课程调整工作区和 `CourseEvolutionPlan` 承担。学习者 AI 老师不复用教师正式写权限。

一次模型调用、一个超长 Prompt 或一个巨型服务都不等于 Agent 架构。Agent 式设计至少要求：

- 工具有清楚的输入、输出、权限、状态和失败合同。
- 工作流可以组合和恢复，而不是只能从头运行。
- 模型只处理需要语义判断的部分，确定性规则负责状态和安全。
- 候选、解释和正式写入分开，用户确认不可省略。
- 每次执行可以追踪使用的对象、资料、修订、模型能力和质量结果。

### 5.2 工作流编排

稳定工作流负责必须发生的依赖、结构安全与来源有效性；Agent 负责在允许范围内选择能力和顺序：

| 内容 | 稳定工作流负责 | Agent 可决定 |
| --- | --- | --- |
| 大纲 | 课程基线、结构校验、批次、当前修订和任务恢复 | 资料如何摘要、候选结构如何解释 |
| 教案 | 当前大纲、课程教学类型、本讲课型、教学块、覆盖和结构可用性 | 如何补充案例、活动和教学表达 |
| 讲义 | 当前教案、块顺序、知识、来源与结构可用性 | 每块的具体讲述、例子与过渡候选 |
| 题库 | 出题意图、公开/私有隔离、验证和审核 | 题目候选、变式和诊断解释 |
| PPT | 当前讲义、页面内容稿内部确认、来源保真和渲染 | 页面叙事、构图和素材建议 |
| 课程调整 | 证据、范围、影响、命令和复验 | 假设、反证、候选修改和说明 |

Prompt 模板是能力内部实现，不拥有产品类型、正式状态和跨能力依赖。

题库重建继续使用同一个课程评估蓝图、重建任务和发布仓库。蓝图把每个讲次拆为概念辨析、目标应用、迁移掌握三个槽位；`compile_question_design_brief` 为每个槽位确定一个主要知识/误区目标，并编译学习者动作数、推理步数和题干长度预算。模型只收到当前槽位的有界投影，三个槽位共同覆盖讲次，不允许单题同时实现整章全部证据要求。课程兼容准备、逐题生成、求解审计和发布仍属于同一个持久 `question_bank_rebuild`，长时间模型活动按固定间隔续写原任务心跳，不新增轮询任务或用浏览器状态冒充后台状态。

### 5.3 AI 提供方与容量

AI 调用统一经过 `AIBase` 和共享容量控制。不同能力可以使用专用 Prompt、模型和解析器，但必须复用：

- 预算、超时、并发、重试和熔断。
- 敏感信息与最小上下文边界。
- 结构化输出解析和质量门。
- 明确降级、最后可用结果和任务回执。

模型失败只影响当前最小工作单元，不能清空整门课程或伪造成功。

## 6. 主要运行链

### 6.1 教师课程生产链

主要课程生产步骤已经确认，技术实现仍在处理 4.3 所述的旧数据兼容：

```text
course_profile + 固定 45 分钟周课表 + 计划讲数
-> TeacherCourseBrief + 学习目的 + 一级学科类型 + 课程教学类型 + 资料引用
-> 同一 course_id 下的空课程空间
-> teacher_outline_generation 一次生成全课按讲大纲
-> 非空且结构可用的大纲直接成为当前修订
-> 当前讲目标 + 本讲课型 + 内容/时长/难度/资料
-> compile_lesson_semantics 形成课堂弧与实施条件
-> TeachingBlockCompiler 形成当前有序教学块
-> compile_teaching_block_contract 写清时长、目标内容、师生行动、产出、检查、反馈调整、衔接和讲义/PPT映射
-> 分讲教案生成完成后直接成为当前可编辑修订
-> 分讲讲义（内部兼容 ID 仍为 `script`）按块生成，完成后直接可编辑并可进入 PPT
-> 页面内容稿编译、审阅与确认
-> 从已确认页面内容稿确定性编译 Web/PPTX
-> 学生视角预览直接读取当前教师投影
```

题库、试卷、教学日历和配套文档读取同一课程基线，但不是四阶段主链的阻断步骤。大纲、教案、讲义和 PPT 使用真实任务 ID 保存进度与检查点，支持暂停、继续、取消、失败重试和完成后重新生成；清空不得覆盖当前或历史修订。全课教案使用一个父回执聚合每讲独立子任务，同一课程的批量教案任务共用串行执行锁，只有上一讲结束后下一讲才进入模型调用；前端把整课启动、进度和恢复操作投影到右侧资料栏。中栏在首次生成前投影本讲准备、课型推荐和教学块摘要，系统保存当前编排，教师可直接启动当前讲独立任务，也可等待批量任务运行到本讲；单讲任务不要求前序讲次完成，一讲失败不清空其他已完成讲次。

课程库的“备课中 / 备课完成”是读模型：只有当前大纲存在，且所有计划讲次均存在当前、结构可用且来源未过期的教案、讲义和 PPT 时才投影为备课完成。该状态不由前端缓存或旧确认指针直接写入。

学生视角预览不是独立发布面。教师从工作台打开预览时，前端使用教师身份读取当前大纲与当前产物，并复用学习界面渲染；系统不再维护整门课程“待发布”状态或发布接口，也不用大纲、教案或讲义确认状态创造第二套可见性。

新课程写入 `authoring_structure_version=lecture_v1`。教师确认的 `planned_lecture_count` 会保存在课程信息与生成简报中；恢复同一任务时只补缺失讲次，最终大纲必须再次校验讲数，不能回到自然语言或由模型重新推断规模。生成内核尚需 `chapter_count/section_count` 时，由兼容适配器固定投影为“一讲一个内部容器”，不得反向暴露给教师。历史章/节课程保持原样读取，不执行迁移。

新讲次式课程的大纲合同版本为 `formal_syllabus_v2`。`course_generation/outline.py` 负责归一课程介绍、学习目标、育人目标、可测量结果及其关联、结构化考核、知识模块、逐讲应用载体/拓展资源/学习任务/分类学时和可选校外导师；`course_generation/prompts.py` 只在这个合同内生成候选；`CourseOutlineReview.vue` 直接编辑同一当前修订。旧 `assessment_methods`、`course_outline` 等字段只由兼容适配器投影，不参与新课程的双写。`course_outline_editorial_review_v6` 使用 `course_outline_editorial_v7` 规则，在生成、手工保存、AI 候选应用和历史恢复入口共用：所有发现都保留在 `issues` 中并统一投影为非阻断建议，不修改生成完成态，不成为教案准入。`CourseOutlineReview.vue` 在每次修订写入后发出最新报告，`TeacherCourseWorkbench.vue` 仅显示低强调“查看大纲审阅”按钮，教师点击后在弹窗中查看建议；可自动修复的问题继续进入原蓝图候选预览/应用链，采用后以保存响应重新审读。固定审读目标关系、逐讲三类责任、来源核验、授课模式、总学时、考核 100% 与模块唯一覆盖；字数和条数仅从教师设置的 `template_constraints` 读取。来源、版次或链接未核验时只允许教师手工补充，AI 不得把未知来源写成已核验事实。

教学日历候选继续由 `routers/teaching_calendar.py` 从当前大纲生成。它投影讲次内容、任务要求、育人目标、从 `hour_breakdown` 推导的教学形式与总学时，以及已确认 `external_mentor`；日期、时间、地点、教师、分组和备注只属于日历修订。`teaching_calendar_export.py` 从同一修订生成 DOCX、PDF、XLSX 和 CSV，其中 PDF 通过 ReportLab 嵌入 `backend/assets/fonts/WenQuanYiMicroHei.ttc` 的实际字形子集，避免依赖服务器或查看者本机字体。

`course_schedule.py` 与前端 `zju-academic-calendar.ts` 共同实现同一教学周规则：`week_range_mode=academic_calendar` 时，春夏、秋冬固定投影为第 1–16 教学周，春、夏、秋、冬及兼容的“春季/秋季”等写法固定投影为第 1–8 教学周；`week_range_mode=custom` 时保留教师填写的起止周。旧课程没有该字段且仍是默认第 1–16 周时，读取短学期会归一为第 1–8 周。大纲已有结构化周课表时按每周实际授课段排讲次；没有周课表时按计划讲数与教学周数计算每周讲数，只投影周次，不从总学时猜测每讲学时。暑期课、寒期课和无法识别的学期不自动套用标准周数；年度具体日期、节假日和调休不由这层规则生成。

当前 `teaching_design/lesson_arrangement.py` 是统一课程语义到本讲编排的适配层：它读取课程教学类型、本讲目标、课型、课堂条件、推荐依据和已解析的 `SubjectStandardPack`，用学科块配方补齐教师动作、学习者行动、预期产物、资料引用和工具，同时继续兼容旧学科画像、细课型和模块注册表，再为每个教学块补齐认知投入、检查方式、三档反馈、调整选项、进入支持、分组和衔接。教师修改课型后，编排器按新课型重新选择并排序教学块；当前编排修订绑定大纲范围修订，大纲变化后进入 `stale`。它只将案例、讨论、实践等作为可选专业动作，不生成所有学科通用的固定课堂顺序。教案生成只消费当前、结构可用且未过期编排，不读取确认指针。`align_teacher_lesson_plan_to_arrangement` 在生成、候选采用和手工保存入口统一恢复模块身份、顺序、讲次归属、分钟数以及上述实施合同；模型拥有具体表达，不拥有教学结构和课堂时钟。本讲总时长与周课表对应连续格不一致，或关键教学块缺少师生行动、产出、检查、反馈调整、衔接和讲义/PPT映射时，结构校验阻断教案生成。

`TeacherLessonAuthoringRepository` 保存分讲教案、讲义、编排、来源关系和任务投影。讲义以有序块为真源，连续 Markdown 是确定性投影；每个修订和内容块同时记录模型生成、教师编辑、本地恢复或旧版兼容来源。讲义的产品合同是教师站在讲台上可以直接说的完整讲述：它保留专业内容、推理和边界，同时包含自然过渡、提问、可能回应、活动指令与反馈提示，不能退化为教材正文或提纲。局部生成失败保留已完成块；所有必要块生成并通过结构校验后，修订直接成为当前讲义。`direct_teaching_script_v7` 与 `teacher_script_quality_v7` 已在自动、手工、候选采用、恢复与兼容入口统一检查块身份、格式是否完整、必要学科产物、教师可直接开口的讲述、块间过渡、提问与反馈、模板占位、跨块复读和整讲深度。其中缺失块身份、顺序或必要正文等结构问题阻断 PPT；口语连贯、过渡、提问反馈、占位语、复读和深度等进入非阻断审阅报告。质量合同版本变化后重新计算报告，不单独取消当前修订的下游资格。结构完整的恢复稿可作为带警告的当前讲义；空结果、结构错误和失败任务仍然阻断 PPT。

### 6.2 学习运行链

```text
CourseDocument + 当前学习身份
-> LearningRuntime
-> 阅读、记录、正式练习和诊断
-> 正式领域对象 + LearningEvent
-> LearnerModel 确定性重算
-> 当前进度、连续性和可解释动作
```

`LearningRuntime` 是无独立存储的协调投影。一级章节只负责导航，只有具备正文和正式目标的可学习节点写入进度；普通位置同步不能跨课程版本迁移快照。

### 6.3 AI 老师与课程生长链

```text
当前课程锚点 + LearningRuntime + 最小必要证据
-> AIContextPackage
-> 解释、举例、简化、提问或白名单动作
-> 候选与影响预览
-> 用户接受、拒绝或调整
-> 领域命令 + 幂等回执
-> 新修订与独立效果证据
```

AI 会话不拥有学习事实。联网状态属于会话设置，默认关闭并按会话隔离；只有普通回答可以检索，正式写入动作不出站。

### 6.4 教学表达与 PPT 链

```text
当前、结构可用且来源未过期的讲义修订 + 教案追溯 + PPT 阶段资料
-> 选定不可变模板合同（页面构造 / 槽位 / 容量 / 来源页）
-> ppt_manuscript_v1 工作稿
-> 页面内容稿质量门与教师确认
-> compile_slide_deck_v6_from_manuscript
-> TeachingRepresentation / SlideDeckV6
-> Web 预览与 PPTX 导出
```

PPT 内容生产与渲染分两步：

1. 页面内容稿编译逐页教学任务、主要结论、可见文案、页型、版式、构图、讲义来源和证据关系。
2. 教师确认页面内容稿后，渲染器只从该修订确定性编译页面，不再调用内容模型改写知识。

参考 PPTX 导入采用双向编译合同：确定性脚本解析 Slide/Layout 关系、继承占位符、归一化几何和可填充容量，形成来源页可追溯的页面构造；AI 故事规划器只在合同允许的构造中选择页型。页面内容稿保存模板 ID、不可变版本和合同摘要；第二步生成 PPT 时重新解析并校验同一版本，摘要漂移或版本缺失直接阻断。脚本不改写教学内容，AI 不修改模板几何。

模型规划不直接接收完整验证载荷。系统保留未压缩请求作为校验真源，另编译不超过硬预算的模型投影：每个讲义块保留稳定 ID、显式标题、必要展示摘录与保护符号；重复证据字段被移除，安全分页只保留最小页数及相邻页数的代表方案。相邻短块通过 `ppt_page_group_id` 形成稳定教学单元，29 个讲义块不会机械扩为 29 页。代表性分页优先选择块数均衡的完整方案，避免一页塞入过多块后再裂成大量续页。调用前预算失败、全局标题分配失败和提供方失败分别返回可恢复失败码；进入页面内容稿只依赖当前讲义，未确认 `ppt_manuscript_v1` 时仅锁定最终 PPT 编译。

讲义生成在提供方不可用时，可以从当前教案为当前块编译可编辑恢复稿，必须标记 `completed_with_warnings` 和逐块来源，不得伪装成模型成功。恢复稿非空、结构完整且来源未过期时可作为带警告的当前讲义进入页面内容稿；空结果、结构错误或失败任务继续拒绝。PPT 故事与视觉规划同样只允许生成“来源绑定、待教师确认”的页面内容稿，禁止绕过页面内容稿直接发布。学生可见投影会移除“给出、提供、重点突出、板书、巡视”等生产与授课指令；AI 故事摘要通过校验后即成为画布投影真源，编译器不得再从 artifact prose 或正文 items/steps 回填完整讲义。完整原文只保留在讲者备注。整讲页面内容稿必须包含开场、学习路径和收束；导出前统一检查来源覆盖、唯一且面向学生的标题、文本框溢出和必需来源区域，任一阻断都不登记可导出 PPTX。

完整教师讲述进入 speaker notes，学生画布只保留当前教学动作需要的定义、条件、推导、例题、步骤、结论和任务。视觉模板提供配色、页面构造、槽位、排版与容量合同，不能把个人模板静默降级成内置通用卡片，也不能反向改变教学语义；教师在 页面内容稿中选定的模板版本保存进同一修订，浏览器预览、PPTX 编译和下载接口都必须读取该版本，不得硬编码覆盖。

老师上传的 PPTX 进入独立审阅链：保存不可变原件，建立页与文字块索引，对照当前课程产物生成报告；手工和 AI 修改形成可恢复修订，教师确认后才登记为当前 PPT。上传原件不进入讲义生成 PPT 的两步链。

V5 只保留历史读取和导出兼容；新写入使用 V6。表达失败保留最后可用版本，不能阻断课程阅读。

### 6.5 课程知识演进链

```text
知识白名单命令 + 当前知识库修订
-> 知识候选、质量门和双向影响
-> 用户确认
-> 与课程修订原子提交 + 幂等回执
-> 下游教案、讲义、练习和 PPT 重建计划
```

知识按稳定实体寻址。改一个知识点只失效引用它的下游；稳定知识 ID 和来源只能通过显式旧新映射迁移。候选遇到基线前移时先重定位，目标或字段已冲突则阻断，不静默覆盖。

### 6.6 教师全课变更链

`course_evolution/change_planning.py` 保存老师原话、解释、约束、保护项和执行策略，不拥有正式课程。普通内容计划使用经过当前正式字段命中校验的精确补丁并编译为 `REPLACE_COURSE_BLOCK`；结构计划使用完整目标树、旧新身份映射和显式退休节点，编译为单个 `REBUILD_COURSE_OUTLINE`，覆盖新增、更新、移动、排序、拆分、合并、退休和重建，并为每类受影响产物给出复用、重绑、局部改写、重建、退休或阻断决定。

教师明确提出“A 统一替换为 B”时，`course_evolution/teacher_planning.py` 先在大纲、正式 `CourseDocument`、教案、讲义、题库和 V6 PPT 的可编辑文字中确定性查找并形成精确补丁或领域迁移，再进入同一个计划与操作组；这一窄场景不依赖模型是否返回合格 JSON，也不改写 ID、修订号、来源关系和答案真值。零命中必须返回范围澄清，不能退化成只有索引命中、没有正式操作的假候选。其他语义改写仍由模型分析，但输出继续接受本地字段命中与结构完整性校验。`course_evolution/application.py` 不重写这些领域规则，只把手工调整、证据触发调整、审阅、采用、拒绝、撤销和重建协调到原有 `CourseEvolutionPlan` 上。

前端只渲染合同返回的资产、前后差异、影响和回执；缺少真实预览时显示待载入，不补造内容。教师确认内容范围或新结构后，仍调用原 `change-set generate` 入口；内部适配器把已审阅迁移编译为教案候选、讲义分节候选、PPT 页批次候选和题库修订候选，并作为 `APPLY_DOMAIN_CANDIDATE` 操作追加到同一个 `CourseEvolutionPlan`。教师逐项排除后，课程正文和结构仍通过 `CourseCommandService.apply_block_operation_group` 写入；下游候选通过原 accept/undo 入口调用各领域既有采用与回退能力，返回逐资产 applied / failed / unchanged 回执并保留 last-good。这里没有新增顶层工作流、公开 API、页面状态机或课程真源；跨仓储写入仍按真实回执协调，不能把部分成功描述成跨域数据库事务。

题库失败讲次重试仍调用原有范围重建接口。若范围任务修复的是同一课程、同一合同下原整课检查点缺失的节点，路由把成功节点、失败原因和终态合并回原课程检查点；只有全部节点发布后才把整课任务改为完成。范围任务不成为第二份课程题库真源。

### 6.7 任务、事件与恢复链

任务由 `task/job ID` 唯一控制，`course_id` 只表示归属，`owner_id` 负责查询和控制隔离。HTTP 提供完整状态，WebSocket 提供低延迟增量；前端缓存保存最后现场，联网后按任务 ID 与服务端对账。

部署重启根据持久任务、检查点和隔离工作区恢复，只继续未完成单元。恢复、手动执行、自动执行和兼容入口必须共用领域函数、结构校验、来源检查和修订检查。终态任务索引可以省略大型请求快照，但恢复前必须从隔离工作区的 `generation_request` 还原完整请求；缺省的观测字段不得冒充完整请求。当前按讲大纲高于派生指纹，恢复后仍保留同一大纲修订、计划讲数和已完成讲次。

提供方认证、额度或后备通道失败使用有界冷却电路，只在冷却窗内阻止重复请求；不得将一次失败固化为进程生命周期内的永久锁定。冷却后恢复同一任务，从最近合法检查点继续。

### 6.8 产品使用记录链

```text
稳定 Vue route / 写操作终态 / 分类客户端错误
-> 前端有界队列
-> /api/usage-events/batch
-> 事件与属性白名单
-> UsageEvent
-> 个人汇总、导出、删除与受保护聚合
```

`UsageEvent` 只回答产品怎样被使用，不回答学习者是否掌握或课程是否发布。请求正文、答案、Prompt、错误消息、堆栈、IP、User-Agent、Cookie 和设备指纹不得进入账本。

## 7. 外部、存储与安全边界

- 生产环境独立运行在拓途浙享服务器的 `/opt/lingzhi`，公开入口固定为 `https://tuotuzju.com/lingzhi/`。Caddy 只对 `/lingzhi/*` 去除路径前缀后转发到 `127.0.0.1:7862`；拓途主站、`/api`、`/code` 与其他服务保持原有路由和数据边界。
- 推送 `main` 后由 GitHub Actions 构建并校验发布包，再通过 SSH 激活 `lingzhi.service`。应用使用独立的 `lingzhi` 系统用户，版本目录、Python 环境和持久数据分别位于 `/opt/lingzhi/releases`、`/opt/lingzhi/.venv` 与 `/opt/lingzhi/state`；地址、账号、私钥、模型密钥和服务器 `.env` 只保存在私有配置或 Actions secrets，不进入 Git。
- 文本 AI 统一经过 `ai_base.py`，并由 `text_ai_provider_policy.py` 在创建网络客户端前检查：通用、评估和 PPT 文本角色只能使用私有登记 `a800-qwen` 的 `/v1` 端点与精确模型 ID `qwen3.8-27b`。`configure_zju_qwen_provider.py` 原子同步本地和生产配置并删除旧外部文本兜底；`probe_zju_qwen_runtime.py` 从真实运行环境验证通用、PPT 故事和 PPT 视觉角色。节点失败时保留现有可恢复失败，不切换到魔搭、DeepSeek 或其他文本提供方。
- 联网调用统一经过 `web_retrieval.py` 的 `SearchProvider`。默认本机 SearXNG 只映射回环地址；Exa 仅作显式兼容，不自动兜底。
- 联网只覆盖教师显式启用的课程资料调研、题库和普通 AI 回答。评分、作答诊断、学习者模型、课程结构演化以及 PPT 渲染不出站。
- 文件上传进入资料管线，浏览器生成 multipart boundary，后端最终校验类型、大小、所有权和用途。
- 用户代码只通过 `runner/` 隔离执行，主后端不直接 `exec` 用户代码。
- 本地 JSON、任务工作区和导出文件只是当前存储介质，不表示对象共享生命周期。
- 源码、用户数据、缓存、演示产物和发布包分开管理；Prompt 正文、密钥和模型推理不进入日志或 Git。
- `usage_events.json` 是运行数据并被 Git 忽略；全局分析只返回聚合，原始使用记录只能由所属身份导出或删除。

## 8. 兼容、降级与扩展

- 旧课程可以只读兼容，新的正式写入必须进入当前领域命令和当前 schema。
- 旧字段、旧 Store、旧路由和旧任务只有明确读取边界、迁移门和退出条件，不成为新能力依赖。
- 模型失败返回可恢复失败、局部明确降级或最后可用结果，不能虚构正式业务内容。
- 新增状态前先确认现有拥有者；新增接口前先确认能否扩展稳定领域投影。
- 新增 AI 能力必须说明输入依据、输出类型、持久化方式、用户控制、失败降级、恢复方式和旧入口退出计划。
- 新增前端界面先判断能否复用现有工作区、正式文档面、资料关系、任务和审阅能力；不能复用时说明新的稳定交互语义。
- 新增后端能力先判断能否由现有领域工具与注册表组合；不能组合时才增加新原子能力。
- 具体字段、状态机、接口和验收场景以当前正式 OpenSpec 为准。
