## 二、产品与数据边界

1. 课程生产、教师备课、学生学习、学习记录和个性化成长属于同一个产品闭环。修改局部功能时，要检查它会不会破坏整个闭环。

2. 教师备课和学生预习都是正式入口，必须能够直接使用，不能因为新增功能而被隐藏或绕远。

3. 教师课程的正式教案、讲义完整正文与修订身份只由教师仓储保存。`CourseDocument + ordered CourseBlock[]` 是阅读、预览、知识与 PPT 消费的内存投影，不跨写学生正文，也不在日常读取中反向恢复教师正文。历史学生课程保持原读取边界；旧教师正文引用只能通过预检、备份、按版本恢复的离线工具转换。

4. 教师课程链中的讲义是师生共用的标准课程材料，形态是可独立阅读的电子教材或教辅，覆盖当前课程范围内的定义、边界、公式与推导、例题、练习作业、参考解答、辨析和总结。教案负责教学目标、教学类型、教学环节、师生活动和时间安排；讲义依据当前、结构可用且来源未过期的教案展开完整知识内容，不要求教师口播、模拟师生回应或课堂调度。讲义链调整须保留数据和任务兼容；未完成学生旧生成链退场与正式正文合并前，不得宣称已经完成。

5. 页面内容稿是当前、结构可用且来源未过期的讲义到最终 PPT 之间唯一的逐页内容合同，保存页数、页型、可见文案、版式、构图和讲义来源。页面内容稿保留自身独立的确认门；最终 PPT 只通过模板与渲染器编译已确认页面内容稿，不得在渲染阶段重新写内容或引入知识；内部继续使用 `ppt_manuscript_v1` 兼容标识。

6. 学习过程中真实发生的事情由 `LearningEvent` 和正式领域仓库保存。`LearnerModel` 只是根据这些事实生成的解释，可以重新计算，不能反过来充当原始事实。

7. 后台任务使用 `task/job ID` 控制暂停、恢复、删除和状态同步。`course_id` 只说明任务属于哪门课程，不能用来代替任务 ID。

8. 不为同一件事建立第二套 Store、第二份课程正文、第二套任务系统，或者只为方便某个页面而设计一套平行接口。

9. AI 修改正式课程、学习记录或长期学习模型前，必须使用系统允许的正式命令，并提供修改范围、修改建议、影响说明、用户确认、执行回执和恢复方法。

10. 教学安排的正式产品语言分为课程级与讲次级：`学习目的 × 一级学科类型 × 课程教学类型 → 整课大纲、讲次课型分布与必备教学环节`，再由 `本讲目标 × 本讲课型 × 学科规则 × 课程约束 → 教学环节`。学习目的只分系统学习、项目实践、期末冲刺；学科类型只保留八个完整一级学科类别；课程教学类型只分理论课、实验课、实践课、研讨课、项目课、综合课；本讲课型只分七种课堂主弧。旧学科细分、教学原型、偏好、安排节奏和模块 ID 只作为内部条件、专业动作或兼容信息，不得重新成为页面分类、平行字段或 Prompt 自有规则。教学对象、模板和内容差异以 `docs/教学内容设计.md` 为准，组合与运行机制以 `docs/产品逻辑设计.md` 为准；其中尚未经过对应学科教师验证的学科设计包仍是待审设计，不能写成教师共识。

11. 新建教师课程的正式层级只有“课程 → 第 N 讲”。讲内主题、小节和教学环节只负责组织一讲内的连续教案与讲义，不得产生独立正式课程文件、确认状态或生成任务；历史章/节只兼容读取，不反向进入新课程写入。

12. 教师端正式术语以 `docs/教学内容设计.md` 的“教师端教学术语体系”为准。内部 ID、旧课程标题和兼容接口可以保留旧值，但菜单、标题、按钮、状态、生成内容和导出文件不得用“节点、模块、教学块、课程资产、页面合同、AI 候选、工作修订、结构化同源”等工程用语指代讲次、小节、教学环节、课程文件和修改建议；“知识模块”等已有明确课程专业含义的名称可以保留。历史内容由显示转换处理，不为改名建立第二套数据。

## 三、课程现场与工程约束

### 3.1 课程与学习数据

1. 正式修改课程版本必须保留来源、影响范围和幂等键。普通滚动、阅读位置与本地恢复只更新当前位置，不产生课程版本。
2. 历史学生课程中的一级章节只负责导航和刷新，只有具备正式正文和学习目标的二级内容才能产生学习事件；这套兼容层级不用于新建教师课程。缺少正式学科包时可以使用当前课程知识，不得伪造学科 ID。
3. 生成预览只读取任务、检查点和安全草稿，不写入学习进度、笔记、AI 修改或正式课程。发布成功后才切换到正式 `CourseDocument`。

### 3.2 生成、质量与恢复

1. 各产物按自己的生成与校验规则处理，不将同一套重试、修复或内容审核套给所有阶段。当前实现以[统一教师生产实现](docs/系统架构.md#统一教师生产实现)为准：讲义仅检查结构与来源绑定，不追加内容审核、模型改写或失败自动重跑；保留完成块与真实接收片段，由教师主动继续缺失块。
2. 不能靠删减完整教学内容提速，也不能用展示降级掩盖正文缺失。教师主动修改与优化入口保持可用；暂停、取消与来源冲突不得自动继续。
3. 正式质量报告分别检查正文、难度、资料、知识、题目和一致性，不能用平均总分掩盖答案矛盾或不可判断等严重问题。会改变通过状态或问题代码的规则必须更新合同版本；旧报告仅在合同版本和规则摘要一致时复用，可本地重算的检查不得要求再次调用模型。
4. 同一能力的自动、手动、恢复和兼容入口复用同一个底层实现及对应质量检查。恢复验证在隔离环境进行，不用教师正在使用的课程做故障实验；教师评价教学适用性。
5. 课程联网来源能力处于冻结保留状态。现有代码与历史数据只作兼容保留，不进入前端入口、后端检索或新课程生成链。未获得明确授权，不得重新启用、扩展或删除；重新启用前必须验证权限、来源审阅、失败恢复与生产行为。

### 3.3 运行中课程与任务保护

1. 操作课程前，核对当前仓库、分支、服务、页面路由和课程数据是否对应，并确认有无其他成员或 AI 对话正在使用、修改或观察该课程。
2. 已被其他任务占用的课程默认只读。未经明确授权接管或并行操作，不得启动生成、修改状态、暂停、取消、恢复或重试，也不得通过重启服务、替换进程或改写数据绕过占用。
3. 用户已启动且仍在运行的生成任务必须保留。未经明确授权，不得重启、替换、标记失败、改写状态或数据，也不得另起同目标任务影响它；诊断默认只读。
4. 长时间 AI 任务不能因关闭弹窗、切换视图或刷新页面丢失。浏览器缓存只保存最后一次成功现场；重新联网后按任务 ID 与服务端对账，不将缓存状态当成仍在运行的证据。一个任务资源由一个同步入口负责恢复，避免多组件重复恢复或覆盖状态。

## 四、教师端界面约束

1. 当前只建设桌面端；没有明确移动端需求时，不扩展移动端设计、适配或验收。
2. 保留现有中文和英文。改动可见文案时同步维护对应英文，通过现有 i18n 入口读取；修改词典后解析 JSON，检查原始 key、异常字符和溢出，不默认扩展全站国际化或其他语言。
3. 当前课程界面是视觉与交互基线，保留成熟的蓝紫色、渐变、状态表达、密度和节奏。新增界面扩展现有共享组件与设计变量，不另建一套设计系统；已有明确要求保留的区域不随其他改动重做。
4. 教师课程的 AI 审阅入口必须保留，流程为“提出要求 → 查看影响 → 审阅候选 → 应用或撤销”，继续使用正式候选、回执与恢复能力。
5. 教师端核心工作区面向年长教师保持可读性：正文、状态与常用操作字号原则上不低于 15px；讲次标题位置稳定、层级清楚，正文自然换行，不用截断或密集多栏换取整齐。重复统计与解释不通过灰色小字、徽标或装饰图标重新加入；区域用途明确时不增加“教学结构”“生成依据”等解释性标题。
6. 顶栏“备课工作台 / 课程文件”是同级分段切换的视觉参考：外层分组，选中项采用较小白底与轻阴影，宽度随内容收拢，内外圆角随高度递减。复用层级、密度与比例，不把固定像素套到普通按钮、标签页或导航。
7. `index.html` 和 SPA 回退页禁止缓存或在发布后重新验证；带内容哈希的静态资源可以长期缓存。涉及发布或资源缓存的改动，同时检查首页、子路由与静态资源响应头。

## 五、模型、验证与发布

### 5.1 文本模型

课程生成、AI 老师、内容修改、评估和 PPT 文本规划统一使用浙大自建 `qwen3.8-27b`。不得将魔搭、DeepSeek 或其他外部文本模型配置成主路由或故障兜底；模型不可用时进入现有失败恢复。赛事作品的魔搭展示链接与独立图像生成不属于这条文本模型约束。

团队成员从项目维护者取得授权端点与凭据，按 [README 的 AI 提供方配置](README.md#ai-提供方配置)写入本地 `.env`；部署使用目标环境或 GitHub Actions Secrets。发布验收须同时证明真实模型请求和生产进程内代表性文本角色使用指定模型。

### 5.2 验证入口

- 文档或规则改动：检查内容、结构、仓库内链接与 `git diff --check`。
- 后端改动：先运行相关测试；完整回归时分别运行 `pytest backend/tests` 和 `pytest tests`，避免同名 `conftest` 的收集冲突。
- 前端改动：按 [README 测试与检查](README.md#测试与检查)运行相关测试与构建；用户可见变化验证中文桌面端，文案改动同时检查对应英文。
- 课程生成、AI 和发布改动：按影响补充真实模型、浏览器与目标环境验证；分别说明验证结果，Mock、单元测试或本地页面不能替代生产证据。

### 5.3 发布隔离

拓途灵知入口为 `https://tuotuzju.com/lingzhi/`，代码、Python 环境和持久数据位于独立 `/opt/lingzhi` 边界内。发布使用 `lingzhi` 系统用户和 `lingzhi.service`，Caddy 将 `/lingzhi/*` 转发至 `127.0.0.1:7862`；不得改写拓途主站的业务数据、API 和运行目录，失败保留上一版本与持久数据。

拓途自动发布工作流为 [deploy-lingzhi.yml](../../.github/workflows/deploy-lingzhi.yml)。浙大使用联合 Compose，启智身份/API 变更与灵知消费者共同验证。提交、构建与自动激活的条件统一遵守[仓库规则](../../AGENTS.md)和[发布说明](../../deploy/README.md)。
