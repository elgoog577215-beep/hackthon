# 灵知项目协作规则

适用于 `apps/lingzhi`，补充[仓库规则](../../AGENTS.md)。供团队成员及 AI 工具共用，不依赖个人记忆或本机目录。下文代码路径相对于本应用，GitHub 工作流位于仓库根目录。

## 从哪里开始

- [README](README.md)：安装、配置、运行、测试与发布入口。
- [产品蓝图](docs/产品蓝图.md)：跨业务目标、共享边界及各功能设计入口。
- [产品状态](docs/产品状态.md)：实现与蓝图的差距、待确认范围及验收依据。
- [发布说明](../../deploy/README.md)：拓途与浙大的环境、数据和恢复边界。

先按业务阅读相关设计，再查看代码与状态。每项业务的内容、逻辑、交互、技术在同一份正文维护；共享机制只写在蓝图。设计不受当前实现限制，状态不变成任务排期；不自动建立事实、经验、规则提炼或归档流程。历史研究与验收不是当前需求。

## 项目不能破坏的边界

1. 教师备课与学生学习属于同一课程产品。教师完整教案、讲义只由教师仓储保存，阅读/预览/PPT 读取内存投影；不跨写另一份学生正文，不新增平行 Store、任务或公开接口。历史学习数据不因文档或教师链整理删除。
2. 新教师课程层级只有“课程 → 第 N 讲”；产品分类和教师术语见[教学内容模板](docs/教学内容模板.md)。讲义是师生共用教材式材料，不能退回口播稿；待审学科方案不冒充教师共识。
3. 大纲、教案、讲义与 PPT 各有准入。讲义仅检查结构和来源，禁止追加内容审核、模型改写或失败自动重跑；保留完成块与真实片段，教师主动继续缺失块。PPT 保留内容稿独立确认，最终渲染不得重新生成知识。
4. 产品内 AI 修改正式内容走精确范围、影响、用户决定、领域命令、回执与恢复；开发工具按用户对当前任务的授权执行，不把产品确认步骤套成重复开发审批。
5. `LearningEvent` 保存事实，`LearnerModel` 是可重算解释；教师预览不得写正式学习记录。正式学生服务恢复范围仍须依据确认的业务设计，不能因历史代码存在便启用。
6. 文本模型只用浙大自建 `qwen3.8-27b`，不配置外部文本兜底；密钥按 README 注入。课程联网来源冻结，未经明确授权不得启用、扩展或删除代码及历史数据。
7. 操作课程前核对仓库、分支、服务和课程对应关系及占用情况。其他任务使用中的课程默认只读；没有明确接管授权，不启动同目标任务、不改数据、不暂停/重试/取消，也不通过重启服务绕过保护。
8. 长任务以真实 task/job ID 控制，一个资源由一个同步入口对账。关闭页面只停止观察；来源冲突、暂停、取消及主动等待不能自动继续。故障与恢复实验使用隔离数据，不使用教师正在工作的课程。
9. UI 沿用当前蓝紫视觉、共享组件与连续阅读布局，具体交互见业务设计。当前仅桌面端；可见文案同步维护已有中英文，核心教师正文和常用操作原则上不低于 15px。

## 怎样验证与交付

- 文档改动检查链接、标题、内容边界及 `git diff --check`；更新受影响入口，删除被替代正文，不留平行版本。
- 后端按影响运行相关测试；完整回归分别运行 `pytest backend/tests` 和 `pytest tests`，避免同名 conftest 冲突。前端命令见 [README](README.md#测试与检查)，用户可见变化还要检查中文桌面及对应英文。
- 生成、模型、浏览器和生产验证分别报告，Mock 与单测不替代真实调用或线上证据。质量合同变化更新版本；本地可重算的检查不重复调用模型。
- 迁移前建立仓库外备份并验证恢复；正式数据转换通过显式工具，部署不顺带迁移课程。HTML/SPA 与哈希资源按不同缓存策略验证。
- 完成必要验证后只提交本任务改动，按仓库规则推送主分支。纯文档提交带 `[no deploy]`；不把推送或构建成功当成上线。拓途主站与灵知应用隔离，浙大身份/API 变更同时验证灵知消费者。
