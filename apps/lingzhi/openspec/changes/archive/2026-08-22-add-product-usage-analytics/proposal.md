## Why

灵知已经拥有正式学习事实 `LearningEvent`、持久任务状态和可选的模型调用遥测，
但还不能稳定回答“用户访问了哪些产品页面、哪些写操作成功或失败、一次会话实际使用
了哪些功能”。把这些信号继续塞进 `LearningEvent` 会污染学习模型；只靠服务日志又
缺少稳定事件合同、幂等、保留期、导出和删除能力。

## What Changes

- 新增独立的追加式 `UsageEvent` 账本，明确它只保存产品使用信号，不拥有学习事实。
- 建立严格白名单事件合同，覆盖会话开始、页面访问、API 写操作成功/失败和脱敏客户端错误。
- 前端统一采集路由访问与 Axios 写操作，不要求每个页面或按钮自行拼装埋点。
- 提供幂等批量接收、有限重试、保留期和容量上限，采集失败不得阻断正式业务。
- 提供当前用户自己的汇总、导出和硬删除，以及由环境密钥保护的全局聚合摘要。
- 聚合口径提供活跃用户、会话、页面访问、成功操作、失败操作、操作成功率、每日趋势和热点入口。

## Capabilities

### Added Capabilities

- `product-usage-analytics`: 自托管、隐私受限、可治理的产品使用记录和聚合能力。

## Impact

- 后端：新增 `product_usage.py` 和 `/api/usage-events` 路由，并接入主应用。
- 前端：新增统一 usage tracker，接入 router 与 HTTP 客户端。
- 数据：新增 `usage_events.json` 运行时文件；不得提交真实使用记录。
- 配置：支持采集开关、保留天数、容量上限和可选管理摘要密钥。
- 现有真源：`LearningEvent`、`LearningRecord`、`PracticeAttempt`、任务和生成遥测语义不变。
