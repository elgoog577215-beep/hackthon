# Application Error Feedback Specification

## Purpose

让全站异常同时具备稳定中文名称、可理解原因、安全技术详情和可追踪请求编号，并把课程级状态收敛为教师真实关心的备课两态。

## ADDED Requirements

### Requirement: 每个可见异常必须使用预设名称和归纳原因

系统 MUST 为每个用户可见异常提供预设的中文名称和归纳原因。名称 MUST 优先来自明确业务动作或稳定错误码；不得把异常类名、原始英文 `detail` 或 HTTP 状态码直接当成完整用户文案。

#### Scenario: 教案保存发生版本冲突

- **WHEN** 教师保存教案时后端返回 `course_document_conflict`
- **THEN** 页面 MUST 显示预设名称“教案保存失败”或“课程版本冲突”
- **AND** MUST 说明需要重新载入或核对最新版本

#### Scenario: 未分类接口返回 503

- **WHEN** 一个没有领域错误码的请求返回 503
- **THEN** 页面 MUST 根据请求接口域显示稳定中文错误名
- **AND** 原始服务反馈 MUST NOT 代替归纳原因

### Requirement: 每个可见异常必须提供可展开技术详情

错误反馈 MUST 提供默认折叠的技术详情，包含已知的错误码、请求编号、HTTP 状态、请求方法、相对 URL 和安全原始反馈。技术详情 MUST NOT 包含认证信息、Cookie、请求体、服务器绝对路径或完整堆栈。

#### Scenario: 教师展开错误详情

- **WHEN** 教师点击“查看技术详情”
- **THEN** 页面 MUST 显示本次错误的错误码、请求编号和请求现场
- **AND** 内容 MUST 可复制并保持换行

### Requirement: 普通错误和后台静默错误必须采用不同打扰策略

普通用户操作产生的 Axios 错误 MUST 进入全局错误反馈层。后台轮询、健康检查和自动恢复请求 MAY 静默，但所属局部页面在需要用户处理时 MUST 使用同一错误模型就地呈现。

#### Scenario: 后台轮询连续失败

- **WHEN** 静默后台轮询连续返回网络错误
- **THEN** 系统 MUST NOT 重复弹出全局错误卡
- **AND** 需要用户处理时 MUST 在任务所属区域显示一次结构化异常和恢复动作

### Requirement: 错误响应必须能够追到服务端日志

HTTP 响应 MUST 返回 `X-Request-Id`。未捕获异常 MUST 返回安全错误码、通用原因和请求编号，并将完整异常与同一请求编号写入服务端日志。

#### Scenario: 服务端出现未捕获异常

- **WHEN** 路由抛出未处理异常
- **THEN** 响应 MUST 包含 `internal_server_error` 和请求编号
- **AND** 浏览器 MUST NOT 收到完整堆栈或服务器绝对路径

### Requirement: 正式课程必须只投影备课两态

教师课程库、课程空间和教学日历中的正式课程状态 MUST 只显示 `正在备课` 或 `备课完成`。生成失败、版本冲突和质量阻断 MUST 作为独立异常显示，不得扩展课程状态词表。

#### Scenario: 课程生成任务失败

- **WHEN** 课程存在失败且可恢复的生成任务
- **THEN** 课程状态 MUST 保持“正在备课”
- **AND** 失败原因、技术详情和重试动作 MUST 在异常区域显示

### Requirement: 内容编辑器不得持续展示生命周期徽标

教案、讲稿和同类当前内容编辑器 MUST NOT 在标题旁持续显示“草稿、编辑中、待确认、已确认、AI 方案”等状态徽标。保存、候选和确认过程 MUST 由按钮忙碌态、候选差异和必要异常反馈表达。

#### Scenario: 教师正在编辑当前教案

- **WHEN** 教师进入编辑模式
- **THEN** 标题区域 MUST 保持课程内容名称和操作
- **AND** MUST NOT 新增“编辑中”“已确认”或其他重复生命周期徽标
