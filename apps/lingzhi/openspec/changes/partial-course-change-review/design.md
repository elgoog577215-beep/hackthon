# 能力合同

1. 扫描覆盖率不再作为整个页面的进入门。存在已完成影响项时允许先查看；每项标注可处理或等待原因。没有可用结果时保留原恢复页。
2. 部分应用必须显式选择已审阅操作。后端重新检查来源已扫描、局部修改范围和结构依赖；缺来源信息、未完成整项、多项共用写入范围未就绪、未解决的老师问题以及受未确认结构变化影响的项不得应用。未知依赖按等待处理。
3. 正文只按稳定块精确修改；教案/讲义按实际整讲写入范围检查，PPT与题库保留原来源约束。部分应用和补查操作互斥，查看旧结果不互斥。结构应用不在覆盖不足时放开。
4. 增加显式 rescan_incomplete_only 参数，并绑定旧方案 ID、原要求及原材料范围。补查先比对逐项来源修订：保留未变化且已完成的判断，只分析失败项和确实变化的项。课程树或老师要求变化时不假装沿用旧判断。
5. 新扫描先公布已保留数量，再开始网络调用；避免先显示0再逐个回放缓存。旧任务检查点缺失时，可由持久方案中完整覆盖记录与逐项判断恢复，不要求教师重新扫描整课。
6. 部分采用沿原回执保持幂等与撤销。后续补查生成同一正式变更体系内的接续方案，保留已应用方案和回执；已成功应用的源项不再次生成应用操作。失败项和未应用项仍可接续处理。
7. 本次只能证明部分工作可以前进，不把86项已检查称作86项可应用。当前实际方案提出全课重建及老师问题时，应显示这些具体依赖，不能删除依赖来强行通过。
8. 针对实际长代码请求的180秒超时，普通内容以1200字符、100字符重叠分片保留全文；超过6000字符且含代码围栏的内容预先按600字符分片，每批正文最多2400字符。最终单片仍超时时再有限拆小一次，保留成功检查点；错误来源编号或结构返回附本批次合法编号进行有限纠错。模型输入不重复序列化完整可编辑字段，不要求补全被切开的代码或生成整份实践项目。模型返回继续通过原结构与来源校验，任一片仍失败则整项保持未完成，不能以空结果或跳过内容冒充通过。
9. 从异常链识别 HTTP 连接失败和连接超时，将其归入服务不可用；沿既有恢复等待有限重试一次，仍不可用则保存未完成范围，不将传输故障拆成每条课程内容反复请求。
10. 分析期间只轮询原任务摘要，结束后再对账课程方案；提交回执不被背景读取覆盖。结果读取失败继续读取该结果，不启动新的模型分析。任务完成保留分片进度和 complete/incomplete 结果标记；任务结束不等于全课检查通过。
11. 结果页直接呈现补查提交、动态进度、结果载入及失败原因。列表默认折叠未就绪或长篇正文，保留展开后的完整 Markdown；等待项不当成用户排除项变灰。操作栏保持可见，不能生成的候选不提供无效重试按钮。
12. 旧方案大量提问可以通过用户显式提交一段统一要求替代，调用既有 confirmedInterpretation 流程重新分析全课；页面说明这与仅补查未完成内容不同，且不会直接改课。没有用户确认时仍保留原教师决策门。
