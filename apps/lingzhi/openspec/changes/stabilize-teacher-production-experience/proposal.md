## Why

教师课程生产已经具备持久任务、按讲资产、失败恢复和跨资产候选，但课程库、工作台与教学日历仍分别拼装生成状态，导致最新一次 `0/1` 重试能够覆盖整课 `15/16` 进度；部分持久化、跨进程和跨仓储崩溃边界也尚未形成统一发布门。现在需要把生成状态这个最难维护的横向问题收敛为一套服务端只读投影和一组可验证的持久化护栏，同时保持当前用户任务、最后可用资产和既有恢复能力不受影响。

## What Changes

- 新增唯一的 `course_production_state_v1` 服务端投影。它从 TaskManager、教师资产任务、PPT 检查点和正式资产可用性实时推导，不保存第二份状态；整课进度始终以当前全部讲次为分母，最新批次只作为 attempt 明细。
- 课程级继续只显示“备课中 / 备课完成”；资产级统一显示“未生成 / 生成中 / 可使用 / 生成失败”，暂停、来源过期、待核对和最近一次重生成失败作为辅助状态，不扩张主状态词表。
- 课程库、工作台、教学日历和课程文件逐步迁移为只消费同一投影。迁移期双读对账，活动任务继续由原所有者运行到终态；差异归零后删除前端独立推导和后端重复聚合分支。
- 失败入口返回稳定的阶段、讲次、教学块和任务身份；“处理问题”只导航、高亮并展开错误，不自动发起写请求。
- 教案和讲义的默认 UI **不再提供“只生成本讲”入口**，只保留“生成全部教案 / 生成全部讲义”；失败后同一按钮原位变为“重新生成”，继续复用批量接口并只恢复失败或缺失单元。单讲底层能力暂时保留给内部恢复和旧客户端兼容，验证无调用后再决定退场。
- 教案知识前置关系的相对顺序不再作为生成硬门；结构校验继续保护知识身份、引用和必填字段完整性。
- 大纲出现学时、来源或其他审阅问题时，区分“结构可用”和“待修正”。不擅自把既有非阻断审阅改成硬门；无最后可用资产且结构硬校验失败时才显示“生成失败”。
- 教学日历纳入讲义状态，按“大纲 → 教案 → 讲义 → PPT”显示四项准备度；可选 AI 推荐资料待核对时保留资产可用性，必需来源损坏、冲突或过期才阻断。
- 继续现有依赖索引、共享重建执行器和课程操作组，补齐教案/讲义块、V6 页面和题库最小合法单元的定向重建，以及跨讲结构操作的部分接受、引用迁移、原子应用和撤销；不创建第二套重建器。
- 在现有全课 AI `partial` 回执和失败项重试之上增加逐操作执行日志，关闭“资产已提交但总回执尚未保存”时的崩溃窗口。
- 历史章/节课程只允许非破坏式复制升级：旧课程保持只读且校验和不变，新课程获得新 ID、讲次映射和迁移报告；不原地迁移、不导入旧教案历史。
- 加固发布与运行时：恢复测试和 Ruff 门，生命周期边界严格持久化，通用 JSON 原子更新，任务索引 last-good 与 degraded 模式，数据目录单领导者锁，快速 readiness、备份校验、低基数指标和隔离故障演练。
- 明确不改：工作区列宽和双侧栏、右侧资料栏常驻、长大纲常驻导航、前端包体、当前蓝紫视觉与装饰性样式、大纲完整度字号和紧凑图标尺寸。经后续讨论确认，失败信息只做职责分层：顶部保留课程级数量摘要，正文对象旁保留局部失败状态与原位恢复，右栏保留完整原因和恢复说明，不让同一条具体错误在三处重复。

## Capabilities

### New Capabilities

- `teacher-production-state`: 教师课程、资产、讲次、任务和错误定位的唯一只读生产状态投影，以及课程库、工作台、日历和文件空间的一致消费合同。
- `teacher-change-execution`: 全课 AI 修改、定向重建和跨讲结构操作的逐操作持久回执、部分续办、对账与补偿合同。
- `runtime-state-durability`: 任务索引、通用 JSON 账本、单实例调度、健康检查、备份恢复、指标和故障演练的运行时稳定合同。
- `teacher-course-upgrade`: 历史章/节课程非破坏式复制为新讲次式课程的身份、映射、报告和失败清理合同。

### Modified Capabilities

- `ai-generation-control`: 教案与讲义的默认可见入口从“生成全部 + 只生成本讲”收敛为“生成全部 / 重新生成”，并由统一投影决定动作和恢复范围。
- `application-error-feedback`: 资产级异常增加稳定定位身份、完整可读摘要和不触发自动重试的深链合同，同时保持课程级备课两态。
- `product-usage-analytics`: 使用量账本的幂等读改写升级为跨进程安全的原子更新，采集失败仍不得阻断正式业务。

## Impact

- 前端：`TeacherCourseLibraryView`、`TeacherCourseWorkbench`、`CourseOutlineReview`、`TeacherTeachingCalendarView`、`TeacherCourseSpaceView`、共享 readiness/状态组件、i18n 和对应 Vitest。
- 后端：课程列表与教师课程投影、TaskManager、教师资产仓库、V6 进度、`Storage` 通用数据入口、课程生长执行器、健康检查、诊断指标和对应 pytest。
- 发布：开发依赖、完整测试/lint 前置 job、systemd 单实例约束、活动任务发布保护、备份 manifest 与恢复验证。
- 兼容：新旧状态字段先并行返回并记录差异；不迁移、不取消、不重启正在运行的用户任务；最后可用资产在重生成失败时继续可读。
- 现有 changes：本 change 收敛 `split-teacher-lesson-authoring-v1`、`unify-course-authoring-learning-workspace`、`build-structured-adaptive-course-ai` 和 `upgrade-slide-deck-v6` 中与状态、恢复和定向重建有关的未完成项，实施时同步核对并标记原任务，避免平行实现。

## 教师反馈补充范围（2026-09-05）

用户已确认全局修改与失败恢复审计方案：保留“预览学生所见”，暂缓 PPT 功能改造；修复全文替换、讲次结构意图、候选持久化与版本关联、放弃/重试/撤销、跨课程响应归属和真实结果展示。全局修改直达现有中心，完整差异与历史可读；失败恢复区分原输入续办与补充要求后新尝试，课程库只显示课程两态。沿用本 change 的状态、领域候选、共享重建与执行回执，不增加平行任务或数据真源。

用户进一步确认：完整大纲在交付前自动审阅、合并修正可自动处理的问题并复审。先修复轻量方案空值覆盖详情的合并错误；学时依据确认输入确定性校正，内容优化复用现有 AI 操作和校验，最多两轮。已有教师内容不静默覆盖，来源无依据不得伪造，失败保留可用草稿和剩余建议。

用户随后将同一要求扩展到教案与讲义：纯 AI 生成应在交付前自行完成审阅、修正与复验，不能把可自动处理的缺陷交给教师逐条修改。教案复用当前优化器修正最终检查问题；讲义既处理单块表达建议，也处理汇编后的跨块重复与衔接。硬校验仍失败时不写正式修订，已有可用版本不受影响。

## 可用性与自动恢复修正（2026-09-06）

教案和讲义的失败条件收敛为实际不可用：缺少必要正文、结构或来源错位、占位内容及无法可靠渲染的损坏语法。辅助教学字段、表达风格、按课时推算篇幅和局部复述作为建议，后台受限改善后仍可交付。临时模型异常或结构化输出错误在原任务内有限重试，重试记录持久化，成功检查点保留；恢复期间不产生终态失败或要求教师点击。暂停、取消、来源冲突及不可重试配置错误不自动继续。失败恢复测试由开发在隔离环境完成，教师评价教学适用性。
