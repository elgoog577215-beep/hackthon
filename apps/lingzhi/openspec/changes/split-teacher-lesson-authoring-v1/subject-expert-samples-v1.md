# 学科专家教学样例与教师审阅方案 v1

## 1. 文件定位

本文是 `split-teacher-lesson-authoring-v1` 的首批学科评审证据，用三节具体课程检查灵知现有教学语义是否符合真实教师备课方式。它不新增产品分类、不建立第二套学科模板，也不代表八种学科已经完成教师验证。

本轮选择三个差异明显的场景：

1. 高等数学概念课：导数概念——从平均变化率到瞬时变化率。
2. 大学物理实验课：验证牛顿第二定律——从测量数据形成有边界的结论。
3. 人工智能项目课：构建并评估一个课程问答助手。

三个样例都使用现有两级合同：

```text
学习目的 × 一级学科类型 × 课程教学类型
→ 本讲目标 × 本讲课型 × 学科标准包 × 课堂条件
→ 教学块：教师动作、学生行动、学习证据、检查、反馈与调整
```

教师不是从空白 Prompt 开始，也不把决定权交给系统。老师先提供原大纲、教案、PPT、课程条件和本讲意图；灵知把材料与现有课程资产组织为候选教学结构，说明推荐理由。老师审阅、要求修改并明确采用候选后，新当前修订再进入教案、讲稿和 PPT。

## 2. 三节课共同遵守的审阅标准

一节课不能只看内容是否正确，还要同时通过以下检查：

1. **目标可观察**：目标写成学生完成本讲后能够解释、推导、实验、实现或判断的表现，不写“了解、熟悉、掌握”而没有结果。
2. **学科方法真实**：数学靠定义、条件和推理成立；物理靠模型、测量与证据成立；AI 工程靠可运行实现、评估和取舍成立。
3. **教师能够执行**：每个教学块都说明老师做什么、学生做什么、使用什么材料、需要多少时间。
4. **现场能够判断**：每个关键目标都产生学生作品、解释、计算、数据、运行结果或修订记录，不能只以“讲完了”作为完成。
5. **反馈改变后续教学**：达到、部分达到、未达到三种情况分别对应继续、补支架或回到前置内容，检查结果必须影响下一步。
6. **支架最终撤除**：示范和提示只用于帮助学生跨过当前障碍，最后必须出现独立完成或条件变化后的迁移任务。
7. **来源与安全有边界**：不伪造定理、实验数据、模型效果或资料来源；实验安全、隐私、数据授权和模型局限必须进入正式教学判断。

## 3. 样例一：高等数学概念课

### 3.1 本讲合同

| 项目 | 设定 |
| --- | --- |
| 课程主题 | 高等数学：导数概念——从平均变化率到瞬时变化率 |
| 学习者 | 已学习函数、极限和直线斜率的大学一年级学生 |
| 时长与环境 | 90 分钟，普通教室，可投影，个人思考与同伴讨论结合 |
| 学习目的 | `systematic`（系统学习） |
| 一级学科 | `math_formal`（数学与形式科学） |
| 学科画像 | `higher_mathematics`（高等数学与分析） |
| 课程教学类型 | `theory`（理论课） |
| 本讲课型 | `theory_practice`（讲练结合） |
| 本讲目标 | 学生能够从平均变化率的极限建立导数定义，说明定义成立的条件，在图像、符号和运动情境之间转换，并独立判断一个函数在给定点是否可导。 |
| 最终证据 | 一份包含极限表达、几何解释、条件判断和自检过程的独立解答。 |

### 3.2 教学块

| 时间 / 角色 | 当前教学任务 | 教师动作 | 学生行动 | 可检查证据 | 根据证据怎样调整 |
| --- | --- | --- | --- | --- | --- |
| 8 分钟 / `orientation` | 从“某一瞬间的速度是多少”建立真实问题 | 展示一段位置—时间数据，只问怎样得到某一时刻的速度，不提前给出导数公式 | 先独立写出办法，再与同伴比较“很短时间内平均速度”和“瞬时速度”的差别 | 初始解释中是否出现区间、逼近和时刻三个对象 | 已能区分区间与时刻：进入极限；只会套速度公式：补一个变速反例；把瞬时速度当作直接测量值：追问测量区间缩短时发生什么 |
| 14 分钟 / `concept` | 在图像、语言和符号之间建立同一个变化过程 | 用割线斜率逐步逼近切线斜率，分别标出自变量增量、函数增量和比值 | 根据动态图或分步图说出每个量的含义，把口头描述写成差商 | 能否把图像中的割线变化准确写成差商，并解释分子、分母 | 三种表征一致：撤掉图示；符号会写但说不清：回到图像标注；混淆函数值和增量：增加数值表逐项对应 |
| 18 分钟 / `reasoning` | 从变化过程建立正式导数定义 | 明确对象、极限过程和存在条件，逐步写出定义；特别说明“令增量等于零”不成立 | 补全推导中被留空的关键步骤，并逐句说明等号或极限转换的依据 | 一条条件完整的定义链，能够说明为何不能直接令分母为零 | 依据完整：进入例题；跳步但结论正确：要求补依据；把代入零当极限：用同一表达比较“趋近”和“取值” |
| 12 分钟 / `example` | 示范如何判断并计算一个点的导数 | 以简单二次函数为例，示范审题、列差商、化简、取极限、用图像核验 | 计算前预测导数正负和大致大小，完成关键计算并对照图像 | 带有预测、计算、结果和图像核验的完整示例 | 预测与结果一致：减少支架；计算正确但无法解释：要求回指图像；代数错误：只修复导致失败的前置运算 |
| 10 分钟 / `counterexample` | 暴露“连续就一定可导”等可信误解 | 给出绝对值函数在零点的图像和左右差商，不先公布结论 | 判断是否可导，找出左右逼近不一致的位置，并修正原命题 | 反例、失效条件和修正后的判断 | 能指出左右极限：进入变式；只凭尖点下结论：要求写证据；认为连续等于可导：对照“可导推出连续”的单向关系 |
| 15 分钟 / `application` | 在不同表征中迁移导数判断 | 提供表格、分段函数和运动情境三选二任务，只给成功标准 | 选择两题独立求解，并说明选择当前方法的理由 | 两种表征下的结果、方法理由和条件说明 | 两题均成立：增加一个参数变化题；一题成立：同伴互评后重做；两题均失败：回到差商对象和极限条件的最小任务 |
| 7 分钟 / `checkpoint` | 取得本讲目标的独立证据 | 给出新的函数与指定点，禁止讨论，要求同时回答“是否可导、为什么” | 独立完成极限表达、条件判断和一句几何解释 | 退出题，按定义、条件、推理、表征四项快速判定 | 四项完整：进入总结；缺一项：标记具体缺口并给相邻变式；定义层失败：完成必要补救前不进入更复杂求导法则 |
| 6 分钟 / `feedback` | 让学生根据证据修正一次 | 展示三种匿名典型答案，指出成功标准而不直接代改 | 对照标准修改自己的退出题，圈出修改位置并写原因 | 修改前后差异和错误原因 | 能自主修正：记录为达成；需提示后修正：下一讲保留短复验；仍不能修正：进入前置极限概念补救 |

### 3.3 这节数学课不能退化成什么

- 用速度故事讲出直觉后直接给求导公式，没有正式定义和成立条件。
- 教师连续演算多个例题，学生没有预测、解释、独立判断和错误修正。
- 用函数图像代替形式推理，或用一次算对代替对定义边界的理解。
- 课堂检查只有答案，没有推理过程，因此无法判断学生卡在概念、极限还是代数运算。

## 4. 样例二：大学物理实验课

### 4.1 本讲合同

| 项目 | 设定 |
| --- | --- |
| 课程主题 | 大学物理实验：验证牛顿第二定律 |
| 学习者 | 已学习受力分析、速度与加速度概念的大学一年级学生 |
| 时长与环境 | 90 分钟，4 人一组，小车、导轨、力与位移传感器或等效设备 |
| 学习目的 | `systematic`（系统学习） |
| 一级学科 | `natural_science`（自然科学） |
| 学科画像 | `physics`（物理学） |
| 内部兼容画像 | `science_physical_modeling` 只作为旧原型选择条件，不成为教师字段 |
| 课程教学类型 | `laboratory`（实验课） |
| 本讲课型 | `experiment_inquiry`（实验探究） |
| 本讲目标 | 学生能够把物理问题转化为可测变量与实验方案，使用数据判断合力、质量和加速度的关系，分析主要不确定性，并把结论限制在证据支持的范围内。 |
| 最终证据 | 可追溯的实验记录、数据图、模型拟合、误差说明和有边界的证据结论。 |

### 4.2 教学块

| 时间 / 角色 | 当前教学任务 | 教师动作 | 学生行动 | 可检查证据 | 根据证据怎样调整 |
| --- | --- | --- | --- | --- | --- |
| 7 分钟 / `orientation` | 从相同推力下不同小车运动差异提出可检验问题 | 演示或播放两个条件不同的运动现象，只要求描述观察，不接受直接背定律作为解释 | 分两栏记录“看见或测到什么”和“可能怎样解释” | 观察与解释是否分开，问题能否通过测量回答 | 已分开：形成假设；把定律当观察：要求改写为可见量；问题不可测：帮助收窄变量 |
| 4 分钟 / `objective` | 确认成果与判定标准 | 给出本讲必须交付的记录、图表、误差和结论标准，说明安全要求 | 用小组自己的话复述“什么结果才算完成”，分配记录、操作、检查和汇报责任 | 角色分工与成功标准复述 | 标准清楚：进入建模；只分工不懂标准：让记录者先写出验收清单 |
| 9 分钟 / `concept` | 把物理模型变成可测变量 | 引导学生从受力图和运动模型识别合力、质量、加速度，追问哪些量保持不变 | 画受力图，定义自变量、因变量、控制变量和单位 | 受力图、变量表、单位与预期关系 | 变量关系正确：设计实验；漏掉摩擦或系统质量：补极限情况和量纲检查；把相关量混作控制量：重写比较方案 |
| 12 分钟 / `activity` | 设计最小可执行实验 | 审阅方案，只用安全、变量控制、测量范围和重复次数四项追问 | 写操作步骤、数据表、重复测量次数、异常标记和安全检查 | 一页实验方案，另一组能够照此执行 | 可复现：批准实施；缺少对照或重复：补最小数据组；存在安全风险或设备超范围：停止并改方案 |
| 24 分钟 / `activity` | 实施测量并保留原始证据 | 巡视但不替学生修数据；记录常见设备、操作和协作问题 | 按方案测量，保留原始数据，标记异常、重测原因和设备设置 | 原始记录、时间或批次、单位、异常标记和操作日志 | 数据可追溯：进入分析；只有整理后数据：补回原始记录；异常被删除：恢复并解释；设备异常：使用备用数据但明确来源 |
| 14 分钟 / `reasoning` | 用数据检验模型而不是寻找“正确答案” | 示范一次图轴、拟合与残差读取，追问斜率或截距的物理含义 | 作图、拟合、比较模型预测与数据，分析主要误差和不确定性 | 数据图、拟合关系、残差或偏差、量纲核验 | 模型与数据相符：说明支持强度；局部不符：检查范围和系统误差；无法判断：增加数据或降低结论强度 |
| 6 分钟 / `counterexample` | 比较替代解释和失效条件 | 提供“摩擦不可忽略”或“传感器零漂”的数据特征，要求比较解释 | 判断现有数据能否区分替代解释，提出一项补充测量 | 替代解释、区分证据和补充方案 | 能区分：修订结论；只罗列误差名词：要求指出它怎样改变图像；无法区分：明确写成待验证 |
| 5 分钟 / `checkpoint` | 独立检查证据推理 | 给每名学生一张新数据图，要求写出观察、解释和结论边界 | 独立写三句话并标明哪一句来自数据、哪一句来自模型 | 个人证据卡 | 三者清楚：进入组内反馈；观察推断混写：用颜色重新标注；结论过强：改成数据真正支持的范围 |
| 5 分钟 / `feedback` | 用共同标准修订小组结论 | 按“数据是否支持、误差是否影响判断、结论是否越界”三项给反馈 | 根据反馈修改结论，保留修改前后版本 | 修订差异与修改理由 | 能据证据修订：达成；只改措辞不改判断：追问证据；核心数据无效：安排补测或明确本次不能验证 |
| 4 分钟 / `transfer` | 把模型用于新条件 | 提问“若质量增大但推力装置不变，当前方案和预期图像要怎样改” | 个人写出预测、需控制的量和验证办法 | 新条件下的预测与实验调整 | 预测和方案一致：完成；预测对但方案错：补变量控制；仍靠背公式：下一讲先复验模型—数据关系 |

### 4.3 这节物理课不能退化成什么

- 先公布标准结论，再让学生按固定步骤得到接近标准值的数据，形成“表演式探究”。
- 只交一张整洁数据表，没有原始记录、异常、设备条件和重测理由。
- 把拟合优度高直接写成理论被证明，或把误差分析写成几个术语的罗列。
- 把观察、模型推断和最终结论混在一句话里，无法判断证据实际支持到哪里。

## 5. 样例三：人工智能项目课

### 5.1 本讲合同

| 项目 | 设定 |
| --- | --- |
| 课程主题 | 人工智能应用：构建并评估一个课程问答助手 |
| 学习者 | 会使用 Python 和调用基础模型接口，但尚未系统学习检索增强生成与评估 |
| 时长与环境 | 120 分钟，2—3 人一组，本地开发环境，使用去标识化课程材料和受控模型接口 |
| 学习目的 | `project`（项目实战） |
| 一级学科 | `programming_engineering`（编程与工程技术） |
| 学科画像 | `data_ai`（数据科学与人工智能） |
| 内部兼容画像 | `engineering_data_ai` 只用于旧原型和模块选择，不成为教师字段 |
| 课程教学类型 | `project`（项目课） |
| 本讲课型 | `project_workshop`（项目工作坊） |
| 本讲目标 | 学生能够围绕明确用户任务建立最小可运行问答助手，设计包含普通、边界和不可回答问题的评估集，比较基线与改进结果，定位失败原因，并说明数据、隐私和模型适用边界。 |
| 最终证据 | 可运行增量、版本与环境说明、评估集、基线对照、失败记录、修订结果和项目决策说明。 |

### 5.2 教学块

| 时间 / 角色 | 当前教学任务 | 教师动作 | 学生行动 | 可检查证据 | 根据证据怎样调整 |
| --- | --- | --- | --- | --- | --- |
| 8 分钟 / `orientation` | 从真实用户失败进入项目，而不是从工具功能进入 | 展示助手对课程规则答错并伪造出处的案例，追问谁会因此作出错误行动 | 写出用户、任务、错误后果和“系统应拒答”的情形 | 一条包含用户、任务、风险和边界的问题定义 | 问题具体：进入验收；只写“做聊天机器人”：要求补用户行动和失败代价；超出课堂范围：缩小成果 |
| 7 分钟 / `objective` | 冻结本讲里程碑和验收标准 | 给出四个硬标准：可运行、有基线、有评估、有失败边界；说明不得上传真实个人数据或密钥 | 选择项目范围，复述验收项，确认数据授权与小组分工 | 项目卡、验收清单、数据来源与责任人 | 四项明确：开始基线；缺数据授权：换用教师提供材料；环境不可用：切换本地样例但保留同一验收标准 |
| 12 分钟 / `application` | 先建立不使用检索的基线 | 提供统一接口与五个初始问题，不解释改进方案 | 运行基线，保存输入、输出、版本、耗时和人工判断 | 可复现基线记录，至少包含一个成功和一个失败 | 基线完整：开始设计；只截图成功例：补失败例；无法复现：先修环境与版本，不进入新功能 |
| 18 分钟 / `activity` | 设计资料处理、引用和拒答规则 | 引导区分课程资料、用户问题、检索结果和模型回答，追问无证据时应做什么 | 检查材料，设计最小切分与检索方案，写出处引用和拒答规则 | 数据清单、处理规则、流程图或接口契约、三类测试问题 | 规则可执行：开始实现；切分只凭固定长度且忽略结构：增加标题或段落边界；没有拒答：补不可回答样本 |
| 30 分钟 / `activity` | 构建最小可运行增量 | 只在环境、接口和调试方法上提供支架，不直接代写完整代码；要求每次改动都能运行 | 实现加载、检索、回答与引用；每完成一段运行测试并记录错误 | 代码或流程、运行命令、一次成功结果、故障与修复记录 | 可运行且可解释：进入评估；能运行但说不清：逐步追踪一次请求；不能运行：缩到最小链路并保留失败复现 |
| 15 分钟 / `checkpoint` | 用事先定义的评估集比较基线与当前版本 | 提供结果表结构，要求分开记录检索命中、回答正确、引用支持和应拒答表现 | 运行普通、边界、不可回答问题，比较两版并标记人工判定依据 | 同一评估集上的基线与改进对照、指标和样例证据 | 改进稳定：进入失败分析；只在部分题提高：按错误类型拆分；评估题被调参过程使用：标记泄漏并更换保留题 |
| 12 分钟 / `feedback` | 用失败案例驱动一次修订 | 选择全班常见的检索错误、证据不支持或幻觉案例，示范定位层次 | 选择一个失败，判断来自数据、检索、提示、模型还是评估，并完成一轮修订与回归 | 失败复现、原因假设、改动、回归结果 | 修复且无回归：保留；只改善展示案例：扩大测试；原因不确定：保留多种假设，不伪造成已定位 |
| 10 分钟 / `reasoning` | 作出安全与工程取舍 | 追问成本、延迟、隐私、资料更新和人工复核，要求选择而非罗列 | 写一段上线边界：哪些任务可自动回答、哪些需引用、拒答或教师确认 | 有条件、有代价的项目决策说明 | 边界明确：准备展示；只有原则口号：绑定一个具体失败；涉及真实个人数据或密钥：立即停止并清理输入路径 |
| 8 分钟 / `transfer` | 展示、互评并确定下一次迭代 | 用统一量规组织交叉测试，不按界面好看评分 | 另一组用新问题测试；本组说明一个关键选择，记录问题并确定下一里程碑 | 新问题表现、同伴评审、修订优先级和下一步 | 新问题仍稳定：提高场景难度；暴露关键失败：进入下一里程碑首项；无法复现：先补环境和运行说明 |

### 5.3 这节 AI 课不能退化成什么

- 只介绍大模型、向量数据库和 RAG 概念，没有可运行成果和失败证据。
- 学生照抄教师代码得到一次成功演示，却不能解释输入怎样经过系统，也不能独立调试。
- 用几个精心选择的问题展示效果，没有固定评估集、基线、边界样本和回归检查。
- 把模型回答流畅当成正确，把“加了检索”当成有依据，忽略出处、泄漏、隐私、幻觉和人工确认。

## 6. 对照现有灵知实现后的判断

### 6.1 已经具备的基础

| 现有对象 | 当前已经能表达什么 | 本轮结论 |
| --- | --- | --- |
| `subject_standard_pack_v1` | 八种一级学科的认识方式、专业动作、典型产物、证据、误区、来源、安全、质量规则和教学块配方 | 继续作为唯一学科标准真源，不新增“数学模板、物理模板、AI 模板”平行注册表 |
| `teaching_semantics_v3` | 三种学习目的、六种课程教学类型、七种本讲课型、课堂条件和统一教学块字段 | 分类层已经够用，下一步重点不是加层级，而是提高具体课堂内容和反馈分支质量 |
| `teacher_lesson_arrangement_v1` | 把内部学科画像与旧模块投影为教师可调整的课型和有序教学块 | 继续承担适配，不允许页面或 Prompt 自行解释一套教学规则 |
| 教案、讲义、PPT 修订链 | 以当前、结构可用且来源未过期的修订作为下游来源；AI 候选需明确采用，PPT 页面内容稿保留确认，大纲来源变化经影响判断后才传播过期状态 | 学科样例最终应约束同一修订链，不生成三份彼此无关的文件 |
| 现有聚焦测试 | 已覆盖标准包解析、字段独立性、课型推荐、教学块补全和固定跨学科样本 | 证明编译器结构成立，但不能代替真实教师对整节课的判断 |

### 6.2 还没有做好的部分

| 优先级 | 缺口 | 在三个样例中的表现 | 应回到现有哪个对象处理 |
| --- | --- | --- | --- |
| P0 | 学科规则是“动作清单”，还没有稳定变成教师认可的一整节课 | 单个教学块可能正确，但块之间未必形成从问题到独立表现的完整进程 | `subject_standard_pack_v1` 的块配方、`teaching_semantics_v3` 的课型弧和现有编排器；用评测样例补证据，不建新链 |
| P0 | 检查方法和三档反馈仍以通用默认句为主 | 系统会说“达到就继续、未达到就补救”，但未必知道数学该补哪一步、物理该补哪种证据、AI 应回归哪类失败 | `compile_teaching_block_contract` 的学科配方与确定性质量检查 |
| P0 | 缺少真实教师评审 | 当前测试证明字段和 Prompt 进入同一链，不能证明老师愿意这样教、顺序合理或时长可实施 | 本文第 7 节审阅表；结果进入 11.3、11.4a、11.8a，不直接改正式合同 |
| P1 | 数学的“直观—定义—推理—反例—独立判断”还不是完整样例门 | 现有规则分别提到表征、定义、推理和反例，但生成后可能只剩公式讲解与例题 | `math_formal` / `higher_mathematics` 配方和数学固定评测样本 |
| P1 | 物理实验的原始记录、不确定性和替代解释不够具体 | 现有自然科学标准已有变量、误差和结论边界，但整讲仍可能退化为验证预设结论 | `natural_science` / `physics` 配方、实验探究课型和物理固定评测样本 |
| P1 | AI 应用课缺少基线、评估集、泄漏、失败归因和人工确认的完整顺序 | 现有 `data_ai` 已有基线、评估、误差和安全边界，但项目课可能只生成“实现—展示” | `programming_engineering` / `data_ai` 配方、项目工作坊课型和 AI 固定评测样本 |
| P1 | 教师端还没有完整显示推荐依据、最终教学块和修改影响 | 老师无法判断系统为什么这样排、要求修改后会影响教案、讲稿还是 PPT | OpenSpec 任务 11.5a；继续通过现有 AI 候选和影响审阅，不恢复逐块手工编辑器 |

核心判断是：当前问题不在“四层框架缺了一层”，而在已有领域定义还没有经过真实教师验证，产品机制还没有把学科证据真正用于下一步调整，交互还没有把推荐依据与影响讲清，技术上仍有一部分通用默认值和旧模块需要收进统一编译入口。

## 7. 教师审阅表

每位学科教师只审本学科样例，不要求理解系统字段。审阅时保留原样例，在旁边记录意见，不直接覆盖证据。

### 7.1 逐块审阅

每个教学块记录：

| 审阅项 | 可选结果 | 必填说明 |
| --- | --- | --- |
| 这一块是否真实需要 | 保留 / 条件保留 / 合并 / 删除 | 什么情况下需要，为什么 |
| 所在顺序是否合理 | 原位 / 前移 / 后移 | 应放到哪一块前后 |
| 时间是否可实施 | 足够 / 偏长 / 偏短 | 45、90 或 120 分钟时怎样调整 |
| 教师动作是否像真实课堂 | 可直接执行 / 需改写 / 不成立 | 教师实际会怎样说或怎样组织 |
| 学生行动是否会真实发生 | 会 / 需要支架 / 不会 | 学生可能怎样应对，常见卡点是什么 |
| 证据能否判断目标 | 能 / 只能判断一部分 / 不能 | 还要看什么作品、过程或回答 |
| 三档调整是否有效 | 有效 / 太泛 / 不可实施 | 达到、部分达到、未达到时各自怎样处理 |

### 7.2 整讲审阅

请教师回答十个问题：

1. 如果明天就上这节课，您会不会采用这个顺序？第一处会改哪里？
2. 哪些环节是本学科不可删除的，哪些只在特定学生、设备或时长下需要？
3. 学生最终交出的东西，是否足以证明本讲目标达到？还缺什么证据？
4. 这节课最容易在哪一步变成“老师讲完了，但学生没有学会”？
5. 系统列出的常见错误是否真实？还有哪些高频错误没有覆盖？
6. 达到、部分达到、未达到三种学生表现，您实际上会怎样调整下一步？
7. 哪些内容可以由 AI 根据老师材料先生成，哪些必须由老师判断或确认？
8. 老师通常会带着哪些已有材料进入：大纲、旧教案、PPT、题目、数据、代码还是其他材料？
9. 老师提出一次修改时，哪些下游材料必须一起更新，哪些必须保留原样？
10. 哪一种能力能让您持续使用灵知，而不是回到通用大模型？请给一个具体工作场景。

### 7.3 结论分级

- **可进入正式标准**：两名以上同学科教师独立审阅，关键块、顺序、证据和反馈没有实质冲突；差异能够由课堂条件解释。
- **继续作为候选**：教师认可方向，但时长、活动、证据或反馈仍有明显修改；只进入评测样本，不提升为硬规则。
- **退回重做**：学科方法不成立、课堂不可实施、学生没有可观察表现，或系统建议会误导教师。

## 8. 完整效果与验收门

| 必须成立的能力 | 领域定义 | 产品机制 | 交互设计 | 技术架构 | 完成标准 |
| --- | --- | --- | --- | --- | --- |
| 八类学科都能形成专业教学 | 每类学科有自己的专业动作、证据、误区与安全边界 | 同一课型在不同学科中产生不同检查与反馈预案 | 老师看到自然的学科教学内容，不需要选择内部细分 | 只扩展现有标准包与统一编译器，不新增学科专用链路 | 八类学科代表样本均能形成不同且可检查的教学块 |
| 老师带着已有材料共同备课 | 原文件、正式资产和候选修订边界清楚 | 主来源优先，AI 只补缺、解释和提出候选 | 资料选择始终作用于当前大纲、讲次或 PPT | 复用现有资料关系与正式修订真源 | 原文件不被覆盖，来源与生成结果可追溯 |
| 修改能够联动但不失控 | 大纲、教案、讲稿和 PPT 各有唯一真源 | 上游更新只标记下游过期，保留最后可用版本 | 老师看得到影响对象并决定是否更新 | 复用现有修订图、候选和 `CourseEvolutionPlan` | 修改不会静默覆盖下游，也不会产生平行文件真源 |
| 教师能理解系统建议 | 课程合同、本讲课型和教学块职责稳定 | 推荐依据、最终块和修改影响来自同一编译结果 | 当前讲直接显示课型、理由、块内容和影响 | 完成 OpenSpec 11.5a，不恢复逐块手工编辑器 | 老师无需阅读系统字段即可确认或提出修改 |
| 质量能够被持续验证 | 三个深度样例只作压力测试，正式范围覆盖八类学科 | 生成、修改、恢复和下游影响都有固定样本 | 关键空、错、旧和过期状态有明确反馈 | 建立 11.8a 代表性组合矩阵与聚焦测试 | 结构测试、真实模型结果和教师结论分开记录 |
| 产品始终只做备课 | 课堂活动是教案内容，不是新的产品对象 | 不采集真实课堂表现，不生成课后调整 | 不新增授课、课中记录或课后复盘页面 | 不新增对应数据表、接口或状态机 | 代码、页面与 OpenSpec 均保持备课边界 |

三份样例是通用机制的深度压力测试，不是三个学科专用模板。正式结论必须由八类学科组合测试和真实教师审阅共同支持；在真实评审完成前，不把专家模拟意见冒充教师共识。
