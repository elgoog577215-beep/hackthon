# 教师课程生产能力迁移清单

> 状态：G1 能力盘点与当前主链合同<br>
> 最后核验：2026-09-04<br>
> 核验对象：当前 `main` 的前端路由、工作台、后端路由、领域服务、任务与聚焦测试<br>
> 用途：决定旧整课链的能力如何被新工作台吸收；不是删除清单，也不替代 `tasks.md`

## 1. 当前两套实现的真实边界

### 1.1 当前正式教师入口

正式入口是 `/courses` 和 `/course/:courseId/workspace/:mode`：

```text
TeacherTeachingCalendarView
→ TeacherCourseLibraryView / TeacherCourseCreateView
→ CourseWorkspaceView
→ TeacherCourseWorkbench
```

旧 `/teacher/course/:courseId/...` 兼容地址、旧页面名和内部返回链接已从路由表删除。`TeacherCourseProductionView.vue`、`TeacherCourseOverviewView.vue`、`TeacherCourseFilesView.vue` 和 `TeacherCourseSidebar.vue` 均已退役；教学日历作为当前课程工作区内的嵌入能力保留。

### 1.2 新工作台仍在复用旧链的部分

新工作台生成大纲时，经 `CourseWorkspaceView.startOutlineGeneration` 调用 `courseStore.generateCourse`，再进入 `/api/course-generation/generate`。请求携带 `target_course_id` 和 `teacher_authoring_mode=lesson_assets_v1`，后端把它投影为教师大纲任务。也就是说，新工作台是新的教师编排壳，但大纲规划、任务和部分数据仍合理复用旧整课链能力。

因此不能按文件名把 `course_generation` 整体删除。必须把“教师入口”“共享生成能力”“学生整课运行时”分开判断。

## 3. 提示词与模板的迁移判断

### 3.1 直接保留

- 大纲：`build_outline_skeleton_v2_prompt`、`build_outline_batch_v2_prompt` 及校正提示词。
- 教案：`build_teaching_plan_skeleton_v3_prompt`、`build_teaching_plan_batch_v3_prompt`、知识细节和关系字段修复提示词。
- 教案 AI 优化：当前紧凑字段合同、最小充分修改和小节身份保护。
- V6：故事规划、来源保真、布局容量和视觉修复合同。
- 灵知正式真源：课程基线、结构化大纲、`CourseTeachingPlanV3`、教学块、来源与修订边界全部保留，外部模板不得覆盖。

### 3.2 拆开吸收

外部正式大纲/教案模板按三层吸收：

1. 字段层：课程基本信息、定位与简介、教学目标、考核、学时安排、参考资料。
2. 生成层：知识与能力、过程与方法、可选迁移与创新，以及“任务进入 → 核心教学 → 学习者行动 → 检查证据”的职责闭环。
3. 投影层：从现有真源确定性渲染高校正式大纲和教案；缺少来源时明确标记待补充，不编造书目、案例或数据。

这三层由 `course_authoring_templates.py` 统一版本化；提示词只读取契约，导出只读取正式数据，不保存平行大纲或教案正文。

旧 `build_content_prompt` 不整体搬入讲稿。需要逐项抽取并建立测试：

1. 八种一级学科合同及其内容条件对应的讲解行为；
2. 背景引入、概念讲解、过程推导、案例、示范、练习、互动、检查、总结等逻辑块约束；
3. 前后小节连贯性、知识范围和资料依据；
4. 输入预算、超时、一次结构修复和可信降级；
5. 代码、公式、表格等学科产物的完整性。

这些能力进入“教学块 → 教师讲义块”的策略选择器；学生自学口吻、学习者个性化、发布 CourseDocument、整节自由重写和练习发布不迁入讲义。教师现场讲述不是旧正文能力的直接搬运，而是依据当前教案重新生成的自然过渡、提问、活动指令和反馈提示。

### 3.3 逐步退场

- 旧教师整课生产页、概览页：静态调用已归零，源码已删除；旧地址保留为新工作台兼容跳转。
- 旧文件页和侧栏：仍被日历、文件组件引用，不按“旧页面”名称直接删除；先迁移仍有价值的课程导航能力。
- 旧轻量教师 PPT 生成/候选：V6 全部覆盖历史需求后改为只读导出，再删除写入口。
- 旧教师整课任务的正文、练习和发布阶段：新工作台不再创建后进入只读兼容；学生仍使用的共享代码不删除。

| --- | --- | --- | --- |
| 四种旧 `course_type` | 系统学习、项目实战、问题探究、考试冲刺及对应必填信息 | 学习目的、具体课程目标、内部策略 | 系统/项目/考试已单向转换；问题探究保留核心问题，学习目的按结果判断并默认推荐研讨课；历史批量对账待完成 |
| 八种学科与旧学科细分 | 学科识别、专业行为、证据、产物、安全护栏和内容条件 | 八种一级学科标准库 | 一级名称保留；二级名称不再展示，识别依据和行为规则吸收到一级合同；完整版本化待完成 |

## 5. 下一实施切片

按风险和依赖，下一阶段不是先删旧代码，而是连续完成以下纵向切片：

1. **教学语义第二版已接入**：新旧字段适配、教学定义、课程合同、讲次课堂弧、推荐依据和可执行教学块合同已有同一入口；下一步把旧学科细分、archetype、节奏和模块彻底迁入版本化标准库与专业动作库。
2. **课程基础新交互已完成**：学习目的、一级学科和课程教学类型已取代旧生成偏好；下一步在当前讲清楚显示本讲课型、推荐依据、最终教学块和修改影响。

## 7. 本轮四维收口（2026-08-27）

### 7.1 领域定义

教师看到的是四种正式产物，不是四块互不相干的页面：

```text
课程大纲修订
→ 本讲教案修订
→ 课程题库修订（按课程或讲次独立生成，不阻断讲稿）
→ 本讲讲稿修订
```

产品导航按“大纲、教案、题库、讲义、PPT”推进，但真实依赖不是确认门串行。教案绑定当前大纲；讲义绑定当前教案；PPT 绑定当前讲义；题库读取当前课程结构和学习目标，可以按讲或整课独立生成。主链共同依赖当前工作修订和精确来源；大纲、教案和讲义只向页面提供当前修订，PPT 按独立合同管理版本。新链只为并发保护和全课调整受限撤销保留必要的内部修订，页面临时状态不能成为新真源。

### 7.2 产品机制

大纲、教案和讲义执行同一条所见即所得闭环：读取当前上游修订，创建耐久任务，分片生成并保存检查点，非空且结构可用的结果直接形成当前修订，教师可立即编辑或进入下一步。AI 候选仍需教师选择采用，但质量审阅只供参考。空结果、结构错误、来源过期和任务失败保持阻断；恢复沿用原任务与原请求，不新建重复课程。PPT 仍在页面内容稿与成品之间保留内部确认。

本轮已修正这条闭环中的关键断点：未生成题库现在返回正常空状态，失败大纲的“重试”沿用原任务检查点；题库后台进程重启后会终止孤儿任务并给出可重试原因；课程正式难度、非选择题作答形式和学习目标身份进入生成、修复、覆盖率计算和发布的同一口径。单讲微课默认不虚构跨章综合题；增量重建保留经过教师处理的有效题，全量重建退役被替换的旧题，两者不再共用含混的合并语义。

### 7.3 交互设计

大纲、教案、讲义统一使用文档画布、编辑操作条、保存状态和本地撤销/重做。生成完成后立即可编辑；监听器只负责路由同步、任务恢复和服务端对账，不得自动关闭编辑、重开审阅、跳步或回退当前修订。三类页面都不提供历史版本面板或恢复入口；新链仅为并发保护与已采用的全课 AI 调整受限撤销保留必要内部修订。大纲质量报告从低强调按钮进入弹窗；AI 候选采用前不改当前内容。

仍需继续完成的交互只有两个明确边界：教案和讲稿的 AI 当前仍以单小节为稳定最小修改范围；精确到同一段中某个词的逐字差异标记，还需要在富文本范围映射稳定后开放。当前版本会标出所有受影响的字段或内容块，不会假装已经做到逐字跟踪。

### 7.4 技术架构

大纲草稿和讲稿继续按各自领域合同保留必要历史与恢复；教案只保留当前修订编号、并发检查和全课 AI 调整撤销所需的内部修订，不对教师提供历史浏览或任意恢复。题库继续使用独立的耐久重建任务和章节检查点；批处理调度器丢失定时刷新时，等待会在有界时间内退回单题处理，不会无期卡在中间进度。退役题继续保留历史和答案关系，但不再进入有效题数、题型分布、待审队列和学生可用题库。

真实课程“二维线性变换与矩阵”已完成一次整讲题库模型生成：3 个预定练习位全部通过质量门并发布，首轮通过率 33.33%，经独立求解、修复和复核后最终覆盖率 100%，耗时约 257 秒。发布后又用确定性迁移退役 3 道旧综合题，最终有效题为 3 道、待审为 0，实际页面和接口口径一致。这一证据证明题库切片已经跑通，但不代表“大纲 → 教案 → 题库 → 讲稿”在同一课程上的新一轮全链数据已齐全；跨产物耗时、恢复次数和最终修订关系仍需继续记录。
