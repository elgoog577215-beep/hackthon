# 灵知产品逻辑设计

本文定义教师智能体是什么，以及课程怎样在产品中被创建、生产、审阅、使用、调整和验证。教学内容本身由《教学内容设计》负责，教师怎样参与由《交互与界面设计》负责，具体实现由《系统架构》负责，当前完成程度由《产品状态》负责。

本文描述目标产品逻辑。图中出现某项能力，不代表当前代码已经完整实现；现状判断不得写回本图，也不能用当前实现反向缩小正确的产品关系。

## 1. 灵知是什么

### 1.1 灵知处理的核心问题

本轮教师智能体需要共同解决五个问题：

1. 教师怎样把教学设想转化为完整、专业、可以实施的课程。
2. 大纲、教案、讲义、题目、教学日历、评价标准和演示课件怎样保持同源。
3. 教师怎样审阅、修改、采用、导出和实际使用这些教学材料。
4. 教师怎样把课堂观察、作业考试结果和学生反馈带回产品，形成下一轮课程改进。
5. 人工智能怎样参与课程设计、内容生产和课程修改，同时保留教师的教学决定权。

### 1.2 核心用户及其真实任务

- **教师**是本轮产品的直接用户和最终责任人，负责设计课程、准备教学、审阅教学材料、用于真实授课、记录反馈并决定怎样调整课程。
- **课程设计者**维护课程结构、教学标准、内容模板和可复用课程内容；同一个人可以同时承担教师和课程设计者职责。

学生是课程设计所服务的教学对象，不是本轮需要建设直接产品流程的用户。学生起点、学习任务、可能回应和学习结果仍然进入教学设计；学生账户、班级、选课、课程发布和个体学习闭环不作为本轮完成条件。

### 1.3 灵知管理的核心对象

- **课程身份**：一门课程长期稳定的身份、归属和基本信息。
- **课程设计依据**：学生起点、学习目的、学科要求、课程类型、资料、模板、课时和教学条件。
- **课程内容与教学资产**：课程正文、课程知识、大纲、教案、讲义、题目、评价标准、教学日历和演示课件。
- **课程工作修订与当前可用教学资产**：教师正在维护的课程内容，以及已经满足结构、来源和必要质量要求、可以直接使用的教学材料。
- **本次教学使用记录**：教师可选记录某次备课或授课实际采用了哪些教学资产修订，不要求建立班级或学生账户。
- **教学反馈**：教师观察，以及教师导入或汇总的作业、考试、课堂整体表现和学生反馈。
- **教学解释与调整候选**：对课程问题的判断，以及等待教师审阅的课程调整方案。
- **修订、回执与效果结论**：教师确认后的正式改变、实际执行结果、恢复记录和后续验证结果。

### 1.4 产品核心价值

```text
结构化同源
+ 教师可控的智能协作
+ 可直接使用的教学材料
+ 教师反馈驱动的持续改进
```

结构化同源保证不同教学材料服务同一门课程；教师可控保证人工智能只在授权范围内生成和修改；可直接使用保证产物能够进入教师真实备课与授课；教学反馈保证课程调整来自实际问题；效果验证判断一次调整究竟改善了后续教学，还是需要缩小、撤销或重做。

### 2.2 完整产品运行图

完整图按九个执行区展开。九区不是九套系统，也不等于九个页面；它们是同一门课程从设计到生长的连续运行过程。

图中的加号表示多项信息共同成为下一步输入；“教师决定”表示产品必须等待，不能替教师继续；“当前可用”表示某项内容已经能够被教师采用或交付，不等于教师实际使用过。

#### 2.2.1 贯穿九区的内容形态与状态

课程内容可以由教师直接编辑、教师主动启动首次生成，或者由人工智能针对已有内容提出修改。三种入口最终都进入同一套内容形态：

```text
 [教师直接创建或编辑]   [教师主动启动首次生成]   [人工智能修改已有内容]
          |                       |                        |
          |               结果通过硬性检查                v
          |                       |                [人工智能修改候选]
          |                       |                        |
          |                       |                 教师采用或拒绝
          |                       |                        |
          +-----------+-----------+------------------------+
                      |
                      v
[课程当前工作修订]
          |
 结构、来源和必要质量检查
          |
          v
[当前可用教学资产]
```

三种形态承担不同责任：

| 内容形态 | 含义 | 不能被误解为什么 |
| --- | --- | --- |
| 人工智能修改候选 | 人工智能针对已有内容提出的待审阅改变 | 已经修改正式课程 |
| 课程当前工作修订 | 教师正在维护的当前课程内容或教学资产 | 已经被教师采用或实际使用 |
| 当前可用教学资产 | 结构完整、来源可接受、能够由教师直接使用的当前修订 | 教师已经在某次教学中使用 |

“课程当前工作修订”表示各课程对象当前可编辑修订的集合，不是另一份课程，也不改变每个对象原有的唯一真源。

内容形态之外，任务、来源、审阅、使用和改进验证必须分别保存，不能压成一个“状态”：

```text
内容形态：缺失 / 候选 / 工作修订 / 当前可用 / 已退役
任务状态：未启动 / 排队 / 运行 / 等待补充 / 等待审阅 / 暂停 / 取消 / 失败 / 完成
来源状态：当前有效 / 已经变化 / 无法确认
审阅状态：无需审阅 / 待审阅 / 已采用 / 已拒绝 / 已撤销
使用状态：未采用 / 已采用 / 已导出 / 已用于教学
改进验证状态：未验证 / 初步支持 / 稳定确认 / 证据不足 / 无效 / 有害
```

一次任务失败，只能改变本次任务和最近尝试，不能自动把最后可用教学资产或教师已经导出的材料判为失败。

## 3. 覆盖整张运行图的共同规则

### 3.1 每次生成都先固定本次依据

```text
[当前上游修订]
+ [本次生成范围]
+ [资料修订和作用范围]
+ [教师补充要求]
+ [内容模板和学科标准]
+ [目标教学产物]
                  |
                  v
          [不可变生成依据]
                  |
                  v
             [本次任务]
```

任务开始后的资料上传、教师编辑和规则变化只参与下一次生成，不能污染正在运行的任务。

### 3.2 批量启动，按最小单元分别恢复

```text
教师点击生成全部
-> 只选择缺失、过期或明确需要重做的讲次
-> 每讲建立独立任务
-> 所有任务一次进入队列
-> 在统一容量下处理
-> 每讲分别保存进度
-> 每讲分别成功或失败
-> 重试只处理失败或缺失讲次
```

批量生成不等于整批共同成败，不要求前一讲完成后才开始后一讲，也不因为一讲失败而清空整门课程。

教案和讲义的自动恢复属于教师已经启动的生成任务，不需要教师逐次点击。每个生成单元最多追加两次恢复，计数保存在原任务中；教案读取最新检查点，讲义只恢复失败分片或教学块。暂停、取消、来源变化、权限或配置错误不自动继续。后台恢复期间不把中间异常写成最终失败，读取和页面刷新也不启动新任务。

内容目标与失败条件分别维护。推荐阅读、教学提醒、过渡、篇幅预算和教学语言检查用于改善内容；缺少这些辅助项，不足以证明教案或讲义无法使用。优化无改善或调用异常时保留最好可用稿，不能为了消除建议阻断下一步。开发负责在隔离环境验证失败与恢复，教师只评价实际教学适用性。

### 3.3 任务状态、资产可用性和教师实际使用彼此独立

```text
最近一次任务失败
+ 上一份教学资产仍然可用
+ 教师已经导出的材料不受影响
+ 教师可以查看原因或重试
```

新的生成任务、当前工作修订、当前可用教学资产和教师实际使用是四件不同的事。新结果失败时保留上一份可用资产；新结果通过检查后也不能反向改写教师已经导出或实际使用的材料记录。

### 3.4 一处变化先判断责任，再决定传播

```text
变化来源
-> 识别变化对象和适用范围
-> 找到真正负责的课程内容或教学资产
-> 分析影响范围
-> 形成调整候选
-> 教师审阅
-> 正式应用
-> 精准更新受影响内容
-> 用后续教学结果验证
```

| 传播类型 | 产品处理 |
| --- | --- |
| 必须传播 | 上游已经明确变化，下游继续使用会产生错误或矛盾；相关内容必须进入处理状态 |
| 需要复核 | 产品知道某些内容可能受影响，但不能确定是否必须修改；向教师说明原因和范围 |
| 禁止自动传播 | 单次课堂弱信号、人工智能推测、普通问答和未经确认的资料变化只形成候选，不改写课程 |

### 3.5 失败回到最近的合法阶段

| 当前情况 | 下一步 |
| --- | --- |
| 创建输入不足 | 回到具体字段，保留其他输入和已上传资料 |
| 等待教师补充 | 回到当前任务补充信息，然后继续原任务 |
| 等待教师审阅 | 进入对应审阅，不能使用普通继续替代决定 |
| 已暂停 | 从原任务检查点继续 |
| 已取消 | 保留取消事实；再次生成时建立新任务 |
| 临时模型或输出异常 | 原任务内最多追加两次恢复，继续显示生成中并保留成功单元 |
| 自动恢复耗尽后的可恢复失败 | 显示最终失败；重新生成只恢复失败或未完成单元 |
| 来源已经变化 | 保留旧可用结果，按最新来源建立新的生成尝试 |
| 内容修改发生冲突 | 回到影响和冲突审阅，不直接覆盖 |
| 状态无法确认 | 只允许查看原因，禁止猜测继续 |
| 服务中断或页面刷新 | 根据任务身份和检查点恢复，不重新建立同目标任务 |
| 教学资产未通过必要检查 | 保留工作修订和上一份可用资产，返回具体问题对象 |
| 导出或交付失败 | 保留当前可用资产和已经成功的导出，不把资产本身判为失败 |
| 教学反馈导入失败 | 保留原始文件和已经记录的反馈，只重新处理失败部分 |
| 效果证据不足 | 继续观察，不宣布调整有效或失败 |

## 5. 图中必须守住的产品边界

1. 课程是产品中心，大纲、教案、讲义、题目和课件只是同一课程面向不同教学任务形成的资产。
2. 一门课程只有一份课程正文；工作修订、可用资产和导出文件不能成为第二份课程正文。
3. 当前工作修订、当前可用教学资产和教师实际使用是不同事实，不能用一个“最新课程”代替。
4. 任务状态、资产可用性、来源新鲜度、教师审阅、实际使用和效果结论是不同状态维度。
5. 每讲独立生成、独立成功、独立失败和独立恢复；一讲失败不能清空整门课程。
6. 上游变化先分析影响、保护不变项并保留旧版本，再由教师决定是否更新。
7. 原始教学反馈、教师解释、调整候选和正式改变必须分开。
8. 人工智能负责理解、生成、分析和提出候选；教师拥有课程内容及其实际使用的最终决定权。
9. 教师直接修改不需要人工智能批准，但它造成的下游影响仍须被识别和处理。
10. 导入的作业、考试和学生反馈只提供课程改进证据，不能自动建立学生画像或改写课程。
11. 调整应用成功只证明产品完成了修改，不证明教学已经改善。
12. 效果结论必须绑定调整对象、基线、预期表现、后续反馈及其证据范围。

## 6. 三层设计怎样闭合

本章不增加新的教学对象或产品模块，而是检查前三层能否逐项对应。

### 6.1 内容对象、产品机制与界面载体

第一层中的每个教学对象都必须回答：

```text
它是什么
-> 由什么形成
-> 谁能够修改
-> 怎样成为当前工作修订
-> 怎样满足当前可用条件
-> 教师怎样审阅、采用、导出或实际使用
-> 教学反馈怎样与它关联
-> 会影响哪些对象
-> 用户在哪里看见和操作
-> 失败后怎样恢复
```

如果一个内容模板在第二层没有形成、修改、使用和验证机制，它仍然只是文档模板；如果一个产品机制在第三层没有入口、过程、状态和决定方式，它仍然只是后台能力。

### 6.2 教学语义与教师产物同源

- 同一个课程目标既要说明教师准备教会什么和怎样检查，也要说明学生最终学会什么和怎样证明。
- 同一讲形成教案、讲义、题目、评价标准、页面内容稿和演示课件，但只有一份课程语义和正式来源。
- 学生任务、可能回应和学习结果是教学设计内容，不因此产生一套独立的学生端课程正文。
- 现有学生视角预览可以作为教师检查材料的辅助方式，但不代表本轮已经建设学生产品。

### 6.3 人工智能与正式结果的边界

```text
人工智能输出
-> 可审阅候选
-> 教师决定
-> 课程当前工作修订
-> 执行结果
-> 撤销与恢复
```

这些步骤不能混成一个“生成成功”。人工智能可以提出改进、解释影响和执行受控动作，但不能替用户确认、扩大范围或隐藏失败。

### 6.4 变化传播的一致性

- 上游变化通过真实来源和依赖找到下游。
- 受影响内容进入复核或局部重建，不受影响内容明确保留。
- 教案和讲义的篇幅、措辞、辅助字段与局部复述只产生建议，后台有限优化后仍可交付可编辑工作修订。必要正文缺失、结构或来源错位、明确知识冲突、占位、成段复读与损坏语法才阻断使用。
- 新结果生成失败时，最后可用结果和教师已经完成的导出继续存在。
- 更新完成后通过新的教师观察、作业考试结果、课堂表现或学生反馈重新验证。

### 6.5 跨层硬边界

- 页面不能另建一套产品事实。
- 导出文件不能反过来成为课程真源。
- 教师导入的结果不能在缺少依据时冒充完整学习事实。
- 单次课堂弱信号不能直接改写课程。
- 课程最新修订不能改写已经完成的导出和实际使用记录。
- 技术字段、接口和存储方式不进入本产品逻辑正文。

## 7. 完成标准

### 7.1 产品机制完成标准

- 九个执行区都有输入、处理、决定、结果和返回路径。
- 工作修订、当前可用、教师采用、导出和实际使用的关系明确。
- 批量、局部、失败、恢复和变化传播规则完整。
- 教师、课程设计者、人工智能和系统的权力边界清楚。
- 教学反馈能够形成课程调整候选，但不能未经教师确认改写课程。
- 调整后的课程能够接受后续真实教学反馈检验。

### 7.2 整体产品完成标准

```text
教师能够完成课程设计
-> 系统能够形成同源教学产物
-> 教师能够审阅、修改、采用和导出
-> 教师能够把材料用于真实教学
-> 教师能够记录或导入教学反馈
-> 系统能够形成可审阅的课程调整候选
-> 教师能够确认并精准更新课程
-> 后续教学能够验证调整效果
```

只有这条链真实成立，本轮教师智能体才从一次性内容生成工具成为能够持续改进课程的教学工作系统。

学生学习现场、班级管理、选课关系、课程发布和个体自适应属于未来扩展。当前设计只要求教师侧课程与教学资产保留必要的兼容边界，不把这些能力作为本轮完成条件。
