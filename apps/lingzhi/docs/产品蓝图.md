# 启智与灵知产品蓝图

启智面向教师建设稳定的教学生产与改进能力；灵知面向学生成长，可以独立开发和使用，围绕课程内容形成个人学习路径与生成式复习材料，并逐步拓展更多学习材料。两者以数据、知识同源的教学核心相互配合，共用适用的课程能力，保留各自的产品任务。

当前教师课程工作台实现在 `apps/lingzhi`，启智门户位于 `apps/qizhi`；代码目录、部署入口与产品分工分别说明，本次设计不搬迁代码、停用教师工作台或混用两个应用的数据库。教师端与学生端都要完整建设，共用课程能力；灵知可先基于学生自建或导入的课程运行，未来接入启智的有界自适应教辅教材，作为启智的 kit 相辅相成。

师生共用生成控制台和适用的生成、编辑、保存与恢复能力，按用途展示输入和产物。生成以完整产物为单位：大纲默认整份一次，教案与讲义每讲一次；有真实依赖、用户决定或实际容量限制才分步。学生不需要单独生成或确认教学大纲、教案，必要结构在内部形成。具体规则见[课程生产](功能设计/课程生产.md)，实施边界与旧分支退出见[生成链路收敛](../../../changes/生成链路收敛.md)。

本文是两者产品分工与课程共享机制的共同设计入口。具体业务在同一份功能设计中连续说明内容、逻辑、交互、技术；课程与学习实现差距见[产品状态](产品状态.md)，启智已有应用能力见[全局图](../../qizhi/docs/全局图.md)，启动和测试见[README](../README.md)。方向、实施设计与运行证据分别表述，不把目标写成已经交付。

## 产品分工与建设主线

已经明确的方向是：启智的“1 个基础功能 + 3 个创新功能”，以及灵知独立发展、面向学生成长的“有核无边”学习服务。下表的具体运行方式是据此形成的实施设计；教材规范的适用清单、审查责任、分析指标与自适应策略仍需结合教学样本细化，不能宣称已经通过专业审查或验证教学效果。

| 产品与能力 | 用户要完成的事情 | 实施设计及边界 |
| --- | --- | --- |
| 启智基础功能：结合日历稳定生成 | 按教学安排完成大纲、课件、PPT，降低反复操作和维护负担 | 日历与讲次共用安排；课件沿现有教案、讲义、页面内容稿与 PPT 分工生成。统一发起和恢复，不跳过既有人工决定；稳定性与维护成本以真实使用衡量 |
| 启智创新一：低成本联动更新 | 修改课程安排或内容后，相关材料一致更新 | 定位依赖，只处理受影响部分，保留人工修改与可复用结果；模型调用量、耗时和人工返工分别记录 |
| 启智创新二：全面联动分析 | 看清目标、内容、活动、评价、课时及教学反馈之间是否一致 | 分析覆盖已知对象和关系，逐项给出依据、缺口与建议；缺少资料时说明覆盖不足，分析不自动改课 |
| 启智创新三：有界自适应教辅教材 | 在明确范围与规范要求内，为不同学生安排不同学习路径 | 定义共同目标、内容范围、必学要求及允许变化；路径与材料变体受同一边界约束，生成可用不等于通过教材规范审查 |
| 灵知：生成式复习与学习材料 | 根据个人目标、困难、兴趣与学习过程，得到适合下一步的材料 | 以课程教学核心为依据生成个人材料，先支持课程内复习、补充理解与应用，再扩展更多学习用途；不等待启智所有创新能力完成 |

“有核”指课程目标、正式内容、来源和版本有明确依据；“无边”指个人材料的形式和拓展范围具有开放性，仍受准确性、来源、授权和可用资源约束。学生材料无需默认承担正式教材全部编审流程，但不能冒充已审教材，不能因此启用当前冻结的联网检索。

学生成长关注理解与表达、迁移应用、问题探究和自主学习。考试复习是明确场景之一；作品、解释、选择及反思也可成为学习依据，不能只按分数或使用时长解释成长。

## 一、内容设计

### 课程及其产物

新建课程统一以“课程 → 第 N 讲”组织，不按创建者角色生成另一套课程结构。讲内主题、小节和教学环节组织连续正文，不另建正式课程文件、确认状态或生成任务。导入保留原文和层级来源，统一映射稳定学习内容身份；历史章/节由读取适配处理，不依赖层级数字判断是否可学习。

| 对象 | 含义与责任 |
| --- | --- |
| 课程设计依据 | 目标、学习者起点、学科、学习目的、教学类型、时长、条件、教师要求及资料 |
| 大纲 | 整课目标、成果与评价、讲次范围及其关系 |
| 教案 | 每讲的目标、师生活动、时间、学习证据和反馈调整 |
| 讲义 | 师生共用、可独立阅读的完整教材式材料；不是口播稿或课堂调度脚本 |
| 题目、量规、日历及配套材料 | 消费同一课程依据，分别服务练习、评价与实施 |
| 页面内容稿与 PPT | 同一讲义的教学表达；内容稿独立确认，成品按该修订编译 |
| 原件及来源关系 | 原件不可变；主来源、参考资料、版本与引用关系可以明确调整 |
| 教学与学习证据 | 真实观察、作答、作品和事件；与教师解释、模型推断分开 |
| 课程调整 | 修改范围、候选、影响、教师决定、执行回执和后续验证 |
| 教学核心及适用边界 | 共同目标、内容范围、必学要求、允许变化、来源修订与教材审查依据；与个人路径分开 |
| 个人生成材料 | 面向特定学习者和用途的补充讲解、复习材料、变式练习或应用任务，保存来源、范围、版本及依据；不覆盖正式教材 |
| 个人学习路径 | 当前目标、起点依据、建议顺序、关联材料、推荐原因与学生选择；执行产生的事实独立保存 |

学习目的只有系统学习、项目实践、期末冲刺；一级学科保留八类；课程教学类型为理论课、实验课、实践课、研讨课、项目课、综合课；本讲课型为七种课堂主弧。具体名称、专业动作和模板由[教学内容模板](教学内容模板.md)维护，旧模块 ID 不成为教师的新分类菜单。

### 正式数据的拥有者

目标是每门课程的正式正文只有一个拥有者和写入责任；每份个人派生材料也有各自唯一的写入责任。教师生产、学生自建、阅读、AI 修改、题库与 PPT 消费明确的课程身份、正文修订和来源关系。共有课程内容与教师专用教案、行政材料分清职责；不能要求所有学生课程必须挂在教师身份下，也不能把原教师仓储复制成另一套学生仓储。

同一教学核心可以派生多份个人材料。个人材料拥有独立身份、归属、用途及修订，引用来源课程/教材及具体内容版本；它们是不同用途的正式对象，不是另一份可随意回写的教材副本。保存材料不等于学生已经学习，调整个人材料不改变教师正式教材；教师采用其中内容时仍走获授权的课程修改流程。

当前教师课程的完整教案与讲义仍由 `TeacherLessonAuthoringRepository` 保存，`teacher_content_projection.py` 生成阅读投影；历史学生课程仍使用原文档来源。这是现有实现边界，不是永久的产品分类。实施时先统一课程访问、正文读写与修订的业务责任，再决定现有仓储的复用或迁移；切换前后都只能有一个正式写入者。迁移须预检、备份、对账与恢复验证，不以双写维持两份正文。

正式题库拥有题目修订，试卷保存有序题目修订引用。`LearningEvent` 等学习仓库保存事实，`LearnerModel` 依据同一批事实重新计算。课程知识、教学表达与配套文档各有明确拥有者；页面、Store、导出文件和 AI 会话都不成为第二真源。`UsageEvent` 只记录产品使用，不作为掌握程度或教学效果证据。

## 二、逻辑设计

### 完整闭环及建设边界

```text
启智：教学安排与稳定生产 → 联动更新、联动分析、有界自适应教材
                                    │
                    授权的教学核心：目标、内容、来源、版本
                                    │
学生自建/导入课程 ───────────→ 灵知：目标、困难、兴趣与学习过程
                                    │
                       个人学习路径、生成式复习与学习材料
                                    │
                        阅读、练习、应用、作品与反思
                                    │
                  个人下一步调整 / 经授权的教学反馈

共用能力：规划、生成、解析、内容引用、题目、修订、权限、任务与恢复
```

教师现有生产工作台继续作为基础；学生端恢复以学习为中心的完整使用过程，复用旧版本的有效交互关系与当前后端能力，不机械回退旧代码。知识图谱本轮不建设；已有内部知识上下文不因此删除。

本轮必须共同成立：教师创建与备课、学生自主创建/导入、学生经授权学习教师课程。完整班级/选课管理、公开课程广场、跨课程复杂自适应和移动端不作为这三条流程的前置条件，也不因本次蓝图调整删除已有能力。学校模板先覆盖有明确输入和样本的类型，不承诺任意格式自动理解。

近期设计在上述完整流程上补齐“选定目标与依据 → 生成个人复习/补充材料 → 使用并留下事实 → 调整下一步”。教材级自适应是启智的正式建设方向，但完整规范审查、多路径效果验证与更多学科覆盖分阶段落实；不把这些长期能力写成本轮已经交付，也不把它们作为灵知独立运行的前置条件。

### 有界教材与个人学习材料怎样协作

有界教材明确必学目标、内容与来源范围、允许的路径/表达变化、评价要求及适用规范。路径可以调整顺序、补充支架与练习，不能偷偷删掉共同要求或把越界生成的内容包装为已审教材。审查结论绑定实际覆盖的教材修订及变体范围，未覆盖的新内容不能继承旧结论。

灵知基于本人目标、自述起点及获授权的真实学习证据，建议学习路径和材料。证据不足时先使用明确的课程顺序或学生选择，不生成精确掌握率。学生能查看理由、纠正起点、接受或调整建议；一次答错、停留时间或闲聊不能自动改变整条路径。

生成个人材料时区分课程要求内的内容、前置补充和兴趣/应用拓展；拓展不自动成为考试范围或全体学生必学内容。材料持续绑定来源，学生可编辑自己的材料、继续使用合法旧版本或主动更新。个人实践作品与反思提供后续调整依据，不由 AI 代造学习成果。

### 同源数据与跨应用边界

“数据、知识同源”要求共享内容可以追溯到同一来源及修订，不要求启智与灵知直接共用数据库。接入至少明确来源应用、来源课程/材料身份、内容与修订、可用范围、用途许可及撤销状态；两侧本地 ID 通过显式关系映射，不凭名称或相同数字认定同一对象。既有 OAuth 身份接通也不等于课程内容已经授权。

个人材料只读取获授权内容，个人记录默认归本人；回流启智的反馈须有相应许可、课程版本和证据范围。来源撤销后停止新的读取和生成；已有个人记录与派生材料按许可处理，个人原创部分可管理，含受限原文的展示/导出仍校验权限，不借快照泄露来源。

### 工作空间、课程归属与权限

| 情形 | 课程与正文权限 | 学习记录与教学材料 |
| --- | --- | --- |
| 教师备课 | 管理本人或明确获授编辑权的课程 | 管理教学材料；学习者个人数据仍有独立授权边界 |
| 学生自建/导入 | 管理自己的课程，手工或 AI 修改走正式命令 | 保存本人笔记、作答、进度与会话；不要求教师行政字段 |
| 学生学习教师课程 | 只能读取获授权的学习内容；默认没有教师正文和教学文件写权 | 本人记录独立保存，私人笔记和会话不自动提供给教师 |
| 教师预览 | 按教师权限查看允许预览的公开内容 | 临时试做，不生成任何人的正式学习记录 |

工作空间是使用方式，不是权限凭据。一个账号可以在有权限的工作空间之间切换；切换不能提升角色或改动课程归属。学生拥有自建课程的内容编辑权，不因此获得教师或管理权限。共享课程要有服务端可核验的授权对象、内容范围与撤销状态；具体授权界面在实现前定稿，不扩展为完整选课平台。

生成完成只证明当前内容可用，不自动把课程、教师教案或答案向其他人公开。正式学习记录必须绑定本人、课程、内容及题目修订；共享访问撤销后停止新内容读取及新增学习操作，本人既有记录保留，来源不可访问时明确提示，不借记录接口继续泄露课程。

### 六组必须联合成立的关系

| 关系 | 共同规则 |
| --- | --- |
| 生成 → 备课 → 学习 | 复用课程规划与正文能力；教师产物和学生简洁流程按用途组织，不复制正文 |
| 正文修改 → 题目 → 教学文件 | 同一来源与修订；只更新实际依赖项，保留人工修改和未受影响内容 |
| 阅读 → 笔记 → 提问 → 练习 | 使用明确内容锚点，切换与返回不丢上下文，提问锁定发送时范围 |
| 作答 → 评分 → 错题 → 再练 → 学习判断 | 从同一正式作答事实派生，新尝试关联原尝试，不覆盖旧结果 |
| 身份 → 课程归属 → 个人记录 | 所有入口服务端验证，同课多人互不串数据，AI 不越权 |
| 任务 → 保存 → 中断 → 恢复 | 同一持久任务身份与冻结输入，已有成果保留，重复请求不重复写入 |

同一关系体系还须覆盖“教学核心 → 个人生成材料 → 学习路径 → 实际使用证据”。材料生成、路径推荐和教学反馈复用前述身份、来源、修订与任务机制，不另建一套学生生成、评分或保存规则。各对象可以有各自任务，不能对同一请求建立互不对账的重复任务。

这六组关系从设计开始共同确定；实施可分组，但前端、后端、数据与恢复围绕完整结果一起交付。

### 版本更新与个人历史

课程当前修订、学习所用修订与已提交作答的题目修订分开记录。内容更新后，未变化的锚点继续有效；被修改、移动或删除的内容先计算影响，提供更新提示和可核对的旧新映射。笔记不自动附到意思不同的文字，无法定位时保留原引用与待定位状态；历史作答不使用新答案重新解释。

目标要求有足够的旧修订或有界内容/题目快照支持追溯，不能只在前端保存版本号。共享课程学习者不能通过个人 AI 修改覆盖教师正文；补充解释与个人笔记留在本人范围。教师采用教学反馈须有相应授权和证据，不自动收集私人会话。

教学核心变化时，逐项标记实际受影响的个人材料与路径，保留未受影响内容和学生手工修改。更新形成新修订，已产生的学习事实继续引用使用时的材料、题目和路径版本；推荐变化不改写历史，保存新材料不自动切换正在使用的版本。

### 状态与决定

任务是否结束、产物是否可用、来源是否过期、编辑者是否采用、是否实际使用、学习或教学效果是否改善分别表达。失败的新尝试不抹掉最后可用结果。大纲、教案和讲义通过各自结构及来源准入后成为当前修订，不再附加人工确认门；PPT 内容稿、正式内容的 AI 修改继续遵守自身确认规则。

有编辑权限的课程使用者直接修改不需要 AI 批准。产品内 AI 修改正式内容必须先明确范围、候选、影响与保持项，经用户决定后通过领域命令执行，返回真实回执和恢复入口。模型输出、执行成功、教学有效是三个不同结论。

上游变化只影响实际依赖它的下游；先说明过期、冲突和更新范围，保留不受影响内容。单次弱信号、普通问答或未采纳资料不得自动改课、建立画像或替用户作决定。

## 三、交互设计

教师从“我的课程 / 我的日历”进入备课空间，以“大纲 → 教案 → 讲义 → PPT”为主路径，题库与配套材料从课程文件进入。学生从自己的课程库新建、导入或继续学习，也能进入已获授权的教师课程；课程内以连续正文为中心组织笔记、AI、练习、错题和学习进度。两端共用课程能力和适用组件，保留各自完整任务流程。

学生不必经过教师备课阶段才能阅读、记录或练习。自有课程编辑显示相应权限，学习他人课程只提供允许的学习操作。教师预览复用学习界面但明确“试用不保存”，正式学生操作必须持久保存。跨对象修改复用原调整能力，按课程权限裁剪，不复制第二套工作流。

灵知在课程内增加“我的学习材料”和可调整的下一步建议，具体交互见[学生学习](功能设计/学生学习.md)。生成入口围绕“我想理解什么、复习什么、怎样应用”收集目标和范围，清楚区分正式课程、个人材料及拓展内容；产品页面不要求学生理解内部任务、投影或仓储。

保留成熟的蓝紫色、渐变、控件密度和阅读节奏。正式内容连续阅读，操作贴近对象；教师核心正文、状态和常用操作原则上不低于 15px。讲次标题位置稳定、正文自然换行，不用密集多栏、截断或装饰性统计挤压阅读。

“备课工作台 / 课程文件”的分段切换保持外层分组、较小白底选中项、轻阴影及随内容收拢的宽度；复用比例与层级，不把固定像素套给其他控件。当前只建设和验收桌面端；中文和对应英文沿已有 i18n 维护。

所有任务反馈回答四件事：正在发生什么、已有内容能否使用、现在可以做什么、失败怎样恢复。跨页面保持课程、对象、阅读锚点与返回位置；关闭观察界面不终止后台任务，监听器不擅自切阶段、关闭编辑或继续生成。

## 四、技术设计

### 分层与共享机制

```text
Vue 页面 → 共享组件 / Pinia 领域投影 → FastAPI 接入
→ 应用服务与工作流 → 领域命令 / 规则 → 仓储与任务检查点
→ 模型、文件解析、渲染、独立 Runner
```

路由负责鉴权、参数与响应；服务组合领域能力；领域层决定状态、权限与不变量；仓库持久化。Agent 只组合已有能力，不能取得正式数据所有权。模型处理语义，稳定分类、顺序、预算、校验与权限由版本化规则和确定性代码负责。

共享渲染链处理 Markdown、公式、Mermaid、代码和安全链接；多个页面消费同一领域 Store，不复制产品状态。`course_production_state.py` 是生产状态的唯一解释者，动作必须同时具有授权及真实目标 task ID。字段、状态机和接口的准确实现以对应源码及测试为准，不再维护一份全量模块清单。

### 身份、存储与恢复

正式启智环境通过 OAuth/JWT 与 RBAC 验证身份，由服务端产生 `qizhi:<user-id>`；HTTP、SSE、WebSocket 使用同一身份依据。本地 `X-User-Id` 是开发身份合同，不等于正式鉴权。共有课程/学习服务支持有权限的学生与教师，教师专属和管理操作保留角色门；每个课程及记录再检查所有者、授权范围和允许动作，不能只把全局角色白名单加上学生。

课程列表、详情、文件下载、任务查询/控制、AI、笔记、作答、导出与实时连接使用相同资源访问规则。旧共享 actor 归属必须显式映射，不能自动认领；迁移和恢复操作也不能绕过权限。

持久任务以 `task/job ID` 控制，课程 ID 只表示归属；冻结输入、来源修订、检查点、幂等键与回执一起决定能否恢复。暂停、取消、来源冲突和主动等待不得自动继续；讲义还遵守业务设计中的“仅有任务控制权限的用户主动续作”规则，不能套用其他阶段的重试策略。

持久化采用跨进程锁、重读、临时写入、原子替换；任务状态先保存再发布。一个数据目录只有一个 TaskManager 领导者；索引和 last-good 都损坏时进入只读降级。健康检查不发模型请求，存活不等于数据及任务已就绪。正式删除通过原任务和仓储协调器建立写入屏障，不让迟到回调重建已删课程，也不删除共享资料。

### 共享对象与数据合同

以下是待实现的数据合同。保留已有 `CourseDocument`、教师仓储、`LearningEvent`、学习记录和 TaskManager 的责任；新增对象优先复用原存储与事务能力，不能直接把下列逻辑对象理解为七套独立数据库或服务。

```text
课程身份 ──→ 正式教学内容及修订 ──→ 教学边界及修订
                  │                         │
                  └────── 来源引用 ──────────┘
                              │
访问授权 ──约束读取与派生──→ 个人材料及修订 ←── 个人学习路径
                              │                    │
                              └──── 实际使用 ──────┘
                                      │
                             学习记录 / 学习事实
                                      │
                          有依据的下一步建议或授权反馈
```

| 逻辑对象 | 最小身份与关联字段 | 唯一保存责任 |
| --- | --- | --- |
| 课程身份 | `course_id`、`owner_actor_id`、来源应用/课程引用、当前正式内容引用 | 课程领域；当前 `owner_id` 等字段统一映射到此语义，页面不产生第二个课程身份 |
| 正式教学内容 | `content_id`、`course_id`、`revision_id`、稳定讲次/内容块 ID、正文、来源引用 | 该课程正式内容拥有者；教师仓储与 `CourseDocument` 的切换显式迁移，读取投影不能回写 |
| 教学边界 | `boundary_id`、`revision_id`、目标、必学范围、允许变化、评价要求、审查引用及覆盖版本 | 课程教学设计；缺少正式边界的自建课程不伪造已审教材状态 |
| 访问授权 | `grant_id`、授权方、接收人、资源/范围、可执行动作、状态、授权修订 | 资源访问能力；所有读写入口以同一判断为准 |
| 个人材料 | `material_id`、`owner_actor_id`、`course_id`、用途、来源引用、当前材料修订、创建请求/任务引用 | 个人材料领域；每份修订保存正文与依据，不进入教师正文或全课共用资产 |
| 个人路径 | `path_id`、本人、课程、路径修订、目标、按顺序的内容/材料引用、依据与个人选择 | 学习运行时协调的个人路径；实际完成情况从事实派生 |
| 学习记录与事实 | 本人、课程、作用对象类型/ID/修订、原引用/位置、用户输入或真实事件 | 原学习记录、作答与事件仓库；各自沿已有责任保存，进度与模型解释只做投影 |

课程和材料 ID 保持稳定，内容变化形成新修订。个人材料的标题、正文和生成依据形成同一修订，编辑时提交预期修订，冲突不覆盖。路径步骤引用对象及修订，推荐可以更新，但已经执行的步骤和事实仍保留当时引用。

源对象引用统一表达为 `source_app + object_type + object_id + revision_id + scope`，其中 `scope` 使用稳定讲次、内容块或题目 ID。`source_fingerprint` 用于检测实际引用范围的变化，不能替代来源身份或授权。个人材料还保存本次采用的边界修订、用户明确目标及证据引用；不复制整门课或整套个人历史来充当生成输入。

### 学习记录怎样关联个人材料

记录与事件增加明确的作用对象引用：`subject_type = course_content | personal_material`、`subject_id`、`subject_revision_id`。课程引用负责归组，作用对象决定笔记、阅读位置和反馈到底针对哪份内容。个人材料上的笔记不能伪装为教师正文的笔记，不能只用原课程 `node_id` 推断位置。

锚点保存作用对象、修订、稳定段落/内容块身份及必要原引用。新修订发布后先给出定位关系，无法定位时保留原引用；不静默把旧笔记挂到新解释上。材料中的练习继续使用正式题目修订和作答仓库，新增材料引用只说明学习上下文，不另存一套答案或分数。

`LearningEvent` 现有 `entity_type/entity_id/entity_revision` 与元数据可承载明确的材料使用事实，接入时须统一到上述语义；`LearningRecordRepository` 的课程/用户隔离可以复用，但当前记录与锚点仍偏向课程节点，需扩展作用对象解析。材料生成成功不写“已学会”，模型建议不写学生选择，学生作品不由生成任务代填。

旧记录继续按其原课程对象解释，不能猜测归到某份新材料。需要改变存储格式时，通过有备份、有对账的显式转换统一新格式；目标接口和正式写入只保留一套合同，不长期维护两套正文或记录协议。

### 授权与版本检查的共同位置

1. 正式身份来自服务端验证；工作空间和请求里的角色字段不授予权限。课程拥有者可管理自己的课程；其他人仅在明确授权范围内使用。当前的 `is_published` 和 `course_document_publication` 不充当新的访问授权。
2. 授权动作区分读取学习内容、以内容生成个人材料、编辑课程、读取教学私有文件及提供学习反馈。只读许可不自动授予派生或再分享权限；教师能管理课程，不等于能读取学生私人材料。
3. 原课程读取、材料列表/详情/历史/导出、题目、AI、任务控制和实时消息均调用同一访问判断。个人材料同时校验本人归属与所用来源许可，不能通过另一个入口绕过。
4. 生成在提交、实际执行、正式保存三个位置检查身份、来源与修订。排队后来源变化或授权撤销时停止旧请求，说明原因；不以任务开始时曾有权限作为保存依据。
5. 撤销后的保留范围以原授权与个人记录规则决定。允许保存的个人原创内容仍可管理，受限原文和依赖其展示的材料不得经历史快照、任务结果或缓存重新公开。

### 个人材料请求与持久任务

| 阶段 | 接入参数与检查 | 持久结果及失败语义 |
| --- | --- | --- |
| 提交生成 | 客户端请求 ID、课程与选定范围、用途、目标、明确选用的个人证据；服务端解析本人和来源 | 保存冻结输入与输入指纹，分配材料/修订目标及唯一 TaskManager 任务；相同请求重发返回原回执，不同输入复用请求 ID 返回冲突 |
| 排队与执行 | 再校验授权、来源及输出范围，读取冻结输入 | 沿原任务保存真实进度和完成块；关闭页面只停止观察，不新建任务 |
| 保存材料 | 检查当前任务状态、来源修订、输出结构及预期材料修订 | 正式材料修订与任务产物引用可对账；保存失败保留生成检查点，不能先报成功或重新请求模型 |
| 阅读与记录 | 校验材料归属及来源许可，指定实际阅读修订 | 返回真实正文、来源关系与更新状态；用户操作写到对应作用对象，列表读取不生成学习事实 |
| 人工修改 | 明确材料 ID、预期修订及修改范围 | 保存个人材料新修订，旧事实不变；不调用教师正文命令 |
| 恢复或重生成 | 指定任务/材料和对应基线，区分原输入恢复与新要求 | 可用检查点只补缺失部分；输入变化建立新尝试并保留关联，暂停、取消和来源冲突不能自动续作 |

冻结输入与材料历史的保存责任独立于任务展示历史；任务索引可能清理终态详情，不能把唯一的来源、生成依据或材料正文留在 `request_snapshot`、任务 `result` 或浏览器缓存中。TaskManager 负责执行状态，个人材料仓库负责产物与修订，学习仓库负责使用事实，三者通过稳定引用对账。

状态分别表达任务是否完成、材料是否可读、来源是否更新、是否采用和是否实际学习。允许生成成功后尚未阅读，也允许新尝试失败而旧材料继续可用；任务清理不能顺带删除个人材料，材料删除不能由迟到任务恢复。

### 实施衔接与验收顺序

实现按依赖推进，始终围绕完整使用过程验证：

1. 统一课程访问与内容引用：正式身份、课程归属/授权、正文读取、修订和范围一起成立，教师与学生入口用相同规则。
2. 接通个人材料：在上述来源上完成生成、持久保存、阅读、个人记录与再次进入，覆盖两个学习者和失败恢复，保留教师课程不变的证据。
3. 接通联动与下一步：来源更新影响到材料/锚点/路径；基于真实学习事实提出可调整建议，再验证学生选择与授权反馈。

每一步都包含相应的前端、领域逻辑、存储和恢复，不按“先做所有页面、再补所有接口”分割。启智完整教材审查和长期自适应效果独立推进，不成为灵知基于自建/导入内容运行的前置条件。

### 共有能力与当前代码的改造责任

| 责任 | 现有代码入口 | 目标约束 |
| --- | --- | --- |
| 身份与课程访问 | `qizhi_auth.py`、`dependencies.py`、课程和领域路由 | 角色、归属、共享范围与个人记录权限一起验证 |
| 课程规划、生成与导入 | `course_generation/`、教师生产、Markdown/材料导入 | 两种用途调用同一业务能力和写入规则，学生请求不伪装教师身份 |
| 正文读取及修订 | 课程仓储、教师仓储、`teacher_content_projection.py` | 当前拥有者唯一；投影不回写，未来迁移不得形成双写 |
| 教学边界与联动分析 | 现有目标、来源关系、日历与课程调整能力 | 补齐边界定义和分析覆盖依据；不将独立文档评分直接视为全面联动分析 |
| 个人材料与路径 | 复用生成、来源、学习记录及任务能力；对象合同待实现 | 独立材料身份与归属，锁定来源和证据，路径建议可修正；不复制第二套生成或评分规则 |
| 学习事实与运行态 | `learning_records`、`practice`、`learning_events`、`learning_runtime` | 记录持久化，错题和进度由事实派生，模型是可重算解释 |
| 任务与恢复 | `jobs/`、工作区与检查点 | 所有入口复用持久任务身份和阶段恢复规则 |

表中是改造入口，不表示目标已经实现。基础存储、异常和纯文本处理不反向依赖课程业务；内容投影由上层传入明确依赖，避免绕依赖组装器形成循环。旧入口按实际调用者、独特能力和历史读取需要退出，不能放宽审计来宣称结构已整理。

### 联合验收

必须用正式入口验证教师备课、学生自建、学生导入及两名学生使用同一授权课程。覆盖阅读—笔记—AI—练习—错题再练—再次进入，验证持久结果、正确身份、上下文与版本。

同一组样例继续验证正文修改后的题目与教学文件影响、笔记定位、作答历史保护，以及重复提交、并发保存、断连、部分失败、授权撤销和恢复。教师预览的无写入与正式学生服务的持久写入分别验证；任何一端完成不代表共有关系已经完成。

新增验收须证明：同一教学核心下两位学生可以得到有依据的不同材料与路径，且课程要求不被改写；证据不足有默认路径，学生可以拒绝或调整建议；来源更新仅影响相关材料，旧作答不变，断连续作不重复生成；撤销权限后缓存、导出与生成均不泄露来源。教材审查覆盖、推荐合理性和学习效果分别验收，不能用页面差异证明自适应有效。

低成本联动更新用相同输入、质量要求和环境下的整量处理作为对照，比较模型调用/用量、耗时、人工返工及未受影响内容保留情况；不虚设成本改善百分比。基础功能的稳定性记录完成、失败恢复和人工介入，全面分析记录对象覆盖与可追溯依据，成长效果依赖实际学习表现。

### 外部能力与运行约束

文本模型固定浙大自建 `qwen3.8-27b`，由 `text_ai_provider_policy.py` 校验，所有模型请求复用 `AIBase` 与 `ai_capacity.py`。不可用时返回可恢复失败，不能切换外部文本兜底。独立图像生成不属于文本模型路由。

课程联网来源目前冻结保留：不显示入口、不执行课程检索、不进入新课程生成；现有代码与历史数据保留，重新启用、扩展或删除需明确授权。用户代码仅在独立 `runner/` 执行。日志和产品使用事件不保存正文、答案、Prompt、凭据或用户敏感信息。

服务器与数据隔离、发布和恢复按[仓库发布说明](../../../deploy/README.md)及[应用 README](../README.md)执行；HTML 与 SPA 回退页禁止缓存或重新验证，哈希静态资源可以长缓存。

## 产品建设与比赛表达

产品同时服务教师与学生；比赛以教师智能体为立项主体，围绕备课、课程使用及有依据的教学调整组织展示。学生自主学习仍是完整产品能力，不因展示主次而删除。具体参赛表述须对照原申报材料，不能由比赛叙事改变已经确认的产品范围。

## 设计与验证怎样对应

功能设计写目标及其条件，代码体现实际实现，验收提供特定版本和范围的证据，[产品状态](产品状态.md)只列二者的差距。需求改变时修改对应业务正文及受影响关系，不把当前实现倒写成目标，也不按日追加日志。

课程生产完成要能交付可用且完整的材料；修改完成要能证明范围、影响、回执和恢复；学习服务完成要能证明身份、课程版本和真实事实闭环；PPT 完成要证明来源、页面与最终文件一致。测试通过、真实模型可用、浏览器体验和生产验收分别记录。教学效果还需后续真实证据，不能由生成成功推定。
