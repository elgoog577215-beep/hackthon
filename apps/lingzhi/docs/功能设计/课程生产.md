# 课程生产

本业务将教师的教学目标或学生的学习目标、资料形成可持续使用和修改的课程；教师专用教学材料在共同课程上按需产生。共享身份、真源与状态见[产品蓝图](../产品蓝图.md)，具体教学字段及待审样例见[教学内容模板](../教学内容模板.md)。下述是目标合同，交付差距见[产品状态](../产品状态.md)。

## 一、内容设计

课程输入保存目标、学习目的、八类一级学科、课程教学类型、学习起点、难度、时长、课堂条件和资料。目标难度与学生起点分开：难度落实为挑战、支架、独立性与迁移，不能靠篇幅、术语或题量伪造。

大纲保存课程目标、育人目标、可测成果、成果关联、考核、知识内容、应用载体、资源、任务和分类学时。本讲教案必须有教师动作、学习者行动、可观察证据、检查方式、达到/部分达到/未达到的处理、支持条件与前后衔接；只有活动名称或内容摘要不构成教案。

讲义为师生共用的教材式材料，包含当前范围内的定义、边界、公式与推导、例题、练习作业、参考解答、辨析和总结；依据教案展开完整知识，不要求口播、模拟学生回应或课堂调度。沿用内部 `script` 标识不改变这种产品含义。

原件只有一份不可变副本，正式目标分别保存主来源、参考资料及模板关系。题目、试卷、量规、日历与配套文件引用同一课程依据，各自保存正式修订。

### 两种用途的输入与产物

| 项目 | 教师备课 | 学生自主学习 |
| --- | --- | --- |
| 输入 | 教学对象、目标、学科、课时、课堂条件、学校栏目和资料 | 本人目标、基础、范围、时间与资料，不要求填写行政栏目 |
| 共同结果 | 课程范围、讲次、完整正文、题目及来源修订 | 使用同一内容定义与生成能力，不另设学生版正文协议 |
| 专用结果 | 教案、教学日历、评分标准、PPT 等按既有模板产生 | 笔记、作答、错题、学习进度由实际学习产生，不能在生成时编造 |
| 规划方式 | 教案作为教师可读可编辑的教学设计文件 | 复用必要教学规划作为内部依据，不强迫学生操作教案或导出教案 |

已有讲义生成依赖教师教案的实现须被整理为可复用的教学规划能力；设计目标不要求生成两份计划。教师文件和学生内部规划消费同一必要结构，用途差异不由两个 Prompt 各自解释。

## 二、逻辑设计

### 共有过程与学生生成、导入

共有过程为“目标与资料 → 范围及讲次规划 → 必要教学结构 → 正文 → 题目与可选产物”。业务规则、来源、质量检查、正式写入和恢复复用；教师和学生的可见步骤按各自任务组织。

学生确认学习范围后明确启动生成，必要内部规划不再要求第二次进入教师教案阶段。正文按讲独立交付，题目逐项可用；不等待 PPT、日历或评分文件才允许学习。未能形成必需规划时说明缺失原因并保留现场，不能以教师默认信息补齐未知条件。

学生导入走现有持久导入能力，复用解析、所有权、来源及内容结构检查；在核对范围和明确提交后保存正式课程。原文与映射来源保留，格式或语义不确定时标记问题，不凭空生成替代正文。相同提交的幂等身份防止重复建课。

生成所得内容是否可用和是否授权他人访问分开。新课程归创建者，访问授权遵守蓝图；学生无需教师角色即可操作自有课程。共有任务记录发起者、课程、用途、来源修订与范围，权限来自正式身份和归属，不信任前端传来的教师模式标志。

### 备课主链

| 环节 | 输入与处理 | 结果与用户决定 |
| --- | --- | --- |
| 创建课程 | 教师填写设计依据，选择从零开始或已有材料；材料解析和用途识别合入同一课程 | 创建失败保留表单；导入成功与 AI 理解成功分开 |
| 大纲方案 | 先形成讲次、标题和简介的轻量方案，可逐项编辑 | 主动等待教师继续，不在刷新后自动生成详情 |
| 完整大纲 | 冻结最新方案与资料范围，形成课程级合同，把全部讲次详情一次入队 | 按方案顺序汇编；非空、结构可用、来源有效后成为当前修订 |
| 分讲教案 | 从当前大纲投影全课预览，按本讲目标、课型、学科与条件形成教学环节 | 每讲独立生成和保存；完成即可编辑，无附加人工确认 |
| 分讲讲义 | 冻结当前教案与有序小节，按块请求完整正文 | 每讲独立交付，不等待整课或 PPT；结构和来源通过即可使用 |
| 其他材料 | 题库、评价量规、教学日历、配套文档消费同一基线 | 独立生成，缺少它们不阻断已可用讲义 |
| 教学表达与使用 | 当前讲义进入独立页面内容稿流程；教师阅读、导出、预览或实际使用 | [PPT 业务](PPT与教学表达.md)维护独立确认；导出成功不等于教学有效 |

### 生成与恢复

生成前固定对象、来源修订、范围、资料作用域、教师要求、模板及输出约束。批量启动一次入队，逐讲独立成功、失败、保存和恢复。课程进度以全部正式讲次为分母，最新重试批次只是尝试明细。

大纲可在原任务检查点中完成交付前优化，教案保留自身检查及有界修复；**讲义仅检查非空、块身份、顺序和来源绑定，不做内容审核、模型改写或失败自动重跑**。确定性格式问题本地处理，中断保留完成块和真实片段，有权限的发起者主动继续只请求缺失块；服务重启不自动重跑讲义。不以删减教学内容或占位文字伪装提速和成功。

| 情况 | 恢复约束 |
| --- | --- |
| 页面断连、切换或关闭 | 只停止观察；重新进入按原 task ID 对账，不新建任务 |
| 暂停或主动等待 | 保留检查点，有权控制任务的用户明确继续才调用后续单元 |
| 取消 | 保留已有可用产物；不能自动续作或作为另一任务的无条件恢复源 |
| 原输入未变、部分失败 | 沿合法检查点只处理缺失内容，阶段规则决定是否允许自动重试 |
| 来源变化、保存冲突 | 拒绝迟到写入；说明变更并由用户决定新尝试，不能复用过期输入 |
| 编辑未保存 | 保留人工输入，切讲、切阶段和离开前先完成保存或明确放弃 |
| 新尝试失败 | 最后可用修订仍存在，显示本次问题而不伪造“没有教案” |

质量报告分别说明正文、难度、资料、知识、题目和一致性；不以平均分掩盖答案矛盾。改变通过状态或错误代码时更新合同版本；可本地重算的检查不再次调用模型。大纲、教案、讲义不提供任意历史浏览/恢复，内部修订仅服务并发保护、候选撤销等安全机制。

### 文件、题目与配套材料

原件移除引用不等于删除；被正式产物引用的原件受到删除保护。新增材料要重新分析完整工作包，但不能覆盖教师已确认的文件用途。资料变化进入[审计与更新中心](课程修改与教学反馈.md)，不得悄悄改写正文。复杂图片、公式或动画含义不确定时保留能力边界，不编造解析内容。

普通练习经题面、作答合同和答案一致性硬检查后直接发布；综合考核及要求对真实个体采取高后果行动的题目保留教师确认。每讲按概念辨析、目标应用、迁移掌握划分槽位，一题聚焦一个主要知识或误区目标。单题成功即可写入题库，重生失败保留旧题；恢复只处理缺失槽位，不撤回其他成功题。

日历读取课程与讲次安排，量规绑定任务与评价证据，图解绑定讲义来源；不得各自重新解释课程目标。配套文档以结构化输入和版本化模板形成修订，导出只是投影。

## 三、交互设计

### 工作空间与入口

教师备课保留下述成熟界面；学生创建、导入和学习入口见[学生学习](学生学习.md)。两种表单归一到共同目标、资料与范围，但不要求行政字段相同。学生只看到本人任务和获授权课程，不经教师预览模式持久保存。

### 教师首页与创建课程

- 我的课程和我的日历在同一教师首页切换。
- 默认进入我的课程，以平铺数据表显示课程身份、备课状态、下次上课与地点、学年学期和最后编辑。保留搜索、状态/学期筛选、排序、分页、直接删除和多选批量删除，不另设卡片模式或视图切换。
- 新建课程收集中英文课程名、课程代码、层次、类别、学分、周/总学时、先修课、学年学期、星期、节次和地点，并明确学生、目标、学科、教学方式与教师要求。
- 教师选择从零开始或基于已有资料，两种路径最终进入同一个课程工作台。
- 已有资料在进入工作台前完成用途识别和集中确认，但文件导入不成为独立教学步骤。
- 创建失败时保留已经填写的内容并给出重试或退出方法。

### 课程工作台

- 左侧固定显示大纲、教案、讲义和演示课件四个主阶段。
- 大纲不展开讲次目录；教案、讲义和演示课件使用同一讲次顺序。
- 中间区域显示当前对象的输入、生成过程、当前修订、阅读、编辑和差异。
- 右侧区域随任务变化：生成前显示资料和要求，生成中显示真实进度和控制，生成后显示来源、修订和影响。
- 课程生成问题摘要、大纲与分讲生成失败、任务启动和课次读取错误统一放入右栏状态区，保留详情与恢复入口；正文和讲次目录不插入这类提示横幅。右栏收起后消息保留，再次展开可继续查看。右栏按当前状态、失败原因与详情、操作按钮顺序排布，同一失败只显示一组说明；按钮与消息左对齐，恢复操作等宽纵向排列，生成和暂停时切换为对应控制。已有可用内容与最近一次失败分别表达，新尝试开始后不残留旧失败操作。
- 教师可以自由切换阶段，但系统根据真实依赖决定哪些动作可用。
- 生成完成后原位进入当前结果，不自动跳到下一讲或下一阶段。
- 学生视角预览保持原完整学习界面和组件，通过原 Store 的预览作用域读取教师公开正文；练习、问答和临时笔记只存在于本次预览内存，不加载或写入正式学习记录。

### 课程文件空间

一级目录固定承载教学大纲、分讲教案、讲义、演示课件、其他课程文件、课程资料和回收站。

- 正式课程文件读取同一课程和讲次关系，不复制底层内容。
- 上传原件只保存一次，再与正式对象建立主来源、参考资料或模板关系。
- 单击选择，明确打开动作进入查看或编辑；批量操作只在多选后出现。
- 删除默认进入回收站；仍被正式内容引用的资料不能直接删除。
- 固定正式对象缺失时显示未生成，重复生成形成新修订而不是并列副本。
- 文件变化进入审计与更新中心，工作台只接收教师确认后的来源关系和调整候选。

### 批量生成与任务反馈

- 教案和讲义默认只显示整课生成入口。
- 全部讲次一次进入任务队列，每讲显示真实状态和当前结果。
- 完成的讲次立即可以查看和使用。
- 某讲失败时原操作切换为重新生成，只恢复失败或缺失讲次。
- 题库中的普通 AI 练习题通过可用性硬检查后直接出现；教师不需要先批准。教师对某题不满意时，可填写改进意见并只重新生成该题；新题失败时原题继续可用。综合考核和要求真实个体采取高后果行动的题目继续明确等待教师确认。
- 题库生成先选择整门课程、连续讲次或指定讲次。连续范围用开始和结束讲次确定；指定范围逐项勾选并可全选、清空。界面就近显示已选讲次数，未选择任何讲次时禁用开始生成，避免误发整课任务。
- 题库浏览使用“讲次—本讲题目—题目详情”三层关系。切换讲次后，搜索、筛选、分页和上一题/下一题只作用于本讲；未归入正式讲次的历史或导入题集中显示在“其他题目”。生成失败默认只在题库标题旁显示紧凑结论和重试入口，详细原因与进度按需展开，不占用题目首屏。
- 暂停、取消、继续和恢复必须作用于真实任务。
- 页面关闭或刷新后重新进入，仍能查看和控制同一任务。
- 界面不使用虚假进度或整课遮罩掩盖部分完成和部分失败。

## 四、技术设计

### 共有生成与导入的改造责任

复用 `course_generation/`、`teaching_design/`、现有正文生成、题库和 TaskManager，按用途组织工作流。课程元信息、正式正文、教师专用产物和个人学习数据分别明确责任；同一种能力只有一套权限、修订与保存规则。

现有 `routers/courses.py` 和任务管理器对 `lesson_assets_v1` 的限制要一起调整，并保留教师行为和任务恢复；不能只移除路由的 410，或让学生伪造教师模式。同步 Markdown 与持久导入合并到同一领域写入规则，实际需要的入口可适配调用，不保留绕过校验的独立写入。

必要教学规划由共有能力形成可追溯结构，教师教案是面向教学的产物，学生课程不被教师文件生命周期控制。仓储复用或迁移遵守[蓝图](../产品蓝图.md#正式数据的拥有者)，新写入不能落到两份独立正文。

### 正式写入与读取

当前 `teacher_lesson_authoring.py` 与原仓储拥有教师分讲教案、讲义及修订；这说明现有实现位置，不把教师仓储名称变成学生创建课程的角色要求。`teacher_content_projection.py` 只在内存投影正文；任何生成、导入、人工保存、AI 采用和全课调整都回到同一写入边界。`teacher_outline_source.py` 选择当前可用大纲，失败的新尝试不覆盖原大纲；`teacher_asset_readiness.py` 逐讲检查准入，不以整课可用推断每讲可用。

`teacher_script.py` 的 `teacher_script_quality_v12` 处理结构与绑定，`handout_prose_v1` 冻结讲义输入。讲次任务原子去重；`ai_capacity.py` 管理真实模型请求容量、按用户/课程轮转并优先较前讲次。排队不耗请求期限，心跳和检查点区分排队、活跃和中断。模型调用不占课程文件事务锁。

`course_production_state.py` 统一解释当前修订、来源、任务与动作；前端 `shared/teacher-production-state.ts` 只读投影。`allowed_actions` 必须与 `action_targets` 的真实 task ID 成对传递，后端再次校验课程、资产与来源，不根据 latest job 猜任务。旧字段过渡必须有调用审计、迁移与退出条件，不能因为整理文档直接删除运行数据。

`teacherLessonAuthoring.ts` 管理一次观察入口、SSE 与有界快照补齐，切换只中断观察。流文字是工作预览，校验后的块才成为持久检查点；终态强制保存。`resume_job_id` 复用冻结输入，`retry_of_job_id` 表示输入变化后的新尝试，不能混用。组件返回保存成功与否，使用开始编辑时的修订避免覆盖并发修改。

### 教学语义编译

`teaching_design/compiler.py` 是统一入口：课程级输入形成整课合同，本讲目标/课型/学科/条件形成教学环节。`standards.py` 保存八类学科与画像；`lesson_arrangement.py` 组织专业动作。教师明确选择与推断分开保存，推断记录依据，冲突不能静默折中。

确定性代码负责分类、顺序、时长、预算和校验；版本化标准库负责动作、产物、证据和安全规则；Prompt 仅在当前环节产生正文、案例与反馈候选；工作流组合已有能力。旧 archetype、105 个模块和旧字段可作为待去重原料，不能继续拥有产品分类权。新学科扩展注册表与评测，不复制生成链。

### 文件和题库实现

`material_document_parser` 输出统一 `ParsedDocument / EvidenceBlock`：OOXML 直接解析，旧 Office 格式在隔离临时目录转换，PDF 保留页与区域，必要时本地 OCR。原件不改写。`course_material_understanding` 记录用途、位置、版本角色、原件关系及置信依据，模型失败显式标记 `rule_fallback`。

`question_bank_rebuild` 复用原 TaskManager，以 `node_id + practice_level` 为最小检查点；题目修订保留稳定 item ID。范围归一为整课或明确 node_ids，空范围拒绝。题库按讲次及其直接小节归组，未归属题进入“其他题目”，不得显示空讲次掩盖现有题目。

### 发布给学习者的内容与题目

生成完成不是共享许可。正文、教学私有材料、题干、提示、答案与评分信息分别投影，依据课程授权及题目作答状态返回。普通练习按既有提示/提交/解析规则反馈，高后果或综合考核继续保留教师门；不能因新增学生入口将私有答案或考核生成权限全部开放。

### 验证

分别检查教师从表单到大纲、教案、独立讲义，学生从目标/资料到正文与题目，以及学生导入后的实际学习；覆盖部分失败、手动续作、来源变更、并发保存与断连恢复，确认没有第二份正文。固定样例验证结构，跨学科真实模型及教师评议验证内容质量，两者不能互相替代。测试入口为 `backend/tests/test_teacher_lesson_authoring.py`、`test_teacher_outline_source_state.py`、`test_course_production_state.py` 及对应前端测试。
