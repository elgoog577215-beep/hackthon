# 课程知识树规格

规格版本：`course_knowledge_tree_spec_v38`，更新日期：2026-10-20。本文是灵知课程知识树的正式业务规格，确定每课知识树、元问题与元知识、完整教学关联、JSON 持久化、关联指针与强度、版本与验收规则，以及“沿用原备课链路生成讲义，再提取课程知识树”的生产方向。当前本讲讲义入口在单次知识候选生成中并行执行有限的树形分类和关系分析，并支持已采用基线的独立关系补充；旧课程与 C17 样板保持原合同。整课自动提取、学科质量与生产发布仍未验收。未列入当前合同的 AI 编排、材料不足策略与后续预算见讨论稿，不因写入规格就视为已实现。

[C语言知识树样板](../研究/C语言知识树样板.md)已将变量与类型、if、for 三个基础分支展开为 119 个基础条目，并补充元问题、元知识点、能力、易错、诊断和补救的三个深化样板。119 个条目仍需按新的元知识标准逐项重整，不能全部直接视为已审定的原子叶子；完整课程绑定与产品实现仍待完善；C17 三组的最小网站流程见下文试点合同。它是本规格的内容样板，不是第二份业务规则。

2026-10-11 已完成[三组千问隔离实测](../验收/知识树三组千问实测-2026-10-11.md)：9 次真实调用完成生成、自审和一次修正，但仍有颗粒度、关联与诊断题问题，修正还引入新错。该结果用于下一轮质量控制讨论，不表示正式课程基线生成已验收通过。

同日完成[改进对比](../验收/知识树三组千问改进对比-2026-10-11.md)：专门原子化、代码执行反馈、A/B 错因和差量守卫共 15 次调用，代码核验与范围保护有效，但最终覆盖与诊断未全面改善，for 拆分未完整落地。实验支持进一步简化模型编辑接口、统一代码答案来源，并继续做语义核对；不据此启用正式讲义生成前置。

第三轮已实现并实测[程序组装语义拆分与答案证据绑定](../验收/知识树语义拆分与答案绑定实测-2026-10-11.md)，交付 [40 点候选树](../研究/C语言三组知识树千问候选.md)及 JSON。结构操作可保存，14 个运行样例绑定了实际答案；核心语义、检查覆盖和三条诊断仍未通过整体采用。隔离实验程序不承担正式课程保存责任。

[第四轮](../验收/知识树讲义基线样板第四轮-2026-10-11.md)先校正知识核，再以千问分批生成检查、选择诊断参数及生成关系，交付 [49 点讲义基线样本](../研究/C语言三组知识树讲义基线样本.md)。经 Codex 复核修订后，49 个检查、34 项范围和三套可执行错因诊断通过本轮样板内容门槛；千问最终仍有一处反向解释被 Codex 修正。样板通过不等于千问全自动通过、学科教师验收或正式课程采用。

适用范围为灵知 `apps/lingzhi`，参考 WenCode 源码的知识组织方式。课程正文仍按“课程 → 第 N 讲”组织；知识树作为本课程知识库的分类视图，通过引用关联讲次、正文和题目。[产品蓝图](../产品蓝图.md)与[学生学习](学生学习.md)共同指向本规格。知识树及其知识关系现已纳入独立设计范围，不自动解冻学生空间其他工作，不修改启智应用。


## 当前网站生成顺序（2026-10-12）

知识树在原工作台中间按讲次查看，使用上一讲、下一讲和讲次选择。生成请求只冻结本讲讲义，自动带入已采用课程知识树的分类、元知识 ID、定义、条件及已有关系作为参考；不把其他讲正文重复送入。候选和失败记录按讲次区分，采用时只更新本讲所属知识和关系，其他讲的内容、讲义和历史保留。互不影响的讲次候选可顺序采用；本讲来源、知识或实际引用的已有定义发生变化时拒绝覆盖，合并后的全课先修环再次检查。

与已有元知识等价时显式复用其 ID 和定义，不通过名称猜测合并；只增加讲次/来源绑定时保留原元知识语义修订。旧整树流程支持模型提出跨讲先修、推导、应用、对比、等价、推广关系，每条关系至少连接一个本讲知识点，并记录目标和依据版本、理由、条件。新分批知识流程保留旧边，采用元知识后可独立分析先修、推导与应用关系，见下文。未知端点、改写旧定义和合并后的先修环均拒绝。关联是待采用建议，不推断掌握程度、不自动重写其他讲；点击跨讲关联在同一工作台切换到目标讲次和元知识。


新建课程进入原备课工作台：填写课程信息，按需上传资料，生成大纲、教案与讲义。资料不是必填项；不再展示独立“课程资料生成知识树”的新课路线。知识树入口位于讲义之后，无讲义时引导准备讲义，有讲义时直接提取候选。旧知识先行课程保留原 ID、讲义与历史，只调整入口；不批量转换正文。

知识树读取原讲义仓储的当前讲义修订及完成块，冻结讲次、讲义修订、段落 ID 和内容哈希。知识点保留逐字引文与具体段落定位，明示讲义是生成内容，不把引文匹配冒充学科正确性。采用候选仅保存知识树新版本，不修改讲义或重排讲次。讲义、课程信息或权限在生成或采用期间变化时拒绝覆盖；历史知识版本仍可读取。

教师工作台按当前所选讲次对照知识树提取时与当前可用讲义的版本；来源变化或当前版本不可用时显示核对提示，候选暂不能采用。旧知识树仍可浏览其定义、关系与来源原文。没有讲义来源记录的历史材料树继续使用原有读取方式；版本对照只说明来源身份，不表示内容已经学科核验。

页面默认只显示任务状态、关系数量和采用前待核对项数。关系选择、逐条依据、独立关系历史及采用确认按需展开；折叠不改变采用前校验或原始记录，中英文行为一致。 元知识详情中的关联列表默认仅显示关联点名称、方向和关系类型；点击名称跳转，关系理由、条件、教学场景、强度、推导、冻结依据及关联点正文统一在“详情”内按需展开，切换知识点时恢复折叠。

目录按知识逻辑递归显示分类，不固定目标深度或最大层数，各分支独立决定何时停止细分，叶子无需对齐；不通过同义套层或拆碎单一命题凑深度；分类调整不改变同一命题的知识身份。例题仅为应用来源，不冒充一般规则。模型请求沿用学校千问与既有预算。本讲入口按下述有限清单与细化批次运行，知识候选使用下述有限提取、一次内容核对及有界定点修正，不重跑整批或形成无限审核循环；讲义仍遵守原结构/来源检查边界，不因此加入讲义审核或改写。旧整树响应保留原有主动重检，分批响应不能借旧重检入口绕过覆盖检查。

知识树的课程、分类和元知识标签，以及详情标题、适用条件和关联说明，复用现有安全公式渲染链。带数学分隔符的分式、上下标及函数记号显示为数学排版，不把 LaTeX 命令当普通文字；中文陈述、普通文本及金额保留原样。长公式在节点中可滚动查看，详情保留完整排版；显示转换不改知识名称原值、命题、条件、身份或来源，也不触发模型重生成。

全部知识点细化完成后，按 `knowledge_hierarchy_v5` 整理整讲层级。模型先划分大主题，再为每个主题生成完整递归子树，子树有限并发；不同分支深度可以不同。子分类必须缩小知识范围，不允许同名祖先套层或以固定层数凑深度。单点主题直接停止，不为一个点增加空层；节点数和模型输入输出仍受本次有限预算约束。

分类队列与每个完成分支保存于原任务检查点，失败后主动继续只处理未完成分支，不重做已保存分类或知识点。 子树分类仅缺少部分归属时，在同一任务内最多一次补全缺失短键；冻结已有分类与归属，模型只选择缺失知识的已有分类短键或直接归属，随后重新校验完整子树。未知知识、未知分类或越界改动仍失败。原始子树响应、补全响应与错误保存于对应分支；不会因失败重跑已经完成的其他分支或关系。旧的平铺候选可主动“整理本讲层级”，新建候选保留原任务、正式树、知识正文、来源及语义修订，不自动采用。页面只显示阶段与百分比进度；分支划分依据留在后台记录，不恢复批次、耗时或诊断面板。

## 知识清单与分批细化（2026-10-17）

本讲讲义入口显式请求 `inventory_atomic_v1`，新 API 请求默认 `extraction_mode=single_pass_v1` 并在同一候选任务中启用 `include_relations=true`。完整来源块按约一千八百字符组批，不截断正文；每组一次主提取产生清单、一般命题、条件、附件与元问题，另作固定一次内容核对；只有本地检查能精确定位错误点时，才按冻结处理合同进行有界限域修正。程序装配原清单和叶子合同，不反复抄写同一命题。条件、边界和例题作为附件或范围信息保留，教学安排与重复演示保留为有理由的背景。单块超预算时拒绝调用并保留任务，不裁剪原文。

直接提取与其递归子树默认最多四路并发，可用 `COURSE_KNOWLEDGE_EXTRACT_CONCURRENCY` 在一至四路内调整；递归树与关系对照并行运行，关系默认每批八点、四路并发，分别可用 `COURSE_KNOWLEDGE_TREE_RELATION_BATCH_SIZE`（二至十六点）与 `COURSE_KNOWLEDGE_TREE_RELATION_CONCURRENCY`（一至四路）调整；所有请求继续服从共享模型容量控制。每批完成后先核对冻结来源，再校验和保存；完成顺序不改变批次键和最终知识顺序。系统故障、来源变化或取消后停止领取新批次；新合同的批次质量失败先汇总独立来源批次，已在途的独立成功批次仍保存；完整响应未通过校验时保存在其所属批次及错误字段中，主动继续只处理未完成批次。过程心跳、计数与模型耗时留在当前任务的内存投影，随下一检查点或失败状态一并持久化，避免逐条重写完整课程历史；已校验知识通过 SSE 逐批显示为不可采用预览。保存历史使用紧凑 JSON，保持原有磁盘刷新、原子替换及读取兼容。

关系请求冻结完整知识目录和本讲焦点，树形分类与关系可并行；已有且端点仍有效的边保留。新直接提取任务使用 `knowledge_tree_relations_v4` 的 `candidate_edges_v2`：程序先列出能满足现有直接引用必要条件的定向点对，固定真实源、目标、引用及各自前提，模型只选择E短键并给类型、理由、场景、额外条件及必要推导。候选表额外冻结allowed_types、allowed_necessities与谓词角色依据。应用仅面向实际使用源操作/规则的完整方法，属性描述和复述不能冒充应用；推荐先学不冒充必要前置，只有明确冻结的必要条件支持required。仅当前角色检查支持的定义蕴含等推导进入候选，不能因写出两句话就认定推出任意算法复杂度。此候选表不证明逻辑关系成立，不能按同章或同名强连；推导仍须得到目标结论及其复杂度上界。

每个有可接受候选点对的焦点都必须有模型取舍记录，缺失不能自动补成通过。没有本焦点负责的合格点对时，只记程序范围排除，可免去模型请求；这不是模型语义判断，`model_reviewed_points`与`program_excluded_points`分别统计。无边焦点可省略稀疏边数组，但不能给其他焦点夹带点对。重复建议按真实方向、类型、场景和条件去重，不以批次归属倒转方向。

未知候选短键、越界焦点、无效字段、错类型、缺推导步骤、推导未得到目标上界及其他无依据建议保留为排除记录，不进入图。单焦点数量受冻结可选点对和类型数约束，输入/输出仍受原预算限制。全部新边及旧边再次校验端点、身份和全课先修环；成环建议单列缺口，不删除原边。证据明确标记为程序绑定的已选冻结命题，不冒充模型挑选的短引文或独立学术文献。旧v2/v3及候选编号v1任务保留冻结协议，不自动切换；收紧谓词角色的候选编号v2用于新尝试。

旧任务继续其冻结模式，不自动切换或重写基线。兼容模式 `extraction_mode=''` 仍先建立清单再细化，每批默认八项、上限十二项；来源约四千五百字符组批，`COURSE_KNOWLEDGE_INVENTORY_BATCH_CHARS` 可在一千至九千字符内调整。两个阶段默认两路并发，`COURSE_KNOWLEDGE_BATCH_CONCURRENCY` 可在一至四路内调整。主动重做已冻结叶子仍使用原清单、条件与检查，不重发来源提取。

原文定位优先逐字对账。历史证据分段曾省略部分换行；只有记录的证据ID、讲义修订、正文块绑定一致，且原段落经同一分段算法可重现完整冻结证据时，才允许打开原段落上下文并明示分段格式差异，不声称精确字符位置。无法重现或正文变化仍拒绝，旧引文、ID和修订不改写。

直接提取的新任务另冻结 `source_unit_contract=complete_handout_blocks_v1`。输入以原作者仓储中的完整已保存讲义块为单位，证据适配器不再先按句长拆块；流程图、代码、公式及方法的开头、分支和结束判据一并进入同一来源单元。原输入身份继续绑定实际正文和修订，派生证据投影另有合同、内容哈希与包修订；预算不足明确停止，不截断正文。采用时按候选冻结的同一投影重新核对当前输入，实际正文变化仍拒绝。旧分段任务、候选和引用保留原合同；不得把旧来源编号直接搬进新的来源划分，使用完整块的新生成保留独立任务记录。

新建任务直接提取输出 `knowledge_extract_v9`，编译后沿用 `knowledge_inventory_passages_v3` 与 `knowledge_leaf_claims_v4`，外层仍为 `inventory_atomic_v1`。新合同使用完整冻结正文块，不在六百字符处切断方法或代码；单块超出预算时明确拒绝调用，不裁剪正文。冻结全讲的范围说明可作为其他块的范围证据，只限定分析模型，不能外推新事实。旧v1至v8任务保持原分段与响应合同，不自动迁移。

知识请求固定低温度0，使用简单JSON对象输出；类型、字段、来源、单一目标与覆盖由本地检查，不依赖复杂远端分支语法约束。事实使用一个主体、一个属性及其完整值；定义保留属概念与必要联合限定；对比保留两侧真实对象及一个维度；方法保留完整必要步骤和完成判据。四种形态只输出自身字段，不使用无意义的第二主体/取值空槽。名称、命题、答案及元问题从同一组槽位装配，真实前提进入元问题，符号须定义输入或计量对象。

每个来源批次固定进行一次 `knowledge_content_review_v1` 内容核对。每个初始点均须明确keep、replace、context或source_issue；遗漏、越界、未说明的删除或新增拒绝。新增只能来自对应冻结块。原始提取、核对响应、逐点决定及范围证据分别保留。同一模型的另一请求不是独立学科认证；不能把原文出处当真实性证明，也不能因一个有效上界不够紧就删除正确结论。

新建任务使用处理合同`knowledge_validation_pipeline_v4`，提取形态仍为`knowledge_extract_v9`。本轮实现与缩减验证范围见[去重与修正事务网页验收](../验收/知识树去重与修正事务网页验收-2026-10-19.md)。顺序固定为：逐块提取与一次内容核对 → 精确命题合并和逐点诊断 → 有界字段修正 → 全讲元问题对账 → 分类与关系。完全相同命题与条件在身份及重复问题校验前合并，保留全部清单、逐字来源、附件与核对出处；不同前提或不同答案不得按名称自动合并。

新建直接提取任务的同义核对升级为 `knowledge_equivalence_v4`。真实范围、否定条件、参数和量的含义仍须一致。只有“某符号表示某量”的说明，才可在冻结命题明确包含同一符号、唯一相同函数参数的情况下，将裸符号与函数记号的差别列为比较候选；符号大小写、参数不同、量名不同或额外范围均不能因此等同。此记号签名不自动合并知识：仍需逐对确认完整命题与原 conditions 双向只是重述，derived_equivalence、different、uncertain 和不完整的传递链继续分开。原条件不改写，双方完整来源与条件留在代表点及 semantic_equivalents。旧 v1/v2/v3 继续原范围检查。

完整块任务在显式继续时可升级同义协议，原任务保留。若旧全目录发现请求结构完整且冻结目录指纹一致，只将其作为原合同的候选建议复用，记录原任务和原合同，不冒充收到过新版提示；受新范围规则影响的逐对确认、分类与关系重新完成，提取和内容核对不重做。目录变化或发现记录与原始响应不一致则拒绝复用。最终同名校验仍保留，不靠给不同知识乱加编号或删点规避。

状态读取与生成写入分开限流：仅 GET 状态与已有任务事件连接使用每客户端、每路径每分钟 120 次的观察预算，完整知识视图和生成等写入仍守原限制。自动查询遇到 429 按 Retry-After 等待，聚焦窗口不绕过等待；已有读取未结束时不并发启动自动查询。刷新状态是独立只读操作，不因内容命令等待而锁住，手动请求期间显示“正在刷新”并防止重复点击。权限失效仍停止自动观察，刷新不创建、重试或取消生成任务。

首次进入与任务结果发生变化时读取完整知识视图；持续观察使用仅含任务元数据、阻塞范围和结果版本的轻量状态查询，不重复传输知识正文、历史版本、候选和讲义。临时连接故障保留已显示内容并退避恢复观察，关闭页面停止观察；权限失效停止自动查询，待用户核对权限后主动刷新。暂停、取消或已经失败的任务均不得因此自动继续。运行中请求的有限连接恢复只处理原请求；额度耗尽后保存真实失败阶段及批次，不能因并发分支的后续进度覆盖。显式继续保留原尝试，只处理未完成批次；较旧候选不得遮挡较新失败任务的恢复入口。模型连接恢复与网页状态查询故障分别显示，状态受限说明稍后自动更新，不能误标为 AI 断线；不展开诊断长文。状态读取遵守课程所有者权限，授权阅读者不获得教师任务状态。

生成记录继续保存与当前讲次、知识版本匹配的缺口和未引用来源片段，不把记录缺失或零条缺口解释为知识完整。工作台不恢复独立的缺口统计、耗时或模型诊断面板；采用前的阻塞、复合命题、身份变化和关系确认仍保留。来源片段引用数不作为知识覆盖率或学科准确性结论。轻量观察本身不增加模型调用；有限内容核对和修正的调用另行计量，不因刷新或轮询重复发起。采用仍走原确认流程。核对内审信息只供拥有者，公开树投影不携带逐点content_review。

## 原文依据与术语

元知识命题与引文分别保存。新候选支持连续逐字短引文，程序校验其确实出现在指定来源片段中；原文直述、归纳、推导由模型另行标注，推导说明单独保存，均不冒充学科核验。旧的来源短键及段落引用继续读取，并明示其尚无更细的句子范围。新输出使用 `knowledge_source_evidence_v2` 证据合同，现有讲义来源合同继续兼容。

英文名称、缩写及其他译名须绑定本知识点引用来源中的实际标注。注释保留完整实体名，不能把优先队列等名称截为队列；重叠名称按完整跨度确认。可证的旧自动后缀误绑只读降为待确认，不删除原手工检索别名、不改知识ID或修订。无法从原文确认的模型术语单独保留待确认，不进入正式检索别名。同一英文的不同原文名称分别展示，不据此合并知识身份。旧知识树可从已保存引文进行只读术语投影，保留原有手工别名，不改写课程文件、不重算知识 ID 或语义修订。检索覆盖名称、命题、已绑定英文、缩写及别名，中文和英文桌面保持同一行为；学生只读知识树保留适用的术语与检索能力。

拥有者可在知识详情内打开引用版本的来源位置，查看来源类别、版本、内容块或资料页码、引用片段与上下文。讲义按引用时的修订、章节及内容块定位；资料按本课程已冻结的来源片段定位。原版本缺失或引文不匹配时保留引用快照并明确说明，禁止静默替换为当前讲义。来源真实性与命题正确性分别说明，生成讲义不标为独立学术原文。历史与候选来源接口只供课程拥有者读取，不向已发布课程的其他阅读者开放教师私有版本，也不新增联网取材或模型审核调用。

## 当前实施范围：先完成知识树地基

当前优先实现“知识清单 → 原子化 → 分类树”。暂停扩展自动出题、能力包、错因诊断、补救和迁移生成；已有教学样板、正式知识基线与讲义继续保留。当前默认方向调整为“先生成讲义，再提取与采用知识树”。

1. **范围冻结**：固定本课学段、学习目标、材料、适用条件和排除范围。准确性与完整性相对于该范围验收，不根据课程标题补全材料未支持的知识。
2. **知识清单**：从材料抽取概念、规则、方法、条件、否定及推断边界，每项保存来源 ID、原文片段与位置。案例、范围前提和通用知识分别标记；先抽知识，再组织目录。
3. **原子化**：每个叶子回答一个明确对象在明确条件下的独立问题。能分别判断的命题拆分；同一定义不可缺少的联合条件可保持整体，不机械拆词。清单每一项必须说明如何被知识点、条件、边界或案例承载；不以已有节点数量冒充材料覆盖。
4. **分类树**：仅分配已冻结知识点的归属、层级与分类名，不改写知识正文、条件或来源。一个知识点只有一个主要位置，无孤点、重复归属或分类环；深度由知识需要决定，避免同义套层。先修、关联强度后续单独补充，本阶段不要求生成。

首版叶子保留稳定 ID、名称、元问题、核心结论、适用条件、边界、材料出处、分类引用和修订版本。元问题用于界定知识边界，不扩写为例题与评分包。材料—清单—叶子建立双向对照：可以查看一项材料由哪里承载，也可以追溯某叶子的证据。原文命中只证明引用真实，不证明模型的概括受到该原文支持。

验收分别报告：**准确性、覆盖、颗粒度、结构**。结构和引用可由程序核对；语义按冻结材料与逐项要求独立复核。每个叶子有题、模型自评通过、格式正确或数量增多均不能代替这四项验收。原始生成与程序装配结果分开保存，人工修订不得计作模型原始通过。

本轮在既有四学科短材料上执行三个阶段的隔离千问试验，每阶段一次请求，另设无材料对照；不写入正式课程，不声称整门课程已覆盖。现有教学合同继续作为后续阶段目标，不作为本阶段的生成任务或通过门槛。

### 定点精修与基线判定

知识清单已覆盖材料时，优先冻结清单与未受影响节点，以明确的字段/拆分意图精修，避免重新生成整棵树。模型只能修改计划允许的字段；程序负责拆分身份、旧新节点映射、范围条件继承、原文附件及分类调整。未涉及的知识正文必须保持一致。重述同一知识保留身份、更新修订；拆分产生新身份并保留旧点去向；纯范围叶子退为元数据，不能无记录消失。

每个叶子独立导出时同时保留本课范围、材料中的范围原文、点内条件及范围修订。分类或展示层不能通过省略父级上下文扩大该点适用范围。清单转述与原文有差异时以原文为依据，引用与承载理由不再附加无依据的知识结论。

本阶段基线要求：没有已发现的错误命题、错误核心回答或材料外断言；冻结材料要求均有正确承载；没有已定位的可独立判断复合点或范围/案例冒充元知识；分类完整且归属恰当；范围随独立节点保留。不可分割的定义联合条件、同一方法的必要步骤可保持整体，不以节点越多越好作为标准。

四份短材料的复核通过只表示本次微单元的知识内容达到样本基线，不等于整门课程完成、模型在其他材料上稳定通过、学科教师正式验收或网站自动采用。模型输出、程序组装、范围与分类人工决策、独立内容复核须分别说明。

## 层级如何组织

结构为“课程 → 大知识分支 → 子主题 → 必要的细分主题 → 元知识点”。中间分类支持递归，按知识本身的复杂度决定深度；同一棵树允许浅分支和多层复杂分支共存，不把固定深度或节点数量当作质量指标。

一个父分支说明自己覆盖的知识范围，子节点沿同一分类维度展开。同级节点避免混放知识、学习活动、例题和难度标签。分支太宽时按真实问题域继续分组；只含一个同义子节点时合并冗余层。每个知识点有一个主要分类位置，可以关联多个讲次或出现在其他分支的交叉引用中，正式知识记录只保存一份。

例如 C 语言可把“变量与类型”“条件分支 if”“循环 for”作为直接入口；是否将 if、switch 收到“选择结构”，将 for、while 收到“循环结构”，由该课程的知识规模与大纲决定。下面是示意片段，其他分支也需要按同样标准细化，不能以省略的分支代表完成：

```text
C 语言程序设计
├─ 变量与数据类型
│  ├─ 变量声明与初始化
│  │  ├─ 声明中的类型与标识符分别表达什么
│  │  ├─ 初始化发生在变量创建时
│  │  └─ 赋值会替换变量当前保存的值
│  ├─ 整数类型
│  │  ├─ 表示范围与类型选择
│  │  │  ├─ 根据数据范围选择能容纳结果的整数类型
│  │  │  └─ 中间运算结果也必须处于可表示范围内
│  │  └─ 整数运算
│  │     ├─ 整数除法会截去小数部分
│  │     └─ 将整数除法结果赋给浮点变量不能恢复小数部分
│  └─ 浮点类型
│     └─ 按本课精度、表示与运算范围继续细分
├─ 条件分支 if
│  ├─ 条件判断
│  │  ├─ 条件的零值与非零值决定分支选择
│  │  └─ 比较相等使用 ==，赋值使用 =
│  ├─ 分支结构
│  │  ├─ if 与 else 选择其中一个分支
│  │  └─ else 与最近的可匹配 if 配对
│  └─ 区间分类
│     ├─ 相邻区间的端点应有明确归属
│     └─ 条件判断顺序影响重叠条件的命中结果
├─ 循环 for
│  ├─ 执行过程
│  │  ├─ 初始化在进入循环时执行一次
│  │  ├─ 条件在每次执行循环体前检查
│  │  └─ 正常完成循环体后执行迭代表达式
│  ├─ 范围与次数
│  │  ├─ 从 0 开始以 i < n 遍历 n 个下标
│  │  └─ 步长影响被遍历到的值与循环次数
│  └─ 流程控制
│     ├─ break 结束所在的最内层循环
│     └─ for 中的 continue 转向迭代表达式后再判断条件
└─ 数组、字符串、函数、指针、结构体、文件等本课实际覆盖的分支
```

示例用于说明拆分方式，正式课程需要绑定采用的语言标准、编译环境和实际教学范围。C 课程不能直接继承 WenCode 中 C++/Python 的容器、默认参数或引用传参等内容；如果课程进行语言对比，应明确标注对比对象。

## 最小知识点标准

最小知识点在本方案中称为“元知识点”：它是在本课学习者的前置知识条件下，能够独立解释并独立检查的一条概念、规则、判断或操作。“元”是本产品的工作定义，表示本课程采用的最小教学单元，不声称存在脱离课程与学习者的绝对最小单位。它可以依赖其他知识点；“独立”指检查目标明确，不能要求完全没有前置知识。

| 标准 | 判定方法 |
| --- | --- |
| 单一语义 | 能用一句准确的话表达核心结论；若包含两个能分别学会或出错的结论，则继续拆分 |
| 边界清楚 | 说明适用对象、条件、限制；依赖语言版本或运行环境时记录该条件 |
| 可以解释 | 能给出针对本课的简短说明与一个例子，而不只重复节点名称 |
| 可以检查 | 至少给出一个检查任务及判定依据；可以是预测、解释、辨析、推导或操作，并非一律选择题 |
| 拆分有意义 | 再拆应能增加独立的教学或诊断价值；不把术语逐字拆开，不为了凑层数拆分 |
| 课程有依据 | 能定位本课内容，或被明确标为必要前置、推导补充、待确认范围；没有来源的生成内容不得冒充教材摘取 |

“指针”“for 循环”“掌握数据类型”仍是大主题。“整数除法向零截断”在给定合法操作数的条件下可以成为叶子；“整数除法规则与强制转换”通常需要拆成不同叶子。一条完整的定义或一个不可分割的最小操作，不因语句较长就强制拆分。原来把多个规则组合得到的应用结论直接作为叶子的条目，要保留内容并调整为综合问题或应用方法，连接其组成知识；不把每个例子中的数值另建知识点。

以“将整数除法结果赋给浮点变量不能恢复小数部分”为例，它适合成为一个综合辨析问题，其内部至少需要区分操作数类型、整数除法规则、结果转换时机；不能仅因能用一句话表达就断言它已经是最小知识点：

- 核心解释：`double x = 5 / 2;` 先执行整数除法，随后将结果转换成浮点值。
- 可观察能力：解释为什么 x 的值为 2.0，并说明如何让除法产生浮点结果。
- 检查任务：对比 `5 / 2`、`5.0 / 2` 和 `(double)5 / 2` 的结果与原因。
- 易错表现：认为接收结果的变量类型会反向改变此前的除法计算。
- 前置引用：整数除法、表达式求值、类型转换；分类父节点不自动成为前置知识。
- 本课定位：生成时绑定实际讲次与正文位置；示例本身不编造本地课程来源。

一次小检查只能提供该知识点的一条学习证据，不能自动宣布学生已经掌握。能力点、易错点、提升动作与掌握证据属于叶子的教学信息，不无限延伸为分类层级。

## 元问题与完整教学框架

知识树承载分类与元知识点；问题、能力、错误解释、练习和证据以明确关系连接这些知识点。在界面上可以呈现为一份完整节点档案，但它们具有不同身份与职责。教学目标还需通过综合任务检查多个元知识的协同使用，不能以“全部原子题做过一次”替代课程能力。

```text
课程目标与范围
  ├─ 主题分类树 → 元知识点 → 来源与前置知识
  ├─ 元问题 → 主要考查的元知识点
  ├─ 能力点 → 需要使用的一个或多个元知识点
  ├─ 诊断问题与作答证据 → 可能的易错原因
  ├─ 补救动作与变式任务 → 对应易错原因及元知识点
  └─ 综合任务与评价标准 → 课程目标及能力点
```

| 对象 | 回答的问题 | 最低内容 |
| --- | --- | --- |
| 元问题 | 学生当前究竟需要弄清哪个问题 | 单一主要判断目标、给定条件、预期解释或表现、主要知识引用；不要求所有学科都有唯一文字答案 |
| 元知识点 | 解决它所依赖的最小规则是什么 | 单一命题、适用条件、边界、前置引用、课程来源和修订 |
| 能力点 | 学生能用这些知识完成什么动作 | 可观察行为、所需知识、完成条件；不能只写“理解”“掌握” |
| 易错点 | 学生可能采用什么错误理解或策略 | 具体错误假设、可能表现、区分性追问、不能据此下结论的情形、对应补救 |
| 检查与练习 | 怎样获得有效的理解证据 | 题目条件、目标、参考判断、可接受表现、需要控制的其他因素；区分单点检查与综合任务 |
| 补救与提升 | 卡住后下一步做什么 | 具体解释、反例或操作步骤、复测方式、何时恢复后续学习；避免只写“多练习” |
| 学习证据 | 目前能支持怎样的判断 | 本人作答、解释、执行或作品、知识及题目修订、时间、评价依据；保留不确定性 |

一条元问题通常有一个主要知识目标，可附必要前置；综合题则分解为多个元问题。一个元知识点可被多个题目和能力引用；同一错答也可能有多个原因，不能强行一对一归因。同一规则在类型、if、for 中被使用时，通过引用复用，不能按页面复制三份正式内容。

每个正式元知识点至少要有一个可判定的元问题和检查方式，但不机械要求每点生成固定数量的易错点。有根据才建立错误候选，并区分教师确认、材料支持、历史学习证据与模型提出的假设；没有统计依据不宣称“高频错误”。

易错点采用完整诊断链：观察到什么 → 有哪些可能原因 → 用什么追问区分 → 采取什么补救 → 用什么新情境复测。答错只形成待验证解释，答对也可能来自记忆或猜测。学习记录先保存事实，掌握判断另行计算，不回写知识规则。

### 继续拆分与停止拆分

继续拆分有三个主要信号：学生可能分别掌握其中两部分；两部分错误需要不同补救；一个检查任务需要给出多个彼此独立的判定。停止拆分的条件是：在明确前置下，它已经有一个清晰教学目标与可区分的检查标准，继续拆只剩措辞、标点、某个例子的具体数值或没有独立教学意义的步骤。

语法符号本身也可能构成知识点，例如 for 的分号分隔规则，前提是课程确实需要单独教学并能检查；不能将“字符短”误认为不值得教学，也不能将“句子短”当成原子性的证据。原样保留已足够原子的条目，对复合条目重分类，对重复条目复用引用，不追求把 119 个条目机械扩成某个数量。

## 讲义后的知识树与产物联动

新课沿用原备课顺序，知识树提取不再作为讲义生成的先决条件。课程输入保存目标、起点与课时，资料可选；大纲与教案明确范围后生成讲义，再由拥有者发起知识树提取。

```text
课程信息与可选资料 → 大纲 → 教案 → 讲义
                                  ├─ 知识树候选 → 确认采用
                                  ├─ PPT 内容稿 → 确认后编译
                                  └─ 题目与其他已授权材料
```

知识树候选只引用当前讲义的真实段落，不负责重排讲次或反向改写正文。程序冻结讲义修订、段落 ID 与原文内容，模型引用来源短键，原段落由程序读取并保留；讲义中的定义、方法、边界与知识关系仍需拥有者审阅。资料为空不阻断原链路，尚无讲义时知识树面板提供返回备课的操作。

采用保存新的知识版本。旧讲义原先绑定的知识修订继续读取旧快照；没有绑定的普通讲义不会因采用知识树被暗中补写。知识树来源段落与正文消费知识版本是两种关系，分别记录，不能冒充全量正文引用已完成。新生成的本讲候选同时带出元知识直接关系，不再要求先采用后才能运行关系分析；在候选中检查分类、知识及关联后一次确认采用。

已有知识先行课程继续保留其原始知识、讲义与历史，相关兼容接口不作为新课入口。后续修改发现知识缺口时提出增补候选，由拥有者决定采用；正文新措辞不自动改写知识定义，也不触发相互重生。讲义生成仍只做原有结构与来源检查，不追加审核、自动改写或失败重跑。

### 批量联动依靠知识引用与产物依赖

每个下游对象或内容块需要记录所用 knowledge_id、知识修订、使用角色及来源产物修订。例如某讲义块使用 K1 的一组定义；PPT 页面引用该讲义块及其修订；一道题的题干、参考答案与评价依据分别绑定其知识和题目修订。可定位到块/字段时局部处理，只有文件级引用时如实报告较粗范围，不冒充精确定位。

必须区分两种关系：知识之间的教学关联，用于前置、对比、推荐与影响排查；知识到正文、题目、PPT 的真实引用，以及产物之间的来源依赖，用于决定具体更新对象。关联强度不直接触发文件重写，沿知识关系到达的节点先作为需检查的候选影响；只有语义变化与实际引用共同支持时才进入修改方案。

| 改动 | 推荐的联动处理 |
| --- | --- |
| 规范名称或别名调整 | 定位绑定该知识的命名字段与有关表述；保留需逐字引用的原文、代码标识和历史称谓，不做不分语境的全文替换 |
| 定义、条件、边界或规则修订 | 检查相关解释、例子、推导、题目答案及评价依据，生成必要的局部更新候选，再沿真实产物依赖更新后续内容 |
| 分类节点改名或移动 | 更新树的浏览结构与相关显示引用；知识语义未变时不据此重生讲义 |
| 前置关系或关联强度变化 | 更新相应学习提示、顺序建议或关联展示；是否影响正文须另行判断 |
| 元知识拆分、合并或移除 | 明确旧新 ID 映射及逐项引用处置；无法准确迁移的引用保留旧修订或标为待处理 |

“一键联动”推荐做成一个有明确范围的批量操作：提出知识变化 → 计算影响 → 生成选定范围的候选差异 → 统一审阅/批量采用 → 返回逐项回执。用户不必分别打开每份文档提出同一修改；正式采用继续遵守[课程修改与教学反馈](课程修改与教学反馈.md)的权限、保护项、领域命令与恢复规则。PPT 的内容稿确认可以在该批次中明确完成，最终渲染仍只编译已确认内容。

执行前核对全部所需的知识、正文及产物修订；执行中按真实依赖顺序推进。有后续文件未更新成功时，标明旧来源或待更新状态，保留最后可用版本并允许定向恢复，不能宣称跨仓储同时成功。人工保护内容、已有学生作答和私人笔记不被批量重写；个人派生材料由本人决定是否更新。已经下载或外发的文件只能生成新的导出版本，不能声称已远程改写其旧副本。

现有 `course_knowledge_impact.py`、`KnowledgeReferenceIndex` 与下游重建入口可作为基础，尚不能据模块存在宣称所有教师文件已经实现此链路。实现前需要核对各产物的引用粒度、有效关系状态、实际写入者和恢复合同；尤其不能把图中可达等同于必须修改，也不能将候选关系直接当作正式传播依据。

联动验收应覆盖：只改术语时无关正文保持；只移动分类时不重生成；规则变化后对应例子与答案完成一致更新；教师人工修改产生冲突时不覆盖；PPT/题库部分失败可定向恢复；旧作答继续指向旧题目修订。先知识树后讲义已经确定；树的具体编排、质量检查和联动采用的确切交互仍待讨论。

## AI 自动生成与质量控制讨论稿

以下提出具体的可试验方案；已经确定的生产顺序不再重开选择。推荐“课程范围规划 + 完整来源抽取 + 按需原子化 + 全课归并 + 教学关联 + 分项检查”。逻辑阶段不等于固定模型调用次数：可以在容量允许时合并相邻产物，按分支批量调用；超长来源分片后完整处理，不能给每个叶子机械安排多次请求。

### 知识树的生成步骤

1. **冻结本次课程输入。** 保存课程身份与已有资料/正文修订，收集课程目标、学习者起点、教学范围、选定教材和资料；课程纳入已有讲义，新课先通过原链路生成讲义。逐项记录纳入材料、解析失败和范围未知项。仅有标题或粗大纲且无法确定教学范围时，先生成范围草稿；缺口未解决前不能报告课程覆盖完整。
2. **建立课程范围清单与大分支。** 写清必学内容、必要前置和可选拓展，给出每个大分支的范围及来源。学科参考框架只用于发现可能遗漏；课程没有要求的高级知识不能自动混入必学范围。仅有标题时生成的框架属于待核对提案。
3. **逐份来源抽取候选知识。** 按完整语义片段处理全文，包括正文、公式、代码、表格和例题，保存原文位置。过长块继续切分并保留重叠与上下文，不能只取前若干字符。候选同时记录“源文明确表达”“根据源文推导”“通用知识补充”等来源方式。
4. **全课程归并与分类。** 综合全部讲次组织子主题，将同一语义的知识点合并并保留多处来源；不能只因名称相同就合并。不同语义的“初始化”“边界条件”等名称用上下文消歧。每个候选有正式归属、合并关系或排除理由。
5. **逐分支细化并装配教学内容。** 对混合多个命题的节点继续拆分；元知识点补充元问题、解释、适用条件、来源和检查依据，再关联能力、易错候选、区分性追问、补救与变式复测。综合题通过引用组合知识，不复制叶子。节点不足以拆分时直接说明原因。分支和调用预算用于控制任务规模，达到预算时保留未完成状态，不伪装成已达到最小颗粒度。
6. **反向核查覆盖和来源。** 从原始范围清单与来源片段逐项核对是否被树覆盖，再从每个叶子回查本课依据。检查者读取原始材料，不能仅阅读生成树或只接受模型给出的“100%”自评分。未覆盖、过粗、重复、越界或来源不足的项形成具体问题清单。
7. **形成可采用的版本。** 先完成确定性的结构、引用和权限校验，再展示候选与缺口。拥有者可采用、编辑或针对指定分支继续生成；已有正式版本在新版本失败时仍可读取。采用通过统一领域命令保存，返回版本与变化回执。

首次点击一次“生成知识树”后，系统完成上述计算流程；不要求用户逐层点击“继续拆分”。人工决定集中在范围确实不明、采用正式版本与主动处理失败/缺口的位置。检查只针对本次知识树产物，不重写或重新审核正式讲义。

文本生成沿用已批准的浙大 `qwen3.8-27b`。本功能不启用冻结的课程联网检索；当前查阅 WenCode 是开发规划参考，不是课程生成时的资料来源。

### 输入合同与中间产物

初始输入至少说明课程主题、学习者起点、目标深度、覆盖范围和可用课时/学习时长，语言或工具类课程还需明确版本。来源包括所选教材、课程要求、参考资料和已有大纲；先生成讲义，再冻结讲义版本作为知识抽取输入。未知条件显式保留，不让 AI 默认选择最高难度或无限扩展学科范围。

| 阶段 | 建议的持久中间产物 | 本阶段要回答的问题 |
| --- | --- | --- |
| 范围与来源整理 | scope_manifest、source_manifest | 哪些必学、哪些前置、哪些拓展；原始资料是否全部进入处理清单 |
| 主干规划与来源抽取 | 分类草稿、带来源片段的知识候选清单 | 大分支是否清楚；定义、规则、条件、边界、方法与例题隐含前置是否遗漏 |
| 原子化与全课归并 | 元知识候选、keep/split/merge/reclassify/needs_evidence 决定 | 每点是否能单独检查；同义是否重复、同名是否异义 |
| 教学内容装配 | 元问题、能力、例子、检查标准、错误假设与补救 | 这些字段能否支持实际学习和诊断，是否只是同一句模板的改写 |
| 关系提出 | 有类型、方向、情境、理由和强度的关系候选 | 为什么应连、方向是什么、在本课什么情况下有用 |
| 分项核对 | 颗粒度、覆盖、关系、易错内容各自的问题清单 | 问题具体位于哪个节点、来源或关系，有什么依据 |
| 局部修正与采用 | 有限修正结果、未解决缺口、版本与采用回执 | 哪些已完成、哪些仍需处理，是否可形成可追溯基线 |

这些是逻辑产物名称，具体字段和存储复用现有课程知识库与任务检查点，不新增平行 Store。目录主干与候选抽取可以相互校准；归并发生在整个课程范围内，不能只处理同一批或相邻叶子。

### 元知识够细的检查方式

对每个候选给出一条主要命题、一个主要元问题、适用边界和检查依据，再用“可分别掌握或出错”检验是否混合多个目标。检查输出必须是具体决定与证据，不能只返回 atomic=true 或一个颗粒度分数。

- **保留**：检查目标明确，条件下的结论单一；例如 else 按语法配对的规则。
- **拆分**：包含可以分别掌握、分别出错、需要不同补救的规则；返回各子命题及能够区分它们的检查问题。
- **归并**：两个候选在相同条件下表达同一知识；保留各自来源与别名，映射到一个身份。
- **重分类**：条目其实是综合应用问题、教学策略或例子；保留并关联组成知识，不为满足树形结构将其冒充原子事实。
- **待补依据**：无法明确适用条件、来源或检查标准；保留问题，不靠补一段泛化解释伪装完成。

以 `double x=5/2` 为例，要求分别判断字面量类型、除法类型、整数商处理与目标转换时机，并检查学生是否可能只在其中一项出错。“for 的初始化只执行一次”则不再为了凑深度拆成“什么是一次”等没有独立教学目标的叶子。不同学科采用自己的可观察检查方式，不能要求文学、历史或设计课程都转成代码式唯一数值答案。

### 覆盖全面的检查方式

推荐同时维护两张映射：课程范围项 → 元知识及能力；原始来源单元 → 元知识或明确排除理由。每个条目区分已覆盖、部分覆盖、未覆盖、待确认、重复/非知识内容等处置。原文有引用并不证明引用支持命题，映射的存在性由程序检查，语义支持还需核对。

覆盖审查从原始课程目标、所选材料和另一种组织视角反查。以 C 语言 for 分支为例，可依执行过程、边界、状态、控制转移、嵌套与终止性分别核查；这是本学科的审查维度，不要求所有分支都凑齐同一模板。检查者必须看完整的待审来源片段，而非只看生成树的摘要；批次状态需覆盖长文尾部、表格、代码和附注。

范围清单自身也要校核，不能让同一个遗漏同时出现在清单和知识树中，然后报告 100%。选定教材/大纲与学科教师确认的参考清单可以支撑范围审查；AI 自行补充的参考框架只作为补漏候选，不能自动扩大必学范围。已知范围和可解析来源的逐项处置可以对账，但无法凭此保证未知材料或整个学科绝无遗漏。

### 关联准确的检查方式

先稳定知识身份，再提关系；候选可来自显式前置、共同任务、对比题、跨讲复用和已有来源，不做全课无差别两两连边。每条关系分别审查命题语义、方向、适用情境与证据。

| 类型 | 需要的支持 | 不能充当支持的信号 |
| --- | --- | --- |
| 前置 | 说明在本课起点与任务下，理解/使用目标为什么需要或受益于源知识；区分 required 与 recommended | 单纯出现在前一讲、属于父分类、文字相似 |
| 推导 | 给出可检查的推导步骤和所需其他前提，结论与条件一致 | 只说“由此可知”、强度很高、同一资料中相邻出现 |
| 对比 | 明确相同点与关键差异，给出能区分两点的条件或任务 | 两者都涉及循环，或模型声称“学生经常混淆” |
| 应用 | 说明源规则在目标方法/知识中承担什么具体作用 | 名称同时出现在例题中，或知识在树上距离接近 |

程序检查引用闭合、重复边、对称规范和前置环；模型审查语义不能由这些结构检查替代。强度按已定三档表达同类型、同情境下的教学关联优先级，保留理由；可信程度和审阅状态独立保存。证据不足的关系保持候选，不进入正式的必要前置或文件传播依据。正确但非必要的关联可不连，不要求每个点具有固定数量的边。

### 易错内容准确的检查方式

先区分选定教材中的明确提醒、经授权的真实错误记录、教师经验与模型假设。一个可用的易错记录至少能写出：错误理解或策略 → 可预期表现 → 区分性追问 → 相反证据/其他可能原因 → 针对性补救 → 变式复测。

例如学生将 `double x=5/2` 判断为 2.5，至少可能是不知道整数除法，也可能知道该规则但认为左侧 double 会反向改变运算。诊断题先去掉左侧问 5/2，再恢复左侧，让两种错误假设产生不同的预测；不能把一个结果错误直接归因于其中一个知识点。

推荐的生成方式是先提出有教学依据的错误假设，再构造一个能暴露它的最小案例和一个能区分替代解释的追问。对于有确定求值语义的 C 示例，可以在受控执行环境中核对结果；未定义行为采用规则辨析或编译诊断，不用运行结果推导规范。其他学科依据对应材料、评价标准与专业审阅核对。

没有足够依据时允许易错列表为空或保留待审候选，不能强制每点生成三条，也不能把“粗心”“理解不深”“多练习”当成完整错因和补救。某个错误程序能复现，只说明技术现象成立，不证明学生真的持有该错误信念，更不能据此推断发生频率。

### 自动化边界与评测

推荐先采用“生成一版 → 分项检查 → 只修被指出的问题 → 达到预算后停止”的有界流程。首轮试验可考虑每个分支最多一次针对性语义修正，但该次数尚未冻结，需按真实模型效果与成本决定。格式保存失败不再次生成语义；已有合格节点与人工内容保持，拆分或归并只重算受影响的关系与教学引用。

程序可硬性保证 JSON 结构与引用等可计算条件；语义正确、教学颗粒度和课程完整性只能通过来源核对、可检验案例、评测与专业审阅逐步提高，不能承诺提示词或同模型自审给出绝对保证。应分别报告覆盖、原子性、关系、易错内容、来源支持、调用量和失败/恢复，不用总分掩盖某一项严重缺口。

下一步评测先从 C 语言的类型转换、if 配对、for 控制流各选一组代表性知识，由学科审阅者确认正确规则、必含范围和故意设置的错误案例。现有 119 个基础条目不是已经审定的标准答案。固定部分样例用于调整提示词，另留未用于调整的变式和章节检验泛化；验证补漏、过度拆分、错连边和错误诊断的检出与误报，再扩展到 Unity 和非编程课程。

关键反例包括：被复合句掩盖的两个知识、过度拆分的单一规则、长资料尾部独有内容、同名异义、缺前提的推导、倒置前置关系、虚构高频错误、同一错答的多种原因。完整循环还需验证知识基线被实际讲义引用、术语一致以及来源更新后的恢复，但不把这些评测塞成每次讲义生成后的自动内容审核。

### 模型输出与程序职责

模型负责提出课程范围、分类、知识命题、元问题、教学内容与带理由的关系候选；程序负责输入分片、结构校验、正式 ID 分配、引用解析、去重候选定位、版本与任务保存、权限检查和最终采用。模型使用当前批次的临时键以及程序提供的已有知识引用，不编造正式 ID。

模型拆点只输出原知识 ID、修订原因与完整子命题，不负责全量 ID 迁移或直接拼接 JSON 操作。程序在已授权范围和匹配修订下组装候选：单点修订保持 ID，拆分分配新 ID 并保存旧修订及替代映射。独立原点可逐项成功或失败，回执不可笼统报告整批完成；同一原点的修改必须完整采用或保留原状。受影响的题目、关系、诊断不能盲目复制给所有子点，需保留旧记录并生成重新绑定或补缺待办。

编程类运行检查将“模型预测、实测样本答案、解释的审阅状态”分别保存。实测答案绑定 check ID、完整代码及执行环境、回执哈希；代码或适用前提改变后，旧核验结果不得继续有效。未定义行为、无法证明终止或环境前提不成立的例子不能通过一次运行证明规则，应保留静态审查状态。受控实验中的源码哈希许可不能替代产品所需的隔离执行环境。

涉及代码的易错诊断和复测只引用上述检查，不另写一份“正确答案”。共同表现须能被不同错误信念共同解释，区分题须使其预测不同，复测应是不同情境；纯输出格式差异不能被当成知识错因的证据。程序仅能检查引用、样本答案和可比较预测，错误信念是否确实导出预测、题目是否测到目标、补救是否有效仍需语义核对。缺检查与未通过项显式保存，不能以字段齐全冒充完成。

检查生成应携带本批明确的知识 ID 清单，逐点接收并识别缺失、重复和越界内容。小批次容量按模型与学科实测决定，不用一个总覆盖声明代替逐点完成。补缺可新增明确目标的检查，修错只变更授权对象；保留模型原稿、范围内修正及复核者编辑的独立记录。

编程课程可使用已审阅的错误规则模板：先固定 A/B 错误信念及其解释方式，由模型选择满足约束的例子参数，再以正确程序和反事实模拟取得预测。反事实代码必须明确标注为错误信念的模拟，不能展示为语言的另一种正确规则；模板及参数边界须核验可终止性与定义域。这样的结果只能证明选定信念的逻辑可区分性，不证明真实学生错误频率或诊断准确率。非编程课程需适合本学科的证据方法，不能套用“代码跑通”标准。

验收分别记录自动候选与经复核修订的基线。复核者修改过的内容保留作者、原因和前后修订，不能把修订后的通过数计为模型独立通过。限定样板通过后可试写讲义草稿；正式课程仍须完成本课材料覆盖、基线采用和版本绑定。审阅哈希只保证评语对应本修订，不能证明评语正确。

批次之间携带课程范围、当前分类和已确认知识的必要摘要；来源抽取必须覆盖完整输入清单。不能用前文摘要代替尚未处理的原始材料，也不能按名字相同自动合并语义不同的知识。

建议在叶子身份稳定后生成能力、错误候选与关系，避免早期拆分造成大量无效引用。关系候选先从显式引用、先修需要、对比问题与跨讲复用中寻找，再由模型检查命题和理由；不对全课所有知识点无差别两两询问。

结构检查由代码执行；语义检查读取原材料及候选，明确报告“拆分不足、重复、来源不支持、范围遗漏、关系无依据”等具体问题。同一模型二次检查只能作为检查信号，不能宣称独立证明正确；固定样板和教师抽查用于验证其漏检与误报。

自动补充或语义修复仅能发生在本次知识树候选中，不能改写正文。若决定启用，应在本次任务授权与预算内限定范围、次数、停止条件；预算耗尽保留成功分支与未完成问题。暂停、取消、失败和来源冲突之后不自动另开任务。确切修复策略仍待本次生成方案讨论，不借此扩大既有讲义生成的自动重跑范围。

| 选择 | 推荐起点 | 尚需确定 |
| --- | --- | --- |

## 全面覆盖与课程针对性如何验收

覆盖全面的分母是“本次明确范围与已取得的课程材料”，不是整门学科的所有知识。范围完整性和从范围到树的映射完整性分开检查；如果资料缺失或范围仍有争议，应显示具体缺口。

| 检查面 | 交付要求 |
| --- | --- |
| 输入处理 | 冻结清单中每份纳入资料都有处理记录；未解析内容可见，长文本尾部、表格与代码不得静默丢失 |
| 范围覆盖 | 每条必学范围有一个或多个知识点及解释，不能仅挂一个同名大分类就算覆盖 |
| 来源覆盖 | 每个有知识含义的来源单元有对应叶子，或有可审查的合并、重复、非知识内容等排除理由；不能把所有正文块都绑定到一个泛化知识点 |
| 原子程度 | 正式叶子均满足元知识点标准；每个有主要目标明确的元问题与检查依据；复合应用题不混作原子事实；字段齐全不能直接算作原子 |
| 教学可用 | 能力描述可观察；已有易错记录能给出具体错误假设、区分性检查、补救与复测；模型猜想不冒充真实学生诊断或高频统计 |
| 针对性 | 每个正式叶子标注必学、前置或拓展，说明入树依据；版本、术语、任务和例子与本课一致 |
| 结构正确 | 单根、父节点存在、无环、叶子无分类子节点、稳定 ID 无冲突、无无意义空分支 |
| 内容可信 | 来源引用真实存在且支持相应命题；源材料错误或冲突单列出来，不能为了忠实抽取而将明显错误标为已验证知识 |
| 重复与关系 | 同义合并有依据，异义不误合并；先修关系单独验证，无环且有理由 |

目标是已确认必学范围和有效来源单元都有可追溯处置；报告分别列出已覆盖、遗漏、待确认和排除项。映射率不是教育完整性的证明。叶子总数、大分支数和平均深度用于理解规模，不设“必须生成几百个点”或“所有分支一样深”的规则。

课程针对性不仅体现在树名：同为 C 语言，入门课侧重语法与基本程序，嵌入式课可能包含寄存器、位操作与存储约束，算法实践课可能强调复杂度与状态表达；这些分支只有在本课范围支持时才进入必学树。现有 Unity 样例则应围绕其六讲的生命周期、输入、物理、角色控制、对象池及存档内容组织，遵守其未覆盖底层渲染与网络同步的课程边界。

## 知识树驱动的单点出题首版

复用原题库与任务机制，以已采用的元知识基线规划单点检查，合同为 `atomic_assessment_v1`。每个具备规则、元问题、修订和可解析来源的必学点默认形成直接判断、对照辨析、迁移应用三个题位，课程可限定为 1—3 题；不再由每讲固定三题承担全部元知识覆盖。没有新基线的存量课继续原流程。缺口须显示，不能以模板题补齐后声称已覆盖。

题位身份与练习层级分开：同讲可有多个概念检查；主考知识与必要前置分开，前置不自动成为被评估目标。正式题目冻结主考知识、知识修订和基线，作答沿用该题原修订。题目重建、合批、部分成功续作、学习资产投影均按题位对账，知识来源变化后旧结果不得写入新基线。

同一点的变式必须改变实际实例结构、规则作用位置或可辨别情形，不能仅换数字、变量名、选项顺序或同义问句。首题保留旧题位身份，其余按变式角色派生；单选测量计划在独立求解之前分配选项位置，保存后保持不变。作答由服务端冻结题位证据身份，同一变式重复作答或重新生成不重复累计独立证据；不同变式仍需各自通过完整知识绑定与质量核验。此逻辑的本地验证及千问 502 阻断见[九点多变式与答案位置验收](../验收/C17九点多变式与答案位置修复-2026-10-13.md)，新 27 题真实质量尚未验证。

单点检查经原题库核验与正式批改后可提供该点的学习证据，不能据此认定整讲能力或综合能力达标。覆盖区分知识被引用、已批准练习覆盖和可用于当前单点评估的覆盖；多点题在没有逐点评分时仍保持待归因。能力任务、错因区分、补救复测及个性化变式不因单点链路接通而视为完成。实现与验证边界见[单点出题验收](../验收/知识树驱动单点出题-2026-10-11.md)。

### 题库的元知识点绑定

题库提供独立的「绑定知识点」入口。进入课程题库、导入后返回题库或题库修订刷新时，如果课程已有正式采用的元知识树，自动匹配尚未绑定的题；按知识树生成且已有精确目标与修订的题直接显示已绑定，不重复调用模型。绑定只使用当前课程中有效的原子知识点，不把分类节点、整讲知识或必要前置当作被测目标。

旧题和导入题通过既有千问通道分批匹配，每批最多八题。模型须给出实际考查点、题面原文依据和置信度；ID 越界、响应缺行或服务失败不保存部分猜测。低置信度及范围外题保留待确认。用户可以搜索知识点并手动选择每题至多五个目标，也可清空为待确认；这不改写题干、标准答案或解析。状态区分已绑定、待绑定、待确认和知识树更新后过期。过期关联由用户核对后重新绑定，不自动迁移到新基线。

关联使用 `question_knowledge_binding_v2`，冻结目标 ID、知识修订和基线，并进入正式练习的 `concept_ids`、`knowledge_revision_refs`。绑定保存为新的题目及题库修订，原修订与历史作答仍可读取。题干、选项和材料等实际考查内容变化后需重新绑定。多目标题没有逐点评分时不分摊整体对错；新关联本身不替代测量有效性核验、不确认具体错因、不授予独立掌握证据。已有 `atomic_assessment_v1` 题变更目标后原独立核验失效，重新进入待审核。

读接口只展示绑定，写接口校验课程拥有者、题库与知识树的预期修订，并在模型返回后再次校验；题库生成期间拒绝绑定写入。教师与学生自有课程共用同一实现。关闭页面结束观察，不撤销已经提交的绑定；模型不可用时保留原题并提供手动绑定与显式重试。此处的自动匹配在题库页面触发，不是知识树后台采用任务的隐式写入。

### 单点证据准入与语言合同

已采用知识基线的语言和版本进入测评槽位；C17题目使用C17语义与C代码。单点题即使选项答案与独立求解一致，也必须核验语言符合范围、题干未直接透露目标规则、独立解析自洽且作答需要真正运用目标。`question_evidence_admission_v2`冻结核验结果与题面、选项、答案修订、知识修订的关联；缺核验、失败或内容变化不授予独立证据资格。正式批改再次检查，不依赖旧题保存的允许计分标记；仍可提供作答反馈，被排除的证据不使掌握分上升或下降。此次策略更新不自动重写历史学习事实。

题干的必要条件、代码、待判断命题与直接告知结论应区别对待。确定的语言不符、规则复述以及“问最后一行但选项均为多行完整输出”等问题先由本地检查处理，再使用原有限预算修复；不能无限重跑。自动语义评审仍可能漏检，不等于学科验收。[C17修复轮对比](../验收/C17单点出题语言与证据修复对比-2026-10-11.md)记录重点问题改善与仍未解决的选项/解析/观测问题。

### 选项、解析和观测证据合同

数值、输出字符串与概念选项使用明确的解释范围。单点题须逐项核对所有实际选项，避免未求值算式、等价数值和不成立的错误选项理由。生成器提交私有测量计划；独立评审重新构造完整目标、公开观测位置、仅改变目标语义的错误规则、同一输入下的两种具体预测与执行摘要。仅有“通过”标记不足以采用；未求值的条件预测、相同观测、改变固定输入、虚构观测位置或改变原程序控制结构的核验记录均不能用于独立掌握证据。

核验包含受限的字面算术、C运算符语义、只读输入和if/else结构检查，未知情况不冒充形式化证明。读取旧题也要加载私有答案复核：`approved_formal_tasks(bundle)`只返回当前通过的题；`revalidate_evidence_admission(item, solution)`只撤销、不凭空授予资格。覆盖统计调用`knowledge_point_coverage(..., solutions=...)`，缺私有答案标为未核验。生成失败保留知识点缺口及历史回执，不能靠旧allow标记或学习资产缓存绕过。

原子题先在私有设计中确定最小材料、观测量、同一输入下正确/错误规则的不同预测，再形成题面。支持的单选题由程序装配设计材料与选项，并对能精确识别的简单C片段选择可区分输入、补充明确初值、保证退出状态可见、从真实语法构造动作/转换范围选项；原始草稿与变更回执保留。计划不进入独立求解与评审，未知结构不猜测改写。核验依据错误只重做核验，解析错误只重新独立求解，材料或观测错误才重新设计；各阶段仍在原有限预算内完整复核，不以降低门槛补齐题量。

[C17同九点核验改进验收](../验收/C17选项解析与观测核验改进-2026-10-11.md)记录此前4题可用、5点缺口。[剩余五点测量生成修复](../验收/C17剩余五点测量生成修复-2026-10-11.md)保留服务502阻断阶段；[恢复后的完整验证](../验收/C17九点千问恢复与完整验证-2026-10-11.md)记录最终同九点9/9、18次C17执行和63次画像回放通过。该结论仅针对九道初始单点检查，不代表全树或稳定掌握已经验证。

## 页面与使用流程

默认展示知识树，初始展开大分支；支持逐层展开、当前分支聚焦、面包屑、搜索及知识点总数。数据可分批加载，但展开已生成节点不额外触发模型调用。继续沿用现有桌面蓝紫视觉、中文及英文文案和可访问的键盘操作。

学生画像中的知识树采用横向从左向右的树状图：左端为课程根，分类分支逐层展开，最右侧叶节点对应元知识点，以掌握百分比圆球呈现。点击叶节点在中间栏打开详情并联动右栏学伴，按“要解决的问题、核心规则、能力与例子、易错与区分性检查、练习与补救、本人学习证据”组织节点详情，并能查看边界、课程来源和前置知识。教师知识维护入口可继续使用列表/关系图，不据此复制另一份知识数据。默认先呈现元问题与核心规则，较长的诊断和证据按需展开，避免一屏堆满字段。点击来源回到具体讲次与正文位置。课程目录仍用于按讲阅读；在知识树中按讲次筛选只是同一知识库的视图，不另生成一棵平行树。

教师或课程拥有者可生成全树、编辑、拆分、合并、移动分支以及仅更新受影响部分。学习者可查阅、定位、提问和练习；学习共享课程时不能改写正式树。教师预览不写学习记录。只有大纲、生成部分完成、生成失败、来源过期、没有权限和真正空内容分别给出准确状态，避免一律显示“旧版需要升级”。

## 学生掌握状态与画像联动

2026-10-11 确认增加单课程知识画像。知识树作为共享内容坐标，个人掌握状态由学习事实按稳定 knowledge_id 与知识修订关联，不能写回共用知识 JSON。节点展示个人掌握参考值、证据程度和未评估状态；分支与全课展示已验证掌握进度、评估覆盖率和已评估平均值。初值、行为证据、首版规则、版本变化及验收由[学生学习：知识树联动的学生画像](学生学习.md#知识树联动的学生画像)统一定义。

元知识点原子性与正式采用仍是前提。未审定条目不能靠显示掌握百分比获得正式知识身份。综合题需有精确考点与逐点检查依据；关系强度用于关联，不直接兑换个人分数。首版逐点画像扩展现有 LearnerModel，不建立平行知识树或个人事实仓库。

## 对现有灵知实现的改造

### JSON 存储与带强度的关联

采用“树形分类 + 元知识记录 + 带类型的关联边”。树负责浏览和归类，关联边负责跨分支引用、教学前置、对比、应用和推导。一个元知识点在本课程只有一个主要父分类，可以被任意多个其他知识点引用；分类父子边不自动变成先修边。样例见[课程知识树JSON样例](../研究/课程知识树JSON样例.json)，其版本标为 draft，不能直接交给现有生产接口导入；正式机器 Schema 在实现时升级并验证兼容性。

首版沿用现有课程知识库的唯一保存责任，以一门课程的一份知识库 JSON 作为逻辑快照。分类采用 parent_id，元知识采用稳定 knowledge_id，关联通过 ID 引用目标，避免嵌套复制整份目标节点。树节点移动或改名不改变 ID；生产 ID 由程序分配，示例中的 demo 编号仅方便讨论。

目前代码已经将正式关系集中保存在 relations 列表，继续保持关系唯一存储。读取单个元知识点时，可以附带 outgoing_relations 与 incoming_relations，让节点详情直接显示“指向谁、谁指向我”；这两项是从正式关系列表计算的读取视图，不再维护第二套关系。即使将来按节点拆成多个物理 JSON 文件，也必须有统一版本、索引与原子采用机制，不能让模型分别覆写文件造成半棵树更新。

| 字段或关系 | 建议合同 |
| --- | --- |
| source_knowledge_id / target_knowledge_id | 指向本课程已存在的稳定元知识 ID；初版不开放任意跨课程引用 |
| prerequisite | source 是 target 的教学前置；必要性另用 necessity=required/recommended 表达，强关联不自动意味着必学 |
| contrasts_with | 用于对比两个不同规则，必须记录 distinction；有易混淆假设时链接相应易错记录，不直接等同于已有实测混淆 |
| applies_to / derives | 分别表达源知识应用到目标知识、源知识推导出目标知识；推导记录保留步骤，不能用高强度替代推导依据 |
| equivalent_to / generalizes | 沿用现有词表；同义重复优先合并正式节点，不能靠大量等价边掩盖重复；泛化方向与现有读写合同统一后再启用 |
| strength | 本课程特定教学情境下的关联展示/引用优先级；初版弱、中、强映射为 0.3、0.6、1.0，映射有独立版本，不是统计概率 |
| context / reason | 说明在哪个教学场景有用、为什么值得关联；不能只写“两个知识相关” |
| confidence | 对关系成立的证据把握，与教学强度分开；没有可靠估计时为 null，不能把模型自报分数当校准概率 |
| provenance / evidence_refs / review_status | 保存来源、依据与 proposed/accepted/rejected 等审阅状态；模型生成首先是候选 |

强度先按同一关系类型与相同使用场景比较。前置知识缺失按明确的必要性规则处理；相关知识推荐可在筛选后按强度排序；对比关系可以服务易错辨析。不能把不同类型的强度直接相加成为统一掌握率，也不自动沿多跳相乘推断新的正式前置关系。

对称关系只保存一次，用端点规范排序防止重复，读取时两端都可见；有向关系严格保留方向。相同端点、类型和教学情境原则上只保留一个当前关系。缺少关系不代表已证实无关联；null 强度表示未知，不与“弱”或零混淆。首版不要求将每对知识点都连接，优先保留有理由且能改善教学的直接关系。

生成时先确定知识身份与范围，再依据具体命题、课程来源和教学场景提出关系候选，最后校验并由拥有者采用。文字相似度只能帮助发现候选，不能独自决定先修、推导或易混淆关系。学生某次答错或点击行为属于个人证据，不直接改变全课程共用的关联强度。

JSON 保存需执行结构检查、ID 引用闭合、唯一根与分类无环、先修无环、重复边检查，以及来源修订与权限检查；同类型的对称边允许形成图中的环，不把所有知识关联强行限制为树。通过临时文件写入与原子替换保存整个版本，配合现有写锁和修订冲突检查。关系目标被拆分、合并或移除时，通过显式映射处理，未确定的新关系标为待审，不静默重定向。个人掌握、错题和学习记录仍在个人学习仓储，不混入课程共用 JSON。

规模或多人编辑需求上升后，可以调整物理存储方式，但继续保持同一课程知识身份、一个正式写入者与可恢复的版本采用过程；无需在首版引入图数据库。

源码中已有课程知识库、能力、易错、标准、正文绑定、知识命令、拆分候选、修订与影响分析。应扩展现有知识库的正式写入责任，避免再创建平行课程 Store。

树版本绑定课程及来源修订。移动、重命名保持 ID；拆分、合并保存显式映射，旧练习、笔记和学习证据仍指向原版本，不自动把旧掌握判断转移给新点。历史课程通过显式升级生成候选，读取页面不触发静默迁移。

建议在原任务机制上提供“发起生成、读取进度与候选、主动继续失败分支、采用候选、执行局部知识命令”这组能力；具体路径复用现有 `/api/courses/{course_id}/knowledge-library/...` 命名空间。发起和采用都检查课程归属、角色权限与来源修订；重建、审阅和旧接口一起检查，不因已有路由可调用就认为权限已完整。

每个任务保存来源快照、分支状态、原始模型结果和成功检查点。暂停、取消、关闭页面和服务重启遵循现有任务语义；不会因断连自动新开全课生成。失败只保留待完成部分，用户主动继续；来源变化时显示过期或冲突，采用时再次校验。并发分支不能各自写正式课程，最终由唯一入口采用版本。

## 首版产品约束

### 复用原课程生成链路的通用化接入方案

原课程链路作为主干，知识树生产补入元知识抽取与教学诊断核验。第一步共享上下文与冻结证据已通过 `course_knowledge_context.py` 接入知识树及讲义任务输入，见[四课对照验收](../验收/共享上下文接回与四课千问对照-2026-10-11.md)。通用全课入口与语义核验仍未完成；不继续把 C17 样板脚本扩写成另一套课程生产系统。

信息顺序为：课程目标、起点与可选资料 → 学科画像与课程范围 → 大纲、教案、讲义 → 从讲义提取知识树候选 → 拥有者确认采用。讲义是提取来源，但不是独立核验依据；知识树不作为原链路生成讲义的先决条件。

#### 统一生成上下文

知识生成请求从已有课程数据派生一份 `KnowledgeGenerationContext`，冻结在原任务的输入快照中。它不是第二份课程主库，应至少带有：

- 课程 ID、目标、受众、学习起点、目标难度及各自来源修订；师生身份不改变学科内容合同。
- 已确认学科画像与教学模块，及画像的人工指定/推断来源和不确定性。
- 同一证据包修订、完整来源单元清单、定位信息、用途限制、解析状态与缺口。
- 全课知识范围及当前生成单元负责范围、允许的前置补充和保留给其他单元的范围。
- 本课术语规范、已有知识 ID/修订、已完成范围及本次允许新增/修改的范围。
- 适用题型、作答证据和校验模式；持久任务 ID、调用预算、检查点与来源冲突条件。

已实现的上下文快照保存在原 job 的 `request_snapshot.knowledge_generation_context`，由输入内容计算修订。请求前、结果写入及候选采用均检查上下文；新讲义保留 `source_context_revision`、`source_evidence_package_revision`、`source_scope_revision`，阅读投影透传。模型请求可省去重复摘要和审计索引，但保留选中证据原文与修订定位；完整快照仍存于任务，硬输入预算超限必须停止而非静默截断。已有冻结包需属于本课程且通过原文哈希校验；显式损坏、未解析或纯风格材料不得静默换成样板。C17复核材料仅作为明确标识的试点输入。

生成器不得自行重判整套课程背景或改用另一份材料。题目与知识点绑定至少包含目标知识及修订、被测能力、题目及修订、题干中的条件/参数与预期观察；核验应覆盖“实际考了什么”，不止校验 ID 存在。

#### 仍需新增或强化的三层

1. **元知识抽取与分型。** 区分定义、规则、方法、适用条件、案例和材料证据。叶子应可独立检查；案例中的人物陈述和某一道题的数值不自动成为通用知识。拆分时保持来源与已有身份，缺材料只给范围草稿和缺口。
2. **教学能力与错因核验。** 复用教案的教学动作合同，但显式绑定知识点。错误规则要能独立推出预测，检查未知、同义重复、错因共存、共同行为与区分证据；修复和迁移必须有具体输入、操作、证据及适用边界。
3. **学科校验与证据来源。** 接入已有数值、单位、符号等校验接口，增加学科条件和推理方向检查；程序执行证据必须由可信执行器产生。人文评分依据引用、论证与限度，允许不同合理解释，不能只按编号、篇幅或模型自评分放行。

2026-10-11 直接调用旧模块的[复用核对记录](../研究/知识树跨课程通用性/旧链路复用核对.json)显示：物理和历史的自动主画像符合样本，Python 被分为 general 主模式及 programming_engineering 次模式，数学附带 humanities_social 次模式。符号等价与单位换算样例通过；本地独立求解注册表当前仅有 numeric_expression、state_operations。史料 `evidence_validator` 单独面对只含所需来源编号和足够篇幅的无依据断言会返回 passed，因为它检查引用覆盖和长度。该结果说明此函数不能独立承担语义审校，不等于旧系统的所有组合门禁都会发布该答案。rubric 接口消费传入评分，代码接口消费传入执行结果，也不能把未经验证的模型自报当成独立证据。

#### 实施顺序与验收

第一步接入共享上下文和冻结证据，替换试点的固定 C17 输入；同步处理旧章/节到现行讲次与知识范围的读取适配。第二步把元知识和教学能力候选纳入原知识生产、修订和题目接口，补齐上述三层。第三步在同一批四学科材料上做接回旧上下文前后的受控对照，再增加长材料与完整课程验收。

验收必须包括：Python 的赋值与浅拷贝区别不混用题目参数；数学证明方向与题目一致；物理只用已给条件和合力关系推断；历史不把记载或推测动机当事实；无材料不虚构完整树；旧引用、知识版本、讲义和学生记录保持可追溯。单纯分类正确、字段完整或调用成功均不能替代这些验收。

知识树采用前可按有界预算做核验与目标字段修正；讲义继续保持每讲一次主请求、只检查结构与来源、不追加自动内容审核或改写循环。学生自有课程可直接消费已采用知识和共用教学能力，不强制填写教师行政栏目或生成隐藏完整教案。现有 C17 正式基线与未通过候选保留，不在接入时静默迁移或重写。

### 教学能力补全与精修对标合同

每个元知识点必须通过真实 ID 关联可观察能力和可判定达标证据。一个能力可组合多个知识点，但每点的检查依据不能省略。具体错因须给出明确错误规则、可观察表现、适用范围和针对性补救；训练必须包含可用输入、操作要求、需提交的证据，以及改变情境的迁移复测。

区分题比较的是错误规则导出的观察差异。无预测表示未知，不能当作正确答案或排除证据；允许错因共存，不机械凑互斥三选一。同题不同 ID 不构成独立证据。结构、引用、诊断逻辑、学科语义和真实学生效度分别核验；不得因 JSON 完整就标记教学可用。

正确答案保持来源与修订绑定，模型预测单独存储。保留原模型结果、格式规范化记录和独立复核意见，人工改写不得计作模型原始通过。框架未通过时只保存候选；有明确未解决核验问题的候选，前后端均禁止采用，原知识树及讲义保持可读。

2026-10-11 的[精修对标实测](../验收/WenCode精修对标与教学补全千问实测-2026-10-11.md)已生成 15 能力组、49 逐点标准、45 错因/补救及 15 组区分题和迁移复测候选。结构与覆盖齐全，但各包仍有语义或诊断问题，不能作为正式基线；这不是完整课程或全自动教学质量验收。

### 题目语义绑定、错因推导与补救合同

题目绑定必须同时保留知识点修订、题目修订、实际检查的命题、所需作答证据和直接检查的理由。题目只用到某个前置知识，不等于直接检查该知识；比较力大小的题不能记作检查加速度，逆命题问题不能记作逆否命题。一个叶子含多条独立判断时必须细分或逐项补齐检查，不能因有一个合法题号就记为完整覆盖。

已冻结题目的题干、输入状态、答案或开放评分准则由程序按精确题目修订装配；生成器不在达标标准中另写一份答案。绑定理由只作为候选解释，不能作为评分依据。补题须保存独立候选身份、来源与候选答案，经过适用条件、输入类型、答案和考点核验后才可作为有效覆盖；材料引文存在不能证明补题正确。训练明确独立重置或明确连续状态，迁移题与训练、区分及补救用途分开；复测的跨能力前置依赖与实际覆盖范围必须如实记录。

错因预测使用“固定题目条件 → 单一错误规则 → 推导步骤 → 可观察回答”的记录。规则没有定义的结果记为无预测，多个规则不得用“或”拼成唯一原因。对答错原因的解释保持候选状态，规则推导成立也不等于已经验证学生的真实认知原因。

每组补救包含材料 ID、准确引文、学生动作、核对题引用和不可泛化的条件。核验须分别检查引文是否存在、动作是否受引文支持、必要条件有无被扩大成充分条件，以及对象、类型、时间或系统边界有无变化。正确引文不能替错误动作背书。

结构检查与独立语义复核分开记录，复核绑定候选内容摘要及题目/知识修订；内容变更后旧复核失效。任一关键语义项未通过就保留候选状态，不能自动采用。程序执行核验、规则推导复核、人工内容复核和真实学生效度分别报告。

2026-10-11 的[四课语义绑定实测](../验收/知识树语义绑定与诊断补救对照-2026-10-11.md)在同一批材料和共享上下文上完成 9 次千问调用。隔离原型已实现冻结答案装配、题目版本检查、补救引文检查与内容修订绑定的复核门槛；28 条引用已有题目的标准均装配原冻结答案，12 条错因中 10 条推导成立，12 组补救中 9 组通过本次内容复核。但新补题、命题方向、必要/充分条件及历史证据边界仍有错误，逐点标准仅 29/34，四科整体 0/4 可用。没有修改模型原始内容、采用候选或替换 C17 正式基线。

本节为质量合同，当前新增程序仍在隔离实验内，尚未接入通用网站生成入口，也没有实现任意学科的自动语义证明。后续沿原题目接口实现检查意图与答案的独立核验，只有经核验的题目才能计入知识覆盖；讲义仍遵循原有一次主请求及结构/来源检查边界。

### 逐点检查与独立核验边界

生成候选应逐点保存检查、具体错因及推导、材料锚定补救、迁移和达标标准。检查题的字段完整性与材料所需判断的有效覆盖分别统计；减少、合并或移走案例节点后，不能只按“现有点都有题”宣称覆盖全面。

独立解题请求采用字段白名单，隐藏生成器的正确答案、达标说明、修正总结和上轮自评。题目实际考点、正确解答、错因预测与补救是否受材料支持分别记录。审查模型仍会看到完成核验所必需的知识命题和补救动作，不把新请求称为独立模型证据，也不把多数模型意见当作事实。

本地答案比较只在可验证的类型和求解范围内给出结论。字面值相同不能证明推导正确，自由文本或开放评分无法确定等价时维持待复核；数学需核验关键推导和适用条件，物理需区分相互作用力与合外力，历史需保持陈述来源与证据限度。补救引文正确仍不足以证明动作正确。

知识树候选可在冻结预算内修正一次已定位字段，修正范围与候选修订须由程序核验；审查响应缺失、格式错误或答案冲突不能记为通过。原输出、格式恢复、模型修正、本地运算与人工复核分别留存；任何内容变动使旧内容复核失效。该机制不扩展为讲义自动审核、改写或失败重跑。

同日[逐点检查与独立核验实测](../验收/知识树逐点检查与独立核验-2026-10-11.md)对相同四微单元完成初始17次请求及修复自评泄漏后的4次复核。最终27个生成点均具有检查和补救，但有效考点覆盖仍有缺口。最后一次千问复核对27张卡均给出通过意见，独立运算与内容检查仍发现Python答案、数学差商、物理合力前提及历史证据错误，整体0/4可用。29项回归测试通过；正式课程未采用候选。通用学科求解及语义覆盖验证仍未完成。

### 通用课程从空白生成

新课选择「从零开始」，直接进入原备课流程，资料上传可选。课程信息、教学起点与目标由原课程信息表单统一维护，不再在知识树面板重复采集。讲义后点击「知识树」，面板展示当前已保存讲义数量、来源版本及生成操作；没有讲义时提供「去准备讲义」。

提取使用原讲义仓储的完成正文块，知识点携带讲次、讲义修订、段落、逐字引文。程序校验来源、分类与先修无环、讲次引用，保持同一命题的课程内稳定身份。分类按语义递归，不固定层数；分支深度由具体内容决定，不以固定层数或节点数冒充质量。当前单次最多160个知识点，模型输入与输出预算仍显式生效；超大课程分批提取尚待扩展。

候选由拥有者确认后形成知识版本，原讲次、正文及历史引用不变。引文匹配只证明出处，不能证明生成讲义学科正确。完整模型响应若仅在本地检查失败，可以主动「重新检查已有结果」；记录原模型任务与原冻结来源，不再次调用模型。输入变化时禁止复用或采用旧候选。

既有 `knowledge_first_c17_v1` 与 `knowledge_first_generic_v1` 数据保持兼容读取，旧资料配置接口保留兼容，网站新课不再进入知识先行路线。提取沿用原任务仓储与接口，并以 `source_mode=handouts` 明确区分来源。

### C17 网站试点合同

在原课程工作台的「知识树管理」内启用知识树与讲义流程，不建立独立试点页面，也不因课程类型自动离开工作台。第一批材料限定为类型转换、if 配对、for 控制流三组，经复核的 49 个元知识点，不宣称已覆盖整门 C 语言课。新流程不转换其他课程，也不自动重跑旧讲义。

- 课程仍只有「课程 → 第 N 讲」。知识分类树属于课程 `course_knowledge_base`，元知识 ID 与修订保持稳定；AI 只组织此轮材料的分类，不将材料载入冒充知识事实重新生成。
- 状态为「空课程 → 知识树候选 → 拥有者采用 → 逐讲生成」。未采用知识基线时禁止生成讲义。一个课程同一时刻一个生成任务，采用期间不允许活动生成任务。
- 知识树任务和讲义任务复用现有讲次任务仓储。每个操作返回持久 job ID，刷新后继续观察；关闭页面不取消任务。取消、模型错误、结构错误、重启中断都不自动再发模型请求，保留片段和已完成讲义，允许用户主动重新发起。
- 正式树与采用历史存于课程元数据；讲义正文及历史版本只由现有 `TeacherLessonAuthoringRepository` 保存，课程阅读走只读投影，不另建正文副本。学生自有课与教师自有课按拥有者授权，已发布课程的非拥有者只读。
- 每讲一次千问请求产生引入、49 点中本讲范围的解释和总结。程序按真实 ID 对账，再插入已核验例题、诊断、补救、复测和检查题；不执行模型返回的 C 程序。仅检查结构、覆盖引用与来源，不追加模型内容审核或自动改写。新讲解标记待教师审阅。
- 每个内容块保留知识 ID、知识点修订、知识树修订、术语修订与答案证据引用；讲义修订另保存来源课程文档修订。点击引用打开对应历史基线。更换基线时旧讲义不覆盖，显示来源已变化。
- 生成提交和采用都核验开始时的课程、知识树、讲义修订；迟到结果不能覆盖新版本。材料或知识事实已改但例题未重新核验时拒绝复用旧答案。后续全课材料抽取、多学科自动原子化与定向联动更新仍按主设计继续建设。

按讲生成知识树时，任务互斥限定在当前讲的来源与知识树任务；其他讲次的教案、讲义或知识树候选任务不阻塞本讲。全课生成及无法识别范围的任务仍保持互斥，采用正式知识基线继续核验共享来源。管理接口统一返回活动任务和逐讲阻塞任务 ID，页面展示具体讲次、任务类型与进度；任务结束后重新对账并解除阻塞，409 响应只触发状态重读，不自动重发生成请求。

管理接口：`GET /api/courses/{id}/knowledge-first` 为知识树管理区的数据对账入口；`POST .../initialize`、`.../generate/{tree|types|if|for}`、`.../adopt/{job_id}`、`.../cancel/{job_id}` 分别执行启用、生成、采用与取消。写操作仅拥有者可用，提交必须携带页面读到的来源修订。

- 每门课程一棵正式知识树；按知识主题组织，按讲次引用。
- 新课先按原链路生成讲义，再提取知识树候选；存量课程补建不阻断原有阅读，不强制重生既有材料。
- 正式叶子采用元知识标准，并连接元问题、可观察能力、检查题、易错候选及补救复测；其中易错内容按真实依据提供，不为凑字段编造。
- 有完整课程材料时后台生成整课候选，按分支保存进度；范围材料不足时提供草稿与缺口。
- 保留必学、前置、拓展三种范围，默认先看本课必学；不将跨学科补充自动扩大成必学分支。
- 首次生成可一键完成候选，正式采用集中确认；后续更改显示差异并支持恢复。

下一步按深化样板逐项重整 C 语言的 119 个基础条目：保留元知识、拆分复合规则、将综合问题与能力方法重分类、归并共享知识，再补齐教学关联与课程来源。完成该审定后进入数据合同和生成流程实现。尚需用实际课程材料确定的是教学范围、来源优先级冲突与合理分批预算；不影响本方案的层级、身份与来源原则。

## 规格验收场景

以下为实施后的必要验收要求，不表示本次文档工作已经通过运行验收。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| KT-01 | 同一门课的知识跨多个讲次出现 | 正式知识身份只有一份，引用多个来源位置；知识树与讲次目录分别展示 |
| KT-02 | 一个候选点包含两条可分别出错的规则 | 将其拆分或调整为综合问题，并保留与组成知识的引用；不靠增加字数冒充细化 |
| KT-03 | 已足够原子的 else 配对规则被要求继续拆分 | 可以保留原规则并说明停止依据，不强造单字符或数值专属叶子 |
| KT-04 | 模型提出“continue 等于 break”的易错假设 | 保存假设来源、区分性追问、补救与复测，不标为该学生已发生的错误或实测高频错误 |
| KT-05 | 元知识重命名、移动分类或跨讲复用 | ID 与既有题目、正文引用保持稳定；拆分合并有映射与旧修订可读 |
| KT-06 | 构建或读取 JSON | 单根、父引用有效、分类无环、正式叶子身份唯一；对称关系只存一份，出入关系视图一致 |
| KT-07 | 强对比关系与建议前置同时存在 | 强度不改变关系类型，不把 strong 自动转换成 required；置信度未知时保持 null |
| KT-08 | 前置关系成环、关系端点不存在或候选指向其他未授权课程 | 拒绝采用错误关系，列出原因并保留可恢复候选；不静默丢弃后声称全部成功 |
| KT-09 | 长正文、代码、表格或尾部材料包含独有知识 | 输入清单可对账，对应知识有来源；尚未解析的片段与未覆盖范围显式可见 |
| KT-10 | 只有粗大纲且范围未知、必需来源未解析、生成尚未完成或来源有冲突 | 展示草稿或缺口状态，不宣称内容全面且已核验；没有未来讲义本身不构成阻断，不自动改写讲义 |
| KT-11 | 重复发起、关闭页面、暂停、取消、保存失败或来源修订改变 | 同一任务可对账，成功部分保留；采用前检查修订，取消后迟到结果不写入正式版本 |
| KT-12 | 教师、学生自有课程、共享学习者和教师预览分别访问 | 写入受课程权限控制；个人事实隔离；预览不产生正式学习记录 |
| KT-13 | 中文和英文桌面打开较大的知识树 | 分支展开、搜索、正文定位与节点详情可用；未生成分支不伪装成真实内容 |
| KT-14 | 检查框架完整性 | 课程目标可追溯至能力与综合任务，元知识连接元问题与检查方式；字段齐全或一次答对不等于掌握或完整教学验收 |
| KT-15 | 新课尚无已采用知识基线却请求生成讲义 | 保留请求并说明所缺知识范围或基线，不能静默绕过知识树前置；学生不因此被要求创建教师行政大纲 |
| KT-16 | 同一课程生成教案、讲义和后续产物 | 记录并使用同一已采用知识修订及本讲范围，引用 ID 有效，规范术语与来源可追溯；PPT 仍读取相应讲义和已确认内容稿 |
| KT-17 | 生成途中知识基线或来源被修改 | 保存前发现修订冲突，保留候选及最后可用版本；不把旧输入产物标为基于新知识版本，也不自动重跑讲义 |
| KT-18 | 存量课还没有新规格知识树 | 既有授权阅读与学习记录正常使用；补建在候选中进行，不自动迁移或覆盖旧正文 |
| KT-19 | 只改分类或关联强度，或知识变更仅影响部分产物 | 分类/强度变化不直接触发全课重写；以真实引用和语义影响确定候选范围，人工保护与旧学习事实保留，部分失败有逐项状态 |
| KT-20 | 模型提交单点拆分意图，邻居或关联还引用旧点 | 程序分配身份并保留旧修订映射；范围外点不变，受影响引用显式失效待绑定，不盲目复制；无效意图保留原点 |
| KT-21 | 模型预测错误，或已核验代码后来改变 | 模型预测与实测样本答案分开，诊断和复测引用同一证据；代码变化、执行失败或前提失效后撤销旧核验 |
| KT-22 | A/B 预测相同、共同表现其实正确、复测复用原题或缺少检查 | 保留候选及具体问题，不作为可用诊断或已完成教学节点；数值合同通过仍不能代替语义核对 |
| KT-23 | 分批生成遗漏、重复返回或补缺时夹带其他点 | 按本批真实知识 ID 对账，缺项可定位；仅授权目标可新增或替换检查，其他点保持原样 |
| KT-24 | 使用错误规则模板，或复核者修正了模型输出 | 反事实与正确代码明确区分，约束和预测可复查；原候选与复核修订分别计分，不把样板逻辑检验冒充真实学生诊断或全自动课程验收 |
