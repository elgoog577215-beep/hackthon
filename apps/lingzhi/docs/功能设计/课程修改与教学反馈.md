# 课程修改与教学反馈

本业务支持有权编辑课程的人修改自有或获授编辑权的课程、处理资料变化；教师还可以根据获授权的真实教学证据判断是否继续调整。共享对象与权限见[产品蓝图](../产品蓝图.md)，生产过程见[课程生产](课程生产.md)。

## 一、内容设计

修改保存操作者原话、目标对象、基础修订、精确范围、约束与保护项。方案包含候选、前后差异、来源、影响与处理决定；执行回执逐项区分应用、失败和保持不变。人工编辑候选与最终批准应用是不同动作。

教学反馈保存原始观察、作业、考试、作品及来源；教师解释和模型推断分开。效果判断必须绑定调整对象、调整前基线、预期表现、后续证据和适用范围。缺证据显示待验证，不用“已应用”代替“改善”。

课程知识按稳定课程内 ID 与修订寻址，学科知识库拥有独立正式 ID；没有学科包时使用当前课程知识，不伪造学科 ID。

### 修改权限与个人内容

教师管理教学课程及文件；学生可以修改自有课程，使用相同候选、影响、采用和恢复能力。学习他人课程的学生只有学习权限时，AI 解释与补充保存为本人内容，不得覆盖教师正文，也不因按钮隐藏而省略服务端检查。

课程修改对象、个人笔记与作答各有拥有者。学生自己的课程更新同样需要保护本人的旧笔记和作答；教师更新共享课程还需保护所有学习者的历史，但不因此取得阅读私人记录的权限。

## 二、逻辑设计

1. 有编辑权限的操作者直接编辑走正式保存；AI 局部修改先精确定位当前字段、条目或唯一选区。
2. 跨讲、跨产物或改变结构的请求形成一个 `CourseEvolutionPlan`，解释范围、约束与影响。
3. 来源或新结构变化，逐项决定复用、重绑、局部修改、重建、退休或阻断，不受影响项保留。
4. 有编辑权限的操作者审阅候选，允许逐项排除、保留原文及编辑建议。保存选择范围不等于批准应用。
5. 正式采用通过既有领域命令和幂等日志，返回真实逐项回执；部分失败保留最后可用版本，不能声称跨仓储原子成功。
6. 撤销按已验证的反向回执恢复，外部修改、来源冲突或基线前移时重新判断，禁止静默覆盖。
7. 教师记录或导入使用后证据，比较原目标与结果，决定保留、缩小、撤销或继续调整；弱信号和一次 AI 回答不自动改课。

材料导入/替换与全课调整共用审计页面，仍由各自领域拥有者执行和撤销。正式模板映射、解析质量、关系冲突与缺失都要先说明，原件、当前内容和人工决定不能被后续导入覆盖。

### 修改与学习使用的联动

| 变化 | 应处理的影响 | 必须保护的内容 |
| --- | --- | --- |
| 正文修改、移动或删除 | 计算稳定内容 ID 与旧新范围关系，标明受影响笔记锚点、题目及教学文件 | 个人原引用、旧作答及未受影响内容，不能自动重写个人记录 |
| 题目或评分依据更新 | 新作答使用相应新修订，旧尝试仍绑定旧题与原评分依据 | 草稿不悄悄换题提交；原评分变更须单独可追溯，不静默重判 |
| 目标或结构变化 | 明确可复用、需重建、已退休和暂不可用的内容及学习范围 | 原学习事实保留，进度重算说明版本和有效分母 |
| 教学材料更新 | 只影响引用该修订的教案、日历、量规、PPT 等 | 教师人工修改、既有导出和实际使用记录不被覆盖 |

采用前检查来源与修改范围，采用后返回各领域真实回执及学习侧更新状态；不能只改正文后把学习影响留给页面猜测。正文采用成功、题库更新失败时保留部分结果并明确恢复动作。

### 教学反馈的授权与效果

教师观察、明确交付的作业或考试结果，以及经授权汇总的学习证据可以形成调整依据；学生私人笔记和 AI 会话默认不可见。反馈绑定课程/内容版本和事实范围，无法核验的导入结果不冒充完整学习事件。正式修改仍由教师决定，后续复验不把“更多点击”或“一次答对”直接解释为教学改善。

## 三、交互设计

全课修改在现有蓝紫色教师界面中独立承载长任务，保留“提出要求 → 影响分析 → 审阅 → 应用回执”的稳定导航；要求输入用单列，审阅用列表和详情。不用弹窗容纳整个长任务，不以预计影响冒充实际候选或应用结果。


### 两端共用的修改入口

学生自有课程的就地修改和范围修改复用原候选与审阅组件，使用学习场景文案，隐藏不适用的教师产物；权限不足时只提供个人解释或记录。正式课程和个人补充须明确标识，保存目标不能由模型推断。以下教师专用交互继续保留。

### 教师编辑与人工智能协作

- 教师直接编辑当前工作修订，保存后显示真实影响。
- 大纲、教案、讲义的文中 AI 修改使用同一个就地助手：悬停正文，在左侧显示沿用老版学生端交互的「解释、举例、简化、修改」四个纵向按钮；前三项直接生成，「修改」打开输入框。结果在原段下方显示，支持继续调整、重做、采用或保留原文。助手嵌入所选段落、字段或表格行之后，展开不改变阅读滚动位置，局部请求直接提交当前文档接口。
- 选择单位按内容组织：知识目标、能力目标、育人目标及重点、难点等紧凑区域按完整字段选择，表格按单元格选择；较长正文和教学备注保留自然段或条目选择。多列区域的助手在整组下方横跨可用宽度展开，顶部小三角指向所选区域；展开宽度不扩大实际修改范围。
- 生成或保存失败保留输入及已生成建议；收起保留现场，采用成功后关闭。来源修订变化禁止采用旧建议，但仍允许保留原文退出。后端按字段、内容块和唯一选区合并，不能定位时提示重选，不能自行扩大范围。
- 含 Markdown 格式的整段修改保留原始源码范围。跨格式边界的部分选区、跨字段选区及重复文字尚不保证可定位；需要选择完整段落或扩大到唯一范围。
- 跨讲次、跨产物或改变讲次身份和顺序的要求进入完整课程调整工作区。
- 候选必须显示改变内容、依据、影响对象和保持不变的内容。
- 精确查找替换的审阅结果同时标出旧词与新词；教师可以在单条课程正文候选中直接编辑修改后的真实字段并保存，人工版本只覆盖当前候选，不扩大到其他命中项，正式课程仍需最后确认后才更新。
- 全课修改列表只呈现标题、处理方式、等待原因与选择控件；原文、修改后正文和编辑在独立详情屏幕中呈现，返回时保留筛选、滚动位置和勾选。待检查或待确认的项目也可先勾选保存，保存范围不等于批准应用。精确正文建议可独立审阅；讲内标题关联教案时提供“保留原标题，只改正文”，不把所有项目统一锁死。旧建议存在重复插入时，先整理并重新审阅；正文与结构化镜像不重复显示。
- 教师可以逐项采用、排除、保留原文、撤销和恢复。
- 人工智能会话不能保存第二份课程正文，也不能占用生产任务右栏。

### 审计与更新中心

审计与更新中心统一承载：

- 新资料导入。
- 资料替换和过期。
- 正式模板栏目映射。
- 教师全课修改。
- 多对象影响分析。
- 冲突、缺失和解析质量。
- 修改候选、执行回执和恢复入口。

同一项变化从文件空间、工作台或人工智能入口进入时，必须回到同一审计或调整任务。

### 课中实施、课后复盘与效果验证

这三项能力在现有课程工作台和学习现场上延伸，不另起一套教师系统：

- 课中查看当前教学块、师生共用的讲义、时间、提问和备用方案。
- 教师快速记录真实学生表现，并区分观察事实和教学判断。
- 课后核对本讲目标、学生成果和课堂证据。
- 教师选择只调整当前讲、相关后续讲次或全课。
- 已应用调整保存调整前基线和后续复验安排。
- 效果结论能够回到原调整方案，并支持保留、缩小、撤销或继续调整。

## 四、技术设计

### 课程知识演进链

```text
知识白名单命令 + 当前知识库修订
-> 知识候选、质量门和双向影响
-> 用户确认
-> 与课程修订原子提交 + 幂等回执
-> 下游教案、讲义、练习和 PPT 重建计划
```

知识按稳定实体寻址。改一个知识点只失效引用它的下游；稳定知识 ID 和来源只能通过显式旧新映射迁移。候选遇到基线前移时先重定位，目标或字段已冲突则阻断，不静默覆盖。

### 教师全课变更链

`course_evolution/change_planning.py` 保存老师原话、解释、约束、保护项和执行策略，不拥有正式课程。普通内容计划使用经过当前正式字段命中校验的精确补丁并编译为 `REPLACE_COURSE_BLOCK`；结构计划使用完整目标树、旧新身份映射和显式退休节点，编译为单个 `REBUILD_COURSE_OUTLINE`，覆盖新增、更新、移动、排序、拆分、合并、退休和重建，并为每类受影响产物给出复用、重绑、局部改写、重建、退休或阻断决定。

教师明确提出“A 统一替换为 B”时，`course_evolution/teacher_planning.py` 先在大纲、正式 `CourseDocument`、教案、讲义、题库和 V6 PPT 的可编辑文字中确定性查找并形成精确补丁或领域迁移，再进入同一个计划与操作组；这一窄场景不依赖模型是否返回合格 JSON，也不改写 ID、修订号、来源关系和答案真值。零命中必须返回范围澄清，不能退化成只有索引命中、没有正式操作的假候选。其他语义改写仍由模型分析，但输出继续接受本地字段命中与结构完整性校验。`course_evolution/application.py` 不重写这些领域规则，只把手工调整、证据触发调整、审阅、采用、拒绝、撤销和重建协调到原有 `CourseEvolutionPlan` 上。

前端只渲染合同返回的资产、前后差异、影响和回执；缺少真实预览时显示待载入，不补造内容。教师确认内容范围或新结构后，仍调用原 `change-set generate` 入口；内部适配器把已审阅迁移编译为教案候选、讲义分节候选、PPT 页批次候选和题库修订候选，并作为 `APPLY_DOMAIN_CANDIDATE` 操作追加到同一个 `CourseEvolutionPlan`。历史学生正文和课程结构仍通过 `CourseCommandService.apply_block_operation_group` 写入；统一教师课程的精确正文由 `exact_authoring.py` 定位当前讲义所有者，转为同一操作 ID 的 `exact_script_block` 领域操作，经已有讲义候选采用与撤销命令写入教师仓储，不写派生 CourseDocument。所有候选通过原 accept/undo 入口返回逐资产 applied / failed / unchanged 回执并保留 last-good。这里没有新增顶层工作流、公开 API 或课程真源；跨仓储写入仍按真实回执协调，不能把部分成功描述成跨域数据库事务。

课程调整中的题库重建继续使用[课程生产的题库与恢复规则](课程生产.md#文件和题库实现)，不建立范围任务专属题库。

全课语义影响分析由既有 `teacher_course_change_analysis` 任务执行。`course_evolution/semantic_scan.py` 先校验每批响应的数组、对象与内容 ID，再合并；可选空补丁归一化为空数组，损坏响应只阻断对应批次，不把未完成检查当成成功。模型异常保留分类原因，课程方案保存和任务检查点写入异常不触发模型重试。

成功批次保存在原任务的私有 `analysis_checkpoint` 中，任务终态保留该检查点，轮询与单任务响应不返回其完整内容。同一任务恢复或同一教师重试失败／阻断分析时，按完整输入、课程来源修订、模型路由标识与扫描合同指纹验证结果；任何一项变化即重新扫描。拆批后已成功的部分可以直接复用，取消任务不成为新任务的复用来源。进度返回实际完成、复用与未完成的内容分片数量；首次分析仍逐批完整检查，未引入无界并发或缩小检查范围。变更分析提示词或合并语义时同步更新扫描合同版本，避免复用旧判断。

### 部分审阅与恢复

课程联动的扫描覆盖率、可审阅性和可应用性分别计算。部分扫描完成时可以展示已完成判断；后端以已完成来源、实际写入范围、共同结构与老师决策计算 `partial_review`，审阅、候选生成和正式应用共用同一依赖门。部分采用必须明确选择已审阅的操作，整课结构和依赖未就绪的修改继续等待，回执与撤销使用原命令。

范围草稿通过原 review 接口的 `selection_only` 保存到 `scope_selection`，与正式 `scope_review` 分离，补查按稳定来源 ID 继承选择。已定位到原位正文的精确修改可绕过无关的全局问题；关联教案的标题变化仍需显式保留原标题或处理教案。教师可先编辑可定位的建议，草稿变化会撤销对应旧应用许可。`content_patches.py` 按原文偏移编译补丁，合并重复项、拒绝冲突，语义长段扩写只处理首个重复锚点并提示位置；字面全量替换保持原语义。旧建议须整理后再审阅，人工版本不自动覆盖。预览选择主正文字段，避免拼接结构化镜像；`CourseChangeDetailView` 在现有工作区内承载独立详情并恢复返回位置。

教师精确正文采用前校验当前投影块、讲义与教案修订及完整讲义质量；同讲正文与整讲重生成建议不能混合覆盖。候选身份、基础修订及预期结果写入现有操作日志后才正式采用，中断按结果修订对账。同讲多项撤销沿已验证的反向回执链恢复；外部修改或来源冲突继续拒绝写入。

分析过程只轮询既有单任务摘要，终态再读取方案；提交期间的后台读取不能覆盖新任务回执，终态结果读取失败继续对账，不重新请求模型。任务终态保留扫描分片统计、`analysis_outcome` 与剩余数量，界面区分任务结束和全课检查完成，并沿 `superseded_by_plan_id` 展示替代结果。未就绪或长篇结果按需展开，底部操作栏固定；等待教师决策时提供统一说明入口，由用户明确确认后沿既有 `confirmedInterpretation` 重新分析全课，不自动采用课程修改。

“重新检查未完成内容”通过 `rescan_incomplete_only` 显式绑定原方案、要求与材料范围，逐项比较来源修订；保存的方案判断可在旧任务检查点不可用时恢复。未变化的已检查项和成功应用项不重复请求，来源发生变化的项重新分析，原方案人工编辑的有效候选继续保留。部分应用后补查保存接续方案，不拒绝或覆盖已应用方案的回执。分片覆盖原文，普通正文按1200字符、超过6000字符且含代码围栏的正文按600字符分片检查，均保留100字符重叠；最终单片超时可有限拆小，来源编号或返回结构错误附合法编号进行有限纠错。模型输入不再重复发送完整可编辑正文。新批次检查点使用 `teacher_semantic_scan_v2`；显式补查仍能逐项恢复旧方案已完成且来源未变的判断。


### 授权、版本与学习影响

原 `CourseEvolutionPlan`、领域命令与回执用于两端的合法课程修改；教师命名的适配器仅是当前入口，不能作为学生自有课程永久禁用修改的依据。共用服务逐次校验操作者、目标课程、可变字段和基线；不得为学生复制另一套采用、撤销与重建逻辑。

影响分析消费统一正文/题目身份，并把学习锚点和历史版本需要一起纳入。学习记录仍由原仓库维护；只能提交明确的重定位关系或更新提示，不跨写个人正文。版本追溯依赖后端留存或有界快照，前端缓存不能独立承担历史恢复。

### 局部修改与材料执行

字段请求携带 `base_revision_id`、`section_node_id`、`target_field`、`target_item_id`、`selected_text`。服务端重读目标并校验身份，模型只返回该字段 `value`，兄弟字段与其他小节不进入可变范围。上下文只提供本讲约束、知识关系和相关资料；完整结果校验后交付，心跳不能冒充输出。

`course_material_absorption` 将材料方案寻址到 `managed:outline`、`lesson-plan:{lesson_unit_id}`、`script:{lesson_unit_id}`、`ppt-v6:{lesson_unit_id}`。材料执行以 `plan_id + target_id + content_hash` 幂等；前端 `courseUpdateCenter` 只整合来源列表和选中状态，不能另存正式内容或任务。

语义扫描遇到提供方熔断时，在原任务写等待原因并等待有界窗口，恢复失败停止后续调用。失败、结构损坏和未检查分别报告；成功分片检查点按输入、来源修订、模型路由及扫描合同核对后才能复用。

### 验证

必须用教师课程和学生自有课程分别证明局部修改不扩大范围，学生不能修改未获编辑授权的教师课程，旧修订不能误采用；跨资产应用和撤销有真实回执，断连/重启能对账，部分失败不抹掉成功项。知识修改要检查双向依赖和稳定 ID。课程效果另需长期、跨课程及独立复验，静态测试不证明教学改善。
