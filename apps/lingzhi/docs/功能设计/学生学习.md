# 学生学习

灵知面向学生成长，支持自主创建/导入课程和学习教师授权课程，并以这些教学内容为核心，形成个人学习路径与生成式复习、补充理解和应用材料。阅读、笔记、AI、练习、错题与继续学习承载实际使用过程。教师预览是临时模式，不代替正式学生服务。产品分工、共有课程、权限与版本规则见[产品蓝图](../产品蓝图.md)。

## 一、内容设计

### 学习对象及其归属

| 对象 | 必须记录什么 | 保存责任 |
| --- | --- | --- |
| 学习中的课程 | 课程身份、来源、自有/获授权关系、当前可访问修订 | 共有课程与访问能力；课程库只查询和展示 |
| 学习内容 | 讲次、小节/内容块稳定身份、正文、学习目标和来源修订 | 正式课程拥有者；学习页不另存可独立修改的正文 |
| 笔记与引用 | 本人、课程、内容身份、来源修订、原引用、个人正文及记录修订 | 原学习记录仓库；随手记允许无原文锚点 |
| 作答与反馈 | 本人、题目修订、答案、提示使用、评分依据及反馈 | 原练习与作答仓库；草稿与正式提交分开 |
| 错题与再练 | 原作答引用、需要复习的依据、后续尝试关联 | 从正式作答派生，不另存第二套分数和答案历史 |
| 位置与进度 | 本人、课程修订、内容位置、真实学习事件 | 原学习进度/快照与事件能力；滚动不等于掌握 |
| AI 会话 | 本人、会话、发送时课程/内容/题目上下文及引用 | 原 AI 会话能力；不得冒充正式学习事件或课程正文 |
| 学习判断 | 使用的事实范围、解释与不确定性 | `LearnerModel` 可重算投影，不反写原始事实 |
| 个人学习材料 | 本人、用途、关联课程、来源对象/范围/修订、生成依据、正文及材料修订；区分课内、前置补充和拓展 | 独立材料对象复用共有内容与任务能力，拥有自己的写入责任，不成为教师正文副本 |
| 学习路径建议 | 当前目标、起点依据、建议顺序、材料引用、推荐理由、学生选择与路径修订 | 个人路径保存建议与选择；完成情况读取实际学习事实 |
| 应用成果与反思 | 本人提交的解释、作品/附件引用、自评和所用材料版本 | 复用个人记录与文件能力，区分学生作品、AI 示例和模型反馈 |

学生创建课程的输入包括学习目标、现有基础、希望覆盖的范围、时间与资料；课程名可编辑，行政代码、学分、班级课表、教案与 PPT 均非学习的必填前置。输入与生成细节由[课程生产](课程生产.md)维护。

### 生成式学习材料的内容

| 用途 | 材料应当提供什么 | 后续可以取得的学习依据 |
| --- | --- | --- |
| 复习与巩固 | 围绕选定目标整理要点、相互关系、个人疑问与代表练习，不把整课机械缩短 | 解释、检索回忆、练习及复习后的自评 |
| 补充理解 | 针对具体困难补前置概念、分步说明、例子与反例，保持原概念条件准确 | 学生能否解释原因、区分适用条件或独立完成相邻任务 |
| 应用与探究 | 围绕兴趣或真实问题给出可完成的小任务、支持材料和成果要求 | 学生实际提交的方案、作品、问题和反思 |

这些是本轮材料设计的代表用途，沿用已有“系统学习、项目实践、期末冲刺”学习目的，不新增一套互斥课程分类。每份材料讲清目标、与课程的关系、必要说明或任务、来源与后续行动；不强制每份材料都包含全部栏目。更广的跨课程、跨模态材料后续按真实需要扩展。

## 二、逻辑设计

### 三条正式使用路径

| 路径 | 使用过程 | 完成条件 |
| --- | --- | --- |
| 自主创建 | 目标/资料 → 可编辑学习范围 → 明确开始 → 共有生成任务 → 阅读与练习 | 本人拥有课程，过程可观察，可读结果保留，中断可继续 |
| 导入已有课程 | 选择文件 → 解析与范围核对 → 明确导入 → 正式课程 | 原文及来源保留，结构和公式问题说明，不凭重复提交创建副本 |
| 学习教师课程 | 服务端验证授权 → 可用内容与修订 → 学习现场 | 不出现教师私有内容/写入权限，个人记录真实独立保存 |

课程生成失败、题目尚未生成或来源暂不可用都应分别表达，不用整课失败遮住已有可读正文。正式学习不强制执行教师备课界面的每一步，也不调用教师预览 API 来代替持久学习。

### 从学习需要到个人材料

1. 学生从当前讲、自己选定的笔记/错题或一个学习目标进入，明确要理解、复习或应用的范围。只使用本人选择或该用途已获授权的证据，不默认扫描全部私人对话。
2. 系统展示生成依据与材料范围，区分课程要求、前置补充和兴趣拓展；缺少证据时使用学生自述及明确范围，不编造薄弱项或画像。
3. 学生明确启动后，沿[共同生产能力](课程生产.md#个人材料的生成与保存)生成、保存并打开材料；已有材料继续可用，生成失败可恢复。材料不必成为新课程，也不自动替换正式教材。
4. 学生阅读、编辑、练习或完成应用任务，形成与材料和题目修订绑定的真实记录。AI 示例不作为学生成果，保存材料不自动计为学习完成。
5. 学生结合实际困难与反馈选择继续、补充、重练或调整材料；再次生成有新修订与理由，保留原有记录和手工修改。

灵知独立运行时使用自建/导入内容作为来源；启智接入后，消费获授权的教材及边界，保留同源引用。学生材料可以拓展，正式教材的规范审查状态不会自动传给这些材料。

### 路径调整与学生成长

首版先在单门课程、明确范围内建议下一步：沿课程顺序学习、补充前置、针对练习或应用任务。每条建议说明依据、通向的目标和可选动作，学生可跳过、调整或恢复默认顺序；跳过内容不自动记为掌握。面向有界教材的路径仍须保留共同必学要求，不足之处明确可见。

学生选择的学习目标可以包括理解与表达、迁移应用、问题探究或自主规划。系统结合解释、作答、作品和反思提供反馈，不将它们压成未经验证的“成长总分”，不以考试分数、点击次数或一次答对替代整体判断。推荐策略及效果需要真实样本验证，首版不依赖知识图谱或复杂长期画像。

### 阅读、记录与提问

阅读位置、原文引用与笔记在同一课程修订下定位。就地记录和笔记本使用同一个保存入口；慢网、重复提交和版本冲突时保留输入，明确正在保存/已保存/失败，不提前关闭编辑器造成误判。再次进入能恢复已保存结果和合法位置。

AI 问题锁定发送时的正文或题目范围，随后滚动不改变上下文。解释、举例和简化先作为个人帮助；保存笔记或应用课程修改是显式动作。学生可以按正式命令修改自有课程；学习他人课程时补充留在本人范围，无正文写权就不展示或接受“应用到课程”。

### 练习、错题与复习

练习读取有权限的正式题目修订，草稿、提示、提交、评分与反馈沿原练习链完成。重试同一次提交不得重复记分，主动再次作答形成新尝试；错误提示不能假称已经保存成功。

错题本从本人正式作答及复习状态取数，可回看原题、原答案、解析和再次练习。再练关联原尝试，新结果不覆盖旧结果；错题列表、学习概况和 AI 引用必须能对账。同一题新修订与旧题区分，历史答案不按新题强行重判。

复习与继续学习按有正文及学习目标的内容身份计算，不把 `node_level == 2` 作为所有新课程的资格条件。阅读、提问和答对一次是不同证据，不能直接合成未经验证的精确掌握率。

### 课程更新与访问变化

遵守[蓝图的版本规则](../产品蓝图.md#版本更新与个人历史)：明确当前学习版本、受影响范围及返回位置。未变化内容继续使用；失去原定位的笔记保留原引用并提示重新定位；未提交的旧题草稿先核对题目版本，不能悄悄换题提交。切换新版本不得抹掉旧作答和学习记录。

访问撤销、课程删除或来源暂不可用时，区分无权、已删除和临时失败。本人记录按约定保留和管理，原文回跳受当前权限检查；不从缓存或历史引用接口绕过访问限制。

个人材料和路径同样遵守上述规则：来源变化先提示实际影响，学生决定采用哪个材料修订；受限原文与个人原创部分按来源许可处理，不能通过保存为个人材料绕过撤销。历史练习引用当时材料和题目，更新不静默重判。

### 教师预览

教师预览使用明确预览作用域和 owner 权限，锁定正文与题目修订。试做、问答和临时笔记只留本次会话内存，退出清除，不写任何身份的正式事件、作答、画像或记录。来源变化要求刷新。教师自己进入正式学习空间时则以本人身份保存学习事实，两种模式不能根据页面相似程度混用。

## 三、交互设计

### 学生课程库与入口

学生工作空间以“我的课程”为入口，提供新建、导入、继续学习及可访问教师课程；明确课程来源与可执行操作。恢复早期以学习为中心的功能关系，沿用当前视觉与组件，不回退整套旧代码。

新建输入围绕目标、基础、范围、时间与资料；必要规划由共有能力承担。任务显示真实范围、已完成内容、等待或失败原因及继续入口。导入在正式写入前核对识别结果，识别失败保留原件与输入。

教师切入学习空间不改变角色和归属；学生不能通过切换按钮获得备课管理权。导航保持课程和位置，工作空间切换不取消已有后台任务。

### 学生学习现场

- 左侧显示讲次目录，中间显示连续课程正文。
- 学习者直接看见本讲要学会什么、完成什么和怎样证明学会。
- 正式练习从对应正文位置或课程练习视图进入，关闭后回到原内容锚点。
- 桌面阅读页右栏顶部提供“笔记 / AI 助手”标签，默认显示笔记；切换保持 AI 会话、输入草稿和笔记编辑结果。全课程笔记本继续从底栏进入，负责搜索、分类、排序和导出。
- 有原文锚点的笔记以短条贴近对应正文位置，随正文滚动，密集笔记向下错开避免重叠；手动滚动笔记栏暂停跟随，可显式恢复。随手记与未定位的引用笔记归到本讲其他笔记，不伪造段落位置；点击短条打开原有编辑器，定位操作回到原文。
- AI 助手显示当前讲与小节。普通问题携带发送时的阅读位置，引用提问优先使用引用位置；之后滚动不改变已经发送问题的上下文。教师预览笔记仍只留在本次内存会话。
- 错题、复习与学习记录读取正式学习事实，不建立各自的进度副本；本轮不新增知识图谱界面。
- 学习位置、笔记草稿和人工智能会话在合理范围内保持连续。
- 教师预览不读取或写入学生数据。

### 笔记本、错题本与继续学习

笔记本支持课程内查找、分类、编辑和返回原文；错题本支持按讲次/复习状态筛选、回看原作答与针对再练。二者是原记录的整理视图，不再独立维护学习事实。课程内这些能力是本轮交付范围，跨课程聚合可以复用相同记录后续扩展。

继续学习展示上次位置和有依据的可选行动，不把模型猜测写成必须执行的路径。练习打开时能看见相关题面和上下文，退出返回原内容锚点；笔记或答题保存失败就近提示并保留草稿。

预览模式明确说明记录不会保存；正式模式显示真实保存状态。内容更新、无权限和暂不可用都给出原因及合法恢复动作，不展示一个笼统空页。

### 我的学习材料与下一步

课程内提供“我的学习材料”，从正文、笔记或错题进入时保留选定范围。生成前简要呈现目标、来源、所用个人记录及材料用途，允许修改；已有目标足够时不重复填写整套建课表单。

材料列表按课程及用途组织，显示名称、目标、来源更新状态和上次使用位置。打开材料沿用连续阅读、笔记、AI 与练习组件，明确标识“个人学习材料”；来源可访问时能返回正式课程，拓展内容显示与课程要求的关系。编辑、重新生成与删除作用于当前个人材料，不作用于教师教材。

继续学习保留上次位置，并在有依据时给出可选择的下一步及简短理由。学生可直接继续、调整目标或选择其他行动；不强制接受画像和推荐后才能阅读，不增设独立的成长排行榜或复杂导航。具体视觉布局在实现时沿用现有组件验证。

## 四、技术设计

### 共用实现及必要调整

| 能力 | 现有实现入口 | 联动调整要求 |
| --- | --- | --- |
| 正式身份与访问 | `qizhi_auth.py`、`dependencies.py`、领域路由 | 支持学生使用共有服务，保留教师专属权限；列表、详情、任务、导出和流连接一致检查 |
| 阅读与来源 | `teacher_content_projection.py`、课程仓储、`LearningView.vue` / `LearnerCourseView.vue` | 消费统一授权内容及修订；教师投影只读，学生自建不伪装教师课程 |
| 笔记与引用 | `routers/learning_records.py`、原记录 Store 与阅读笔记组件 | 复用保存、幂等及并发修订检查；锚点带来源版本 |
| 练习与错题 | `routers/practice.py`、作答仓库、`routers/review.py` | 题目访问、提交、评分、再练和复习范围一致，去除不适用的旧层级假设 |
| 进度与学习判断 | `learning_runtime.py`、`learning_events.py`、`learning_records.py`、`learner_model.py` | 运行态协调不独立存储，事实与解释分开，进度能从正式数据重建 |
| AI | 原 AI 老师服务、上下文与候选命令 | 只使用本人有权读取的最小上下文，课程修改仍验证归属和来源 |
| 临时预览 | `routers/teacher_preview.py`、原 Store 的预览作用域 | 明确隔离，无学习写入，复用评分能力但不复用正式作答保存动作 |

当前角色白名单、生成入口与旧复习范围尚未完成目标改造；具体差距见[产品状态](../产品状态.md)。新入口、手工操作、AI、批量、重试与恢复须调用同一权限和领域规则，不能复制学生专用评分或保存链。

### 个人材料与路径的实现责任

现有课程、笔记和 AI 会话不能直接充当个人生成材料的存储合同。实施前明确材料拥有者、来源引用、修订与授权检查，并复用已有文件/正文保存、生成编排及 TaskManager；新增领域对象不意味着复制底层能力。生成输入绑定实际采用的个人证据及版本，日志不保存这些私人内容。

路径建议与实际学习事实分离；建议改变只形成新路径修订，不能回写完成状态。材料中的正式练习沿同一题库/评分规则创建独立题目修订，并绑定个人可见范围；未保存的 AI 示例不进入正式分数与错题。应用任务的反馈保留证据与不确定性，首版不新增独立自动评分系统。

跨应用来源按[蓝图的同源边界](../产品蓝图.md#同源数据与跨应用边界)检查授权；课程、材料、学习者、生成任务和缓存之间保持同一作用域。私有材料及其下载不可因引用公开课程而变成公开内容。

### 联合验收

至少覆盖学生自主创建、导入、学习教师课程、教师正式学习与教师预览；两名学生共用一门课时个人数据隔离。逐项验证读取、记笔记、提问、练习、错题再练、关闭后再次继续，以及重复提交、慢网、并发保存、版本变化与授权撤销。

已有 `backend/tests/test_teacher_preview_unified.py` 只能证明相应预览边界；正式学习还须运行实际完整流程，教师生产回归与学生验收同时通过才证明共用能力可交付。

个人材料至少以两名学习者、同一核心内容、不同目标/困难验证差异的依据，覆盖复习、补充理解和一个应用任务。检查默认路径、调整/拒绝建议、材料保存与再次进入、来源变化、授权撤销、手工修改保护及失败恢复；作品与反思确由本人提交。能生成不同材料只是功能证据，理解或应用是否改善还需真实学习样本。
