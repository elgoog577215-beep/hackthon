# 灵知评委路演展示方案

2026-10-20按最新产品定义调整。当前产品介绍沿用已制作的 **16 页框架和蓝紫色风格**，重排讲述重点；若用于 **8 分钟 PPT + 4 分钟网站演示**，附录不占主讲时间，按赛事规则压缩主讲页。当前尚未取得评分表和原申报材料，项目类别、正式名称、团队信息与参赛措辞在定稿时对照原件。

建议标题：**启智与灵知：一门课程，千人千面**。

产品定义：面向学生自学的 Agent，以讲义为学习主体，与教师 AI 联动。先让观众看到学生怎样通过讲解、提问与练习学懂，再解释目的与场景怎样决定教学编排、知识树和画像怎样支持动态调整，最后回到教师的一键备课、联动修改与二次备课。讲解线与个性化线共用同一个学习现场，具体定义见[阶段项目目标](阶段项目目标.md#产品定义与建设主线)。

## 展示内容与优先级

| 优先级 | 展示内容 | 评委需要看到的证据 | 当前展示边界 |
| --- | --- | --- | --- |
| 必讲 | 讲义中的讲解、提问与练习 | 一段完整学习内容、就地提问与练习，体现教学顺序、比例和节奏 | 当前实拍只证明已有画面与操作；尚未实现的动态编排单独画方案示意 |
| 必讲 | 同一课程的不同学习场景 | 用同一个 C 语言知识点对照备考和项目的讲解重点、提问方向及练习安排 | 未生成或未核对的对照内容属于教学编排示例，不伪装成运行中的自动调整 |
| 必讲 | 多模态与推导依据 | 用图表解释一个具体关系或过程，侧栏能展开依据与关键步骤 | 展示可复核内容；不把旁边多一个聊天窗口称为完成推导拆解 |
| 必讲 | 教师备课工作台 | 一门课的目标、讲次、大纲、教案和教材式讲义 | 展示已准备的产物；现场只做短操作，完整生成用录屏说明 |
| 必讲 | 讲义阅读与 AI 追问 | 同一处正文、选区引用、针对该段的解释、笔记入口 | 彩排确认模型连接和上下文；避免任意开放提问拖长演示 |
| 必讲 | 知识树与题目关联 | 从知识点回到讲义、查看已有题目及绑定关系 | 自动匹配结果仍有待确认项，现场采用已核对绑定；关联不等于已确定错因 |
| 必讲 | 教师课程与学生学习空间 | 授权课程、相同讲次、阅读与继续学习、笔记或 AI | 使用演示账号；学校联合登录及目标环境另行验收 |
| 必讲 | 学生练习与教师反馈 | 已有练习、一次作答或历史记录、教师侧反馈回执 | 完整题库尚未整体验收；人工联调题须明确标注，不计教学效果证据 |
| 选讲 | PPT 与教学表达 | 同一讲义对应的内容稿、预览与真实导出文件 | 固定样例已有导出验证，两门存量课程暂无已发布 PPT；彩排须选定可复核的实际文件 |
| 选讲 | 局部调整与任务恢复 | 修改作用范围、人工决定、已有回执或恢复结果 | 复杂联动仍需整链验收；仅展示彩排确认的操作或带范围说明的录屏 |
| 必讲 | 个人学习材料 | 本人资料或授权课程、用途选择、生成结果、保存重开 | 与教师规范资料的来源关系清楚；项目实践完整流程仍有差距 |

题目生成逻辑保持现状。路演使用已有、经核对的题目与解析；题目生成细节放在答辩材料中。

### 已有截图怎样继续使用

- 讲义工作台、完整公式与例题、阅读与选段提问，前移到第 4—6 页，构成学生学习现场。
- 整树截图用于第 7 页；学习记录、笔记和画像用于第 8 页；伴学与自测用于第 9—10 页。当前知识画像与伴学交互中的预设数据、预设回答持续标明为交互演示。
- 教师备课与联动修改实拍分别移至第 11—12 页，个人统计与教学行动映射用于第 13 页。
- 重点补齐同一知识范围的两种场景编排、连续教学块和实际图表/步骤展示。只有结构示意可用时直接画教学编排，不生成虚构产品截图。
- 主讲页通常保留一张主要实景图和两三句说明。画像数值、证据规则和数据合同放在备注或附录，避免后半段再次变成机制表格堆叠。
- 用户已明确展示方式：能截图的直接截当前页面；缺少的界面先复用当前页头、导航、配色和组件布局，制作独立演示页，再用浏览器截图。方案页标明示意与示例数据，不另造一套产品视觉，不用图像模型生成的UI代替这些截图。完整知识树另保留原分辨率素材，PPT中以完整主干配合展开局部保证可读。

## 四分钟网站演示

准备教师和学生两个已登录的浏览器窗口。优先选择一门已经授权、具有完整讲义的现有课程，彩排后锁定课程和讲次。不同功能只有不同样例可用时，明确说“下面切换到专项样例”，不拼接成同一课程已经全程通过的叙事。

| 时间 | 操作 | 讲述目的 |
| --- | --- | --- |
| 0:00–0:45 | 学生进入已准备的讲义，展示一段解释、例子及就地练习 | 让观众先看到讲义怎样承载自学，说明所选学习场景 |
| 0:45–1:25 | 展开一个图表或关键步骤，围绕选段发送已彩排的短问题 | 展示清晰讲解与上下文帮助；缺少已验收步骤侧栏时展示实际可用部分 |
| 1:25–2:05 | 从知识点查看已有学习记录、原题和笔记，再回到正文 | 说明知识定位、历史与当前帮助的关系 |
| 2:05–2:45 | 做一道已核对的检查题，或展示真实尝试记录 | 说明后续独立表现怎样验证帮助，不以提示后完成代替掌握 |
| 2:45–3:25 | 切教师端，展示同一课程的备课资料和联动修改范围 | 交代内容依据及教师如何维护规范课程 |
| 3:25–4:00 | 展示授权反馈或已核对回执，说明个人、班级与时间维度的后续分析 | 收回针对性教学与二次备课；无真实班级报表时明确其设计状态 |

长讲义生成和 PPT 导出准备 30–45 秒录屏备用。已有首讲完整生成记录中，一次请求约 152 秒，因此现场演示预算不依赖整讲生成完成。录屏保留操作顺序和实际结果，标明录屏与样例时间；等待可剪短，不能伪装为实时速度。

模型响应超出彩排确定的等待窗口时，切换到该步骤的真实录屏或保存结果。模型状态以当场可见结果说明，不重复发起长任务。

## 三项重点与表达尺度

1. **讲义中能完成一次有效学习。** 用一段内容讲清讲解、提问、练习怎样配合，图表和关键步骤解决了什么理解问题。
2. **目的与画像落实到教学块。** 同一知识点因目的不同而编排不同，出现具体困难后再调整讲解、提问或练习。分别说明已有能力、交互演示与动态自适应目标。
3. **师生反馈有共同依据。** 课程产物对应同一目标、来源和修订，学习反馈按授权回到教师。用真实作答和后续检查说明变化，不以阅读或提示后完成直接证明掌握。

上述三项是建议的路演价值主张。与其他产品的差异、技术首创性和竞争优势需要独立证据，当前不使用“行业首创”“全面领先”等措辞。

## 素材与版式

- 16:9，沿用网站蓝紫色及白色背景。正文截图优先，减少装饰；标题建议 32–36 pt，正文 20–24 pt。
- 每页一句主张、最多三项说明，通常一张主要截图。需要比较时用两张同尺度裁图，标清对应区域。
- 截图锁定同一版本、同一课程和中文桌面。移除无关标签页、真实学生信息、访问令牌、服务地址与内部诊断信息；保留解释功能所需的文案。
- 必备素材：教师课程工作台、完整讲义片段、知识树定位、学生选区追问、保存笔记、题目与历史尝试、教师反馈。PPT 导出文件和长任务录屏按是否纳入演示补齐。
- 测试数和模块数放答辩附录，主讲页使用实际产物与操作证据。备课节省比例、用户量、准确率和提分数据只有真实记录并注明样本口径后才能使用。
- 沿用仓库文档格式，讲稿和素材引用在本方案维护；正式 PPT 的外部事实与素材来源写在对应页备注。

## 彩排前需要完成的事项

1. 对照赛事通知、评分表和原申报材料，确认正式项目名称、时限、申报类别与评分重点，区分赛事类别和最新学生自学 Agent 产品定义。
2. 锁定展示 URL、代码版本、演示账号、课程与讲次；本地合并通过不代表对外网站已经更新。
3. 核对所用课程正文、来源、知识点与题目解析。当前已有人工联调题和限定知识树样例，须在演示中标明用途。
4. 在实际展示环境走完两个身份的完整脚本，确认授权、中文桌面、选区引用、保存重开、模型响应和反馈读取；保护已有运行任务与课程。
5. 确认 PPT 页和导出文件真实可用；复杂图型、公式和字体按实际投影比例检查。没有通过的页面用其他已核对素材替换。
6. 用计时器完成一次 12 分钟彩排，准备离线 PPT、真实录屏、关键截图与已保存回答。代码与依赖问题单独处理，不在演示前临时调整题目生成策略。

## 答辩准备

| 评委可能提问 | 回答依据 |
| --- | --- |
| 与通用聊天工具有什么区别？ | 演示课程来源、讲次/选区上下文、持久产物、知识关联与反馈回执，而非只展示一次对话 |
| 生成错误怎么办？ | 说明教师核对与采用、原文依据和修订范围；生成成功与内容审定分别判断 |
| 是否验证学习效果？ | 当前可展示限定样例、真实操作与作答过程；长期效果通过教师评议、后续独立作答和试点研究验证 |
| 是否已经支持所有学科？ | 已有多类结构和渲染能力；跨学科真实内容质量仍需学科样本验证 |
| 数据如何在师生之间流动？ | 教师授权课程，学习事实按身份保存，教师接收明确范围的反馈；私人材料和会话不默认发送 |
| 题目生成是否稳定？ | 展示已有经过核对的结果，解释当前完整题库验收边界；本次保持原有生成策略 |
| 部署是否已经完成？ | 按展示环境的实际版本与验收回执回答；本地代码、构建和生产分别说明 |
