# 灵知当前阶段项目目标与开发准则

确定日期：2026-10-19；产品定义与近期主线更新：2026-10-20。适用于 `apps/lingzhi`，作为本阶段 AI 开发、评审和验收的共同依据。

## 产品定义与建设主线

灵知是面向学生自学的 Agent，以讲义为学习主体，与教师 AI 联动。围绕“针对性地教、个性化地学”，让同一门课程在共同教学要求下形成适合不同学生的学习内容与帮助，以“一门课程，千人千面”为产品目标。

学生以教师授权的规范课程资料或本人自建、导入资料为依据，在连续阅读中得到讲解、提问与练习。讲义承担主要学习过程，知识关系、推导依据和关键步骤可以在侧栏展开；项目实践同时保留任务、作品提交及反馈，不强制全部改成讲义。

### 讲解线：针对性与清晰讲解

1. **按目的与场景组织内容。** 同样学习 C 语言，期末备考侧重范围内的概念、题型与易错点，产业项目侧重任务需要、实现方法与应用约束，相应改变讲解重点、提问方向和练习安排。
2. **教学色块承载教学编排。** 围绕学习曲线调整讲解、提问、练习的顺序、比例与节奏；色块用于区分教学作用，编排须说明为什么在此处讲、问或练，不机械重复固定顺序。
3. **多模态帮助理解。** 文字结合适合知识内容的图表，解释关系、变化和过程；侧栏展示可核对的知识关系、推导依据与关键步骤。“思维链拆解”在产品中指这些面向学习者的教学说明。

| 教学块 | 包含的教学内容 |
| --- | --- |
| 讲解 | 背景、定义、推导、举例、对比 |
| 提问 | 复习性提问、启发性提问及沿回答继续的追问 |
| 练习 | 理论型 exercise、实战型 case |

### 个性化线：学习画像与动态自适应

1. **知识定位。** 知识树逐层细分，在具体知识点下关联易错点、拓展点、前置与资源；保持完整知识及其条件，易错表现不另拆成重复知识叶子。
2. **学习标注。** 对话、笔记和思考等动态痕迹，与作答对错、测验结果等静态痕迹，共同提供判断依据。红绿历史保留每次标注、来源与时间，不相消；无数据、待判断与有证据未通过分开，错误判断允许纠正。
3. **调整三类教学块。** 结合学习目标与同一画像，调整讲解的内容、结构、风格和深度，提问的复习/启发侧重与追问方式，练习的理论/实战比例、数量与难度。调整须落到具体知识点和教学块，再用后续独立表现检验。

“无感个性化”指减少重复填表和设置，结合课程上下文与学习过程逐步调整；关键调整仍可查看理由、修改、拒绝或稍后处理，不据此自动改变教师规范要求。

### 教师联动：一键备课、联动修改与二次备课

- 一份教学资料可作为备课起点，结合教师确定的目标和范围，生成课程大纲、教案、讲义、PPT、题目与实践任务，并配套细颗粒度知识树；保留既有产物确认与主动恢复边界。
- 课程目标、安排或内容变化时，识别受影响的资料，统一提出多格式关联内容的修改，保留人工修改，由教师审阅采用。
- 学生的学习场景与学情按授权回到教师端：个人看掌握情况、薄弱点和成长路径，班级看共性问题与学生差异，时间维度看持续变化，辅助更敏捷的针对性教学与下一次备课。

“启智—灵知”用于表达上述师生产品协作。当前实施仍以 `apps/lingzhi` 的教师与学生能力为范围，不据此修改 `apps/qizhi` 的身份、服务或部署。

## 阶段目标

在现有讲义、教学块、知识树、作答记录和 AI 问答的基础上，先按学习目的与场景形成清楚的讲解、提问和练习编排；再把学生在做题、对话和笔记中反映的问题对应到具体知识点，完善学习画像，分清是概念没懂、操作不熟，还是换个场景就不会。讲义、后续问答、题目生成和复习安排共用这份画像，针对具体困难调整教学块；再根据学生能否独立完成、过段时间是否仍会、换个场景能否应用判断效果，持续更新画像。判断不准时允许纠正，并将获授权的场景与学情反馈给教师，辅助下一次备课。

核心过程：学习表现 → 定位困难及依据 → 针对性帮助 → 后续独立验证 → 更新画像 → 授权教学反馈。

## 开发准则

讲解质量与个性化闭环共同验收。每次帮助都应能说明落在哪个教学块、改善什么理解问题，避免只增加聊天入口或画像数值而没有改善学习内容。

1. **判断有依据。** 关联具体知识点、学生表现、来源和时间；证据不足保留“待判断”。一次答错不直接认定缺少某种能力，反复提问也不直接等于不会。
2. **帮助对准困难。** 问答、出题和复习共用同一份画像，结合学习目标与可用时间提供解释、辨析、分步练习或变化场景。学生能查看理由，接受、调整或稍后处理。
3. **效果看后续表现。** 阅读、保存笔记、AI 整理稿、提示后答对与独立掌握分开记录。用新的本人表现验证效果，不把提供过帮助当成已经补齐。
4. **历史保留，判断可改。** 同一活动不重复计证，红绿历史不相消；当前判断随新证据更新，纠正保留依据，不覆盖旧作答、笔记和来源版本。
5. **保护内容与权限。** 个人补充不覆盖教师正文；教师只接收获授权的学情，私人笔记和对话原文不默认开放；教师预览不产生正式学习记录。
6. **复用现有能力。** 在现有知识树、题库、学习记录、画像和任务机制上完善，避免另建重复系统。优先打通一门课的完整过程，再扩大学科和场景。
7. **控制互动。** 根据实际困难决定是否追问、诊断和验证，不要求每次问答都跑完整流程，不反复打断学生。
8. **有明确对象地借鉴开源。** 按[开发计划的仓库对应与首轮工作](../../../changes/学习闭环开发计划.md#开源借鉴与首轮执行)选择方法和代码，说明借什么、接到哪里、怎样验证。优先统一证据并接通教学策略，再开展复习调度和画像算法对照；固定上游版本，复用现有正式仓储、权限、修订与任务机制。

## 开发与验收要求

- 每项相关任务说明：改善上述哪个环节、使用什么依据、学生会得到什么帮助、怎样验证结果。
- 验收既覆盖有效帮助，也覆盖证据不足、误判纠正、帮助无明显效果、重复提交及版本变化。
- 将代码实现、模拟测试、真实模型、真实学生和生产验收分别报告；不以生成成功或测试通过代替教学效果。
- 阶段目标不代表功能已经实现或具体任务自动启动。实施范围遵守现行业务规格、权限、数据和恢复约束；批次参考[学习闭环开发计划](../../../changes/学习闭环开发计划.md)。
