## 0. 一页结论

启智不应继续被理解为“输入主题，AI 一次性生成一门课”。近期最有价值、也最符合教师真实工作的产品形式，是一个围绕真实授课周期运转的课程工作台：

1. 教师进入“课程工作台”先看到自己负责的全部课程和教学总日历。
2. “新建课程”使用独立分步页。先填写课程名称、学年学期与教师并创建可恢复的课程壳；周数、星期/节次、地点和学时可在下一步补充，但生成教学日历前必须完整。
3. 空白、导入已有大纲、AI 规划只决定大纲的起点，最终都进入同一个课程壳、同一套受管资产和同一条确认流程。
4. 点击课程卡始终先进入课程概览，不根据状态突然跳页；概览用一个“下一步”引导教师继续大纲、日历或某一讲的制作。
5. 单课程一级导航固定为：**课程概览、教学大纲、教学日历、课程生产、课程文件、发布管理**。左侧负责分类，顶部集中状态，中间正文优先。
6. 教师主生产链是可暂停的阶段链：**大纲草稿 → 确认大纲 → 分讲教案 → 确认教案 → 按需生成 PPT → 确认 → 选择版本发布**。完成教案后可以离开，稍后再继续 PPT。
7. 大纲确认后同时解锁两条并行支线：课程教学日历和分讲教案。日历不是生成教案的强制门；二者共享教学单元，但修改不会静默互相覆盖。
8. 课程生产默认显示横向课次总表；单击教案/PPT状态进入大尺寸快速预览，点击“继续制作”进入沉浸式课次工作区。明确点击“继续”可以跳过预览。
9. 教案和 PPT 按教学单元组织；每个单元可以有多份 PPT，每份 PPT 可以有多个版本。列表默认只显示当前工作版，历史版本折叠收纳。
10. 教师工作稿、教师确认版与学生发布版分离。保存或确认不会自动改变学生看到的内容；发布创建不可变快照。
11. 课程生产和课程文件是同一资产的两种视图，不是两套内容。移动或重命名文件不改变课程关联，生成也不复制第二份内容。
12. 教师总日历位于“课程工作台”层，汇总多门课程；课程教学日历位于单课程层，负责一门课的教学安排和学校模板导出。
13. V1 不重构现有偏学生端的课程内容流程，不删除旧入口，也不把“学生资料”强塞入新的教师生产标签。学生侧最终归属作为下一阶段独立议题。

本轮开发应先按本方案重组真实教师生产流程，并复用 `/workspace-concept/teacher-course-v1` 已验证过的颜色、字体、按钮和紧凑尺度；不得照搬模拟页的信息架构。随后完成教学日历真实存储与教师总日历聚合。不要先重写 PPT 接口，也不要另建第二套 Course 数据模型。

## 1. 背景、目标与非目标

### 1.1 背景

现有项目已经具备课程生成、大纲审阅、教案工作台、课程正文、PPT 工作台、教师文件空间等能力，但它们被分散在不同页面和状态链中。现有课程生成体验更接近“生成学生电子讲义”，教师难以快速理解：

- 我现在处于哪一步；
- 哪些内容是课程级，哪些内容属于某一讲；
- 大纲改了以后教案和 PPT 会怎样；
- 当前编辑的是草稿、确认版还是学生版；
- 应该在生产页操作，还是在文件系统里操作；
- 教学日历与大纲、上课时间、课件之间是什么关系。

与此同时，教师真实工作不是每学期从零生成课程。更多时候是承接多年积累的大纲、教案、PPT、历年试题和学校材料，在旧版本上更新、检查、组织、发布和复用。

### 1.2 产品目标

V1 目标不是堆更多功能，而是让教师完成一条可信、可恢复、可理解的主闭环：

```text
进入课程工作台
  → 新建或打开课程
  → 确认课程设置与参考资料
  → 导入/生成并确认教学大纲
  → 形成教学单元与课程教学日历
  → 按讲次编辑/生成教案
  → 按讲次生成或导入 PPT
  → 预览学生版
  → 发布冻结快照
  → 按日历进入下一次真实授课
```

### 1.3 非目标

V1 暂不承诺：

- 自动对接学校教务系统；
- 复杂的实验课排课算法；
- 知识节点改变后自动重写全部下游内容；
- PPT 深度在线编辑器重做；
- 教师可查看学生私人笔记或私人 AI 对话；
- 让文件夹成为课程内容的第二数据真源；
- 以线性向导限制教师只能向前不能回看；
- 用抽象“智能指数”“可信度分”等无判断价值的数字占据首屏。

## 2. 第一性原理与产品定位

### 2.1 我们为什么服务

启智服务的不是“生成文件”这个动作，而是教师与学生围绕一门真实课程持续发生的教学关系：

```text
教师组织课程 → 真实授课 → 学生使用与反馈 → 教师判断并改进 → 下一次发布
```

因此，课程是长期对象，不是一次生成任务；文件是资产，不是孤立附件；日历是进入真实教学场景的时间索引；发布是师生权限边界，不是普通保存。

### 2.2 产品定位

推荐表达：

> 启智承接教师已有课程资产，帮助教师每天管理、检查和持续改进课程；同时让学生在教师权威内容上获得适合自己的学习路径。

### 2.3 近期优先级

1. 教师首先可用：已有材料承接、生产、版本、日历、文件与发布。
2. 学生同源使用：教师发布快照、私人笔记、AI 学习、主动反馈。
3. 质量建立信任：大纲一致性、内容过时、引用与事实风险逐步进入发布门。
4. 知识节点作为未来底座：先保留关联，不在 V1 强行做全链自动联动。

## 3. UI 设计宪法

本功能必须继承真实项目现有组件、按钮、字体、颜色、弹窗、抽屉、提示与表格风格。`/workspace-concept/teacher-course-v1` 只提供视觉气质与密度参考；具体栏宽、间距、展开方式和页面网格必须由当前功能任务决定，不能照抄模拟页布局，也不能创建另一套视觉语言。

### 3.1 硬性原则

| 原则 | 执行规则 | 禁止做法 |
| --- | --- | --- |
| 高密度 | 同一对象的状态集中在一行；首屏尽快出现正文 | 用四五张指标卡展示同一课程状态 |
| 强分类 | 左侧负责分类，点击后中间只展示当前分类 | 把大纲、日历、教案、PPT、文件说明全部平铺 |
| 少打扰 | 只在异常、不可逆或概念易误解时解释 | 每个区域都加“这里可以做什么”的说明文案 |
| 正文优先 | 状态栏后立即进入可操作内容 | 大标题、宣传文案、空洞指标占据首屏三分之一 |
| 少容器化 | 独立单元才使用卡片；同类信息共用行和区域 | 每个字段套圆角卡片 |
| 组件复用 | 复用原按钮、Badge、Dialog、Drawer、Toast、Confirm、Editor | 新造一套按钮、颜色、阴影和交互反馈 |
| 状态真实 | 状态来自真实 store/API；未实现能力明确标识 | 用 setTimeout、假 toast 假装生成成功 |

### 3.2 页面空间关系

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 产品栏：启智 / 课程工作台 / 当前课程 / 当前功能       学生预览  更多 │
├─────────┬────────────────────────────────────────────────────────────┤
│ 单课程  │ 顶部状态栏：课程｜资产状态｜待处理｜下一动作               │
│ 功能栏  │────────────────────────────────────────────────────────────│
│ 概览    │ [课次总览] [教案制作] [PPT]                 [智能操作 ▾]   │
│ 大纲    │────────────────────────────────────────────────────────────│
│ 日历    │ 主体编辑 / 审阅 / 表格 / 大尺寸预览区                     │
│ 生产    │                                                            │
│ 文件    │ 版本、来源、AI、影响按需打开抽屉，不固定占据正文           │
│ 发布    │                                                任务小浮窗  │
│         │                                                            │
│ 切换课  │                                                            │
└─────────┴────────────────────────────────────────────────────────────┘
```

左侧导航下方允许留白，但不得成为一条宽而高的视觉空洞：栏宽由最长标签、图标、徽标和正文最小可用宽度共同计算，并优先使用已有布局变量；降低边界对比，把“切换课程/返回课程工作台”固定在底部即可。不要为填满空间添加最近任务、指标或说明卡。课程生产总览只有这一根课程边栏，不能再常驻阶段边栏与状态边栏。二级生产分类放在正文顶部，进入具体课次制作时再把课程边栏收为图标栏并增加课次栏。

### 3.3 组件继承与功能布局矩阵

| 层级 | 处理方式 | 具体规则 |
| --- | --- | --- |
| 原子组件 | 直接继承 | 按钮、图标按钮、Badge、输入框、选择器、分页、Tooltip、Toast、Confirm 不重新造样式 |
| 复合组件 | 原样复用或薄适配 | `CourseOutlineReview`、`GenerationLessonPlan`、`CourseGenerationGate`、`CourseTaskCenter`、PPT 工作台保留接口与交互语义 |
| 反馈组件 | 统一继承 | 加载、保存中、成功、失败、冲突、二次确认使用项目既有模式；同一状态不在不同页面换表现 |
| 页面骨架 | 按功能重组 | 课程集合、概览、大纲、日历、生产、发布各自根据任务密度决定网格，不复制学生页或模拟页骨架 |
| 间距 | 使用现有 token 组合 | 以 `--space-1/2/3/4/6/8` 等项目 token 形成 4/8/12/16/24/32 节奏；组件内部沿用原间距，页面分区按关联强弱增减 |
| 栏宽 | 内容与任务驱动 | 导航以完整标签和徽标为下限，正文以表格/编辑器最小可用宽度为优先；需要空间时先折叠次要栏，不压缩正文到不可读 |
| 容器 | 只在独立任务使用 | 编辑器、预览、表格、任务抽屉可有容器；普通状态和字段不逐项套卡片 |
| 响应式 | 改变结构而非缩小全部 | 桌面用边栏，窄屏转图标栏或顶部短导航；宽表滚动，主操作保持可达，禁止竖排中文 |

判断顺序固定为：**先确认用户当前任务 → 决定页面空间关系 → 选择可复用组件 → 用既有 token 调整间距 → 浏览器验证**。禁止先复制一个现成页面，再把功能硬塞进去。

### 3.4 响应式原则

- `≥ 1200px`：一级课程边栏 + 顶部单行状态 + 主体；只有进入沉浸式课次制作时才出现第二层窄课次栏。课程生产总览不得同时固定“阶段栏”和“状态栏”挤压正文。
- `900–1199px`：一级课程边栏收为带 Tooltip 的图标栏；来源、版本、状态详情进入抽屉；表格保留首列、状态列和下一步列，次要字段允许横向滚动。
- `680–899px`：图标栏保持 64px，但活动项文字不得挤成竖排；顶部状态只保留当前页面、失败/待办与下一动作。
- `< 680px`：课程功能变为顶部可横向滚动的短导航，正文全宽；工具栏可分两行，宽表允许横向滚动并固定课次与操作列。禁止靠压缩列宽、隐藏主操作或竖排中文“适配”。
- 移动端主要完成查看日程、确认地点、预览材料、处理轻量提醒；复杂大纲、教案与逐页 PPT 编辑明确提示切换电脑端，但已有查看、保存、返回和异常恢复动作仍必须可达。

### 3.5 模拟页面参考规则

`/workspace-concept/teacher-course-v1` 保留为可浏览的交互实验，只能作为视觉气质、空间密度和控件尺度参考。它不是信息架构、状态机或页面层级真源；真实改造必须遵循“复用原项目风格，按已确认方案重建逻辑”：

| 模拟页内容 | 真实页面处理 |
| --- | --- |
| 顶部产品栏、品牌、面包屑 | 参考视觉并接真实路由；具体层级以本方案为准 |
| 左侧课程身份和功能边栏 | 参考视觉与尺寸，导航严格为概览/大纲/日历/生产/文件/发布 |
| 紧凑的一行状态 | 继承样式，数据改接真实 course/generation/calendar 状态 |
| 低容器化正文、表格和按钮 | 继续沿用，不增加指标卡阵列或说明卡片 |
| 原有颜色、字体、圆角、边框、图标 | 优先复用项目 token、Element Plus 和现有组件 |
| 模拟课次与假进度 | 全部替换为真实教学单元、资产版本和任务状态 |
| 原页面的课程生产排布 | 不继承；严格实现课次总表 → 大预览 → 沉浸式制作 |
| 原模拟路由 | 保留作为只读对照和体验参考，不被真实页覆盖 |

优化重点不是让真实页面“长得像另一套新后台”，而是在模拟页已有观感上解决空间拥挤、层级不清和假交互问题。

## 4. 全局信息架构

### 4.1 平台层级

```text
启智首页
├─ 课程课件/课程工作台
│  ├─ 我的课程（默认页）
│  ├─ 教学总日历
│  └─ 新建课程
├─ 视频分析（与课程课件平级的独立能力入口）
└─ 独立功能（论文助手等，本方案不展开）
```

知识库和 AI 学习工具不在顶层结构图中重复展开；它们是可被课程引用的通用能力或独立功能。

### 4.2 课程工作台层

教师点击“课程工作台”后，首先进入课程集合，而不是直接进入某一门课。

```text
课程工作台
├─ 我的课程
│  ├─ 按学年/学期分组的紧凑课程卡
│  ├─ 当前学期课程
│  ├─ 历史学年课程（默认折叠）
│  ├─ 被授权课程
│  └─ 新建课程
└─ 教学总日历
   ├─ 月视图
   ├─ 周视图
   └─ 列表视图
```

课程卡只保留教师可立即判断的信息：课程名称、授课对象/学时、教学大纲状态、教学日历状态、教案/PPT进度和一个“下一步”。版本历史、来源和批量动作不进入卡片。

### 4.3 单课程层

```text
单课程工作台
├─ 课程概览
├─ 教学大纲
├─ 教学日历
├─ 课程生产
│  ├─ 课次总览
│  ├─ 大尺寸快速预览
│  └─ 单课次制作：教案 / PPT
├─ 课程文件
└─ 发布管理
```

教学大纲、教学日历和课程生产是三个独立的专业页面，但共享同一课程壳、同一教学单元和同一 CourseAsset。生产页可以查看大纲片段和来源版本，但深度修改大纲必须回到教学大纲页，不复制第二份大纲编辑器。

学生与反馈不是本轮单课程一级导航的实施范围。现有学生学习入口和课程内容流程保持原状，待师生关系、私人笔记与反馈策略独立确认后再进入导航重构。

## 5. 关键对象模型

### 5.1 必须区分“教学单元”和“授课场次”

参考资料揭示：一份大纲可以定义约 32 讲，但正式教学日历样例包含 63 条上课记录。同一个实验内容会分 A/B/C 班，在不同地点或由不同教师重复授课。

因此必须采用两层模型：

| 对象 | 含义 | 示例 |
| --- | --- | --- |
| LessonUnit 教学单元 | 课程内容顺序与教学目标 | 第 9 讲：模型迭代与产品发布 |
| ClassSession 授课场次 | 实际发生的一次上课 | 2026-03-24 08:00，紫金港西 1-415，理论课 |
| SessionGroup 班组 | 同内容的不同学生群体 | 实验 A 班、B 班、C 班 |
| Artifact 课程资产 | 大纲、教案、PPT、讲义、作业等 | 第 9 讲主教案、主课件 |

关系：

```text
Course 1 ── N LessonUnit
LessonUnit 1 ── N ClassSession
LessonUnit 1 ── N TeachingPlanAsset
LessonUnit 1 ── N SlideDeckAsset
ClassSession N ── 1 LessonUnit
ClassSession N ── 0..1 确认使用的教案版本/PPT版本
```

### 5.2 课程资产单真源

生产表和文件树是同一 CourseAsset 的不同投影：

```text
CourseAsset
├─ asset_id（稳定）
├─ course_id
├─ lesson_unit_id（课程级资产可为空）
├─ type：outline / calendar / plan / content / ppt / raw_file
├─ folder_membership（组织位置）
├─ versions[]
├─ working_revision
├─ teacher_confirmed_revision
├─ student_published_revision
└─ dependency_state：fresh / stale / needs_regeneration / blocked
```

移动和重命名只改组织元数据；不会改变 asset_id、教学单元关联和版本历史。

### 5.3 三个版本指针

每个受管资产至少区分：

1. **工作稿**：教师正在编辑，可频繁保存。
2. **教师确认版**：教师认为可以作为下游生成依据。
3. **学生发布版**：学生当前可见的冻结快照。

保存工作稿不自动确认；确认不自动发布；撤回发布不删除教师资产；恢复历史版本会创建新工作稿，不覆盖历史。

## 6. 完整用户路径

### 6.1 教师首次进入

1. 登录后进入“我的课程”。
2. 只显示本人拥有或被授权的课程，历史学年默认折叠。
3. 页面顶部显示近期课程与需要处理的真实事项，不显示无意义综合分。
4. 若无课程，正文直接出现三种新建方式。

### 6.2 新建课程

新建入口只有一个，使用独立分步页面，不在课程列表上用拥挤弹窗一次收集全部信息。

```text
Step 1 基本信息
  课程名称｜学年学期｜主讲教师
  → 确认后立即创建可恢复课程壳

Step 2 排课基础
  授课对象｜总学时｜周数｜星期/节次｜地点｜单次时长
  → 可以暂时跳过，但生成教学日历前必须补齐

Step 3 大纲起点
  AI 规划｜导入大纲｜空白开始
  → 三种方式进入同一大纲草稿与确认流程
```

大纲起点提供三种方式：

| 起点 | 适用教师 | 创建结果 |
| --- | --- | --- |
| AI 规划 | 有课程目标与参考资料 | 基于课程简报生成大纲候选草稿 |
| 导入已有大纲 | 已有 Word/PDF 大纲 | 保留原文件并识别为结构化候选，不自动覆盖 |
| 从空白开始 | 新课或教师希望自行编写 | 创建空大纲工作稿 |

课程壳建立后：

- 后端先创建唯一 Course；只有发起 AI 生成时才创建 GenerationJob；
- 返回课程列表可看到“尚未建立大纲”的真实状态；
- 进入课程时始终先到课程概览，由“下一步”引导补排课信息或建立大纲；
- 不跳到学生学习页，也不因生成状态自动把教师扔进某个深层页面；
- 复制历史课程作为后续增强入口，不阻塞 V1 的三种大纲起点。

### 6.3 返回位置

每次从深度编辑器或 PPT 工作台返回，必须恢复：

- 原课程；
- 原教学单元；
- 原资产标签；
- 原滚动位置；
- 未保存提醒状态。

不能返回课程库首页后让教师重新寻找。

课程卡点击行为保持稳定：任何状态都先进入课程概览。只有教师在概览点击“继续准备第 06 讲”等明确动作时，才进入对应页面和课次。

## 7. 课程生产主流程

### 7.1 教师可见流程

```text
课程概览
  ↓
教学大纲：导入 / AI 生成 / 空白编写
  ↓ 教师确认某一大纲版本
  ├──────────────┐
  ↓              ↓
教学日历          分讲教案
排课与学校模板     按教学单元逐讲生成/导入/编辑
                  ↓ 教师确认选中教案版本
                  PPT
                  按需继续，不强制一次完成
                         ↓
                  发布管理
                  选择课次、资产和精确版本创建快照
```

各阶段独立保存、独立恢复。教师可以只完成大纲和若干讲教案后离开；需要 PPT 时从对应讲次继续。页面不得用单一“课程完成度”掩盖不同资产的真实状态。

内部真实状态仍复用现有：

```text
requirements → outline → teaching → content → release
```

映射规则：

| 内部阶段 | 教师界面归属 | 说明 |
| --- | --- | --- |
| requirements | 课程设置与资料 | 课程简报、目标、时长、资料依据 |
| outline | 教学大纲 | 课程级审阅门 |
| teaching | 分讲教案 | 按教学单元编辑和确认 |
| content | 保持现有学生课程内容流程 | Q19 暂缓；V1 不迁入教师主生产标签，也不删除旧入口 |
| release | 发布审阅 | 质量、范围与学生影响检查 |
| PPT representations | PPT | 现有同源下游工作台，保持接口不变 |

### 7.2 为什么不是一次性向导

教师可以回到上游修改，但系统必须给出影响：

```text
大纲 v4 修改第 4/5/6 讲
  → 相关教案标记“来源已更新”
  → 相关 PPT 标记“需评估/需重建”
  → 最后确认版和学生发布版保持可用
  → 教师选择逐讲更新或批量更新
```

禁止做法：修改大纲后清空旧教案、静默重写 PPT，或让学生立即看到教师未确认草稿。

### 7.3 页面默认位置

课程卡点击后始终进入课程概览，避免系统根据状态突然跳转。概览根据真实状态只给一个推荐下一步：

| 课程状态 | 概览上的推荐下一步 |
| --- | --- |
| 新建、排课基础未补齐 | 完善课程信息 |
| 尚无大纲 | 生成或导入教学大纲 |
| 等待大纲确认 | 审阅并确认大纲 |
| 大纲已确认、无教案 | 准备第一个教学单元 |
| 部分讲次异常 | 处理第一个失败或来源已更新的讲次 |
| 等待发布确认 | 预览学生版并检查发布范围 |
| 已发布、无待办 | 准备下一次授课 |

推荐只提供快捷入口，不构成强制向导；教师仍可通过左侧一级导航进入其他页面。

### 7.4 顶部状态栏

一行展示：

```text
设计思维与创新设计｜32个教学单元｜教案确认18｜PPT就绪16｜待处理4｜下次：3月12日 第09讲｜准备第09讲
```

只展示能支持立即判断的信息，不拆成指标卡。生成任务不长期占据状态栏，而由右下任务浮窗承载；状态栏只保留“生成中 2 项 / 失败 1 项”等摘要。

```text
当前：课程生产｜教案确认18/32｜PPT就绪16/32｜失败1｜下一步：处理第09讲
```

### 7.5 智能操作菜单

每个专业页面右上只保留一个随状态变化的操作控件，不把生成、导入、编辑、确认、预览、导出全部并排：

```text
大纲为空：      [生成大纲 ▾]
已有大纲草稿：  [确认大纲 ▾]
大纲已确认：    [生成教学日历 ▾]
日历有缺项：    [补全排课信息 ▾]
```

点击按钮主体执行当前推荐动作；点击箭头展开分类菜单。常用动作放在“编辑与生成”，查看与交付放在“预览、版本、导出”，放弃草稿、删除等危险动作单独分组并二次确认。表格行内动作默认隐藏在“···”，悬停或选中时出现。

## 8. 大纲、教案与 PPT 的交互隔断

### 8.1 教学大纲

大纲是课程级受管资产，支持：

- 从空白创建；
- 导入 Word/PDF 并识别为候选草稿；
- 基于课程简报和资料 AI 生成；
- 人工编辑；
- AI 调整候选、差异预览、接受/拒绝；
- 教师确认版本；
- 导出学校要求的 Word/PDF。

首次确认大纲后才建立稳定 LessonUnit。大纲片段在讲次页只做上下文展示；深度结构调整回到课程级大纲页。

### 8.2 分讲教案

课程生产默认先显示横向课次总表：

```text
课次｜日期｜教学主题｜教案状态｜PPT状态｜学生发布版｜下一步
```

大纲节点、来源版本、资料依据、负责人和更新时间进入课次详情，不继续横向扩列。总表支持选择课次进行批量生成、批量更新和发布前检查，但每项任务独立执行、独立失败、独立重试。

进入沉浸式课次制作区后，第二层左侧栏才按教学单元排列；中间只切换“教案 / PPT”。大纲片段作为上下文抽屉查看，学生资料归属暂缓，不进入 V1 标签。

教案支持：

- 读取当前确认大纲与所选资料；
- 生成新草稿，不覆盖旧版；
- 直接编辑；
- AI 局部优化并显示候选差异；
- 教师确认；
- 多版本比较与恢复；
- 标记影响到 PPT 的范围；学生内容影响保持原流程，不在本阶段扩展。

总表负责巡视，制作区负责长时间编辑。二者不在同一屏平铺：进入制作区后，课程一级导航收成图标栏，课次列表保持窄栏，中央正文获得最大宽度。

### 8.3 PPT

PPT 是下游表达，不是第二课程真源。V1 保留现有 PPT 接口和工作台。

每个教学单元可拥有一个课件集合：

```text
第 06 讲课件
├─ 主课件（当前工作版 v5）
├─ 习题课件（当前工作版 v2）
└─ 补充案例课件（未发布）
```

每份课件的历史版本折叠在详情中，不在讲次列表平铺 v1/v2/v3。

操作：

- 导入已有 PPT；
- 基于确认教案生成；
- 选择模式、模板和来源版本；
- 进入现有 PPT 工作台预览、构建、导出；
- 返回时恢复原讲次和课件集合；
- 来源更新后显示 stale，不自动覆盖。

### 8.4 预览策略

课程生产采用三段式渐进打开：

```text
1. 课次总览：判断十几讲的状态与下一步
       ↓ 单击教案/PPT状态
2. 大尺寸快速预览：阅读正文/缩略页、版本和来源影响
       ↓ 点击“继续制作”
3. 沉浸式课次制作：课次列表 + 教案/PPT + 按需上下文抽屉
```

教师点击总表“下一步/继续”时可直接进入第 3 层，跳过预览；不使用双击、右键等隐藏规则。快速预览使用接近视口的大预览层，不用压缩正文的窄抽屉；关闭后恢复总表的筛选、滚动位置和选中课次。

| 内容 | 快速预览 | 深度编辑 |
| --- | --- | --- |
| 大纲 | 大纲页当前章节只读态 | 同页点击编辑，复用 `CourseOutlineReview`/正式大纲组件 |
| 教案 | 大尺寸全文预览 | 沉浸式课次制作区复用 `GenerationLessonPlan` |
| PDF/图片/Excel | 按媒介自然尺寸/视口自适应 | 下载或外部打开 |
| PPT | 大尺寸缩略页与课件集合 | 跳现有 PPT 工作台；返回恢复原讲次/PPT |
| 学生版 | 发布管理中读取候选或已发布快照 | 只读预览，绝不读取教师未确认草稿 |

### 8.5 任务浮窗

真实生成任务继续复用现有 `CourseTaskCenter`、WebSocket、轮询、暂停/恢复和失败详情。教师页面只新增一个轻量浮窗入口：

```text
默认收起：[生成任务 2 · 46%]
展开后：当前课程任务、阶段、进度、失败原因、暂停/重试、查看详情
```

- 浮窗默认位于右下角；打开 `SideAIPanel` 时自动左移，不能遮挡 AI 面板或正文操作。
- 课程内默认只展示当前课程任务，课程列表页可看全部课程。
- 任务完成后短暂提示并自动收起；失败任务保留红点直到处理。
- 失败必须显示教师可理解的原因、影响范围、已完成工作、是否可重试和推荐动作；技术详情折叠。

## 9. 课程教学日历

### 9.1 产品位置

课程教学日历是单课程一级专业页面，与教学大纲并列，但两者共享课程结构：

```text
单课程工作台
├─ 教学大纲：讲什么、为什么、多少学时、目标是什么
└─ 教学日历：具体哪天、几点、在哪、给谁、由谁上
```

教学日历不是课程生产的强制阻塞门。教师可以先生成大纲再排课，也可以先手工录入部分日程；但只有绑定 LessonUnit 后，日历才能一键进入对应教案和 PPT。

### 9.2 正式示例中的字段

参考《浙江大学本科教学日历（2025—2026 春夏学期）》，正式样例为 A4 纵向 5 页、63 条记录。第 1 页包含课程元数据和 10 列主表，后续页面跨页续排，末页有合并备注区。V1 数据字段应覆盖：

- 记录序号；
- 日期；
- 开始/结束时间；
- 教学内容；
- 教学要求（含作业）；
- 上课地点；
- 上课教师；
- 教学类型；
- 实验小班/班组；
- 教学时数；
- 备注；
- 关联教学单元；
- 使用的教案/PPT 版本（系统字段，导出可隐藏）。

课程大纲附录还常见：课程思政育人目标、教学形式、企业导师参与情况。模板引擎应允许学校字段配置，不把所有学校字段硬编码在主界面。

参考资料同时证明“教学单元”和“授课场次”不能 1:1：大纲附表约 32 讲，而正式日历因实验 A/B/C 小组拆分形成 63 条真实记录。大纲提供教学内容、学时、教学形式和作业要求；日期、地点、教师、班组、选课课号等教务字段必须由排课信息、校历或教师补充。

样例 PDF 的正文实际被栅格化，且含 Safari 打印页眉页脚。产品导出只复刻正式主体版式，不复刻浏览器 URL、打印时间和“第 n/5 页”等浏览器噪声；正文必须保持可搜索、可编辑。

### 9.3 日历的三种建立方式

1. **手工录入**：第一版必备；支持每周重复、连续 16 周、批量改地点/教师。
2. **由大纲生成完整草稿**：读取教学单元、学时、教学形式、内容要点，以及已填写的周次/星期/节次，生成整学期场次；无法判断的地点、教师、班组等字段留空并明确标记，不编造。
3. **导入识别**：导入学校教学日历或大纲，先生成识别结果和差异，不直接覆盖当前日历。

教学日历默认使用高密度表格视图，可切换日历视图。日期、地点、教师、类型、班组和学时等短字段允许表内编辑；教学内容、教学要求/作业、备注和大纲关联在右侧编辑器中处理。查看关联大纲时先开侧栏，深度修改回到教学大纲页。

### 9.4 大纲与日历联动

联动不等于自动覆盖。规则：

| 事件 | 系统动作 |
| --- | --- |
| 大纲新增教学单元 | 日历出现“未排课单元”候选 |
| 大纲删除教学单元 | 已绑定场次标记“来源已移除”，等待教师处理 |
| 大纲修改标题/内容 | 日历显示来源更新，可选择同步标题/内容摘要 |
| 日历改日期/地点 | 不反写大纲 |
| 日历拆成 A/B/C 班 | 创建多个 Session，共享同一个 LessonUnit |
| 教师调整校历冲突 | 只改 Session 日期，教学单元和资产不变 |

### 9.5 校历导入与冲突处理

导入校历后识别：开学周、节假日、调休、补课日、停课日。系统根据重复规则提出调整方案，但必须显示：

- 原日期；
- 建议日期；
- 冲突原因；
- 受影响场次；
- 是否跨班组；
- 是否改变授课顺序。

教师逐项接受、批量接受或忽略。不能静默移动所有课程。

### 9.6 受管文件与导出

教学日历是受管文件：

- 可在界面编辑结构化字段；
- 有草稿、确认、导出版本；
- 第一版以可编辑 DOCX 为主交付，同时导出 PDF；Excel 作为字段交换格式，不是正式版式主交付；
- 导出前预览分页和字段缺失；
- 原始导入文件保留为来源附件，不被覆盖。

浙江大学模板作为 V1 内置模板，导出需保留标题、课程元数据、10 列顺序、非等宽列宽、细网格、小字号、长文本左对齐、短字段居中、A/B/C 组独立行、跨页续排和末页备注区。正式模板应使用真实 Word 表格而不是整页图片。

## 10. 教师教学总日历

### 10.1 产品位置

教学总日历属于教师个人，位于课程工作台层，与“我的课程”并列，不放进任何一门课程内部。

### 10.2 数据来源

总日历只聚合教师拥有/任教课程中已启用的 ClassSession：

```text
教师总日历 = 课程 A 日历 + 课程 B 日历 + 课程 C 日历 + 教师个人提醒
```

课程色标稳定，避免同一门课程每次颜色变化。

### 10.3 交互

- 月视图（默认）：看哪天有课，用课程稳定色点区分。
- 周视图：看具体时间、地点和冲突。
- 列表视图：按日期查看近期课程、准备状态和地点。
- 悬停/点击：课程名、教学单元、场次、地点、教案/PPT 准备状态。
- “进入准备”：跳到对应课程、教学单元、教案或 PPT 标签。
- 若课程日历变更，总日历自动更新；总日历不复制场次数据。

### 10.4 第一版边界

V1 总日历只聚合课程教学日历，并从总日历进入课程/场次；V2 才允许在总日历直接编辑同一条 ClassSession。两处始终读取同一场次记录，不建立双向复制。个人提醒、钉钉、Google Calendar 和教务系统双向同步均后置到有明确权限与接口协议之后。

## 11. 课程文件空间

### 11.1 文件空间角色

文件空间负责找、开、导入、归档、移动、下载和导出；课程生产负责状态、依赖、生成与发布。两者打开同一个 asset_id 和同一版本历史。

### 11.2 推荐目录模板

```text
课程资料/
├─ 0、教学大纲/
├─ 1、教学日历/
├─ 2、分讲教案/
│  ├─ 第01讲/
│  └─ 第02讲/
├─ 3、PPT/
│  ├─ 第01讲/
│  └─ 第02讲/
└─ 4、参考资料/
```

模板默认只创建文件夹；若必须生成文件，则生成可打开的空白受管文件，不创建带假内容的占位文档。序号连续。作业、实验、成绩、试题和学生发布资料仍可由教师自行创建目录，但不进入第一版强制模板。

### 11.3 文件能力

- 整个文件夹一键导入，保留层级与空文件夹；
- 新建多层文件夹；
- 拖入文件；
- 文件和文件夹删除二次确认，进入回收站；
- 原始文件下载/预览；
- 图片、PDF 自适应大小；
- 受管文档进入统一编辑器；
- 整包 ZIP 导出包含空文件夹；
- 导入后 AI 分类只产生建议，教师可修正。

### 11.4 与生产的映射

生成教案后自动挂入对应目录，但不复制内容；在文件系统移动教案仍保留“关联第 06 讲”。原始 Word/PDF 可通过“转为受管资产”建立结构化候选；识别失败时保留原文件并说明原因。

## 12. 教师端、学生端与权限

### 12.1 教师端

教师可以：

- 创建与管理课程；
- 管理大纲、日历、教案、PPT 和文件；
- 保存草稿、确认版本、发布或撤回学生快照；
- 查看学生主动提交的反馈；
- 查看知识节点级的匿名聚合学习信号；
- 生成邀请码或授权学生加入课程。

### 12.2 学生端

学生可以：

- 读取教师发布快照；
- 基于教师 PPT 页、讲义或知识点创建私人笔记；
- 使用 AI 解释、练习和个性化表达；
- 在自己的资料空间修改副本；
- 主动提交问题、建议或匿名反馈。

学生不能：

- 修改教师源资产；
- 看到教师未发布草稿；
- 影响其他学生的私人资料；
- 通过复制副本绕过教师撤回后的权限规则（可保留个人笔记，但源内容可见性按政策处理）。

### 12.3 隐私边界

教师默认看不到学生私人笔记和私人 AI 对话，只看到：

- 学生主动提交的内容；
- 去标识化、达到最小人数阈值的聚合数据；
- 与教学改进直接相关的知识节点困难分布。

### 12.4 权限矩阵

| 对象/动作 | 教师 | 学生 | 被授权协作教师 |
| --- | --- | --- | --- |
| 教师工作草稿 | 读写 | 不可见 | 按授权读写 |
| 教师确认版 | 读写/发布 | 不可见 | 按授权 |
| 学生发布快照 | 发布/撤回 | 只读 | 按授权 |
| 学生私人笔记 | 不可见 | 读写本人 | 不可见 |
| 主动反馈 | 查看/处理 | 提交/撤回本人 | 按授权查看 |
| 成绩与敏感材料 | 教师私有 | 仅本人相关结果 | 强制显式授权 |

## 13. AI 生成与资料依据

### 13.1 三种内容建立方式必须并存

大纲、教案、PPT 都允许：

- 导入已有内容；
- 从空白创建；
- AI 生成候选。

三者最终进入同一受管资产模型，不因来源不同产生三套流程。

### 13.2 资料使用

生成大纲：课程简报 + 核心资料 + 辅助资料 + 可选公开检索。  
生成教案：教师确认大纲版本 + 当前教学单元 + 选定资料 + 教学要求。  
生成 PPT：教师确认教案/课程同源内容 + 模式 + 模板 + 图片策略。

每次生成前显示：

- 主要依据及版本；
- 参考资料；
- 资料权威等级；
- 是否允许通用知识补充；
- 输出位置；
- 是否影响既有版本；
- 预计生成范围。

生成结果永远是候选草稿，不直接成为学生版。

课程内提供轻量“资料池”，承接大纲、教案、PPT生成所需的核心资料和辅助资料；它不是完整文件系统。教师在阶段生成抽屉中选择资料、输入版本和额外要求，生成时固定以下输入快照：大纲/教案版本、资料版本、检索策略、额外指令、模型/生成策略和时间。

资料存在冲突时，生成前显示冲突与采用顺序：**教师确认大纲 > 标记为核心的资料 > 其他参考资料 > AI 通用知识**。教师可以排除某个来源后再生成，系统不得静默混合互相矛盾的依据。

### 13.3 联网搜索

课程生成保留联网搜索能力，默认模式为“资料缺口时自动检索”；教师可切换为关闭或始终检索。联网结果必须展示：

- 检索关键词；
- 来源标题与链接；
- 抓取时间和使用位置；
- 可信度/适用性提示；
- 被系统拒绝的来源及原因；
- 教师排除/恢复来源的入口。

最终生成版本保留引用快照。联网失败不应伪装成成功：如果仍可仅用本地资料继续，应明确“未获取联网资料，本次仅使用已有资料”；如果缺少必要依据，则阻止生成并说明需要补充什么。

### 13.4 隐私与联网

教师原始私有资料默认在自控环境处理。联网搜索只发送最小必要的公开检索词和脱敏摘要；外部模型调用必须显示授权范围。V1 不用“已脱敏”文案代替真实技术证据。

## 14. 发布、预览与反馈闭环

### 14.1 发布检查

发布前按教学单元列出：

- 教师候选版本；
- 学生当前版本；
- 将新增/替换/撤回的内容；
- stale 或阻断项；
- 受影响学生范围；
- 是否缺少必要教案/PPT；
- 质量检查结果。

确认后创建不可变发布快照，例如：`2026 秋 · 第 2 次发布`。教师按“课次 + 资产 + 精确版本”选择发布范围，不要求整门课程所有内容一起发布。

默认可见性：所有教师资产均为私有；教学大纲可选择发布；教学日历只发布面向学生的安全字段；教案默认教师私有；PPT与补充资料可按版本发布；成绩、考勤、试题答案等敏感资产强制教师私有。

### 14.2 学生预览

学生预览默认读取“准备发布的候选快照”；界面顶部必须明确“预览，不是正式发布”。已发布课程还可切换查看“学生当前版本”，用于对比。

### 14.3 反馈回流

```text
学生主动问题/聚合困难
  → 教师查看来源与关联教学单元
  → 创建改进建议（proposal）
  → 接受后创建新教案草稿
  → 必要时生成 PPT 新草稿
  → 教师确认
  → 发布新快照
```

拒绝建议不改变现有草稿；接受建议也不直接发布。

## 15. 异常、恢复与可信状态

### 15.1 失败不能只用 Toast

任务失败应落在对应阶段和讲次：

- 顶部只显示异常数量摘要；
- 右下任务浮窗持续展示进行中和未处理失败；
- 讲次栏显示警告；
- 任务详情显示教师可理解的失败原因、影响范围、已完成工作、可恢复性和最后可用版本；
- 提供“只重试本讲”“继续任务”“查看失败详情”；
- 生成中的可暂停任务显示暂停；
- 已确认内容不得因重试被重复覆盖。

### 15.2 典型异常

| 异常 | 用户看到 | 可执行动作 |
| --- | --- | --- |
| 资料解析失败 | 文件仍保留，标记不可用于生成 | 重试解析、替换、仅保留原文件 |
| 大纲冲突 | 当前草稿与基础版本不一致 | 查看差异、重新基于最新版本 |
| 部分讲次失败 | 精确标记失败讲次 | 单讲重试、跳过并保留 last-good |
| PPT 来源过期 | stale badge，不清空旧 PPT | 基于新来源生成新版本 |
| 发布阻断 | 发布检查列出阻断项 | 定位处理、暂不发布 |
| 网络断开 | 显示任务仍在服务器运行或状态未知 | 重连并拉取真实任务状态 |

### 17.1 总依赖图

```text
F0 真实状态与路由基线
│
├─ F1 课程工作台入口与新建课程
│   └─ F2 单课程真实生产壳
│       ├─ F3 大纲确认门
│       │   └─ F4 教学单元与分讲教案
│       │       ├─ F5 PPT 集合与现有工作台跳转
│       │       └─ F6 发布/学生预览
│       └─ F7 课程教学日历
│           ├─ F7.1 Lesson/Session 模型
│           ├─ F7.2 手工编辑与重复规则
│           ├─ F7.3 大纲映射与差异确认
│           └─ F7.4 学校模板导出
│
├─ F8 教师教学总日历（依赖 F7）
├─ F9 文件空间与生成资料桥接（依赖 CourseAsset）
└─ F10 权限、质量、验收与观测（贯穿所有阶段）
```

### 17.2 分阶段计划

#### 阶段 A：真实生产页重组，不改接口语义（P0）

目标：以已确认的产品信息架构重建 `/course/:courseId/production` 真实页面；模拟页只提供视觉气质、控件尺度和间距参考。

工作包：

1. 保留原模拟页作为只读参考路由。
2. 课程卡点击始终进入课程概览；新建课程改为课程壳优先的分步页。
3. 真实页继承原项目的产品栏、组件、视觉 token 与交互反馈；页面网格按课程生产任务重组，模拟页只提供密度和尺度参考。
4. 接入 courseStore/generationStore，删除假数据和假生成。
5. 建立“横向课次总表 → 大尺寸快速预览 → 沉浸式课次制作”三段交互。
6. 把真实大纲、教案、发布组件嵌入对应专业页面；学生 content 流保持原入口。
7. PPT 跳现有工作台，保留返回上下文。
8. 复用 CourseTaskCenter 并补小浮窗，不复制任务状态机。
9. 覆盖新建、等待确认、生成中、部分失败、暂停、已发布六种状态。

验收：真实浏览器中任务状态和组件随真实后端变化；刷新后不丢；控制台无错误；原模拟页不受影响。

#### 阶段 B：课程教学日历 MVP（P0）

目标：一门课程可建立、编辑、保存和查看真实教学日历。

工作包：

1. 定义 Calendar、LessonUnit、ClassSession、SessionGroup 模型。
2. 新增课程日历聚合读写 API，统一 owner 校验。
3. 支持手工增删场次、批量重复、批量改地点/教师。
4. 从已确认大纲建立“未排课教学单元”候选。
5. 大纲变化只生成差异建议，不自动覆盖。
6. 提供表格视图、周历视图和缺项检查。
7. 日历先形成稳定受管资产和版本语义；课程文件空间投影在生产与日历稳定后再桥接，不阻塞本阶段。

验收：刷新后真实保存；一个教学单元可绑定多个 A/B/C 场次；增删均二次确认或可撤销；权限隔离。

#### 阶段 C：导入、校历与学校模板导出（P1）

目标：减少教师重复填写学校材料的机械劳动。

工作包：

1. 导入学校教学日历，优先 PDF + Excel，输出识别候选；Word 在字段合同稳定后接入。
2. 导入校历，识别节假日、调休和补课。
3. 冲突预览与逐项/批量接受。
4. 模板字段映射与缺项检查。
5. 导出可编辑 DOCX 和固定阅读 PDF，保留正式分页和表头；Excel 作为字段交换格式，不作为正式版式主交付。
6. 保留原始文件、识别结果和导出版本链。

验收：使用参考《浙江大学本科教学日历》复刻字段和分页；导出内容与受管数据逐项对账。

#### 阶段 D：教师教学总日历（P1）

目标：教师可从个人时间视角进入真实课程准备。

工作包：

1. 聚合多门课程已启用场次。
2. 月/周/列表三种视图。
3. 课程稳定色标、地点和冲突提醒。
4. 进入对应教学单元的教案/PPT。
5. 移动端轻量查看和提醒。

验收：课程内修改场次后总日历同步；总日历无复制数据；跳转恢复准确课程与讲次。

#### 阶段 E：文件、版本与师生闭环（P1/P2）

1. teacher-course-space 与 CourseAsset/Material 统一桥接。
2. 整课文件夹识别为候选关联。
3. 发布快照与学生私人副本。
4. 学生主动反馈 → 教师改进建议 → 新草稿 → 新发布。
5. 质量校核进入发布门。

### 17.3 建议迭代顺序

| 迭代 | 可演示成果 | 不做什么 |
| --- | --- | --- |
| Iteration 1 | 教师工作台入口、教师概览、六项课程导航与真实生产隔断 | 不改生成/PPT接口语义 |
| Iteration 2 | 真实日历保存、Lesson/Session、手工排课 | 不做教务系统对接 |
| Iteration 3 | 教师总日历、进入对应课程/场次、移动轻量查看 | 不在总日历复制或直接编辑场次 |
| Iteration 4 | 大纲/日历导入、校历冲突、浙江大学模板导出 | 不自动无确认改日期 |
| Iteration 5 | 文件桥接、发布快照、反馈闭环 | 不强制知识节点全链自动重写 |

### 17.4 Alpha、产品 V1 与后续阶段的边界

为避免把“接口接通”误称为“整套产品完成”，发布口径固定如下：

| 里程碑 | 必须具备 | 不能宣称 |
| --- | --- | --- |
| V1.0-alpha | 真实课程身份/生成状态；课程日历手工持久化；总日历基础聚合；无模拟成功 | 不能宣称教师工作台入口、最终生产交互、正式导入导出或完整权限已完成 |
| V1.0-beta | 我的课程/总日历统一壳；教师概览；六项真实路由；课次表→大预览→沉浸制作；四档布局通过 | 不能宣称学校模板正式交付，除非 DOCX/PDF 已逐项对账 |
| 产品 V1.0 | beta 全部通过；大纲/日历导入候选；校历冲突；浙江大学可编辑 DOCX 与阅读 PDF；模型、权限、失败恢复证据齐全 | 不能宣称 CourseAsset 文件桥接、学生私人笔记或知识节点全链联动已完成 |
| 后续版本 | 课程文件单真源投影、整夹识别、学生反馈、协作教师权限、知识节点影响建议 | 不得静默改写教师资产或学生发布版 |

实际开发顺序为 **A 真实生产与入口 → B 单课程日历 → D 教师总日历 → C 导入/校历/模板导出 → E 文件与师生闭环**。字母沿用能力分组，不代表必须按字母顺序施工。总日历先于正式模板导出，是因为它只依赖稳定的 ClassSession，而模板导出还依赖字段映射和分页复刻。

## 20. 验收标准

### 20.1 课程入口与新建

- 教师进入课程工作台看到本人/授权课程，不泄露其他课程。
- 课程按学年/学期分组；课程卡不堆版本和操作按钮。
- 课程卡点击始终进入课程概览，概览只突出一个真实下一步。
- 新建课程使用独立分步页，基本信息确认后先创建可恢复课程壳。
- AI 规划、导入大纲和空白开始最终进入同一大纲草稿与确认流程。
- 新建生成请求只提交一次，可恢复重复点击。

### 20.2 真实生产页

- 页面视觉与原 `teacher-course-v1` 一致，组件与项目风格一致。
- 真实状态驱动默认位置和按钮，不存在模拟计时器。
- 默认课次总表列为课次、日期、主题、教案、PPT、学生发布版和下一步。
- 单击资产状态打开大尺寸快速预览；继续制作进入课次工作区；关闭或返回后恢复原表格位置。
- 课次工作区只展示课次列表和教案/PPT，学生内容流程保持原入口。
- 大纲未确认时教案/PPT 显示明确门禁。
- 上游重开后下游标记 stale/needs_regeneration，last-good 保留。
- 失败精确到阶段/讲次，可暂停、恢复或重试。
- 右下任务浮窗不遮挡 AI 面板，完整详情复用真实 CourseTaskCenter。

### 20.3 版本与发布

- 工作稿、教师确认版、学生发布版可区分。
- 保存不发布；确认不发布；发布创建冻结快照。
- 发布范围精确到课次、资产和版本，未选择资产保持教师私有。
- 学生预览不读取教师未确认草稿。

### 20.4 教学日历

- 支持手工增删改场次并真实持久化。
- 一个 LessonUnit 可绑定多个 Session 和不同班组。
- 大纲变化不静默覆盖日历。
- 校历冲突有原值/建议值/原因/影响范围。
- 导出与学校模板字段、行数、分页逐项对账。
- 浙江大学样例按 63 条记录、10 列、A/B/C 组和末页备注区验证；正文可编辑、可搜索，不保留浏览器打印噪声。

### 20.5 UI 与浏览器

- 1440×900 首屏立即进入正文，无大段解释文案。
- 1180、880、680 三档布局可用。
- 关键按钮可键盘操作，有焦点和 aria 状态。
- 控制台无未注册组件、未定义变量和权限状态泄漏。
- 角色切换或预览不会保留教师编辑抽屉给学生。

## 21. 对抗性检查与明确否决项

| 诱人方案 | 为什么看似合理 | 为什么否决 |
| --- | --- | --- |
| 线性一步步向导 | 新用户容易理解 | 教师需要回看、局部修订、处理上游变化；向导会掩盖真实依赖 |
| 所有功能都做成课程内标签 | 入口统一 | 教师总日历属于个人多课程；视频分析不必依附课程 |
| 文件系统作为唯一入口 | 符合电脑习惯 | 文件路径不能表达确认门、依赖、发布与学生快照 |
| 生产页和文件页各存一份 | 实现短期方便 | 形成双真源和同步冲突 |
| 大纲改完自动改全部 | 展示 AI 能力 | 风险不可控，会覆盖教师多年资产和学生正式版本 |
| 一个讲次等于一个日历行 | 模型简单 | 真实案例有 A/B/C 班和重复场次，会立即失真 |
| 所有版本都展示在树中 | 信息完整 | 视觉爆炸；应显示当前指针，历史折叠 |
| 保存即发布 | 步骤少 | 破坏教师确认与学生权限边界 |
| 教师查看学生所有 AI 对话 | 反馈更全面 | 侵犯私人学习空间，降低学生信任 |
| 用假状态完善演示 | 快速好看 | 用户已明确要求真实可用，会再次产生“看起来有、实际不能用”问题 |

## 22. 风险与缓解

| 风险 | 表现 | 缓解 |
| --- | --- | --- |
| 范围失控 | 同时重做首页、文件、日历、PPT、学生端 | 严格按阶段 A-E，先真实生产页和日历 MVP |
| 双真源 | 文件与生产互相覆盖 | CourseAsset 稳定 ID，多视图只做投影 |
| 权限缺口 | 多教师或学生看到不该看的资产 | course/job/resource ownership 统一校验 |
| 生成不稳定 | 长任务断线、部分失败 | 真实任务恢复、last-good、局部重试 |
| 教学日历失真 | 把讲次与场次混为一谈 | LessonUnit/ClassSession 分层 |
| 模板不可维护 | 为每所学校硬编码页面 | 字段映射模板 + 受管数据模型 |
| 视觉回退 | 新功能又做成不同 UI | 原模拟页为视觉基线，normalize 审查和浏览器验收 |
| 信任风险 | AI 错误直接发布 | 候选、确认、质量检查、冻结发布快照 |

## 23. 决策记录

### 已确定

1. 原模拟页只作为视觉气质、控件尺度和密度参考；真实页面的信息架构、流程与状态以本方案为准。
2. 课程工作台默认“我的课程”，教学总日历与之同级；课程按学年/学期分组展示。
3. 新建课程使用独立分步页；先建课程壳，再选择 AI 规划、导入大纲或空白开始。
4. 点击课程卡始终进入课程概览，不按状态自动跳转；概览推荐唯一下一步。
5. 单课程一级导航为概览、大纲、日历、生产、文件、发布。
6. 教师主生产链按大纲、教案、PPT 隔断；大纲确认后日历和教案可并行。
7. 完成教案后可暂停，PPT 按需继续；各任务独立失败和重试。
8. 课程生产先用横向课次总表巡视，再用大预览和沉浸式制作区逐层打开。
9. 页面使用智能操作菜单：只突出当前推荐动作，其余动作分类收纳。
10. 生成任务使用小浮窗，完整状态复用 CourseTaskCenter；联网检索保留来源、排除和失败证据。
11. 教学日历默认表格并可切日历视图，短字段表内编辑，长内容侧栏编辑。
12. 浙江大学教学日历作为 V1 内置模板，DOCX 为主要可编辑导出，PDF为正式阅读交付。
13. 教师总日历 V1 聚合并跳转，V2 才允许直接编辑同一 ClassSession。
14. 文件模板为 0大纲、1日历、2分讲教案、3PPT、4参考资料，版本不写入文件名。
15. 真实后端状态必须进入页面，不以假交互代替。
16. 教学单元与授课场次分离。
17. 课程生产与课程文件共享 CourseAsset 单真源。
18. UI 遵守高密度、强分类、少打扰、正文优先并复用原组件。
19. 教师确认与学生发布分离，发布选择精确课次、资产和版本。
20. Q19 暂缓：现有偏学生端的内容流程保持原入口，不在 V1 重构或强塞进教师课次标签。

### 待产品/技术共同确认

1. 浙江大学模板之外，第二个正式学校模板何时加入。
2. 学校校历导入的格式优先级（建议先 PDF + Excel，再 Word）。
3. 现有 student-oriented content 阶段最终在教师产品中的归属（Q19，明确后置）。
4. 协作教师的编辑、确认、发布权限是否拆分。
5. 个人提醒是否进入教学总日历，以及与课程场次的视觉区别。

### 24.2 UI 实施顺序

1. 先纠正空间骨架：课程工作台层、单课程六项导航、生产总览只保留一层课程边栏。
2. 再纠正正文打开方式：课次表 → 大预览 → 沉浸制作；状态、版本、来源分别上收状态栏或进入抽屉。
3. 再做四档响应式：1440、1180、880、680；每档都验证正文宽度、导航可读、主操作可达和滚动上下文。
4. 最后做视觉归一：只使用原项目 token、按钮、表格、Drawer、Dialog、Toast、Confirm 与图标；禁止新增宣传卡、抽象指标、厚侧边强调线和无意义阴影。
5. 视觉通过不等于功能通过；必须同时验证真实 Store/API 状态、刷新恢复、失败原因、版本指针和返回位置。
6. 阶段 C 再实现校历识别和浙江大学模板 DOCX/PDF 导出，逐字段、逐行、逐页对账；在此之前只能称“功能 alpha/MVP”，不能称完整产品 V1 已发布。

这样可以避免在 UI 尚未确认时同时改后端、文件和日历，减少返工，同时又不牺牲真实流程。
