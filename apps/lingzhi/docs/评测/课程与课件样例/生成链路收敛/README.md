# 生成链路收敛评测输入

[固定输入.json](固定输入.json)是自编合成输入，不含生产课程、教师资料或真实用户记录。当前只有输入，尚未执行模型对照，不是验收结果。实施与完整验收矩阵见[生成链路收敛](../../../../../../changes/生成链路收敛.md)。

## 固定案例

| case_id | 用途 | 重点 |
| --- | --- | --- |
| statistics_basic | 普通短课程，2 讲 | 固定数值、定义边界、完整例题与可独立学习 |
| binary_tree_code | 6 讲课程与代码 | 相同案例跨讲一致、递归调用解释、代码可运行、空树与复杂度 |
| calculus_reasoning | 6 讲课程与公式推导 | 必要中间步骤、适用条件、驻点与极值反例、公式完整 |

`source_text` 原样作为同等输入资料，`checks` 只交给验收者，不附加到某一组模型输入。统一使用 `title`、`audience`、`purpose`、`lesson_topics` 和 `requirements`；按当前表单映射课时单位并记录换算，不把 45 分钟与项目的一学时混用。两组均锁定相同讲次主题，防止生成不同课程后比较速度。

## 两层对照

1. **单项对照**：先在隔离环境用旧基线形成一个共享大纲、教案并冻结摘要指纹。讲义实验的旧/新两组必须读取同一教案与资料；PPT 两组必须读取同一讲义及模板。避免上游内容差异掩盖本阶段效果。大纲与教案各自也使用一致输入。
2. **完整链对照**：两组从同一固定输入走完正常流程，分别检查目标、课时、例题和产物衔接。记录人工动作与等待，不能把老师等待时间记成模型耗时，也不能从总交付时间里无说明地去掉。

旧基线绑定变更说明的审查提交，在隔离 checkout 或发布包运行；候选绑定确定提交。对照工具是实验环境，不作为产品内新旧双路由。不得在当前生产课程或正式数据目录做重试与故障实验。

每个常规样例各运行至少三次，保持模型权重/量化、思考模式、抽样参数、输入与服务负载条件可比较；不只展示最好一次。先记录当前有效配置，再实验 16,000/32,000 输出预算、1/2 并发。相同输出预算比较用于判断拆分方式；候选不同预算的探索另列，不混成同条件结论。输入长度、实际输出、最大长度、finish_reason、用量缺失情况分别报告，设置预算不代表模型必须写满。

## 必须记录的结果

- 每样例、每产物：基线/候选提交、输入指纹、模型 ID 与量化、服务有效长度、输入/输出预算、思考和抽样设置、并发、是否冷启动。
- 请求：主生成、恢复、结构修复、独立求解和服务重试分别计数；记录总调用量、输入/输出 tokens、排队、首字、总耗时及 finish_reason。服务未返回 usage 时标记未知，不当作零。
- 结果：正式保存是否成功、完整小节数、来源冲突、失败与恢复动作、人工修改耗时。原文和 prompt 留隔离私有输出；公开报告只保留可分享的合成产物和统计，清除端点、账户及运行路径。
- 硬检查：JSON 可解析且全部必需栏目存在，讲次与课时对齐，讲义无漏小节、公式/代码无截断，固定知识检查全部通过；独立代码运行的结果与预期对应。
- 人工逐项判断：内容完整性、事实正确性、叙述连贯性、独立阅读可用性、修改量。评阅者可只见匿名 A/B 成品，避免先知道调用次数；无真人评阅时注明仅 AI/开发者审阅，不能宣称教师认可。

性能不设未经基线验证的百分比承诺。先满足全部硬检查，候选人工质量不低于同输入基线，再比较首次完整交付率、各次总耗时和用量；失败样例一并计入，不能剔除后宣称更快。

## 长度与故障样例

在上述固定案例上注入故障，不另造“超长却无实际教学内容”的填充课程：

| 条件 | 注入与预期 |
| --- | --- |
| 请求前超限 | 测试桩将有效预算设为低于完整输入；应说明超限，不悄悄截断原资料，不自动回到旧块生成器 |
| 真实输出能力 | 在长推导/代码讲次逐档测量；模型提前正常结束不等于触及能力上限，不用机械重复文本证明容量 |
| 输出截断 | 在小节边界、公式中、代码围栏中分别断流；保留原片段，只有完整小节可作为续作检查点 |
| 标记歧义 | 正文代码围栏含小节/结束标记字面量；不误判为结构边界；未知/重复/乱序 ID 不发布 |
| 保存失败 | 生成成功后模拟磁盘写入错误；恢复只重试持久化，新增模型调用为 0 |
| 服务重启/重复提交 | 任务与 request_id 对账，不重复产物；讲义重启不自动续作 |
| 来源/权限变化 | 排队或生成中改来源、撤权；旧请求不能提交新正式修订 |
| 取消/删除 | 产生迟到响应；不得重建被删内容或将取消改为成功 |
| 人工修改冲突 | 模型未结束时用户保存另一修订；保留双方内容并提示冲突，禁止覆盖 |

完整执行后把经过脱敏的验收结论放入现有验收目录并从变更说明引用。本目录只维护输入与方法，不预填通过状态。

G1 大纲子集的真实重复调用与已发现问题见[验收记录](../../../验收/生成链路G1大纲验收.md)。其他产物、完整固定知识检查与旧链对照仍未执行；不修改输入文件的初始状态来冒充整套评测已通过。
