# 通用题目生成与质量闭环评测

> 文档状态：题目生成专项能力合同与发布评测<br>
> 上位设计：[课程生产](../功能设计/课程生产.md)、[教学内容模板](../教学内容模板.md)<br>
> 当前实现状态：[产品状态](../产品状态.md)<br>
> 适用范围：题库重建、课程正式练习、诊断与复验候选、代码题验证

本文承载题目生成专项协议、质量门和回归指标，不定义产品总体方向，也不维护项目进度。

## 1. 正式生成链

```text
课程教案 + 课程知识库 + 学习目标
-> course_assessment_blueprint_v2
-> question_reference_package_v1
-> 三类稳定任务槽与作答模式约束
-> 公开题面候选 + 私有解答合同
-> 独立求解 + 确定性领域验证 + 隔离语义评审
-> question_quality_report_v5
-> 发布、局部修复、整题重生或废弃
-> 不可变题库修订
-> question_generation_audit_v2
```

当前审计同时保存 `assessment_generation_policy_version` 与
`assessment_prompt_template_version`。断点恢复必须同时匹配蓝图修订、资料范围、
生成策略和提示词模板，不能把旧提示词生成的章节静默混入新一轮重建。

教师题库的创建任务、恢复任务、状态轮询、私有答案和审核请求必须显式使用教师身份，
不能依赖当前路由的临时身份状态。无活动任务由接口返回成功的 `idle`；权限保护返回的
404 不得吞成空任务或提示为内容已删除。请求未获得任务 ID 时显示“题目生成未启动”，
不能显示“等待生成”，也不能触发自动补生成。

### 1.1 课程测评蓝图

`course_assessment_blueprint_v2` 在逐题生成前冻结：

- 每个二级学习目标的概念检查、目标应用和掌握迁移三个稳定任务槽。
- 每个任务槽的教学理由、目标知识、能力、易错和可观察表现。
- 题型、作答输入、难度、来源和验证方式的约束。
- 节点覆盖、全课分布和综合考核边界。

同一节点至少支持两种 `input_contract_v2` 作答模式；纯长文本题不能占据该节点全部练习位。正式主练习可以使用稳定的三题选择题策略，但教师导入题、历史题目修订和显式其他题型的综合检测不被默认策略批量改写。

### 1.2 参考包

`question_reference_package_v1` 按以下优先级装配：

1. 教师题库和教师确认资料。
2. 当前课程教案、知识、正文与来源绑定。
3. 允许访问的公开网页与检索证据。
4. 模型通用知识。

来源不足、冲突、时效不明或只有模型常识时，候选必须降低来源置信度或进入人工审阅，不能把模型记忆冒充课程指定事实。

### 1.3 公开题面与私有解答

每道正式题必须分离：

- 公开 `QuestionSpec`：题面、条件、交付形式、学生可见资源和输入合同。
- 私有解答合同：标准答案、量规、验证器参数、隐藏测试与参考解题图。

二者只通过版本化解答修订标识关联。学生 API、浏览器状态、日志和导出不得暴露私有字段。

## 2. 质量门与发布决策

每个候选题依次经过：

1. 结构与输入合同检查。
2. 答案可判定性与量规完整性检查。
3. 独立求解及与生成答案的一致性检查。
4. 学科确定性插件或 Runner 验证。
5. 来源、重复度、范围、难度和语义质量评审。
6. `question_quality_report_v5` 汇总结构、教学适配和独立事实证据。

生成阶段采用精简候选合同：生成器先锁定公开题面、实际标准答案、验证器和量规，
不重复生成完整教学解析；独立求解器只读取公开题面，重新作答并补全学生提交后可见的
解析。单题与批量提示必须共享答案先行、来源约束、难度证据和题型作答规则。

复杂任务只有在输入模式、验证器、风险或资料冲突确实需要时才开启模型思考。
模型响应达到输出上限或只有 reasoning、没有完整 JSON 时必须失败关闭，并在有真实
输出余量时重试；残缺 JSON 即使能够被语法修补，也不能进入后续质量门。

当前质量决策合同：

| 结果 | 行为 |
| --- | --- |
| 总分低于 75 | 整题重生 |
| 总分 75-84 | 按问题代码局部修复 |
| 总分至少 85 且无核心维度不足或硬阻断 | 进入对应发布策略 |
| 三次处理后仍未通过 | 废弃，不进入学生题池 |

达到总分仍不能覆盖硬性阻断。答案不可判定、范围外知识、隐藏评分条件、来源严重不足、独立求解冲突、Runner 失败和学生字段泄漏都必须失败关闭。

概念检查在低风险、确定性验证与语义预检全部通过时可以走快速路径；目标练习与掌握
检验必须执行隔离语义评审。评审必须判断题目是否真实要求目标中的可观察表现、难度
是否由必要推理步骤/条件交互/迁移距离体现、课程事实是否有来源支持。评审一旦触发，
`passed=false`、置信度低于 `0.85`、答案不一致或任一 critical 语义问题都属于发布硬门，
不能再被确定性答案验证覆盖。

### 2.1 自动发布与人工审核

- 通过全部质量门的普通低风险题可以自动发布，不要求教师逐题批准。
- 高风险内容、低来源置信度、独立求解不一致、未知学科候选和综合考核必须在发布前审核。
- 教师可以打回已发布题目；该修订立即退出学生池，保留历史与打回原因，再由异步任务只替换这一题。
- 教师不能强行发布未达到质量门或命中硬阻断的题目。
- 任意生成、检索、评分或验证失败都保留当前有效题库 bundle，不能用失败候选覆盖最后可用版本。

### 2.1.1 事实证据与生成完成分开

新生成合同使用 `assessment_fact_evidence_v1`。作者答案、独立解答和模型评审分数均不能充当事实证明；发布入口重新计算证据，不接受模型自行填写的“verified”标记。

| 事实状态 | 后续行为 |
| --- | --- |
| 完整程序证据已覆盖公开题面、答案及评分依据 | 通过结构和教学适配检查后可自动发布 |
| 暂无完整独立证据 | 保留完整候选，任务为 `waiting_review`，显示“已生成，待事实复核”，不因缺少证据自动重写 |
| 公开前提或答案已被程序反例否定 | 阻止发布，仅在原有次数预算内修复对应题目；不允许模型高分覆盖反例 |

计算计划由程序先计算再渲染完整题面。当前覆盖有界的精确四则运算、动态数组倍增追加、闭区间求和、随机优先级 Treap 固定键期望深度、离散 Zipf 覆盖分位数，以及列表/字典状态操作。参数范围、公开条件、作答字段、完整解析和评分规则均参与绑定；增加额外前提或修改任一未覆盖字段后，不再宣称完整核验。任意代码题继续使用原 Runner 执行验证，不能把有限测试通过扩大成对所有题面事实的证明；未覆盖的证明或代码前提仍需复核。

完整程序证据存在时，模型只检查教学目标、可观察动作及表达适配，不重新裁决已由程序证明的数值或状态。对于尚未核验的普通题，模型教学适配检查也不能解除事实复核要求。原子测评的专用证据检查保留，但不得代替独立事实证据。

定理、证明题可通过 `premise_bindings` 关联题面断言、资料引文和服务端冻结的 `reference_id`。程序核对引文是否真实存在并保存来源快照摘要。引文匹配只说明可以追溯原文，不自动证明定理或推导正确；伪造引用、缺失来源和未验证的证明均不能自动发布。完整引文、计算结果及反例保存在教师私有解答边界，学生侧只接收不含答案的核验状态。

继续生成时保留已发布题和已完成、待事实复核的候选；重建单题的任务状态只计算本次选中修订，不能被其他待审题影响。历史题目不做隐式迁移或撤回。用户明确审核通过仍绑定现有不可变修订，已被程序证伪的题目不能通过审核绕过。

回归同时使用正确题、错误前提、篡改答案、额外未覆盖条件、伪造来源及边界假设。计算核验器分别以穷举树排列、闭式扩容成本、前缀和与整数权重分位数作独立对照。真实模型验证固定同一组输入、多轮改变顺序，并分别报告错误放行、正确误拦与接口故障；生成调用完成不等于内容验收通过。

### 2.2 代码题 Runner

正式代码题只能通过独立 Runner 注册和执行隐藏测试：

- 主后端只保存测试包 ID、摘要、资源限制和回执，不保存可由学生接口读取的隐藏测试正文。
- Runner 必须隔离网络、文件系统、进程、时间、内存和输出。
- Runner 不可用、回执过期或测试包不匹配时，实现题失败关闭；不能降级为字符串比对后自动发布。
- 旧文本代码题在重建前可以兼容读取，不能被原地改写成伪 Runner 题。

## 3. 作答与诊断边界

正式评分回答“学生是否达到本题量规”，作答诊断回答“学生真实答案表现出什么方法、正确部分和关键差距”。两者可以并发，但不能互相伪造。

- 诊断先读取学生真实答案，再映射本题允许的课程知识、能力和易错范围。
- 范围外标签被丢弃，不为填满字段强行套用课程知识。
- 选择题只证明学生选择了一个命题，不能反推学生未表达的计算步骤或思维过程。
- 诊断模型失败时保留正式评分并明确标记诊断不可用。
- 真实差距进入现有诊断、补救、针对再练和独立复验链。

## 4. 能力评测

- 十类题目原型通过类型化注册表可用。
- 数学、自然科学、编程、人文、语言和商业目标不依赖主题专用旁路即可路由。
- 每个公开题面都有独立版本化私有解答。
- 独立求解与生成答案不一致时强制进入教师审阅。
- 只有标题、缺少知识合同的目标只能成为候选，不能自动发布。
- 同一二级目标的三个任务槽分别覆盖概念、应用和迁移，不用随机凑题代替教学设计。
- 学生载荷不存在解答、量规、验证器参数和隐藏测试泄漏。

## 5. 回归评测

- 图算法、哈希、线性代数、微积分、热力学、Java 和 C++ 等现有确定性适配器继续有效。
- 已有题库修订、当前有效 bundle 和历史 `PracticeAttempt` 保持可读。
- 搜索、模型、质量评审、发布或 Runner 失败时，当前活动 bundle 不变。
- 部分发布只包含已经批准且通过质量门的任务。
- 被教师打回的题目在替换成功前保持下架，失败不能自动恢复。
- 题库重建只替换通过验证的新修订，不原地污染旧题。
- 中文、英文、桌面和移动端均不暴露原始内部状态或私有字段。

## 6. 发布指标

| 指标 | 门槛 |
| --- | --- |
| 能力评测 `pass@3` | `>= 0.90` |
| 发布关键回归 `pass^3` | `1.00` |
| 可确定验证题的答案验证率 | `100%` |
| 学生答案、量规或隐藏测试泄漏 | `0` |
| 未通过质量门的自动发布 | `0` |
| 生成失败覆盖当前有效 bundle | `0` |

发布指标只证明题目链符合当前合同，不单独证明整门课程或长期学习效果成立。

单次真实课程成功只能证明链路可运行，不能替代 `pass@3`。发布评测至少应同时保留：

- 全题型提示合同测试，确保非选择题不会收到选择题约束，单题与批量规则一致。
- 生成、独立求解、语义评审、质量硬门和断点恢复的确定性回归。
- 使用真实课程资料但不写入正式题库的只读样本生成。
- 固定跨学科样本集的三次独立生成结果，用于计算 `pass@3` 与失败类型分布。
