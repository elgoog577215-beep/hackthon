## 建议先融入哪里

先把现有内容中已经明确的关系表达好，再扩展新图型。最合适的第一入口是教师讲义的局部教学图解：保留连续正文，在真正需要解释关系的位置展示图，或从已有图解候选面板预览并采用。当前讲义右侧的概念关系图已经消费教案与知识关系，适合改进局部布局与阅读定位，不应扩成全课程知识图谱。

PPT 是第二入口。同一份已确认内容和来源关系选择不同布局，由共享场景同时输出网页和原生 PPTX。不能把上游 HTML 截图贴到 PPT 后称为可编辑图解，也不能为了画图在最终渲染阶段再调用模型补写知识。

学生复习材料、学习路径和课程分析可以后续复用选型方法；学生空间实施冻结，不能因为本轮参考项目而开放入口、建立掌握率或修改正式学习记录。

| 使用位置 | 最先解决的问题 | 建议表达 | 数据前提 |
| --- | --- | --- | --- |
| 讲义正文中的推导、原理和前置知识 | 条件是什么，如何得到结论 | 带条件的推导/关系图 | 已有明确关系、解释及来源；条件与中间步骤不能省略 |
| 讲义中的分类与概念范围 | 谁属于谁，层级怎样组织 | 分类树；集合包含可用嵌套图 | 真正的父子/包含关系；多父节点不能硬改为树 |
| 讲义中的易混概念与方法选择 | 比较的是哪两个对象、哪些维度 | 对照表或并列比较 | 共同维度、适用条件和结论；没有集合交集就不用 Venn |
| PPT 中的算法、实验步骤 | 顺序与分支条件 | 过程图；有条件出口才用流程图 | 来源含顺序、判断和出口；只有步骤的资料不能补出分支 |
| PPT 中的系统机制 | 层次与职责如何分开 | 分层图 | 来源已有抽象层或职责层；不把普通列表强排成层 |
| PPT 中的协议与交互 | 谁在何时向谁发送什么 | 时序图 | 明确参与者、消息顺序、调用与返回；不能只凭段落顺序推断 |
| 讲义/PPT 的定量比较 | 同一尺度上的数量差异 | 横向条形图 | 数值、单位、来源和条件完整；零基线、相同比例 |

示例覆盖这七类，不表示七类都已被现有合同支持。第一批建议收敛到**推导/关系、分类树、对照表、普通过程**，因为已有语义与来源合同最接近。分支流程、分层、时序需要补齐自己的语义合同及共享布局；条形图沿现有真实数值合同改进样式。

## 怎样选择，避免为好看而画图

1. 先确定读者要回答的问题：顺序、条件、因果、包含、比较、交互还是数值。标题或段落顺序不是关系证据。
2. 检查已有内容与来源能否支持图的全部对象、边、条件和数值。证据不够时显示原文、表格或列表；不给缺失数据填零，也不让模型猜测关系。
3. 再选图型：纯顺序用过程；有判断用流程；单父层级用树；混合前置/推导关系用带标签的局部关系图；共同维度用比较表；消息时序用时序图；定量数据才用统计图。
4. 默认一张图解释一个局部教学动作，约 3–7 个对象。复杂内容拆成概览与细节，保留来源导航及完整文字；不以截断标签、丢掉条件或静默删节点满足容量。
5. 推荐只是一种候选表达。编辑者能查看适用理由、来源和替代图型，在既有采用流程里决定。换图型保留语义；几何、颜色和字体由系统控制。

暂不优先选择雷达、桑基、象限、鱼骨、Wardley、看板或大型架构图。不是这些图没有价值，而是当前教学入口尚没有普遍满足它们的评分量规、守恒流量、双轴依据、因果证据或工作流数据。雷达尤其不能把停留时间、一次作答或模型解释包装成精确能力分；本轮也不建设全课程知识图谱。

## 吸收哪些设计，保留哪些本项目规则

值得吸收的是一图一义、节点层级、正交连线、明确箭头方向、连线文字遮罩、少量焦点、留白和复杂度限制。树表达包含，判断菱形表达分支，生命线表达消息时序；不用一组相同卡片替代所有关系。

灵知继续使用蓝紫配色、白色正文与系统中文字体。上游默认橙色、英文衬线标题、点阵背景和偏小字号不直接进入产品。常用操作和主要正文不低于 15px；侧栏空间不足时换紧凑表达或展开阅读，不把整图缩成不可读小字。焦点与状态分开，颜色不能替代关系文本。

运行时不执行上游生成脚本、不上传课程给外部服务、不加载 Google Fonts、不安装插件或新增模型提供方。若以后引入具体模板或工具，只复制已选择且可追溯的必要部分，保留许可并记录上游提交；第三方图标/字体分别核查，仓库 MIT 不自动覆盖所有附件。

## 最小落地建议与验收

建议从同一小节的**关系图 + 对照表 + 过程/分类表达**开始，每种用一个固定教学样本证明“比原文或现有卡片更容易看清关系”。把本页示例中认可的方向转换成正式业务设计后，再在原组件与原稿件链里实现。新增图型不拆出另一个课程 Store 或独立生成任务。

上线前至少覆盖：

- 来源、方向、关系类型、条件、数字和公式完整；复杂图不静默丢内容，证据不足有可读文字降级。
- 中英文桌面、长中文、长技术标识、公式、键盘焦点、来源定位与窄侧栏可读性。
- 候选采用、来源过期、权限及恢复沿原流程；教师预览不产生正式学习记录。
- 同一已确认稿件的 Web/PPTX 关系、文本和比例一致；PPT 使用原生对象并经过回读与溢出检查。
- 图型选择不追加默认规划/自审调用；最终渲染无模型改写；真实调用、浏览器、导出及生产验收分别说明。

本轮完成项目获取、静态评估和独立示例。示例已检查七图 × 中英文 × 两种框架的 28 组切换、条长与数值比例、SVG 标题/描述及 ID 唯一性；默认桌面浏览器检查七图中英文文字边界与文字相交，未发现裁切或文字重叠，控制台无错误/警告。实际下载的 SVG 已核对 XML、自包含样式与两个判断节点；本地文档链接和 MIT 许可一致性检查通过。这些检查只覆盖手写示例。

正式应用接入、真实课程采用与 PPTX/生产验收尚未实施；本页不将这些建议登记为已交付功能。
