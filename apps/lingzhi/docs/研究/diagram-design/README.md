## 建议先融入哪里

先把现有内容中已经明确的关系表达好，再扩展新图型。最合适的第一入口是**师生共用讲义的局部教学图解**，学生独立阅读属于首要使用场景。保留连续正文，在真正需要解释关系的位置展示图；编辑者从已有图解候选能力预览并采用。当前讲义右侧的概念关系图已经消费教案与知识关系，适合局部概览与正文定位，不能代替正文中的教学图解，也不扩成全课程知识图谱。

PPT 是第二入口。同一份已确认内容和来源关系选择不同布局，由共享场景同时输出网页和原生 PPTX。不能把上游 HTML 截图贴到 PPT 后称为可编辑图解，也不能为了画图在最终渲染阶段再调用模型补写知识。

学生讲义的教学图解已纳入[学生学习设计](../../功能设计/学生学习.md#学生讲义中的教学图解)，学生复习材料可按同一方法选择表达。正式学生空间实施仍冻结，本次补齐阅读设计和独立原型，不开放身份入口或写入学习记录；教师预览与正式学习继续分别验收。

## 44 种类型怎样用于学生讲义

上游类型表的 44 种全部在下表分类，前轮七个、本轮十个手写示例只是选型样本，不是可用类型上限。对照表是项目已有表达；推导图是关系语义的教学用法，两者不另算上游类型。依据为获取提交中的[上游类型表](https://github.com/cathrynlavery/diagram-design/blob/7a2e22170ee838e859d8142ba825d83f8b6375e6/skills/diagram-design/SKILL.md#visual-type-guide-44)。

| 类型组 | 上游类型（合计 44） | 学生讲义里的适用情形与前提 |
| --- | --- | --- |
| 通用结构，8 种 | Flowchart、Process、Tree、Nested、Venn、Layer stack、Timeline、Loop | 算法、实验步骤、分类、集合、抽象层与时间过程。分支流程必须标明条件出口，时间轴必须有时间，上游 Loop 布局须确实返回起点并向同一中心汇总状态；不能把普通步骤任意围成圈 |
| 交互与依赖，4 种 | Sequence、State machine、Swimlane、Dependency graph | 协议消息、对象状态、分工交接、多父依赖或循环。明确参与者、触发、方向和关系；局部依赖图不等于建设全课知识图谱 |
| 定量表达，10 种 | Bar chart、Line chart、Scatter plot、Heatmap、Treemap、Waterfall、Sankey、Polar chart、Radar / Spider、Pyramid / funnel | 数量、趋势、分布、矩阵、占比、贡献和流量。须有可追溯数值/单位/统计条件；桑基需数量关系成立，雷达需共同量规，不能生成学生精确能力分 |
| 系统与数据结构，13 种 | Architecture、Architecture delta、IT current-state、ER / data model、Org chart、High-Level、Medallion、Data flow、DP integration、DP security matrix、Deployment、UML class、Database schema | 计算机、数据工程、组织管理等学科中的真实系统、结构与权限材料。专名、字段、关系和边界须有来源，按学科选用，不让每门课都变成软件架构图 |
| 空间与构造，2 种 | Exploded axonometric、Axonometric plan | 机械构造、零件关系、空间与场地说明。须有结构与空间依据；示意投影不能冒充实测尺寸或工程图 |
| 项目与分析，7 种 | Quadrant、Gantt、Fishbone、Wardley map、Kanban、User journey、Story map | 项目实践、实验安排、原因分析、设计与管理课程。坐标、时长、因果或任务状态必须有依据；个人项目记录只读取真实任务，不由图解生成器代造进度 |

通用结构和对照表达通常最贴近讲义。专用系统图、空间图和统计图可能是某门学科的核心表达，并非一律延后；是否选用取决于具体教学内容与现有数据合同。首批实现只收敛工程范围，不收缩长期图型选择。

## 学生阅读中怎样放

正式交互以[学生学习设计](../../功能设计/学生学习.md#学生讲义中的教学图解)为准。建议按“说明当前问题与条件 → 局部图解 → 图注及结论 → 可选的解释/应用问题”组织同一小节，图仍引用正式内容。十个示例增加学生阅读框架，可直观看见图前、图中和图后的关系；示例问题及展开解释不计分、不保存，不冒充已接通正式练习。

| 位置 | 展示原则 | 代表情形 |
| --- | --- | --- |
| 对应正文中，默认可见 | 核心关系就地说明，完整文字与公式继续保留 | 例题中的推导图、集合包含图、算法分支、易混概念比较 |
| 正文中可展开或放大 | 概览先读懂，复杂细节按需查看，返回保持锚点 | 长时序、多层结构、多条件关系；不能整图缩小后藏掉字 |
| 现有概念关系面板 | 只承担局部概览与正文导航，不塞入所有图型 | 当前小节的已有前置、推导、对比关系 |
| 复习与个人材料 | 从获授权内容派生个人表达，保留来源与本人归属 | 对照整理、时间线、错题关联的小段说明；不覆盖教师教材 |

学生右栏继续是笔记与 AI 助手，图解放入现有 `ContentArea → CourseBlockStream → HandoutContentBlock` 连续阅读链。教材里的已采用图解由师生共用，读取权限、来源过期与答案过滤在原投影中完成；学生个人生成的补充图解则归本人材料。两种拥有者不能混用，不能让学生为看到同一教材图另调用一次模型。

| 使用位置 | 最先解决的问题 | 建议表达 | 数据前提 |
| --- | --- | --- | --- |
| 讲义正文中的推导、原理和前置知识 | 条件是什么，如何得到结论 | 带条件的推导/关系图 | 已有明确关系、解释及来源；条件与中间步骤不能省略 |
| 讲义中的分类与概念范围 | 谁属于谁，层级怎样组织 | 分类树；集合包含可用嵌套图 | 真正的父子/包含关系；多父节点不能硬改为树 |
| 讲义中的易混概念与方法选择 | 比较的是哪两个对象、哪些维度 | 对照表或并列比较 | 共同维度、适用条件和结论；没有集合交集就不用 Venn |
| 讲义/PPT 中的算法、实验步骤 | 顺序与分支条件 | 过程图；有条件出口才用分支流程图 | 来源含顺序、判断和出口；只有步骤的资料不能补出分支 |
| 讲义/PPT 中的系统机制 | 层次与职责如何分开 | 分层图 | 来源已有抽象层或职责层；不把普通列表强排成层 |
| 讲义/PPT 中的协议与交互 | 谁在何时向谁发送什么 | 时序图 | 明确参与者、消息顺序、调用与返回；不能只凭段落顺序推断 |
| 讲义/PPT 的定量比较 | 同一尺度上的数量差异 | 横向条形图 | 数值、单位、来源和条件完整；零基线、相同比例 |
| 讲义中的集合范围 | 哪个集合包含哪个集合 | 嵌套图 | 集合包含须成立；框面积不暗示元素数量 |
| 讲义中的集合运算 | 哪些元素共同属于两个集合 | Venn 图 | 交集、差集及全集明确；面积不冒充数量比例 |
| 讲义中的事件或实验记录 | 先后顺序与间隔多长 | 时间轴 | 时间和单位明确；位置按间隔计算，未知时间不补造 |

示例覆盖这十类，不表示十类都已被现有合同支持。第一批建议收敛到**推导/关系、分类树、对照表、普通过程**，因为已有语义与来源合同最接近。分支流程、分层、时序、集合及时间轴需要补齐自己的语义合同及共享布局；条形图沿现有真实数值合同改进样式。

## 怎样选择，避免为好看而画图

1. 先确定读者要回答的问题：顺序、条件、因果、包含、比较、交互还是数值。标题或段落顺序不是关系证据。
2. 检查已有内容与来源能否支持图的全部对象、边、条件和数值。证据不够时显示原文、表格或列表；不给缺失数据填零，也不让模型猜测关系。
3. 再选图型：纯顺序用过程；有判断用流程；单父层级用树；混合前置/推导关系用带标签的局部关系图；共同维度用比较表；消息时序用时序图；定量数据才用统计图。
4. 默认一张图解释一个局部教学动作，约 3–7 个对象。复杂内容拆成概览与细节，保留来源导航及完整文字；不以截断标签、丢掉条件或静默删节点满足容量。
5. 推荐只是一种候选表达。编辑者能查看适用理由、来源和替代图型，在既有采用流程里决定。换图型保留语义；几何、颜色和字体由系统控制。

雷达、桑基、象限、鱼骨、Wardley、看板或大型架构图按学科与材料条件选择。当前通用教学入口没有普遍满足它们的评分量规、守恒流量、双轴依据、因果证据或工作流数据；不能只因模板漂亮就推荐。雷达尤其不能把停留时间、一次作答或模型解释包装成精确能力分；本轮也不建设全课程知识图谱。

## 吸收哪些设计，保留哪些本项目规则

值得吸收的是一图一义、节点层级、正交连线、明确箭头方向、连线文字遮罩、少量焦点、留白和复杂度限制。树表达包含，判断菱形表达分支，生命线表达消息时序；不用一组相同卡片替代所有关系。

灵知继续使用蓝紫配色、白色正文与系统中文字体。上游默认橙色、英文衬线标题、点阵背景和偏小字号不直接进入产品。常用操作和主要正文不低于 15px；侧栏空间不足时换紧凑表达或展开阅读，不把整图缩成不可读小字。焦点与状态分开，颜色不能替代关系文本。

运行时不执行上游生成脚本、不上传课程给外部服务、不加载 Google Fonts、不安装插件或新增模型提供方。若以后引入具体模板或工具，只复制已选择且可追溯的必要部分，保留许可并记录上游提交；第三方图标/字体分别核查，仓库 MIT 不自动覆盖所有附件。

## 最小落地建议与验收

建议从同一小节的**关系图 + 对照表 + 过程/分类表达**开始，每种用一个固定教学样本证明“比原文或现有卡片更容易看清关系”。把本页示例中认可的方向转换成正式业务设计后，再在原组件与原稿件链里实现。新增图型不拆出另一个课程 Store 或独立生成任务。

上线前至少覆盖：

- 来源、方向、关系类型、条件、数字和公式完整；复杂图不静默丢内容，证据不足有可读文字降级。
- 中英文桌面、长中文、长技术标识、公式、键盘焦点、来源定位与窄侧栏可读性。
- 候选采用、来源过期、权限及恢复沿原流程；教师预览不产生正式学习记录。
- 同一已确认稿件的 Web/PPTX 关系、文本和比例一致；PPT 使用原生对象并经过回读与溢出检查。
- 图型选择不追加默认规划/自审调用；最终渲染无模型改写；真实调用、浏览器、导出及生产验收分别说明。

本轮完成项目获取、静态评估、学生阅读设计及独立示例。示例已检查十图 × 中英文 × 三种框架的 60 组切换、条长与数值比例、时间轴间隔、SVG 标题/描述及 ID 唯一性，以及学生说明/问题的显隐和切换图型时解析收起；默认桌面浏览器检查十图中英文文字边界与文字相交，未发现裁切或文字重叠，控制台无错误/警告。浏览器已验证解析展开；实际下载的流程图与时间轴 SVG 已核对 XML、自包含样式及相应结构。本地文档链接、44 种类型覆盖和 MIT 许可一致性检查通过。这些检查只覆盖手写示例。

正式应用接入、真实课程采用与 PPTX/生产验收尚未实施；本页不将这些建议登记为已交付功能。
