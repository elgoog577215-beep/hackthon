## 4. 两条非"完成"的具体原因

### G2 退化 —— 结构性，不是模型不行

`_select_sources` 只在**当前节点**的 blocks 内排序取材（`backend/ai_teacher_context.py`），跨节点正文根本不在上下文里。实测两个 provider 的 `source_node_ids` 都只有 `node-5`。

判为"退化"而非"失败"的依据：两者都**没有**把不在上下文里的前置小节当成课程来源引用，即没有伪造。这正是任务集第 6 节说的"结构性做不到的任务，其价值在于给出可比的失败基线"。

### G4 未跑通 —— 缺前置设施，未伪造数据

端到端来源绑定需要可达的 SearXNG 实例；本机未部署（架构文档要求它只监听 `127.0.0.1:8080` 由独立工作流部署）。

**已验证的部分**：会话级门控三种情形全部正确（关闭时不检索、开启时检索、直接动作不出站）。**未验证的部分**：`[S1]` 引用标记、`citation_id`/`url`/`retrieved_at` 绑定、检索失败降级提示。按要求没有造假来源糊过去。

## 5. 跨 provider 差异：只有速度，没有结果差异

结论一致，但延迟差一个量级：

| 指标 | 千问 3.6 | DeepSeek |
| --- | --- | --- |
| 模型类任务平均耗时 | **22.0 s** | **5.7 s** |
| 最慢单条（E2，含三次追问） | 43.4 s | 10.0 s |
| G1 流式分片数 / 回答字数 | 312 / 526 | 232 / 428 |

**千问慢约 3.9 倍**，原因已定位：该端点默认开启思考链。实测同一问题 `max_tokens=200` 时返回**空内容**（1308 token 全部消耗在思考上），放大到 3000 才返回 34 字答案。AI 老师问答链路默认 `max_tokens=8192`，所以能正常出答案，但每次都付思考开销。

> ⚠️ **一个需要决策的兼容性问题**：`ai_base._thinking_extra_body` 对非 DeepSeek 端点发的是扁平 `{"enable_thinking": false}`，**该 vLLM 端点会静默忽略它**——实测仍然消耗满 300 token 且返回空内容。有效写法是 `chat_template_kwargs: {"enable_thinking": false}`（实测 29 token 出答案）。这条本轮**没有改**，因为它影响所有 AI 能力而不只是 AI 老师，属于跨线改动。详见第 7 节。

## 7. 本轮如实记录的问题（不修，只记）

1. **千问端点 `enable_thinking` 扁平写法无效**（见第 5 节）。影响：小 `max_tokens` 的调用路径在千问上会拿到空响应并被判为 `empty_response` 失败。AI 老师问答不受影响（8192 预算够），但出题、评审等设了较小预算的路径需要单独核。
2. **仓库自带的 `scripts/qwen_endpoint_smoke.py` 对该端点判"不可上线"**（短补全、长 JSON 两项阻断）。实测两项都是**思考链吃掉 token 预算**导致的，不是端点坏。该脚本的判定阈值需要按"会思考的模型"重新标定，否则会持续误报。
3. **DeepSeek 首轮 5 条返回 `model_auth_failed`**（E2/E3/E4/S2/S3），单独重试全部通过，key 用 curl 直连正常。判定为 provider 侧瞬时故障。**本表采用重试结果，并在此显式声明**，没有把瞬时故障记成实现缺陷，也没有假装首轮没发生过。

## 8. 与 W16 口径对齐

W16 的真机冒烟（`dev/lz-integration` NOTES 第四节）此前两轮都报 **AI 老师流式呈现缺陷**，其测法是"网络层 chunk 数 vs 回答区 DOM 增长次数"。

- W16 两轮测的是 tip `c8980794`，**早于**流式修复 `5dd5d7ed`；
- 该修复现已合入集成分支（`a0d23bd2`）；
- 本轮基线跑在含修复的树上，G1 实测流式分片 312（千问）/ 232（DeepSeek）。

**口径统一建议**：流式是否达标以 `scripts/verify_ai_stream_render_e2e.mjs` 的 **chunk→paint p50 延迟**为准（当前实现 11–19ms，旧实现 73–88ms），而不是"DOM 增长次数"——后者会被合帧影响，在正常实现上也可能读数偏低。

## 9. 未覆盖边界

- **G4 端到端未验证**（缺 SearXNG），见第 4 节。
- **本基线不含前端**：20 条都在后端链路上判定，浏览器层的流式与视觉另由 `verify_ai_stream_render_e2e.mjs` 覆盖。
- **单轮采样**：每条任务每个 provider 只跑一次（E2/S3 内含多次追问）。模型输出有随机性，"完成"表示本轮满足判定标准，不等于稳定复现率。要给出复现率需多轮重跑。
- **成本未测**：任务集第 3 节已声明延迟与成本需独立基线，本轮只记录耗时，未记 token 成本。
