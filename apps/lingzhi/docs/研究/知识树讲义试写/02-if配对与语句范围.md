# 第2讲　if 的语句范围与 else 配对

知识树驱动试写样稿。正文为千问首次输出；例题、诊断和自测答案按冻结引用插入。独立核对结论见配套验收报告。

在C17中，`if` 语句不仅用来判断真假，更通过严格的语法规则决定了执行流的走向。初学者常犯的错误不是不知道逻辑，而是误判了 `else` 与哪个 `if` 配对，或者误以为 `if` 控制了后续多行代码。本讲通过解析标量条件的语义、复合语句的范围以及 `else` 的词法就近原则，帮助建立对 C 语言控制流的结构化理解。

本讲按 C17 讨论。代码示例为 `void sample(void)` 函数体内的片段，已包含 `<stdio.h>`、`<limits.h>` 等头文件，由 `main` 调用；出现 `return;` 表示结束该 `sample` 函数。

本讲统一术语：标量表达式；分支体；复合语句（可用别名：语句块）；else 配对（可用别名：else归属）；空语句；if/else-if 选择链（可用别名：选择链）；独立 if（可用别名：独立if）。

## 条件、语句范围与一次分支选择

### 条件的真值与分支体范围

C17 规定，`if` 语句后的条件必须是一个标量表达式。所谓标量表达式，是指其求值结果为标量类型（如整数、浮点数、指针）的表达式。在判断分支时，程序依据的是“零值为假，非零值为真”的语义。这意味着，无论是正数、负数还是浮点数，只要结果不为 0，程序就会进入 `if` 的真分支体。例如，对于整数变量 `int n = -5;`，表达式 `n` 的求值结果是非零值，因此被视为真。这一点常被误解为只有大于 0 的数才为真，但在 C 语言中，负数如 `-5` 同样满足真值的定义。

与条件求值同样重要的是分支体的边界。语法上，`if` 语句后的分支体由一条完整的语句组成。如果没有花括号，分支体仅包含紧随其后的第一条语句；如果需要包含多条语句，必须使用复合语句（也叫语句块，即由花括号包围的一段代码）。初学者常误以为 `if` 会控制其后的所有缩进代码，这在语法上是不成立的。

知识依据：K-I01 标量条件的真值语义；K-I03 分支体的语句范围。

### 示例：负数作为真值

**例题 E-I01：标量条件的真值语义**

```c
int n=-5;if(n)printf("T");else printf("F");
```

标准输出（核验记录）：

```text
T
```

观察变量 `int n = -5;` 的情况。当执行条件判断 `if(n)` 时，编译器评估表达式的值。因为 `n` 的值是 -5，不等同于 0，根据 C17 标量真值语义，该条件判定为真。程序随后进入真分支。这个例子强调了分支决策不依赖于数值的正负号，仅依赖于其是否为零。

知识依据：K-I01 标量条件的真值语义。

### 分支选择的不可逆性

一旦程序进入 `if` 的某个分支，它就不会在分支内部修改条件变量后，自动跳转到另一个分支。在普通顺序执行流中，分支决策是在进入该语句时进行的。如果在真分支体内，将原本为真的变量修改为 0，程序在结束该分支后会直接向下执行，不会回头去补执行 `else` 分支。这是控制流的一个关键特性：分支选择是单次的，且一旦执行完选定的分支体，该 `if` 语句的执行逻辑即告结束。

知识依据：K-I02 一次执行不重新选分支。

### 示例：修改条件不触发 else

**例题 E-I02：一次执行不重新选分支**

```c
int x=1,y=0;if(x){x=0;}else{y=1;}printf("%d",y);
```

标准输出（核验记录）：

```text
0
```

设有 `int x=1, y=0;`。执行 `if(x){x=0;}else{y=1;}`。由于 `x` 初始值为 1（真），程序进入真分支，执行 `x=0`。此时 `x` 已经改变，但由于分支已经选定，`else` 分支被跳过。最终 `y` 保持为 0。此例说明，分支内对变量的操作不会回溯改变已做的路径决策。

知识依据：K-I02 一次执行不重新选分支。

### 示例：分支体仅限一行

**例题 E-I03：分支体的语句范围**

```c
int a=0,x=0,y=0;if(a)x=1;y=2;printf("%d",y);
```

标准输出（核验记录）：

```text
2
```

设有 `int a=0, x=0, y=0;`。执行 `if(a) x=1; y=2;`。这里 `if` 分支体仅包含赋值 `x=1`。由于 `a` 为 0，条件为假，`x=1` 不被执行。然而，紧接着的 `y=2` 是独立于 `if` 之后的后续语句，无论条件真假都会执行。因此最终输出 `y` 的值是 2，而不是初始的 0。这展示了没有花括号时，`if` 无法控制后续非紧邻语句的范围。

知识依据：K-I03 分支体的语句范围。

## else 配对：语法、花括号与缩进

### 词法就近原则

当存在多个 `if` 和一个 `else` 时，确定 `else` 归属于哪一个 `if` 是初学者最常遇的陷阱。C 语言采用了“词法就近配对”原则：`else` 结合到语法允许的、词法上最近的前面出现的 `if`。在没有花括号干预的情况下，`else` 总是与嵌套层级中最后写到的 `if` 配对。这意味着，如果代码写成 `if(a) if(b) x=1; else x=2;`，这个 `else` 实际上是属于内层 `if(b)` 的，而不是属于外层 `if(a)` 的。这种语法规定与视觉缩进无关，完全由词法顺序和括号界定。

知识依据：K-I04 else 的词法就近配对。

### 花括号对配对边界的约束

花括号（复合语句的边界）可以改变这种就近配对的逻辑。如果内层 `if` 被包裹在一个复合语句中，例如 `if(a){ if(b) x=1; }`，那么位于花括号闭合后的 `else` 无法跨越这个花括号边界去与内部最末的 `if(b)` 配对。此时，`else` 在语法上只能归属于外层 `if(a)`。这是因为 `else` 必须在语法允许的范围内寻找最近的 `if`，而复合语句的边界阻断了它与内部嵌套 `if` 的配对关系。

知识依据：K-I05 花括号显式修改 else 归属。

### 缩进与语法的解耦

虽然花括号能改变配对，但单纯调整代码的空白缩进则完全不能改变语法规则。在 C 语言中，空格、制表符和换行符仅仅是用于分隔记号的空白字符。编译器在词法分析阶段会忽略这些空白。因此，即使你将 `else` 视觉上缩进到与外层 `if` 对齐的位置，只要没有增加花括号改变语法结构，编译后的行为依然遵循词法就近配对。

知识依据：K-I06 缩进不改变语法归属。

## 外层未进入与空语句陷阱

### 控制流的依赖关系

当程序嵌套了 `if` 结构时，内层的执行依赖于外层是否选中了对应分支。如果外层 `if` 的条件为假，控制流会跳过该分支体的所有内容，直接进入下一条后续语句。这意味着，即使内层的 `else` 逻辑上看似乎是一个“兜底”分支，但如果它位于一个未被执行的分支体内，它也永远不会被执行。这种整体性——外层未命中，内层结构整体跳过——是理解复杂嵌套逻辑的基础。

知识依据：K-I07 未进入外层则不执行内层。

### 示例：外层条件为假

**例题 E-I04：未进入外层则不执行内层**

```c
int a=0,b=1,x=0;if(a)if(b)x=1;else x=2;printf("%d",x);
```

标准输出（核验记录）：

```text
0
```

设有 `int a=0, b=1, x=0;`。代码为 `if(a) if(b) x=1; else x=2;`。这里外层 `if(a)` 的条件 `a` 为 0（假）。虽然内层 `if(b)` 的条件 `b` 为 1（真），但由于外层未通过，内层的 `if(b)` 及其配对的 `else` 整体都不执行。最终 `x` 保持为 0，而不是 2。这证明了外层逻辑的“门槛”作用。

知识依据：K-I07 未进入外层则不执行内层。

### 空语句导致的逻辑断点

在书写 `if` 语句时，如果在条件右括号和分支语句之间意外多写了一个分号，例如 `if(cond);`，这在语法上等同于 `if(cond) { }`。这个分号构成了一个空语句。此时，原本期望受该 `if` 控制的下一条语句，变成了与 `if` 平行的后续独立语句。程序无论条件真假，都会执行该后续语句。这是一个极难通过阅读发现但极易发生的逻辑错误。

知识依据：K-I08 空语句对控制范围的破坏。

## 选择链与独立判断

### if/else-if 选择链的本质

C 语言中没有 `else if` 这一语法关键字，它只是 `else` 子句内部嵌套的另一条 `if` 语句。这种结构形成了所谓的 if/else-if 选择链。选择链的特性在于互斥性：在普通顺序执行中，一旦链中某个条件被判定为真并执行了对应分支，程序就会跳出整个链，后续的分支条件求值被直接跳过。这种特性非常适合处理等级判定或分类逻辑。

知识依据：K-I09 else if 的语法结构；K-I10 选择链首命中后停止判断。

### 示例：链式判断的短路

**例题 E-I05：选择链首命中后停止判断**

```c
int b_calls=0;if(1){}else if(++b_calls){}printf("%d",b_calls);
```

标准输出（核验记录）：

```text
0
```

设有变量 `int b_calls=0;`。代码执行 `if(1){}else if(++b_calls){}`。这里 `1` 始终为真。程序进入 `if(1)` 的分支体（空块），执行完毕后，直接跳过 `else if` 分支。因此 `++b_calls` 不会执行，输出变量 `b_calls` 依然保持为 0。这展示了选择链一旦首中，后续判断即被忽略。

知识依据：K-I10 选择链首命中后停止判断。

### 独立 if 的顺序执行

与选择链不同，多个独立书写的 `if` 语句是平级的。每条 `if` 都会独立地读取当前的变量状态并做出自己的判断。前面的 `if` 即使改变了某个变量的值，后续 `if` 在求值时看到的也是修改后的新值。这种顺序依赖性要求程序员必须仔细考虑变量在执行流中的状态变化，不能将 `if` 视为孤立的快照判断。

知识依据：K-I11 独立 if 可以多次命中；K-I12 后续 if 读取新状态。

### 示例：新状态下的二次判断

**例题 E-I06：后续 if 读取新状态**

```c
int x=1,y=0;if(x)x=0;if(x)y=1;printf("%d %d",x,y);
```

标准输出（核验记录）：

```text
0 0
```

设有 `int x=1, y=0;`。代码段为 `if(x)x=0; if(x)y=1;`。第一条 `if` 中 `x` 为真，进入分支，将 `x` 修改为 0。随后执行第二条 `if(x)`。此时程序读取 `x` 的当前值 0，条件为假，因此 `y=1` 不执行。最终输出 `x` 和 `y` 均为 0。这里清晰地展示了第二个 `if` 依赖第一个 `if` 产生的状态修改。

知识依据：K-I12 后续 if 读取新状态。

适用条件：顺序执行到各if；无提前return等跳转；a、b、x、y已正确声明初始化，所有自增有定义。

### 自测 6 · Q-I12

已知代码段：`int x = 1; if(x) x = 0; if(x) y = 1;`，在普通顺序执行下，第二条 `if(x)` 中的条件 `x` 被求值时，其结果是什么？

适用条件：普通顺序执行；变量已初始化，修改及读取有定义；代码片段中的y事先声明为int。

### 参考解答

1. 0 else 词法上就近配对到内层 if(b)。因为 a 为假，外层 if 的整个分支体（包括内层 if 和配对的 else）都不执行。

2. 不能，配对由语法（如花括号边界）决定，空白缩进无此效力。 C17的词法分析会跳过空白字符（包括空格和制表符），词法记号序列和后续的语法分析（AST构建）完全不受视觉缩进的影响。`else` 的配对严格由其与 `if` 的相对语法位置（尤其是花括号边界）决定。

3. 20 分号紧跟 if 条件后构成空语句作为分支体，y=20 是独立于 if 之后的语句，无论条件真假均执行。

4. 不会 由于 `else if` 在语法上是 `else` 的分支，而 `if`/`else` 的语义规定只有当条件为假时才会执行 `else` 分支。因此一旦 `A` 为真，控制流进入 `A` 分支，根本不会到达 `else` 分支去求值 `B`。

5. 能，因为这是两条独立的 `if`。 两条独立的 `if` 语句之间没有语法上的分支绑定关系。第一条 `if` 命中并执行后，控制流继续往下，第二条 `if` 会独立地对其条件 `b` 进行求值并执行其分支。

6. 为假（或0），因为求值时 `x` 的值已经被前一条语句修改为0。 第二条 `if` 在执行到该语句时，才会对条件 `x` 进行求值。由于前一条 `if` 内的 `x=0` 已经执行完毕并改变了 `x` 的内存状态，因此第二次求值读到的是修改后的当前值 `0`（即假）。
