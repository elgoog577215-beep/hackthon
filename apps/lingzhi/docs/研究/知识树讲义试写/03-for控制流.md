# 第3讲　for 控制流

知识树驱动试写样稿。正文为千问首次输出；例题、诊断和自测答案按冻结引用插入。独立核对结论见配套验收报告。

本讲旨在梳理 C17 语言中 `for` 循环的结构、执行顺序及其边界行为。我们将深入探讨控制流的三个核心组成部分：初始化子句、控制表达式与迭代表达式，并分析 `continue` 和 `break` 在嵌套结构中的跳转目标，以及整数类型在循环终止条件中的潜在陷阱。

本讲按 C17 讨论。代码示例为 `void sample(void)` 函数体内的片段，已包含 `<stdio.h>`、`<limits.h>` 等头文件，由 `main` 调用；出现 `return;` 表示结束该 `sample` 函数。

本讲统一术语：初始化子句（可用别名：初始化部分）；控制表达式（可用别名：条件表达式、控制条件）；迭代表达式（可用别名：更新表达式、第三部分）；循环体；作用域；空语句；无符号回绕（可用别名：无符号整数回绕）；有符号整数溢出。

## 一次 for 循环怎样推进

### 循环的推进机制

一个 `for` 循环的推进取决于三个部分。首先是**初始化子句**（initializer），它在程序每次正常进入该 `for` 语句时执行且仅执行一次（K-F01）。这意味着即使循环体重复执行多次，变量的初值也只会被设定一次。其次是**控制表达式**（control），它负责判断循环是否继续；在每次进入**循环体**（body）之前，系统都会评估这个表达式（K-F02）。如果表达式非零，才进入循环体；如果首次评估即为假，则循环体执行零次（K-F03）。最后，在循环体正常完成且没有被中断语句（如 `break`）打断后，程序会执行头部的**迭代表达式**（iteration，即更新表达式），随后再次回到控制表达式处进行判断（K-F04）。对于正常执行了 n 次循环体后退出循环的情况，控制表达式总共会被评估 n+1 次（K-F05），多出的这一次正是为了确认循环结束条件。

知识依据：K-F01 初始化子句执行频次；K-F02 每次入体前判断条件；K-F03 首判为假与零次执行；K-F04 体后更新顺序；K-F05 正常退出时的条件判断次数。

### 首判为假

**例题 E-F01：首判为假与零次执行**

```c
int i;for(i=10;i>100;i++){i=-1;}printf("%d",i);
```

标准输出（核验记录）：

```text
10
```

在以下代码中，循环初始状态为 `i=10`，控制条件是 `i>100`。由于 10 不大于 100，控制条件在首次评估时即为假（K-F03）。根据“先判断再入体”的规则，程序直接跳过了循环体，因此 `i` 始终保持为 10，未被循环内部的 `i=-1` 修改。

知识依据：K-F03 首判为假与零次执行。

### 更新顺序分析

**例题 E-F02：体后更新顺序**

```c
int i=0;for(i=0;i<2;i++){i+=10;}printf("%d",i);
```

标准输出（核验记录）：

```text
11
```

观察这段代码，第一轮时 `i=0` 入体，执行 `i+=10` 后 `i` 变为 10。由于循环体正常结束，程序接着执行头部迭代表达式 `i++`，此时 `i` 变为 11。接着判断 `i<2`（即 11<2）为假，循环退出。这印证了更新步骤发生在循环体正常完成之后、下一次判断之前（K-F04）。

知识依据：K-F04 体后更新顺序。

## 头部省略与循环体范围

### 语法细节与省略规则

`for` 的语法允许三部分中的任何一部分被省略，但必须保留两个分号（K-F09）。如果省略了**初始化子句**，循环将从已有的变量状态开始（K-F06）；如果省略了**控制表达式**，其效果等同于该位置填入了一个非零常量，即条件恒为真（K-F07）。同样，省略**迭代表达式**仅表示该处没有自动更新代码，系统不会主动执行 `i++`（K-F08）。关于循环体，它必须是单条语句。如果需要包含多条指令，必须使用复合语句（即用大括号括起来的块）。特别要注意空语句（null statement）的风险：`for(...);` 中的分号本身就是循环体，后续的代码块不再属于循环（K-F11）。

知识依据：K-F06 省略初始化使用已有状态；K-F07 省略条件视为真；K-F08 省略迭代不自动更新；K-F09 for头部保留两个分号；K-F10 for 的单语句体；K-F11 for 的空语句体。

### 空语句陷阱

**例题 E-F08：for 的空语句体**

```c
int i,x=0;for(i=0;i<3;i++);x++;printf("%d",x);
```

标准输出（核验记录）：

```text
1
```

这段代码展示了 `for(i=0;i<3;i++);` 的微妙之处。分号构成了一个**空语句**，这意味着循环体没有任何操作。当 `i` 从 0 增加到 3 循环结束后，程序才执行下一个独立语句 `x++`。因此 `x` 只被加 1，结果为 1（K-F11）。如果去掉分号，`x++` 则会作为循环体重复三次。

知识依据：K-F11 for 的空语句体。

## continue、break、return 与嵌套目标

### 控制流转移的目标

控制流在 `for` 循环内部的转移取决于指令类型。`continue` 会跳过当前循环体剩余部分，并**立即执行头部第三部分的迭代表达式**（K-F12）。与此不同，`break` 会直接结束循环，**不再执行**迭代表达式（K-F13）。而 `return` 则更为彻底，它结束整个函数的执行，连循环的更新步骤都不会进行（K-F14）。在嵌套结构中，如 `for` 内部包含 `switch`，`break` 只结束最内层的 `switch`，随后继续执行 `switch` 之后的循环体代码（K-F15）；但此时若使用 `continue`，其目标是 `for` 循环，它会跳过 `switch` 及其后的代码，直接去执行 `for` 的更新部分（K-F16）。

知识依据：K-F12 continue 的执行逻辑；K-F13 break 退出机制；K-F14 return 结束机制；K-F15 switch 内 break 的作用域；K-F16 switch 内 continue 的目标。

### continue 跳过剩余代码

**例题 E-F03：continue 的执行逻辑**

```c
int i=2,h=0;for(;i<3;i++){continue;h++;}printf("%d %d",i,h);
```

标准输出（核验记录）：

```text
3 0
```

此处 `for` 循环初始 `i=2`。入体后直接执行 `continue`，这会跳过 `h++`，直接执行 `i++` 使 `i` 变为 3。随后判断 `i<3`（3<3）为假，退出。最终 `h` 保持为 0（K-F12）。

知识依据：K-F12 continue 的执行逻辑。

### break 直接结束

**例题 E-F04：break 退出机制**

```c
int i=2,h=0;for(;i<3;i++){break;h++;}printf("%d %d",i,h);
```

标准输出（核验记录）：

```text
2 0
```

与 `continue` 不同，`for(;i<3;i++){break;}` 在第一次入体后执行 `break`。程序完全跳出循环，不再执行 `i++`。因此 `i` 仍为 2，`h` 为 0（K-F13）。

知识依据：K-F13 break 退出机制。

### 辨析 continue 与 break 的路径

- 错误信念 A：误以为continue等同于break，遇到后直接退出整个for，不再更新。
- 错误信念 B：误以为continue只跳过本轮剩余循环体和第三部分更新，直接回到条件判断。

**共同表现题**

```c
int i=0, hits=0;
for(;i<6;i++) {
 hits++;
 if(i==3) {i=6; continue;}
}
printf("%d %d\n",i,hits);
```

正确输出：`7 4`；按错误信念 A 预测：`6 4`；按 B 预测：`6 4`。

**区分题**

```c
int i=0, hits=0;
for(;i<6;i++) {
 hits++;
 if(i==3) {i=4; continue;}
}
printf("%d %d\n",i,hits);
```

正确输出：`6 5`；按错误信念 A 预测：`4 4`；按 B 预测：`6 6`。

**变式复测**

```c
int i=0, hits=0;
for(;i<7;i++) {
 hits++;
 if(i==3) {i=7; continue;}
}
printf("%d %d\n",i,hits);
```

正确输出：`8 4`；按错误信念 A 预测：`7 4`；按 B 预测：`7 4`。

针对 A：continue不会结束整个循环；用执行轨迹确认它仍会执行for第三部分，随后判断条件。

针对 B：把for更新位置显式画在continue之后：只有break退出该for才跳过该次更新。

上述错误预测是固定假设的模拟；一次作答不能直接确认学生真实错因。

初学者常混淆 `continue` 和 `break`。在本题的三组程序中，关键观察点是 `continue` 触发后是否执行了 `i++`。如果认为 `continue` 等同于 `break`（假设A），会错误地认为循环直接结束，忽略 `i` 的递增。如果认为 `continue` 跳过更新（假设B），则会忽略迭代表达式的作用。实际上，`continue` 会强制执行迭代步骤。通过观察最终 `i` 的值（如 7 而非 6），可以验证迭代表达式确实被执行了（K-F12, K-F13）。

知识依据：K-F12 continue 的执行逻辑；K-F13 break 退出机制；K-F19 循环体修改变量。

## 变量作用域与终止边界

### 作用域与极端边界

在 `for` 头部声明的变量（如 `int i`）其**作用域**（scope）仅限于该循环，外部不可见（K-F17）。若声明在外部，循环结束后变量会保留最后一次迭代的值（K-F18）。循环体内部的修改（如 `i+=2`）会直接影响下一次迭代的更新与判断结果（K-F19）。在极端边界下，无符号类型（unsigned int）由于其非负特性，`i>=0` 恒为真，无法通过递减来退出，其越界行为遵循**无符号回绕**（wrap）规则，即回绕到最大值（K-F20）。相反，有符号整数若从 `INT_MAX-1` 递增至 `INT_MAX`，下一轮迭代的 `i++` 将导致**有符号整数溢出**（overflow），这在 C17 中属于未定义行为（K-F21）。

知识依据：K-F17 头部声明的作用域；K-F18 外部变量最终值；K-F19 循环体修改变量；K-F20 无符号变量倒序终止失败；K-F21 有符号最大值后的迭代溢出。

### 循环体内的多重修改

**例题 E-F06：循环体修改变量**

```c
for(int i=0;i<5;i++){printf("%d ",i);i+=2;}
```

标准输出（核验记录）：

```text
0 3
```

输出末尾含空白；精确输出字符串：`"0 3 "`。

在第一轮中 `i=0`，入体后打印 0，随后 `i+=2` 变为 2。执行头部 `i++` 后 `i=3`。第二轮 `i=3`，打印 3，`i+=2` 变为 5。头部 `i++` 使 `i=6`。判断 `6<5` 为假，退出。这种循环体与头部的协同修改会改变循环的步长（K-F19）。

知识依据：K-F19 循环体修改变量。

### 自测 6 · Q-F21

for(int i = INT_MAX - 1; i <= INT_MAX; i++) { } 循环中，当 i 等于 INT_MAX 且循环体执行完毕后，执行 i++ 会发生什么？

适用条件：变量类型为 signed int；当前值为 INT_MAX；头部迭代表达式包含 i++；执行第三部分i++之前，i仍等于INT_MAX；循环体没有把它改为其他值。

### 参考解答

1. 未被修改，`i` 仍为 `10`。 当控制条件在首次评估时即为假（10 > 100 为假），循环体将不被执行，因此变量不会被修改。

2. 6次。 for 循环每次进入循环体前都会检查一次条件，执行完 5 次循环体后，会第 6 次检查条件（i=5 时为假）并退出，因此共 5+1=6 次。

3. 1 省略的控制表达式视为真（1），循环进入一次，执行 break 退出。

4. 1 for语句后紧跟的第一条语句是x++，因此它是for的循环体。y++位于for语句之后，是独立语句，只执行一次。

5. 不能 `for` 循环头部声明的变量 `i` 的作用域仅限于该循环内部，在循环结束后其生命周期结束，因此在外部的 `printf` 语句中访问 `i` 是非法的。

6. 发生有符号整数溢出，产生未定义行为。 当 i 达到 INT_MAX 时，循环体正常结束，随后执行 for 头部的 i++。i++ 会将 INT_MAX 增加 1，这超出了 signed int 的最大值，根据 C 标准属于未定义行为。
