## 字面量类型确定与整数提升

在C17中，当我们写下一个数字而没有给出类型后缀时，编译器会根据规范确定其默认类型。首先看整数字面量。若一个十进制整数字面量的数值可以被int类型完全容纳，且该字面量没有后缀，其类型默认就是int。例如数字123，由于它远小于int的最大值，编译器将其视为int类型。这种机制简化了编程，避免了为小数字频繁指定类型。但如果数字带有U后缀，比如1U，则其类型被明确规定为unsigned int。这表明U后缀不仅改变了数值范围，也强制改变了类型。

接着看浮点字面量。如果没有f或l后缀，像3.14这样的十进制浮点数的默认类型是double，而不是float。C语言的设计者认为double具有更高的有效精度，因此将其设为默认。

当我们在表达式中操作不同类型的整数时，C语言会执行整数提升。其基本规则是：如果一个整数类型的值可以完全由int表示，它会被提升为int；如果原类型的最大值超过了int的范围（例如在某些平台上unsigned short可能超出int范围），则被提升为unsigned int。这确保了在算术运算中，较小的整数有足够精度参与计算。

## 算术转换与运算顺序

当不同类型的操作数参与运算时，它们会经过通常算术转换。若一个操作数是int，另一个是double，根据规则，int值会被转换为double，运算在double精度下进行。若操作数分别为int与unsigned int，且它们的转换秩相同，int值会被转换为unsigned int。这意味着如果比较(int)-1与(unsigned int)1，-1会被转换为一个极大的unsigned int值，导致比较结果可能不符合直觉。

运算的类型在求值前确定，不会因为赋值的接收类型而改变。例如，在语句double x = 5 / 2;中，右侧的5和2都是int，除法会执行整数除法，得到结果2。之后这个int值2被转换为double存入x，x的值是2.0，而不是2.5。这种先计算后转换的特性在显式类型转换中表现得尤为关键。(double)5 / 2会先将5转为double，执行浮点除法得到2.5；而(double)(5 / 2)则是先执行整数除法得到2，再转换为double得到2.0。

此外，显式转换不会改变原变量的类型。如果执行double tmp = (double)n;，变量n在内存中的类型依然是int，值也保持不变。转换仅作用于表达式产生的临时值。

## 转换的边界与未定义行为

当类型转换超出目标范围时，必须了解其后果。对于整数到无符号类型的转换，遵循模转换规则：结果与原值对目标类型的范围取模。例如，将整数-1转换为unsigned int，结果是该类型的最大值UINT_MAX，无论其底层位宽是多少。这一行为是标准确定的。

然而，将超出范围的整数转换为有符号类型则是实现定义行为。C语言不保证这种转换会导致截断或其他特定值，不同编译器可能有不同表现。因此，依赖这种转换的行为是不安全的。

对于浮点转整数，若浮点值是有限的，转换会执行向零截断。例如，(int)3.999f会得到3，而不是4。但如果截断后的整数部分超出了目标类型的表示范围（例如(unsigned int)-1.5，截断后是-1，但unsigned int不能表示负数），该行为是未定义行为。程序可能崩溃或产生任意结果。

## 有效精度与数值损失

将整数转换为浮点类型（如double）时，即使整数的值在浮点的数值表示范围内，也不能保证转换后的值在数学上精确等于原整数。浮点类型存储的是有限个有效数字（有效精度）。如果整数包含的有效数字超过了浮点类型能提供的位数，多余的低位会被舍入或截断，导致精度损失。例如，一个巨大的整数可能超出了double的有效精度范围，即使double的指数范围足以容纳它，转换后的double值可能是一个近似值，而非精确值。

### 参考解答

1. double int 和 double 参与运算时，int 操作数转换为 double，因此共同类型为 double。

2. x 存储 3.0；计算结果类型是 int，值是 3。 目标类型 double 不会反向改变右侧子表达式 `7 / 2` 的运算类型，它先按整数除法得到 int 值 3，然后转换为 double 3.0。

3. 不必，结果总是UINT_MAX。 整数转为无符号时，结果与原值模目标最大值加一同余。对-1而言，同余值恒为目标类型的最大可表示值。

4. 行为未定义。因为向零截断后的-1超出了 unsigned int 的取值范围，属于浮点越界。 该题直接测试有限浮点转无符号整数时的截断越界规则，而非整数取模规则。

5. 不一定。在数值范围内的整数也可能因浮点精度限制而丢失部分有效数字。 直接测试整数到浮点转换中“范围内不保证精确”的核心命题。
