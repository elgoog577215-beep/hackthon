### 具体错因与区分预测（未验证）

**A · 整数提升统一为 int 规则**

所有在 C17 中参与算术的窄整数类型（如 unsigned short, char）在混合运算前一律提升为 int，忽略无符号类型的存在

表现：将 `unsigned short + 1` 的结果推导为 int，或者在混合 `unsigned short` 和 `int` 时错误认为两者统一变成了 `int`

- `Q-T04`：int；理由：应用统一提升规则，认为 unsigned short 作为窄整数必须变为 int 才能参与运算
- `Q-T05`：double；理由：此错误规则不适用于 float/double 混合，int 转 double 是通用规则，结果一致
- `Q-T06`：int；理由：应用统一规则认为无符号整数比较需转为带符号，但此题是 int 与 unsigned int，该规则通常导致错误地将 unsigned int 转为 int

补救（待修订）：

- 画出 unsigned short 和 int 的值域范围图，标出重叠部分
- 写出 `unsigned short` 的最大值和 `int` 的最大值，比较大小
- 查阅标准规则：若 int 不能表示原类型全部值，则转为同宽度的 unsigned

**B · 算术运算遵循最窄操作数类型**

算术运算的结果类型由操作数中转换秩最小的那个类型决定，或者认为负数必须用带符号类型保留

表现：在 `10 / 2.0` 中认为结果是 int 然后转 double；在 `int < unsigned` 中认为 unsigned 转为 int 以保留负数

- `Q-T04`：int；理由：认为 unsigned short 和 int 相比，int 秩高但为了保留数值精度，可能错误地统一推导为 int（或无预测，视是否认为 unsigned 必须转 int）
- `Q-T05`：int；理由：应用最窄类型规则，int 秩低于 double，认为运算先在 int 下进行
- `Q-T06`：int；理由：应用最窄/带符号优先规则，认为 unsigned int 应转换为 int 以保留 -1

补救（待修订）：

- 重写混合运算规则：通常算术转换是向秩高的（double 或 unsigned int）转换
- 对于 `10 / 2.0`，强制将 10 写为 10.0 再计算，观察类型
- 对于负数比较，手动将 -1 转换为 unsigned int 的位模式，计算其无符号值

**C · 负数无符号转换溢出截断**

当负数 int 转换为 unsigned int 时，认为值溢出为 0 或保持为负数，而不是遵循标准的位模式保留（补码转无符号）

表现：认为 -1 转换为 unsigned int 后是 0，或者认为编译器会报错，或者认为结果是负数

- `Q-T04`：unsigned int；理由：此题无负数，无预测，正确应用规则得到 unsigned int
- `Q-T05`：double；理由：此题无无符号负数，无预测，正确应用规则得到 double
- `Q-T06`：0 或 Error；理由：应用溢出截断规则，认为 -1 转无符号时高位被截断为 0 或导致未定义行为

补救（待修订）：

- 在纸上画出 int -1 的 32 位二进制补码表示
- 将这些位原样复制到 unsigned int 的值域中
- 查阅标准附录或工具，计算该位模式对应的无符号整数值 (UINT_MAX)

### 具体错因与区分预测（未验证）

**A · C型取整与接收类型反向传递**

C语言中整数除法的截断规则等同于C99/C11的C99 floor/截断规则（向负无穷取整）；左侧接收目标变量的类型会自动传递到右侧所有子表达式中，改变其计算类型

表现：负数除法得出向下取整的偏小值；在混合类型赋值时，直接写出浮点除法结果，跳过了整数中间截断

- `Q-T07`：-4；理由：将-7/2的实数商-3.5应用向负无穷取整的规则，得到-4
- `Q-T08`：x存储3.5；计算结果类型是double，值3.5。；理由：认为接收类型double让7和2自动变成了浮点数，从而执行浮点除法得到3.5
- `Q-T09`：两个结果都是2.5。；理由：认为只要出现(double)转换，整个表达式的所有数字都按浮点数计算，导致(5/2)的截断失效
- `Q-T10`：类型是double，存储值仍是10。；理由：认为对n进行显式转换操作本身，就会把n在内存中存储的类型改变为double

**B · 转换优先级与操作数范围误解**

显式类型转换运算符的优先级高于算术运算符，会将其作用范围内的所有数字同时转换为指定类型；转换作用于表达式求值完成后的最终结果

表现：对包含转换和除法组合的表达式，未能识别出转换只改变一个特定数字的类型，导致计算顺序错误

- `Q-T07`：无预测；理由：该题没有显式类型转换，仅涉及纯整数除法，学生无法应用关于转换优先级的错误规则
- `Q-T08`：无预测；理由：该题考察隐式赋值转换，学生若未将隐式接收视为显式转换，则不触发该错误信念
- `Q-T09`：第一个是2.5，第二个是2.5。；理由：错误地认为第二个表达式中的(double)转换也改变了5和2的类型，因此先转换再除法，导致第二个也是2.5
- `Q-T10`：类型是int，存储值是10。；理由：该题的转换发生在读取后，学生可能意识到转换不改变原变量，或者该错误规则在此题没有足够信息去推导错误答案

**C · 转换具有修改变量的副作用**

对变量执行显式类型转换(即读取变量并改变其类型表达)是一种带有副作用的操作，它会永久改变该变量在内存中的存储类型或存储数值

表现：在后续代码追踪中，把只被读取和转换过的变量的声明类型或值当作已被修改，导致后续逻辑错误

- `Q-T07`：无预测；理由：该题没有涉及对变量的读取和转换，不涉及变量状态是否改变的问题
- `Q-T08`：无预测；理由：虽然7和2是变量，但没有对它们进行显式转换，仅发生了计算，不触发转换产生副作用的错误规则
- `Q-T09`：无预测；理由：该题中的操作数是字面量5和2，并非已声明的变量，变量修改副作用的规则不适用
- `Q-T10`：类型是double，存储值是10.0。；理由：认为(double)n这个动作把变量n的类型变成了double，因此读取n时其声明类型就是double

### 迁移复测（模型调用前冻结）

### 迁移复测（模型调用前冻结）

for 体包含 switch，switch 后还有语句 S，最内层循环就是该 for。switch 分支中分别执行 break 与 continue 时，S 和 for 的迭代表达式是否会执行？设第三部分非空，S 无跳转且正常结束。

### 具体错因与区分预测（未验证）

**A · 无符号下界假死结**

认为 unsigned 类型的数值在递减到 0 时，下一次递减会让比较条件 i>=0 变为假，从而安全跳出循环。

表现：学生在分析 unsigned 倒序循环时，错误地画出了 'i=-1' 或类似状态，并在图中判定此时条件为假从而退出。

- `Q-F21`：无预测；理由：该错误仅针对无符号下界，不影响对有符号上界的判断。

- 检查证据：指出当 u=0 执行 u-- 时，u 的下一个值是什么，它大于 0 吗？

**B · 有符号回绕幻觉**

认为 signed int 在超过 INT_MAX 后，会像 unsigned 一样在底层内存中发生二进制回绕，变成 INT_MIN 然后正常循环。

表现：学生在分析有符号上界溢出时，未提到'未定义行为'，而是给出一个确定的负数结果，并认为程序会继续运行。

- `Q-F20`：无预测；理由：该错误仅针对有符号上界，不影响无符号行为的分析。

补救（待修订）：

- 查阅 C 标准中关于 signed integer overflow 的条款，抄写相关描述。
- 对比 unsigned 和 signed 的边界行为：unsigned 有定义，signed 无定义。
- 检查证据：写出一个代码片段，解释为什么不能在代码中依赖 signed 溢出的结果。

**C · for 头部执行顺序错位**

错误认为 for 循环在每次迭代时，先执行头部递增(如 i++)，然后再判断终止条件；或者认为当变量达到 INT_MAX 时，程序会在递增前就停止。

- `Q-F21`：当 i 到达 INT_MAX 时，由于已经满足了条件，程序会在执行 i++ 之前直接结束循环。；理由：误以为 i=INT_MAX 时循环就'完成'了，忽略了 for 语法中 i++ 会在下一次判断条件前强制执行。

### 迁移复测（模型调用前冻结）
