## 一次 for 循环怎样推进

### 循环的推进机制

每次从入口正常进入for时，非空的初始化子句执行一次。它不会在同一次for运行的每一轮都重新执行；若以后再次从入口执行这条for语句，那是另一次进入。控制表达式负责决定是否进入循环体：每次入体前求值非空控制表达式，结果非零才入体。第一次判断就为假时，循环体执行零次。

一次循环体正常完成后，先执行非空的迭代表达式，再回到控制表达式进行判断。这里的正常路径不包括break或return等提前转移；continue的路径随后单独说明。若完整执行了n次循环体，没有提前控制转移，并最终因条件为假退出，非空控制表达式共判断n+1次。多出的最后一次是假值检查，而不是又执行了一次循环体；不能把这个计数直接套到提前break的路径。

知识依据：K-F01 初始化子句执行频次；K-F02 每次入体前判断条件；K-F03 首判为假与零次执行；K-F04 体后更新顺序；K-F05 正常退出时的条件判断次数。

### 首判为假

**例题 E-F01：首判为假与零次执行**

```c
int i;for(i=10;i>100;i++){i=-1;}printf("%d",i);
```

标准输出（核验记录）：

```text
10
```

在以下代码中，循环初始状态为 `i=10`，控制条件是 `i>100`。由于 10 不大于 100，控制条件在首次评估时即为假（K-F03）。根据“先判断再入体”的规则，程序直接跳过了循环体，因此 `i` 始终保持为 10，未被循环内部的 `i=-1` 修改。

知识依据：K-F03 首判为假与零次执行。

### 更新顺序分析

**例题 E-F02：体后更新顺序**

```c
int i=0;for(i=0;i<2;i++){i+=10;}printf("%d",i);
```

标准输出（核验记录）：

```text
11
```

观察这段代码，第一轮时 `i=0` 入体，执行 `i+=10` 后 `i` 变为 10。由于循环体正常结束，程序接着执行头部迭代表达式 `i++`，此时 `i` 变为 11。接着判断 `i<2`（即 11<2）为假，循环退出。这印证了更新步骤发生在循环体正常完成之后、下一次判断之前（K-F04）。

知识依据：K-F04 体后更新顺序。

## 头部省略与循环体范围

### 语法细节与省略规则

for头部的初始化子句、控制表达式、迭代表达式都可以省略，但分隔三部分的两个分号必须保留。省略初始化时，循环从已有合法状态开始；因此用到的变量必须已经正确初始化，不能把“没有初始化子句”误当成变量自动变为零。

省略控制表达式时按非零常量处理，这只是说它不会因该条件变假而退出；循环体中的break或return仍可能结束相应执行。省略迭代表达式只表示该处没有更新操作，不会自动补出i++，状态仍可在循环体等位置改变。

循环体在语法上是一条语句，复合语句可包含多条语句。for(...);中的分号是一条空语句，因而成为循环体；它后面的独立语句或块不属于这个循环体。单语句、复合语句和空语句的区别，与排版行数无关。

知识依据：K-F06 省略初始化使用已有状态；K-F07 省略条件视为真；K-F08 省略迭代不自动更新；K-F09 for头部保留两个分号；K-F10 for 的单语句体；K-F11 for 的空语句体。

### 空语句陷阱

**例题 E-F08：for 的空语句体**

```c
int i,x=0;for(i=0;i<3;i++);x++;printf("%d",x);
```

标准输出（核验记录）：

```text
1
```

这段代码展示了 `for(i=0;i<3;i++);` 的微妙之处。分号构成了一个**空语句**，这意味着循环体没有任何操作。当 `i` 从 0 增加到 3 循环结束后，程序才执行下一个独立语句 `x++`。因此 `x` 只被加 1，结果为 1（K-F11）。如果去掉分号，`x++` 则会作为循环体重复三次。

知识依据：K-F11 for 的空语句体。

## continue、break、return 与嵌套目标

### 控制流转移的目标

当最内层包围continue的循环是所述for时，continue跳过本轮剩余循环体，转到该for的推进位置，执行非空的迭代表达式，再判断条件；若第三部分省略，则没有该处更新可执行。break结束的是最内层包围它的循环或switch。如果实际被退出的是这个for，该次第三部分不会再执行。return则结束当前函数，不只是结束某一层循环；本讲运行片段位于void函数中，所以使用return;。

对于直接位于for体内switch中的break，若没有更内层循环或switch包围它，它只结束该switch，随后继续执行switch之后尚余的循环体语句，不能直接跳过这些语句去更新。switch本身不是continue的目标：当没有更内层循环时，switch中的continue仍转到所述for的推进位置。判断目标应看实际包围结构，不是找最近的花括号。

知识依据：K-F12 continue 的执行逻辑；K-F13 break 退出机制；K-F14 return 结束机制；K-F15 switch 内 break 的作用域；K-F16 switch 内 continue 的目标。

### continue 跳过剩余代码

**例题 E-F03：continue 的执行逻辑**

```c
int i=2,h=0;for(;i<3;i++){continue;h++;}printf("%d %d",i,h);
```

标准输出（核验记录）：

```text
3 0
```

此处 `for` 循环初始 `i=2`。入体后直接执行 `continue`，这会跳过 `h++`，直接执行 `i++` 使 `i` 变为 3。随后判断 `i<3`（3<3）为假，退出。最终 `h` 保持为 0（K-F12）。

知识依据：K-F12 continue 的执行逻辑。

### break 直接结束

**例题 E-F04：break 退出机制**

```c
int i=2,h=0;for(;i<3;i++){break;h++;}printf("%d %d",i,h);
```

标准输出（核验记录）：

```text
2 0
```

与 `continue` 不同，`for(;i<3;i++){break;}` 在第一次入体后执行 `break`。程序完全跳出循环，不再执行 `i++`。因此 `i` 仍为 2，`h` 为 0（K-F13）。

知识依据：K-F13 break 退出机制。

### return结束的是当前函数

**例题 E-F05：return 结束机制**

```c
for(int i=0;i<3;i++,puts("update")){if(i==1)return;}puts("after");
```

标准输出（核验记录）：

```text
update
```

例题把输出update作为第三部分执行的观察标记。i=0时正常完成循环体，更新后打印一次update；i=1时执行return，sample函数立即结束，因此没有第二次update，也不会执行循环后的after。这个结果只用于说明该void函数片段的控制流，不能把return理解成只退出当前for。

知识依据：K-F14 return 结束机制。

### 退出switch后仍执行循环体余下语句

**例题 E-F07：switch 内 break 的作用域**

```c
for(int i=0;i<2;i++){switch(i){case 0:break;default:break;}printf("A");}
```

标准输出（核验记录）：

```text
AA
```

两个case路径中的break都只结束当前switch。每一轮仍会继续执行其后的printf("A")，所以两轮共输出AA。若把break错误地理解成退出外层for，或者把switch后的语句直接跳过，就无法解释这个输出。

知识依据：K-F15 switch 内 break 的作用域。

### 辨析 continue 与 break 的路径

- 错误信念 A：误以为continue等同于break，遇到后直接退出整个for，不再更新。
- 错误信念 B：误以为continue只跳过本轮剩余循环体和第三部分更新，直接回到条件判断。

**共同表现题**

```c
int i=0, hits=0;
for(;i<6;i++) {
 hits++;
 if(i==3) {i=6; continue;}
}
printf("%d %d\n",i,hits);
```

正确输出：`7 4`；按错误信念 A 预测：`6 4`；按 B 预测：`6 4`。

**区分题**

```c
int i=0, hits=0;
for(;i<6;i++) {
 hits++;
 if(i==3) {i=4; continue;}
}
printf("%d %d\n",i,hits);
```

正确输出：`6 5`；按错误信念 A 预测：`4 4`；按 B 预测：`6 6`。

**变式复测**

```c
int i=0, hits=0;
for(;i<7;i++) {
 hits++;
 if(i==3) {i=7; continue;}
}
printf("%d %d\n",i,hits);
```

正确输出：`8 4`；按错误信念 A 预测：`7 4`；按 B 预测：`7 4`。

针对 A：continue不会结束整个循环；用执行轨迹确认它仍会执行for第三部分，随后判断条件。

针对 B：把for更新位置显式画在continue之后：只有break退出该for才跳过该次更新。

上述错误预测是固定假设的模拟；一次作答不能直接确认学生真实错因。

共同表现题在i=3时先令i=6，再执行continue。正确路径还执行一次i++，所以最终输出i=7、hits=4；A把continue当break，B跳过更新直接判断，两者都会得到i=6、hits=4。仅凭这个共同错答无法区分A与B。

区分题把触发时的赋值改成i=4。正确路径更新到5后还入体一次，得到6 5；A在赋值后直接退出，得到4 4；B跳过这次更新，于是会多执行i=4这一轮，最后得到6 6。两种错误信念在第二题中的差别，同时体现在退出位置或入体次数上。复测再改变上界，正确值为8 4，A/B均预测7 4。这里的程序特意让三种路径都能终止，不用无界运行去猜错误原因。

知识依据：K-F12 continue 的执行逻辑；K-F13 break 退出机制；K-F19 循环体修改变量。

### 综合应用：内层转移后外层从哪里继续

在外层for中嵌套内层for，且没有更内层循环或switch改变目标时，内层continue只推进该内层for：跳过内层本轮余下语句，执行它的第三部分，再检查它的条件。内层break则结束内层for，从内层for之后的语句继续执行外层循环体。它们都不会自动跳到外层for的更新位置，也不会自动结束外层for。

完成一次分析可以依次标出：当前所在的最内层循环或switch，实际跳转的目标，目标之后仍会执行的语句，以及何时才轮到外层更新。若有return，才会按函数边界离开。这是一道组合应用，应引用continue和break等原子规则共同求解，而不是把整段复杂流程再当成一个不可拆的元知识。

知识依据：K-F12 continue 的执行逻辑；K-F13 break 退出机制；K-F14 return 结束机制。

## 变量作用域与终止边界

### 作用域与极端边界

for头部声明的变量，其名字作用域限定在相应for语句范围内，结束后不能在外部继续访问这个头部局部变量。若外层恰有另一个同名变量，之后读到的是外层对象，不能据此声称头部变量仍然可见。作用域讨论的是名字在哪里有效，不是简单地看两个变量是否拼写相同。

变量若声明在循环外，且程序行为有定义，循环结束后保留的是实际退出路径上的当前值。不要把它笼统叫作“最后一次入体值”。例如前面的continue例题最终i为3，而break例题最终i为2：初值相同，但是否执行更新不同，退出状态就不同。循环体本身对变量的合法修改，也要一起纳入后续更新和判断。

unsigned int的i>=0恒为真，不能只靠这个判断让倒序递减循环退出。从无符号零继续减一会按模回绕到最大值，回绕本身有定义；不代表所有无符号更新都回到最大值，也不代表i!=0等其他判断无效。显式break或return仍可改变退出路径。

有符号边界要检查真正执行更新之前的值：若int类型的i此时仍等于INT_MAX，循环体没有将它改小，也没有提前跳出，继续执行i++会发生有符号整数溢出，属于未定义行为。如果循环体改变了i，或通过break/return使这次更新不再发生，就不能直接断言发生了同一溢出。此类边界只作静态判断，不运行未定义行为来推断规范。

知识依据：K-F17 头部声明的作用域；K-F18 外部变量最终值；K-F19 循环体修改变量；K-F20 无符号变量倒序终止失败；K-F21 有符号最大值后的迭代溢出。

### 循环体内的多重修改

**例题 E-F06：循环体修改变量**

```c
for(int i=0;i<5;i++){printf("%d ",i);i+=2;}
```

标准输出（核验记录）：

```text
0 3
```

输出末尾含空白；精确输出字符串：`"0 3 "`。

在第一轮中 `i=0`，入体后打印 0，随后 `i+=2` 变为 2。执行头部 `i++` 后 `i=3`。第二轮 `i=3`，打印 3，`i+=2` 变为 5。头部 `i++` 使 `i=6`。判断 `6<5` 为假，退出。这种循环体与头部的协同修改会改变循环的步长（K-F19）。

知识依据：K-F19 循环体修改变量。

### 沿真实控制流逐步核对

分析for时，先写清初始化、每次体前判断、循环体和更新的顺序，再检查是否有空语句或省略部分。正常退出的n+1次判断公式有明确前提，不能代替对break、continue、return的逐步追踪。

遇到嵌套结构，先确定每条跳转实际作用的最内层目标，再继续追踪余下语句；遇到循环外的变量值，要按实际退出路径记录状态。最后检查数值与作用域边界：变量是否仍可见，循环体是否也修改控制变量，无符号判断能否终止，以及执行有符号更新前是否已处于不能再递增的值。

知识依据：K-F01 初始化子句执行频次；K-F02 每次入体前判断条件；K-F03 首判为假与零次执行；K-F04 体后更新顺序；K-F05 正常退出时的条件判断次数；K-F06 省略初始化使用已有状态；K-F07 省略条件视为真；K-F08 省略迭代不自动更新；K-F09 for头部保留两个分号；K-F10 for 的单语句体；K-F11 for 的空语句体；K-F12 continue 的执行逻辑；K-F13 break 退出机制；K-F14 return 结束机制；K-F15 switch 内 break 的作用域；K-F16 switch 内 continue 的目标；K-F17 头部声明的作用域；K-F18 外部变量最终值；K-F19 循环体修改变量；K-F20 无符号变量倒序终止失败；K-F21 有符号最大值后的迭代溢出。

### 自测 6 · Q-F21

for(int i = INT_MAX - 1; i <= INT_MAX; i++) { } 循环中，当 i 等于 INT_MAX 且循环体执行完毕后，执行 i++ 会发生什么？

适用条件：变量类型为 signed int；当前值为 INT_MAX；头部迭代表达式包含 i++；执行第三部分i++之前，i仍等于INT_MAX；循环体没有把它改为其他值。

### 参考解答

1. 未被修改，`i` 仍为 `10`。 当控制条件在首次评估时即为假（10 > 100 为假），循环体将不被执行，因此变量不会被修改。

2. 6次。 for 循环每次进入循环体前都会检查一次条件，执行完 5 次循环体后，会第 6 次检查条件（i=5 时为假）并退出，因此共 5+1=6 次。

3. 1 省略的控制表达式视为真（1），循环进入一次，执行 break 退出。

4. 1 for语句后紧跟的第一条语句是x++，因此它是for的循环体。y++位于for语句之后，是独立语句，只执行一次。

5. 不能 `for` 循环头部声明的变量 `i` 的作用域仅限于该循环内部，在循环结束后其生命周期结束，因此在外部的 `printf` 语句中访问 `i` 是非法的。

6. 发生有符号整数溢出，产生未定义行为。 当 i 达到 INT_MAX 时，循环体正常结束，随后执行 for 头部的 i++。i++ 会将 INT_MAX 增加 1，这超出了 signed int 的最大值，根据 C 标准属于未定义行为。
