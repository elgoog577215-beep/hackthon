# 第1讲　数值类型转换

知识树驱动讲义修订稿。根据用户要求由 Codex 定向修订，初稿另存供对照；例题、诊断与自测答案继续使用同一知识基线。

本讲把数值类型转换分成四个问题：操作数的类型如何确定，转换在表达式的哪个位置发生，目标类型能否表示所得值，以及表示是否精确。先掌握这些判断顺序，再用例题和自测检验，避免只根据变量名字或某次运行结果猜答案。

本讲按 C17 讨论。代码示例为 `void sample(void)` 函数体内的片段，已包含 `<stdio.h>`、`<limits.h>` 等头文件，由 `main` 调用；出现 `return;` 表示结束该 `sample` 函数。

需要运行例题时，将一个例题片段放入下面模板的 `sample` 中，以 C17 编译 `.c` 文件。不同例题分别运行，不把各题片段连续粘在同一个函数里。

```c
#include <stdio.h>
#include <limits.h>

void sample(void) {
    /* 在此放入一个例题片段 */
}
int main(void) {
    sample();
    return 0;
}
```

本讲统一术语：整数字面量（可用别名：整数常量）；整数提升；通常算术转换；显式类型转换（可用别名：强制类型转换）；向零截断；无符号整数的模转换（可用别名：模转换）；实现定义；未定义行为（可用别名：UB）；数值范围；有效精度。

## 先确定表达式的类型

### 先识别字面量的类型

数值相同，不代表参与运算的类型相同。阅读一个表达式时，应先识别每个操作数的类型，再判断运算与结果转换。C17中，无后缀的十进制整数字面量在能由int表示时具有int类型；例如123符合这个条件。这里的“能表示”是必要条件，不能据此断言任意大的无后缀整数都使用int。

本课使用的1U具有unsigned int类型；我们只用这个可表示的小值，不把结论推广到所有带U后缀的大整数字面量。无后缀的浮点字面量，如3.14，则具有double类型。先把整数、无符号整数与实浮点操作数辨认清楚，后续才能选择相应的转换规则。字面量类型由语言规则决定，不需要猜测语言设计者的动机。

知识依据：K-T01 默认整型；K-T02 1U 的类型；K-T03 浮点默认。

### 整数提升看原类型的全部取值

整数提升适用于语言规定需要提升、且原类型满足提升条件的场合，例如相应的较窄整数参与整数算术运算。判断依据是原类型的全部可取值范围：若int可以表示这些值，提升结果为int；否则为unsigned int。不能只看这一次变量恰好存了一个小值，就据此选择提升类型。

因此，在已知int能够表示unsigned char全部值的环境中，两个unsigned char相加可以先在int中计算，不能直接当作按一个字节回绕。这条规则也不能简化为“任何不同类型的数运算前都先做整数提升”；浮点混合运算要按相应的通常算术转换规则判断。

知识依据：K-T04 整数提升规则。

### 两种限定的共同类型规则

通常算术转换用于确定相关算术操作的共同类型。本课先区分两种明确的情境：int与double运算时，int操作数转换为double，随后按double进行相应运算；int与unsigned int进行通常算术转换时，因为二者转换秩相同，int操作数转换为unsigned int。

后一条不能推广为“任意有符号类型遇到任意无符号类型，都变成无符号类型”。例如比较int值-1与unsigned int值1，应先应用这里的转换方向，再按整数转无符号的规则确定转换值；不能直接套用负数一定小于正数的直觉。转换方向与转换后的具体数值，是推导中的两个步骤。

知识依据：K-T05 int 与 double 的共同类型；K-T06 int与unsigned int的通常算术转换方向。

## 先计算再转换

### 整数商向零截断

在运算有定义的前提下，整数除法得到整数商，丢弃小数部分时朝零截断。正数商和负数商都遵守这条规则；向零截断不等于总是向下取整。分析负数例子时，先想清楚数学商位于哪两个整数之间，再选择靠近零的整数。以下只讨论有定义的运算，不对除零等情形预测正常数值结果。

知识依据：K-T07 整数除法截断。

### 用负数区分截断方向

**例题 E-T01：整数除法截断**

```c
printf("%d",-7/2);
```

标准输出（核验记录）：

```text
-3
```

例题计算-7/2。数学商是-3.5，向零截断后为-3，所以程序打印-3。若误用向下取整会得到-4；两者在正数例子中可能看不出区别，因此这里特意观察负数商。

知识依据：K-T07 整数除法截断。

### 接收类型不会反向改变右侧运算

普通标量初始化或简单赋值，把右侧表达式已经求出的值转换为目标类型。左侧变量是double，并不会让右侧原本的int除法自动变成浮点除法。写题时可以把过程分成“右侧按自己的操作数类型求值”和“把所得值转换并存入目标”两步。

这里说明的是值的转换与保存，不能进一步推断任意复杂赋值表达式的左右操作数总按“先右后左”的顺序求值。也不要把复合赋值和任意副作用表达式不加区分地套进这个简化说明。

知识依据：K-T08 接收类型不反向改变表达式。

### double接收的是已经算好的值

**例题 E-T02：接收类型不反向改变表达式**

```c
double x=7/2; printf("%.1f",x);
```

标准输出（核验记录）：

```text
3.0
```

代码中7和2都是int，所以7/2先得到整数3。随后该值转换为double，x保存3.0，按一位小数打印为3.0。正确判断必须先看右侧除法的操作数类型，不能从左侧double倒推右侧得到了3.5。

知识依据：K-T08 接收类型不反向改变表达式。

### 显式转换的位置与副作用边界

显式类型转换只作用于语法上指定的操作数。在(double)5/2中，显式转换先作用于5，随后与2进行浮点运算；在(double)(5/2)中，括号里的整数除法先完成，显式转换才作用于其结果。转换不能恢复此前已经丢掉的小数部分。

单独读取变量并转换所得值，不会改变原变量的声明类型或存储值。如果操作数自身还带有自增、赋值等副作用，需要另外分析这些操作；“转换本身不改原变量”不等于“任何带转换符的整个表达式都没有副作用”。

知识依据：K-T09 显式转换的位置；K-T10 转换表达式不改原变量。

### 对照转换发生在除法之前还是之后

**例题 E-T03：显式转换的位置**

```c
printf("%.1f %.1f",(double)5/2,(double)(5/2));
```

标准输出（核验记录）：

```text
2.5 2.0
```

第一项先将5转为double再相除，得到2.5；第二项先算5/2得到2，再转换成2.0。输出顺序正是2.5、2.0。先圈定转换的操作数，再判断除法类型，比只记“出现double就保留小数”可靠。

知识依据：K-T09 显式转换的位置。

### 转换结果与原变量分开

**例题 E-T04：转换表达式不改原变量**

```c
int n=10; double tmp=(double)n; printf("%d %d",_Generic(n,int:1,default:0),n);
```

标准输出（核验记录）：

```text
1 10
```

n先被声明为int并保存10。(double)n产生用于初始化tmp的double值，但n只被读取。代码中的_Generic是辅助类型检查：此处n的类型为int就选取1，否则选取0；本讲只借它观察类型，不要求掌握其完整语法。输出的第一个1表示n仍是int，后面的10是n的存储值。它们验证的是原变量未被这次转换改动，而不是说所有带副作用的操作数都不改变状态。

知识依据：K-T10 转换表达式不改原变量。

## 转换的边界

### 整数目标能否表示原值

整数转换到另一整数类型时，首先问目标类型能否表示原值。若能表示，数值保持不变，例如将100转换到能够表示100的short，结果仍为100。只有离开这个前提，才需要分别讨论无符号目标与有符号目标。

若源值是整数、目标是有符号整数，而原值不能由目标表示，C17规定结果由实现定义，或者引发实现定义的信号。不能一律说成固定截位，也不能与有符号算术溢出的未定义行为混为一谈。实现定义意味着实现必须说明其选择，不意味着不同实现都给同一个结果。

知识依据：K-T12 有符号越界；K-T13 可表示整数转换保持数值。

### 无符号整数的模转换

整数转换为非_Bool无符号整数类型时，可用“模目标最大值加一”描述结果：选择目标范围内、与原整数同余的值。模数不是含混的“范围”，更不能漏掉最大值后面的加一。由此可知，整数-1转为unsigned int会得到UINT_MAX，不需要先假定unsigned int恰好是32位。

这是整数到无符号整数的规则。不要把它拿去处理浮点转整数，也不要把无符号回绕与有符号溢出混为同一种行为。

知识依据：K-T11 模转换。

### 打印的是比较结果，不是UINT_MAX本身

**例题 E-T06：模转换**

```c
printf("%d",(unsigned int)-1==UINT_MAX);
```

标准输出（核验记录）：

```text
1
```

本例把整数-1转换为unsigned int，再与UINT_MAX比较。程序打印1，表示这个相等比较成立；它并没有直接打印UINT_MAX的十进制数值。因此，即使不同实现的unsigned int位数不同，这个比较结论也不依赖某一个具体位数。

知识依据：K-T11 模转换。

### 有限实浮点转整数：先截断，再看上下界

有限实浮点值转换为非_Bool整数类型时，先丢弃小数部分，方向仍是向零。随后必须检查截断后的整数部分能否由目标类型表示；若不能，行为未定义。这里比较的是目标实际上下界，不是把源值取绝对值后只比一个上限。

例如(unsigned int)-1.5的整数部分为-1，unsigned int不能表示它，因此不能套用整数-1的模转换规则来给出UINT_MAX。另一方面，判断越界也不能只凭“原浮点值为负”这一特征，关键仍是截断后的整数部分是否可表示。越界情形在本讲作静态判断，不通过运行某次结果来证明规范。

知识依据：K-T14 浮点截断；K-T15 浮点越界。

### 截断不是四舍五入

**例题 E-T05：浮点截断**

```c
printf("%d",(int)3.999f);
```

标准输出（核验记录）：

```text
3
```

本例只有一个转换：将有限浮点值3.999f转为int。整数部分3能够由int表示，所以向零截断后程序打印3，而不是四舍五入得到4。负值也遵循向零方向，但仍要检查截断后的整数部分是否可由目标类型表示；不能根据这个有定义的例子给越界转换指定正常输出。

知识依据：K-T14 浮点截断。

## 精度与易错辨析

### 数值范围足够，不代表精确表示

数值范围回答“大小是否容纳得下”，有效精度回答“相邻数值能否被区分”。整数转为实浮点时，即使整数处于目标浮点类型的数值范围内，也可能因为有效精度有限而无法精确表示。并非所有较大的整数都会丢失精度，仍要看该值能否由目标格式精确表示。

本讲不假定所有C实现的double都有相同有效精度或采用相同的舍入选择。因此，讨论某个具体整数转换后精确得到哪个邻近值时，还需给出实现和格式条件；不能把本机一次结果推广为无条件的语言规则。

知识依据：K-T16 整数到浮点。

### 同一个错答可能来自两种不同理解

- 错误信念 A：误以为两个int的除法也保留数学上的小数商。
- 错误信念 B：知道int除法会截断，但误以为左侧double接收变量会反向把右侧int除法变成浮点除法。

**共同表现题**

```c
double x=7/3; printf("%.2f\n",x);
```

正确输出：`2.00`；按错误信念 A 预测：`2.33`；按 B 预测：`2.33`。

**区分题**

```c
printf("%.2f\n",(double)(7/3));
```

正确输出：`2.00`；按错误信念 A 预测：`2.33`；按 B 预测：`2.00`。

**变式复测**

```c
printf("%.2f %.2f\n",(double)(11/4),(double)11/4);
```

正确输出：`2.00 2.75`；按错误信念 A 预测：`2.75 2.75`；按 B 预测：`2.00 2.75`。

针对 A：先判定运算操作数类型：两个int相除在有定义时得到向零截断的整数商；需要小数时先转换一个操作数。

针对 B：区分右侧表达式求值与接收转换：左侧double只转换已经算出的值，不会恢复已丢弃的小数。

上述错误预测是固定假设的模拟；一次作答不能直接确认学生真实错因。

共同表现题把7/3的结果存入double后打印。正确结果是2.00，但A、B两种错误信念都会预测2.33，所以仅凭第一题不能区分它们。区分题去掉double接收变量，只在除法结束后显式转换结果：A仍把int除法误当作保留小数，预测2.33；按B的既定信念，没有左侧double接收情境，因而会预测正确的2.00。

补救后再比较11/4在转换前后的位置差异，正确输出为2.00 2.75。复测改变数值并同时考查两个转换位置，防止只记住第一题的答案。这里的A/B是两种固定的错误模型；实际学习者还可能因为猜测、粗心或其他缺口给出同样结果，需要结合解释和更多证据判断。

知识依据：K-T07 整数除法截断；K-T08 接收类型不反向改变表达式；K-T09 显式转换的位置。

### 本讲的判断顺序

处理数值转换题，可以依次检查：字面量与变量是什么类型；该运算是否需要整数提升或通常算术转换；显式转换具体作用于哪个操作数；表达式求得的值再怎样转换到接收类型。遇到边界时，将“整数到整数”和“有限实浮点到整数”分开，并区分数值范围与有效精度。

始终保留适用条件：可表示的整数转换保持数值；整数转非_Bool无符号整数按目标最大值加一取模；整数转有符号且不能表示属于实现定义结果或信号；有限实浮点转非_Bool整数的整数部分不能表示则是未定义行为。规则相似不等于可以互换。

知识依据：K-T01 默认整型；K-T02 1U 的类型；K-T03 浮点默认；K-T04 整数提升规则；K-T05 int 与 double 的共同类型；K-T06 int与unsigned int的通常算术转换方向；K-T07 整数除法截断；K-T08 接收类型不反向改变表达式；K-T09 显式转换的位置；K-T10 转换表达式不改原变量；K-T11 模转换；K-T12 有符号越界；K-T13 可表示整数转换保持数值；K-T14 浮点截断；K-T15 浮点越界；K-T16 整数到浮点。

## 自测与参考解答

### 自测 1 · Q-T05

在执行表达式 `double d = 10 / 2.0;` 时，操作数 `10` 和 `2.0` 进行通常算术转换后的共同类型是什么？

适用条件：实数算术操作数分别为int和double；运算有定义；本点不描述其他有符号/无符号类型组合

### 自测 2 · Q-T08

执行语句 `double x = 7 / 2;` 后，变量 `x` 存储的数值是多少？右侧表达式 `7 / 2` 在转换为 double 之前的计算结果类型和值分别是什么？

适用条件：C17普通标量初始化或简单赋值；右侧表达式及转换有定义；不主张赋值左右操作数固定先右后左求值

### 自测 3 · Q-T11

把整数-1转换为unsigned int，是否必须假设unsigned int是32位才能确定结果？

适用条件：源值为整数；目标为非_Bool无符号整数类型；不用于浮点转整数

### 自测 4 · Q-T15

表达式 (unsigned int)-1.5 的行为是确定的吗？如果是，其计算结果是什么？如果不是，请说明原因。

适用条件：源值有限；目标为非_Bool整数类型；按目标实际上下界判断整数部分，不对其取绝对值

### 自测 5 · Q-T16

假设已知整数 X 处于 double 的数值表示范围内，那么表达式 (double)X 转换后的值在数学上是否一定精确等于 X？

适用条件：整数在目标浮点数值范围内；不假设所有C实现的double有效精度或舍入方式相同

### 参考解答

1. double int 和 double 参与运算时，int 操作数转换为 double，因此共同类型为 double。

2. x 存储 3.0；计算结果类型是 int，值是 3。 目标类型 double 不会反向改变右侧子表达式 `7 / 2` 的运算类型，它先按整数除法得到 int 值 3，然后转换为 double 3.0。

3. 不必，结果总是UINT_MAX。 整数转为无符号时，结果与原值模目标最大值加一同余。对-1而言，同余值恒为目标类型的最大可表示值。

4. 行为未定义。因为向零截断后的-1超出了 unsigned int 的取值范围，属于浮点越界。 该题直接测试有限浮点转无符号整数时的截断越界规则，而非整数取模规则。

5. 不一定。在数值范围内的整数也可能因浮点精度限制而丢失部分有效数字。 直接测试整数到浮点转换中“范围内不保证精确”的核心命题。
