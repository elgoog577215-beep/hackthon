# 第2讲　if 的语句范围与 else 配对

知识树驱动讲义修订稿。根据用户要求由 Codex 定向修订，初稿另存供对照；例题、诊断与自测答案继续使用同一知识基线。

本讲区分两个问题：语法决定一条语句属于哪个分支，运行时的条件求值决定该分支是否执行。我们依次讨论标量条件、分支体边界、else配对和独立判断，并通过同源例题观察变量状态。以下均讨论普通结构化控制流，不考虑通过goto或标签跳入分支。

本讲按 C17 讨论。代码示例为 `void sample(void)` 函数体内的片段，已包含 `<stdio.h>`、`<limits.h>` 等头文件，由 `main` 调用；出现 `return;` 表示结束该 `sample` 函数。

需要运行例题时，将一个例题片段放入下面模板的 `sample` 中，以 C17 编译 `.c` 文件。不同例题分别运行，不把各题片段连续粘在同一个函数里。

```c
#include <stdio.h>
#include <limits.h>

void sample(void) {
    /* 在此放入一个例题片段 */
}
int main(void) {
    sample();
    return 0;
}
```

本讲统一术语：标量表达式；分支体；复合语句（可用别名：语句块）；else 配对（可用别名：else归属）；空语句；if/else-if 选择链（可用别名：选择链）；独立 if（可用别名：独立if）。

## 条件、语句范围与一次分支选择

### 条件的真值与分支体范围

C17要求if的条件为标量表达式。本讲用整数和浮点数说明条件判断：与零比较不等为真，与零相等为假，因此非零负整数也为真；不需要“大于零”才能进入真分支。

语法上，if的每个分支体是一条语句。这条语句可以是简单赋值、复合语句，也可以是整个嵌套if。若希望在同一个分支中顺序执行多条语句，可使用花括号形成复合语句。这里计算的是语句，不是文本行数：一条语句能跨多行，一行也能写多条语句。缩进可以帮助阅读，却不能替代语法边界。

知识依据：K-I01 标量条件的真值语义；K-I03 分支体的语句范围。

### 示例：负数作为真值

**例题 E-I01：标量条件的真值语义**

```c
int n=-5;if(n)printf("T");else printf("F");
```

标准输出（核验记录）：

```text
T
```

执行if(n)时，程序根据当时n的值选择分支。n为-5，不等于零，因此进入真分支并输出T。这个例子只需要判断是否为零，不应将数值的正负号当成真假标准；这里描述的是程序执行语义，而不是要求编译器在编译时计算所有条件。

知识依据：K-I01 标量条件的真值语义。

### 一次执行只按当时条件选分支

一旦程序进入 `if` 的某个分支，它就不会在分支内部修改条件变量后，自动跳转到另一个分支。在普通顺序执行流中，分支决策是在进入该语句时进行的。如果在真分支体内，将原本为真的变量修改为 0，程序在结束该分支后会直接向下执行，不会回头去补执行 `else` 分支。这是控制流的一个关键特性：分支选择是单次的，且一旦执行完选定的分支体，该 `if` 语句的执行逻辑即告结束。

知识依据：K-I02 一次执行不重新选分支。

### 示例：修改条件不触发 else

**例题 E-I02：一次执行不重新选分支**

```c
int x=1,y=0;if(x){x=0;}else{y=1;}printf("%d",y);
```

标准输出（核验记录）：

```text
0
```

设有 `int x=1, y=0;`。执行 `if(x){x=0;}else{y=1;}`。由于 `x` 初始值为 1（真），程序进入真分支，执行 `x=0`。此时 `x` 已经改变，但由于分支已经选定，`else` 分支被跳过。最终 `y` 保持为 0。此例说明，分支内对变量的操作不会回溯改变已做的路径决策。

知识依据：K-I02 一次执行不重新选分支。

### 示例：分支体是一条语句

**例题 E-I03：分支体的语句范围**

```c
int a=0,x=0,y=0;if(a)x=1;y=2;printf("%d",y);
```

标准输出（核验记录）：

```text
2
```

设有int a=0, x=0, y=0，执行if(a) x=1; y=2;。本例的真分支体仅是赋值语句x=1。因为a为0，这条赋值不执行；y=2是整条if之后的独立语句，仍会执行，所以最终y为2。即使这两条赋值写在同一行，控制范围也不会扩大；应以完整语句的语法边界判断，而不是数行数。

知识依据：K-I03 分支体的语句范围。

## else 配对：语法、花括号与缩进

### 词法就近原则

else结合到语法允许的、词法上最近的前面那个if。“语法允许”不可省略：需要尊重语句的完整结构，不能只搜索文本中最后出现的if。对于if(a) if(b) x=1; else x=2;，else属于内层if(b)。外层if的真分支体是整个内层if/else语句。

先确定配对，再代入a、b的值分析路径。某个条件此时是真还是假，不会改变else在语法上归属于谁。这样可以避免根据希望执行的分支反过来猜配对。

知识依据：K-I04 else 的词法就近配对。

### 花括号对配对边界的约束

花括号（复合语句的边界）可以改变这种就近配对的逻辑。如果内层 `if` 被包裹在一个复合语句中，例如 `if(a){ if(b) x=1; }`，那么位于花括号闭合后的 `else` 无法跨越这个花括号边界去与内部最末的 `if(b)` 配对。此时，`else` 在语法上只能归属于外层 `if(a)`。这是因为 `else` 必须在语法允许的范围内寻找最近的 `if`，而复合语句的边界阻断了它与内部嵌套 `if` 的配对关系。

知识依据：K-I05 花括号显式修改 else 归属。

### 缩进与语法的解耦

只改变普通if/else代码的空白缩进，不改变词法记号、花括号、注释内容或语法结构，就不会改变else归属。将else视觉上对齐外层if，不能让原本配对内层if的else自动改属外层。

这个结论只针对上述缩进调整，不能扩写成“C程序中的所有空格和换行都无意义”。字符串、注释和预处理等场景也不能按这条排版规则随意改动。本讲分析配对时，以合法程序的记号和结构为依据。

知识依据：K-I06 缩进不改变语法归属。

### 用缩进变化区分两种错误信念

- 错误信念 A：误以为else与视觉上缩进同列的if配对，而不是由C语法决定。
- 错误信念 B：误以为无花括号嵌套if中的else总与最外层if配对。

**共同表现题**

```c
int a=1, b=0, v=0;
if(a)
  if(b) v=1;
else v=2;
printf("%d\n",v);
```

正确输出：`2`；按错误信念 A 预测：`0`；按 B 预测：`0`。

**区分题**

```c
int a=1, b=0, v=0;
if(a)
  if(b) v=1;
  else v=2;
printf("%d\n",v);
```

正确输出：`2`；按错误信念 A 预测：`2`；按 B 预测：`0`。

**变式复测**

```c
int a=0, b=0, v=3;
if(a)
  if(b) v=1;
else v=2;
printf("%d\n",v);
```

正确输出：`3`；按错误信念 A 预测：`2`；按 B 预测：`2`。

针对 A：忽略缩进提示，按语法允许的最近if配对；再用花括号明确期望边界。

针对 B：先识别内层完整if/else结构；外层不进入时，内层if和else都不执行。

上述错误预测是固定假设的模拟；一次作答不能直接确认学生真实错因。

共同表现题和区分题都使用a=1、b=0、初始v=0；两题只改变else的视觉缩进，合法C程序的语法配对没有改变，所以正确输出都为2。共同题中，A按缩进配外层，B按“总归最外层”配对，两者都会错误地预测v仍为0。

把else缩进到内层if同列后，A的既定规则会改为配内层并预测2，B仍按外层配对并预测0，这才产生区分。复测把外层条件设为假、初始v改为3；整个内层结构不执行，正确值仍为3，而按这两种错误规则会预测2。比较的是固定信念在不同情境中的结果，不是仅凭一次错答就给学习者贴标签。

知识依据：K-I04 else 的词法就近配对；K-I06 缩进不改变语法归属；K-I07 未进入外层则不执行内层。

## 外层未进入与空语句陷阱

### 控制流的依赖关系

内层if/else能否执行，首先取决于包含它的外层分支是否被选中。外层没有选择该分支时，里面整个选择语句都不执行，内层else不能作为一个独立“兜底”从外部进入；即使这个嵌套选择语句没有额外花括号，也遵守相同原则。

不要将它误读为“外层条件为假时总是直接跳到整条if之后”：如果外层本身还有else，应继续按外层的选择结构执行那个else。本结论只说明未被选中的那一部分内层代码不会执行，并限定在没有goto等跳入的普通控制流中。

知识依据：K-I07 未进入外层则不执行内层。

### 示例：外层条件为假

**例题 E-I04：未进入外层则不执行内层**

```c
int a=0,b=1,x=0;if(a)if(b)x=1;else x=2;printf("%d",x);
```

标准输出（核验记录）：

```text
0
```

设有 `int a=0, b=1, x=0;`。代码为 `if(a) if(b) x=1; else x=2;`。这里外层 `if(a)` 的条件 `a` 为 0（假）。虽然内层 `if(b)` 的条件 `b` 为 1（真），但由于外层未通过，内层的 `if(b)` 及其配对的 `else` 整体都不执行。最终 `x` 保持为 0，而不是 2。这证明了外层逻辑的“门槛”作用。

知识依据：K-I07 未进入外层则不执行内层。

### 空语句导致的逻辑断点

if(cond);中的分号本身构成空语句，所以这个if的真分支体为空语句。紧跟其后的独立语句不因此受该if控制。对于这种普通执行情境，if(cond);与if(cond){}的分支都没有要执行的操作，执行效果可以相同，但语法类别不同：前者是空语句，后者是复合语句。

检查控制范围时，应看完整语句和花括号，而不看“想把哪几行放进if”。例如条件为假时，如果后续赋值仍执行，先核对分号是否已经结束了那个空分支。

知识依据：K-I08 空语句对控制范围的破坏。

## 选择链与独立判断

### if/else-if 选择链的本质

C 语言中没有 `else if` 这一语法关键字，它只是 `else` 子句内部嵌套的另一条 `if` 语句。这种结构形成了所谓的 if/else-if 选择链。选择链的特性在于互斥性：在普通顺序执行中，一旦链中某个条件被判定为真并执行了对应分支，程序就会跳出整个链，后续的分支条件求值被直接跳过。这种特性非常适合处理等级判定或分类逻辑。

知识依据：K-I09 else if 的语法结构；K-I10 选择链首命中后停止判断。

### 示例：链式判断的短路

**例题 E-I05：选择链首命中后停止判断**

```c
int b_calls=0;if(1){}else if(++b_calls){}printf("%d",b_calls);
```

标准输出（核验记录）：

```text
0
```

设有变量 `int b_calls=0;`。代码执行 `if(1){}else if(++b_calls){}`。这里 `1` 始终为真。程序进入 `if(1)` 的分支体（空块），执行完毕后，直接跳过 `else if` 分支。因此 `++b_calls` 不会执行，输出变量 `b_calls` 依然保持为 0。这展示了选择链一旦首中，后续判断即被忽略。

知识依据：K-I10 选择链首命中后停止判断。

### 独立 if 的顺序执行

多个独立if会在控制流顺序到达它们时分别求值，前一个if命中不会自动跳过后一个条件。因此，在没有提前return等控制转移、操作均有定义的情况下，多个独立if可以先后命中。

后续if读取的是自己求值时的当前状态。前一条if若修改了相关变量，后一条就会看到修改后的值；因此“彼此独立”并不意味着前面的状态修改不会影响后面的判断。与选择链比较时，应同时区分是否继续求值，以及继续求值时读到了什么状态。

知识依据：K-I11 独立 if 可以多次命中；K-I12 后续 if 读取新状态。

### 示例：新状态下的二次判断

**例题 E-I06：后续 if 读取新状态**

```c
int x=1,y=0;if(x)x=0;if(x)y=1;printf("%d %d",x,y);
```

标准输出（核验记录）：

```text
0 0
```

设有 `int x=1, y=0;`。代码段为 `if(x)x=0; if(x)y=1;`。第一条 `if` 中 `x` 为真，进入分支，将 `x` 修改为 0。随后执行第二条 `if(x)`。此时程序读取 `x` 的当前值 0，条件为假，因此 `y=1` 不执行。最终输出 `x` 和 `y` 均为 0。这里清晰地展示了第二个 `if` 依赖第一个 `if` 产生的状态修改。

知识依据：K-I12 后续 if 读取新状态。

### 先定结构，再沿路径追踪状态

分析if代码时，先按语法找出每个分支体和else的归属，再按实际条件选择执行路径。分支体是一条语句，复合语句可以包含多条语句；空语句和缩进都不能被误当成预期的控制范围。

运行分析中，检查外层是否进入、当前条件何时读取、分支内修改了哪些变量。一次if执行不会因改值而补选另一分支；if/else-if选择链首命中后停止后续判断，独立if则在控制流到达时继续读取当前状态。任何简化判断都应保留“普通结构化执行、无额外跳转”的前提。

知识依据：K-I01 标量条件的真值语义；K-I02 一次执行不重新选分支；K-I03 分支体的语句范围；K-I04 else 的词法就近配对；K-I05 花括号显式修改 else 归属；K-I06 缩进不改变语法归属；K-I07 未进入外层则不执行内层；K-I08 空语句对控制范围的破坏；K-I09 else if 的语法结构；K-I10 选择链首命中后停止判断；K-I11 独立 if 可以多次命中；K-I12 后续 if 读取新状态。

对于独立书写的两条语句 `if(a) x++; if(b) y++;`，在没有提前返回等跳转的情况下，若 `a` 和 `b` 在求值时都为真，第二条 `if` 的自增操作 `y++` 能否被执行？

适用条件：顺序执行到各if；无提前return等跳转；a、b、x、y已正确声明初始化，所有自增有定义。

### 自测 6 · Q-I12

已知代码段：`int x = 1; if(x) x = 0; if(x) y = 1;`，在普通顺序执行下，第二条 `if(x)` 中的条件 `x` 被求值时，其结果是什么？

适用条件：普通顺序执行；变量已初始化，修改及读取有定义；代码片段中的y事先声明为int。

### 参考解答

1. 0 else 词法上就近配对到内层 if(b)。因为 a 为假，外层 if 的整个分支体（包括内层 if 和配对的 else）都不执行。

2. 不能，配对由语法（如花括号边界）决定，空白缩进无此效力。 C17的词法分析会跳过空白字符（包括空格和制表符），词法记号序列和后续的语法分析（AST构建）完全不受视觉缩进的影响。`else` 的配对严格由其与 `if` 的相对语法位置（尤其是花括号边界）决定。

3. 20 分号紧跟 if 条件后构成空语句作为分支体，y=20 是独立于 if 之后的语句，无论条件真假均执行。

4. 不会 由于 `else if` 在语法上是 `else` 的分支，而 `if`/`else` 的语义规定只有当条件为假时才会执行 `else` 分支。因此一旦 `A` 为真，控制流进入 `A` 分支，根本不会到达 `else` 分支去求值 `B`。

5. 能，因为这是两条独立的 `if`。 两条独立的 `if` 语句之间没有语法上的分支绑定关系。第一条 `if` 命中并执行后，控制流继续往下，第二条 `if` 会独立地对其条件 `b` 进行求值并执行其分支。

6. 为假（或0），因为求值时 `x` 的值已经被前一条语句修改为0。 第二条 `if` 在执行到该语句时，才会对条件 `x` 进行求值。由于前一条 `if` 内的 `x=0` 已经执行完毕并改变了 `x` 的内存状态，因此第二次求值读到的是修改后的当前值 `0`（即假）。
