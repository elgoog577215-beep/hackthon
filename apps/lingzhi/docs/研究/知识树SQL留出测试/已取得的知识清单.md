## 2.5. Querying a Table

来源：https://www.postgresql.org/docs/18/tutorial-select.html

状态：取得清单；待后续阶段

- **C1 [definition]** SQL SELECT语句用于从表中检索数据，由select list、table list和可选的qualification组成
- **C2 [rule]** SELECT * 是“所有列”的简写
- **C3 [rule]** 在select list中，可以写表达式，而不只是简单的列引用
- **C4 [method]** AS子句可用于重新标记输出列
- **C5 [rule]** AS子句是可选的
- **C6 [method]** 通过添加指定所需行的WHERE子句，可以“限定”查询
- **C7 [rule]** WHERE子句包含一个布尔（真值）表达式，并且只有使布尔表达式为真的行才会被返回
- **C8 [rule]** 在限定条件中允许使用常用的布尔运算符（AND、OR和NOT）
- **C9 [method]** 可以请求以排序顺序返回查询结果（使用ORDER BY）
- **C10 [boundary]** 如果排序顺序未完全指定，结果可能会以任意顺序出现
- **C11 [rule]** 可以请求从查询结果中移除重复行（使用DISTINCT）
- **C12 [boundary]** DISTINCT的结果行顺序可能会变化
- **C13 [method]** 通过使用DISTINCT和ORDER BY一起，可以确保获得一致的结果
- **C14 [boundary]** 虽然SELECT *对于临时查询很有用，但在生产代码中被广泛认为是糟糕的风格，因为向表中添加一列会改变结果
- **C15 [boundary]** SQL标准不要求DISTINCT自动对行进行排序，当前的PostgreSQL也不保证DISTINCT会导致行被排序

## 2.6. Joins Between Tables

来源：https://www.postgresql.org/docs/18/tutorial-join.html

状态：取得清单；待后续阶段

- **C1 [definition]** 同时访问多个表（或同一表的多个实例）的查询被称为join queries（连接查询）。
- **C2 [rule]** 内连接（inner join）会忽略未匹配的表行，导致结果集中不包含这些行。
- **C3 [rule]** 使用SELECT *进行多表连接时，结果集包含两个表中所有列的拼接，可能导致列名重复。
- **C4 [rule]** 在SQL-92中，WHERE子句中包含连接条件被称为旧式隐式连接语法，其与JOIN/ON语法结果相同但可读性较差。
- **C5 [rule]** 左外连接（LEFT OUTER JOIN）保证左表所有行至少出现一次，右表无匹配行时其列填入NULL值。
- **C6 [definition]** 自连接（self join）是指一个表与其自身进行连接的操作。
- **C7 [rule]** 在查询中为表起别名（如w1, w2）是为了在自连接或其他多实例场景中区分配对侧的行数据。
- **C8 [boundary]** 文中将行对比较描述为概念模型，实际执行引擎可能采用更高效的算法而非直接比较所有行对，这对用户是透明的。
- **C9 [case]** 示例中Weather表与Cities表连接后，Hayward因在Cities表中无匹配而被默认内连接排除，但在左外连接下保留并补全NULL。
- **C10 [rule]** 在存在重名列名的表中，必须使用表名或表别名限定列名（如 weather.city），否则查询可能失败或产生歧义。

## 2.7. Aggregate Functions

来源：https://www.postgresql.org/docs/18/tutorial-agg.html

状态：取得清单；待后续阶段

- **C1 [definition]** 聚合函数（aggregate function）从多行输入中计算出一个单一结果。
- **C2 [case]** PostgreSQL 中用于对行集计算 count, sum, avg, max, min 的聚合函数是特定示例，展示了可计算的聚合类型。
- **C3 [case]** 查询 max(temp_lo) 得到最高最低温度读数为 46。
- **C4 [rule]** 聚合函数（如 max）不能用于 WHERE 子句中。
- **C5 [boundary]** WHERE 子句必须先于聚合函数计算被评估，因为它决定了哪些行将包含在聚合计算中。
- **C6 [method]** 若需在查询中使用聚合函数作为条件，可以使用子查询（subquery）。
- **C7 [reason]** 子查询中的聚合计算是独立的，与外部查询中发生的事情分开进行，因此可以合法地在 WHERE 中引用。
- **C8 [case]** 使用 GROUP BY city 查询各城市的记录数和最高最低温度，其中 Hayward 计数为 1，最高 37；San Francisco 计数为 2，最高 46。
- **C9 [rule]** GROUP BY 子句生成每个组（如每个城市）一行输出，每个聚合结果仅在该组匹配的行上计算。
- **C10 [rule]** HAVING 子句用于过滤分组后的行（grouped rows），即聚合计算完成之后。
- **C11 [case]** 应用 HAVING max(temp_lo) < 40 仅保留 Hayward（最高 37），过滤掉 San Francisco（最高 46）。
- **C12 [rule]** WHERE 和 HAVING 的根本区别在于：WHERE 在分组和聚合计算之前选择输入行，控制哪些行进入聚合；而 HAVING 在分组和聚合计算之后选择组行。
- **C13 [boundary]** WHERE 子句不能包含聚合函数，因为试图使用聚合来决定哪些行作为聚合输入在逻辑上无意义。
- **C14 [rule]** HAVING 子句通常包含聚合函数。
- **C15 [scope]** 虽然允许编写不使用聚合的 HAVING 子句，但很少有用，同样的条件在 WHERE 阶段使用会更高效。
- **C16 [method]** 如果一个条件不需要聚合（如城市名限制），应放在 WHERE 中而不是 HAVING 中，以避免对未通过 WHERE 检查的所有行执行分组和聚合计算，从而更高效。
- **C17 [definition]** FILTER 是用于选择进入特定聚合计算的行的另一种方式，它是每个聚合的选项（per-aggregate option）。
- **C18 [rule]** FILTER 与 WHERE 类似，但它仅从其附加的特定聚合函数的输入中移除行。
- **C19 [case]** 在示例中，使用 count(*) FILTER (WHERE temp_lo < 45)，count 仅计算 temp_lo 小于 45 的行（San Francisco 中仅 1 行符合），而 max(temp_lo) 仍应用于所有行（仍找到 46）。
