# 联网资料语义级内容安全：最小可落地方案

> 文档状态：**设计提案，尚未实施**
> 提出方：`dev/lz-web-search`
> 提出日期：2026-08-09
> 相关代码：`backend/web_retrieval.py` 的 `classify_source()`、
> `backend/web_material_search.py` 的落地链
>
> 本文只做设计，不含实现。评审通过后再排期。

---

## 1. 现状：只有"形式安全"，没有"语义安全"

当前联网资料在进入教学材料前，实际经过的安全门只有四道，**全部是形式判定**：

| 现有门 | 判什么 | 位置 |
| --- | --- | --- |
| `unsafe_url` | URL 是否为公开 https、host 是否合法 | `_canonical_public_https_url()` |
| `prompt_injection` | 正文是否含"忽略之前指令"类注入话术 | `_contains_injection()` |
| `low_relevance` | 查询词与标题/摘要重合度 < 0.55 | `_relevance()` |
| 域名信誉 | 是否命中 tier_a 域名清单 | `_DEFAULT_TIER_A_DOMAINS` |

另外 SearXNG 侧开了 `safesearch=2`，Exa 侧传了 `moderation: true`，
但那是**搜索引擎级的色情/暴力过滤**，不解决教育场景的问题。

**缺口**：一个 `.edu` 域名下、相关性高、无注入话术的页面，
只要域名在 tier_a 清单里就会被判 `accepted_for_generation=True`，
**不经教师确认直接进入生成上下文**。而它的内容可能是：

- 事实性错误（过时结论、被撤稿的研究）
- 学术争议内容（未定论假说被表述为定论）
- 意识形态/价值观敏感内容（历史、政治、民族、宗教相关表述）
- 教学不适宜内容（面向研究者而非学生的深度内容、极端案例）

教育产品对这几类的容忍度显著低于通用搜索。

## 2. 设计原则

1. **不做内容审查，做内容标记。** 目标不是替教师判断对错，
   而是把"这条需要你看一眼"明确标出来。教师是最终决策者。
2. **不新增外部依赖。** 不引入第三方审核 API（延迟、成本、数据出境风险）。
   最小实现只用本地规则 + 已有的 LLM 调用链。
3. **不阻断生成。** 安全判定失败必须降级为"标记未知"，
   与现有 `degraded` 语义一致，不能让内容安全成为新的生成失败源。
4. **复用既有分级，不新建平行真源。** 判定结果挂在
   `retrieval_source_v1` 上，走既有 `trust_tier` / `rejection_reasons` 通道。

## 3. 最小实现：三层，按成本递增

### 第 1 层：敏感主题词表（本地，零成本，建议先做）

在 `classify_source()` 里增加一个 `sensitivity` 判定，**只标记不拒绝**：

```python
# 概念示意，非最终代码
SENSITIVE_TOPICS = {
    "history_politics": ("领土", "主权", "政权", "革命", "战争罪", ...),
    "ethnicity_religion": ("民族", "宗教", "教派", ...),
    "medical_advice": ("剂量", "处方", "诊断标准", "副作用", ...),
    "unsettled_science": ("尚有争议", "有待验证", "assumption", "hypothesis", ...),
}

def assess_sensitivity(title: str, excerpt: str) -> dict:
    hits = {topic: matched for topic, words in SENSITIVE_TOPICS.items()
            if (matched := [w for w in words if w in text])}
    return {
        "level": "review_recommended" if hits else "none",
        "topics": sorted(hits),
        "matched_terms": ...,   # 供教师看到"为什么被标"
    }
```

**产出**：`retrieval_source_v1` 增加 `sensitivity` 字段。

**动作**：
- `level == "review_recommended"` 时，把 `accepted_for_generation` 降为 `False`
  （即从"自动进链"降为"需教师确认"），**但仍保留在候选列表里**。
- 教师端审阅面板显示黄色标记 + 命中主题 + 命中词，教师一键接受或剔除。

**代价**：词表维护。建议初版只覆盖"医学建议"与"未定论科学"两类
（这两类在教学场景最常见且最容易误导），其余留配置位。

### 第 2 层：来源时效与撤稿信号（本地，低成本）

教育材料里"过时"比"错误"更常见。已有 `published_date` 字段但只用于
`missing_date_for_current_query`。建议扩展：

- 学科敏感度分级：医学/技术类资料超过 N 年标 `stale_for_subject`；
  数学/基础物理不标。
- 检测 `retracted`、`撤稿`、`更正声明`、`erratum` 等词，命中直接降 tier_c。

**代价**：需要一份"学科→时效窗口"映射，可以先硬编码三档
（fast: 技术/医学 2 年；medium: 社科 5 年；slow: 数学/基础学科 不限）。

### 第 3 层：LLM 教学适宜性评审（有成本，建议灰度）

对**已通过前两层、且准备进入正文**的来源，调一次轻量 LLM 判定：

```
输入：来源标题 + 摘要（不超过 800 字）+ 课程主题与学段
输出（结构化）：
  suitability: suitable | needs_review | unsuitable
  reasons: [factual_risk | age_inappropriate | ideological_sensitive | out_of_scope]
  one_line_note: 给教师看的一句话说明
```

**关键约束**：
- 用 `AI_MODEL_FAST` 而非主模型，控制成本。
- 每次生成的评审调用数有上限（建议 ≤ `max_sources`，即最多 8 次）。
- **调用失败一律降级为 `needs_review`**，不阻断生成，不默认放行。
- 判定结果写入 `sensitivity.llm_review`，与规则层结果并存，不互相覆盖。

**代价**：每门课增加最多 8 次 fast 模型调用。按当前用量估算成本可忽略，
但会增加生成时长约 2-5 秒（可并发）。

## 4. 教师端呈现（复用已有面板）

审阅面板已有"采用/排除"两栏，增加**第三栏"建议复核"**：

```
联网资料                                    已就绪
采用 3 条 · 建议复核 2 条 · 已排除 5 条

⚠ 建议复核
  《XX 疗法的临床应用》  medical_advice · 含"剂量"表述
  https://example.edu/...        [采用] [剔除] [打开原文]
```

文案键沿用 `courseGeneration.materials.webSearch.*` 命名空间，
新增 `sensitivity.*` 子树，中英文同步（走既有 i18n 守卫测试）。

## 5. 落地顺序与验收

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| P0 | 第 1 层词表 + `sensitivity` 字段 + 面板"建议复核"栏 | 构造命中样本必须被标记且不自动进链；未命中样本行为不变 |
| P1 | 第 2 层时效与撤稿信号 | 撤稿样本降 tier_c；学科时效分档生效 |
| P2 | 第 3 层 LLM 评审（灰度开关 `WEB_RETRIEVAL_LLM_REVIEW=off/allowlist/on`） | 调用失败降级为 needs_review；调用数不超上限 |

**每一层都必须配"应通过样本"与"必须标记样本"两组测试**
（对应 `docs/开发禁区.md` 3.3「新质量规则必须同时准备应通过样本和必须阻断样本」）。

## 6. 明确不做的事

- **不做自动删改内容**。只标记与降级，不改写来源正文。
- **不做政治立场判定**。词表只标"该主题需人工看"，不判对错。
- **不引入第三方审核 API**。避免数据出境与额外依赖。
- **不把安全判定做成阻断门**。任何判定失败都降级为"需复核"，
  绝不因内容安全导致生成失败——这与现有 `degraded` 契约一致。

## 7. 与现有约束的关系

- 联网资料**已经**不能绕过白名单命令写入已发布课程正文
  （见 `backend/tests/test_web_material_course_write_boundary.py`，2026-08-09 验证）。
  所以本方案针对的是**生成期**进入正文的路径，不涉及课程调整路径。
- `reuse_policy=reference_only` 与出处保留机制不变，本方案是叠加的一层。
