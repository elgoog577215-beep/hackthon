## 范围与拆分标准

- 变量与类型：标量变量的声明、初始化、整数、实浮点、字符、布尔、转换、类型工具、作用域和存储期；枚举、void、数组与指针只覆盖类型识别边界。
- if：普通顺序执行中的条件、逻辑组合、受控语句、分支配对、分类与状态检查。
- for：基本执行、缺省部分、范围、控制转移、累积/搜索、嵌套和终止边界。
- 数组和指针的完整操作、自定义结构体/联合体、复杂声明、多文件链接细节、格式化输入输出、复数、原子类型、restrict、volatile、并发、内存模型和 C23 扩展另属其他分支，不用几个空目录冒充已经细化。
- 本样板中的代码片段默认位于适当的函数/声明上下文，所需变量和标准头文件已提供；特殊初值、非空集合、无提前退出等条件随题说明。
- 一个叶子承载一个可区分的结论或操作判断；解释、边界、例子和检查方式是其内容，不继续拆成分类节点。
- 一般规则及其特定语境应用通过引用关联。例如 I01 与 V30、F05 与 V47；正式导入时保留不同教学对象的边界，完全同义的条目则合并。

关键语言边界按 C17 工作草案 N2176 的 6.3.1.3–6.3.1.4、6.8.4.1、6.8.5.3、6.8.6.2–6.8.6.4 核对：越界转换不能笼统视为截位；else 的绑定由语法决定；for 中 continue 后仍进入迭代表达式；break 与 return 的退出范围不同。[WG14 C17 工作草案镜像](https://files.lhmouse.com/standards/ISO%20C%20N2176.pdf)。教学分组、题目和判断说明为本样板原创组织。

## 元问题与元知识的三个深化样板

“元问题”只追问一个主要判断；“元知识点”提供解决该判断的最小规则。相互独立的规则各自保存，可被多个问题引用。以下能力、错误假设、诊断追问和补救都是教学设计样例，尚无真实学生数据支持错误频率或个人诊断。涉及 C17 的已核对规则沿用上文来源，未另行声称来源已绑定实际课程。

### 类型转换样板

起点是 V36：`double x = 5 / 2;` 为什么得到 2.0？原条目保留为综合辨析问题；它的答案由下面的知识共同支撑。

| 元问题 | 对应元知识点 | 单点检查 |
| --- | --- | --- |
| 5 与 2 这样的常量各是什么类型 | T1：可由 int 表示的无后缀十进制整数字面量，其类型为 int | 改成 7 与 3 后，仍应判断为 int；理由不能是“看左侧变量” |
| 整数操作数的除法采用什么结果类型 | T2：这里的两个 int 操作数按整数除法运算，结果类型为 int | 即使最终要保存到 double，也应先判断该除法的结果类型 |
| 非整除时怎样处理小数部分 | T3：有定义的整数除法将商向零截断 | 5/2 为 2，−5/2 为 −2；区分向零与向下 |
| 目标类型的转换发生在什么时候 | T4：普通标量初始化将右侧表达式求得的值转换到所声明的对象类型 | 此例先得到整数 2，再转为 double 的 2.0 |
| 显式转换作用于哪个子表达式 | T5：转换的语法位置决定它作用的子表达式 | `(double)(5/2)` 转的是商；`(double)5/2` 先转操作数 |
| 一个操作数是 double 时怎样计算本例除法 | T6：本例 int 与 double 的通常算术转换使除法按 double 类型计算 | `(double)5/2` 得到 2.5；前提是除法有定义 |

T1 与 T3 等应复用第一轮已有知识内容；T5/T6 的必要性来自强制转换变式，不能将每个新例子都创建成另一套规则。能力分成“辨认类型”“逐步追踪求值”“选择转换位置”，再由综合题检查三者能否配合。

| 易错假设 | 可以观察到的表现 | 区分性追问 | 补救与复测 |
| --- | --- | --- | --- |
| 接收变量的 double 会反向改变除法 | 预测 x=2.5，并以左侧类型为理由 | 先不显示左侧，问 5/2 的结果类型和值，再恢复左侧；检查错误是否发生在 T2/T4 | 把求值与保存画成两步；用 `double y=7/2;` 要求解释 3.0 的来源 |
| 最后强转可以恢复被丢弃的小数 | 认为 `(double)(5/2)` 也是 2.5 | 让学生标出括号内部先得到的值；区分 T3 不清与 T5 位置误读 | 比较 `(double)(7/2)` 与 `(double)7/2`，解释 3.0 与 3.5 的差异 |
| 负数整数除法总向下取整 | 将 −5/2 判为 −3 | 同时询问 5/2 与 −5/2 的截断方向，排除单纯笔误 | 沿数轴解释朝零方向，再用 −7/2 检查是否得到 −3 |

判定时保存学生的中间类型、值和解释。只看到 x=2.5 不能确定是哪条规则出错；复测中答案正确但理由仍依赖左侧类型，也不能视为错误理解已消除。

### if 配对样板

I17“else 匹配最近且语法上可匹配的 if”本身可以保留为元知识。需要补齐它与相邻规则、问题和诊断的联系，而不是为了增加颗粒度强拆这条规则。

```c
int a = 1, b = 0, x = 0;
if (a)
    if (b)
        x = 1;
    else
        x = 2;
```

| 元问题 | 对应元知识点 | 单点检查 |
| --- | --- | --- |
| 一个无花括号的 if 控制多大范围 | B1：if 的一个分支体是一条语句，该语句也可以是另一个 if | 指出外层受控语句包含整个内层 if/else |
| 花括号怎样改变语句分组 | B2：复合语句将其中的语句组织成一个语句块 | 给外层真分支加完整花括号，辨认其结束位置 |
| 这一个 else 与谁配对 | B3：else 按语法匹配最近且可匹配的 if | 在本例中指出 if(b)，不依赖缩进判断 |
| 外层未命中时会不会执行内层 | B4：仅在对应分支被选中时，才执行该分支中的受控语句 | 把 a 改为 0 后，说明为什么内层判断也不执行 |

能力包括给代码标出分支归属、按条件追踪一条执行路径、用花括号表达指定配对。作为综合检查，本例 a=1、b=0 时 x=2；a=0 时 x 保持 0。

| 易错假设 | 可以观察到的表现 | 区分性追问 | 补救与复测 |
| --- | --- | --- | --- |
| else 应当跟视觉上对齐的 if 配对 | 仅改变缩进就改变预测结果 | 保留全部符号只调整缩进，要求标出配对；再问“最近”是否仍受语法边界限制 | 为每个 if 标号，画配对，再加花括号改成外层 else；用新排版复测 |
| 外层不成立，内层 else 仍会单独执行 | 当 a=0 时预测 x=2 | 先问内层 if(b) 有没有被执行，再问其 else 是否可脱离外层进入 | 逐级圈出受控语句；比较 a=0 与 a=1、b=0 的两条路径 |

补救题必须检查“未执行”与“条件为假”的区别。学生说出“else 跟最近的 if”但忽略花括号，也仍需检查其是否真正理解语法配对条件。

### for 与 continue 样板

从 F19 的复合描述中分别检查“跳过哪些语句”“接下来到哪里”“什么时候再判断条件”，并与原有循环顺序规则建立引用。

```c
int sum = 0;
for (int i = 0; i < 4; i++) {
    if (i == 1) continue;
    sum += i;
}
```

| 元问题 | 对应元知识点 | 单点检查 |
| --- | --- | --- |
| continue 后本轮剩下的语句还执行吗 | L1：continue 跳过所在最内层循环体的剩余部分 | i=1 时的 sum+=i 不执行 |
| 在 for 中下一步转到哪个位置 | L2：for 的 continue 转到循环推进位置，执行非空的迭代表达式 | i=1 后仍执行 i++，得到 2 |
| 推进后先判断还是先执行循环体 | L3：下一轮循环体开始前需要重新判断控制条件 | i++ 后先计算 i<4，不直接执行 sum+=i |
| 如果改成 break，退出范围是什么 | L4：break 终止最内层包围它的循环或 switch | 本例没有 switch，因此退出该 for；不会执行其后续 i++ |

sum 的初始化与累积分别引用变量和表达式/算法分支的知识，不在此重复定义。能力包括定位控制转移目标、写出逐轮状态、比较 break 与 continue。

| 进入循环体时 i | 命中 continue | 本轮累加后 sum | 后续推进 |
| --- | --- | --- | --- |
| 0 | 否 | 0 | i 变成 1，再判断 |
| 1 | 是 | 0 | i 仍推进为 2，再判断 |
| 2 | 否 | 2 | i 变成 3，再判断 |
| 3 | 否 | 5 | i 变成 4，判断失败后结束 |

| 易错假设 | 可以观察到的表现 | 区分性追问 | 补救与复测 |
| --- | --- | --- | --- |
| continue 同时跳过 for 头部更新 | 认为 i 会停在 1，或该程序无法结束 | 只问 i=1 这一轮结束后的下一位置和下一值，暂不要求计算 sum | 标出“循环体 → 迭代表达式 → 条件”的控制路径；换一个跳过值复测 |
| continue 结束整个循环 | 预测 i=1 时就停止后续所有轮次 | 对照只替换为 break 的两个程序，询问 i=2 的循环体能否到达 | 逐项对比退出范围；用三轮短循环重新追踪 |
| 命中 continue 后仍会累加 | 报告 sum=6 且列出 0、1、2、3 都被累加 | 要求标出 i=1 时跳过的语句，区分 L1 误解与单纯算术错误 | 先逐轮标“执行/跳过”，再计算总和；将条件改为 i==2，复测应得到 4 |

该题最终 sum=5 只是结果证据；解释和逐轮状态用于区分控制流理解与猜测。更高层综合任务再检查学生能否独立写出“跳过指定输入后累计”的程序。

## 第一轮基础条目的教学内容与检查

### 变量与类型

#### 声明与标识符

**V01 声明把标识符与类型关联**

- 核心结论：在使用普通局部变量前先声明其类型；`int count;` 将 count 声明为 int 对象。
- 检查题：`count = 3;` 前缺少任何 count 声明，应该补什么？
- 判断依据：例如 `int count;`；不能期待 C17 从第一次赋值自动推断变量类型。

**V02 基础标识符的组成规则**

- 核心结论：采用基础英文字母写法时，标识符可含字母、数字、下划线，但不能以数字开头，也不能使用关键字。
- 检查题：`2count`、`count2`、`for` 哪个可作为普通变量名？
- 判断依据：count2；另外两个分别违反首字符与关键字限制。课程命名避免以下划线开头，以避开保留名规则。

**V03 标识符区分大小写**

- 核心结论：count 与 Count 是两个不同标识符。
- 检查题：声明 `int count = 1; int Count = 2;` 后修改 count，会改变 Count 吗？
- 判断依据：不会；大小写差异不是同一变量的别名。

**V04 一条声明中的初始化逐个生效**

- 核心结论：`int a, b = 0;` 的初始化器只属于 b。
- 检查题：在函数内执行该声明，能断言 a 也等于 0 吗？
- 判断依据：不能；仅 b 被显式初始化，普通自动变量 a 没有得到初值。

**V05 变量与当前值是不同概念**

- 核心结论：变量有持续的身份和类型，保存的值可在合法赋值后变化。
- 检查题：`int n = 2; n = 5;` 是创建了第二个 n 吗？
- 判断依据：不是；原来的 int 对象获得新值 5。

#### 初始化与赋值

**V06 初始化与后续赋值发生在不同阶段**

- 核心结论：初始化发生在对象建立初值时，后续赋值替换已存在对象的值。
- 检查题：`int x = 1; x = 2;` 哪一步是初始化？
- 判断依据：第一步；第二步是赋值，两处等号处于不同语法结构。

**V07 普通标量赋值保存当时的值**

- 核心结论：给普通非指针数值变量赋值时保存计算结果，不建立持续联动关系。
- 检查题：`int a = 3; int b = a; a = 8;` 后 b 是多少？
- 判断依据：3；改变 a 不会让 b 自动重新读取 a。

**V08 普通自动变量不会默认初始化为零**

- 核心结论：未显式初始化的普通自动局部变量具有不确定值，必须在读取前建立合法值。
- 检查题：函数内 `int x;` 后直接用 x 算平均数是否可靠？
- 判断依据：不可靠；应先赋值或初始化。不能把某次运行结果当作默认初值规则。

**V09 静态存储期的算术对象默认零初始化**

- 核心结论：文件作用域的算术对象及 static 局部算术对象未显式初始化时，按相应算术类型初始化为零。
- 检查题：文件作用域 `int total;` 与函数内 `static double sum;` 的初值是什么？
- 判断依据：分别是整数零和浮点零；这不是普通自动局部变量的默认规则。

**V10 自增前必须已经有合法旧值**

- 核心结论：`x++` 需要读取 x 的旧值再更新，不能承担未初始化变量的首次赋值。
- 检查题：`int x; x++;` 能作为“从 0 开始加一”吗？
- 判断依据：不能；先用 `int x = 0;` 建立初值。

#### 整数类型与可表示范围

**V11 整数类型家族表达不同范围需求**

- 核心结论：标准有符号整数类型包括 signed char、short、int、long、long long，并有对应无符号类型。
- 检查题：需要比 int 至少不更窄的标准整数候选，可查看哪些类型？
- 判断依据：long、long long；最终仍需核对该实现的范围，不能仅凭名字假定字节数。

**V12 整数类型修饰符只能合法组合**

- 核心结论：`unsigned long int` 可组合符号与长度说明；signed 与 unsigned 不能同时修饰同一类型。
- 检查题：`unsigned long int` 与 `signed unsigned int` 哪个声明形式有效？
- 判断依据：前者；后者的类型说明符组合不合法。

**V13 无符号整数没有负数值域**

- 核心结论：unsigned 类型的值域从 0 开始；负数转入时需按转换规则处理。
- 检查题：温度需要保存负值，unsigned int 能原样表达 −5 吗？
- 判断依据：不能；应选择覆盖所需负值范围的有符号类型，不能把无符号转换后的值当作负温度。

**V14 int 的实际范围由实现给出**

- 核心结论：不能将 int 永远是 32 位作为可移植规则；应查询 limits.h 的 INT_MIN、INT_MAX 等。
- 检查题：想判断本机 int 能否容纳十亿，检查什么？
- 判断依据：检查 INT_MAX 是否至少为十亿；不从一次 sizeof 结果推断所有平台。

**V15 有符号整数溢出没有规定的回绕结果**

- 核心结论：有符号整数算术结果超出其类型可表示范围时，不能假定它按固定方式变成负数。
- 检查题：`int x = INT_MAX; x = x + 1;` 能断言 x 等于 INT_MIN 吗？
- 判断依据：不能；发生有符号算术溢出，属于未定义行为。只作规则辨析，不运行来证明结果。

**V16 无符号算术按值域大小取模**

- 核心结论：unsigned int 算术按 UINT_MAX + 1 的数学模数计算。
- 检查题：`unsigned int x = UINT_MAX; x++;` 后 x 是多少？
- 判断依据：0；这里 x 的运算类型是 unsigned int，不套用有符号溢出的判断。

#### 整数字面量

**V17 整数前缀决定书写进制**

- 核心结论：C17 中 10 是十进制，010 是八进制，0x10 是十六进制。
- 检查题：这三个字面量分别表示多少？
- 判断依据：10、8、16；不要将前导零看成纯排版。

**V18 整数字面量后缀参与类型选择**

- 核心结论：U 表示无符号候选，L、LL 指定相应长度候选；可合法组合。
- 检查题：`1U` 与 `1LL` 分别有什么类型含义？
- 判断依据：前者为 unsigned int；后者为 long long int。数值相同不意味着类型相同。

**V19 无后缀十进制整数按可容纳范围选类型**

- 核心结论：无后缀十进制整数字面量依次尝试 int、long int、long long int 中能容纳它的类型。
- 检查题：假设 int 容纳不了某个十进制字面量但 long 可以，它是否仍然必为 int？
- 判断依据：不是，应选 long；十六进制或八进制的候选序列另含无符号类型，不与该规则混用。

#### 实浮点类型与精度

**V20 float 与 double 的类型选择要看精度需求**

- 核心结论：float、double、long double 是不同实浮点类型；后者的表示集合至少包含前者，但不保证一定占更多字节。
- 检查题：是否能仅凭类型名断言 long double 必须比 double 多占字节？
- 判断依据：不能；实际精度与范围用 float.h 等实现信息核对。

**V21 普通小数字面量默认是 double**

- 核心结论：无后缀的十进制浮点常量如 1.5 的类型是 double。
- 检查题：`float x = 1.5;` 中 1.5 的类型会因 x 是 float 而改变吗？
- 判断依据：不会；常量先是 double，再在初始化时转换为 float。

**V22 浮点后缀直接选择常量类型**

- 核心结论：F/f 选择 float，L/l 选择 long double。
- 检查题：`1.5f` 与 `1.5L` 分别是什么类型？
- 判断依据：float 与 long double；后缀不是小数位数说明。

**V23 有限精度不保证精确表示每个十进制小数**

- 核心结论：浮点类型只能表示有限个值；常见二进制浮点实现对 0.1 等值采用近似表示。
- 检查题：在采用二进制浮点的课程环境中，保存 0.1 是否就能保证数学上的精确十分之一？
- 判断依据：不能；要区分数学实数与实际可表示的近似值。

**V24 整数转浮点也可能损失精度**

- 核心结论：整数即使落在浮点类型的数值范围内，也可能因为有效精度不足而不能精确表示。
- 检查题：能否认为任意整数转成 double 都一定保留全部整数位？
- 判断依据：不能；需结合原整数范围和 double 的实际有效精度判断，范围足够不代表精度足够。

#### 字符类型与字符常量

**V25 char 占一个 C 字节**

- 核心结论：sizeof(char) 恒为 1；一个 C 字节的位数由 CHAR_BIT 表示，不应把两个概念混为一谈。
- 检查题：sizeof(char) 为 1，能否直接推出所有实现的 char 都是 8 位？
- 判断依据：不能；需查看 CHAR_BIT。

**V26 普通 char 的符号性由实现决定**

- 核心结论：char、signed char、unsigned char 是不同类型；普通 char 的值域选择依实现而定。
- 检查题：需要明确保存小范围负数时，能否不加说明地依赖 char？
- 判断依据：不能；应明确使用 signed char 并核对范围。

**V27 字符数字与对应整数值不同**

- 核心结论：字符常量 '7' 表达编码字符，整数 7 表达数值，两者不能直接当作同一含义。
- 检查题：已知 c 是 '0' 到 '9' 的数字字符，如何得到相应整数？
- 判断依据：使用 `c - '0'`；前提是已确认 c 属于十进制数字字符。

**V28 普通单字符常量的类型是 int**

- 核心结论：在 C17 中，'A' 这样的普通整数字符常量具有 int 类型，而非 char 类型。
- 检查题：`sizeof('A')` 应与 sizeof(int) 还是固定数字 1 对应？
- 判断依据：与 sizeof(int) 对应；char 变量大小与字符常量类型是不同问题。

**V29 空字符与字符零不同**

- 核心结论：'\0' 是值为零的空字符；'0' 是可显示的数字字符。
- 检查题：`'\0' == '0'` 是否成立？
- 判断依据：不成立；两者的数值与用途不同。

#### 布尔值

**V30 _Bool 将零与非零归一化**

- 核心结论：标量值转换为 _Bool 时，等于零得到 0，否则得到 1。
- 检查题：`_Bool a = 0; _Bool b = -3;` 的值是什么？
- 判断依据：a 为 0，b 为 1；b 不保存原数值 −3。

**V31 stdbool.h 提供 C17 的布尔便捷名称**

- 核心结论：在 C17 中，可通过 stdbool.h 使用 bool、true、false。
- 检查题：使用 `bool done = false;` 时应包含哪个标准头文件？
- 判断依据：`#include <stdbool.h>`；不把 C23 的关键字规则混入本课程。

**V32 关系比较的结果是 int 类型的零或一**

- 核心结论：`<`、`>=`、`==` 等关系或相等比较产生 int 类型结果，值为 0 或 1。
- 检查题：`int x = (3 < 5);` 后 x 是多少？
- 判断依据：1；比较结果可以赋给 _Bool，但表达式自身的类型仍为 int。

#### 数值转换与表达式类型

**V33 窄整数参加运算前可能先提升**

- 核心结论：在整数提升适用的运算中，若 int 可表示原类型全部值，则提升为 int，否则提升为 unsigned int。
- 检查题：假设 int 能表示 unsigned char 的所有值，两个 unsigned char 相加时直接按字节回绕吗？
- 判断依据：不会；先提升为 int 再运算，结果写回较窄变量时才另作转换。

**V34 混合算术先确定共同运算类型**

- 核心结论：对本课的 int 与 double 混合算术，int 操作数转换为 double 后再运算。
- 检查题：`5 / 2.0` 为什么能得到 2.5？
- 判断依据：2.0 是 double，使此次除法按浮点运算进行。

**V35 整数除法向零截断**

- 核心结论：当两个操作数经转换后均为整数，且除法有定义时，商去掉小数部分，方向朝零。
- 检查题：`5 / 2` 和 `-5 / 2` 分别是多少？
- 判断依据：2 与 −2；向零截断不同于始终向下取整，除零及不可表示的商另行排除。

**V36 接收变量类型不能改变已经完成的运算**

- 核心结论：赋值或初始化的目标类型不会反向改变右侧已经完成的整数除法。
- 检查题：`double x = 5 / 2;` 中 x 是 2.5 吗？
- 判断依据：不是，是 2.0；先得到整数商 2，再转换为 double。

**V37 强制转换的位置影响后续运算**

- 核心结论：在除法之前转换操作数，才能让该次除法按浮点规则计算；在整数除法之后转换不能恢复被丢弃部分。
- 检查题：比较 `(double)5 / 2` 与 `(double)(5 / 2)`。
- 判断依据：分别为 2.5 与 2.0；先确认括号和转换作用的表达式。

**V38 有限浮点值转整数时向零截断**

- 核心结论：有限实浮点值转非 _Bool 整数时，先丢弃小数部分；截断后的值须能由目标类型表示。
- 检查题：`(int)3.9` 与 `(int)-3.9` 分别是多少？
- 判断依据：3 与 −3；若截断值超出 int 范围，则不能据此规则编造一个结果。

**V39 整数转无符号类型按目标值域取模**

- 核心结论：转换到无符号整数类型时，用目标最大值加一作为数学模数。
- 检查题：`(unsigned int)-1` 等于什么？
- 判断依据：UINT_MAX；这里是整数到无符号整数的转换，不推广成浮点到整数越界的规则。

**V40 混合有符号与无符号比较可能改变含义**

- 核心结论：对于同等级的 int 与 unsigned int 比较，int 被转换为 unsigned int。
- 检查题：`-1 < 1U` 的结果是什么？
- 判断依据：0；−1 转成 UINT_MAX 后再比较。其他类型组合需要重新判断共同类型。

**V41 窄化到有符号整数不能假定固定截位结果**

- 核心结论：整数转到无法容纳该值的有符号整数类型时，C17 不给出统一的可移植数值结果。
- 检查题：一个过大的 int 转 signed char，能否无条件断言得到某个负数？
- 判断依据：不能；结果由实现定义，或引发实现定义的信号。应先检查范围。

#### 类型工具与只读约束

**V42 sizeof 报告对象或类型的字节大小**

- 核心结论：sizeof 的结果表示占用多少个 C 字节，不直接表示值域或有效精度。
- 检查题：sizeof(int) 能直接回答 int 的最小值是多少吗？
- 判断依据：不能；用 limits.h 查询相应范围。

**V43 sizeof 的结果类型是 size_t**

- 核心结论：size_t 是无符号整数类型；进行减法或与负数比较时要考虑无符号规则。
- 检查题：`sizeof(char) - 2` 是否必然得到有符号整数 −1？
- 判断依据：不是；该表达式涉及 size_t 的无符号运算。

**V44 typedef 创建类型别名**

- 核心结论：typedef 为已有类型提供另一种名称，不创建不同于原类型的新类型。
- 检查题：`typedef unsigned int Count;` 后 Count 是否拥有与 unsigned int 不同的运算规则？
- 判断依据：没有；它是类型别名。

**V45 const 限制通过该对象的修改**

- 核心结论：声明为 const 的普通对象不能通过该 const 对象表达式赋新值。
- 检查题：`const int limit = 10; limit = 20;` 是否符合约束？
- 判断依据：不符合；初始化可以建立值，随后该赋值不合法。

**V46 const 对象不自动成为 C17 整数常量表达式**

- 核心结论：const 限制修改，但不意味着其值能用于所有必须为整数常量表达式的位置。
- 检查题：`const int n = 3;` 后写 `case n:`，能否仅凭 const 判为符合 C17？
- 判断依据：不能；case 标签要求整数常量表达式，该 const 对象引用不因此满足要求。switch 的其他规则在对应分支学习。

#### 作用域与存储期

**V47 块内声明的名字只在相应作用域可见**

- 核心结论：普通块作用域变量的名字不能在其作用域外继续使用。
- 检查题：`{ int x = 3; }` 之后直接使用 x，是否仍能找到该局部声明？
- 判断依据：不能；离开该作用域后，名字不再由此声明提供。

**V48 内层同名声明会遮蔽外层名字**

- 核心结论：内层块声明同名局部变量后，该内层范围中的普通名字查找使用内层声明。
- 检查题：`int x = 1; { int x = 2; }` 后外层 x 是否变为 2？
- 判断依据：不会，仍为 1；内层定义的是另一个对象。

**V49 普通自动局部对象的生存期随所在块执行结束**

- 核心结论：本课普通非变长局部对象在进入其关联块时取得存储，在该次块执行结束后生存期结束。
- 检查题：函数返回后，能否把此前普通局部对象视为仍然存在并继续使用？
- 判断依据：不能；名字是否可见与对象是否活着是需要分别判断的问题。

**V50 static 局部对象在多次调用间保留值**

- 核心结论：块作用域 static 对象具有静态存储期，重复进入块不会每次重新执行一次初始化。
- 检查题：函数内 `static int n = 0; return ++n;` 连续调用两次返回什么？
- 判断依据：1、2；其名字仍保持局部作用域。

**V51 extern 声明可引用在其他位置定义的对象**

- 核心结论：常见的 `extern int total;` 是声明而非重新分配另一个 total；程序需有匹配的定义。
- 检查题：两个文件都想访问同一 total，是否应各写一个独立定义？
- 判断依据：不应靠重复定义实现共享；给出一个定义，其他位置使用匹配的声明，具体链接规则另见多文件分支。

#### 其他类型的边界识别

**V52 枚举常量提供命名整数值**

- 核心结论：`enum State { OFF, ON };` 声明命名常量；未指定值时从 0 起依次加一。
- 检查题：上述 OFF、ON 的值分别是什么？
- 判断依据：0、1；枚举的具体使用与更多成员关系可在自定义类型分支展开。

**V53 void 不能作为普通变量的对象类型**

- 核心结论：void 表示没有值的类型，不能定义 `void x;` 这样的普通对象。
- 检查题：`void x;` 和返回类型为 void 的函数声明是同一回事吗？
- 判断依据：不是；前者不合法，后者可表示函数不返回值。

**V54 指针与数组具有不同的声明含义**

- 核心结论：`int *p;` 声明指针对象，`int a[3];` 声明含三个 int 元素的数组，两者不是同一类型。
- 检查题：能否把 `int *p` 的声明直接解释成“创建三个整数的空间”？
- 判断依据：不能；指针保存指向对象的信息，数组才在此声明中含三个元素。内存、访问与转换规则转到指针/数组分支。

### 条件分支 if

#### 条件表达式的解释

**I01 零为假而非零为真**

- 核心结论：if 的标量条件按是否等于零决定分支；负数同样可以为真。
- 检查题：`if (-2)` 会进入其受控语句吗？
- 判断依据：会；条件为真不要求数值恰好等于 1。

**I02 if 条件必须具有标量类型**

- 核心结论：算术类型和指针类型可用作 if 条件；结构体对象不能直接作为条件。
- 检查题：能否直接写 `if (some_struct)` 判断整个结构体“非空”？
- 判断依据：不能；应选择需要检查的成员或明确比较规则。

**I03 C17 的 if 圆括号中需要表达式**

- 核心结论：C17 不支持直接把 `int x = 1` 声明放进 if 条件。
- 检查题：`if (int x = 1)` 是本课可使用的 C17 语法吗？
- 判断依据：不是；先声明，再用表达式作为条件，避免混入 C++ 规则。

**I04 每次到达 if 时只据当次条件选择分支**

- 核心结论：一次 if 执行不会因为分支内修改了条件变量，就自动重新判断并切换到另一个分支。
- 检查题：`int x = 1; if (x) x = 0; else x = 2;` 结束后 x 是多少？
- 判断依据：0；else 不会因 x 被修改为 0 而补执行。

#### 比较与逻辑组合

**I05 相等判断与赋值具有不同效果**

- 核心结论：`==` 比较，`=` 赋值且表达式具有赋值后的值。
- 检查题：`int x = 3; if (x = 0) x = 9;` 最后 x 是多少？
- 判断依据：0；赋值发生了，但结果为零，受控语句未执行。

**I06 逻辑与要求两个条件都成立**

- 核心结论：A && B 仅在两者都为真时为真，结果为 int 类型的 0 或 1。
- 检查题：要表达“年龄至少 18 且不超过 60”，应怎样组合两个比较？
- 判断依据：`age >= 18 && age <= 60`；前提是 age 已取得合法值。

**I07 逻辑或表示至少一个条件成立**

- 核心结论：A || B 在任意一个条件为真时为真。
- 检查题：要表达“分数小于 0 或大于 100”，怎样写？
- 判断依据：`score < 0 || score > 100`。

**I08 逻辑非作用于整个被否定表达式**

- 核心结论：! 将真值取反；要否定一个复合判断，需明确括号范围。
- 检查题：“不满足 x 大于 0”应写 `!(x > 0)` 还是 `!x > 0`？
- 判断依据：前者；后者先计算 !x，含义不同。

**I09 逻辑与在左侧为假时跳过右侧**

- 核心结论：&& 的左操作数先求值，为假时右操作数不求值。
- 检查题：`int x = 0; int r = 0 && ++x;` 后 x 是多少？
- 判断依据：0；右侧自增被短路。

**I10 逻辑或在左侧为真时跳过右侧**

- 核心结论：|| 的左操作数先求值，为真时右操作数不求值。
- 检查题：`int x = 0; int r = 1 || ++x;` 后 x 是多少？
- 判断依据：0；右侧自增被短路。

**I11 逻辑与比逻辑或结合更紧**

- 核心结论：没有额外括号时，A || B && C 按 A || (B && C) 分组。
- 检查题：A 为真、B 和 C 为假时，`A || B && C` 是什么？
- 判断依据：真；若意图是 `(A || B) && C`，必须显式加括号。

**I12 位运算与不能替代逻辑与**

- 核心结论：& 对整数位操作，&& 判断真值并短路，两者语义不同。
- 检查题：`4 & 2` 与 `4 && 2` 的值分别是什么？
- 判断依据：0 与 1；不要因某些输入下相同就交换使用。

#### 受控语句与分支结构

**I13 无花括号时 if 只控制紧随的一条语句**

- 核心结论：缩进不改变 if 的控制范围。
- 检查题：`int a=0,b=0; if(0) a=1; b=2;` 后 b 是多少？
- 判断依据：2；b 的赋值不受该 if 控制。

**I14 花括号将多条语句组织为一个分支体**

- 核心结论：复合语句可以让一组动作共同受条件控制。
- 检查题：希望 a=1 与 b=2 仅在条件成立时都执行，应怎样组织？
- 判断依据：写成 `if (condition) { a=1; b=2; }`。

**I15 if 后的孤立分号是空语句**

- 核心结论：`if (condition);` 的受控语句已经结束，后面的块不再属于这个 if。
- 检查题：`int x=0; if(0); { x=1; }` 后 x 是多少？
- 判断依据：1；本例用来识别错误，正常编写应去掉意外分号。

**I16 if 与 else 选择其中一个分支**

- 核心结论：按普通顺序进入 if/else 时，根据条件执行其中一侧。
- 检查题：`int x; if (3>2) x=1; else x=2;` 后 x 是多少？
- 判断依据：1；不会再顺序执行 else 一侧。

**I17 else 匹配最近且语法上可匹配的 if**

- 核心结论：缩进不能将 else 自动绑定到更外层的 if。
- 检查题：`if(a) if(b) x=1; else x=2;` 中 else 属于哪个 if？
- 判断依据：属于 if(b)；需要绑定外层时用花括号明确结构。

**I18 else if 链在首个命中分支后结束选择**

- 核心结论：前面分支已命中时，后续 else if 的条件不再求值。
- 检查题：`if(x>0) a=1; else if(x>10) a=2;` 当 x=20 时 a 是多少？
- 判断依据：1；x>10 一支被前面的宽条件挡住。

**I19 多个独立 if 可以同时命中**

- 核心结论：独立 if 各自判断，没有 else if 链的互斥约束。
- 检查题：`if(x>0) n++; if(x>10) n++;` 当 x=20、n 初值为 0 时 n 是多少？
- 判断依据：2；两个条件都被判断并命中。

#### 范围分类与安全顺序

**I20 数学连写区间不能直接照搬成 C 比较**

- 核心结论：`1 < x < 5` 先算 1<x，随后用其 0/1 结果再与 5 比较。
- 检查题：当 x=9，`1 < x < 5` 与 `1 < x && x < 5` 分别真假？
- 判断依据：前者真、后者假；区间需用两个比较组合。

**I21 相邻分类的端点必须有明确归属**

- 核心结论：区间分支应根据需求确定 <、<=、>、>=，避免阈值遗漏或重复归属。
- 检查题：低于 60 为不及格、60 起为及格，60 应进入哪一类？
- 判断依据：及格；前者使用 `<60`，后者包含 60。

**I22 分类需要覆盖约定的全部输入域**

- 核心结论：只覆盖常见值不足以保证分类完整，需核对剩余合法情况。
- 检查题：整数 x 的分类只写 x>0 和 x<0，漏掉什么？
- 判断依据：x==0；需要独立处理或通过明确的默认分支覆盖。

**I23 有重叠的条件需要按预期优先级排列**

- 核心结论：else if 链的顺序决定重叠范围中的命中结果。
- 检查题：分数 95 应评为优秀，`>=60` 与 `>=90` 哪个应先判断？
- 判断依据：优先判断 >=90，再判断 >=60；或将分支条件改成不重叠的范围。

**I24 危险操作的保护条件必须先判断**

- 核心结论：利用短路保护时，安全前提应放在危险表达式的左侧。
- 检查题：对已有合法 int 值 a,b，`b!=0 && a/b>2` 与反序哪种能先排除除零？
- 判断依据：前者；反序会先执行除法。还需另行排除除法结果不可表示的情形。

#### 分支后的状态与核查

**I25 后续要读取的结果必须在所有可能路径上有值**

- 核心结论：若结果变量没有初值，每条能够到达后续读取位置的路径都应先赋值。
- 检查题：`int r; if(x>0) r=1;` 后直接读取 r，哪条路径有问题？
- 判断依据：x<=0 时没有建立 r 的值；可补默认初始化或对应分支。

**I26 分支中的修改会影响后面的独立判断**

- 核心结论：后续独立 if 使用当时的新状态，不保留最初的输入快照。
- 检查题：`int x=1,n=0; if(x>0) x=0; if(x==0) n++;` 后 n 是多少？
- 判断依据：1；第二次判断读取已被修改的 x。

**I27 边界检查应覆盖阈值两侧与阈值本身**

- 核心结论：核查区间分类时，需要能区分严格与非严格比较的输入。
- 检查题：验证“60 分及格”的边界，最小的相邻整数测试组是什么？
- 判断依据：59、60、61；其他范围与非法输入需要另外检查。

**I28 每条有效路径都要有能命中的检查输入**

- 核心结论：输入样例应覆盖每个分支和缺省路径，不能只测试成功路径。
- 检查题：测试“正、零、负”三分类，只给 1 和 2 是否够？
- 判断依据：不够；至少还需覆盖 0 与负值，并核对预期分类。

### 循环 for

#### 基本执行顺序

**F01 初始化子句在进入循环时执行一次**

- 核心结论：普通顺序进入 for 后，先执行初始化，再开始条件判断。
- 检查题：`int k=0; for(k++; k<3; k++) {}` 中头部的第一个 k++ 执行几次？
- 判断依据：一次；初始化不会在每轮重复执行。

**F02 循环条件在每次循环体前判断**

- 核心结论：条件为假时不进入当次循环体。
- 检查题：`for(int i=3; i<3; i++)` 的循环体执行几次？
- 判断依据：零次；for 不保证至少执行一次。

**F03 正常完成循环体后执行迭代表达式**

- 核心结论：一轮正常经过循环体末尾后，执行头部第三部分，再回到条件判断。
- 检查题：`for(int i=0;i<2;i++)` 的两次循环体开头分别看到哪个 i？
- 判断依据：0、1；i++ 位于每轮正常循环体之后。

**F04 正常结束还需要最后一次失败的条件判断**

- 核心结论：无 break、return 等提前转移且条件正常求值时，执行 n 次循环体对应 n+1 次条件判断。
- 检查题：`for(int i=0;i<3;i++)` 中 i<3 判断几次？
- 判断依据：4 次，依次在 i=0、1、2、3 时判断。

**F05 for 声明的循环变量在循环外不可见**

- 核心结论：`for(int i=0;...)` 中 i 的作用域覆盖该循环的相关部分，不延伸到循环之后。
- 检查题：循环结束后直接用这个 i 是否符合 C17 作用域规则？
- 判断依据：不符合；若结束后确需读取，可在循环前声明，并注意初值与实际执行路径。

**F06 循环外声明的变量保留最终状态**

- 核心结论：在循环前声明 i，则循环结束后可以按实际退出路径读取它。
- 检查题：`int i; for(i=0;i<3;i++) {}` 后 i 是多少？
- 判断依据：3；因条件失败正常结束，不等同于最后一次循环体内的值 2。

#### 可省略部分与循环体

**F07 省略初始化时使用已有状态**

- 核心结论：for 的第一部分可以为空，但相关变量必须已经有合法值。
- 检查题：`int i=2; for(;i<4;i++)` 访问哪些 i？
- 判断依据：2、3；省略初始化不等于自动从 0 开始。

**F08 省略条件表示不由头部条件终止**

- 核心结论：for 省略第二部分时，视为持续成立的控制条件，需通过其他明确方式结束。
- 检查题：`for(;;)` 会因“条件没写”自动执行零次吗？
- 判断依据：不会；本样板只作静态辨析，不运行无退出的演示。

**F09 省略迭代表达式不意味着自动递增**

- 核心结论：头部第三部分为空时，状态推进必须由其他代码完成。
- 检查题：`int i=0; for(;i<3;) { ++i; }` 是否能够正常结束？
- 判断依据：能，i 由循环体推进到 3；删除该推进则无法按预期计数结束。

**F10 省略内容仍需保留头部两个分号**

- 核心结论：for 的三部分由两个分号分隔，空部分不删除分隔符。
- 检查题：三个部分都省略时，正确头部是什么？
- 判断依据：`for(;;)`，不是 `for()`。

**F11 无花括号时 for 只控制一条语句**

- 核心结论：多条循环动作需要组成复合语句，缩进不改变循环体范围。
- 检查题：`for(i=0;i<3;i++) a++; b++;` 中 b++ 执行几次？
- 判断依据：一次；只有 a++ 是循环体，假设循环正常完成且变量已初始化。

**F12 for 头部后的分号可以构成空循环体**

- 核心结论：`for(...);` 的循环体是空语句，后面的块在循环结束后另行执行。
- 检查题：`int i,n=0; for(i=0;i<3;i++); {n++;}` 后 n 是多少？
- 判断依据：1；该分号在语法上有效，是否正确取决于意图。

#### 遍历范围与次数

**F13 从零开始的小于 n 遍历 n 个位置**

- 核心结论：当 n 是非负 int 且状态按每轮加一推进，`i=0;i<n;i++` 访问 0 到 n−1。
- 检查题：n=4 时访问哪些值？
- 判断依据：0、1、2、3，共 4 次；n=0 时为空。

**F14 闭区间的两个端点都要计入**

- 核心结论：在范围可表示且无更新溢出的条件下，从 1 到 n 含两端的循环应包含上界 n。
- 检查题：n=4，`i=1;i<=n;i++` 访问哪些值？
- 判断依据：1、2、3、4；不要机械把所有 <= 都判为错误。

**F15 非零起点改变循环次数**

- 核心结论：在 b>=a 且相关算术有定义时，步长 1 的 [a,b) 遍历次数为 b−a。
- 检查题：`i=3;i<7;i++` 执行几次？
- 判断依据：4 次，访问 3、4、5、6。

**F16 正步长可能跳过范围内的部分值**

- 核心结论：步长大于 1 时，访问起点加若干步长得到且仍满足条件的值。
- 检查题：`i=0;i<7;i+=2` 访问什么？
- 判断依据：0、2、4、6，共 4 次；不是 7 次，也不是简单取 7/2 的整数商。

**F17 倒序遍历需要匹配终止条件**

- 核心结论：对足够范围的有符号 int，`i=3;i>=0;i--` 能访问 3 到 0 后结束。
- 检查题：访问完 i=0 后，下一次判断看到什么值？
- 判断依据：−1，条件失败；此例不适用于无符号 i。

**F18 空范围应自然执行零次**

- 核心结论：起点已经不满足条件时，应按任务允许的空范围处理，而非访问不存在的首元素。
- 检查题：长度 n=0 时 `i=0;i<n;i++` 会读取第零项吗？
- 判断依据：不会进入循环体；循环外若读取首项，仍需单独检查 n。

#### 循环控制转移

**F19 continue 跳过本轮剩余语句后进入迭代表达式**

- 核心结论：在 for 中执行 continue 后，先转向头部第三部分，再检查下一轮条件。
- 检查题：`for(int i=0;i<4;i++){if(i==1)continue;sum+=i;}` 且 sum 初值为 0，结果多少？
- 判断依据：5，累加 0、2、3；continue 没有跳过 i++。

**F20 break 退出最内层可退出结构**

- 核心结论：break 结束最内层包围它的循环或 switch；仅嵌套循环时不会直接退出外层循环。
- 检查题：双重 for 的内层执行 break，外层会直接结束吗？
- 判断依据：不会；若中间还包着 switch，需重新识别 break 实际退出的结构。

**F21 break 不执行被退出 for 的迭代表达式**

- 核心结论：break 从该循环体直接退出，不再走该 for 的头部第三部分。
- 检查题：`int i; for(i=0;i<5;i++){if(i==2)break;}` 后 i 是多少？
- 判断依据：2，不是 3。

**F22 return 会结束整个当前函数**

- 核心结论：循环体中 return 的退出范围是函数，超过单个循环。
- 检查题：在函数的 for 内 return 后，函数中位于循环之后的语句还执行吗？
- 判断依据：不会；需要只退出循环时应考虑 break。

**F23 嵌套循环中的 continue 只作用于最近循环**

- 核心结论：内层 continue 开始内层循环的后续推进，不自动跳到下一轮外层。
- 检查题：外层 i 循环中包着内层 j 循环，j 循环执行 continue 后先更新谁？
- 判断依据：内层 for 的迭代表达式，通常是 j；外层不会因此立即推进。

#### 循环状态与常用操作

**F24 累加器应在需要的累计范围开始前初始化**

- 核心结论：需要跨多轮保留总和时，累加器不能在每轮重置。
- 检查题：计算 1+2+3，sum=0 放在循环体每轮开头会怎样？
- 判断依据：之前的累计被清空；正常完整遍历后只留下最后一轮对应的 3，而不是 6。

**F25 计数器只在目标事件发生时递增**

- 核心结论：统计满足条件的项时，计数更新要放在该条件成立的路径内。
- 检查题：统计 1 到 5 的偶数，cnt 应何时加一，最终多少？
- 判断依据：仅在 i%2==0 时加一，结果为 2。

**F26 非空集合求最大值可从首个有效值初始化**

- 核心结论：将最大值初始为 0 会对全负集合产生错误；需选合法初始依据。
- 检查题：数据为 −5、−2、−8，max 初值为 0 会返回正确结果吗？
- 判断依据：不会；用首个有效值 −5 初始化再比较，可得到 −2；空集合需另行处理。

**F27 乘积累积通常从乘法单位元一开始**

- 核心结论：计算一段数的乘积时，初值 0 会把结果始终压成零。
- 检查题：计算 1×2×3，product 的自然初值应是什么？
- 判断依据：1，结果为 6；具体空集合约定由题目明确。

**F28 搜索结束后必须区分找到与未找到**

- 核心结论：找到时可记录位置或标记并退出；遍历结束不自动意味着成功。
- 检查题：搜索值不存在时，能否直接使用上一次记录的结果变量？
- 判断依据：不能；开始前建立“未找到”状态，找到时更新，结束后先检查该状态。

#### 嵌套循环

**F29 每次进入内层 for 都重新执行其初始化**

- 核心结论：内层循环完整结束后，外层下一轮重新进入它，会再次执行其第一部分。
- 检查题：外层两轮、内层 `j=0;j<3;j++`，第二轮外层的 j 从哪里开始？
- 判断依据：从 0 开始，而不是延续上一轮结束时的 3。

**F30 固定矩形嵌套的次数可相乘**

- 核心结论：外层 m 轮且每轮内层固定 n 次、无提前退出时，内层循环体共 m×n 次。
- 检查题：两轮外层、每轮三次内层，共执行几次内层动作？
- 判断依据：6 次；内层范围随外层变化时不能直接使用这个乘法。

**F31 变化上界的嵌套需要逐层累计次数**

- 核心结论：内层次数依赖外层变量时，总次数是各轮内层次数之和。
- 检查题：外层 i 从 0 到 3，内层 `j=0;j<i;j++`，内层动作总次数多少？
- 判断依据：0+1+2+3=6 次。

**F32 每组独立统计的状态在组开始时重置**

- 核心结论：每行或每组需要独立总和时，初始化应放在外层循环体内、内层之前。
- 检查题：要分别求两行的和，row_sum 应在哪一层清零？
- 判断依据：每次进入新一行时清零；若只在全部行之前清零，会把前一行带入下一行。

#### 终止性与数值边界

**F33 无符号倒序不能用 i>=0 作为停止条件**

- 核心结论：无符号值始终非负，减到零之后继续减会发生无符号回绕。
- 检查题：`unsigned int i=3; i>=0; i--` 能靠该条件正常结束吗？
- 判断依据：不能；此条件始终成立，需要改写倒序结构。只作静态辨析，不运行无界循环。

**F34 状态推进必须有机会让条件变假**

- 核心结论：如果控制状态一直不变且条件持续为真，循环不能按预期终止。
- 检查题：`i=0;i<3;i+=0` 的推进问题是什么？
- 判断依据：i 始终为 0；应采用符合遍历目标的非零推进或明确退出机制。

**F35 循环体修改控制变量会改变遍历序列**

- 核心结论：当循环体与头部都更新 i 时，实际步长由两处更新共同决定。
- 检查题：`for(int i=0;i<6;i++){记录i; i++;}` 记录哪些值？
- 判断依据：0、2、4；不是 0 到 5 的逐项遍历。

**F36 最后一次迭代后的更新也必须可表示**

- 核心结论：包含整数类型最大值的闭区间循环可能在最后一次循环体之后自增溢出。
- 检查题：`for(int i=INT_MAX-1;i<=INT_MAX;i++)` 有什么问题？
- 判断依据：处理 INT_MAX 后的 i++ 会产生有符号溢出；不能因为业务值都合法就忽略更新操作。

**F37 浮点累计误差会影响循环终点判断**

- 核心结论：在使用近似表示的浮点环境中，以小数反复递增可能不精确落到预期终点。
- 检查题：要求严格执行十次操作，是否应优先用“加 0.1 直到等于 1.0”？
- 判断依据：不应依赖这种精确相等；用整数次数控制，再按次数计算需要的浮点值。

## 颗粒度的实际落点

“for 循环执行过程”仍是分组。初始化一次、循环体前判断、正常完成后更新、正常退出前的失败判断分别是叶子；break 与 continue 对后续执行的影响还要单独判断。这样学生答错时，才有可能区分他不清楚哪一步，而不是笼统归为“不会循环”。

“类型转换”仍是分组。整数除法、赋值时转换、显式转换发生位置、浮点转整数、有符号/无符号混合比较分别形成不同叶子。若实际课程只要求入门子集，可将更复杂转换标为进阶；不为保持目录好看删掉课程明确要求的内容。

叶子的检查题只产生一次具体理解证据。做对一道题不自动等于掌握；正式掌握判断应结合变式、解释及实际任务。错误代码与未定义行为采用规则辨析或编译诊断，不以某次机器运行结果宣布语言规则。
