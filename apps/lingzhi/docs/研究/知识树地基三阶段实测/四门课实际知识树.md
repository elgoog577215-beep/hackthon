### 元知识与原文

#### P1 列表赋值不复制

对列表执行赋值 b=a 会使 b 和 a 指向同一个列表对象，该操作本身不会复制列表的内容。

元问题：列表赋值操作是否创建了新列表？

核心回答：不创建新列表，两个名字指向同一对象。

条件：a 和 b 是列表变量；执行赋值语句 b=a

边界：未另列；另见关联附件

- 原文 `M1 / C1`：赋值b=a使两个名字指向同一列表，不会复制列表。
- 附件 `boundary / C9`：只讨论这些普通列表操作。

#### P2 共享列表内容修改同步

当两个名字指向同一列表时，通过其中一个名字对该列表对象进行内容修改，另一个名字访问时会观察到同一对象的变化。

元问题：修改共享列表的内容时，另一个引用该列表的名字能否看到变化？

核心回答：能看到，因为它们指向同一对象。

条件：两个名字指向同一列表对象；通过其中一个名字修改列表内容（非重新绑定名字）

边界：未另列；另见关联附件

- 原文 `M1 / C2`：通过其中一个名字修改该列表，另一个名字会看到同一对象的变化
- 附件 `boundary / C9`：只讨论这些普通列表操作。

#### P3 变量重新绑定独立性

当 b=a 时，将 b 重新绑定到一个全新的列表上，不会使 a 指向新列表，a 仍保持指向原来的列表对象。

元问题：重新绑定变量 b 到新的列表后，原变量 a 的指向会发生改变吗？

核心回答：不会，a 仍指向原列表，b 指向新列表。

条件：初始状态 b 和 a 指向同一列表；执行 b = 新列表 操作

边界：未另列；另见关联附件

- 原文 `M1 / C3`：将b重新绑定到新列表不会重新绑定a。
- 附件 `boundary / C9`：只讨论这些普通列表操作。

#### P4 浅拷贝创建新外层

调用 a.copy() 会创建一个新列表，这个新列表是原列表的浅拷贝，其外层列表对象与原列表不同，但内部元素是原元素的引用。

元问题：list.copy() 操作创建的是深拷贝还是浅拷贝？其外层和元素的关系如何？

核心回答：创建浅拷贝，外层是新对象，元素引用原对象。

条件：a 是列表；调用 a.copy() 方法

边界：未另列；另见关联附件

- 原文 `M2 / C4`：a.copy()新建外层列表
- 附件 `boundary / C9`：只讨论这些普通列表操作。

#### P5 浅拷贝外层独立性

对 a.copy() 返回的新外层列表执行 append 操作，不会影响原外层列表的内容。

元问题：在浅拷贝的列表上添加元素，原列表会增加该元素吗？

核心回答：不会，原列表外层内容不变。

条件：b 是 a 的浅拷贝 (b = a.copy())；对 b 执行 append 操作

边界：未另列；另见关联附件

- 原文 `M2 / C5`：对新外层append不改变原外层。
- 附件 `boundary / C9`：只讨论这些普通列表操作。

#### P6 嵌套元素共享引用

对于包含嵌套列表的列表，使用浅拷贝后，新列表中的对应元素仍然引用与原列表完全相同的内层列表对象。

元问题：浅拷贝列表中嵌套的子列表对象，与原列表中的子列表对象是同一个吗？

核心回答：是同一个，引用相同。

条件：原列表包含嵌套列表；执行浅拷贝操作

边界：未另列；另见关联附件

- 原文 `M2 / C6`：对于嵌套列表，浅拷贝的对应元素仍引用同一个内层列表
- 附件 `boundary / C9`：只讨论这些普通列表操作。

#### P7 共享内层修改同步

如果一个内层列表被原列表和浅拷贝后的列表共同引用，对该共享的内层列表执行 append 操作，两个外层列表都能观察到该内层元素的变化。

元问题：修改浅拷贝列表中嵌套的子列表，原列表中的对应子列表会变化吗？

核心回答：会变化，因为内层对象是共享的。

条件：原列表和浅拷贝列表共享同一个内层列表对象；对该共享的内层列表执行 append 操作

边界：未另列；另见关联附件

- 原文 `M2 / C7`：对共享内层append会同时从两个外层观察到变化。
- 附件 `boundary / C9`：只讨论这些普通列表操作。

#### P8 浅拷贝元素重新绑定独立性

对浅拷贝后的列表 b 的某个元素（如 b[0]）重新赋值为一个新的列表，这个操作只会修改 b 的对应元素引用，不会改变原列表 a 的对应元素（a[0]）。

元问题：将浅拷贝列表中某个嵌套元素替换为新列表，原列表的对应元素会变吗？

核心回答：不会变，只改变了浅拷贝列表中的引用。

条件：b 是 a 的浅拷贝；对 b[i] 执行 b[i] = 新列表 操作

边界：未另列；另见关联附件

- 原文 `M2 / C8`：对浅拷贝的b[0]重新赋一个新列表，只改变b的该元素引用，不改变a[0]。
- 附件 `boundary / C9`：只讨论这些普通列表操作。

```text
│  ├─ 史料背景变量 [P2]

│  └─ 立场材料价值 [P4]
├─ 互证逻辑与矛盾处理

│  ├─ 转载独立性判定 [P6]
│  └─ 矛盾处理流程 [P7]
└─ 推论限制与结论表达

   ├─ 有限来源推论限制 [P9]
   └─ 结论表达结构 [P10]
```

### 四项复核

- 准确性：主要规则忠实；结论强度措辞需收紧
- 颗粒度：比前轮清楚，仍有三个复合点
- 结构：分类合法，P8应移动到矛盾处理组
- 覆盖：12/12要求有承载；A/B/C及缺证据保留为案例附件

### 待修订

- `P1`：区分观察/推断与为推断提供依据是两项独立要求，仍合成一个元问题。
- `P5`：来源独立性与对象/时段可比性仍合并，应拆为不同核查维度。
- `P8`：数量投票和预设立场两条禁止推断仍合并；拆开可避免后续再次混成一个错因。
- `P9.statement / disposition.C9`：“结论强度”被写成“可信度强度”，映射理由又称数量与强度的对应规则；材料并未给出数量到可信度的定量或单调关系。
- `P10`：“可以说什么”改成“可以确定什么”，容易提高证据承诺；应保留可支持的主张及不确定性原意。
- `P8.parent`：真假判断禁区归入推论限制与结论表达，与同组其他点维度不一致；更适合互证逻辑与矛盾处理。

#### P8 定真假禁区

判断史料的真假时，禁止依据持有该史料的来源数量进行“投票”，也禁止依据预设立场来判定。
