# 微积分知识树生成链路修复

日期：2026-10-20。范围：本讲讲义提取、内容核对、表达校验、主动继续、显示装配和下游分类关系。改善阶段目标中的“将学习表现关联到稳定的具体知识”，本轮只验证知识生产与恢复，不验证学生诊断或教学效果。

## 原因与职责调整

用户本地微积分第 2 讲卡在 70%，第 6 批已有完整的内容核对响应，但“瞬时速度的极限定义”只是属性名。异常在内容核对内部抛出，没有进入定点修正；主动继续又清除有效核对并重做整批核对。因此，单纯点击继续或改提示词不能保证恢复。

| 链路问题 | 修复后的责任 |
| --- | --- |
| 语义核对与名称质量异常混为一次成功/失败 | 先保存结构完整的核对，表达错误单独标记待修；无效名称仍不能编译成完整候选 |
| 定点修正只诊断语义槽位 | v4 同时诊断名称；只有表达错误时仅允许 rename，完整知识、公式、条件和来源冻结 |
| 主动继续丢失有效核对 | 新子任务以提取、来源、上下文和协议指纹复用完整核对；格式损坏或来源变化仍拒绝复用 |
| 本次失败反馈被归到过去的模型输入 | 原核对保留真实原输入；新反馈只进入本次修正，分别记录来源 |
| 字符检查混淆记号与自由量 | 先识别匹配阶数的微分算子、明确单位字段及单一关系属性；其他自由量和独立属性仍检查 |
| 公式显示删除了对象 | v4 显示“法线：x=a”“垂直切线：x=a”，不同条件下的两个知识不再被程序转成同名；不借重名合并知识 |

新任务冻结 `knowledge_validation_pipeline_v4`，定点修正使用 `knowledge_correction_plan_v3`。原提取形态和表达合同不变。主动继续失败的 v3 表达任务时记录升级来源，原任务保留；旧的其他合同不静默切换。完成旧批次只在副本装配时调整公式显示，保留原提取、核对、修正及语义身份，不增加模型请求。

## 验证

- 先补失败测试，再实现；相关后端回归 **261 项通过**；补齐过程预览与最终树的一致显示后，受影响的 **86 项通过**。Ruff 致命错误检查通过。
- 隔离副本使用原授权 `qwen3.8-27b`，复用原失败任务的 9 个完成批次；第 6 批仅一次请求修正名称，语义点逐字段保持不变。
- 全讲另外一次原有冲突对账，随后完成同义核对、分类和关系，进度到 **100%**，生成 **75 个候选点**。共 18 次真实请求，其中重新提取和重新内容核对均为 0 次。
- 隔离运行校验原失败任务、课程正文、讲义和实际用户数据文件均未改变；未采用候选。
- 隔离首轮在下游发现“公式显示丢对象”造成重名，原始失败与修复后的第二轮分别保存，没有人工改写模型知识或覆盖原响应以凑通过。

本地网站使用的原数据目录已确认并在仓库外备份，备份内容逐文件验证。后端从已提交代码快照启动，通过原拥有者身份和原 API 继续失败任务。该次任务已到 **100%**，保存 **76 个候选点、34 个分类、14 条关系**，校验报告无待处理问题。18 次真实请求均为必要修正与下游处理，提取和内容核对请求均为 0；9 个完成批次的提取、核对和修正原记录一致，名称修正未改语义点。备份对照确认原 16 个任务、课程文件和讲义不变，候选未采用。

浏览器实际检查了原网站的完成状态、76 点层级树、14 条关系计数；搜索并打开原卡点对应的瞬时速度知识，完整极限公式、适用条件及来源均可读取，冻结原文接口 200 且 `available=true`，无页面异常。过程预览与最终装配共用保留对象的公式显示规则，旧检查点不改写。后端代码快照与原数据目录均记录在仓库外运行清单，前端沿用原验收实例，未推送或部署到线上。

依赖审计仍报告已有核心模块及学习路由循环导入，本轮未顺带重构。未运行全量后端、生产或真实学生效果验收。所有语义回执保持 `semantics_verified=false`；结构通过、同一模型的再次核对及生成完成均不等于独立学科认证。
