# 知识树三组千问实测

日期：2026-10-11。目标：按[课程知识树规格](../功能设计/课程知识树.md)讨论的生成、分项检查、一次局部修正流程，实际调用现有千问，观察 C17 类型转换、if 配对和 for 控制流三个主题的质量。

## 结论

当前流程可以自动生成结构化候选和修正部分问题，但不满足直接作为正式知识与术语基线的条件。首轮 27 个候选点经过一次自动修正变为 28 个；按本次元知识标准由 Codex 复核，仍有 13 个需要拆分或重分类。15 条最终关联中有 4 条的方向或前置依据需要修订；8 条易错候选均未达到区分不同错误原因的完整诊断合同，其中还保留了具体题目错误。

同模型自审倾向于认可原结果，且修正会引入新错。最明确的新错是把 `short x = 300; /* 假设 short 为16位 */` 当成有符号越界转换例子，给出“不确定、取决于实现”的预期；实际这个值处在所声明范围内。不能将“JSON 有效、自审认为质量较高、修正任务完成”当作可采用证明。

本轮完成隔离实验和证据保存，没有写入真实课程、启动课程生产任务、修改模型配置、调用外部文本兜底或发布。

## 实验边界与方法

- 模型请求：现有 `AIBase` 主路由的 `qwen3.8-27b`，沿用当前关闭思考的配置。供应端身份按项目配置与调用记录确认，本轮不推断服务内部模型权重。
- 输入：三组课程目标及人工编写的 C17 教学参考摘记，不含原先 119 条知识树答案。材料明确提供相关规则，包含平台条件与 for 尾部 switch 区别，用来测试组织、原子化、覆盖与教学内容生成；不是从题目名称无资料自由生成，也不是用户实际教材。
- 预先冻结：11 个类型转换、9 个 if、14 个 for 覆盖单元，共 34 项；文件 SHA-256 在首个模型调用前保存，结束后核对未改动。
- 执行：每组一次生成、一次同模型检查、最多一次修正；三组均执行了修正，共 9 个逻辑调用、9 个物理请求，串行，无隐藏服务重试。
- 修正输入仅使用千问自己的检查意见与其报告的 partial/missing 项；没有把 Codex 另外发现的错误和保留测试答案喂给修正阶段。这一设置用于观察自动流程本身的能力，不能将最终评估理解成人工已修好内容。
- 评估：代码检查结构与引用；千问自审按四维输出；Codex 再逐项核对具体命题、例子、关联和错误解释，并对选定代码做编译/运行取证。Codex 复核不是盲审，也不是学科教师金标准。
- 保留测试：12 个未进入生成、审查、修正提示词的变式，其中 11 个有定义的可运行程序在 GCC 10.2.0 的 C17 模式、O0/O2 下共 22 项核验通过；另一个越界行为区分题只作静态核对。这是核验参照答案，不是千问答对 12 题的成绩。
- 未测试：全课程生成、多次独立重复、不同温度或思考配置、真实教师审阅、完整讲义/PPT 联动及生产环境验收。

原始实验目录位于 `本机私有目录/.codex_tmp/knowledge-tree-qwen-20261011-01a128a6`，运行数据留在仓库外，凭据只在内存读取，未写入实验文件。公开可检查的规格、样板与本报告仍在原文档目录。

## 四维质量复核

覆盖只衡量冻结清单中的命题是否明确出现，**不等于检查题正确、诊断有效或课程整体准确率**。covered/partial/missing 的逐项依据保存在 `independent-assessment.json`；partial 包括规则只隐含在例子、必要边界缺失、矛盾陈述或只出现在错误解释中。

| 主题 | 命题明确覆盖前后 | 最终部分覆盖 | 最终需拆分/重分类 | 最终需修订关联 | 完整区分性诊断合同 |
| --- | --- | ---: | --- | --- | --- |
| 类型转换 | 8/11 → 9/11 | 2 | 4/10 | 2/3 | 0/3 达标 |
| if 配对 | 6/9 → 6/9 | 3 | 3/6 | 1/3 | 0/2 达标 |
| for 控制流 | 11/14 → 12/14 | 2 | 6/12 | 1/9 | 0/3 达标 |
| 合计 | 25/34 → 27/34 | 7 | 13/28 | 4/15 | 0/8 达标 |

“需拆分/重分类”是依据本次规格的教学判断，不是通过节点数量自动得出的客观分数。“易错合同未达标”不表示所有错误假设都是错的：多数假设可理解，但候选普遍将正确答案或原错误的复述放进 alternative_explanation，并未区分两种能造成同一表现的原因。

### 颗粒度仍然偏粗

- 类型 `p3` 混合 int/double 共同类型、两个 int 的结果类型及整数商截断；`p10` 混合赋值转换时机、显式转换位置与原变量不改变。
- 类型修正后的 `p1` 为补字面量覆盖，将字面量类型又塞入整数提升，stop_reason 明确辩称合并后仍可独立检查。覆盖补了一部分，原子性反而变差。
- if `p1` 将真假解释和一次选择后不重选混合；`p5` 同时讲语法嵌套与后续条件不求值；`p6` 同时讲独立判断和状态读取。
- for `p1` 将初始化、判断、循环体、更新整套流程判作一个最小点；`p2` 将三个省略规则和分号合并；`p5` 混合名字作用域与退出值；`p6` 混合多个控制转移目标。
- 千问的逐点审查没有提出任何 split 决定。它会在停止理由中解释“这些内容很重要/相关”，但尚未有效运用“可以分别掌握和分别出错”的标准。

### 覆盖补漏有作用但不能信自报完成

首稿类型转换未单列字面量规则，for 漏掉了 return，虽然它们都在输入材料中。修正补入字面量描述和 return 节点，但类型新增描述写成“无后缀十进制常量为 int”，丢掉“可由 int 容纳”的条件；for 的 n+1 次判断仍没有明确知识/检查。

if 的一般单语句体规则不足，外层未进入时跳过全部内层结构主要留在易错说明中；空语句节点错误地将“后续没有花括号”列为条件，未覆盖后续独立块。for 零次执行节点将“首次为假”与“省略后恒真”并列，产生矛盾表述。

三个首稿的 gaps 都为空，不能据此宣称没有缺口。千问自审还在 for 覆盖表中引用了并不存在的 `p14`，在 if 的 point_ids 中放入易错记录 `m1`；审查结果本身也必须检查引用类型和存在性。

### 关联主要问题是强前置与方向

- 类型 `r2` 的理由是“混合运算确定要转无符号时，需要模数规则计算数值”，但 applies_to 的指向却是混合转换点 → 模数规则。按规格“源规则应用到目标”的含义，方向相反；自审仍判 supported。
- 类型 `r1` 把窄整数提升设为本例所有 int/double 转换的 required 前置，依赖程度过强。
- if `r1` 把真假求值作为语法判断 else 配对的 required 前置，混淆了语法归属与执行结果分析。
- for `r2` 将省略子句作为首次条件为假/零次循环的前置，理由不足。
- 正面结果：if 自审指出空语句与嵌套配对之间的对比理由牵强，修正后删除了该边；continue/break、break/return 的直接对比有清晰用途。

强度均在允许的三档中，没有不加说明地生成 0.93 等细分值。按合同应为空的置信度未被填入虚构概率，但新增 for `r9` 省略了 confidence 字段，而非显式 null；当前基础检查未将该序列化差异视为错误，正式 Schema 仍需明确必填规则。

### 易错诊断与复测最弱

- 类型 `m1` 将“按字节回绕”的表现写成 200+100 赋给 int 得到 100；这不能由给定错误信念直接推出。其复测把整数常量相加后存 unsigned char，也无法区分运算提升与存储转换的两种理解。
- if `m2` 要求在 b 为真时填入 `else puts(3)` 打印 3，实际该 else 不会执行。整数参数传给 puts 还违反类型约束。自审标为 usable，自动修正保留。
- for `m1` 在 for 头部声明局部 i，却询问整个循环结束后 i 是 0 还是 1，忽略变量已离开作用域；复测重复此问题。自审同样标为 usable。
- 多数 alternative_explanation 实际写的是正确原理或同一错误信念的来源，诊断题只是再次问对错，缺少区分两种错误原因所需的不同预测。
- origin 都保留 model_hypothesis，未伪造具体学生记录；但自审说明使用“真实且常见”等词语，没有本轮数据支持这些频率判断。

## 评测工具自身的一处修正

第一版结构检查把 for `p3` 的 `expected=""` 判成 missing_check，但这个程序本来就没有输出，属于合法的空输出预期。已将检查改为“字段存在且为字符串”，原始误报、修正说明和重算结果分别保存，没有覆盖原证据。

已经启动的同模型审查进程仍读到了原误报；它判断该提示可能误报，没有要求修复不存在的字段。最终基础树结构与引用检查采用重算结果，三组前后都通过。这里的基础检查不等同于完整 JSON Schema 或语义验收。

## 下一轮建议

1. **原子化单独产生决定。** 要求每个拟保留点给出可独立检查的一个主要目标，拟拆分点给出各子问题；用已核准的复合点/原子点正反例测误拆与漏拆。本轮不能以补字段代替这一步。
2. **代码和边界交给确定性检查。** 有定义的代码检查题在受控环境运行；类型和作用域约束做编译诊断；平台相关命题要求明确 CHAR_BIT、范围或浮点模型。UB 题只验证分类和依据。
3. **关系逐边判断方向与必要性。** 把“如何从源知识帮助目标”写成明确合同，输出 required 的实际依据；删去仅因相邻、同类或措辞相似建立的边。
4. **易错题要求两个原因产生不同预测。** 同时给出假设 A、假设 B、追问及二者预期回答；无法形成差异就不能声称可区分。复测必须附正确判断。
5. **修正改用受限差量。** 明确允许修改的节点/字段，未涉及部分校验指纹；本轮重新输出整份 JSON 改坏了未指定的 p6。修正后重新做本地检查和受影响内容复核，不能以请求完成替代通过。
6. **保留本次失败样例作为回归，另外留新题验证泛化。** 本轮没有调整提示词后反复采样挑最好结果，也没有估计稳定性；下轮需要区分提示词改进效果与偶然波动。
