## 已交付的能力

| Spec | 首版实现 | 关键保护 |
| --- | --- | --- |
| C1 正文辅学 | 正式课程与个人讲义共用原位/完整展示容器，快捷操作、追问、收起及返回保留同一会话、草稿和在途响应 | AI 回复不进入教材引用；原文定位排除辅学内容；切换展示不重复请求；旧来源宿主移除时回完整界面 |
| C2 持续主线 | 总体目标、目的/期限/可用时间、按现有可读讲次与目的生成的阶段安排，预览后采用，可延后/恢复；本人约定记忆可纠正、停用，原问答与相关帮助决定承接历史；单一课程来源材料读取本人原课程主线，材料目标单独管理 | 临时提问不修改总体目标；计划不另计完成分；冲突重读保留目标草稿；相同待确认命令重用请求身份 |
| C3 画像到教学动作 | 正式画像与精确知识修订选择一种教学动作，学伴会话可明确请求解释、辨析、一步提示或独立检查 | 未知不诊断，提供过帮助不算掌握；独立检查只选择质量通过、精确绑定且本人未做过的新题，无题保持待验证；后续表现读取原正式尝试，不虚构效果 |
| C4 主动程度 | 本人全局轻主动/仅提问偏好；前后端共同保护，正常阅读不打断；稍后/不再提醒以事项持久保存，支持显式恢复 | 仅提问不自动检查笔记、不计算主动建议；加载失败/存储损坏不启用默认主动；输入、作答、讨论、隐藏或预览期间不插入；欢迎语不遮挡正在进行的辅学 |
| C5 教师反馈 | 原发布面板增加版本/时间范围、授权名单分母、共性关注点及原作答下钻；目标摘要明确分享/撤回；选择关注点后进入原生成与审阅流程 | 版本不混算、回执去重、未知与无数据分开；私人笔记/对话/个人讲义不发送；发送前复核摘要授权和修订，旧排队摘要不能绕过撤回；生成候选不自动采用或发布 |

阶段安排首版按课程已有内容及目的形成可调整主线，沿原继续学习、画像和练习提供支持；没有实现或声称复杂长期排程、经校准的能力概率、自动跨课程人格推断。知识树生成与本批并行，只消费已采用身份/修订，不修改生成合同、恢复机制或其来源内容校验策略。

## 实际代码与接口

- `backend/companion_learning.py`：目标、计划、明确记忆、偏好和教学决定；交互元数据通过原 `AITeacherRepository` 保存。画像、作答、教材仍由原仓储负责。`ai_teacher_state.py` 增加跨进程文件锁及同线程嵌套事务对账，防止并发修订覆盖。
- `backend/routers/companion_learning.py`：经过 `study_identity` 验证的偏好及课程/个人材料上下文 API，不接受请求体声明的本人身份；课程读取复用已有授权，个人材料检查真实拥有者和来源访问。
- `study_dialogues.py`、`ai_teacher_context.py`、`study/assistant.py`：将保存的主线与有依据的教学决定接入真实问答；私人材料仍按本人、材料及修订隔离。
- `backend/companion_teaching_feedback.py` 与原 `course_exchange`：只读正式回执投影、最小摘要及撤回；底层传输通过应用层注入的校验函数核对摘要授权，不导入上层画像服务形成新循环。
- `CompanionPlanPanel.vue` / `companionPreferences.ts`：管理主线、阶段预览/采用、记忆、偏好与分享；`StudyDialoguePanel.vue` 提供四类动作和原练习入口；`TeacherLearningConcerns.vue` 接原发布面板与 `CourseEvolutionWorkspace`。

新增 API（均保留原路径和消费者）：

| 方法与路径 | 用途 |
| --- | --- |
| `GET/PATCH /api/study/companion/preferences` | 本人持久主动偏好，预期修订与幂等身份 |
| `GET/POST /api/courses/{course_id}/learning-records/companion` | 当前课程的目标/计划/记忆与命令，读取原画像/进度/后续表现 |
| `GET/POST /api/study/materials/{material_id}/companion` | 本人个人讲义的同类上下文，保持独立作用域并读取获授权的单一来源课程主线 |
| `GET/POST .../learning-records/companion/suppressions` | 当前课程的语义事项抑制与显式恢复 |
| `POST .../learning-records/companion/check-target` | 校验当前会话及知识修订，寻找未用过的合格题目；只返回定位，不暴露答案 |
| `GET /api/teacher/courses/{course_id}/exchange/learning-analysis` | 授权班级关注点、时间/版本/分母与证据 |
| `POST /api/study/courses/{course_id}/exchange/learning-summary` | 明确分享或撤回最小摘要，复用发送箱与回执 |

没有新增文本提供方；模型仍是既有浙大 `qwen3.8-27b`。没有增加产品依赖或自动迁移正式数据。

## 真实模型和浏览器

隔离运行使用仓库源码、独立数据与端口 8036/5196。资料、课程、学生与班级回执均为明确自编或合成验收对象；没有操作知识树任务使用的课程、服务或正式学习记录。

1. 真实 API 验证保存总体目标、预览后采用计划、保存本人偏好及个人记忆、跨读取恢复；个人讲义向原 Qwen 发起“一步提示”，持久任务完成，重读不重复创建任务。
2. 外部无头 Edge 在中文/英文桌面走通个人讲义和学生自有课程两条真实前后端路径。主动模式刷新后保留，正文/完整讨论切换保留未发送草稿，明确 step 动作通过真实模型返回。检查并修正了欢迎气泡遮挡正在辅学、跨课程未完成保存阻塞新课程操作的问题；迟到响应不能覆盖新课程状态。
3. 教师关注点在真实 API 和浏览器展示合成的三人名单及两人的正式回执。明确选择关注点后，原课程调整服务调用真实 Qwen 生成教学修改分析计划，并打开原修改工作区第 2 步“审阅修改方案”；教师确认范围后沿原流程生成内容候选，没有自动采用、改正式教材或发布。
4. 教师自编验收课最初缺少 canonical 状态和知识契约，原准入先后拒绝，两次失败未绕过或隐藏。仅对该隔离课建立并核验备份，使用原显式迁移工具与自编知识合同补齐后，再完成真实模型分析和浏览器衔接；未迁移其他课程。

中英文计划、原位辅学、教师关注点及候选审阅截图均已查看。可重跑的教师界面隔离入口为 `frontend/e2e/teacher-concerns.html`，合成接口衔接脚本仍为 `frontend/e2e/reading-companion.cjs`；前者需指定已准备好的隔离课程，不能指向正在工作的正式课程运行生成实验。
