# 共享上下文接回与四课千问对照

日期：2026-10-11。结论：原课程链路的共享上下文与冻结证据已接回知识树任务输入；本轮结构合同和部分知识拆分改善，题目语义引用与错因诊断仍未达标，不能据此自动采用四课候选。

## 接入内容

新增 `backend/course_knowledge_context.py`，实际复用原 `course_pedagogy` 的画像与教学模块、`material_evidence.build_evidence_units`、`evidence_package.freeze_evidence_package` 和 `build_course_knowledge_scope_contract`。适配器只读课程数据，支持已有冻结包、已解析材料和明确标识的 C17 复核样板输入，不新建课程主库、不联网取资料。

上下文包含目标、起点、难度、已声明/推断学科画像、教学模块、范围合同、完整证据单元、原文定位与哈希、用途限制、解析缺口，以及材料短键到证据 ID 的映射。现行单层讲次以临时输入形状调用旧范围编译器，没有保存旧的章/节结构。

`KnowledgeFirstService` 在原 job 的 `request_snapshot` 中冻结上下文，知识树及讲义请求都消费该快照。开始请求、提交结果及采用候选时核验来源；课程目标、材料、用途或范围变化会阻止迟到写入。新讲义同时保存上下文、证据包和范围修订，统一阅读投影保留这些引用。已有知识和讲义不被重写。

C17 运行请求保留全部选中证据原文，但删除重复摘要、关键词、审计索引，并避免将同一批样板命题重复放入分类提示。完整证据仍在任务快照中；接入原 `CoursePlanningBudget` 的硬输入预算，超限停止而不静默裁掉材料。当前 C17 分类输入保守估算约14,860 tokens，三讲输入约10,000—13,200 tokens，低于默认16,000预算。四课短材料对照使用调用前冻结的完整上下文视图，没有为压缩另跑模型或改动原始输出。

网站当前仍限定 C17 三组试点；这次接回共享输入层，不是把所有课程的上传、抽取、核验和采用入口全部开放。四门课的真实调用使用与运行时相同的上下文适配器，在隔离目录执行。

## 对照条件

基线为[上一轮四课实测](知识树跨课程通用性实测-2026-10-11.md)。本轮直接复制其冻结材料、题库、迁移复测和三份提示词，并比较内容摘要，确认完全一致。模型仍为学校 `qwen3.8-27b`，每门课一次树抽取、一次教学生成，另一次材料不足对照，共9次，无模型重试或事后内容修订。

本轮增加的输入是：已声明学科类型、原教学模块与质量提示、课程范围合同、冻结证据包及引用映射。四门课按实验已知课程类型显式指定编程、数学、自然科学、人文社科；不是声称自动分类器这次自行修好了误判。新证据包分别包含2、2、2、3个来源单元，标题对照为0个。

同一门课的两阶段引用同一上下文和证据修订。抽取阶段仍看不到冻结题目答案和隐藏覆盖清单；教学阶段按原合同接收题库。模型调用累计记录耗时由175.25秒变为180.56秒。单次顺序运行不能作为性能结论。

### 必须保留的反例

- 数学 Q1 是 `f(x)=x (x≠0), f(0)=1` 在0的连续性，正确结论为不连续；本轮标准却要求判断 `|x-2|` 在2连续。Q2是平方函数的差商，本轮标准却换成绝对值的差商。因此题号齐全不能证明绑定正确。
- 数学训练直接使用了冻结复测 R1 的 `|x-2|` 情境，再把 R1 当迁移证据，不能证明独立迁移。
- Python 训练先执行 `b.append(2)` 再重新绑定b，此时a保持 `[1,2]`；独立 Q3 从另一初值出发，a保持 `[1]`。两者本身都可成立，但评分必须明确针对哪一题、从哪一初始状态开始。
- 物理原材料明确「不能由相互作用力相等推出加速度相等」，本轮树漏掉此边界，也未声明缺口。不能把原先对应的错误不再出现，当作该问题已解决。上一轮六项覆盖清单没有单列此边界，也是评测自身的局限。
- 历史材料没有证明“收入增长、工时延长”与“生活改善”必然矛盾。本轮教学已承认不确定性，但树的案例叶子仍把逻辑矛盾写入条件，需要跨产物语义核对。

## 判断与剩余工作

接回旧链路提供了正确的工程基础，减少格式偏差并改善部分拆分和范围表述；它没有证明元知识、题目和诊断之间的语义一致性。下一步需要题目—知识点—参数的联合校验、错误规则到预测的可检查约束，以及案例与知识分型，而不是把更多字段存在视作内容可靠。

本次每门课只有一个微单元、每阶段一次调用；同时加入多个上游字段，且没有重复试跑，不能将改善因果归给单一组件，也不能声称稳定成功率。通用全课入口、长材料分批预算、学科教师审阅和真实学生诊断有效性仍未验证。
