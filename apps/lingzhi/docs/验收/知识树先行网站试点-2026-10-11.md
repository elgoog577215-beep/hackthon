## 调用与失败记录

实际调用学校 `qwen3.8-27b` 共 5 次：知识树 2 次，讲义每讲各 1 次。首次知识树返回了 JSON 围栏，严格解析失败；离线检查还发现长 ID 抄写错误与重复项。原失败任务及片段保留，没有自动重跑。

修正外层 JSON 围栏兼容，并改为模型返回 `K-T01` 等固定短键、程序映射正式 ID 后，主动重新发起一次分类生成成功。成功树任务为 `tlj-07677cc9232b4445b7905ef3a964db52`；三讲任务依次为 `tlj-0478e6d3f905494b92941bd724976d4c`、`tlj-987f9871b2d04ee1b236148488b8e870`、`tlj-a812bbdd2d8b44ac81145697f07dd100`。首次失败任务为 `tlj-bd7a292d8fd94dfb88002e07805cc0e1`。

首次成功讲义任务在正文原子提交时已冻结，后续补写模型名称没有生效；该轮模型身份以服务调用日志为依据。实现已改为模型请求开始前保存名称，并在正文提交时同时保存完成状态，单测覆盖此修正。没有为补写元数据再次生成讲义，也没有修改这些历史任务。

## 存储与保护

- `course_knowledge_base` 保存本课程正式树；课程元数据保存采用历史。树的分类、知识关系与课程讲次分开。原知识库消费者通过只读字段映射读取同一棵树，不从讲义重建 ID；旧重建入口不能覆盖知识先行课程。
- 正文及旧讲义修订由原 `TeacherLessonAuthoringRepository` 保存。课程统一阅读接口只读投影这份正文，实际返回 3 讲、128 块和 49 个知识引用。
- 每块保留知识 ID、点修订、树修订、术语修订和答案证据。讲义保存来源文档修订；引用按钮可打开对应知识卡和历史树版本。
- 未采用知识树不能生成讲义。同课程活动任务互斥；重复请求幂等。保存核验冻结的来源与讲义修订、拥有者及任务状态；取消或来源变化后拒绝迟到写入。失败不覆盖已有讲义。
- 服务重启后实际树版本、三讲修订和任务数量不变，没有新模型调用。运行中任务的中断恢复通过隔离测试验证，不在使用中的课程上制造故障。
- Windows 原子保存保留文件刷新，并只在 POSIX 进行额外目录 fsync，避免本地出现文件已保存却返回目录访问错误。

## 验证

主后端定向回归 205 项通过；最后的知识先行专项 15 项、原知识库兼容回归 33 项通过（专项与主回归有重叠，不相加）。覆盖树完整性、短键映射、固定答案、单次调用、权限、幂等、取消、来源冲突、历史采用、重启中断及原知识消费者身份保留。

前端知识先行页面 4 项测试通过；连同旁侧 AI 面板的 31 项，共 35 项通过。修复了并行工作区中该面板测试的一处 `mockResolvedValue` 缺参类型错误，仅补为合法的 `null` 返回值。前端生产构建通过，保留既有大包体提示。

浏览器检查了中文和英文操作文案、桌面布局、生成与采用、三讲读取、来源修订和知识卡跳转；最后恢复中文。另验证了 8000 后端和 5174 前端对应同一份本地课程数据。

## 边界

这是「复核材料驱动的 C17 网站试点」。49 个知识事实、例题及诊断来自已复核样板；千问本轮生成分类组织与新讲解，没有证明从任意材料自动生成高质量元知识的能力。新讲解保留待教师审阅状态，结构与引用通过不等于教学内容已经审定。
