# 本地运行身份与统一入口

日期：2026-10-19。功能及运行包提交：`821a81aa`。本次处理运行入口、固定版本与数据身份，未修改知识提取、原子装配、层级生成和紧凑协议；这四个核心模块仍与 `c5575670` 一致。

## 根因

用户第6讲58%的失败记录产生于5173前端连接的8000服务，任务实际采用 `knowledge_extract_v9 / knowledge_validation_pipeline_v3`。此前验证通过的独立关系实现位于5175连接的8001，采用 `knowledge_extract_v1`。两套界面相同，原启动助手仍默认恢复旧服务；只更改隔离站代码无法改变用户原入口的执行版本。

## 运行契约

- `scripts/run_local_isolated.py prepare` 要求已提交的源码、隔离数据目录和本地凭据文件，校验核心模块仍为指定基线，拒绝正式数据目录及其父子目录。凭据仅载入进程环境，不复制进运行包。
- 准备阶段从指定Git提交的仓库根目录归档源码，并在停止旧服务前检查后端入口是否齐全。前端构建进入新的运行目录，写入公开的最小身份清单。运行包中的后端源码和前端资源都与开发目录分离，后续编辑不会改变正在运行的进程。
- `activate` 检查隔离数据没有活动生成任务后启动。后端先核对静态包的运行ID、源码版本、数据目录指纹、模式和知识协议；不一致则拒绝启动。5173同源提供页面、API及WebSocket，不再依靠开发代理把页面拼到另一套后端。
- `/api/runtime` 返回上述非敏感元数据，不返回数据路径、连接地址或凭据。页面首次加载核对身份，所有Axios写请求在发送前再核对；后端对身份缺失或不一致的API写请求返回409，原权限校验继续执行。
- 浏览器生成状态按数据目录指纹分开保存，保留原缓存而不串用。新知识任务保存 `runtime_identity`，可以追溯实际执行版本、数据与知识协议。
- 5175、8000和8001只保留旧入口处理：页面导航跳至5173，API写请求直接拒绝，不转发生成或采用操作。原本地启动助手已备份并指向当前选定运行包，避免重新启动旧v9服务。

## 操作方式

准备运行包时显式传入隔离数据目录、运行目录和本地 `.env` 路径：

```text
python scripts/run_local_isolated.py prepare --data-dir ISOLATED_DATA --state-dir RUNTIME_STATE --env-file LOCAL_ENV --node NODE_EXECUTABLE
python scripts/run_local_isolated.py activate --run-dir PREPARED_RELEASE_DIRECTORY
```

占用端口或活动任务必须先核对，不以启动器强杀无关进程。旧服务的本次停用在课程任务及任务管理器均无活动任务时执行，保留全部原数据和入口脚本备份。后续无需切换浏览器端口，使用本地5173并刷新即可。
