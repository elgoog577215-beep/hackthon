## 实现了什么

### 程序负责身份与结构更新

模型只给分类路径、命题和“原点替换为哪些命题”的意图，不再生成正式 ID、父引用或 JSON 增删改操作。程序分配身份，单点修订保留 ID；真正拆分生成新 ID，保留旧内容与替代映射。

每个原点作为独立事务处理，无效意图不覆盖该点，也不抹掉其他点的有效结果。陈旧基线和范围外编辑被拒绝。依赖发生变化时，旧题目、关系、诊断转入失效记录，待重新绑定；不能将它们复制给所有子点并假定语义仍成立。

本轮 8 个修改意图均成功组装保存，其中 if 的一个意图将原点真正拆成两个点，其余 7 个是单点修订。不是“8 个点都已经被拆细”。for 虽保存了 6 个修订，但模型仍未拆开头部省略等复合点。

### 样本答案只读代码证据

模型预测保留在 `predicted_stdout`，实际答案从精确源码、环境与运行回执绑定到 `verified_answer`。题目、易错诊断和复测引用同一个 check ID、源码哈希及回执哈希；代码变化后，旧答案核验失效。静态题不冒充已运行验证。

最后 14 个运行题均在 GCC 10.2.0 MinGW32 的 C17 模式下完成 O0/O2 两次执行且输出一致；另有 5 个静态题待内容核对。**这不是模型答对 14 题**：模型原字段只有 3 个精确匹配，8 个仅差末尾换行，3 个值本身错误。实际答案已由程序保存，模型错误原文保留以供核对。

| 最后保留的题 | 模型预测 | 程序实测 |
| --- | --- | --- |
| if `ch_ind_if_state` | `Y` | `N\n` |
| for `c_continue` | `x=14` | `x=8` |
| for `c_break` | `x=10` | `x=6` |

初稿 if `ch_brace_scope` 还曾预测 `2`，实测为 `10\n`。千问修正时改变了输入值，程序撤销其旧回执，新代码重新检查后才绑定 `2\n`，没有拿旧代码的输出冒充新代码验证。

类型精度例子要求 `long int` 至少 64 位，本机 GCC 实测宏为 `__SIZEOF_LONG__=4`、`__LONG_MAX__=0x7fffffffL`，因此没有运行该不满足前提的例子。千问将其改成静态题；静态解释仍存在将舍入方式说死的问题，没有因转成静态就视为正确。

执行前，Codex 逐段检查有限控制流、类型范围及副作用，并按精确哈希准许运行。这是受控本地实验，不是已经部署的通用 C 沙箱；编译成功和 O0/O2 一致也不能证明任意程序没有未定义行为。

### 诊断失败能明确定位

程序比较三道固定题：共同错误表现、区分性追问、变式复测。两种信念在第一题须产生相同且错误的预测，在区分题须产生不同预测，复测不能复用同一个 check。诊断比较忽略纯空白差异，避免把漏换行当成一种知识错误；样本输出的严格匹配仍保留完整字符。

本轮 3 条诊断全部被阻断，原因可定位：

- 类型：共同预测就是实际正确结果，区分题 A/B 又相同；推理过程中还改变了原先定义的错误信念。
- if：共同预测不相同，其中一个已经正确；区分题预测却相同，假设与代码缺乏对应。
- for：复测复用了区分题，A/B 的预测也不符合其错误信念。例如认为 continue 跳过更新，在给定例子会卡在 i=2，不能推出模型写的有限累加值。

这些记录保存为 `model_hypothesis`、`needs_review`，不能作为学生已发生的错误或可靠个体诊断。

## 仍未通过的内容

**6 个颗粒度问题：** 类型转换的作用位置与不改变原变量；else-if 的语法与停止判断；独立 if 的多次命中与状态读取；for 的单语句体与空体；头部各部分省略语义；嵌套 break/continue 的综合目标判断。

**16 个点没有教学检查绑定：** 类型 2 个、for 14 个。知识点自身已有元问题与模型答案，但教学生成没有完成全部检查。即使有检查，引用某点也不代表确实测到它：if 的状态题没有改变状态，for 的 break 题只打印 x，无法区分 break 后 i 是否又更新。这些另有逐项评语，不能用绑定率代替检查效度。

**核心命题仍有严重错误：** U 后缀被无条件判为 unsigned int；转换位置的答案说反；无符号回绕被混写成未定义行为；花括号内外 else 的范围表述含混。自审还把原本正确的 int/unsigned int 转换方向，加上“unsigned int 能表示 int 全部值”的不可满足前提。范围保护能阻止越界修改，无法保证允许范围内的内容一定被改好。

对同秩有符号/无符号转换、浮点分支与整数提升顺序，以及赋值操作数求值次序，复核时还对照了 WG14 的 [N1570 §6.3.1.8、§6.5.16](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)。这是开发审查参考，没有加入课程资料检索链路；N2176 网络读取超时，未声称本次重新获取了该文本。

**关系：** 类型组仍有一条错误的 required 先修边；for 的 continue/break 对比方向基本成立，但“极易混淆”缺少学生数据支持。if 教学生成中未产出有效关系。

## 实验控制与程序自身修正

三组资料、评测定义和保留题按字节沿用前两轮并校验哈希。保留题不进入模型提示，也不充当模型考试得分。本轮从生成阶段起就给定覆盖清单，协议为 core → atomize → teach → repair，每主题每阶段最多一次，未额外补采样挑结果，未人工改写千问知识内容。

12 个物理请求全部 stop 完成，无供应端重试。3 个响应直接是严格 JSON，9 个使用现有提取器解析。if 教学响应中有不完整对象及 10 个混入数组的散文字符串：修正后的对象可解析保存，10 个字符串始终拒收并记录，不把它们算成知识或易错点。

估算输入 91,053 tokens、输出 33,875 tokens，共 124,928；均为项目估算，非供应端计费回执。314.93 秒仅为模型调用累计，不含开发、人工检查与本地编译时间。

实验中修复了两项程序问题：修正范围构建曾对数组里的字符串调用 `.get`，现在逐项拒收非法成员；修正包仅缺可选的 `unresolved` 注释字段时，不再错误拒绝有效替换，未知字段、身份变更和越权仍拒绝。使用同一份原始模型结果重算，没有额外模型调用。另在诊断结果比较中增加空白等价规则，防止假阳性。

19 项离线回归通过，覆盖拆分历史、邻居保护、关联失效、陈旧基线、循环前置、坏数组成员、范围修正、证据撤销、运行失败与不一致、错误诊断的阻断。浏览器验证仅针对本轮展开树的展示；没有改动或验收正式课程页面。
