# 师生课程闭环历史审计

以下发现、建议和测试结果仅对应 2026-07-23 的 `c03ab5a`，本次共享未重跑。不能据此认定当前版本仍有同样缺陷。历史的停启服务或复位方案只适用于独立 Demo 环境，当前操作必须遵守任务保护规则。

审计日期：2026-07-23
审计对象：灵知当前 `main` 版本（`c03ab5a`）
审计口径：不是“代码里存在某个接口或按钮”，而是“在 Demo 页面中能够从起点连续操作到最终结果，并让观众直接看见价值”。

## 一、结论

当前系统已经具备两条主链路的大部分底层能力，但还不能称为“教师需求已完成”。

- 教师侧“教学材料一键生成及一键更新”：底层的同源编译、影响分析、语义修改和多材料重建已经存在；但一键生成没有形成材料结果工作台，一键更新在 Demo 模式下没有展示真实逐项差异，且目前只有 PPT 能作为反向修改入口。
- 学生侧“个性化的学”：从对话证据到课程生长、从当前小节到后续小节、再到动画和个性化练习已经可以真实落地；但练习后的独立评阅和效果验证没有闭环，两个课程调整入口还会得出不一致的结果。

因此，当前阶段应停止继续增加外围功能，集中把两条主链从“能力存在”收束为“闭环可展示”。

## 二、什么才叫全链路完成

### 2.1 教师侧：教学材料一键生成及一键更新

完整链路应当是：

```text
教师提出课程需求
→ 生成统一课程源
→ 一键生成大纲、教案、讲义、练习、PPT、图示
→ 进入材料总览并逐项查看
→ 修改任意一种材料中的一个教学语义
→ AI 判断修改意图和影响范围
→ 展示哪些材料、哪些位置将变化，哪些保持不变
→ 教师确认
→ 精准更新各项材料
→ 逐项展示更新前后差异并高亮
→ 所有材料处于同一课程版本
```

完成标准不是弹出“更新成功”，而是观众能够直接看到：

1. 六种材料确实由同一个课程源生成。
2. 修改不是整套推倒重做，而是对相关位置进行精准更新。
3. 大纲改得少、教案和讲义改得更具体、PPT改得更直接。
4. 从上游修改可以向下联动，从下游材料修改也可以反向更新统一课程源。
5. 更新完成后，每一种材料都能打开，并能看到真实的修改位置。

### 2.2 学生侧：个性化的学

完整链路应当是：

```text
学生学习课程
→ 在与 AI 的交流、错题、练习和笔记中产生学习证据
→ AI 判断已掌握内容、真实困难、教学需要和影响范围
→ 生成当前小节与后续相关小节的调整方案
→ 学生预览、选择、确认
→ 个性化内容写入自己的课程版本
→ 学生实际学习新增内容并完成个性化练习
→ 系统独立评阅学习效果
→ 决定保留、继续增强、提高难度或回滚
→ 形成个人学习路径与个人课程版本
```

完成标准不是“新增了几个 AI 块”，而是课程变化后必须继续产生新的学习行为和验证结果，使系统能够证明这次变化是否有效。

## 四、阻断“完成”的问题

### P0-1：教师侧必须返回真实逐项差异

当前 Demo 超时后会生成“看起来成功”的合成回执，但缺少每个单元真实的 `before / after`。这直接违背真实结果必须可见的验收要求。

必须改为：

- 真正等待后台任务完成，或采用提前生成并与真实课程版本绑定的可靠回执。
- 每个受影响单元返回材料类型、章节位置、修改前、修改后、修改理由和来源版本。
- 前端不再用“未提供逐字差异”替代结果。

### P0-2：建立教师材料总览与结果导览

一键生成后必须出现一个统一页面，明确展示六种材料都已完成，并能逐项打开。

一键更新后必须提供：

- 总体更新摘要。
- 大纲、教案、讲义、练习、PPT、图示的更新数量。
- 每类材料至少一个真实高亮差异。
- “查看下一类材料”或自动导览能力。
- 更新后统一版本号和同源状态。

### P0-3：补齐真正的双向编辑入口

目前“PPT → 统一课程源 → 其他材料”可以工作，但“改任何材料”还不成立。

最低闭环要求：

- PPT 可以发起反向语义更新。
- 大纲或教案至少有一个可编辑入口，可以发起正向更新。
- 两个入口最终走同一套影响分析、确认、重建和差异回执。

### P0-4：做出一个真实的小变动迭代场景

除“大范围语义升级”外，还需要一个只改变少量内容的场景，例如：

> “把这个案例换成更贴近大一学生的例子，并在讲义中补一句解释。”

预期只更新 1—3 个相关节点，大部分材料明确显示“不受影响”。这才能证明系统是交互式迭代，而不是重新生成整套内容。

### P0-5：统一学生侧两个调整入口

“AI 对话”和“调整课程”不能对同一句需求产生相反结果。应当：

- 统一进入同一个意图解析、证据判断、范围规划和质量检查管线；或
- 在本轮产品中只保留一个正式入口，避免用户走入失败支线。

### P0-6：补齐个性化练习后的评阅与效果判定

为 Demo 固定任务提供可重复的本地确定性评阅，或者保证线上评分模型稳定可用。

评阅后必须产生：

- 正误与解释。
- 新掌握证据。
- 对本次课程调整效果的判断。
- “保留本次调整 / 继续补强 / 提升难度 / 回滚”的结果。

没有这一步，学生侧只能叫“课程内容生成”，不能叫“个性化学习闭环”。

### P0-7：让 Demo 数据复位真正幂等

当前服务器运行时执行准备脚本，可能因为内存缓存未清理而保留旧课程状态。必须提供：

- 一个服务端 Demo Reset 接口；或
- 一个统一命令完成“停止服务 → 清理数据 → 准备固定数据 → 启动服务 → 健康检查”。

连续复位两次后，课程必须仍然只有同样的 6 个新增节点，不能重复生长。

### P0-8：移除与核心叙事无关的控件

在教师侧 Demo 页面移除或隐藏“清风课堂”“学术蓝灰”等主题按钮，使页面只服务于：

```text
材料生成 → 修改 → 影响分析 → 确认 → 联动更新 → 查看结果
```

## 五、P1 增强项

这些不是本轮 Demo 闭环的前置条件，但决定产品是否真正达到教师描述的长期形态：

1. 个人学习地图：展示统一课程、我的学习路径、已掌握跳过、补充节点和挑战节点。
2. 掌握后做减法：不仅能增加解释，也能折叠、跳过或压缩已经掌握的内容。
3. 能力提升后升级课程：从“补弱”扩展到“加深推导、提高题目难度、增加迁移任务”。
4. 将笔记、错题、问答和练习统一成证据时间线。
5. 教师能查看班级共性困难，并将学生侧证据反哺到下一轮教学材料迭代。

## 六、建议开发顺序

### 第一阶段：把教师侧“更新结果”做真

1. 移除合成回执。
2. 打通真实后台任务进度与真实差异数据。
3. 建立更新结果总览和逐材料差异展示。
4. 隐藏无关主题控件。

验收：修改 PPT 一个教学语义后，可以依次打开大纲、教案、讲义、PPT，看到真实高亮变化。

### 第二阶段：把教师侧“一键生成 + 双向更新”做全

1. 增加材料生成结果工作台。
2. 增加大纲或教案编辑入口。
3. 统一所有编辑入口的影响分析与重建协议。
4. 准备“大改”和“小改”两个确定性场景。

验收：从课程需求生成整套材料；从大纲修改可向下更新；从 PPT 修改可反向更新。

### 第三阶段：把学生侧“学习效果”闭上

1. 统一两个调整入口。
2. 为固定个性化练习增加稳定评阅。
3. 将评阅结果写回证据系统。
4. 展示本次调整的保留、增强、升级或回滚结论。

验收：同一句学生诉求稳定生成 6 个调整；完成个性化练习后，系统能明确证明调整是否有效。

### 第四阶段：保证现场稳定

1. 一键复位。
2. 启动前健康检查。
3. 固定课程、固定输入、固定结果。
4. 连续完整回归三次。
5. 对无模型、慢任务和意外刷新设计真实且可解释的降级路径。

## 七、最终验收清单

满足以下条件后，才建议宣布“开发完成，可以开始录制”：

- [ ] 一次点击生成六种教学材料，并能逐项打开。
- [ ] 大纲或教案修改能够向下联动。
- [ ] PPT 修改能够反向更新统一课程源和其他材料。
- [ ] 更新前明确展示影响范围与不受影响范围。
- [ ] 更新后每类材料都有真实 `before / after` 高亮。
- [ ] 小变动只更新少量相关节点，不表现为整套重生成。
- [ ] 学生对话能生成当前与后续课程调整。
- [ ] 学生可以学习新增动画并完成个性化题目。
- [ ] 题目能够稳定评阅并反哺学习证据。
- [ ] 系统能给出调整保留、增强、升级或回滚结论。
- [ ] 两个学生调整入口行为一致，或只保留一个正式入口。
- [ ] Demo 数据可一键复位且不会重复生长。
- [ ] 页面中没有干扰核心叙事的无关功能。
- [ ] 两条链路连续完整回归三次，结果一致。
