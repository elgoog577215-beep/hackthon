## 通用实现

1. 选项语义：数值题拒绝未求值算式与等价数值选项；明确区分数值与逐字输出，不因程序含printf就把数值题暗自当字符串题。选项逐项独立解释、判定正确集合，与参考答案对账。
2. 解析事实：有限字面量加减乘用安全AST/Decimal核对，不执行模型代码；检查无来源精确条款引用、C除法运算符前缀/中缀/后缀混淆，以及额外假定的初值。检查有明确支持范围，未知情况交语义评审，不能自称通用程序证明器。
3. 观测证明：生成器先提供私有measurement_plan；独立评审看不到这个计划，须重新给出review_witness：完整主考规则、实际公开观测位置、只改变目标语义的错误规则、正确/错误预测和简短可复核执行摘要。相同预测、虚构位置、改变固定输入、偷换目标均不通过。
4. 控制流核验：如果目标是不求值后续条件，纯条件加分支体赋值不能替代求值观测；直接问求值行为或有实际条件侧观测才可继续。对有限if/else/块/分号子集比较else归属，防止核验trace添加花括号后证明了另一个程序。未知语法不猜测。
5. 候选JSON归位：仅移动明确错放的solution、options等既有字段，内容不变，有冲突则拒绝。不会用模型再次生成一遍来修纯嵌套错误；原始响应保留。
6. 证据准入升级为question_evidence_admission_v2，要求8项检查和结构化核验依据，最终提示版本为assessment_prompt_template_v10（两轮主模型运行分别使用v8/v9，v10新增具体预测要求作本地反例回归）。正式读取通过approved_formal_tasks(bundle)加载私有答案执行revalidate_evidence_admission；该函数只撤销、不凭空授予资格。knowledge_point_coverage必须传solutions，缺私有答案视为未核验，不误报答案错误。

八项检查为language_aligned、no_answer_leakage、explanation_consistent、independently_assessable、options_unambiguous、observation_discriminates、reasoning_grounded、prerequisites_within_scope。布尔标记本身不足以准入。

### K-F12 continue 的执行逻辑

以下代码展示了 `continue` 语句在 `for` 循环中的行为。观察 `counter` 的变化：

```c
int counter = 0;
for (int i = 0; i < 3; i++) {
    if (i == 1) {
        continue;
    }
    counter = counter + 1;
}
```

在上述 `if` 块中执行 `continue` 后，控制流立即转移到了哪个位置？
当代码执行 `continue` 后，紧接着进行的逻辑操作是什么？

- A. 直接终止循环，不再执行任何后续迭代。
- B. 跳过本轮循环体剩余部分，执行 i++ 后再判断 i < 3。
- C. 跳过本轮循环体剩余部分，也跳过 i++，然后判断 i < 3。
- D. 跳过本轮循环体剩余部分，直接返回函数调用者。

参考答案：B。

### K-I08 空语句对控制范围的破坏

在C17标准下，考虑以下代码：
```c
int x = 15;
int y = 0;

if (x > 10);
    y = 20;
```
根据C17语法结构，分析 `if (x > 10);` 及其后的语句 `y = 20;` 的执行关系。选择正确描述该程序执行逻辑的选项。

- A. y = 20; 无条件执行，因为 if (x > 10); 中的分号构成了if的分支体（空语句），后续语句独立于该if结构。
- B. y = 20; 仅在 x > 10 为真时执行，因为该语句紧邻 if 条件，逻辑上受该条件控制。
- C. 代码存在语法错误，if 语句后不能直接跟随分号。

参考答案：A。
