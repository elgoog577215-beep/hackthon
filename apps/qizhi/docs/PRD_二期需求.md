# MentorAI（启智）二期需求 PRD

> 版本: v1.0 | 日期: 2026-06-25 | 状态: 待评审

---

## 一、背景与目标

启智 MentorAI 一期已上线视频分析（5 维度评价）、智能对话、论文检查、PPT 生成等核心功能。
张老师及团队提出二期需求，围绕 **性能、交互、功能扩展** 三个方向迭代。

### 核心目标

| # | 目标 | 量化指标 |
|---|------|---------|
| 1 | 高并发可用 | 300-400 人同时在线，核心接口 P99 < 3s |
| 2 | 模型响应提速 | 90 分钟视频分析 ≤ 30s；对话首 token ≤ 1s |
| 3 | 交互优化 | 提示语与输入框在视觉/功能上紧密关联 |
| 4 | 教研资源水平分析 | 支持 Word/PPT/视频的横向能力评价与改进建议 |

---

## 二、需求详述

### P0: 并发压测与性能保障（300-400 人）

**现状问题**
- 当前部署为单进程 uvicorn，无水平扩展
- vLLM 仅用 1 个 tp=4 实例（已有 tp=1 新实例但未暴露端口）
- 智能对话 SSE 流遇高并发时出现 `Connection error`（见截图）
- 模型层故障时前端仅显示"服务暂时出现了一些问题"，无明确错误提示

**需求描述**

| 子项 | 说明 | 优先级 |
|------|------|--------|
| 2.1.1 后端水平扩展 | uvicorn 多 worker（当前代码已支持 `--workers` 参数）；验证多 worker 下数据库连接池、任务队列的并发安全性 | P0 |
| 2.1.2 vLLM 多实例负载均衡 | 暴露 GPU 容器端口 7891 的 NodePort（需集群管理员协助）；后端 `VLLM_TEXT_ENDPOINT` 配置多 URL 逗号分隔；代码已支持 `random.choice` 客户端负载均衡 | P0 |
| 2.1.3 压测执行 | 使用 Locust/k6 编写压测脚本，覆盖：对话 SSE 流、视频分析提交、教案生成、报告查看等核心接口；目标 400 并发下 P99 < 3s、错误率 < 1% | P0 |
| 2.1.4 前端错误提示优化 | 模型层 `Connection error` 时区分"模型繁忙请排队"和"服务不可用"，给用户明确提示而非通用报错 | P1 |

**验收标准**
- [ ] 400 并发下对话接口 P99 < 3s
- [ ] 400 并发下视频分析提交不丢失任务
- [ ] 模型故障时前端显示具体错误信息

---

### P0: 模型回答速度优化

**现状问题**
- 10 分钟视频分析耗时 5-6 分钟（流式流水线代码已 push 到 main 但后端未重启）
- 对话场景首 token 延迟较高
- 单 vLLM 实例处理并发请求时排队

**需求描述**

| 子项 | 说明 | 优先级 |
|------|------|--------|
| 2.2.1 后端重启部署 | 重启后端进程以激活已 push 的 5 个 commit（流式流水线、map-reduce 并行、死锁修复、多实例 LB） | P0-紧急 |
| 2.2.2 流式流水线验证 | ASR 完成一段 → 立即投喂 LLM 4 维度并行分析（已实现），验证端到端提速效果 | P0 |
| 2.2.3 多 vLLM 实例扩容 | tp=4 主实例 + tp=1 辅助实例 + 未来按需扩展；GPU 5 的 tp=1 实例已启动（端口 7891，PID 7321） | P0 |
| 2.2.4 对话首 token 优化 | 评估 vLLM `--enable-chunked-prefill` 效果；对话 prompt 精简以减少 prefill 时间 | P1 |
| 2.2.5 ASR 并发度提升 | 当前 ASR 单实例 tp=1；评估是否需要第二个 ASR 实例 | P2 |

**验收标准**
- [ ] 10 分钟视频分析 ≤ 60s（当前 5-6 分钟）
- [ ] 90 分钟视频分析 ≤ 5 分钟（远期目标 30s 需更多 GPU）
- [ ] 对话首 token ≤ 1s

### P1: 提示语与输入交互优化

**现状问题**（见截图）
- 教案编辑页面中，右侧 AI 交互区分为两部分：
  - 上方：预设提示按钮（"根据大纲补充本章教学目标与重点"、"将现有内容改写为更清晰的 Markdown 结构"、"增加 3 道中等难度的练习题"）
  - 下方：自由输入框（"输入需求，与 AI 继续修改当前内容"）
- 两者之间有大片空白，视觉上割裂，用户不清楚提示语与输入框的关系

**需求描述**

| 子项 | 说明 | 优先级 |
|------|------|--------|
| 2.3.1 布局整合 | 将预设提示按钮移至输入框上方或内部（参考 ChatGPT 的快捷提示气泡风格），让用户一眼看到"点击提示 = 自动填入输入框" | P1 |
| 2.3.2 提示语上下文关联 | 提示按钮内容根据当前编辑的章节/段落动态变化（如正在编辑"教学目标"时，提示语聚焦目标优化；编辑"练习题"时聚焦题目设计） | P1 |
| 2.3.3 点击提示后的反馈 | 点击提示按钮 → 内容填入输入框（可编辑修改）→ 用户确认后发送，而非直接触发生成 | P2 |

**验收标准**
- [ ] 提示按钮与输入框在视觉上紧邻，间距 ≤ 12px
- [ ] 提示语内容与当前编辑上下文相关
- [ ] 用户可编辑提示语后再发送

**涉及文件**
- `client/website/src/components/resource-ai/` — AI 交互面板组件
- `client/website/src/components/teaching-plan/` — 教案编辑组件

### P1: 教研资源水平分析（Word/PPT/Video）

**现状问题**
- 当前仅支持视频的多维度分析
- 教学大纲、教案以 Markdown 编辑器形式在平台内编辑，无法对已有 Word/PPT 文件做分析
- 教师需要对多份教研材料做横向比较和能力评价

**需求描述**

| 子项 | 说明 | 优先级 |
|------|------|--------|
| 2.4.1 Word 文档分析 | 上传 .docx → 提取文本 → LLM 分析教学设计质量、知识体系完整度、表述规范性 → 生成能力评价 + 改进建议 | P1 |
| 2.4.2 PPT 分析 | 上传 .pptx → 提取文本 + 布局信息 → LLM 分析内容组织、视觉设计合理性、教学逻辑 → 生成评价 + 建议 | P1 |
| 2.4.3 视频水平分析增强 | 在现有 5 维度基础上，增加"能力评价"维度（教学能力雷达图）和"改进建议"结构化输出 | P1 |
| 2.4.4 横向对比 | 同一教师多次课的纵向对比；不同教师同一课程的横向对比（需管理员权限） | P2 |
| 2.4.5 报告导出 | 分析结果支持导出为 Word 报告（含雷达图、评分表、改进建议列表） | P2 |

**分析维度（Word/PPT 通用）**

| 维度 | 评价内容 |
|------|---------|
| 教学目标清晰度 | 目标是否具体、可衡量、与课程大纲对齐 |
| 内容组织逻辑 | 知识点排列是否有层次递进、前后衔接 |
| 教学方法适切性 | 是否采用多样化教学方法、是否匹配知识类型 |
| 学生互动设计 | 是否设计了提问、讨论、练习等互动环节 |
| 思政融合 | 是否有课程思政元素的自然融入 |
| 规范性 | 格式、术语、引用是否符合教学文档规范 |

**验收标准**
- [ ] 支持 .docx / .pptx 上传并生成分析报告
- [ ] 分析报告包含能力评价雷达图 + 结构化改进建议
- [ ] 分析耗时 ≤ 30s（单文档）

**涉及文件（新增）**
- `server/api/` — 新增文档分析 API 路由
- `server/service/document/` — 新增文档分析服务（Word 解析、PPT 解析、LLM prompt）
- `client/website/src/views/` — 新增文档分析上传/报告页面

## 三、技术方案概要

### 3.1 并发架构

```
                        ┌─── vLLM tp=4 (GPU 0-3, port 7890, NodePort 30938)
用户 → Nginx(未来) → FastAPI (多 worker) ─┤
                        ├─── vLLM tp=1 (GPU 5, port 7891, NodePort 待分配)
                        └─── vLLM ASR  (GPU 4, port 7894, NodePort 30026)
```

### 3.2 文档分析流程

```
上传 Word/PPT → 文本提取 (python-docx / python-pptx)
                    ↓
             分段（按章节/幻灯片）
                    ↓
         Map: 每段 → LLM 维度分析 (并行)
                    ↓
         Reduce: 合并段落结果 → 总评
                    ↓
              生成报告 (雷达图 + 评价 + 建议)
```

### 3.3 压测方案

| 场景 | 并发数 | 持续时间 | 关注指标 |
|------|--------|---------|---------|
| 对话 SSE 流 | 400 | 10 min | 首 token 延迟、完成率 |
| 视频分析提交 | 50 | 5 min | 任务入队成功率 |
| 教案 AI 生成 | 200 | 10 min | 响应时间 P95/P99 |
| 报告页加载 | 400 | 5 min | TTFB、渲染完成时间 |

## 五、当前阻塞项

| # | 阻塞 | 影响 | 解决方式 |
|---|------|------|---------|
| 1 | 后端进程未重启 | 5 个 commit 未生效，所有模型服务报 Connection error | SSH 到 127.0.0.1 手动重启 uvicorn |
| 2 | vLLM tp=1 端口未暴露 | 新实例在容器内运行正常但外部不可达 | 联系集群管理员添加 NodePort 映射 7891 → 3093x |
| 3 | K8s 服务账号无 services 权限 | 无法自行创建 NodePort | 需管理员授权或手动操作 |

## 六、风险与依赖

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| GPU 单机 6 卡不够 400 并发 | 高 | 模型排队，P99 劣化 | 申请第二台 8 卡节点 |
| 浙大统一认证压测困难 | 中 | 无法模拟真实登录流 | 开发测试 bypass 或 mock token |
| Word/PPT 解析复杂格式丢失 | 中 | 分析质量下降 | 先支持纯文本提取，复杂格式标记跳过 |
| 后端多 worker 下任务队列竞争 | 低 | 任务重复执行 | 数据库行锁 + FOR UPDATE SKIP LOCKED |
