# 灵知学习闭环开发计划

初始核对：2026-10-19；开源借鉴方向确认：2026-10-20。阶段方向已纳入[正式项目目标与准则](../apps/lingzhi/docs/阶段项目目标.md)。本轮进入仓库源码核对和隔离小实验准备，具体接入沿原批次实施；借鉴范围与首轮工作见[开源借鉴与首轮执行](#开源借鉴与首轮执行)，不代表功能已接入或教学效果已验收。

本计划将本次用户提供的“教师备课 → 学生定制 → 学习痕迹 → 用户画像 → 个性化服务 → 教学反馈”总纲，对照灵知现有实现转成执行批次。业务规则继续由[产品蓝图](../apps/lingzhi/docs/产品蓝图.md)及各功能设计维护；教师生成改造仍归[生成链路收敛](生成链路收敛.md)，学生入口及项目能力仍归[学生学习空间](学生学习空间.md)，本文只安排跨模块闭环的增量及联合验收。

## 近期产品主线与执行重点（2026-10-20）

按本次确认的[产品定义与建设主线](../apps/lingzhi/docs/阶段项目目标.md#产品定义与建设主线)，灵知以学生自学 Agent 和讲义学习现场为中心，同时建设“针对性与清晰讲解”和“学习画像与动态自适应”，通过教师 AI 形成备课与教学反馈循环。两条线共同落实到讲解、提问、练习三类教学块；不将本阶段缩减成画像统计与答疑入口。

每次演示分别标明：真实界面与实际产物、使用示例数据的交互、尚待实现的教学安排。PPT 与演示顺序统一由[展示方案](../apps/lingzhi/docs/评委路演展示方案.md)维护，避免把目标排期写成已交付能力。本次更新规划，不启动新的课程生成、服务切换、数据迁移或发布。

## 三、必须保持的实现约束

1. 学习事实与模型解释分开。原始作答和检查历史保留；当前判断可以重算，纠正通过新修订/更正关系表达，不静默改掉旧事实。
2. 同一活动产生的作答、批改、理解分析与教师回执共享来源链；重复请求或重分析不能增加独立证据。同题历史保留与当前证据去重分别处理。
3. 提问、阅读、笔记保存、AI 整理稿都不直接证明掌握。学生明确自述可以触发帮助，但不能直接变成“已确诊某种错误”。
4. 未评估、待判断、旧版本证据、当前未通过分别显示；红绿保留历史，不能相消成一个无依据的当前结论。
5. 教师正式正文只有一个写入责任。学生个人补充写入本人材料；教师课程改动继续走原有范围、影响、决定、领域命令与回执。
6. 课程/知识点/题目修订及原文锚点贯穿全链路。新版本不追认旧作答，不自动重新批改旧题，不静默替换在答题目。
7. 共用原 TaskManager、题库和记录仓储；失败保存片段，由有权用户主动继续。文本模型仍为项目规定的 Qwen，课程联网来源仍冻结。
8. 私人内容默认归学生。教师只消费获授权的学习事实和反馈；教师预览不读写真实个人画像。
9. 当前知识树规格暂停扩展自动出题、错因诊断、补救及迁移生成。下述后续批次是排期建议，进入实现前须同步确认并更新原业务规格，不能据本文自行解冻。

## 四、开发批次与完成条件

### P0：确定同一基线，整理真实可用范围

工作：核对运行清单、源码提交、现有未提交修改及各课程已采用知识基线；将已完成且验收的改动纳入后续开发基线。修正入口文档中仍写“知识树先于讲义”和学生整体冻结的过时摘要，保留历史证据。使用隔离课程建立贯通样例。

交付：一份可复现的版本/数据/测试清单；已可复用、需修复和未验证项分清。文档对齐不顺带切换服务或迁移数据。

退出条件：教师原课程、学生既有笔记/作答及活动任务校验不变；实现人员能确定自己测试的是哪个版本。

### P1：把知识树、题目和学习证据真正绑到一起

工作：沿当前讲义后提取流程，先完成一门代表课程中的连续讲次；处理拆分、重复知识复用、来源缺口与关系待审。贯通正式采用、题库精确绑定、学习页和画像的同一修订。绑定出错和知识变更要显示具体受影响项。

复用：`course_knowledge_*`、`knowledge_extract.py`、`knowledge_assessment.py`、`question_bank_knowledge.py`、`knowledge_mastery.py`、`TeacherKnowledgeManager.vue`、`QuestionKnowledgeBinding.vue`。

退出条件：每个试点范围内知识点能回到来源；缺题/待审明确；学生正式作答绑定当时的题目与知识修订。来源变化、候选未采用、教师预览及两学生隔离均通过；不要求全课程全部知识自动一次生成成功。

### P2：统一学习证据时间线

工作：扩展原事件合同，增加同一次活动的来源链、证据片段、学生实际表达、知识绑定、帮助使用及更正关系。先接正式作答和现有理解检查，再接有明确知识上下文的对话/笔记分析。分析产生候选结论，依据不足保留待判断；学生可以查看原文并提出纠正。矩阵增加解释检查等证据入口与服务端游标分页。

复用：`learning_events.py`、`learning_records.py`、`routers/study_dialogues.py`、`practice_attempts.py`、`LearningMatrix.vue`。

退出条件：同一材料重复分析、同一次提交重发、笔记另存、教师收到回执，都不会重复计算证据；独立解释与 AI 帮写可区分；更正后旧事实仍可追溯；跨用户、版本和授权隔离通过。

### P3：形成可解释的当前画像及变化过程

工作：在现有投影上增加理解、操作、迁移表现，以及困难假设、提示依赖、证据充分程度和近期变化。当前状态与完整历史分别返回；明确“改善、仍不稳定、疑似复发”的证据条件。现有参考分值先保留兼容，不将其作为未经校准的客观能力概率。

复用：`learner_model.py`、`learner_model_service.py`、`knowledge_mastery.py`、现有诊断工作流及知识详情组件。

退出条件：固定事实回放能稳定重现“多次失败→独立通过→隔段时间再次失败”；仅因时间过去只能提示待复查，不能生成一次虚构答错。无数据、单次失败、提示完成、综合题无法逐点归因等情况均不过度判断。用学科教师标注样例检验错因与证据结论，报告错误类型。

### P4：闭合一次个性化帮助及后续验证

工作：2026-10-22 确认首批为直接解惑、概念辨析、分步提示、帮助后独立检查，具体触发、回应、证据及验收规则见[画像到四类教学动作](../apps/lingzhi/docs/功能设计/学生学习.md#画像到四类教学动作)。补前置、变化场景等后续范围按证据与已确认规格逐类扩展。建议记录所用画像修订、原始证据、策略和目标；学生可接受、修改、延后或拒绝。短帮助在原阅读上下文显示，可复用补充保存为本人材料；不改教师教材。复用诊断—补救—验证流程，并给实际帮助增加贯通标识。

2026-10-22 确认学伴消费正式画像并结合总体目标、持续计划和相关记忆选择帮助，规则见[总体学习目标、持续计划与学伴记忆](../apps/lingzhi/docs/功能设计/学生学习.md#总体学习目标持续计划与学伴记忆)。实际使用与新的独立表现沿原事实机制反馈画像；聊天摘要不另建掌握分，生成过帮助不视为困难已解决。2026-10-23 已完成首版工程接入与隔离验收，真实学生效果仍须课程试点。

主动程度同日确认：默认轻主动，允许本人持久选择仅在提问时回应；提醒时机、跨会话抑制与不打断规则见[学伴主动程度与提醒时机](../apps/lingzhi/docs/功能设计/学生学习.md#学伴主动程度与提醒时机)。沿原建议与学伴提醒机制统一接入，不能把会话内关闭误当作跨刷新生效。

复用：`diagnostic_service.py`、`diagnostic_workflows.py`、`study/repository.py`、`study/service.py`、学伴与个人讲义组件。原课程修改候选只服务有权编辑的正式内容；不能把其名称中的 personalization 当成私人覆盖层复用。

退出条件：一次困难能完成“证据→建议→本人使用→新的独立检查→画像重算”；拒绝和稍后处理不反复打断；看过讲解不加掌握证据；重复练原题与真正变化题分别表达。诊断、变式及补救内容需真实模型与学科样例验收。

### P5：接入目标、场景、节奏与效果跟踪

工作：在现有学习起点上补齐可修改的目标、范围、基础依据、截止日期及周可用时间，支持系统学习/备考/项目的组合。复用继续学习和复习投影，为下一步提供理由及任务负荷；目标修改展示受影响安排，保留已完成活动。关联帮助后的即时、延时和变化情境表现。

2026-10-22 确认学伴以“总体目标 → 阶段计划 → 当次活动”为持续主线，结合有来源的个人学习记忆承接跨会话帮助；临时需求不自动覆盖总体目标。具体规则见[总体学习目标、持续计划与学伴记忆](../apps/lingzhi/docs/功能设计/学生学习.md#总体学习目标持续计划与学伴记忆)，沿 P2/P3 的事实及判断边界、P4 的正文辅学接入，不另建记忆分数或进度真源。2026-10-23 已实现可采用的阶段安排、本人记忆管理与跨会话恢复；复杂长期调度不在首版范围。

退出条件：学生调整期限后只更新未来安排；不足以覆盖目标时如实提示取舍；延后/拒绝的建议跨入口一致。区分“未使用、已使用未验证、已有后续证据、效果仍不确定”；自然学习前后变化只作关联描述，不宣称已证明因果效果。

### P6：把经授权学情接回教师备课

工作：在原发布与反馈面板增加个人困难、班级共性问题和时间变化。班级范围先采用教师明确指定的课程授权学生集合，不以访问人数或实际答题人数替代名单；展示总人数、有效证据人数、版本和时间范围。将共性问题转成补讲/练习/实践建议，通过原影响分析生成可选修改，教师采用后跟踪后续表现。

复用：`course_exchange.py`、`routers/course_exchange.py`、`course_evolution/`、`course_knowledge_impact.py`、课程发布反馈组件。

退出条件：无数据与有证据未通过分开；重复回执不增加人数或学习事实；撤销/更新授权后不再新增越权反馈；教师看不到默认未授权的私人原文。教师修改后，原学生笔记和作答仍保留原修订，学生可主动采用新版本。

### P7：项目实践与更多学科扩展

沿原学生空间 S3 批次建设“成果要求→任务→学生提交→反馈→本人修订→新情境验证”。先完成一个小型编程项目，再扩到其他学科；项目能力与知识理解分别留证，AI 示例不计本人作品。项目场景可在学习目标中先声明，完整项目工作台不作为首个闭环试点的前置条件。

## 六、首个可交付版本

先用一门有真实讲义的课程、两个连续讲次、约 10—20 个经核对的知识点及两个独立学生身份完成贯通；题目按实际需要选用，不以点数达标代替教学覆盖。沿用当前已有合适课程及其隔离副本，不为了本计划改动教师正在工作的课程。

学生输入目标和时间，完成一次正式练习或独立解释；系统定位证据并提供一项有理由的帮助；学生决定是否使用，再接受新的独立检查；矩阵保留前后历史，画像说明变化；教师只看到获授权的事实及课程范围反馈。

首版工程验收必须包括：同源去重、提示/答案隔离、版本冲突、暂停与主动继续、重开、教师预览、两学生隔离、私人信息边界及中英文桌面。真实模型质量与教师内容复核单列；模拟事实用于检验逻辑，不作为真实学生效果证据。延时保持由后续观察验证，不能在当天宣布完成。

## 七、顺序、估算与交接

依赖为 `P0 → P1 → P2 → P3 → P4`；P3 先完善基于现有规则、可解释的画像，BKT 等算法的离线对照可以独立开展，不作为 P4 接通帮助的前置条件。P5 的目标设置可在 P2 后开展，其自适应部分依赖 P3/P4；P6 的基本授权聚合可在 P2 后开展，效果与再备课闭环依赖 P4/P5。P7 在首个闭环稳定后扩展。

建议每批结束演示一个真实动作和一组失败/恢复场景，再进入下一批。未提供人员投入与目标上线日期，因此暂不承诺日历工期；P0 收口后按实际质量缺口、现有分支整合量和教师评议资源估算。长期效果观察与工程开发工期分开。

可直接准备：P0 的只读对账、隔离验收样例、P1 已授权范围内的缺口梳理，以及下文已确认的仓库源码核对与小实验。进入相应接入批次时明确 P2 的分析/纠正及来源链、P3 的维度和趋势规则、P4 个人帮助归属、P6 的教师可见范围与名单分母，再按现行业务规格实现。

建议默认策略：首版建议由学生选择；目标/期限变更先展示安排差异；教学分析默认只用正式提交与获授权反馈。是否允许更高自动调整程度、班级分析最小展示人数以及首个试点学科，进入对应批次前确认，不阻塞本次现状分析。

### 4. 运行过程与决策顺序

一次帮助的过程：解析本人及有权内容 → 冻结来源/知识/目标/画像修订 → 读取相关记忆与未完成计划 → 形成教学决定 → 学生主动请求或接受建议 → 原任务生成帮助 → 本人使用/作答 → 保存事实 → 重新投影画像和下一步。

教学决定顺序：

1. 先校验可信身份、资源权限与版本；不可用时说明原因，禁止用缓存绕过。
2. 先响应明确请求。举例、解释或带一步可直接进入相应动作；仅提问模式不阻止这些本人操作。
3. 错因不明确时保留未知，提供短解释或一次必要澄清；首次答错不自动诊断整节薄弱。
4. 有具体混淆证据选概念辨析，有步骤受阻证据选分步提示；画像只给“需帮助”而无归因时不得机械同时生成解释、例子、练习和复习。
5. 结合总体目标改变案例、深度与节奏；近期接受过同类帮助但无效时重新核实或换策略，不循环重复原答案。
6. 帮助后独立检查是可选后续，有精确绑定和合格材料才正式验证。提示或答案暴露后再完成，记录其实际辅助程度；新题也须确认未暴露答案，不因题目身份新就自动算独立。
7. 正确完成后区分当次通过与长期稳定；更新建议只影响适用范围。未选择的建议、未读回答或未做检查不记成已使用/已完成。

| `TeachingDecision` | `decision_id`、`action`、目标/计划/画像修订、内容锚点/知识修订、证据引用、困难假设/不确定性、教学目标、帮助上限、后续检查策略、返回锚点 | 在既有建议/会话工作区保存决定及理由；规则选择约束，Qwen 生成具体表达 |
| `HelpEpisode` | `help_id`、决定/会话/消息/任务引用、请求身份、来源修订、建议决定、实际使用事件、提示/答案揭示、后续尝试引用 | 作为原会话/工作流关联，不复制消息、题目或作答；接受、实际使用、验证分开 |
| `CompanionPreference/Suppression` | 本人、模式、修订；建议语义事项键、状态、可空 `snoozed_until`/恢复条件、原因与决定时间 | 扩展既有设置/服务端 suppress；模式是本人偏好，学习计划仍按课程隔离 |
| `TeachingFeedbackProjection` | 教师/课程/发布版本、名单快照、时间窗、知识修订、授权范围、去重人数与覆盖、原回执引用、缺口/不确定性 | 原反馈边界内派生；跨实例只接最小授权摘要，教师不另建学生原始事实 |

所有正式写入包含 `request_id`、`expected_revision`（创建时可为空）、`schema_version` 与实际操作者。本人身份从已验证会话/中间件解析，不信任请求体声明的 `user_id`，不能以裸 `X-User-Id` 作为新增生产鉴权。

内容作用域包含当前能取得的 `course_id/course_version_id`、个人材料及修订（适用时）、`node_id`、`block_id/block_revision_id`、精确知识修订引用；跨块或未绑定时保留有效范围及缺口，不伪造精确关联。别名/短名称不作为知识身份。

同源链沿“原活动 → 作答/解释检查 → 分析 → 画像 → 帮助 → 新尝试”引用。重复提交、重复分析、教师回执和笔记另存不新增独立表现；新的本人尝试保留历史，是否计为独立证据仍由原规则决定。

### 6. 状态与恢复合同

| 对象 | 必须区分的状态与转换 |
| --- | --- |
| 小框呈现 | `closed → open → collapsed`；完整界面展开只改变呈现位置，返回恢复锚点；关闭/折叠不取消任务、不删除会话 |
| 主动建议 | `pending → accepted / deferred / dismissed`，依据失效为 `stale`；接受不等于已使用；稍后到约定条件才可再候选，不再提醒保持语义事项抑制 |
| 模型任务 | 映射原引擎的排队、运行、暂停、失败、取消、完成状态，不创建第二个执行状态真源；失败片段保留，有权用户显式继续；完成后读失败只重读结果 |
| 计划变更 | `draft → proposed → adopted / rejected`，基础版本变化为 `stale`；已有明确本人命令按原设置命令提交，主要路线变化先展示差异；旧修订可追溯 |
| 记忆解释 | `active → corrected / disabled / stale`，更正保留原依据与替代关系；停止使用解释不删除原作答事实 |
| 帮助效果 | `not_used → used_unverified → evidence_available`；结论可为当次通过、未通过、待判断，后续保持/迁移独立观察；不把没有检查改成失败 |
| 教师调整 | 关注点 → 主动请求候选 → 原影响分析/审阅 → 逐项采用回执 → 发布 → 学生主动更新 → 后续观察；各阶段分别可失败与恢复 |

语义事项键应由本人、课程、目标/知识范围及待解决事项构成；模型修订、候选 ID 或消息 ID 变化不能单独重置“不再提醒”。学生手动恢复事项或主动求助可继续，不影响其他独立事项。

慢网、刷新和多端冲突时保留草稿，以正式修订对账；相同请求和相同输入回原结果，不同输入复用同一请求 ID 返回冲突。切换课程或材料后旧响应不能覆盖新上下文。授权撤销后停止新读取与写入，保留依法可保留的本人记录，不继续展现受限正文缓存。

### 7. 接口能力与兼容方案

表中为建议的能力划分，不宣称新增路由已经存在。沿已有 router 和仓储扩展，不另启服务；实际路径、字段 Schema 与客户端类型在对应批次同步定稿并测试。

| 接口能力 | 输入与输出合同 | 复用入口 |
| --- | --- | --- |
| 读/改目标与计划 | 读当前修订；写本人明确要求和预期修订；返回新修订、未来安排差异、保留项与冲突 | 原学习设置/继续学习路由及服务 |
| 读/纠正相关记忆 | 按本人课程和内容作用域分页取来源摘要；纠正或禁用某项并使受影响建议过期 | 原会话/学习记录命令；原事实更正另走既有机制 |
| 打开/继续辅学 | 作用域、明确动作或自由问题、请求身份与修订；返回同一会话、教学决定、原 task ID、实际片段及可展开提示 | `routers/study_dialogues.py` 的 open/command 和原 AI 持久任务；个人讲义保持自身权限与来源模型 |
| 设置主动程度/处理建议 | 读写本人模式；展示/接受/稍后/不再提醒按同一语义事项对账 | 现有 `/api/ai-teacher/trigger`、`/trigger/shown`、`/trigger/suppress` 扩展；统一笔记提醒通路 |
| 提交检查/读画像及证据 | 冻结题目与知识修订、本人答案、帮助标识、真实辅助程度及请求身份；返回原评分、证据可用性和新画像修订 | 原 practice / study-dialogues check；现有 `/courses/{course_id}/learner-model` 投影、原记录接口 |
| 读教师关注点/依据 | 教师权限、发布版本、时间窗、明确名单和游标；返回覆盖分母、版本分组、授权依据与缺口 | 现有 teacher exchange feedback 及 `course_exchange` 协议扩展 |
| 主动生成/采用教学建议 | 选定关注点、证据快照、目标与范围、预期版本；返回原任务、候选、影响及 `CourseEvolutionPlan` 引用 | 原课程演进和领域命令；发布沿原协议，实际效果另读投影 |

读能力不发起生成、不补写事实；生成、分析、计划改变和正式采用使用显式命令。失败沿现有错误合同返回可理解原因，至少区分无权、版本冲突、缺少知识绑定、缺合格题、模型不可用和暂时读失败；精确 HTTP 映射沿现有约定，不能把暂时故障当空内容或自动换模型。

现有对话和个人材料保持可读，新增字段缺失时表示未设置/未知。新界面默认轻主动，但初次读取偏好失败不能覆盖已保存设置，也不应在无法确定模式时发起后台模型请求；既有暂停/不再提醒不由新默认值重置。

### 8. 前端交互与教师闭环

学生沿现有桌面蓝紫视觉和中英文文案。选区菜单保留笔记/标记功能；块级与选段入口指向同一学伴工作区，先小框，再按需展开现有侧栏/浮窗，按解释复杂度决定推荐而非知识点字数。保留键盘可达、焦点返回、生成/保存/失败状态和可读字号；回答、图表展开或迟到消息不抢当前阅读位置。

学习设置展示“总体目标、当前阶段、下一步”和可编辑入口；临时需求留当次上下文，变更主要路线展示未来安排差异。记忆入口可查看“学伴依据什么”，查看来源、纠正或停止使用，不展示未经校准的精确能力概率。

轻主动只在自然停顿给一项短建议；正在输入/作答、页面隐藏、专注模式、预览模式不主动插入。仅提问模式也停止自动笔记检查等主动模型调用，仍正常响应本人请求和其任务进度。模式、稍后及不再提醒由服务端持久对账。

教师沿原发布反馈面板显示关注知识、证据覆盖、帮助使用和后续表现；个人详情是下钻，不新建学生排行榜。名单分母、重复去重、版本隔离、授权摘要和教师主动生成的完整规则只在[教师业务正文](../apps/lingzhi/docs/功能设计/课程修改与教学反馈.md#学情汇总与二次备课)维护。一次教师修改、发布和学生更新之后，后续独立表现按各自版本分组回看；无法比较时明确提示。

### 9. 实施批次与并行边界

沿 P0—P6 执行，以下为本轮子批次，不重排既有工程真源。文档确认不启动代码生成任务、课程写入或发布，也不自动解除知识树规格中的教学生成实施冻结；涉及冻结能力的批次须先在原规格明确授权实施范围。

| 子批次 | 主要交付与依赖 | 退出条件 |
| --- | --- | --- |
| P0 本轮基线 | 确定提交/本地差异、运行源和隔离数据、现有鉴权与仓储归属；选连续两讲和核对材料 | 源码—服务—课程对应可重现；正在使用的原课不变；冻结能力及可接范围清楚 |
| P4.1 正文会话衔接 | 复用旧就地能力与正式对话，覆盖教师授权课和个人讲义；可与知识树完善独立推进 | 小框/完整界面同会话同任务，草稿与失败片段保留，回位和权限通过 |
| P5.1 目标、计划与偏好 | 复用现有设置及继续学习，先结构化保存目标/阶段与轻主动偏好；可以并行设计实现 | 跨会话恢复、临时需求不覆盖总目标、重要调整差异可见、模式/拒绝持久化；不依赖复杂画像算法 |
| P2/P3.1 证据与记忆 | 绑定已采用知识子集，统一同源、提示/答案、解释检查、更正与分页；依赖 P0 和样例范围的知识契约 | 两学生隔离、旧修订和重复事件回放一致，纠正后可重算，不复制掌握分 |

| P6.1 教师共性问题 | 原授权作答可先做基本汇总；新增场景/帮助摘要依赖授权协议及 P4.2 | 分母、覆盖、版本与私人边界通过；主动建议进入原修改流程并产生真实回执 |
| P5/P6.2 试点观察 | 在上述批次和发布前必要验证通过后选真实师生试点 | 有实际使用、人工修订量、即时和后续检查证据，未取得长期观察前不宣布长期效果 |

可以同时推进交互/目标偏好与知识树；需要等待的是精确知识归因和正式检查所消费的身份/修订合同。多人或多任务不得同时改同一课程数据；正式集成时对齐提交及合同版本，不用复制运行目录里的源码代替合入。

| A11 | 教师查看问题、请求建议、编辑采用、发布、学生更新 | 原影响预览和逐项回执存在；未选对象不变，旧笔记作答保留，后续比较有版本范围 |

| A13 | 中文/英文桌面、键盘和可读性 | 入口、模式、错误/恢复和空态均可理解；焦点不丢，原有视觉与可读字号保持 |

测试按影响运行后端相关组、前端组件/状态测试、类型检查和构建；联合验收阶段再分别运行 `pytest backend/tests`、`pytest tests` 及前端适当回归，避免同名 conftest 冲突。模拟流/合成事实、真实 Qwen、实际浏览器、正式环境和教学效果分别报告，不以一种替代另一种。

每次帮助记录可关联的决定、目标/画像修订、原任务、策略、实际帮助程度和后续尝试；计量首段/总耗时、失败原因、调用次数/实际用量及人工采用/修订。日志只留必要引用和脱敏元数据，不写密钥、私人全文。不存在真实提供方用量时明确估算，不能把复用/重读算新生成。

上线前以受控测试身份和课程验证，初始版本不批量迁移原学习事实。依赖旧身份或旧字段的消费者保留兼容读；数据结构确需转换时另做显式迁移、备份和恢复验证，不随部署自动执行。恢复到旧版本前验证新增数据的可读性；不支持时关闭本轮能力入口并保留原始数据，而不是清空数据回退。

### 11. 工程落点与试点交接

已固定的产品规则为 C1—C5、四动作、轻主动默认/仅提问选择、同会话、画像唯一真源、个人与教师边界。架构取向为复用既有仓储、任务和视图，最终实现的字段、接口与验证边界见[首版落地验收](../apps/lingzhi/docs/验收/学伴与师生学习闭环Spec落地验收-2026-10-23.md)。

工程落点已确定：目标/计划/明确记忆扩展原 AITeacherRepository；正文和个人讲义保留各自原会话仓储，以 ReadingCompanionSurface 共用展示；画像与正式作答仍按原责任读取。单一课程来源的个人讲义按本人授权读取原课程主线，材料目标只影响当前补充，不复制或覆盖课程总体目标；混合课程来源不自动合并。没有全量解冻内容生成或自动迁移正式数据。

试点前另行确定课程/教师、可用于真实检查的材料、学生反馈授权文案与范围、提醒延后默认时机、记忆摘要保留和清理规则。延后未约定时机时首版可保持挂起直至本人主动恢复；不能自行填入不确定时间反复提醒。未确定真实课程和授权时可先完成隔离工程验收，不以合成数据宣布真实效果。

交接结论：C1—C5 的首版工程实现和隔离验收已完成；真实师生试点与生产发布仍分别验收。新增目标摘要采用明确分享/撤回和发送前授权复核，教师建议进入原影响分析和审阅流程；未自动采用或发布。验收记录保留测试、真实模型、浏览器和未关闭基线问题。

### 接入时保持的边界

1. 知识树保存完整知识及其适用条件。分类关系与先修关系分开；诊断可以拆成多个检查角度，不能把同一公式的因子、必要条件或每一种学生错误都拆成共享知识叶子。
2. 原始表现、解释判断、当前画像和教学决策分别关联。AI 发现可疑表达先保留待判断，按需要追问核实；同一活动不重复计证，更正不删除原文或历史。
3. 在画像与生成之间明确教学决策：本次困难、证据、目标、策略、帮助程度和后续检查。模型按该决定生成个人讲解或练习，不把“薄弱”二字当作完整生成依据。
4. 个人补充沿原材料仓储保存，正式教师教材的修改沿原范围、影响和用户决定流程；讲义插块保护阅读位置、旧笔记和题目修订。
5. xAPI 先用于完善现有事件约定，H5P 先用于题块状态设计；现阶段不整体部署 Learning Locker、不替换阅读器，不建立第二套课程、题库、事实仓储或任务引擎。
6. pyBKT、pyKT、EduStudio 先作离线对照，FSRS 只处理适合回忆检查的复习安排；它们都不直接完成自由文本错因诊断或证明帮助有效。
7. 首轮只参考 EdNet 的过程字段和实验组织，不导入其数据训练产品。复用外部代码前固定提交，核对代码与数据各自的许可，保留来源和必要署名；源码中的模型、账号和存储方式不直接覆盖本项目配置。
8. 所有生成继续使用项目规定的 Qwen 和原 TaskManager；不因引入参考项目追加教师讲义自动审核、重写或无限重试流程。

### 第一轮怎样开始

- **先确定代码与数据基线。** 确定采用的整合提交，核对旧记录可读，使用隔离样例；记录每个参考项目的实际入口、固定提交和准备借用的部分。
- **先打通证据与教学策略。** 对照 xAPI/EdNet 完善一个活动的来源、更正和去重关系；对照 Tutor CoPilot/LearningMAP 整理解释、核实、提示等策略及其输入，接到现有问答和个人材料。
- **以已有链式法则样板为第一条回放。** 复用现有知识、困难候选与后续检查，形成“表现 → 核实 → 帮助 → 新的独立检查 → 画像更新 → 授权反馈”的可追溯过程；再用一个 C 语言例子检查能否复用。样板回放不冒充真实学生效果。
- **随后补互动与复习。** 稳定块身份和题目修订后，借 H5P 检查插块、重排与恢复；有有效回忆记录后，再实验 FSRS。教师反馈先沿已有授权回执完善。
- **最后比较画像算法。** 用同一批记录比较规则、BKT，再按需要扩到 pyKT/EduStudio；同一活动及其派生分析不能跨入训练与评测两边，后续表现按时间向后验证。

首轮交付包括：仓库源码对应关系、拟复用代码或规则及固定版本、对现有模块的最小改动方案、一条可重复的完整样例，以及失败、待判断和误判更正的结果。通过验收的内容再进入原 P1—P6 批次，不用“引用了开源项目”代替功能完成。
