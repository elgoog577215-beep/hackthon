# 生成链路收敛

## 范围与状态

范围：仅灵知（`apps/lingzhi`）的教师端、学生端及共用能力。启智（`apps/qizhi`）的生成入口、任务、资源、身份服务与部署保持原样，不属于本次替换或清理对象。

目标：在现有课程生成框架上，以完整产物为请求单位；有真实依赖才分步，同一产物内部尽量一次生成。被替代的入口、提示词、执行与恢复分支随对应阶段一起退出，不以新旧开关长期并存。

源码审查基线：`4f10d46f3f1cb241572001761ed32f47d8300edd`。G1 已替换教师大纲执行、请求模式、恢复与前端，删除对应旧调度和提示词；默认 `outline_mode=full`，可主动选 `plan_first`。G2 已在原路径完成教案、整讲讲义、任务恢复、保存与消费者适配，删除逐模块普通生成及分片调度。未改生产数据库、在途任务或部署。实现与失败轮次见 [G1 验收](../apps/lingzhi/docs/验收/生成链路G1大纲验收.md)和 [G2 验收](../apps/lingzhi/docs/验收/生成链路G2教案与讲义验收.md)；完整发布条件仍未关闭。

业务目标以[课程生产](../apps/lingzhi/docs/功能设计/课程生产.md)、[PPT 与教学表达](../apps/lingzhi/docs/功能设计/PPT与教学表达.md)、[课程修改与教学反馈](../apps/lingzhi/docs/功能设计/课程修改与教学反馈.md)为准。实现差距见[产品状态](../apps/lingzhi/docs/产品状态.md)。

本次覆盖大纲、教案、讲义及其预算、状态、恢复与旧入口退出；后续同一变更继续收敛 PPT、题库。教师和学生共用能力，但本次不把全局角色白名单放开、不补造学生授权、不把尚未接通的个人材料宣称完成。成熟学生阅读界面与现有教师工作台作为 UI 基础。独立论文检查、视频分析、聊天等不因名字包含 AI 而删除。

## 决策与请求边界

正常成功路径的“单次”是一次主要模型请求，不包含解析、校验、存储、流式推送等程序动作。用户请求改写、故障恢复、独立求解分别计量，不能隐去后称单次生成。

| 对象 | 改造前拆分 | 目标与例外 |
| --- | --- | --- |
| 大纲 | 轻量框架、课程级要求、逐讲详情、纠正与最多两轮交付前优化 | 默认一次完整大纲；只有教师主动选“先看方案”才先生成简案并等待继续，后续一次展开完整大纲 |
| 教案 | 每讲联合生成知识安排和教案；外层重试、修复 | 每讲一次主请求；保留本地结构检查，移除常规语义优化循环，明确错误才进入原任务的受控修复 |
| 讲义 | 根据教案模块逐块请求并汇编 | 每讲一次正文请求，按小节保存定位；真实长度超限才按连续主题分段，同一个生成方法处理剩余范围 |
| PPT 内容稿 | 按小节补页、逐页修复，并存其他规划入口 | 每讲一次形成完整逐页合同；保留模板、来源及容量检查，失败只修受影响页 |
| PPT 文件 | 已确认稿件的编译与渲染 | 无内容模型调用；确认与导出分开，模型不得在渲染时改稿 |
| 正式题库 | 候选生成、独立求解、语义审阅、修复 | 按合理题量合批生成；独立求解或代码运行必须在题目产生后进行，本地可算则不再调用模型；同模型独立求解不等于消除所有错误 |
| 日历、配套文件 | 课程数据投影与模板编译 | 保持程序计算，不增加模型步骤 |
| 资料准备 | 文件解析、用途与关系理解 | 解析先行并复用；需要语义辨认时按资料版本分析一次；不是每次生成都重新概括资料 |
| 局部修改 | 有范围的候选与采用 | 一次产生所选范围候选；用户采用仍独立，不重生成其他内容 |
| 全课联动修改 | 影响分析、决定、跨资产候选、采用 | 保留决策依赖；每份候选调用原产物能力，同次分析能装下时合并，超限才按完整对象分批 |
| 图解与图片 | 语义规划、编译或图像服务 | 图解一次形成结构；需要调用图像工具时保留工具依赖，不能用文本模型调用次数代表全部成本 |
| 个人学习材料 | 设计已定义，完整生产未接通 | 一份材料一次主请求；沿用共用讲义能力和独立材料写入责任，不新建学生引擎 |

依赖顺序为完整大纲 → 本讲教案 → 本讲讲义 → 本讲 PPT 内容稿 → 确认后编译。不同讲次可并发；下游只等待自己所需的讲次修订，不等待全课同阶段完成。额外产物仅在本次请求明确选择时推进，不能借此次简化默认自动生成一切。

## G1、G2 必须实现的输入与输出合同

### 冻结输入

在现有请求快照中补齐：合同版本、产物类型、用途、课程/讲次、目标修订、来源修订及摘要指纹、所选资料、教师要求、完整小节顺序、范围、请求 ID、前置产物 ID、预算。数据来自服务端授权读取；客户端用途不授予角色权限。具体字段沿用已有命名，缺失的字段扩展原类型，不新增平行 DTO/Store。

来源全文与其修订引用保留在既有资料/正文仓储，任务只持有对账所需引用与生成快照；任务历史裁剪后仍可追溯。日志和遥测不记录完整 prompt、正文、答案、凭据或用户记录。

### 大纲与教案

大纲一次响应返回现有课程字段与全部讲次详情的 JSON；完整字段集复用既有规范化/校验结构，不把每个字段独立请求。服务端分配或核验稳定 ID，校验课时和、讲次覆盖与来源。方案模式仍调用同一能力，输出范围为讲次标题/简介；教师继续时一次生成正式全量输出。

教案沿用当前单讲 JSON，知识安排和教学环节同次输出。学生必要规划是内部结构，不要求先生成教师专用教案文件或学校大纲；共用能力不能强制学生填写行政栏目。学生正式入口接通仍需要独立授权与学习记录验收，此项不因后端函数共用自动关闭。

### 整讲讲义

请求一次给齐整讲目标、全部小节、必要教学安排、选定来源与教师要求。固定课程/小节身份，正文的段落、示例和推导由模型连贯组织；不再固定一个教学环节对应一个 API 请求。

输出采用 Markdown 正文与轻量分隔标记：每个既定小节以 `<!-- section:<请求中已有的 section_id> -->` 开始，整讲以 `<!-- handout:end -->` 结束。标记只承担身份与截断识别，不进入可见正文；模型不得发明小节 ID。解析器忽略代码围栏内部的同形标记，拒绝重复、未知、缺失、乱序 ID；结束标记不能替代 API `finish_reason` 和必需小节完整性检查。其单元测试必须包含代码中出现标记文本的情况。

解析器写回原 `sections/blocks` 仓储：新整讲生成每个小节先保存一个连续正文块，块 ID 由服务端按该小节的正文角色稳定分配；段落标题不再对应远程请求。阅读、局部编辑、内容稿和导出消费同一修订。既有课程首次改用整讲生成形成新修订，旧块 ID、笔记引用和旧正文保持不变；只对有充分依据的对应关系建立映射，不能按数组位置把旧笔记贴到新段落。

### 生成结果与保存

原任务保存尝试身份、模型完成原因、用量、已解析小节、未完成范围、来源指纹、最后检查点、候选引用和正式产物引用。禁止流式文字到达就报正式成功。只有整讲完整、结构与来源检查通过、保存成功，才能成为当前正式讲义；旧的可用修订始终保留。失败片段在工作区可见，但明确未完成。

在同一任务的一次“继续”中，已完整解析的小节可复用；所有剩余小节合成一次请求，输入包含相同冻结依据、已完成正文和当前未完成片段。接到下一合法小节标记且前一小节代码围栏等结构闭合，才可把前一小节记为完整检查点；最后小节还需结束标记和正常完成原因。模型中途断在公式或代码内部的片段只留草稿，继续时重写当前未完成小节，不能直接拼接半个 token/半行代码。预览/候选可复用检查点不等于已发布半份正式讲义。

局部改写继续使用原候选/差异/采用机制。若未采用候选或用户手改未保存，整讲重新生成不得静默覆盖。取消、删除、来源变化或授权撤销均在正式提交前再次检查，迟到响应不得恢复已终止任务。

## 预算、长度与恢复

代码基线：`course_generation_budget.py` 默认输入 16,000 tokens / 32,000 字符，正文输出 8,192 tokens，环境值正文输出钳制上限 32,000，讲义活动请求默认 180 秒；`outline.py` 另有教师大纲输出预算，`course_generation/budget.py` 有教案预算。需一起核对，不只调一个环境变量。

G1 在隔离环境读取有效预算，包括 AIBase 的最终请求参数与推理服务的 context/max-output/思考模式。公开结果只含能力数值与模型 ID，不记录地址、账号或凭据。本轮接口报告上下文 131,072 tokens；应用输入 16,000、完整大纲输出预算 16,384，余量 1,024。精确 tokenizer 和真实最大输出仍待验证，不能用窗口大小冒充输出能力。

预算原则：输入 tokens + 预留输出 tokens（包括服务计入的思考部分）+ 明确余量不得超过服务有效上下文。按部署匹配的 tokenizer 计量；仅有估算器时注明误差，不以字符截断静默丢来源。初次实验正文输出用 16,000 和 32,000 tokens 两档，均是试验值而非新生产默认值。活动总期限按实际吞吐设定；持续无输出超时独立处理；队列等待不占活动期限。并发从 1、2 测起，不能直接沿用旧块生成并发 8。

| 事件 | 同一链路中的处理 |
| --- | --- |
| 普通完成 | 本地结构/来源检查后保存，一次主请求，没有默认模型润色/自审 |
| 请求前预算不足 | 说明真实超限；缩小范围或按连续主题分段。段是同一任务的范围参数，不回落旧模块生成器 |
| 返回 length / 断流 | 保留检查点和草稿，等待有权限用户继续；不后台自发补写 |
| 讲义非空但缺小节/重复 ID | 不发布；保留输出、明确结构问题，用户选择恢复当前范围 |
| 大纲/教案返回不可解析结构 | 本地无损格式修复优先；任务层最多一次明确结构修复请求，记录为额外调用；仍失败就停，不进入语义优化循环 |
| 连接失败、服务限流 | 唯一调度层分类处理，底层不再叠加重试；讲义失败保持显式继续。任何新尝试都计量，禁止用重新拆块掩盖服务故障 |
| 保存失败 | 保留结果，仅恢复持久化；不再调用模型 |
| 来源/授权/预期修订冲突 | 阻止提交，保留候选与原可用结果；重新确定输入后建立新尝试 |
| 取消或删除 | 终止后续提交，丢弃迟到写入；页面断连本身不取消任务 |

上述规则收敛 `_run_generation_step`、`AIBase` 与调用方的重试责任。独立求解与 PPT 局部修复继续有各自业务原因和总预算，不能藏入“主要请求”的统计。

## 旧任务、旧入口与回退

部署盘点是切换前的实时条件，不是现在可以凭源码证明的事实。只在读过项目部署说明和私有基础设施登记后连接目标环境；不把生产数据复制进仓库。

1. 列出灵知各部署当前提交、使用中的入口、旧类型任务数量与状态、非终态任务引用、资源所有者映射及外部 API 消费者。后台只读盘点，不通过重启服务或自动取消来制造“零任务”。
2. 正在运行且属其他任务的生成先保持原服务完成；无法完成的任务在明确接管后终止。保留完成产物与片段，通过显式转换工具绑定新输入/任务并记录转换回执，不将旧 checkpoint 直接当成新合同。切换时旧执行任务必须归零。
3. 新版本仅包含重构后的执行路径。已完成历史任务作为只读记录，旧格式不提供旧引擎 resume；读取时说明可查看的结果及可用的新生成动作。
4. 核对灵知旧入口的页面、API 调用者与资源引用；完成调用方适配后删除灵知被替代的生成 API 和恢复分支。保留灵知历史资料、修订与学习记录，不迁移启智资源、不改启智入口或数据库。灵知调用者有遗漏则该阶段不算完成。
5. 切换前生成仓库外带时间戳的数据备份，核对摘要并在隔离目录恢复一次。回退使用旧发布包及其兼容数据快照；新任务停止写入后再回退，不在运行时加回旧链开关。新版本产生的数据不能直接交给旧程序读取，须先导出保护并走已验证恢复步骤。

历史成品和学习记录必须保留。删除执行代码不是删除原始资料、旧修订或学习证据。

## 执行批次与完成条件

实现与删除成对交付。若某共享旧函数仍有调用者，该批次只能标部分完成；不能用“以后清理”宣称链路已收敛。

| 批次 | 工作范围 | 完成条件 |
| --- | --- | --- |
| G1 大纲与共同请求边界 | 核对有效预算；替换大纲分层请求；显式方案模式；统一调用计量和重试；更新状态/前端；旧大纲 prompt 和分批调度退出 | 普通完整大纲一次请求；方案模式严格两次且中间等待；整课覆盖与课时检查；旧正常入口无分批调用；恢复/并发保存通过 |
| G2 单讲教案与整讲讲义 | 保留联合教案；移除常规优化；整讲流式解析、小节身份、保存/续作/局部改写/候选/PPT来源适配；清理逐模块调度 | 正常单讲教案一次、讲义一次；新旧笔记引用不串；单个失败不毁其他讲；旧分片 executor 无可达调用 |
| G3 PPT 收敛 | 统一内容稿入口、全讲内容与版式选择；局部容量修复；内容稿确认；编译不改知识 | 普通内容稿一次；渲染零内容调用；来源覆盖、公式代码、Web/PPTX一致和上传审阅回归通过 |

| G5 灵知旧路径退出 | 核对灵知旧任务、调用者与资源引用；移除灵知旧整课执行和恢复；清掉专属开关、配置、提示词、弃用测试与文档 | 灵知被替代链路无残留调用或旧引擎恢复，历史成品可读；启智保持原样；灵知部署前检查和隔离恢复通过 |
